@one Deep Learning trains Neural Networks, built by stacking many Layers of Linear Transformations and nonlinear Activation Functions, with Backpropagation and Gradient Descent so they automatically learn Representations from raw data; it trains deep networks stably with an Architecture suited to the data's structure (CNNs for images, RNNs·Transformers for Sequences), Regularization·Normalization Layers, and good Optimizers.

## Basic Concepts

#### What Is Deep Learning? Learning Even the Features on Its Own
ONE: **Deep Learning** is Machine Learning in which a Neural Network made of **many layers (Layers)** **learns even the features (Features) on its own** from raw data.
LIKE: Picture an assembly plant. Raw materials (pixels) become "lines" at the first station, "shapes" at the next, then "eyes·ears," and at the last station, the finished product "cat." People don't decide what each station does; the plant learns it on its own.
STEP:
1. **Traditional ML**: People pick the Features. "Are the ears pointy? Are there whiskers?" Then the model decides.
2. But for **unorganized data (Unstructured Data)** like photos·sound·text, it's too hard for people to create good Features.
3. **Deep Learning**: Feed in the pixels as-is, and the early Layers learn simple features (lines, colors) while the later Layers learn complex features (object parts, objects). This is called **Representation Learning**.
4. **What a single Neuron does**: Multiplies each input by a Weight and adds them up (Weighted Sum), adds a Bias, then passes the result through an Activation Function.
5. **Layer**: One layer of many Neurons side by side. Input layer → several hidden layers (Hidden Layers) → output layer.
6. **"Deep"**: Means there are several Hidden Layers.
PRO: Overwhelming performance on photos·audio·text, and less need for people to create Features.
CON: It needs lots of data and compute (GPUs), and it's hard to interpret why it decided what it did.
END: Deep Learning = a Neural Network that learns even the features on its own as data passes through many stations.

#### The Perceptron and the XOR Problem
ONE: The **Perceptron** is the simplest Neuron, splitting things in two by drawing **a single straight line** with a weighted sum of its inputs. A single line can't solve **XOR**, so you need an **MLP** that stacks layers.
LIKE: Picture a 2×2 grid with white stones in the top-left·bottom-right and black stones in the top-right·bottom-left. However you lay a single ruler, you can't separate the white stones from the black ones. With two rulers, you can.
STEP:
1. **Perceptron**: Adds up input × Weight, adds a Bias, and outputs 1 if the result is greater than 0, otherwise 0.
2. In the end, this rule splits space in two with **a single straight line (a plane in higher dimensions)**.
3. **AND, OR**: They can be separated by a single line, so a Perceptron solves them.
4. **XOR**: 1 only when the two inputs differ. (0,1) and (1,0) are 1, (0,0) and (1,1) are 0, so the diagonals match and a single line can't separate them (Not Linearly Separable).
5. **MLP (Multi-Layer Perceptron)**: Put a Hidden Layer in between, and the first layer draws two lines while the next layer combines the results to solve XOR. Two Hidden Neurons are enough.
6. When this limitation was pointed out in 1969, Neural Network research stagnated for a while, and it revived once Backpropagation, which trains multilayer networks, became widely known (1986).
END: Problems a single line (Perceptron) can't solve are solved by stacking layers (MLP).

#### Non-Linearity: Why Activation Functions Are Needed
ONE: Without **nonlinear functions (Activation Functions)** between Layers, no matter how many you stack, it's **the same as a single Layer**. Nonlinearity is what makes depth meaningful.
LIKE: Chain together 100 copiers that enlarge·rotate, and the result is the same as "enlarging·rotating once." You need a machine in between that folds or cuts the paper (nonlinear) to create new shapes.
STEP:
1. **Linear**: A transformation that only scales inputs by constants and adds them. Wx + b.
2. Applying Linear twice gives W₂(W₁x) = (W₂W₁)x, the same as multiplying by a single Matrix.
3. So stacking 100 Linear Layers alone has the same expressive power as 1 Linear Layer.
4. **Activation Function**: Applies a nonlinear function (ReLU, etc.) to each Neuron's output. This plays the "paper folding" role.
5. **Universal Approximation Theorem**: Even a Network with a single Hidden Layer with nonlinear Activations can approximate a continuous function to any desired accuracy, given enough Neurons.
6. **Making curves with ReLU**: A single ReLU is "a straight line with one bend." Add up many ReLUs with different bend locations and slopes, and the broken line becomes dense and approaches a curve. It's like making a circle by joining short straws.
KEY: The theorem means "such Weights exist"; it doesn't guarantee they can be found by training or how many Neurons it takes. In practice, stacking **many layers deep** is far more efficient than one wide layer.
END: Without nonlinearity, however deep, it's a single line. Activation Functions give the Network the power to draw curves.

#### The Role of Bias
ONE: **Bias** is a constant added to a Neuron's weighted sum. It **shifts the reference point** at which the Neuron responds.
LIKE: With only y = ax, every line has to pass through the origin. You need the b in y = ax + b to move the line up and down and place it where you want.
STEP:
1. Neuron: z = w₁x₁ + w₂x₂ + … + **b**.
2. Without b, z is always 0 whenever all inputs are 0.
3. The boundary wᵀx = 0 also has to pass through the origin, which reduces expressive power.
4. With b, each Neuron can learn "how easily it turns on (Threshold)."
5. If Batch Normalization comes right after, BN's β plays the same role, so the Bias is sometimes omitted.
END: Weight is the slope, Bias is the position. Bias lets you place the boundary where you want.

### What is Deep Learning? How does it differ from Machine Learning?
E: In traditional Machine Learning, people had to pick features like "cats have pointy ears and whiskers," but give Deep Learning just the photo's pixels and it builds the features on its own in the order lines → shapes → ears·eyes → cat.
A: Deep Learning is a branch of Machine Learning that learns Representations from input to output step by step with Artificial Neural Networks of many Layers. While traditional ML depends heavily on human-made Features, Deep Learning learns Feature Extraction too (Representation Learning), making it strong on Unstructured Data like images·audio·text, but in exchange it needs more data and compute and is hard to interpret.

### What are the Perceptron and the MLP? Why can't a Perceptron solve XOR?
E: XOR is a 2×2 grid where diagonal squares have the same color. A single ruler (straight line) can't separate the two colors; you need two rulers.
A: A Perceptron is a Linear Classifier that adds a Bias to the Weighted Sum of its inputs and outputs 0/1 with a Step Function, so its Decision Boundary is a single straight line (Hyperplane), and XOR is a problem that can't be separated by a single line (Not Linearly Separable). An MLP (Multi-Layer Perceptron) adds a Hidden Layer with nonlinear Activations that transforms the input space into a Linearly Separable one, so even just 2 Hidden Neurons can solve XOR.

### What does Non-Linearity mean, and why is it needed?
E: Chain together a hundred copiers that enlarge·rotate, and in the end it's the same as "enlarging·rotating once." You need to put a machine in between that folds or cuts the paper (Non-Linear) to get new shapes.
A: Non-Linearity means the output can't be expressed as constant multiples·sums of the input. If you stack only Linear Layers without Activation Functions, then as in W₂(W₁x) = (W₂W₁)x, however deep it gets it's equivalent to a single Linear Layer, so you have to put nonlinear functions like ReLU between Layers for depth to matter and for complex functions to be expressible.

### How does ReLU approximate a curved function? (Universal Approximation Theorem)
E: Join enough short straws and you can even draw a circle. A single ReLU is one "bent straight line," and adding several of them makes a broken line with many bends that gets closer and closer to a curve.
A: A ReLU Network is a Piecewise Linear Function, and adding ReLUs with different positions and slopes lets you build a broken line that bends wherever you want, so the more Neurons you add, the more precisely it can follow a curve. The Universal Approximation Theorem says that a Network with a single Hidden Layer using a non-polynomial Activation Function (including ReLU) can approximate a continuous function on a bounded interval to any desired accuracy, given enough Neurons. However, it only means "such Weights exist"; it doesn't guarantee the number of Neurons needed or whether they can be found by training, and in practice stacking deep is far more efficient, with far fewer Neurons.

### Why does Bias exist?
E: With only y = ax, every line has to pass through the origin. You need the b in y = ax + b to move the line up and down.
A: Bias is a constant added to a Neuron's Weighted Sum, shifting the reference point (Threshold) at which Activation happens. Without Bias, the Decision Boundary wᵀx = 0 always has to pass through the origin, and the output is fixed when the input is 0, which reduces expressive power. (However, if BN comes right after, BN's β plays the same role, so the Bias is sometimes omitted.)

## Activation Functions and Loss Functions

#### Loss Function: How Wrong It Is, in a Single Number
ONE: A **Loss Function** expresses **how different** the model's prediction is from the answer as a single number. Training is the process of **reducing this number**.
LIKE: It's scoring defects at a plant's final inspection. If the defect score is high, you adjust the stations, and you repeat until it comes down.
STEP:
1. **Regression (predicting numbers)**: **MSE** = the average of squared errors. Big penalty for big errors.
2. **Classification (predicting categories)**: **Cross-Entropy** = −log(probability given to the correct Class). Giving the correct answer probability 0.9 gives a penalty of about 0.1, and 0.01 gives about 4.6, so the more confidently wrong, the more the penalty soars.
3. **Loss vs Cost**: Usually one sample's error is called the Loss, and the overall average (+ Regularization) the Cost. In practice the terms are used interchangeably.
4. **Why not use MSE for Classification?** Using MSE with Sigmoid·Softmax makes the Gradient actually smaller when the model is confidently wrong, so training is slow. With Cross-Entropy the Gradient is large then, so it gets corrected quickly.
5. **Metrics for Monitoring**: You can train with Cross-Entropy while computing Accuracy or MSE (the MSE of probabilities = the Brier Score) separately just for logging.
END: Loss is the defect score. MSE for Regression and Cross-Entropy for Classification are the defaults.

#### Comparing Activation Functions: Sigmoid · Tanh · ReLU
ONE: Activation Functions make a Neuron's output nonlinear. **Sigmoid·Tanh** have the problem of slopes vanishing at both ends, so Hidden Layers mainly use **the ReLU family**.
LIKE: Sigmoid is like a dimmer switch. It responds well in the middle, but once you turn it all the way, turning further barely changes the brightness (Saturation). ReLU is a simple switch: "off if negative, pass through unchanged if positive."
STEP:
1. **Sigmoid**: Output 0–1. Good for probability outputs, but its derivative is at most **0.25**, so the Gradient shrinks with every layer it passes. When the input is very large or small, the slope is almost 0.
2. **Tanh**: Output −1–1. Symmetric around 0, so it's better than Sigmoid, but it still saturates at both ends.
3. **ReLU**: max(0, x). Its slope is 1 for positive values, so Gradients pass through well, and it just needs a comparison, so it's fast to compute. It outputs 0 for negative inputs, so only some Neurons turn on (Sparse).
4. **Dying ReLU**: If a Neuron's input is always negative, both its output and slope are 0, so it never learns again. It's a switch that broke and got stuck "off."
5. **LeakyReLU**: Leaves a small slope (e.g., 0.01) for negative values too, preventing Dying ReLU.
6. **GELU·SiLU**: Smoothed versions of ReLU, widely used in Transformers.
| Function | Output range | Pros | Cons |
| Sigmoid | 0 ~ 1 | Interpretable as a probability | Saturation, derivative at most 0.25 |
| Tanh | −1 ~ 1 | Zero-centered | Saturation |
| ReLU | 0 ~ ∞ | Fast, passes Gradients well | Dying ReLU |
| LeakyReLU | −∞ ~ ∞ | Mitigates Dying ReLU | The slope α must be chosen |
| GELU | Includes slight negatives | Smooth | Slightly more expensive to compute |
END: Hidden Layers use the ReLU family (Transformers use GELU), and Sigmoid·Tanh are mainly used in output layers or LSTM Gates.

#### Pairing the Last Layer with the Loss
ONE: The output layer is chosen to fit **the kind of value being predicted**, and the Loss is its matching **pair**.
LIKE: A plant's final packaging station varies by product. Just as liquids go in bottles and snacks go in bags, the packaging (output layer) differs for predicting a number·Yes/No·one of several·several at once.
STEP:
1. **Predicting a single number (Regression)**: 1 Unit, no Activation → MSE·MAE.
2. **Yes / No (Binary)**: 1 Unit + Sigmoid → Binary Cross-Entropy.
3. **One of several (Multi-Class)**: K Units + Softmax (sums to 1) → Cross-Entropy.
4. **Several possible at once (Multi-Label)**: K Units + a Sigmoid on each → per-Class BCE. Example: a photo contains both a "cat" and a "sofa."
5. **Practical tip**: Instead of putting Sigmoid·Softmax at the end yourself, pass the pre-activation scores (**Logits**) to PyTorch's BCEWithLogitsLoss·CrossEntropyLoss. They compute it stably together with the Log internally, preventing numbers from overflowing or becoming 0.
END: Numbers get Identity + MSE, binary gets Sigmoid + BCE, picking one gets Softmax + CE, and several get Sigmoids + BCE.

### What are the Cost Function and the Activation Function?
A: A Loss (Cost) Function expresses how different the model's prediction is from the answer as a single number (MSE for Regression, Cross-Entropy for Classification), and training is the process of minimizing this value. Usually one sample's error is called the Loss, and the overall average (including the Regularization term) the Cost. An Activation Function is a nonlinear function applied to each Neuron's Weighted Sum that gives a Neural Network nonlinear expressive power.

### What Activation Functions do you know? (Sigmoid, Tanh, ReLU, LeakyReLU, etc.)
| Function | Formula | Output range | Characteristics |
| Sigmoid | 1/(1 + e⁻ˣ) | (0, 1) | Suited to probability outputs, derivative at most 0.25, saturates at both ends, output not centered at 0 |
| Tanh | (eˣ − e⁻ˣ)/(eˣ + e⁻ˣ) | (−1, 1) | Zero-Centered, derivative at most 1, still saturates |
| ReLU | max(0, x) | [0, ∞) | Cheap to compute, slope 1 for positives, 0 for negatives |
| LeakyReLU | x if x ≥ 0, else αx (e.g., 0.01) | (−∞, ∞) | A small slope for negatives too, mitigating Dying ReLU |
| GELU, SiLU | x·Φ(x), x·σ(x) | Includes slight negatives | Smooth ReLU, widely used in Transformers |
| Softmax | e^(zᵢ)/Σe^(zⱼ) | (0, 1), sums to 1 | Output layer for Multi-Class Classification |
A: Hidden Layers usually use the ReLU family (Transformers use GELU), and the Output Layer uses Sigmoid·Softmax·Identity depending on the task. Sigmoid·tanh have the Saturation problem, where the slope approaches 0 as the input grows, so these days they're mainly used in outputs or LSTM Gates rather than Hidden Layers.

### Why is ReLU used more than Sigmoid these days?
A: Sigmoid's derivative is at most 0.25, so the slope shrinks with every Layer and becomes almost 0 in the Saturation region, causing Vanishing Gradients in deep networks, whereas ReLU has a slope of 1 in the positive region, so Gradients pass through well. It's also fast, needing only a comparison with no exponentials, it creates Sparse Activations by outputting 0 for negative inputs, and in practice it converged much faster.

### What's the problem with ReLU? (Dying ReLU)
E: If a switch breaks in the "off" position, it'll never turn on again.
A: ReLU has both output and slope 0 for negative inputs, so if a large Learning Rate or similar changes the Weights·Bias drastically and a Neuron's input becomes always negative, that Neuron becomes a Dead Neuron that's never updated again. It's mitigated with variants like LeakyReLU·PReLU·ELU, a suitable Learning Rate, and He Initialization. A minor drawback is also that its output isn't Zero-Centered and is unbounded above.

### How do you set up the last Layer?
| Task | Output Layer | Loss Function |
| Regression | 1 Unit (or the number of Targets), no Activation | MSE, MAE, Huber |
| Binary Classification | 1 Unit + Sigmoid | BCE (Binary Cross-Entropy) |
| Multi-Class (one answer) | K Units + Softmax | Categorical Cross-Entropy |
| Multi-Label (several answers) | K Units + a Sigmoid on each | Per-Class BCE |
A: The Output Layer is chosen to fit the kind of value being predicted, as in the table above. In practice, for Numerical Stability, you don't put Sigmoid·Softmax at the end yourself; you pass the Logits (pre-activation scores) to PyTorch's BCEWithLogitsLoss or CrossEntropyLoss, which stably compute the Activation and Log together internally.

### What if you want to train with BCE Loss but watch progress with MSE Loss?
A: Use only BCE for Backpropagation, and compute the MSE between predicted probabilities and answers separately, just as a Monitoring Metric for logging. In PyTorch, call backward on `loss = bce(logits, y)`, compute `mse = ((torch.sigmoid(logits) - y) ** 2).mean()` inside `torch.no_grad()`, and log it to TensorBoard or similar; in Keras, just add `'mse'` to `metrics`. The MSE of probabilities is called the Brier Score and shows how well the probabilities match reality (Calibration).

## Gradient Descent and Backpropagation

#### Gradient Descent: One Step Downhill at a Time
ONE: **Gradient Descent** repeatedly moves the Weights **a little at a time** in the direction that reduces the Loss (the **opposite direction** of the Gradient).
LIKE: It's finding the lowest point in a valley blindfolded. You feel the slope of the ground with your feet and take one step at a time downhill. If your stride is too big you overshoot the valley; too small and the sun sets before you get there.
STEP:
1. **Gradient**: The collection of derivatives of the Loss with respect to each Weight. It points to "which way makes the Loss **grow** fastest."
2. **Update**: θ ← θ − η × Gradient. You have to go the opposite way for the Loss to shrink.
3. **Learning Rate (η)**: The stride. It's the most important Hyperparameter.
4. **Why the Gradient specifically?** With billions of Weights, changing them one at a time to measure the Loss is impossible. The Gradient tells you **the direction for every Weight at once** with a single Backpropagation pass.
5. **As a graph**: The textbook picture has Weight on the horizontal axis and Loss on the vertical axis. In reality there are as many axes as Weights, so it can't be drawn; instead you look at the **Learning Curve**, with training Steps on the horizontal axis and Loss on the vertical axis.
6. **Why the Loss sometimes goes up**: The stride is too big and it overshoots the valley (Overshooting), or each Mini-Batch estimates the direction from different data, so it wobbles (Stochastic Noise). If only the Validation Loss rises, that's a sign of Overfitting.
END: Repeatedly moving by the Learning Rate in the opposite direction of the Gradient reduces the Loss.

#### Backpropagation: Assigning Responsibility Backward
ONE: **Backpropagation** works **from back to front**, tracing the output error backward and using the Chain Rule to compute in one pass **how responsible every Weight is for the error (the Gradient)**.
LIKE: At a bread factory, the finished bread came out too salty. Tracing backward from the baking team → the dough team → the ingredient-measuring team, each asks "how much did my step contribute to the saltiness?" and adjusts a little.
STEP:
1. **Forward Pass**: Pass the input from front to back to compute the prediction and the Loss. Intermediate values are saved.
2. **Backward Pass**: Starting from the output layer, pass the derivative of the Loss forward toward the earlier layers.
3. **Chain Rule**: If the Loss is connected to w through y and then z, ∂Loss/∂w = ∂Loss/∂y × ∂y/∂z × ∂z/∂w. You just multiply each step's "local derivative" (topic 12).
4. **Fast thanks to reuse**: Earlier Layers pick up and reuse the derivatives already computed in later Layers. So the total cost is on the same order as the Forward Pass.
5. **Update**: Gradient Descent adjusts the Weights with the Gradients found.
6. **Autograd (automatic differentiation)**: Records the computation as a Graph of small operation Nodes like addition·multiplication (a Computational Graph), then follows it backward to differentiate automatically. PyTorch's `loss.backward()` does this.
END: Compute forward (Forward), assign responsibility backward (Backward). Thanks to the Chain Rule, the Gradients of all Weights are found in one pass.

#### Vanishing · Exploding Gradient
ONE: The Gradient of an early Layer is **the product of the derivatives of all the later Layers multiplied together**, so if the values being multiplied are smaller than 1 it **vanishes (Vanishing)**, and if they're larger it **explodes (Exploding)**.
LIKE: It's like the game of Telephone: the more people there are, the more the message fades away to nothing, or conversely gets more and more exaggerated until it's nonsense.
STEP:
1. In Backpropagation, an early Layer's Gradient = the product, in turn, of the later Layers' (Activation derivative × Weight).
2. **Vanishing**: Sigmoid's derivative is at most 0.25. Over 10 layers, 0.25¹⁰ ≈ 0.000001, almost 0, so the early Layers don't learn.
3. **Exploding**: If the multiplied values are larger than 1, it grows exponentially, so the Weights jump around and the Loss becomes NaN.
4. **Especially bad in RNNs**: Because the same Weight is multiplied over and over at every time Step.
5. **Fixing Vanishing**: ReLU, good initialization (He·Xavier), Batch·Layer Normalization, Residual Connections, LSTM Gates.
6. **Fixing Exploding**: **Gradient Clipping** (cutting the Gradient down when its size exceeds a threshold).
END: Keep multiplying small numbers and it vanishes; multiply big numbers and it explodes. Prevent it with ReLU·initialization·Normalization·Residuals·Clipping.

### How would you explain Gradient Descent simply?
E: If you were finding the lowest point in a valley blindfolded, you'd feel the slope of the ground with your feet and move one step at a time downhill. If your stride is too big you overshoot the valley; too small and the sun sets before you get there.
A: Gradient Descent is an Optimization method that repeatedly moves the Parameters a little at a time in the opposite direction of the Gradient (the direction in which the Loss grows fastest), the derivative of the Loss with respect to the Parameters: θ ← θ − η∇L(θ), where η (the Learning Rate) is the stride.

### Why must you use the Gradient? What are that graph's horizontal and vertical axes? What does it actually look like?
A: Changing millions to hundreds of billions of Parameters one at a time to check the Loss is impossible, but the Gradient tells you, for every Parameter, "which way and how much to change it to reduce the Loss," with a single Backpropagation pass (at a cost similar to the Forward Pass). In the textbook picture, the horizontal axis is the Parameter (Weight) value and the vertical axis is the Loss. In reality it's an ultra-high-dimensional terrain (Loss Landscape) with as many axes as Parameters, so it can't be drawn; instead you look at the Learning Curve, with training steps (Steps·Epochs) on the horizontal axis and Loss on the vertical axis, and this curve goes down overall while bouncing up and down due to Mini-Batch noise.

### Why does the Loss sometimes increase during GD?
A: Because the Learning Rate is too big and it jumps over the valley to a higher spot on the other side (Overshooting), or because each Mini-Batch estimates the Gradient from different samples, so the direction wobbles (Stochastic Noise). It can also go up when Momentum overshoots from inertia or when the Learning Rate Schedule raises the rate again, and if only the Validation Loss rises, that's a sign of Overfitting. If the Loss keeps jumping around, lower the Learning Rate or use Gradient Clipping.

### How would you explain Backpropagation simply?
E: If the final bread at a bread factory came out too salty, you'd trace backward from the baking team → the dough team → the ingredient-measuring team, each asking "how much did my step contribute to the saltiness?" and adjusting a little.
A: Backpropagation is the Algorithm that, after computing the Loss with a Forward Pass, applies the Chain Rule from the Output Layer toward the Input Layer to find the derivative of the Loss with respect to every Weight in one pass. Earlier Layers reuse the derivatives computed in later Layers, so the cost is on the same order as the Forward Pass, and Gradient Descent updates the Weights with the Gradients found.

### What are the Computational Graph and Autograd (automatic differentiation)?
A: A Computational Graph is a Directed Graph that breaks an expression into basic operation Nodes like addition·multiplication, and Automatic Differentiation records the Graph and intermediate values during the Forward Pass, then goes in reverse, multiplying each Node's Local Gradient by the Chain Rule (Reverse Mode). Unlike Numerical Differentiation (an approximation), it's exact, and unlike Symbolic Differentiation, the expressions don't explode; PyTorch's `loss.backward()` does this.

### Why do Vanishing Gradients and Exploding Gradients happen?
E: In the game of Telephone, the more people there are, the more the message fades away to nothing, or conversely gets more and more exaggerated until it's nonsense.
A: In Backpropagation, an early Layer's Gradient is the product of the later Layers' derivatives (Activation Function derivative × Weight) multiplied together, so if the multiplied values are smaller than 1 (Sigmoid derivative ≤ 0.25) it shrinks exponentially with the number of Layers (Vanishing), and if they're larger than 1 it grows exponentially (Exploding). RNNs multiply the same Weight at every Time Step, so it's especially bad. Vanishing is prevented with ReLU, He·Xavier Initialization, Batch·Layer Normalization, Residual Connections, and LSTM Gates, and Exploding with Gradient Clipping.

## The Loss Landscape and Local Minima

#### High-Dimensional Terrain and Saddle Points
ONE: The Loss terrain of Deep Learning is bumpy, but in high dimensions there are far more **saddle shapes (Saddle Points)** than real dips that trap you, and most dips are **low enough** anyway, so in practice training goes well.
LIKE: On a 2D mountain, it's easy to get stuck in a small dip. But on terrain with a million directions, a dip where **every direction goes uphill at once** is rare. Most are saddles where some direction still goes downhill.
STEP:
1. **Local Minimum**: The bottom of a dip where every direction goes uphill.
2. **Saddle Point**: A point where some directions go uphill and some go downhill. The Gradient is 0 so you might pause briefly, but there's a way out.
3. In high dimensions, most points where the Gradient is 0 are Saddle Points.
4. Research shows that the Local Minima of large Networks don't differ much in Loss from the Global Minimum.
5. With very many Parameters (Over-Parameterization), the terrain becomes smoother.
6. **Escape tools**: The noise of Mini-Batch SGD (shaking it loose), Momentum (getting over ridges with inertia), starting with a large Learning Rate or periodically raising it again (Warm Restart), and training several times from different initial values.
7. **Can you tell if it's the Global Minimum?** In general, no. And the Global Minimum of the Training Loss might actually be Overfitting, so the goal is **a solution with good Validation performance**.
END: In high dimensions, saddles are the problem more than dips, and SGD noise and Momentum help escape them. The goal isn't the Global Minimum but a solution that generalizes well.

### Why does Deep Learning work well despite the Local Minimum problem?
E: On a 2D mountain, it's easy to get stuck in a dip, but on terrain with a million directions, a real dip where every direction goes uphill at once is rare; most are saddle shapes (Saddle Points) where some direction still goes downhill.
A: In a high-dimensional Loss Landscape, most points where the Gradient is 0 are Saddle Points rather than Local Minima, and research shows that the Local Minima of large Neural Networks don't differ much in Loss from the Global Minimum. Over-Parameterization with many Parameters makes the terrain smoother, and SGD's noise and Momentum help escape Saddle Points, so in practice training reaches a "good enough" solution.

### How does GD avoid Local Minima?
A: It uses the noise of Mini-Batch SGD to bounce out of shallow dips, Momentum's inertia to get over small ridges, and a large Learning Rate early on or a Schedule that periodically raises the Learning Rate again (Warm Restart). You can also train several times with different Initializations and pick the best one or Ensemble them.

### Is there a way to tell whether the solution found is the Global Minimum?
A: For Non-Convex functions, in general you can't. However, when you know a lower bound on the Loss (Cross-Entropy is 0 or more), if the Training Loss nearly reaches that bound you can say it's close to the Global Minimum with respect to the Training Data, and you can also check by comparing the results of several Initializations. In practice, the Global Minimum of the Training Loss might actually be Overfitting, so the goal is to find a solution with good Validation performance.

## Optimizers

#### SGD · Momentum · RMSprop · Adam
ONE: An Optimizer decides **which direction and how far** to move based on the Gradient. **Momentum** adds inertia, **RMSprop** adjusts the stride per direction, and **Adam** combines the two.
LIKE: SGD is walking while looking only at the slope under your feet at each step, Momentum is carrying on your previous speed like a ball rolling down a hill, RMSprop is walking carefully with small strides in directions that have often been steep, and Adam is a rolling ball that also adjusts its stride to fit the terrain.
STEP:
1. **SGD**: Estimates the Gradient from a randomly drawn Mini-Batch instead of all the data and moves right away. **Stochastic** means "estimating from a randomly drawn subset." On average it equals the full Gradient, but it's noisy.
2. **Momentum**: Uses a "velocity" v that accumulates past movement directions. v ← βv + g. When the direction stays the same it accelerates, and when it zigzags the moves cancel out, reducing oscillation.
3. **RMSprop**: Remembers the recent Gradient size (mean of squares) for each Weight and divides by it. Directions that have always been steep get smaller strides, and gentle ones get bigger strides (Adaptive Learning Rate).
4. **Adam**: Momentum (the average of the direction) + RMSprop (the average of the size). It corrects the skew caused by starting at 0 (Bias Correction). It works well even with the defaults β₁ = 0.9, β₂ = 0.999, η = 0.001, so it's the most widely used.
5. **AdamW**: A version that separates Weight Decay from Adam's stride adjustment, and the standard for training Transformers.
6. **SGD + Momentum**: Many reports say it generalizes better when well tuned, so it's still used for image models.
| Optimizer | Key idea | Analogy |
| SGD | Move right away with the Mini-Batch Gradient | Walking looking only at your feet |
| Momentum | Accumulate past directions | A rolling ball |
| RMSprop | Automatically adjust the stride per direction | Careful where it's steep |
| Adam | Momentum + RMSprop | A ball that adjusts its stride |
END: Adam, which combines inertia (Momentum) and per-direction strides (RMSprop), is the default, and Transformers use AdamW.

#### Mini-Batch Size and Learning Rate Schedules
ONE: The **Mini-Batch** size balances speed·stability·Generalization, and a **Learning Rate Schedule** is a plan that changes the stride from large at first to small later. **Warmup**, which raises it gradually at the start, is also used.
LIKE: It's like deciding the size of a taste-testing panel. A small panel gives quick, frequent feedback but the opinions are all over the place; a big one gives stable opinions but takes a long time to gather each round. And you change the recipe in big ways at first, then adjust a pinch of salt at a time as it nears completion.
STEP:
1. **Pros of small Batches**: They use less Memory, update more often in the same Epoch, and the noise can act as a kind of Regularization.
2. **Cons of small Batches**: They wobble more, so they need a smaller Learning Rate; they can't fully use GPU parallelism, so total time is longer; and Batch Normalization statistics become inaccurate.
3. **Step Decay**: Reduces the Learning Rate every so many Epochs (e.g., to 1/10).
4. **Cosine Annealing**: Reduces it smoothly, like a cosine curve.
5. **Warmup**: Gradually raises the Learning Rate from near 0 to the target value over the first few thousand Steps. It prevents divergence early on, when the Weights are random and Adam's statistics are unstable. It's nearly essential for Transformers and large-Batch training.
END: The Batch balances speed and stability, and the Learning Rate is raised with Warmup and then gradually lowered.

### How would you explain SGD, RMSprop, and Adam? What's the formula for Momentum?
E: SGD is walking while looking only at the slope under your feet at each step, Momentum is carrying on your previous speed like a rolling ball, RMSprop is walking carefully with small strides in directions that have often been steep and with big strides in gentle ones, and Adam combines the two.
| Method | Update rule (g is the Gradient) | Key point |
| SGD | θ ← θ − ηg | The simplest; many reports say it generalizes well when well tuned |
| Momentum | v ← βv + g, θ ← θ − ηv (β ≈ 0.9) | Accumulates past directions to reduce oscillation and accelerate |
| RMSprop | s ← ρs + (1 − ρ)g², θ ← θ − ηg / (√s + ε) | Automatically adjusts each Parameter's stride based on recent Gradient size |
| Adam | m ← β₁m + (1 − β₁)g, v ← β₂v + (1 − β₂)g², Bias Correction m̂ = m/(1 − β₁ᵗ), v̂ = v/(1 − β₂ᵗ), θ ← θ − ηm̂ / (√v̂ + ε) | Momentum + RMSprop, defaults β₁ = 0.9, β₂ = 0.999, η = 0.001 |
A: SGD updates right away with the Mini-Batch Gradient, Momentum builds a velocity from the Exponential Moving Average of the Gradient to reduce oscillation, and RMSprop divides by the moving average of the squared Gradient to adjust each Parameter's Learning Rate (Adaptive Learning Rate). Adam combines the two and corrects the Bias from initializing at 0, and since it works well even with defaults, it's the most widely used; AdamW, which separates Weight Decay, is the standard for training Transformers.

### What does Stochastic mean in SGD?
A: It means estimating the Gradient from a single randomly drawn sample or Mini-Batch instead of the Gradient over all the data. This estimate equals the full Gradient on average (Unbiased) but is noisy, so each update is much cheaper, and the noise also helps escape Saddle Points.

### What are the pros and cons of making the Mini-Batch small?
A: Small Batches use less Memory and update more often in the same Epoch, and there are reports that the Gradient noise acts as a kind of Regularization that helps Generalization. On the other hand, the noise is large, so training is unstable and needs a smaller Learning Rate; they can't fully use GPU parallelism, so total time is longer; and Batch Normalization's statistics become inaccurate.

### What are Learning Rate Scheduling and Warmup?
A: To descend quickly with a large Learning Rate at first and then shrink it later to converge finely, methods like Step Decay, which reduces it every so many Epochs, and Cosine Annealing, which reduces it along a cosine curve, are used. Warmup gradually raises the Learning Rate from near 0 to the target value over the first few thousand Steps of training; it prevents Divergence early on, when the Weights are random and Adam's statistics are unstable, and it's nearly essential for Transformer·large-Batch training.

## Training Setup

#### Parameter vs Hyperparameter
ONE: **Parameters** are **values set automatically** by training (Weights, Biases), and **Hyperparameters** are **settings people choose** before training (Learning Rate, Batch Size, number of Layers, etc.).
LIKE: When baking bread, the oven temperature and baking time are settings the baker chooses (Hyperparameters), while the flavor and texture that develop as the dough rises (Parameters) are determined during baking.
STEP:
1. **Parameters**: Weights, Biases. Gradient Descent finds them from data. Millions to hundreds of billions of them.
2. **Hyperparameters**: Learning Rate, Batch Size, number of Epochs, number of Layers, number of Neurons, Dropout rate, Weight Decay strength, choice of Optimizer.
3. Hyperparameters aren't learned by the Gradient, so you try several and pick by Validation performance.
4. **How to pick**: Trying every combination (Grid Search), trying random combinations (Random Search, usually more efficient than Grid), and smartly choosing the next try based on results so far (Bayesian Optimization).
END: Set by training is a Parameter; set by people is a Hyperparameter. Choose Hyperparameters with Validation.

#### Weight Initialization
ONE: **What values the Weights start at** determines whether training succeeds. If they're all the same, the Neurons learn identically, and if they're too large or small, signals blow up or vanish. So they start random **in a way that keeps the signal size steady from layer to layer**.
LIKE: Give every worker at a plant the same manual and the same feedback, and they'll all end up doing the same job. They have to start a little differently to take on different roles.
STEP:
1. **All 0 (or the same value)**: Neurons in the same Layer get the same output and the same Gradient, so they stay identical forever (the Symmetry problem).
2. **Random values that are too large**: The signal grows with each layer and explodes, or Sigmoid·Tanh saturate.
3. **Values that are too small**: The signal vanishes toward 0 with each layer.
4. **Xavier (Glorot)**: Var(W) = 2 / (n_in + n_out). Sets the variance based on the numbers of input·output Neurons. Suited to Sigmoid·Tanh.
5. **He (Kaiming)**: Var(W) = 2 / n_in. Doubled to compensate for ReLU zeroing out half. Used for the ReLU family.
END: The same value causes the symmetry problem; the wrong size causes blow-ups·vanishing. Start with He for ReLU and Xavier for Sigmoid·Tanh.

#### Data Normalization
ONE: Bringing input Features to **similar ranges**. Either fit them to mean 0·variance 1, or divide pixels by 255. Training becomes **faster and more stable**.
LIKE: If a recipe lists sugar in teaspoons and salt in pounds, it's confusing and your measurements go haywire. Matching the units makes adjustment easy.
STEP:
1. When Feature ranges differ, the Loss terrain becomes a valley stretched long in one direction.
2. Then Gradient Descent zigzags back and forth between the valley walls, descending slowly.
3. Matching the ranges makes the terrain closer to a round bowl, so it heads straight down.
4. Large inputs saturate Sigmoid·Tanh and kill the Gradient, and Normalization prevents this too.
5. Compute the mean·variance **only from the Training Data**, and use those same values for Validation·Test (Data Leakage in topic 14).
END: Matching units makes the terrain round, so it descends quickly. Compute the statistics only from the Training Data.

### What are Hyperparameters, and how do they differ from Parameters?
E: In cooking, the oven temperature and baking time are settings the cook chooses (Hyperparameters), and the flavor and texture the dough creates as it rises on its own (Parameters) are determined during the process.
A: Parameters are values like Weights·Biases that training sets automatically from data, and Hyperparameters are settings people choose before training, like the Learning Rate·Batch Size·number of Layers·Dropout rate·number of Epochs. Hyperparameters are chosen by watching Validation Set performance, with Grid·Random Search or Bayesian Optimization.

### What Weight Initialization methods are there, and which are common? (Xavier, He)
A: Setting all Weights to 0 or the same value causes the Symmetry problem, where Neurons in the same Layer learn identically, and values that are too large or small make signals and Gradients blow up or vanish as they pass through Layers. So Weights are initialized randomly so that each Layer's output variance is preserved: Xavier (Glorot) uses Var(W) = 2/(n_in + n_out) for Sigmoid·tanh, and He (Kaiming) compensates for ReLU zeroing out half with Var(W) = 2/n_in for the ReLU family. These days, He Initialization is the most common for ReLU Networks.

### What is Data Normalization, and why is it needed?
A: It's making the ranges of input Features similar, for example by fitting them to mean 0·variance 1 or dividing pixels by 255. When Feature scales differ, the Loss Landscape gets stretched long in one direction so Gradient Descent converges slowly in a zigzag, and large inputs saturate the Activation Function, so Normalization makes training fast and stable. The statistics are computed only from the Training Data.

## Data Split

#### Why Split into Train · Validation · Test
ONE: You learn with the **Training Set**, choose settings with the **Validation Set**, and measure ability with the **Test Set** **just once** at the end. Using the Test set to choose inflates the score.
LIKE: You study with a workbook (Training), change your study methods based on practice tests (Validation), and take the SAT (Test) just once. If you changed your study methods many times to fit the practice tests, your practice test scores are already inflated above your real ability.
STEP:
1. **Training Set**: Used to learn the Weights. The model can memorize it, so this score is too optimistic.
2. **Validation Set**: Used to choose Hyperparameters, decide when to stop training (Early Stopping), and choose which model to use.
3. **Test Set**: Measures final performance once, after all choices are made.
4. **Why a separate Validation set?** If you choose while watching the Test score, the choice itself becomes fitted to the Test set, and the Test score is no longer a score on "never-seen data."
5. **Test contamination (Contamination)**: When Test information has gotten mixed into training·selection by any route. Examples include duplicate samples in Train·Test, repeated tuning while watching the Test score, preprocessing with Test statistics, and Benchmark questions mixed into LLM training data.
END: Studying is Training, adjusting study methods is Validation, and the real thing is Test, once.

### Why separate the Training Set and the Test Set? Why is there a separate Validation Set?
E: You study with a workbook (Training), change your study methods based on practice tests (Validation), and take the SAT (Test) just once. If you took many practice tests and tuned your study methods to them, your practice test scores are already inflated above your ability.
A: Performance on the Training Data is optimistic because the model can memorize it, so Generalization performance is estimated with a Test Set it has never seen. Using the Test Set for Hyperparameter Tuning, Early Stopping, or Model Selection fits the choices themselves to the Test set and inflates the score, so a Validation Set is kept to take on this role separately.

### What does it mean for a Test Set to be contaminated (Contamination)?
A: It's the state where information from the Test Data has gotten into the training or selection process by some route, so it's no longer "never-seen data." Typical cases are duplicate samples between Train·Test, repeated tuning while watching the Test score, preprocessing using Test statistics, and Benchmark questions mixed into LLM Pre-training data, and in those cases the Test score comes out higher than real performance.

## Overfitting and Regularization

#### Overfitting Remedies at a Glance
ONE: **Regularization** is any constraint placed on training to improve performance **on never-seen data** rather than on the training data. You can work on it in three places: the data·the model·the training process.
LIKE: To fix a student who only memorizes past exam questions, you give more varied problems (data), reduce the room for memorizing (model), and make them stop memorizing once their practice test scores start dropping (training process).
STEP:
1. **More data**: Collect more data, or expand the data you have by changing it slightly (**Data Augmentation**: flipping·cropping·rotating·recoloring images, swapping synonyms in text).
2. **Smaller model**: Reduce the Layers or Neurons.
3. **Weight Decay (L2)**: Penalize Weights so they don't grow large (topic 14).
4. **Dropout**: Randomly switch off Neurons during training.
5. **Early Stopping**: Stop training when the Validation Loss stops improving, and use the Weights from the best point.
6. **Batch Normalization**: Also has a weak Regularization effect.
7. **Ensemble**: Average the predictions of several models.
8. **Transfer Learning**: Starting from a model pretrained on large data means less memorizing even with little data.
END: Add data, simplify the model, penalize the Weights, randomly switch off Neurons, and stop at the right time.

#### Dropout
ONE: **Dropout** **randomly switches off Neurons with probability p** at every training Step, so the network doesn't come to rely on any particular Neuron.
LIKE: If a team project randomly gives a few people the day off every day, the team doesn't depend on one particular ace; everyone learns to do a bit of every job.
STEP:
1. At every Step during training, switch off each Neuron with probability p (e.g., 0.5) (set its output to 0).
2. Then Neurons can't depend on each other with "the Neuron next to me will handle it" (Co-Adaptation).
3. It amounts to training a different small Network each time, which has an **Ensemble effect** of averaging many Networks.
4. **At inference, nothing is switched off.**
5. **Matching the scale (Inverted Dropout)**: During training, the outputs of the surviving Neurons are scaled up by 1/(1 − p). Then at inference you can use the network as-is and the average size is the same.
6. In PyTorch, switching to `model.eval()` turns Dropout off.
END: Switch off at random during training, turn everything on at inference. Making Neurons independent of each other means less memorizing.

#### Batch Normalization and Layer Normalization
ONE: **Batch Normalization** is a Layer that **fits each Feature to mean 0·variance 1** within a Mini-Batch and then rescales it with learnable parameters. **Layer Normalization** does the same thing **within a single sample**.
LIKE: If test difficulty varies by class so scores are hard to compare, you convert them to standard scores by subtracting the class mean and dividing by the standard deviation (BN). But if there's only one test taker in the room on exam day, you can't compute a class mean, so you use the overall average collected so far. LN computes standard scores among one student's own subject scores instead of using the class mean.
STEP:
1. **BN during training**: Normalizes each Channel (Feature) using its mean·variance in the Mini-Batch.
2. Then it rescales with learnable γ (scale) and β (shift), so it can even undo the normalization if needed.
3. **Effects**: You can use a larger Learning Rate, it converges faster, it's less sensitive to initialization, and it has a weak Regularization effect. (It was first explained as reducing Internal Covariate Shift, but later an explanation that it smooths the Loss terrain was proposed.)
4. **BN at inference**: Uses the **Running Mean·Var** collected during training instead of Batch statistics. In PyTorch you must call `model.eval()`. If you forget, predictions vary with the Batch composition, and with a Batch Size of 1 you get nonsense values.
5. **LN**: Computes the mean·variance over all Features of a single sample. It doesn't depend on the Batch Size and behaves the same in training and inference.
6. **Where it's used**: BN for CNNs with large enough Batches, LN for RNNs·Transformers that handle Sequences of different lengths.
END: BN normalizes along the Batch (with Running statistics at inference), LN within a single sample. BN for CNNs, LN for Transformers.

### What should you do about Overfitting? What is Regularization?
A: Regularization refers to any constraint placed on training to reduce Generalization error rather than Training error. If a model is overfitting, add data or use Augmentation (rotation·cropping·noise), shrink the model, or use Weight Decay (L2), Dropout, Early Stopping, Batch Normalization, Ensembles, or Transfer Learning from a Pre-trained Model.

### What is the effect of Dropout?
E: If a team project randomly gives a few people the day off every day, the team doesn't depend on one particular person; everyone learns to do a bit of every job.
A: Dropout randomly switches off Neurons with probability p at every training Step, preventing Neurons from depending too much on each other (Co-Adaptation), and creates an Ensemble effect of training and averaging a different small Network each time. Usually the surviving Neurons are scaled up by 1/(1 − p) during training (Inverted Dropout), so at inference nothing is switched off and the network is used as-is.

### What are the effects of Batch Normalization? What should you watch out for when actually using it after training?
E: If test difficulty varies by class so scores are hard to compare, you convert them to standard scores by subtracting the class mean and dividing by the standard deviation. But on exam day you have to grade even if there's only one test taker, so you use the "overall average" collected so far.
A: BN (Batch Normalization) is a Layer that normalizes each Channel (Feature) to mean 0·variance 1 within a Mini-Batch and then Scales·Shifts it again with learnable γ·β; it enables larger Learning Rates and faster convergence, makes training less sensitive to Initialization, and also has a weak Regularization effect (it was first explained as reducing Internal Covariate Shift, but later an explanation that it smooths the Loss Landscape was proposed). At inference you have to use the Running Mean·Var collected during training instead of Batch statistics, so in PyTorch you call `model.eval()` (which also turns off Dropout), switch back with `model.train()` when training again, and run inference inside `torch.no_grad()`. If you forget eval, predictions vary with the Batch composition, and with a Batch Size of 1 you get nonsense values.

### How does Layer Normalization differ from BN?
A: BN normalizes the same Feature gathered along the Batch, while LN (Layer Normalization) normalizes all the Features of a single sample together. So LN isn't affected by the Batch Size and behaves the same in training and inference, which is why it's used in RNNs·Transformers that handle Sequences of different lengths, while BN is mainly used in CNNs with large enough Batches.

## CNN (Convolutional Neural Network)

#### Convolution: Scanning with a Magnifying Glass
ONE: **Convolution** is an operation that slides a small **Filter (magnifying glass)** over an image, scoring **how strongly** a particular pattern (lines, edges) **appears** at each position, to build a **Feature Map**.
LIKE: It's scanning a photo one cell at a time from the top left with a "vertical-line-finding magnifying glass," writing down a score for "is there a vertical line here?" Use several magnifying glasses (vertical lines, horizontal lines, circles) and you get several score sheets.
STEP:
1. **Filter (Kernel)**: A small grid of numbers like 3×3. These numbers are the Weights being learned.
2. **Convolution**: Lay the Filter over one part of the image, multiply the corresponding cells, and add them up (Dot Product). That's the score at that position.
3. Slide the Filter along and repeat to build the score sheet (**Feature Map**).
4. **Stride**: How many cells the Filter moves at a time. With 2, the output size becomes roughly half.
5. **Padding**: Surrounds the border with zeros so the edges get looked at too. It can keep the output size unchanged.
6. **Output size**: ⌊(W − K + 2P) / S⌋ + 1. Example: a 5×5 Filter on 32×32 with P = 0, S = 1 gives (32 − 5) / 1 + 1 = 28 → 28×28.
7. **Pooling**: Keeps only the largest value (Max Pooling) or the average in each region to shrink the size. It has no Weights to learn, and the result wobbles less when positions shift slightly.
8. **Stacking layers**: Early layers find lines·edges, middle layers find parts like eyes·wheels, and later layers find objects like faces·cars.
END: Scan with Filters to build pattern score sheets (Convolution), shrink the size (Pooling), and stack layers to climb from lines → parts → objects.

#### Why CNNs Are Strong on Images
ONE: In a CNN, each Neuron **looks only at nearby pixels (Local Connectivity)** and the same Filter is **reused across the whole image (Weight Sharing)**, so it has **far fewer Weights** than an MLP and finds the same pattern even when its position changes.
LIKE: In a hidden-picture puzzle, you just scan the whole picture with one "find-the-cat-shape magnifying glass." You don't need to make a different magnifying glass for every cell of the picture.
STEP:
1. **The problem with MLPs**: Fully connecting a 224×224×3 image to 1,000 Hidden Neurons needs about 150 million Weights for the first Layer alone.
2. On top of that, an MLP flattens the pixels into one long row, ignoring the spatial structure of "neighboring pixels."
3. **Local Connectivity**: Meaningful patterns in images (lines, edges) are formed by nearby pixels. So looking only at the neighborhood is enough.
4. **Weight Sharing**: A vertical line is a vertical line wherever it is in the image. Reusing the same Filter cuts the Weights enormously.
5. **Translation Equivariance**: Whether the cat is on the left or the right, the same Filter responds.
6. **Would an MLP work?** For small, centered digit images like MNIST, an MLP also reaches about 98%. But for large real-world photos it needs far more data.
7. With ultra-large-scale data, **ViT**, which handles images with a Transformer and no Convolution, is also competitive.
END: Looking only at neighbors and reusing the same Filter means few Weights and robustness to position. That's why images get CNNs.

#### ResNet and Residual Connections
ONE: A **Residual Connection** makes a Block's output **y = F(x) + x**, providing a **shortcut** that passes the input straight through. Thanks to this, even very deep Networks with over 100 layers became trainable.
LIKE: It's putting an elevator next to a long staircase. Each floor only has to learn "the small part to fix from what came in," and the signal can ride the elevator straight up and down.
STEP:
1. **The problem (Degradation)**: Simply adding Layers caused even **the Training error** to rise, even though it wasn't Overfitting. Deep networks were hard to train.
2. **The idea**: Instead of having a Layer learn the whole target H(x), have it learn only the **difference (Residual)** from the input, F(x) = H(x) − x. The output is F(x) + x.
3. **Unneeded Layers**: If one learns F(x) ≈ 0, it becomes a Layer that just passes the input through. Useless Layers don't ruin performance.
4. **A Gradient shortcut**: During Backpropagation, the Gradient travels through the +x path all the way to the early layers without shrinking. Vanishing Gradients drop sharply.
5. **The result**: ResNet (2015) trained a 152-layer Network and won the ImageNet competition.
6. Transformers also use Residual Connections in every Block.
END: Thanks to the shortcut that adds the input back in, each layer only needs small fixes, and the Gradient flows unblocked.

### What are Convolution, Filter, Stride, Padding, and Pooling? What's the output size formula?
E: Scanning a photo one cell at a time from the top left with a magnifying glass (Filter), writing down a score for "is there a vertical line here?", is Convolution. How many cells it moves at a time is the Stride, surrounding the border with zeros so the edges get looked at too is Padding, and keeping only the largest score in each region to shrink the size is Pooling.
A: A Convolution Layer slides a small Filter (Kernel) over the input, computing a Dot Product at each position to build a Feature Map, and the Filter values are learned Weights. For input size W, Filter K, Padding P, and Stride S, the output size is ⌊(W − K + 2P)/S⌋ + 1; for example, a 5×5 Filter on 32×32 with P = 0, S = 1 gives 28×28. Pooling (Max·Average) shrinks the size without learned Parameters, reducing computation and making the network less sensitive to small position changes.

### Why are CNNs stronger than MLPs on images? Would an MLP instead of a CNN work well too?
A: Thanks to Local Connectivity, where each Neuron looks only at nearby pixels, and Weight Sharing, where the same Filter is reused across the whole image, a CNN has far fewer Parameters, the same Filter responds wherever the cat is (Translation Equivariance), and stacking Layers learns hierarchical features from lines → shapes → objects. An MLP also works well, at about 98% accuracy, on small, centered images like MNIST, but connecting a 224×224×3 image to 1,000 Hidden Neurons needs about 150 million Weights for the first Layer alone, and it ignores spatial structure, so it needs far more data. (That said, with ultra-large-scale data, Convolution-free architectures like ViT·MLP-Mixer are also competitive.)

### Why do ResNet's Residual Connections make deep networks trainable?
E: It's putting an elevator next to a long staircase. Each floor only has to learn "the small part to fix from what came in," and the signal can ride the elevator straight up and down.
A: A Residual Connection (Skip Connection) makes a Block's output y = F(x) + x, so the Layer learns only the Residual F(x) rather than the whole target function. During Backpropagation, the Gradient passes through the +x path (Identity Mapping) to the early Layers without shrinking, and unneeded Layers can easily become the Identity Function with F(x) ≈ 0; this solved the Degradation problem, where adding Layers actually raised the Training error, and made deep networks like 152 layers trainable. Transformers also use Residual Connections in every Block.

## Sequence Models

#### Time Series and AR Models
ONE: A **Time Series** is data where **the order in time carries meaning**. An **AR(p) Model** predicts the current value as **a weighted sum of the previous p values + noise**.
LIKE: It's predicting tomorrow's temperature as "a weighted average of today's·yesterday's·the day before's temperatures + a bit of luck."
STEP:
1. **Time Series examples**: Stock prices, temperatures, sales, sensor readings, web traffic.
2. **Characteristic**: Nearby points in time resemble each other (Autocorrelation). That breaks ordinary ML's assumption that "samples are independent of each other."
3. **AR(p) (Autoregressive)**: xₜ = c + φ₁xₜ₋₁ + … + φₚxₜ₋ₚ + εₜ. It regresses the series on its own past.
4. The coefficients φ are estimated with Least Squares or similar.
5. **Careful with splitting**: Training·Validation must be split in **past → future order**. Shuffling randomly amounts to predicting the past with the future (Data Leakage).
END: For data where time order matters, predict the present from past values, and always train on the past and validate on the future.

#### RNNs: Reading While Rewriting a Summary Note
ONE: An **RNN** reads one item at a time in order, combining **the summary so far (Hidden State)** with **the current input** to make a new summary. But **as sequences get long it forgets the beginning**, and since it has to compute in order, **it's slow**.
LIKE: It's reading a book one word at a time while continually rewriting a summary note in your head. The notepad has a fixed size, so as the book gets longer, the contents of the first chapter fade more and more.
STEP:
1. **At each time step**: hₜ = tanh(Wₕhₜ₋₁ + Wₓxₜ + b). Makes a new summary hₜ from the previous summary hₜ₋₁ and the current word xₜ.
2. **Shared Weights**: It uses the same Wₕ, Wₓ at every time step, so it can handle sentences of different lengths.
3. **Training (BPTT)**: Applies Backpropagation to the Network unrolled along the time axis (Backpropagation Through Time).
4. **Why it's weak on long sentences**: The Gradient is multiplied by the same Wₕ and tanh derivative over and over, once per time step, so it vanishes or explodes the further back it goes (the Long-Term Dependency problem).
5. **Why it's slow**: To compute hₜ you need hₜ₋₁ first, so it can only be computed in order. GPU parallelization is hard.
END: An RNN remembers order by carrying a summary forward, but it forgets over long spans and is hard to parallelize.

#### LSTM and GRU: A Notepad with an Eraser and a Pen
ONE: An **LSTM** has a separate long-term memory channel (**Cell State**) and **three Gates** (forget·write·read out), deciding on its own what to remember and what to forget, so it **remembers even long sentences**.
LIKE: It's a notepad (Cell State) fitted with an eraser (Forget Gate), a pen (Input Gate), and a cover sheet that "shows only the part to say right now" (Output Gate).
STEP:
1. **Cell State cₜ**: A conveyor belt along which information flows over long spans.
2. **Forget Gate fₜ**: Decides, from 0 to 1, how much of the previous memory to keep. 0 erases it and 1 keeps it as is.
3. **Input Gate iₜ**: Decides how much of the new candidate information to write.
4. **Output Gate oₜ**: Decides how much of the memory to read out as output.
5. **Update**: cₜ = fₜ ⊙ cₜ₋₁ + iₜ ⊙ c̃ₜ. The key is that it's **an additive path**. Unlike an RNN, which multiplies repeatedly, the Gradient survives for a long time.
6. **Output**: hₜ = oₜ ⊙ tanh(cₜ).
7. **GRU**: Reduces the Gates to 2 (Update, Reset) and merges the Cell State and Hidden State. It has fewer Parameters and is faster, and its performance is often similar.
END: LSTM = a notepad with an eraser·pen·cover sheet. Its additive path lets it remember for a long time. GRU is a lighter version.

### What are Time Series data and the AR(p) Model?
E: It's predicting tomorrow's temperature as "a weighted average of today's·yesterday's·the day before's temperatures + a bit of luck."
A: A Time Series is data where the order in time carries meaning, and adjacent values are correlated (Autocorrelation), breaking the assumption that samples are independent. The AR(p) (Autoregressive) Model explains the current value as a Linear Combination of the previous p values plus noise, as in xₜ = c + φ₁xₜ₋₁ + … + φₚxₜ₋ₚ + εₜ, and the coefficients are estimated with Least Squares or similar. Training·Validation must be split in past → future order.

### How does an RNN remember order, and why is it weak on long sentences? (BPTT)
E: It's reading a book one word at a time while continually rewriting a summary note in your head. The notepad has a fixed size, so as the book gets longer, the contents of the first chapter fade more and more.
A: An RNN (Recurrent Neural Network) makes a new State at each time step by combining the previous Hidden State and the current input, as in hₜ = tanh(Wₕhₜ₋₁ + Wₓxₜ + b), and shares the same Weights across all time steps to handle Sequences of different lengths. It's trained with BPTT (Backpropagation Through Time), which applies Backpropagation to the Network unrolled along the time axis, but because the Gradient is multiplied by the same Wₕ and tanh derivative once per time step, it Vanishes·Explodes, making information from the distant past hard to learn (the Long-Term Dependency problem), and since it must compute in order, parallelization is hard too.

### What are the LSTM's three Gates and Cell State? How does it differ from a GRU?
E: An LSTM fits a notepad (Cell State) with an eraser (Forget Gate), a pen (Input Gate), and a cover sheet that "shows only the part to say right now" (Output Gate), deciding on its own what to forget, what to write, and what to read out.
A: An LSTM (Long Short-Term Memory) has a Cell State cₜ in addition to the Hidden State, and uses Sigmoids (0–1) to decide how much of the previous memory to keep (Forget Gate fₜ), how much of the new candidate c̃ₜ to add (Input Gate iₜ), and how much to output (Output Gate oₜ). The Cell update cₜ = fₜ ⊙ cₜ₋₁ + iₜ ⊙ c̃ₜ is an additive rather than multiplicative path, so the Gradient survives for a long time, and the output is hₜ = oₜ ⊙ tanh(cₜ). A GRU (Gated Recurrent Unit) merges the Cell State and Hidden State with two Gates, Update·Reset, so it has fewer Parameters and is faster, and its performance is often similar.

## Attention and Transformers

#### Attention: Deciding Where to Look on Its Own
ONE: **Attention** gathers information by deciding, with weights, **which of all the other positions to consult, and how much**, for the position currently being processed. It works with three things: **Query·Key·Value**.
LIKE: At a library, you compare your question (Query) with the titles on the book spines (Key), read more of the books the more relevant they are, and build an answer by blending those books' contents (Value) in proportion to their relevance.
STEP:
1. **Example**: In "The animal didn't cross the street because it was too tired," to know what "it" refers to, the model needs to consult "animal" heavily.
2. **Query (Q)**: What the current position wants to find. **Key (K)**: The "index information" each position holds. **Value (V)**: The actual content of each position.
3. **Similarity**: Scores "how relevant" with the Dot Product of Q and each K.
4. **Weights**: Divides the scores by √dₖ, then turns them into proportions summing to 1 with Softmax.
5. **Result**: Takes the weighted average of the Vs using those proportions.
6. **Formula**: Attention(Q, K, V) = softmax(QKᵀ / √dₖ) V.
7. **Why divide by √dₖ**: In high dimensions the Dot Products get large, so the Softmax piles onto one side (Saturation) and the Gradient becomes small. Dividing keeps the size in check.
8. **Self-Attention**: Q·K·V are all made from the same sentence, by multiplying by different Weight Matrices.
9. **Multi-Head Attention**: Does this with several sets in parallel. One Head might look at grammatical relationships and another at semantic relationships, seeing multiple perspectives at once.
END: Use the Query to look up Keys and blend the Values by relevance. The model decides on its own where in the sentence to look.

#### Why Transformers Replaced RNNs
ONE: A **Transformer** processes **all positions at once with Self-Attention**, without recurrence. So it allows **parallel training** and learns **relationships between distant words** well, becoming the foundation of LLMs since 2017.
LIKE: An RNN is people standing in a line whispering a message along, so it's slow and the message gets garbled. A Transformer is everyone gathered in one meeting room, all looking at each other at once. But the meeting room has no seating order, so everyone has to wear a number tag (Positional Encoding) to know the order.
STEP:
1. **Parallelization**: An RNN can compute the next word only after finishing the previous one. A Transformer computes all words simultaneously, keeping the GPU fully busy.
2. **Distant relationships**: An RNN passes along a relationship between words 100 apart through 100 steps. In a Transformer, any two positions are connected in **a single step**.
3. **Scaling**: Performance keeps rising as the model·data grow, which made large language models (LLMs) possible.
4. **Weakness**: It compares every pair, so the Attention cost is **O(n²)** in the sentence length n. It's expensive for long documents.
5. **Why Positional Encoding is needed**: If you shuffle the word order, Self-Attention gives the same results, just in shuffled positions. To distinguish "dog bites man" from "man bites dog," you have to add position information. Methods include sine·cosine values (Sinusoidal), learned position Embeddings, and RoPE.
6. **Block structure**: Multi-Head Self-Attention → Feed-Forward Network, with Residual Connection + Layer Normalization at each stage.
7. **Three forms**: Encoder only (BERT, strong at understanding), Decoder only (GPT, strong at generation), both (the original Transformer, T5, translation).
| Comparison | RNN | Transformer |
| How it processes | One at a time, in order | All positions at once |
| Parallelization | Hard | Easy |
| Distant word relationships | Weaker the longer it is | Connected in one step |
| Cost in length n | O(n) sequential | O(n²) Attention |
END: Everyone sees each other at once, so it's fast and catches distant relationships well. But order has to be given by number tags, and long inputs are expensive.

### What is Attention? What are Query·Key·Value?
E: At a library, you compare your question (Query) with the titles on the book spines (Key), read more of the books the more relevant they are, and build an answer by blending those books' contents (Value) in proportion to their relevance.
A: Attention is a method that gathers information by deciding, with learned weights, which of all the other positions the current position should consult and how much. Scaled Dot-Product Attention is Attention(Q, K, V) = softmax(QKᵀ/√dₖ)V: it computes similarity with the Dot Product of the Query and each Key, makes weights with Softmax, and takes the weighted average of the Values, and dividing by √dₖ prevents the Dot Products from growing large and saturating the Softmax. Q·K·V are made by multiplying the same input by different Weight Matrices (Self-Attention), and using several sets in parallel is Multi-Head Attention.

### Why did Transformers replace RNNs? Why is Positional Encoding needed?
E: An RNN is people standing in a line whispering a message along, so it's slow and the message gets garbled, while a Transformer is everyone gathered in one meeting room, all looking at each other at once. But the meeting room has no seating order, so everyone has to wear a number tag (Positional Encoding) to know the order.
A: A Transformer processes all positions at once with Self-Attention, without recurrence, so it can train in parallel on GPUs; any two positions are connected in a single step, so it learns Long-Range Dependencies well; and performance keeps rising as the model·data grow. In exchange, the Attention cost is O(n²) in the Sequence length n. Self-Attention is an operation where reordering the input just reorders the output the same way (Permutation Equivariant), so it has no order information, and position information is added with methods like Sinusoidal Positional Encoding, learned Positional Embeddings, and RoPE.

## Generative Models and Learning from Little Data

#### Generative Models: GAN · Autoencoder · VAE
ONE: A **Generative Model** **creates new data** instead of classifying it. A **GAN** does it through a contest between a forger and the police, an **Autoencoder** by compressing and reconstructing, and a **VAE** by making the compressed space a probability distribution and sampling new examples from it.
LIKE: A GAN is a contest between a counterfeiter (Generator) and the police (Discriminator). The better the police get at catching fakes, the more the counterfeiter's skills improve, until bills come out that look real. An Autoencoder is practice in boiling a long article down to a one-line summary and then writing it back out in full.
STEP:
1. **The GAN's Generator**: Takes random noise and produces fake samples (images).
2. **The GAN's Discriminator**: Judges whether something is real or fake.
3. The two compete to beat each other (Minimax Game) and improve together.
4. **GAN pros and cons**: It produces sharp images, but training is unstable and **Mode Collapse**, where it produces only similar things, can occur.
5. **Autoencoder**: The Encoder compresses the input into a small Vector (Latent), and the Decoder reconstructs it. It's trained to reduce the reconstruction error. Used for dimensionality reduction, noise removal, and anomaly detection (if reconstruction goes poorly, it's an anomaly).
6. **VAE**: The Encoder outputs the **distribution (mean·variance)** of the Latent, trained so that distribution stays close to a standard normal distribution. So you can pick any point in that space, feed it to the Decoder, and get new data.
7. **Boltzmann Machine**: A probability model that makes lower-Energy states appear more often. The Deep Belief Network (2006), built by stacking simplified RBMs and pretraining them layer by layer, was one of the triggers of Deep Learning's revival. It's rarely used now.
8. **These days**: For image generation, Diffusion Models, which create a picture by removing noise a little at a time, have become mainstream, and text generation is handled by Transformer LLMs.
END: Creating through competition is a GAN, compressing·reconstructing is an Autoencoder, and creating by sampling from the compressed space is a VAE.

#### Transfer Learning and Learning from Little Data
ONE: **Transfer Learning** **reuses the knowledge of a model pretrained** on large data **for a new task**. It addresses Neural Networks' biggest weakness: "they need lots of data."
LIKE: Someone who plays piano doesn't learn the organ from scratch. They keep their finger technique and just learn the pedals. And just as a child can recognize a giraffe at the zoo after seeing a single photo of one, there are also ways to learn from few examples (One-Shot).
STEP:
1. **Neural Networks' weaknesses**: They need lots of labeled data, computation is expensive, and they're hard to interpret.
2. **Pre-training**: First learn general knowledge from large data like ImageNet (images) or web text.
3. **The Feature Extraction approach**: Freeze the pretrained body (Backbone) and train only the last Layer for the new task. Good when data is very scarce.
4. **The Fine-tuning approach**: With a small Learning Rate, gradually adjust some or all of the Weights to fit the new data.
5. **PEFT (LoRA, etc.)**: Huge models are too expensive to adjust in full, so only a small number of added Parameters are trained.
6. **One-Shot / Few-Shot Learning**: Learning from 1 (or a few) examples per Class. The Siamese Network (face recognition), which learns a distance for judging "are these two photos the same person?", is the classic example.
7. **In-Context Learning in LLMs**: Showing just a few examples in the Prompt lets the model perform the task without changing its Weights.
END: Bring in knowledge pretrained on large data and adjust it a little, and you get high performance even with little data.

### What is a Boltzmann Machine?
A: A Boltzmann Machine is an Energy-Based Model in which binary stochastic Units are connected by symmetric Weights, defining the probability of a state x as P(x) ∝ exp(−E(x)) so that lower-Energy states appear more often. General Boltzmann Machines are very hard to train, so the approach used was the RBM (Restricted Boltzmann Machine), with connections only between the Visible Layer and the Hidden Layer, trained approximately with Contrastive Divergence (CD), and the layer-by-layer Pre-training of the Deep Belief Network built by stacking RBMs (2006) became a trigger for Deep Learning's revival. Today it has been overtaken by other Generative Models and is rarely used.

### What are the Generator and Discriminator in a GAN? What are the Autoencoder and VAE?
E: A GAN is a contest between a counterfeiter (Generator) and the police (Discriminator). The better the police get at catching fakes, the more the counterfeiter's skills improve, until bills come out that look real. An Autoencoder is practice in boiling a long article down to a one-line summary and then writing it back out in full.
A: In a GAN (Generative Adversarial Network), the Generator G turns random Noise z into fake samples and the Discriminator D tells real from fake; the two play the game (Minimax) min_G max_D E[log D(x)] + E[log(1 − D(G(z)))], and it produces sharp samples, but training is unstable and Mode Collapse, where it produces only similar things, can occur. An Autoencoder reduces the Reconstruction Error by having the Encoder compress the input into a low-dimensional Latent Vector and the Decoder reconstruct it, and it's used for Dimensionality Reduction·Denoising·Anomaly Detection. A VAE (Variational Autoencoder) has the Encoder output the distribution (mean·variance) of the Latent Variable and Samples with the Reparameterization Trick, minimizing the Reconstruction Error together with a KL term that keeps the Latent distribution close to the Standard Normal (maximizing the ELBO), so new data can be generated by sampling from the Latent Space.

### Is it okay to apply BN on the Generator side of a GAN too?
A: You can, and the well-known DCGAN used BN in both the Generator and the Discriminator, except for the Generator's Output Layer and the Discriminator's Input Layer, to stabilize training. However, BN shares statistics among samples in the same Batch, so generated results influence each other depending on the Batch composition, small Batches at inference can cause problems, and feeding a mix of real·fake samples into the Discriminator contaminates the statistics. That's why recent models often use alternatives like Instance Normalization, AdaIN·Weight Modulation (StyleGAN), and Spectral Normalization in the Discriminator.

### What is the biggest drawback of Neural Networks? What is One-Shot Learning?
E: A child can recognize a giraffe at the zoo after seeing a single photo of one. An ordinary Neural Network needs thousands of giraffe photos.
A: The biggest drawback is that they need lots of Labeled data (along with computational cost and difficulty of interpretation). One-Shot Learning is recognizing a new Class from just one example per Class (Few-Shot: a few), either by learning a distance (Similarity) for judging "are these two inputs the same?" like a Siamese Network and comparing against a single registered photo (face recognition), or by learning "how to learn quickly" with Prototypical Networks·Meta-Learning (MAML). These days, Transfer Learning from huge Pre-trained Models and examples in an LLM's Prompt (In-Context Few-Shot) are also ways of solving the same problem.

### What are Transfer Learning and Fine-tuning?
E: Someone who plays piano doesn't learn the organ from scratch; they keep their finger technique and just learn the pedals.
A: Transfer Learning is reusing the knowledge of a model pretrained on large data like ImageNet or web text for a new task. There's the Feature Extraction approach, which Freezes the Backbone and trains only the last Layer anew, and Fine-tuning, which adjusts some or all of the Weights to the new data with a small Learning Rate; for large models, PEFT (Parameter-Efficient Fine-Tuning) such as LoRA, which trains only some Parameters, is used. The key advantage is high performance even with little data.

## Implementation and Tools

#### PyTorch and TensorFlow, and Debugging Tips
ONE: **PyTorch** builds the computation Graph the moment the code runs, so it **feels natural like Python and is easy to debug**, making it the mainstream for research, while **TensorFlow**'s strengths are Keras and its **deployment tools**. Today the differences have narrowed a lot.
LIKE: PyTorch is cooking while tasting and adjusting as you go, while TensorFlow (1.x) was writing out the whole recipe in advance and cooking it all at once. Today both support both styles.
STEP:
1. **PyTorch**: Define-by-Run (builds the Graph while running). You can use print·debuggers just like ordinary Python code. Since 2.x it also does Graph optimization with `torch.compile`.
2. **TensorFlow**: 1.x used a Static Graph, and since 2.x immediate execution (Eager) is the default. Its strengths are deployment tools like Keras, TF Serving, and TF Lite (mobile).
3. **Debugging tip ① Overfit a small Batch**: Deliberately make it memorize a few data points and check that the Loss goes nearly to 0. If it doesn't, there's a Bug in the model or the Loss code.
4. **② Check the initial Loss**: For a 10-Class Softmax, the initial Loss should be about ln 10 ≈ 2.3.
5. **③ Look at the data**: Plot input images and Labels yourself to confirm they match up.
6. **④ Print Shape·dtype·device**, and watch Gradient sizes and NaNs.
7. **Common mistakes**: Forgetting to switch `model.train()`/`eval()`, missing `optimizer.zero_grad()`, applying Softmax twice.
8. Fix the Seed for reproducibility, and when something's wrong, try changing the Learning Rate first.
END: PyTorch was strong for research and TensorFlow for deployment tools, but the gap has narrowed. Start Debugging with "try making it memorize a small amount of data."

### What are the characteristics of TensorFlow and PyTorch, and how do they differ?
A: PyTorch uses a Dynamic approach (Define-by-Run) where the Graph is built the moment the code runs, so it feels natural like Python and is easy to debug, making it the mainstream for research and recent open-source models, and since 2.x it also does Graph optimization with `torch.compile`. TensorFlow used a Static Graph in 1.x, but since 2.x Eager Execution is the default and Graphs are built with `tf.function`, and its strengths are the high-level API Keras and deployment tools like TF Serving·TF Lite·TF.js. Today the feature differences have narrowed a lot, so you choose based on your team and deployment environment.

### What are your Debugging tips when using TF·PyTorch?
A: First, deliberately overfit a single small Batch and check that the Loss goes down nearly to 0 (if not, there's a Bug in the model·Loss code), and check that the initial Loss matches the expected value (about ln 10 ≈ 2.3 for a 10-Class Softmax). Visualize input images and Labels yourself to check the Data Pipeline, print Tensor shape·dtype·device, and Monitor Gradient sizes and NaNs (`torch.autograd.set_detect_anomaly`). Common mistakes are switching `model.train()`/`eval()`, missing `optimizer.zero_grad()`, and applying Softmax twice; fix the Seed to ensure Reproducibility, and try changing the Learning Rate first.

### How many lines and how many hours would it take to build an MNIST MLP Classifier in numpy? How many lines is Backpropagation, and what if you switch to a CNN? With a Framework?
A: This isn't a question with a set answer but one that probes implementation experience, so answer with estimates reviewed component by component. A 1-Hidden-Layer MLP, covering data loading·One-Hot conversion·Initialization·Forward Pass (ReLU, Softmax)·Cross-Entropy·Backpropagation·the Mini-Batch SGD Loop·Accuracy calculation, is roughly 50–100 lines, and of that, Backpropagation is 2–3 lines per Layer, around 10 lines total, because the Gradient of Softmax+Cross-Entropy simplifies to "prediction − answer." Someone who knows the concepts can reach about 97–98% Test Accuracy within 1–3 hours, with most of the time spent on shape mistakes and Gradient Debugging. Switching to a CNN means writing the Forward·Backward of Convolution and Pooling yourself (im2col, etc.), adding roughly several dozen to 100 more lines, and it's slower too. With PyTorch·Keras, Datasets·Layers·Autograd are provided, so 30–50 lines and, once you're familiar, tens of minutes to an hour is enough.

## GPUs and Resources

#### Why GPUs Are Fast, and Using Multiple GPUs
ONE: Most Neural Network computation is **Matrix multiplication with enormous numbers of independent multiplications·additions**, so GPUs, which compute **with thousands of Cores at once**, are far faster. Multiple GPUs are used by **splitting the data (Data Parallel)** or **splitting the model (Model Parallel)**.
LIKE: A CPU is a few chefs who are good at everything; a GPU is thousands of kitchen assistants who only peel potatoes. If you need ten thousand potatoes peeled, the latter is far faster.
STEP:
1. **CPU**: A few to a few dozen powerful Cores that handle complex tasks quickly.
2. **GPU**: Thousands of Cores doing simple computations + far wider Memory Bandwidth than a CPU.
3. In Matrix multiplication, each cell's computation is independent of the others, so thousands of Cores can process them simultaneously.
4. **Tensor Cores and Mixed Precision**: Speed up Matrix multiplication further with smaller number formats like FP16·BF16.
5. **Data Parallelism**: Copy the model to each GPU, split the Batch and compute, then average the Gradients (All-Reduce) so all update to the same Weights. Used when the model fits on one GPU. PyTorch recommends DistributedDataParallel (DDP).
6. **Model Parallelism**: When the model doesn't fit on one GPU, split up the Layers (Pipeline) or split a single Layer's Matrix across GPUs (Tensor).
7. **FSDP·ZeRO**: Save Memory by splitting the Parameters·Gradients·Optimizer State across the GPUs.
END: There's an enormous amount of independent computation, so GPUs with many Cores are fast. With several, split the data or split the model.

#### Calculating the GPU Memory Needed for Training
ONE: Training Memory = **Parameters + Gradients + Optimizer State + Activations**. With FP32 and Adam, it takes about **16 Bytes** per Parameter.
LIKE: To run a plant, you need space not just for the machines (Parameters) but also for the notes on what to fix (Gradients), the work logs (Optimizer State), and the intermediate products piled up at each station (Activations).
STEP:
1. **Parameters**: 4 Bytes each in FP32.
2. **Gradients**: One per Parameter, 4 Bytes.
3. **Adam's Optimizer State**: Two values, m and v, 8 Bytes.
4. **Total**: About 16 Bytes × the number of Parameters. A 1-billion-Parameter model needs about 16GB even excluding Activations.
5. **Activations**: Intermediate outputs saved for use in Backpropagation. They grow in proportion to the Batch Size·sentence length·number of Layers.
6. **Inference**: Generally needs only the Parameters. Loading a 7-billion-Parameter model in FP16 (2 Bytes) takes about 14GB, and LLMs add a KV Cache.
7. **When it doesn't fit**: Reduce the Batch, Mixed Precision (FP16·BF16), Gradient Checkpointing, which recomputes Activations, Gradient Accumulation, which accumulates Gradients over several small Batches, and Quantization, which stores numbers in smaller formats.
END: Training takes about 16 Bytes per Parameter + Activations; inference takes roughly the size of the Parameters.

### Why is it good to use GPUs for Deep Learning?
E: A CPU is a few chefs who are good at everything; a GPU is thousands of kitchen assistants who only peel potatoes. If you need ten thousand potatoes peeled, the latter is far faster.
A: Most Neural Network operations are Matrix Multiplications with enormous numbers of independent multiplications·additions, and GPUs process them simultaneously with thousands of Cores, with far wider Memory Bandwidth than CPUs too. Tensor Cores further accelerate FP16·BF16 Mixed Precision Matrix multiplication, and optimized Libraries like CUDA·cuDNN make training tens of times faster or more.

### What if you want to use both of two GPUs? (Data Parallelism vs Model Parallelism)
A: Data Parallelism copies the model to both GPUs, splits the Batch in half to compute, then averages the Gradients (All-Reduce) to update to the same Weights; it's used when the model fits on one GPU, and in PyTorch DistributedDataParallel (DDP) is recommended over DataParallel. Model Parallelism is used when the model doesn't fit on one GPU, either splitting up the Layers (Pipeline Parallelism) or splitting a single Layer's Matrix across GPUs (Tensor Parallelism), and FSDP·ZeRO, which split the Parameters·Gradients·Optimizer State across the GPUs, are also widely used.

### How do you calculate the GPU Memory needed for training?
A: Training Memory is Parameters + Gradients + Optimizer State + Activations (intermediate outputs saved for Backpropagation). With FP32 and Adam, it's Parameter 4 Bytes + Gradient 4 Bytes + Adam's m·v 8 Bytes, about 16 Bytes per Parameter, so a 1-billion-Parameter model needs about 16GB even excluding Activations, and Activations grow in proportion to the Batch Size·Sequence length·number of Layers. Inference generally needs only the Parameters, so loading a 7-billion-Parameter model in FP16 takes about 14GB (+ a KV Cache for LLMs), and when it doesn't fit, use a smaller Batch, Mixed Precision, Gradient Checkpointing, Gradient Accumulation, or Quantization.
