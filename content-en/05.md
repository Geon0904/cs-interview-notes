## Concepts Shared by All Languages

#### How Programming Languages Run: Compile · Interpret · Bytecode
ONE: There are three ways to turn human-written code into machine code the CPU understands: **translate it all in advance (Compile)**, **interpret it while running (Interpret)**, and the in-between approach, **Bytecode + a Virtual Machine**.
LIKE: Compiling is translating a whole book in advance, and Interpreting is having an interpreter next to you translating each sentence on the spot. A translated book is fast to read, and an interpreter can start right away.
STEP:
1. The CPU understands only machine code (instructions made of 0s and 1s). Human-written code (Source Code) must always be translated.
2. **Compiled Languages (C, C++, Rust, Go)**: Before running, a Compiler translates the whole Source into a machine-code executable. It runs fast and catches many errors before running. In exchange, you must Compile again after every change.
3. **The Interpreted approach**: Code is interpreted while it runs. You can change it and run it immediately, so development is fast. In exchange, it runs slowly.
4. **The in-between approach (Java, Python)**: Source is first turned into an intermediate language called **Bytecode**, and a **Virtual Machine (VM)** runs that Bytecode. Bytecode is not tied to a specific CPU, so the same code runs on many OSes.
5. **JIT (Just-In-Time) Compilation**: A technique that speeds things up by turning frequently used parts into machine code on the fly while the program runs. Java's JVM, JavaScript engines, and PyPy use it.
WHY: You pick a language and execution style based on whether "fast to run" or "fast to develop" matters more.
END: Translating everything in advance is Compiling (fast to run); interpreting while running is Interpreting (fast to develop). Python and Java take the in-between approach where a VM runs Bytecode.

#### Type Systems: Static vs Dynamic, Strong vs Weak
ONE: **Static/Dynamic** is about "**when** is the Type decided (before running vs while running)," and **Strong/Weak** is about "does it **freely mix** different Types for you?"
LIKE: Static Typing is writing "apples only" on a box in advance, while Dynamic Typing decides what kind of box it is the moment you put something in. Strong Typing refuses when you ask it to add an apple and a number, while Weak Typing converts one on its own and adds them anyway.
STEP:
1. **Type**: The kind of a value: integer (int), floating-point number (float), string (str), and so on.
2. **Static Typing (Java, C++, Go)**: A Variable's Type is decided at Compile time: `int x = 3;`. If Types do not match, you get an error before running.
3. **Dynamic Typing (Python, JavaScript)**: The Type is decided at runtime when a value comes in. `x = 3` followed by `x = "hi"` is fine.
4. **Strong Typing (Python)**: Different Types are not converted automatically. `"1" + 1` is a TypeError.
5. **Weak Typing (JavaScript)**: Converts on its own to compute. `"1" + 1` becomes `"11"`. Convenient, but it easily produces unexpected results.
6. The two criteria are independent. Python is **Dynamic + Strong**, JavaScript is **Dynamic + Weak**, and Java is **Static + Strong**.
PRO: Static catches errors in advance and makes tools (autocomplete) smarter. Dynamic lets you write short, flexible code.
CON: Static makes code longer, and with Dynamic you only find Type errors by running the code.
USE: Even in Python, writing **Type Hints** like `def add(a: int, b: int) -> int:` and checking them with a tool like mypy gets you some of the benefits of Static Typing.
END: Static/Dynamic is "when is it decided"; Strong/Weak is "does it freely mix." Python decides at runtime but does not freely mix.

#### Variables Are Name Tags: References and Argument Passing
ONE: In Python, a Variable is not a box that holds a value but **a name tag stuck on an Object**. When you pass it to a function, it also makes one more "name tag pointing to the same Object" (**Call by Object Reference**).
LIKE: `b = a` does not copy the object; it sticks one more sticky note on the same object. So if you change the object through b, it is changed when you look through a too. But if you peel off the b sticky note and stick it on another object, a stays the same.
STEP:
1. `a = [1, 2]` creates a list Object and sticks the name tag `a` on it.
2. `b = a` sticks one more name tag, `b`, on the same list. It is not a copy.
3. If you change the object with `b.append(3)`, looking through `a` also shows `[1, 2, 3]`.
4. `b = [9]` peels off the `b` name tag and sticks it on a new list. `a` still points to the original list.
5. **Function Arguments**: When you pass `a` to a function, the Parameter inside the function becomes a new name tag on the same Object.
6. So if you **modify** the list inside the function, the change is visible outside, but if you **assign a new Object** to the Parameter, the outside stays the same.
```python
def change(lst):
    lst.append(4)   # modifies the same list → visible outside too
    lst = [0]       # moves the name tag to a new list → outside unchanged

a = [1, 2, 3]
change(a)
print(a)  # [1, 2, 3, 4]
```
KEY: In other languages' terms, C uses **Call by Value** (passing a copy), and C++ references (&) are **Call by Reference** (passing the variable itself). Python is neither; it is **Call by Sharing**, "passing the Reference by value."
WHY: Without knowing this, you cannot understand Bugs like "I passed it to a function and the original changed" or "I changed it but it didn't change."
END: Variables are name tags. Modify the object and every name tag sees it; move a name tag and only that tag changes.

#### Garbage Collection (Automatic Memory Cleanup)
ONE: A feature where **the language automatically finds Objects nobody uses anymore and reclaims their Memory**. The main approaches are **Reference Counting** and **Tracing**.
LIKE: Reference Counting is counting "how many name tags are stuck on this object" and throwing it away the moment it hits 0. Tracing is occasionally walking the whole warehouse and clearing out, all at once, "objects that aren't connected to anything."
STEP:
1. In C, you had to `free` Memory you borrowed with `malloc` yourself. Forget, and you get a Memory Leak; do it twice, and you get a Double Free.
2. **Reference Counting**: Each Object counts "how many References point to me." It is freed the moment the count hits 0. Cleanup is immediate, which is nice.
3. Weakness: If A points to B and B points to A (**Circular Reference**), each keeps the other's Count at 1, so they are never deleted even if nobody outside uses them.
4. **Tracing GC (Mark-and-Sweep)**: Starting from the points the program is definitely using (Roots: global variables, variables of running functions), it marks (Mark) every Object it can reach and sweeps up the unmarked ones (Sweep). It can clean up Circular References too.
5. **Generational GC**: Uses the observation that "most Objects are thrown away quickly" to check newly created Objects often and long-surviving Objects only occasionally.
6. **CPython** uses Reference Counting by default, and Circular References are handled periodically by a Generational GC (the `gc` module). Java uses Tracing GC.
PRO: Programmers do not have to worry about freeing Memory, which greatly reduces Memory errors.
CON: Cleanup takes time, and a Tracing GC can briefly pause the program while it cleans (Stop-the-World).
END: GC is "a janitor that automatically clears away unused things." Python uses name-tag counting (Reference Counting) plus a cleanup (GC) for Circular References.

### What is the difference between Compiled and Interpreted Languages?
E: Compiling is translating a whole book in advance; an Interpreter is an interpreter next to you translating each sentence on the spot. A translated book is fast to read, and an interpreter can start right away.
A: Compiled Languages (C, Rust) translate Source into machine code before running, so they run fast and catch errors in advance. The Interpreter approach interprets code while running, so development·changes are fast but execution is slow. In practice, many fall in between: Java and Python Compile to Bytecode, which a Virtual Machine then runs.

### What are Static Typing vs Dynamic Typing and Strong Typing vs Weak Typing?
E: Static Typing is writing "apples only in this box" in advance; Dynamic Typing decides the kind the moment you put something in. Strong Typing refuses when you ask it to add an apple and a number, while Weak Typing converts one on its own and adds them anyway.
A: In Static Typing (Java, C++), a Variable's Type is decided at Compile time; in Dynamic Typing (Python, JavaScript), it is decided at runtime by the value. Python is Dynamic but Strongly Typed, so `"1" + 1` is a TypeError, while JavaScript is Weakly Typed, so it becomes `"11"`.

### What are Call by Value, Call by Reference, and Python's Argument passing?
E: Call by Value hands over a copy, and Call by Reference hands over the original itself. Python "makes one more name tag stuck on the same object." If you modify the object inside the function, it changes outside too, but if you move the name tag to another object, the outside stays the same.
A: Call by Value passes a copy of the value, so changes inside the function do not affect the outside; Call by Reference passes the Variable itself, so changing it inside also changes it outside. Python is Call by Object Reference (Call by Sharing), passing a Reference to the Object by value, so modifying a Mutable Object like a list inside is visible to the caller, but assigning a new Object to the Parameter does not change the outside Variable.
```python
def change(lst):
    lst.append(4)   # modifies the same list → visible outside too
    lst = [0]       # moves the name tag to a new list → outside unchanged

a = [1, 2, 3]
change(a)
print(a)  # [1, 2, 3, 4]
```

### What are the approaches to Garbage Collection?
E: Reference Counting is counting "how many name tags are stuck on each object" and throwing it away the moment it hits 0; Tracing is occasionally walking the warehouse and clearing out, all at once, "objects not connected to anyone."
A: Reference Counting frees an Object the moment the number of References pointing to it hits 0, but cannot clean up Circular References that point to each other. Tracing GC (Mark-and-Sweep, Generational GC) finds and frees Objects unreachable from the Roots. CPython uses Reference Counting by default and handles Circular References with a Generational Cyclic GC (the gc module).

## Python Language Characteristics

#### Python's Features and How It Runs
ONE: Python is a general-purpose language with **easy-to-read syntax**, **automatic Memory management**, and a **huge collection of Libraries**. Code is turned into Bytecode and then run by the Python Virtual Machine.
LIKE: Python is like a car with an automatic transmission. The car shifts the gears (Memory management, resizing data structures) for you, so driving is easy. In exchange, it is hard to reach the extreme speeds of someone skilled with a manual transmission (C).
STEP:
1. **Easy-to-read syntax**: Blocks are marked by **Indentation** instead of curly braces. That is why wrong indentation causes an IndentationError.
2. **What the language does for you**: Something that takes dozens of lines in C takes a few lines in Python, because the language handles freeing Memory, lists that grow automatically, dicts that are Hash Tables, and integers that can grow without limit.
3. **How it runs**: `.py` Source → Compiled to Bytecode (imported Modules are saved as `.pyc` in the `__pycache__` folder) → the **Python Virtual Machine** runs the Bytecode one instruction at a time.
4. It does not create a separate machine-code executable, so it is called an "Interpreted Language." The common explanation that "it interprets one line at a time" is not accurate. It first turns the whole thing into Bytecode and then runs it.
5. **The price is speed**: The same calculation in pure Python is much slower than in C. So heavy computation is usually handed off to Libraries written in C (NumPy, etc.).
6. **Python vs CPython**: Python is the language's rules (specification), and **CPython** is the standard Interpreter that implements those rules in C (the one you download from python.org). Others include **PyPy**, which is fast thanks to JIT, and **MicroPython** for small devices. Features like the GIL and the Small Integer Cache are how CPython is implemented.
USE: Widely used for data analysis, AI (PyTorch, TensorFlow), web servers (Django, FastAPI), work-automation Scripts, and education.
END: Python is a language that "gained development speed by giving up a little execution speed," and it makes up for heavy computation with Libraries written in C.

#### Python Code Style: PEP 8 · Comments · Docstrings
ONE: **PEP 8** is Python's official code style guide, and you explain code with `#` **Comments** and **Docstrings** on the first line of functions·Classes.
LIKE: If classmates agree on note-taking rules (titles in red, the date in the top right), they can read each other's notebooks quickly. PEP 8 is the note-taking rule set for Python developers.
STEP:
1. **Indentation**: 4 Spaces.
2. **Naming**: Functions·Variables use `snake_case` (lowercase + underscores), Classes use `CapWords` (capitalize the first letter of each word), and constants use `UPPER_CASE`.
3. **Line length**: Keeping lines under 79 characters is recommended (some teams allow longer).
4. **Case Sensitive**: `name` and `Name` are different Variables.
5. **Comments**: Written after `#`. For multi-line Comments, the standard is to put `#` on each line.
6. **Docstring**: A `"""description"""` string written on the very first line of a function·Class·Module. You can read it with `help(function)` or `function.__doc__`. The difference is that triple quotes are a string, not a Comment.
USE: Tools like black, ruff, and flake8 automatically check and tidy code according to PEP 8.
WHY: Code is read far longer than it takes to write. When everyone writes in the same style, you can read other people's code as quickly as your own.
END: PEP 8 is Python's shared spelling guide, and explanations go in Comments (#) and Docstrings (""").

It has a rich Standard Library and ecosystem (NumPy, pandas, PyTorch) and runs the same way on many OSes.

## Data Types and Operators

#### Built-in Types and Mutable · Immutable
ONE: Python's basic Types include numbers·strings·list·tuple·dict·set and more. If **its contents can be changed** after creation, it is **Mutable**; if **they cannot**, it is **Immutable**.
LIKE: Mutable is a whiteboard you can erase and rewrite; Immutable is a rubber stamp that cannot be changed once it is made. To change the words on a stamp, you have to carve a new stamp.
STEP:
1. **Numbers**: int (integer), float (floating-point), complex (complex number), bool (True/False).
2. **Ordered collections (Sequences)**: str (string), list, tuple, range.
3. **Key-Value**: dict. **Sets**: set, frozenset.
4. **Nothing**: None.
5. **Mutable**: list, dict, set, bytearray. Their contents can be changed after creation.
6. **Immutable**: int, float, str, tuple, frozenset. When it looks like you are "changing" one, a new Object is actually being created. `s = "hi"; s += "!"` creates a new string and moves the `s` name tag onto it.
7. **Type conversion**: Convert explicitly, like `int("3")`, `str(10)`, `list("abc")`. Mixing int and float gives a float, but str and int are not mixed automatically.
KEY: **dict Keys and set elements must be Hashable (usually Immutable).** A dict decides where to store an entry from the Key's Hash value, so if the Key's contents changed, its Hash would change too and it could never be found again.
WHY: When several name tags share a Mutable Object, a change made through one is visible through the others. Knowing which Types are Mutable lets you avoid these Bugs.
END: If it can change, it is Mutable (list·dict·set); if not, it is Immutable (numbers·str·tuple). Keys must be Immutable.

#### list · tuple · dict · set: When to Use Which
ONE: Use a **list** for an ordered list, a **tuple** for a bundle that does not change, a **dict** for looking things up by name, and a **set** for a collection without duplicates and fast "is it in here?" checks.
LIKE: A list is a grocery list written in order, a tuple is a birth date that never changes once set, a dict is a dictionary where looking up a word gives you its meaning, and a set is a sticker album collected without duplicates.
STEP:
1. **list**: Ordered, and you can freely add·remove·modify. Adding and removing at the end (`append`, `pop()`) is O(1) on average, but adding and removing at the front (`insert(0, x)`, `pop(0)`) is O(n) because every element behind has to shift.
2. **tuple**: Like a list but cannot be changed. Used for fixed bundles like coordinates `(x, y)`, and if every element is Hashable, it can even be a dict Key.
3. **dict**: A Hash Table that finds a Value by Key in O(1) on average. Since Python 3.7, insertion order is preserved. Safely get a missing Key with `d.get(k, default)`.
4. **set**: Removes duplicates automatically, and the `x in s` check is O(1) on average. Union (`|`), intersection (`&`), and difference (`-`) work too.
5. **Speed of "x in container"**: A list checks one by one from the start, so O(n); a set·dict finds it directly by Hash, so O(1) on average.
| Use | What to pick |
| Collect in order and modify often | list |
| Fixed bundle of values, dict Key | tuple |
| Find a value by name (Key) | dict |
| Remove duplicates, fast membership check | set |
| Frequent adding and removing at both ends | collections.deque |
KEY: If you are going to hold lots of numbers and compute with them, a **NumPy Array** is much faster than a list and uses less Memory.
END: Order is list, fixed is tuple, lookup is dict, and removing duplicates and "is it in here?" is set.

#### Indexing and Slicing, Working with Strings
ONE: Use an **Index** to get one element and a **Slice** to get a range. Negative Indexes count from the end, and `[::-1]` makes a new, reversed Sequence.
LIKE: You can count the people in a line from the front as number 0, 1, … or from the back as number −1 (the very end), −2, …. A Slice picks one stretch, like "everyone from number 3 up to just before number 6, please step out."
STEP:
1. **Indexes start at 0**. If `s = "python"`, then `s[0]` is `'p'`.
2. **Negative Index**: Counts from the end. `s[-1]` is the last letter, `'n'`. You can reach the end without knowing the length.
3. **Slice `[start:stop:step]`**: Takes elements from start up to **just before** stop, every step. `s[1:4]` is `'yth'`.
4. If omitted, the defaults are the start·the end·step 1. `s[:2]` is `'py'`, and `s[::2]` is `'pto'`.
5. **`[::-1]`**: The step is −1, so it takes elements backward. It leaves the original alone and makes a new, reversed Sequence.
6. **len()**: Tells you the number of elements. Internally it calls the Object's `__len__`.
7. **String Methods**: `lower()` (lowercase), `upper()` (uppercase), `capitalize()` (only the first letter uppercase), `title()` (first letter of every word uppercase), `split(sep)` (cut into a list), `" ".join(list)` (join a list into one), `strip()` (remove whitespace on both sides).
KEY: Strings are Immutable, so every string Method **returns a new string** instead of changing the original. If you just write `s.upper()` without keeping the result, nothing happens.
END: An Index gets one, a Slice gets a range, negatives count from the end, and `[::-1]` reverses.

#### is and ==, in and not
ONE: **==** asks "is the **value** the same?", and **is** asks "is it **the very same Object**?" **in** asks "is it inside?", and **not** means "the opposite."
LIKE: == asks "do the two books have the same content?", and is asks "are these two literally the same single copy of the book?" Two identically printed books are == but not is.
STEP:
1. If `a = [1, 2]; b = [1, 2]`, then `a == b` is True (same value) and `a is b` is False (different Objects).
2. If `c = a`, then `a is c` is True (two name tags on the same Object).
3. **Compare with None using `is`**: `if x is None:`. None is the only Object of its kind in the program, so is is accurate and fast.
4. **in**: `3 in [1, 2, 3]` → True. A list checks one by one (O(n)), while a set·dict checks directly by Hash (O(1) on average).
5. **not**: Logical negation. `not in` means "is it not inside?"
KEY: Do not use is to compare numbers or strings. CPython creates just one copy of some values, such as the integers −5 to 256, in advance and reuses them (**Interning**), so it sometimes happens to return True, but that is an implementation detail and must not be relied on. Always compare values with ==.
END: Value is ==, identity is is, None is is None, and "is it inside?" is in.

A: There are Numeric (int, float, complex, bool), Sequence (str, list, tuple, range), Mapping (dict), Set (set, frozenset), Binary (bytes, bytearray, memoryview), and None. Of these, list·dict·set·bytearray are Mutable and the rest are Immutable.

### What are Mutable and Immutable Objects, and why must dict Keys be Immutable?
E: If library lockers were assigned by "the number of letters in the owner's name" and the owner changed their name, the locker could never be found again. A Key has to be something that cannot change.
A: A Mutable Object can have its contents changed after creation (list, dict, set), and an Immutable Object cannot, so "changing" it creates a new Object (int, str, tuple). A dict decides an entry's location from the Key's Hash value, so if the Key changed, it could not be found; therefore only Hashable (usually Immutable) Objects can be Keys.

### What is the difference between list and tuple?
E: A list is a whiteboard you can erase and rewrite; a tuple is a rubber stamp that cannot be changed once it is made.
A: A list is Mutable, so elements can be added·removed·modified, and a tuple is Immutable, so it cannot be changed after creation. A tuple can be a dict Key if all its elements are Hashable, and it is a bit lighter. So fixed bundles like coordinates (x, y) use a tuple, and changing lists use a list.

### What is a dictionary in Python?
E: It is a dictionary where looking up a word (Key) immediately gives you its meaning (Value).
A: A dict is a Hash Table that stores Key-Value pairs and finds a Value by Key in O(1) on average. Keys must be Hashable, and since Python 3.7, preserving Insertion Order is part of the language specification. Using `d.get(k, default)` avoids a KeyError on a missing Key.

### What is the difference between Python arrays and lists? How to add / remove values?
E: A list is a junk bag you can throw anything into, and an array is an egg carton with only same-size slots. An egg carton holds only eggs, but it is compact and light.
A: A list can hold Objects of different Types, while an Array from the array module holds only one numeric Type set by a Type Code ('i', 'f', etc.) and uses less Memory. For math, people usually use a NumPy Array. Add with append (one at the end), extend (several), or insert(i, x), and remove with remove(x) (the first one with that value), pop(i) (take out by position and return it), or `del lst[i]`.
M: append and pop() (at the end) are O(1) on average, while insert(0, x) and pop(0) are O(n) because every element behind has to shift. If you take from the front often, use collections.deque.

### What is type conversion in Python?
A: It is turning a value into another Type, done Explicitly with `int("3")`, `float("2.5")`, `str(10)`, `list("abc")`, tuple(), set(), dict(), and so on. There is also Implicit conversion, where mixing int and float as in `1 + 2.0` gives a float, but str and int are not converted automatically and raise a TypeError.

### What are negative indexes? What does [::-1] do? What does len() do?
E: If you count a line from the back, the very last person is number −1. `[::-1]` is a new line formed by "going from start to end, one step at a time, backward."
A: A Negative Index is a position counted from the end, so `lst[-1]` is the last element, which is handy because you can reach the end without knowing the length. `[::-1]` is a Slice with a Step of −1 that makes a new Sequence in reverse order (the original stays the same), and len() returns the number of elements in an Object, calling `__len__` internally.

### What is the purpose of is, not and in operators?
E: == asks "do the two books have the same content?", and is asks "are they literally the same single copy?"
A: is compares whether two Variables are the same Object (Identity), and == compares whether their values are equal (Equality). not is logical negation, and in is the Membership Operator that checks whether an element is in a Container (O(n) for a list, O(1) on average for a set·dict). When comparing with None, use `x is None`.

### How to capitalize the first letter / convert to lowercase? What is split used for?
A: `s.capitalize()` makes the first letter uppercase and the rest lowercase (to leave the rest as is, use `s[:1].upper() + s[1:]`), and `s.title()` capitalizes the first letter of every word. `s.lower()` makes everything lowercase, and casefold() is more accurate for case-insensitive comparison. `s.split(sep)` cuts a String by a Separator into a list, and with no argument it splits on runs of Whitespace. Strings are Immutable, so all of these return a new String.

## Control Flow and Functions

#### Functions and First-Class Objects
ONE: A **Function** is a named bundle of code you can reuse, and in Python a Function is also an Object, so you can **store it in a Variable, pass it around, and return it** (**First-Class Object**).
LIKE: A Function is a recipe card. You can keep the card in a box, hand it to a friend, or give it to another cook and say "make it like this card says."
STEP:
1. It is created with the `def` keyword, takes Arguments, and returns a value with `return`. Without `return`, it returns None.
2. **Store it in a Variable**: After `f = print`, `f("hi")` works.
3. **Pass it as an Argument**: `sorted(words, key=len)` passes the len Function to say "sort by length."
4. **Return it**: A Function can create and return a Function. This is the basis of Closures and Decorators.
5. **Control flow helpers**: `break` exits a loop immediately, `continue` skips just the current iteration, and `pass` does nothing and just fills the spot.
6. **One-line conditional expression (Ternary)**: `label = "adult" if age >= 18 else "minor"`.
WHY: If you can treat Functions like values, you can write flexible code where "what to do" is plugged in later.
END: A Function is a reusable bundle of code, and in Python you can store, pass, and return it like a value.

#### lambda · map · Comprehensions
ONE: A **lambda** is a nameless one-line Function, **map** is a tool that applies the same Function to every element, and a **Comprehension** is Python syntax for writing that in one, more readable line.
LIKE: A lambda is a disposable sticky-note instruction you use once and throw away, and map is a machine that does the same job to each item on a conveyor belt.
STEP:
1. **lambda**: `lambda x: x * 2` is "a Function that takes x and returns x × 2." It can contain only one Expression.
2. It is mostly used to pass something short: `sorted(people, key=lambda p: p["age"])` sorts by age.
3. **map(function, iterable)**: Applies the Function to each element. It is a Lazy Iterator that does not build the results right away but makes them one at a time when needed, so if you need a list, wrap it in `list(map(...))`.
4. **filter(function, iterable)**: Keeps only the elements where the condition is True.
5. **List Comprehension**: Writes "transform + condition" in one line, like `[x * 2 for x in nums if x > 0]`. It is easier to read than map·filter, so it is used more in Python.
6. It works for dicts and sets too: `{k: v for k, v in pairs}`, `{x % 3 for x in nums}`.
```python
nums = [1, -2, 3]
doubled = list(map(lambda x: x * 2, nums))   # [2, -4, 6]
positive_doubled = [x * 2 for x in nums if x > 0]  # [2, 6]
```
KEY: If a Comprehension gets so complex it runs past one line, writing it out as a for loop reads better.
END: A lambda is a disposable Function, map is "the same job for everyone," and a Comprehension is a more readable way to write it.

#### *args and **kwargs
ONE: **`*args`** collects an unspecified number of positional Arguments **into a tuple**, and **`**kwargs`** collects named Arguments **into a dict**.
LIKE: `*args` is "putting everything you received into a bag in order," and `**kwargs` is "putting every labeled item into the drawer with its name."
STEP:
1. If defined as `def f(*args)`, the Arguments of `f(1, 2, 3)` come in as `args = (1, 2, 3)`.
2. If defined as `def f(**kwargs)`, `f(a=1, b=2)` comes in as `kwargs = {"a": 1, "b": 2}`.
3. The names `args` and `kwargs` are just conventions; what matters is `*` and `**`.
4. **Unpacking when calling**: `f(*[1, 2])` is the same as `f(1, 2)`, and `f(**{"a": 1})` is the same as `f(a=1)`.
5. It is especially useful for passing received Arguments straight to another Function: `def wrapper(*args, **kwargs): return func(*args, **kwargs)`.
USE: Used for Functions that take any number of Arguments like `print()`, for Decorators, and for passing Arguments straight through to a parent Class's `__init__`.
END: `*` gathers in order into a tuple, `**` gathers by name into a dict. Used when calling, they unpack in reverse.

#### Decorators
ONE: A Function that takes a Function and **returns a new Function with extra behavior added**. Writing `@name` above a Function adds behavior without changing the original code.
LIKE: It is leaving the gift (Function) as it is and wrapping it in paper. The wrapping paper takes care of things like "time how long it takes before opening" or "check whether you're allowed to open it."
STEP:
1. Because Functions are Objects, a Function can take a Function as an Argument and create and return a new Function.
2. A Decorator creates a `wrapper` Function that wraps the original Function. The wrapper does extra work before and after and calls the original Function in the middle.
3. Writing `@timer` above `def work():` makes Python run `work = timer(work)` for you.
4. Now when you call `work()`, it is actually the wrapper that runs.
5. Adding `functools.wraps` keeps the original Function's name and Docstring.
```python
import functools, time

def timer(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = func(*args, **kwargs)      # run the original Function
        print(f"{func.__name__}: {time.perf_counter() - start:.3f}s")
        return result
    return wrapper

@timer          # work = timer(work)
def work():
    time.sleep(0.1)
```
USE: Used for measuring run time, Logging, checking logins (`@login_required` in web Frameworks), saving results (`@functools.lru_cache`), and mapping URLs (Flask's `@app.route("/")`).
WHY: Work that many Functions need in common can be managed in one place instead of being copied into each Function.
END: A Decorator wraps a Function in paper, and `@deco` is shorthand for `func = deco(func)`.

#### Closures and the Default Argument Trap
ONE: A **Closure** is when an inner Function **remembers the Variables of the Function that encloses it** and keeps using them. And Default Arguments have a trap: they are created **only once, when the Function is defined**.
LIKE: A Closure is a Function carrying the things from the room it was born in, in its backpack. The Default Argument trap is when the store says "you get an empty shopping basket by default," but it turns out every customer is passed the same single basket.
STEP:
1. **Closure example**: Inside `def counter(): n = 0`, create `def inc(): nonlocal n; n += 1; return n` and return `inc`.
2. Even though `counter()` has already finished, the returned `inc` remembers `n` and returns 1, 2, 3 each time you call it.
3. This lets you make Functions that quietly carry state, so it is used to express simple state without a Class. Decorators also work through Closures.
4. **The Default Argument trap**: In `def add(x, lst=[])`, the `[]` is created **exactly once, when the Function is defined**.
5. So `add(1)` → `[1]`, then `add(2)` → `[1, 2]`: the same list keeps piling up between calls.
6. **Fix**: Make the default None and create a new one inside.
```python
def add(x, lst=None):
    if lst is None:
        lst = []        # a new list on every call
    lst.append(x)
    return lst
```
KEY: Do not use Mutable Objects like list·dict·set directly as Default Arguments. It is a classic interview question.
END: A Closure is "a Function that remembers the Variables of where it was born," and since Default Arguments are created only once, replace Mutable defaults with None.

### What are functions in Python?
A: A Function is a reusable bundle of code defined with def; it takes Arguments and returns a value with return, and returns None if there is no return. In Python, Functions are First-Class Objects, so they can be stored in Variables or used as another Function's Arguments·Return Values.

### How does break, continue and pass work?
E: When running 10 laps around the track, break is "I'm done working out today," continue is "skip this lap and go to the next," and pass is "do nothing and just keep going."
A: break immediately exits the nearest Loop, and continue skips the rest of the current iteration and goes to the next one. pass is a Statement that does nothing, used as a placeholder for an empty Function·Class·if Block where the syntax requires a Statement.

### How can the ternary operator be used in Python?
A: Python's Ternary Operator has the form `value_if_true if condition else value_if_false`. For example, `label = "adult" if age >= 18 else "minor"` picks a value based on a condition in one line.

### What is a lambda function? What is the map function?
E: A lambda is a disposable sticky-note instruction with no name tag that you use once and throw away, and map is a machine that does the same job to each item on a conveyor belt.
A: A lambda is an Anonymous Function with just one Expression, like `lambda x: x * 2`, used to pass something short, as in `sorted(…, key=lambda p: p[1])`. `map(function, iterable)` returns a Lazy Iterator that applies the Function to each element, so wrap it in list() if you need a list. For simple cases, the List Comprehension `[x * 2 for x in xs]` is easier to read.

### What does *args, **kwargs mean? Why would we use it?
E: `*args` is "putting everything you received into a junk bag in order," and `**kwargs` is "putting every labeled item into the drawer with its name."
A: `*args` receives an unspecified number of Positional Arguments as a tuple, and `**kwargs` receives an unspecified number of Keyword Arguments as a dict. They are used for Functions with a variable number of Arguments and for Decorators·Wrappers that pass received Arguments straight to another Function. When calling, you can also pass them unpacked (Unpacking), as in `f(*lst, **d)`.

### What are decorators in Python?
E: It is wrapping the gift (Function) in paper without changing it. The wrapping paper adds things like "time how long it takes before opening" or "check whether you're allowed to open it."
A: A Decorator is a Function that takes a Function as an Argument and returns a new Function with extra behavior; writing `@name` above a Function is the same as `func = name(func)`. It is used to attach common features like Logging·measuring run time·permission checks·Caching (`functools.lru_cache`) without changing the original code. Use `functools.wraps` to keep the original Function's name·Docstring.
```python

    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = func(*args, **kwargs)

def work():
    time.sleep(0.1)
```

A: A Closure is a Function where the inner Function remembers the Variables of the Function enclosing it, so it can use those values even after the outer Function has finished. A Default Argument is created exactly once, when the Function is defined, so using a Mutable Object as in `def f(x, lst=[])` makes the same list keep piling up across calls. That is why you set `lst=None` and create a new list inside the Function.

## Iterators and Generators

#### Iterables and Iterators
ONE: An **Iterable** is a **collection** you can take items out of one at a time (list, str, dict, etc.), and an **Iterator** is a **bookmark that hands you the next value** from that collection, one at a time.
LIKE: An Iterable is a book, and an Iterator is a bookmark placed in that book. You can put as many new bookmarks in one book as you like, and a bookmark only moves forward one page at a time.
STEP:
1. **Iterable**: An Object that creates an Iterator when you call `iter(obj)` (internally, `__iter__`).
2. **Iterator**: Returns the next value each time you call `next(it)` (`__next__`) and raises **StopIteration** when there are no more.
3. **What a for loop really is**: `for x in lst:` internally creates `it = iter(lst)` and keeps calling `next(it)` until StopIteration occurs, then stops.
4. An Iterator is **done once it has been used up**. To go around again from the start, you must create a new Iterator from the Iterable.
5. `map`, `filter`, `zip`, and file Objects are Iterators, so you can go through them only once.
```python
it = iter([10, 20])
next(it)  # 10
next(it)  # 20
next(it)  # StopIteration
```
WHY: It makes "taking values out one at a time when needed, without building them all in advance" possible, which saves Memory and lets you handle endless data.
END: An Iterable is the book, and an Iterator is the bookmark. A for loop is syntax for turning the bookmark one page at a time.

#### Generators and Lazy Evaluation
ONE: A **Generator** is a Function that uses `yield` to **produce and send out values one at a time, pausing and then picking up where it left off on the next request**. It does not build all the values in advance, so it uses almost no Memory.
LIKE: Instead of baking 10,000 cookies in advance and stacking them in the fridge, it is a shop that bakes one each time an order comes in. It barely needs a fridge (Memory).
STEP:
1. If a Function contains `yield`, calling it does not run it but returns a Generator Object.
2. Calling `next()` runs it up to the first `yield`, sends out that value, and **pauses right there**.
3. Calling `next()` again picks up from where it paused and runs to the next `yield`.
4. When the Function ends, StopIteration occurs. A Generator is an Iterator, so you can use it directly in a for loop.
5. Computing only when needed like this is called **Lazy Evaluation**.
6. **Generator Expression**: Writing it with parentheses, like `(x * x for x in range(10))`, gives a Generator instead of building a list.
7. **range** is Lazy too. In Python 3, `range(10**9)` does not create a billion numbers but computes them when needed (this is what Python 2's xrange became).
```python
def read_lines(path):
    with open(path) as f:
        for line in f:
            yield line.strip()   # send out one line and pause

for line in read_lines("big.log"):   # even a 10GB file, one line at a time
    ...
```
USE: Used for processing very large files line by line, generating endless sequences, and building data processing Pipelines.
CON: Once you have gone through it, you cannot reuse it, and you cannot jump directly to a middle value by Index.
END: A Generator is a Function that "makes one each time an order comes in." It lets you handle big data with little Memory.

### What's the difference between iterator and iterable?
E: An Iterable is a book, and an Iterator is a bookmark placed in that book. You can make as many new bookmarks for a book as you like, and a bookmark only moves forward one page at a time.
A: An Iterable is an Object that can create an Iterator through `__iter__` (list, str, dict, etc.), and an Iterator is an Object that returns the next value one at a time through `__next__` and raises StopIteration when it runs out. An Iterator is done once used up, and a for loop calls iter() and next() internally.

### What are generators in Python?
E: Instead of baking 10,000 cookies in advance, it is a shop that bakes one each time an order comes in. It barely needs a fridge (Memory).
A: A Generator is an Iterator made from a Function that uses yield; it pauses every time it sends out a value and continues from where it paused on the next request. It does not build all the values in advance (Lazy Evaluation), so it uses almost no Memory, which makes it good for reading big files line by line or handling infinite sequences, and it can also be made with a Generator Expression like `(x * x for x in range(10))`.

### What is the difference between range and xrange?
A: In Python 2, range built a list containing every number, and xrange was an Object that made numbers when needed. In Python 3, xrange was removed and range became an Object that computes Lazily, like xrange. That is why even range(10⁹) uses almost no Memory.

## Namespaces and Modules

#### Namespaces and the LEGB Rule
ONE: A **Namespace** is a "name → Object" mapping table, and Python looks up names in the order **Local → Enclosing → Global → Built-in** (the **LEGB Rule**).
LIKE: Two kids named "Alex" in my class and the class next door are different people. A Namespace is "which class roster," and when Python looks up a name, it checks the rosters in the order my class → the outer class → the whole school → the school district.
STEP:
1. **Local**: Names inside the Function currently running.
2. **Enclosing**: Names of the outer Function that encloses this Function (in the case of Closures).
3. **Global**: Names at the top level of this Module (.py file).
4. **Built-in**: Python's basic names like `print` and `len`.
5. It searches from the innermost scope outward and uses the first one it finds. If it is nowhere, you get a NameError.
6. **Changing a Global Variable**: Inside a Function, just **reading** a Global Variable works, but if you **assign a new value**, that name is treated as a Local Variable. To change a Global, use `global x`; to change a Variable of the enclosing Function, use `nonlocal x`.
```python
x = "global"
def outer():
    x = "enclosing"
    def inner():
        print(x)     # enclosing (not in Local, so it looks outward)
    inner()
```
KEY: If you use a Built-in name as a Variable, like `list = [1, 2]`, you can no longer use the original `list()` in that Module. Avoid Built-in names.
WHY: Because Namespaces are separate, using the same name in different files and Functions does not cause conflicts.
END: Names are looked up in the order L → E → G → B, and to change an outer Variable, use global·nonlocal.

#### Modules · Packages · import
ONE: A **Module** is a single `.py` file containing code, a **Package** is a folder of Modules, and a **Library** is a collection of Modules·Packages gathered for reuse.
LIKE: A Module is one recipe card, a Package is a binder of recipes, and a Library is the bookshelf where the binders sit.
STEP:
1. **Module**: A `.py` file containing Functions·Classes·Variables. If there is a `math.py`, you bring it in with `import math`.
2. **Package**: A folder containing several Modules (usually with an `__init__.py`). You access it with dots, like `import a.b`.
3. **Ways to import**: `import math`, `from math import sqrt`, `import numpy as np`. Avoid `from x import *`, because it is hard to tell which names came in.
4. **Search order**: Python searches the folders in `sys.path` one by one to find a Module. You can add folders with the **PYTHONPATH** environment variable.
5. Once a Module is imported, it is stored in `sys.modules`, so importing it again does not rerun its code.
6. **Standard Library**: Basic Modules you can use without installing anything: os, sys, math, random, datetime, json, re, collections, itertools, functools, and more.
7. **External Libraries**: Installed with `pip install`. For data·AI: NumPy, pandas, scikit-learn, PyTorch; for the web: Django, Flask, FastAPI, requests.
KEY: You can explore an unfamiliar Library with `help(obj)` (the manual) and `dir(obj)` (the list of what it has).
END: A file is a Module, a folder is a Package, and a collection is a Library. import searches sys.path and runs a Module only once.

### What is namespace in Python?
E: Two kids named "Alex" in my class and the class next door are different people. A Namespace is "which class roster." When Python looks up a name, it flips through the rosters in the order my class → the outer class → the whole school → the school district.
A: A Namespace is a Mapping from names to Objects that keeps the same name in different places from colliding. Python looks up names in the order Local → Enclosing (the enclosing Function) → Global (Module) → Built-in, which is called the LEGB Rule.

### What are local variables and global variables?
A: A Local Variable is created inside a Function and visible only inside that Function, and a Global Variable is created at the top level of a Module and visible throughout the Module. Inside a Function, just reading a Global Variable works, but assigning a new value requires the global Keyword, and for a Variable of the enclosing Function, use nonlocal.

### What are Python modules and packages? Name some built-in modules.
E: A Module is one recipe card (.py file), a Package is a binder of recipes (folder), and a Library is the bookshelf where the binders sit.
A: A Module is a .py file containing Functions·Classes·Variables, and a Package is a Directory containing several Modules (usually with an `__init__.py`), accessed with dots like `import a.b`. Commonly used Built-in Modules are os, sys, math, random, datetime, json, re, collections, itertools, and functools.

### How to import modules? What is PYTHONPATH?
A: You import with `import math`, `from math import sqrt`, or `import numpy as np`, and avoid `from x import *` because names can get mixed up. Python searches the Directories in sys.path one by one to find a Module, and PYTHONPATH is an Environment Variable that adds Directories to it. Once a Module is imported, it is Cached in sys.modules, so importing it again does not rerun it.

### What are Python libraries? Name a few.
A: A Library is a collection of reusable Modules·Packages; there is the Standard Library and external (Third-Party) Libraries installed with pip. For data·AI, NumPy, pandas, Matplotlib, scikit-learn, PyTorch, and TensorFlow are common, and for the web, Django, Flask, FastAPI, and requests.

### What is the usage of help() and dir()?
A: help(obj) shows an Object's Docstring and usage notes, and dir(obj) returns the list of Attribute·Method names that Object has. Calling dir() with no Argument shows the names in the current Scope, which is useful when exploring an unfamiliar Library.

## Memory Management

#### Memory Management in Python
ONE: Python creates every Object on its own Heap, **frees it immediately when its Reference Count hits 0**, and has a **Garbage Collector** periodically clean up circular references.
LIKE: Python keeps count of "how many name tags are stuck on each object" and clears it away as soon as the count hits 0. Piles of objects that are isolated and only point at each other get cleared separately by a janitor who comes around now and then.
STEP:
1. Every value in Python (numbers, strings, even Functions) is an Object, created in a dedicated Memory area called the **Private Heap**.
2. Small Objects are quickly given space by a dedicated allocator called **pymalloc**.
3. Every Object has a Reference Count. Sticking on a name tag is +1, and peeling one off (deleting a variable, assigning another value, a function ending) is −1.
4. The moment the Count hits 0, the Memory is reclaimed immediately.
5. Circular references (Objects pointing to each other) never reach a Count of 0, so the **Generational GC** (the `gc` module) periodically finds and frees them.
6. Programmers do not need to call `free`. `del x` does not delete the Object; it peels off the name tag `x`.
KEY: When Python exits, not every Object may be cleaned up (circular references or Memory held by C Libraries), but when the Process ends, the OS reclaims all of that Process's Memory, so it is not a real Leak.
CON: If you keep leaving name tags somewhere else (a global list, a Cache, etc.), the Count never reaches 0, so Memory can keep growing even with a GC.
END: Python clears things immediately by counting name tags (Reference Counting), and the GC clears circular references separately.

#### Shallow Copy vs Deep Copy
ONE: A **Shallow Copy** makes only a new outer container and **shares** the contents with the original, while a **Deep Copy** makes **everything new**, all the way inside.
LIKE: A Shallow Copy of a dresser buys only a new dresser frame, and the boxes inside the drawers are still shared with the original. A Deep Copy buys new boxes and new things inside them too.
STEP:
1. **Assignment (`b = a`)**: Not a copy. It just sticks one more name tag on the same Object.
2. **Shallow Copy**: `copy.copy(a)`, `a[:]`, `list(a)`, `a.copy()`. The outer list is new, but the Objects inside point to the same ones as the original.
3. So if the insides are Immutable, like numbers, there is no problem, but if the insides are Mutable, like lists, changing an inner item on one side changes the other side too.
4. **Deep Copy**: `copy.deepcopy(a)`. It recursively makes new copies of all the inner Objects, giving a completely independent copy.
5. Deep Copy is slow and uses more Memory, so use it only when you really need it.
```python
import copy
a = [[1, 2], [3, 4]]
b = copy.copy(a)      # Shallow
c = copy.deepcopy(a)  # Deep
a[0].append(99)
print(b[0])  # [1, 2, 99]  ← shares the inside
print(c[0])  # [1, 2]      ← completely independent
```
KEY: If you make a 2D list with `[[0] * 3] * 3`, it points to the same inner list three times, so changing one cell changes all three rows. You have to make it with `[[0] * 3 for _ in range(3)]`.
END: Assignment adds a name tag, Shallow makes only the outside new, and Deep makes everything new.

#### Object Interning
ONE: An optimization that **creates just one Immutable Object for a given value and reuses it**, saving Memory and comparison time.
LIKE: It is like the whole class sharing one "Great job!" stamp that everyone borrows instead of each kid having one. The words on the stamp never change, so sharing it is safe.
STEP:
1. CPython creates the commonly used small integers −5 to 256 in advance and hands out the same Object whenever one of these values is needed.
2. Short strings that look like names (Variable names, dict Keys, etc.) are also often created once automatically and reused.
3. You can also intern a string yourself with `sys.intern(s)`. It speeds things up when you compare the same strings a great many times.
4. This is possible because they are Immutable. If values could change, sharing them would make them affect each other.
KEY: Interning is a CPython implementation detail, so it varies by version and situation. That is why comparing values with `a is b` may happen to work and then fail. Always compare values with ==.
END: Interning is "make one copy of the same value and share it," which is why is sometimes returns True, but you must not rely on it.

### How is memory managed in Python?
E: Python keeps count of "how many name tags are stuck on each object" and clears it away as soon as it hits 0, and piles of isolated objects that only point at each other get cleaned separately now and then.
A: Every Object in Python lives on a Private Heap managed by the Python Memory Manager, and small Objects are allocated quickly by pymalloc. CPython frees an Object the moment its Reference Count hits 0, and Circular References that Reference Counting cannot catch are periodically found and freed by the Generational Garbage Collector (the gc module). Programmers do not need to free anything themselves.

### What is the difference between deep and shallow copy?
E: A Shallow Copy of a dresser buys only a new dresser frame and keeps sharing the boxes inside the drawers. A Deep Copy buys new boxes and new things inside them too.
A: A Shallow Copy (`copy.copy`, `lst[:]`, `list(lst)`) makes only a new outer Container and shares the inner Objects with the original, so changing the inside of a nested list changes the original too. A Deep Copy (`copy.deepcopy`) recursively makes new inner Objects as well, creating a completely independent copy.
```python
import copy
a = [[1, 2], [3, 4]]
b = copy.copy(a)      # Shallow Copy
c = copy.deepcopy(a)  # Deep Copy
a[0].append(99)
print(b[0])  # [1, 2, 99]  ← shares the inner list
print(c[0])  # [1, 2]      ← independent
```

### What is object interning?
E: It is making just one commonly used "Hello" stamp and having everyone borrow it. The value never changes, so sharing it is safe.
A: Interning is an optimization that creates just one Immutable Object for a given value and reuses it, saving Memory and comparison time. CPython interns Small Integers from −5 to 256 and some Strings that look like Identifiers, and you can also do it yourself with `sys.intern()`. It is an implementation detail, so you must not use is to compare values; use ==.

### Whenever Python exits, why isn't all the memory de-allocated?
A: According to the official Python FAQ, Objects referenced from Module Global Namespaces, especially those with Circular References, are not always freed at exit, and some Memory allocated by C Libraries cannot be freed by Python. However, when the Process ends, the OS reclaims all of that Process's Memory, so it does not lead to a real Memory Leak.

## OOP (Object-Oriented Programming)

P: The analogy for this group: a Class is a **cookie cutter**, and an Object (Instance) is **each cookie** cut with it. There is one cutter, but each cookie can have different toppings (sprinkles·chocolate chips).

#### Classes and Objects, __init__ and self
ONE: A **Class** is a **blueprint (mold)** for making Objects, and an **Object (Instance)** is the **actual thing** made from that mold. `__init__` fills in the initial values at creation, and `self` refers to "this very Object itself."
LIKE: A Class is a cookie cutter, and an Object is each cookie cut with it. There is one cutter, but each cookie can have different toppings (sprinkles·chocolate chips). `__init__` is the step of adding toppings as soon as the cookie comes out of the cutter, and `self` is "this exact cookie in my hand right now."
STEP:
1. **Making a Class**: `class Dog:`. An empty Class is `class Empty: pass`.
2. **Making an Object**: `d = Dog("Coco")`. You can make as many Objects as you like from the same Class.
3. **Attribute**: Data an Object holds: `d.name`.
4. **Method**: A Function defined inside a Class. It works with the Object's data.
5. **`__init__`**: Called automatically right after an Object is created to fill in its Attributes. Strictly speaking, `__new__` is what "creates" the Object, and `__init__` only "initializes" it.
6. **`self`**: The first Parameter of a Method, which is the Object that called the Method. `d.bark()` actually runs as `Dog.bark(d)`. `self` is not a reserved word but a conventional name.
```python
class Dog:
    def __init__(self, name):
        self.name = name          # this Object's Attribute
    def bark(self):
        return f"{self.name}: Woof!"

d = Dog("Coco")
d.bark()   # Dog.bark(d) → 'Coco: Woof!'
```
WHY: Bundling data with the features that work on it lets you organize a big program as "objects working together."
END: A Class is the cutter, an Object is the cookie, `__init__` adds the toppings, and `self` is this cookie right here.

#### Inheritance and MRO
ONE: **Inheritance** is when a child Class **inherits a parent Class's features to reuse them, changing only what it needs (Overriding)**.
LIKE: If you build a "dog" mold by inheriting from an "animal" mold, you do not have to rebuild common parts like name·age; you only need to define "bark."
STEP:
1. Write the parent Class in parentheses, like `class Dog(Animal):`.
2. The child can use the parent's Attributes and Methods as they are.
3. **Overriding**: If the child redefines a Method with the same name as the parent's, the child's version is used.
4. **super()**: Used inside a child Method to call the parent's Method. Example: `super().__init__(name)`.
5. **Multiple Inheritance**: In Python a Class can have several parents: `class C(A, B):`.
6. **MRO (Method Resolution Order)**: The rule for the order in which Methods are searched when there are several parents (the C3 Algorithm). You can check it with `C.__mro__`, and super() also calls "the next Class" in this order.
```python
class Animal:
    def __init__(self, name):
        self.name = name
    def speak(self):
        return "..."

class Dog(Animal):          # inherits from Animal
    def speak(self):        # Overriding
        return f"{self.name}: Woof woof"

Dog("Coco").speak()  # 'Coco: Woof woof'
```
CON: Stacking inheritance deep makes it hard to track where things change. That is why there is also the principle "Composition over Inheritance" (topic 10).
END: Inheritance means inheriting and changing only what you need, and with several parents, Methods are searched in MRO order.

#### Polymorphism · Encapsulation · Abstraction
ONE: The three core ideas of OOP: **each responding differently to the same command (Polymorphism)**, **hiding the inside and showing only the buttons (Encapsulation)**, and **defining only "what must be done" (Abstraction)**.
LIKE: Say "Make a sound!" and a dog goes woof while a cat goes meow (Polymorphism). A TV remote hides its circuits and shows only buttons (Encapsulation). If you decide "anything that is a vehicle must have 'start moving'," a bike and a car each start moving in their own way (Abstraction).
STEP:
1. **Polymorphism**: Handle Objects of different Types through the same Method name. `for a in animals: a.speak()` makes a different sound for each Object.
2. Python cares more about "does it have that Method?" than about the Type. This is called **Duck Typing**, from "if it walks like a duck and quacks like a duck, it's a duck."
3. `+` meaning addition for numbers and concatenation for strings is also Polymorphism (Operator Overloading, `__add__`).
4. **Encapsulation**: Bundle data and the Methods that work on it into one Class, and hide the inside.
5. Python has no enforced rule like Java's `private`. Instead, `_name` is a promise meaning "this is internal, don't use it from outside," and `__name` gets renamed to `_Class__name` (Name Mangling) so it does not collide with names in child Classes. Even so, it can still be accessed.
6. **Abstraction**: Use `ABC` and `@abstractmethod` from the `abc` module to define "Methods that must be implemented." A child Class that does not implement them cannot create Objects.
WHY: Polymorphism lets you add new Types without changing existing code, Encapsulation keeps the outside from breaking when you change the inside, and Abstraction sets the promise that multiple implementations must keep.
END: Same command, different behavior (Polymorphism); hide the inside (Encapsulation); define only what must be done (Abstraction).

#### @classmethod · @staticmethod · @property
ONE: Decorators that set the kind of Method. **@classmethod** receives the Class itself, **@staticmethod** receives nothing, and **@property** lets you read a Method like an Attribute.
LIKE: A regular Method works on one cookie, @classmethod works on the cookie cutter itself, @staticmethod is the calculator sitting in the shop (related to the shop but not to any particular cookie), and @property is a price tag that is calculated behind the scenes but looks like it is simply attached.
STEP:
1. **Regular Method**: The first Argument is `self` (the Object). It works with each Object's data.
2. **@classmethod**: The first Argument is `cls` (the Class). Often used for an **Alternative Constructor** that creates Objects another way, like `Date.from_string("2026-10-23")`. When called from a child Class, `cls` is the child Class, so a child Object is created.
3. **@staticmethod**: Receives neither `self` nor `cls`. Used to keep helper Functions related to the Class organized inside the Class.
4. **@property**: Lets you read `obj.area` without parentheses instead of `obj.area()`. With `@area.setter`, you can also validate values when they are set (e.g., no negatives).
| Kind | First Argument | When to use |
| Regular Method | self | Working with each Object's data |
| @classmethod | cls | Alternative Constructor, Class-wide settings |
| @staticmethod | None | Related helper Function |
| @property | self | A computed value as an Attribute, validating values |
END: Use a regular Method to work on an Object, @classmethod to work on the Class, @staticmethod when you need neither, and @property to make something look like an Attribute.

#### Magic Methods and Monkey Patching
ONE: A **Magic Method** is a special Method of the form `__name__` that Python syntax (`+`, `len()`, `print()`) calls internally. **Monkey Patching** is swapping out a Class's or Module's behavior while the program runs.
LIKE: Magic Methods are like carving reaction rules into the cookie cutter, such as "when the + button is pressed, do this" and "when asked how many, answer like this." Monkey Patching is secretly swapping a puppet's arm for a different one in the middle of the show.
STEP:
1. **Magic Methods (Dunder Methods)**: The name has two underscores (double underscore) on each side.
2. `print(obj)` → `__str__`, the developer-facing display → `__repr__`, `a == b` → `__eq__`, `len(obj)` → `__len__`, `a + b` → `__add__`, `for x in obj` → `__iter__`.
3. If you define these on your own Class, your Objects can use `+`, `len()`, and for loops just like Built-in Types.
4. **Monkey Patching**: Swap things out at runtime, like `SomeClass.method = new_function`.
5. It is useful in Tests for putting in a fake (Mock) instead of a real external API (`unittest.mock.patch`).
CON: Overusing Monkey Patching in real service code creates a state where "what's written in the code differs from what actually runs," which is very hard to track down.
END: Magic Methods are the hooks that connect syntax to your Class, and Monkey Patching is swapping at runtime (carefully, and only in Tests).

### Does Python have OOP concepts? How are classes created? How to create an empty class?

Strictly speaking, `__new__` is what creates the Object, and `__init__` only does Initialization. self is the first Parameter, pointing to the Instance the Method was called on, and `obj.method()` actually runs as `Class.method(obj)`. self is not a reserved word (Keyword) but a conventional name.

## Concurrency

#### GIL (Global Interpreter Lock)
ONE: A global Lock in CPython that lets **only one Thread run Python Bytecode at any moment**. That is why adding Threads does not speed up pure Python computation.
LIKE: It is a kitchen with several cooks but only one knife. Even with more cooks (Threads), chopping (running Python code) happens one person at a time. But while waiting for an ingredient delivery (I/O), a cook puts the knife down so another cook can use it.
STEP:
1. CPython manages Memory with Reference Counting. If several Threads modify a Count at the same time, it can get tangled (Race Condition).
2. Instead of putting a Lock on every Object, it puts one Lock (the GIL) on the whole Interpreter to keep things simple and safe.
3. So CPU-heavy computation (**CPU-Bound**) does not speed up even with 4 Threads, because only one runs at a time.
4. On the other hand, the GIL is released while reading files·waiting on the Network (**I/O-Bound**), so other Threads can work in the meantime. That is why Threads are effective for I/O work.
5. C Extensions like NumPy can release the GIL during heavy computation, so they can use multiple Cores.
6. Starting with Python 3.13, a build that runs without the GIL (**Free-Threaded**) is available as an option.
WHY: "Why doesn't Python get faster when you add Threads?" is a classic interview question. The answer is the GIL, and the solution depends on the kind of work (next concept).
END: The GIL is "a kitchen with only one knife." Computation does not get faster with Threads, but Threads help for work that waits (I/O).

#### threading vs multiprocessing vs asyncio
ONE: If there is a lot of waiting, use **threading** or **asyncio**; if there is a lot of CPU computation, use **multiprocessing**.
LIKE: threading is putting several cooks in one kitchen (with one knife), multiprocessing is setting up several kitchens (each with its own knife), and asyncio is one cook putting several pots on the stove at once and tending to them in the order they boil.
STEP:
1. **Check the kind of work first**: Is it CPU-Bound (mostly computation) or I/O-Bound (mostly waiting)?
2. **threading**: Several Threads within one Process. They share the GIL, so computation does not speed up, but other Threads work while one waits on I/O. Protect shared data with `threading.Lock`.
3. **multiprocessing**: Creates several Processes. Each Process has its own Interpreter and GIL, so they truly compute at the same time on multiple Cores. In exchange, exchanging data between Processes is costly.
4. **asyncio**: In one Thread, an **Event Loop** runs several tasks in turns. While one task waits with `await`, it moves the others forward. It can handle thousands of Network connections lightly.
5. With `ThreadPoolExecutor` and `ProcessPoolExecutor` from `concurrent.futures`, you can switch between the two using the same shape of code.
| Approach | How it works | Good fit |
| threading | One Process, several Threads, shared GIL | Work with a lot of file·Network waiting |
| multiprocessing | Several Processes, one GIL per Process | Heavy computation across multiple Cores |
| asyncio | One Thread, an Event Loop | A huge number of simultaneous Network connections |
END: Computation is multiprocessing, waiting is threading, and tons of waiting is asyncio.

### What is GIL?
E: It is a Python kitchen with several cooks but only one knife. Even with more cooks (Threads), chopping (running Python code) happens one person at a time, but while waiting for an ingredient delivery (I/O), a cook puts the knife down so another can use it.
A: The GIL (Global Interpreter Lock) is a global Lock in CPython that lets only one Thread run Python Bytecode at any moment, keeping internal Memory management like Reference Counting simple and safe. So CPU-Bound work does not speed up with more Threads, but the GIL is released during I/O waits, so Threads are effective there, and C Extensions like NumPy can also release the GIL during computation. Starting with Python 3.13, an experimental build that runs without the GIL (Free-Threaded) is also available.

### How is multithreading achieved in Python? threading vs multiprocessing vs asyncio
| Approach | How it runs | Good fit |
| threading | Several Threads in one Process, shared GIL | I/O-Bound work with a lot of file·Network waiting |
| multiprocessing | A separate Interpreter and GIL per Process | CPU-Bound work using multiple Cores |
| asyncio | An Event Loop in one Thread runs tasks in turns | Thousands of simultaneous Network connections |
A: Create Threads with the threading module (or `concurrent.futures.ThreadPoolExecutor`) and protect shared Data with `threading.Lock`. Because of the GIL, CPU computation is split across Cores with multiprocessing, and for Network work with a huge number of simultaneous connections, asyncio's async/await is efficient.

## Standard Library and NumPy

#### Exception Handling and the with Statement
ONE: Catch errors (Exceptions) and recover with **try/except**, and use the **with statement** to **reliably clean up** resources like files·Locks **no matter what happens**.
LIKE: try is "give it a shot," except is "if it fails, recover like this," and finally is "whether it works or not, turn off the lights on your way out." with is a door that closes automatically after you go in and come out.
STEP:
1. **try**: Put in the code that might fail.
2. **except ErrorType**: Runs if that error occurs. Catch specific kinds, like `except ValueError:`.
3. **else**: Runs only if there was no error.
4. **finally**: Always runs, error or not. Put cleanup work here.
5. **raise**: Raise an error yourself. Used to signal bad input.
6. **with statement**: `with open("a.txt") as f:` The moment you leave the Block, the file closes automatically, even if an error occurred. Internally it uses a **Context Manager** (`__enter__`/`__exit__`).
```python
try:
    n = int(input())
except ValueError:
    print("Please enter a number")
else:
    print(n * 2)
finally:
    print("Done")
```
KEY: Avoid a bare `except:` that swallows every error. It even blocks things like Ctrl+C and hides real Bugs.
END: Recover from errors with try/except, and reliably clean up with finally or with.

#### Why NumPy Arrays Are Faster than lists
ONE: A NumPy Array stores **numbers of the same Type side by side in Memory** and **computes everything at once in C without loops (Vectorization)**, so it is much faster and lighter than a list.
LIKE: A list is a box where each slot holds only a note saying "the real item is somewhere in the warehouse." A NumPy Array is an egg carton with same-size numbers lined up, so you can put the whole carton into the calculator at once.
STEP:
1. **Structure of a list**: Each slot holds only an Object's address, and the actual number Objects are scattered around Memory. Even a single number is a large Object carrying Type information and more.
2. **Structure of a NumPy Array**: Only values of the same Type (e.g., 64 Bit floats), packed tightly in contiguous Memory. It uses less Memory and has good Cache efficiency (Locality from topic 02).
3. **Vectorization**: Writing `a + b` or `a * 2` has C code compute the whole thing at once, without a Python loop. Depending on the case, it can be tens of times faster or more.
4. **Broadcasting**: Even Arrays of different sizes are stretched according to rules and computed. `a + 1` adds 1 to every element.
5. It has a rich set of functions like Matrix multiplication (`a @ b`) and statistics (`mean`, `std`), making it a basic tool for data analysis and AI.
```python
import numpy as np
a = np.arange(1_000_000)
b = a * 2          # a million elements at once, no loop
```
CON: Its size is fixed, so a list is better when you frequently add and remove elements or mix different Types.
END: NumPy is fast because it "lines up the same Type side by side + computes everything at once in C." Number crunching is NumPy; miscellaneous lists are list.

#### Serialization: pickle and JSON
ONE: **Turning an Object into Bytes that can be saved to a file or sent over a Network** is Serialization, and turning it back is Deserialization.
LIKE: Pickling is packing an assembled LEGO set into a box along with its instructions for storage, and Unpickling is opening the box and assembling it exactly the same way again.
STEP:
1. Objects in a program exist only in Memory. To save them or send them elsewhere, they must be turned into Bytes.
2. **pickle**: Turns Python Objects into Bytes almost as they are (`pickle.dump` / `dumps`). To turn them back, use `load` / `loads`.
3. pickle is Python-only, so other languages cannot read it.
4. **Danger**: Unpickling can run code hidden in the data. **Never open pickle data that comes from an untrusted source.**
5. **JSON**: A human-readable text format supported by almost every language (`json.dumps` / `loads`). Use JSON to exchange data with other programs·languages. In exchange, it can hold only basic Types like dict·list·numbers·strings.
| Aspect | pickle | JSON |
| Format | Binary (Python-only) | Text (language-independent) |
| What it can hold | Almost any Python Object | Basic Types only |
| Security | Dangerous with untrusted data | Relatively safe |
END: Serialization is packaging an Object into Bytes. pickle for internal Python use, JSON for exchanging with the outside.

#### Commonly Used Standard Library Modules: random · re · os
ONE: Python comes with many basic tools you can use without installing anything. **random** (randomness), **re** (Regular Expressions), and **os·pathlib·shutil** (working with files) are the classics.
LIKE: It is the tool kit that comes in the box when you get Python. It includes dice (random), a magnifying glass for finding text (re), and a file organizer (os).
STEP:
1. **random**: `random.random()` gives a float from 0 up to (but not including) 1, `random.randint(a, b)` gives an integer from a to b inclusive, `random.choice(seq)` picks one, and `random.shuffle(lst)` shuffles a list in place (returning None).
2. To reproduce the same results, fix the Seed, like `random.seed(42)`.
3. For random values where security matters, like passwords·Tokens, use the **secrets** module, not random. random is predictable, so it is not for security.
4. **re**: Find and replace by text pattern. `re.split(r"[,;]\s*", "a, b;c")` → `['a', 'b', 'c']`, `re.sub(r"\d", "#", "a1b22")` → `'a#b##'`, and `re.subn` also returns the number of replacements.
5. **Deleting files**: `os.remove(path)` or `pathlib.Path(path).unlink()`. An empty folder uses `os.rmdir()`, and a folder with contents uses `shutil.rmtree()`.
KEY: Trying to delete a file that does not exist raises FileNotFoundError. Check first or handle it with try/except.
END: Randomness is random (secrets for security), patterns are re, and files are os·pathlib·shutil.

### How can you generate random numbers? How can you randomize a list in place?
A: Use the random module. `random.random()` gives a float from 0 up to (but not including) 1, `random.randint(a, b)` gives an integer from a to b inclusive, and `random.choice(seq)` picks a random element. `random.shuffle(lst)` shuffles the list In-Place and returns None; use `random.seed()` when you need reproducibility, and the secrets module when you need security, as for passwords·Tokens.

### Explain split(), sub(), subn() methods of the re module.
A: `re.split(pattern, string)` cuts a String wherever the Regular Expression matches and returns a list, `re.sub(pattern, repl, string)` returns a new String with the matches replaced, and `re.subn()` returns a (new String, number of replacements) tuple.
```python
import re
re.split(r"[,;]\s*", "a, b;c")   # ['a', 'b', 'c']
re.sub(r"\d", "#", "a1b22")       # 'a#b##'
re.subn(r"\d", "#", "a1b22")      # ('a#b##', 3)
```

### What is pickling and unpickling?
E: Pickling is packing an assembled LEGO set into a box along with its instructions for storage, and Unpickling is opening the box and assembling it exactly the same way again.
A: Pickling is using the pickle module to Serialize a Python Object into a Byte Stream (dump/dumps), and Unpickling is restoring that Byte Stream back into an Object (Deserialization) (load/loads). Unpickling can run arbitrary code, so untrusted Data must never be Unpickled, and JSON is used to exchange Data with other languages.

### How can files be deleted in Python?
A: Delete a file with `os.remove(path)` or `pathlib.Path(path).unlink()`, an empty Directory with `os.rmdir()`, and a Directory with contents with `shutil.rmtree()`. If the file does not exist, FileNotFoundError is raised, so check first or handle the Exception.

### What advantages do NumPy arrays offer over nested lists? Is NumPy better than lists?
E: A list is like each box holding only a note saying "the real item is somewhere in the warehouse," and a NumPy Array is an egg carton with same-size numbers lined up. You can put the whole carton into the calculator at once.
A: A NumPy Array stores values of the same Type in contiguous Memory, so it uses less Memory and has good Cache efficiency. It handles Vectorized operations like `a + b` and `a * 2` in C without Loops, making it up to tens of times faster or more, and it provides Broadcasting·Matrix operations·statistics functions. However, its size is fixed, so a list is better when you frequently add·remove elements or mix different Types.

### What are Exception Handling and the with statement?
E: try is "give it a shot," except is "if it fails, recover like this," and finally is "whether it works or not, turn off the lights and leave." with is a door that closes automatically when you come out.
A: try/except catches and handles Exceptions; else runs when there is no Exception, and finally always runs. It is better to catch specific Exception Types than to use an `except:` that swallows every Exception.
