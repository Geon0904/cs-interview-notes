## How to Choose a Data Structure

#### Data Structures and a Feel for Time Complexity
ONE: A **Data Structure** is a way of holding data, and you choose one by looking at **"which operation happens most often."** No structure makes every operation fast.
LIKE: Think about organizing clothes. Hanging them on hangers makes them quick to grab but takes up a lot of space; folding them into drawers saves space but makes the clothes at the bottom awkward to get out. How you organize depends on what you do most often.
STEP:
1. Most things you do with data fall into four kinds: **access** (get the i-th item), **search** (find whether something is there), **insert** (put something in), and **delete** (take something out).
2. Each Data Structure makes some of these fast at the cost of others.
3. Speed is described with **Big-O**: how the time grows with n when there are n pieces of data. O(1) is constant regardless of n, O(log n) grows very slowly, and O(n) is proportional to n.
4. A feel for it when n = 1 million: O(1) is one step, O(log n) is about 20 steps, and O(n) is a million steps.
5. So when you see a problem, first ask "what's the most frequent operation?", then pick the structure that makes that operation fast.
| Structure | Fast at | Slow at | Typical use |
| Array | Access by Index O(1) | Middle insert·delete O(n) | Most lists |
| Linked List | Insert·delete O(1) if position known | Access the i-th item O(n) | Frequent insertions, LRU Cache |
| Stack / Queue | Insert and remove at the ends O(1) | No middle access | Undo, waiting lines, DFS·BFS |
| Hash Table | Search·insert·delete O(1) on average | No order, worst case O(n) | Duplicate checks, counting frequency |
| Balanced BST | Keeps order + everything O(log n) | Slower than Hash | Sorted data, range queries |
| Heap | Peek minimum O(1), extract O(log n) | Arbitrary search O(n) | Priority queues, top k |
| Trie | Strings of length L in O(L) | Uses a lot of Memory | Autocomplete, prefix search |
| Union-Find | Merge·same-group check nearly O(1) | Cannot split | Connected components, Cycle checks |
WHY: For the same problem, changing just one Data Structure can turn a program that took hours into one that finishes in a second.
END: There is no one right structure; the right one is whichever makes "the thing you do most often" fast.

### How do you choose a Data Structure?
E: Just as you use hangers if you change clothes often and drawers if space is tight, you pick the storage method that makes the most frequent task fast.
A: No Data Structure makes every operation fast, so first identify the operation the problem does most often (Index access, search, insert·delete, extracting the minimum, keeping sorted order, etc.) and pick the structure with the best Time Complexity for that operation. For example, if "check whether it exists" is frequent, use a Hash Set; if you need sorted order and range queries, use a Balanced BST; if you keep extracting the minimum, use a Heap.

## Arrays and Dynamic Arrays

#### Array
ONE: An **Array** is a structure where same-size slots are placed **side by side in one row** in Memory. Whichever slot you want, you get there with a single calculation (O(1)).
LIKE: Numbered lockers sit side by side in one row. If you know where the first locker is and how wide each one is, you can calculate where locker 100 is without walking over to look.
STEP:
1. An Array places its elements one after another in a contiguous region of Memory.
2. Address of the i-th element = **start address + i × element size**. One multiplication and one addition and you are done, so it is O(1). This is called **Random Access**.
3. **Inserting in the middle**: To insert at position 3, everything from position 3 to the end must shift back one slot. Worst case O(n).
4. **Deleting in the middle**: To fill the gap, the elements behind must shift forward one slot. Worst case O(n).
5. **Search**: If it is not sorted, you have to look one by one from the start, so O(n). If it is sorted, Binary Search gives O(log n).
6. The elements sit next to each other, so the Cache fetches several elements at once. That is why it is very fast in practice too (Spatial Locality from topic 02).
PRO: Access is O(1) and Cache efficiency is good. The structure is simple and wastes no Memory.
CON: You must decide the size in advance (fixed Array), and inserting·deleting in the middle is slow.
END: An Array is the king of "go straight there by number." But inserting and removing in the middle is slow.

#### Dynamic Arrays and Amortized O(1)
ONE: A **Dynamic Array** is an Array that, when it fills up, **creates a bigger Array and moves everything over**. Moving is occasionally expensive, but on average, adding to the end is O(1).
LIKE: When your bookshelf fills up, you buy one twice as big and move all the books over. Moving day is hard, but it rarely happens, and on all the other days you just slide a book in, so on average each day's work is light.
STEP:
1. Python's list, Java's ArrayList, and C++'s vector are Dynamic Arrays.
2. At first it allocates an Array with spare room, and adding to the end just drops the item into an empty slot. O(1).
3. When it is full, it creates a bigger Array and copies every existing element. This one time is O(n).
4. If it doubles in size each time, the total amount copied while inserting n items is 1 + 2 + 4 + … + n < 2n.
5. So the total cost of n insertions is O(n), and the average per insertion is O(1). This "average that spreads an occasional expensive operation across all the operations" is called **Amortized O(1)**.
6. The growth ratio varies by implementation. CPython's list grows by about 1.125 times.
KEY: "Average O(1)" (like a Hash Table, fast most of the time in a probabilistic sense) and "Amortized O(1)" (even in the worst sequence, the total divided out is O(1)) are different concepts.
WHY: You get an Array's fast access even without knowing the size in advance, which is why it became the most widely used data structure.
END: A Dynamic Array moves to a bigger place when it fills up, and spreading out the moving cost makes each insert O(1).

### Why is Array Index access O(1)?
E: An Array is numbered lockers side by side in one row. If you know where the first locker is and how wide each one is, one calculation takes you straight to locker 100.
A: An Array stores same-size elements in contiguous Memory, so the i-th Address can be calculated in one step as "start Address + i × element size," making it O(1) (Random Access). In exchange, inserting or removing in the middle requires shifting every element behind by one slot, so it is O(n), and contiguous Memory gives good Cache efficiency.

### Why is append on a Dynamic Array (ArrayList, Python list) "O(1) on average"?
E: When your bookshelf fills up, you buy one twice as big and move all the books over. Moving day is hard, but it rarely happens, and on all the other days you just slide a book in, so on average each day's work is light.
A: When a Dynamic Array fills up, it creates a bigger Array and copies everything (O(n)), but because it grows by a fixed ratio, copying happens rarely. If it doubles, the total copied over n appends is 1 + 2 + 4 + … < 2n, so the average per append is O(1), which is called Amortized O(1). The Growth Factor varies by implementation; CPython's list uses about 1.125.

## Linked Lists

#### Linked List
ONE: A **Linked List** is a structure of Nodes chained together, each holding data and **"the location of the next one (Pointer)."** If you know the position, inserting·removing is O(1), but finding the i-th item is O(n).
LIKE: It is like a treasure hunt. Each note has its content plus "the next note is under the slide." To read the 5th note, you have to follow them in order starting from the 1st. But to slip a new note into the middle, you only need to rewrite the "next location" on the note before it.
STEP:
1. **Node** = data + the address of the next Node (next).
2. The first Node is called the **Head**, and the last Node's next is empty (None/NULL).
3. **Accessing the i-th item**: You have to follow next i times starting from the Head, so O(n).
4. **Insert**: If you know the Node before the spot, set the new Node's next to the following Node and the previous Node's next to the new Node, and you are done. Nothing gets shifted. O(1).
5. **Delete**: Set the previous Node's next to the Node after the one being deleted, and you are done. O(1).
6. Nodes are scattered around Memory, so Cache efficiency is low.
| Comparison | Array | Linked List |
| Access the i-th item | O(1) | O(n) |
| Insert·delete when position known | O(n) (shifting) | O(1) |
| Memory | Data only | Data + Pointer |
| Cache efficiency | Good (contiguous) | Low (scattered) |
KEY: "Insert in O(1)" holds only **when you already know the position**. If you walk from the front to find that position, it ends up O(n).
USE: In practice, Arrays are often faster thanks to the Cache, so Linked Lists shine in situations like an LRU Cache where you "already hold the middle Node."
END: A Linked List is a chain you follow by "next location." Inserting is easy; finding by number is slow.

#### Singly · Doubly · Circular Linked Lists
ONE: If each Node points only to the next one, it is **Singly**; if it points both forward and back, it is **Doubly**; if the last connects back to the first, it is a **Circular** Linked List.
LIKE: Singly is a one-way street you can only go forward on, Doubly is a two-way street, and Circular is a traffic circle where the end connects back to the start.
STEP:
1. **Singly Linked List**: One next per Node. The structure is simple and uses less Memory. But you cannot go backward, and to delete a Node you need to know **the Node before it**.
2. **Doubly Linked List**: Two per Node, next and prev. You can move in both directions, and knowing just one Node is enough to delete it in O(1) (since you can reach the Nodes before and after it directly). In exchange, it needs one more Pointer.
3. **Circular Linked List**: The last Node points back to the first Node. It suits things that cycle endlessly (taking turns in order, a repeating playlist). Get the stop condition wrong and you fall into an infinite loop.
USE: An **LRU Cache** is the classic example built from a Hash Table (find a Node directly by Key) + a Doubly Linked List (keep the most-recently-used order, move a Node to the front or remove the last one in O(1)).
END: One direction is Singly, both directions is Doubly, and a loop is Circular. If you need to delete a middle Node directly, use Doubly.

#### Finding a Cycle in a Linked List: Floyd's Algorithm
ONE: A method that sends a **slow Pointer** moving one step at a time and a **fast Pointer** moving two steps at a time together, and concludes there is a Cycle if they meet.
LIKE: On a track, the tortoise moves one step at a time and the hare moves two. If the path is straight and ends, the hare reaches the end first; if the track is a loop, the hare laps around and eventually catches up to the tortoise.
STEP:
1. Start both Pointers at the Head. slow moves one step and fast moves two steps at a time.
2. If fast reaches the end (None), there is no Cycle.
3. If there is a Cycle, both eventually enter the loop.
4. Inside the loop, fast gets one step closer to slow each move. So they are guaranteed to meet.
5. Time is O(n), and the extra Memory is just two Pointers, so O(1).
```python
def has_cycle(head):
    slow = fast = head
    while fast and fast.next:
        slow, fast = slow.next, fast.next.next
        if slow is fast:
            return True
    return False
```
KEY: The same "fast·slow Pointer" technique also finds the **middle Node** of a Linked List. When fast reaches the end, slow is in the middle.
WHY: Storing every visited Node in a Set costs O(n) Memory. The key point is that two Pointers can do the same job.
END: Send a tortoise and a hare together; if they meet, there is a Cycle. Memory is O(1).

### What is a Linked List? What are its pros and cons compared with an Array?
E: It is a treasure hunt. Each note has its content plus "the next note is under the playground slide," so to read the 5th note you have to follow them in order starting from the 1st. But to slip a note into the middle, you only need to change the "next location" on the note before it.
A: A Linked List is a structure of Nodes chained together, each with Data and a Pointer to the next Node. If you know the position, insert·delete is O(1) and you do not need to decide the size in advance, but accessing the i-th element is O(n), the Pointers use extra Memory, and Nodes are scattered, so Cache efficiency is low.

### What is the difference between Singly / Doubly / Circular Linked Lists?
| Kind | Structure | Pros | Cons |
| Singly | Each Node points only to the next Node | Simple structure, uses less Memory | Cannot go backward; must know the previous Node to delete |
| Doubly | Points to both next and previous (prev) | Moves both ways, O(1) delete knowing just one Node | Needs one more Pointer |
| Circular | The last Node points back to the first Node | Cycles endlessly (Round Robin Scheduling, repeating playlists) | Infinite Loop if the stop condition is wrong |
A: A Singly Linked List has only a next Pointer, a Doubly Linked List has both prev·next Pointers, allowing two-way Traversal and O(1) deletion, and a Circular Linked List connects its end back to its start. An LRU Cache is the classic example built from a Hash Table + a Doubly Linked List.

### How do you find whether a Linked List has a Cycle?
E: On a track, let the tortoise move one step at a time and the hare two. If the path is straight and ends, the hare reaches the end first; if the track is a loop, the hare laps around and catches up to the tortoise.
A: Floyd's Cycle Detection (Tortoise and Hare) Algorithm sends a Slow Pointer moving one step and a Fast Pointer moving two steps together; if they meet, there is a Cycle, and if the Fast Pointer reaches the end (None), there is none. Time O(n), extra space O(1).

## Stacks and Queues

#### Stack (LIFO)
ONE: A **Stack** is a structure where **the last thing put in is the first taken out (LIFO, Last In First Out)**. Both putting in (push) and taking out (pop) are O(1).
LIKE: It is a stack of plates. A new plate goes on top, and when you take one, you take from the top too. To get the bottom plate, you have to remove all the plates above it.
STEP:
1. **push(x)**: Put x on top.
2. **pop()**: Take off the top.
3. **peek()**: Look at the top without taking it off.
4. Only the top is touched, so everything is O(1). Middle elements cannot be accessed.
5. In Python, a Stack is made with a list's `append()` and `pop()` (adding and removing only at the end is O(1)).
USE: Function call records (Call Stack), undo (Ctrl+Z), the browser back button, bracket matching, and DFS (Depth-First Search).
KEY: **Bracket matching**: Push opening brackets, and when a closing bracket appears, pop and check that they match. If the Stack is empty at the end, the brackets are valid.
END: A Stack is a stack of plates. The last one in comes out first.

#### Queue (FIFO) and Circular Queues
ONE: A **Queue** is a structure where **the first thing put in is the first taken out (FIFO, First In First Out)**. When building one with an Array, you use a **Circular Queue** that reuses the space like a ring.
LIKE: A Queue is the line outside a popular restaurant. Whoever lines up first goes in first. A Circular Queue is like a conveyor-belt sushi track: when it reaches the end it loops back to the start, so the empty spot left when someone takes a plate at the front becomes a spot at the back again.
STEP:
1. **enqueue(x)**: Add to the back of the line (rear).
2. **dequeue()**: Take from the front of the line (front).
3. Python list's `pop(0)` has to pull every element behind forward, so it is O(n). That is why Queues use `collections.deque` (O(1) at both ends).
4. **The problem with a plain Array-based Queue**: Spots freed at the front cannot be reused. When the back is full, you cannot add anything even if there are empty slots at the front.
5. **Circular Queue**: Move the front and rear Indexes with `(i + 1) % size` so they wrap back to 0 at the end. The Array is reused like a ring.
6. Front and rear can be equal both when it is empty and when it is full, so you tell them apart by deliberately leaving one slot empty or keeping a separate count of elements.
USE: Printer queues, job queues (Job Queue), BFS (Breadth-First Search), and **Ring Buffers** that hold keyboard input or Streaming data.
END: A Queue is standing in line (first come, first served), and when building one with an Array, the standard is a Circular Queue that wraps around like a ring.

#### Deques and Building a Queue from Two Stacks
ONE: A **Deque** is a structure where you can add and remove **at both ends** in O(1). And combining two Stacks lets you build a Queue.
LIKE: A Deque is a bus with both a front door and a back door. You can get on and off through either door. Building a Queue from two Stacks works like stacking incoming plates in one pile, then flipping the whole pile over into another pile when you need one, which brings the very first plate to the top.
STEP:
1. **Deque (Double-Ended Queue)**: Adding·removing at both ends is O(1), so it can serve as either a Stack or a Queue. In Python, `collections.deque`.
2. **Queue from 2 Stacks**: Push incoming items onto the inbox Stack.
3. When taking one out, if the outbox Stack is empty, pop every element from inbox one by one and push it onto outbox. The order is reversed, so the item that came in first ends up on top of outbox.
4. Popping from outbox gives the item that came in first.
5. Each element is moved from inbox to outbox **exactly once**. So even though the occasional move is expensive, it averages out to (Amortized) O(1).
USE: Deques are often used in Coding Test problems like the sliding window maximum. "Build a Queue with Stacks" is a classic interview question.
END: A Deque is a line with doors at both ends, and flipping one Stack into another turns two Stacks into a Queue.

### What is the difference between a Stack (LIFO) and a Queue (FIFO), and what are they used for?
E: A Stack is a stack of plates, so the last plate placed on top is the first one taken off. A Queue is the line outside a popular restaurant, so whoever lines up first goes in first.
A: A Stack is a LIFO (Last In First Out) structure where the last one in is the first one out, with push·pop in O(1), used for the Call Stack, undo (Ctrl+Z), the Browser back button, bracket matching, and DFS. A Queue is a FIFO (First In First Out) structure where the first one in is the first one out, used for printer queues, Job Queues, and BFS. In Python, a Queue uses `collections.deque` because `list.pop(0)` is O(n).

### Why do we need Circular Queues?
E: Like a conveyor-belt sushi track, it loops back to the start when it reaches the end. The empty spot left when a plate is taken at the front becomes a spot at the back again.
A: A plain Array-based Queue cannot reuse spots freed at the front, so when the back is full it cannot insert even if there are empty slots at the front. A Circular Queue moves the front·rear Indexes with `(i + 1) % size` to reuse the Array like a ring, and leaves one slot empty or keeps a separate count to tell the Full and Empty states apart. It is used for Streaming Buffers and keyboard input Buffers (Ring Buffers).

### What is a Deque? How do you build a Queue from 2 Stacks?
A: A Deque (Double-Ended Queue) is a Queue where you can add and remove at both ends in O(1). To build a Queue from 2 Stacks, push incoming items onto inbox, and when taking one out, if outbox is empty, dump all of inbox into outbox and then pop from outbox. Each element is moved at most once, so it averages out to (Amortized) O(1).

## Hash Tables

#### How a Hash Table Works
ONE: A structure that turns a Key into a number with a **Hash Function** and uses that number to immediately pick the slot (Bucket) to store it in, doing search·insert·delete in **O(1) on average**.
LIKE: In an apartment building's package lockers, you enter your unit number (Key), and a rule (Hash Function) immediately gives you the locker number. You go straight to it without opening the lockers one by one.
STEP:
1. Prepare an Array of slots called Buckets.
2. Put a Key into the Hash Function and an integer (the Hash value) comes out. Example: `hash("apple")`.
3. **Slot number = Hash value % number of slots**. Store (Key, Value) in that slot.
4. To find it, do the same calculation to get the slot number and go straight there. It is one calculation, so O(1) on average.
5. **Collision**: Different Keys can land in the same slot. If there are more kinds of Keys than slots, it is guaranteed to happen (the pigeonhole principle).
6. If, by bad luck, every Key piles into one slot, you have to compare them one by one inside that slot, so it is **O(n) in the worst case**.
USE: Python's dict and set, Java's HashMap, database Hash Indexes, and Caches. It is the basic tool for "have I seen this before?", "how many times did it appear?", and "does it have a pair?" problems.
CON: It has no order, so it cannot do "view in sorted order" or "range queries." For those, use a Balanced BST.
END: A Hash Table is a structure that "finds the slot directly by calculation." O(1) on average, O(n) in the worst case when collisions pile up.

#### Resolving Collisions: Chaining vs Open Addressing
ONE: When several Keys land in the same slot, you either **hang them in a chain (Chaining)** or **find another empty slot to put them in (Open Addressing)**.
LIKE: Chaining is tying several packages together on a string when they all arrive for the same locker. Open Addressing is checking the locker next door, then the one after that, if yours is taken, and using the first empty one.
STEP:
1. **Chaining**: Each slot is a small list (a Linked List, etc.). On a collision, the item is appended to that list.
2. Chaining is simple to implement and keeps working even when there are more elements than slots. Java's HashMap uses Chaining, and when too many pile into one slot, it turns that slot into a Tree to reduce the worst case.
3. **Open Addressing**: Every element goes directly into the Array. If a slot is taken, it finds the next slot by a fixed rule (**Probing**).
4. Probing methods: **Linear Probing** (starting with the slot right next door), **Quadratic Probing** (jumping 1, 4, 9 slots), and **Double Hashing** (a second Hash Function decides the jump size).
5. Open Addressing has good Cache efficiency because the elements sit together, but once slots fill up it slows down sharply searching for empty ones, and deleting is tricky because you have to leave a "something used to be here" marker. Python's dict uses Open Addressing.
| Aspect | Chaining | Open Addressing |
| Collision handling | Hang a list in the slot | Find another empty slot |
| When nearly full | Keeps working | Slows down sharply |
| Cache efficiency | Low | Good |
| Deletion | Easy | Tricky |
| Example | Java HashMap | Python dict |
END: Collisions cannot be avoided. You resolve them by either hanging them in a chain (Chaining) or finding a nearby slot (Open Addressing).

#### Load Factor · Rehashing · Good Hash Functions
ONE: To keep O(1), when **how full the slots are (Load Factor)** gets high, you enlarge the table and redistribute everything (**Rehashing**), and you use a **good Hash Function** that spreads Keys evenly.
LIKE: When a parking lot is almost full, you have to circle a long time to find a spot. So when the lot gets about 75% full, you move to a lot twice as big and re-park the cars.
STEP:
1. **Load Factor = number of stored elements ÷ number of slots**. The higher it is, the more collisions there are.
2. When it passes a threshold (e.g., 0.75 for Java's HashMap), a new Array is created, usually with twice as many slots.
3. When the number of slots changes, `Hash % number of slots` changes too, so every Key must be put into its new slot again. This is **Rehashing**. It is O(n) once, but it is rare, so O(1) on average is maintained.
4. **Condition ① of a good Hash Function**: Always the same value for the same Key (Deterministic).
5. **Condition ②**: Spreads Keys evenly across the slots (Uniform Distribution). If they pile up on one side, collisions increase.
6. **Condition ③**: Fast to compute.
7. **Security angle**: If an attacker deliberately sends lots of Keys that land in the same slot, the server slows to O(n). That is why Python mixes a random value into string Hashes each time it starts, to prevent this.
KEY: Hashes for storing passwords (SHA-256, bcrypt) have a different purpose. They must be impossible to reverse, and some, like bcrypt, are deliberately made slow. For Hash Table Hashes, being fast is what matters.
END: Grow when full (Rehashing) and spread evenly (a good Hash), and a Hash Table keeps running at O(1).

### What is a Hash Table? Why is it O(1) on average, and when is it O(n) in the worst case?
E: It is like an apartment building's package lockers, where entering your unit number (Key) immediately gives you the locker number according to a rule (Hash Function). You almost always find it in one try, but if by bad luck everything piles into the same locker, you have to dig through that one item by item.
A: A Hash Table stores Values by turning Keys into Array Indexes (Buckets) with a Hash Function, finding the location in a single calculation, so Search·Insert·Delete are O(1) on average. But if many Keys Collide in the same Bucket, you have to compare them one by one inside it, which makes it O(n) in the worst case. Python's dict·set and Java's HashMap are the classic examples.

### What makes a good Hash Function?
A: It must always give the same value for the same Key (Deterministic), spread Keys evenly across Buckets (Uniform Distribution), and be fast to compute. A Cryptographic Hash for storing passwords (SHA-256, bcrypt) must additionally be impossible to reverse, so its purpose differs from a Hash for Hash Tables.

### What are the Collision resolution methods: Chaining vs Open Addressing?
E: Chaining is tying several packages together on a string when they all arrive for the same locker; Open Addressing is finding an empty locker next door when yours is taken.
A: Chaining keeps each Bucket as a Linked List (or Tree) and appends colliding entries; it is simple to implement and keeps working even when full. Open Addressing finds another empty spot within the Array (Linear Probing, Quadratic Probing, Double Hashing); it has good Cache efficiency but slows down sharply as the Load Factor rises, and deletion is tricky. Java's HashMap uses Chaining, and Python's dict uses Open Addressing.

### What are Load Factor and Rehashing?
A: The Load Factor is the number of stored entries ÷ the number of Buckets, and the higher it is, the more Collisions there are and the slower things get. So when it passes a set value (e.g., 0.75 for Java's HashMap), the Bucket Array is usually doubled and every Key is redistributed, which is Rehashing. Rehashing itself is O(n), but it happens rarely, so O(1) on average is maintained.

## Tree Basics

#### Trees and Basic Terms
ONE: A **Tree** is a **hierarchical structure with no Cycles** that branches downward from a single top point (the **Root**).
LIKE: It is a family tree or a company org chart. It branches down from one person at the top (the Root), and people with nobody below them are Leaves.
STEP:
1. **Node**: A point holding data. **Edge**: A line connecting Nodes.
2. **Root**: The top Node. It has no parent.
3. **Parent / Child**: The one directly above is the parent, and the ones directly below are children. Nodes with the same parent are **Siblings**.
4. **Leaf**: A Node with no children.
5. **Depth**: The number of Edges from the Root down to that Node. The Root's Depth is 0.
6. **Height**: The number of Edges from that Node to its farthest Leaf. The Height of a Tree is the Height of its Root.
7. **Subtree**: A Node together with everything below it is also a Tree. That is why Tree problems are well suited to Recursion.
WHY: In a Tree, the time for most operations is proportional to the **Height**. Keeping the Height low is the core of Tree design.
USE: File systems (folders inside folders), HTML document structure (DOM), company org charts, database Indexes, and compilers' syntax trees.
END: A Tree is a Cycle-free structure that branches down from the Root, and its performance is set by its Height.

#### Kinds of Binary Trees: Full · Complete · Perfect
ONE: A **Binary Tree**, where each Node has at most 2 children, is classified by shape as **Full** (0 or 2 children), **Complete** (filled from the left with no gaps), or **Perfect** (every level completely full).
LIKE: Think of theater seating. Complete is when seats are filled from the front row back, and each row from the left. Only the last row may have empty seats on the right. Perfect is a sold-out house without a single empty seat.
STEP:
1. **Binary Tree**: Every Node has at most 2 children (Left, Right).
2. **Full Binary Tree**: Every Node has either 0 or exactly 2 children. No Node has just one.
3. **Complete Binary Tree**: Every level except the last is completely full, and the last level is filled **from the left**.
4. **Perfect Binary Tree**: Every level is completely full. If the Height is h, there are 2ʰ⁺¹ − 1 Nodes.
5. The Height of a Complete Binary Tree with n Nodes is about log₂ n. That is very low.
KEY: A Complete Binary Tree has no gaps, so it can be stored **in a single Array without Pointers**. That is why Heaps use this shape. Some textbooks swap the names Full and Perfect, so in an interview it is safer to state the condition along with the name.
END: At most 2 is Binary, 0 or 2 is Full, no gaps from the left is Complete, and completely full is Perfect.

#### Tree Traversal
ONE: Ways of visiting every Node in a Tree exactly once. Depending on **when the Root is visited**, it is Preorder·Inorder·Postorder, and visiting level by level is Level-Order.
LIKE: It is like the different ways you can read an org chart. You can look at the team lead first and then the team members (Preorder), look at all the team members and the team lead last (Postorder), or go rank by rank, level by level (Level-Order).
STEP:
1. **Preorder**: Root → Left → Right. The parent is visited first. Used for copying a Tree and printing a folder structure.
2. **Inorder**: Left → Root → Right. The parent is visited in the middle. **Traversing a BST Inorder gives sorted order**.
3. **Postorder**: Left → Right → Root. The parent is visited after all its children. Used for deleting a Tree and calculating folder sizes (add up the children's sizes, then compute the parent).
4. The three above are **DFS (Depth-First)**, going all the way down one direction before coming back, and they can be written briefly with recursion.
5. **Level-Order**: Top level first, and left to right within a level. It is **BFS (Breadth-First)**, implemented with a **Queue**. It is good for finding the shallowest Leaf.
6. All of them look at every Node once, so they are O(n).
```python
def inorder(node):
    if node is None:
        return
    inorder(node.left)
    print(node.val)      # visit the Root in the middle
    inorder(node.right)
```
END: Visiting the Root first (Pre), in the middle (In), or last (Post) is DFS; visiting level by level is BFS (Level-Order).

### What is a Tree? What are Root·Leaf·Depth·Height?
E: It is a family tree or a company org chart. It branches down from one person at the top (the Root), and people with nobody below them are Leaves.
A: A Tree is a hierarchical Graph with no Cycles that starts at the Root and goes down through Parent-Child relationships; a Node with no Children is called a Leaf. Depth is the number of Edges from the Root to that Node, and Height is the number of Edges from that Node to its farthest Leaf. File Systems, the HTML DOM, and org charts are Tree structures.

### What is the difference between Binary / Full / Complete / Perfect Binary Trees?
| Kind | Condition | Analogy |
| Binary Tree | Every Node has at most 2 Children | A family with two kids or fewer |
| Full Binary Tree | Every Node has 0 or 2 Children | No kids, or exactly two |
| Complete Binary Tree | Only the last level may have gaps, and it is filled from the left | Theater seats filled from the front row, and from the left |
| Perfect Binary Tree | Every level is completely full (Height h means 2ʰ⁺¹ − 1 Nodes) | A sold-out house with no empty seats |
A: A Binary Tree is a Tree with at most two Children per Node; in a Full Binary Tree every Node has 0 or 2 Children; and a Complete Binary Tree is full except for the last level, which is filled from the left. A Perfect Binary Tree is a Tree where every level is completely full. A Complete Binary Tree has no gaps, so it stores nicely in an Array, which is why Heaps use it.
M: Some textbooks swap the names Full and Perfect, so in an interview it is safer to state the condition along with the name.

### What are Preorder·Inorder·Postorder·Level-Order Traversals?
E: The names come from "when the Root is visited." Preorder is first, Inorder is in the middle, and Postorder is last. Level-Order is reading an org chart level by level from the top.
| Traversal | Order | Use |
| Preorder | Root → Left → Right | Copying a Tree, printing a folder structure |
| Inorder | Left → Root → Right | Ascending sorted output from a BST |
| Postorder | Left → Right → Root | Deleting a Tree, calculating folder sizes |
| Level-Order | Level by level from top to bottom, left to right | BFS, finding the shallowest depth (uses a Queue) |
A: Preorder·Inorder·Postorder Traversals are DFS (depth-first) traversals that visit the Root first·in the middle·last, respectively, and Level-Order Traversal is a BFS (breadth-first) traversal that uses a Queue to visit level by level. All of them look at every Node once, so they are O(n), and an Inorder Traversal of a BST gives the values in sorted order.

## BSTs and Balanced Trees

#### BST (Binary Search Tree)
ONE: A **BST** is a Binary Tree organized so that at every Node, **only smaller values go on the left and only larger values on the right**. Search·insert·delete time is proportional to the Tree's height.
LIKE: It is a map of forks in the road for a number-guessing game: go left when told "lower" and right when told "higher." At every fork, the candidates are cut in half.
STEP:
1. **Rule**: For any Node, every value in its left Subtree < that Node < every value in its right Subtree.
2. **Search**: Start at the Root and go down left if the target is smaller and right if it is larger. If you reach a Leaf without finding it, it is not there.
3. **Insert**: Go down as if searching, and attach the new Node at the empty spot.
4. **Delete**: If it is a Leaf, just remove it; if it has one child, move that child up into its place; if it has two children, swap in the smallest value on the right (or the largest on the left) and then delete that Node.
5. Every operation takes **O(h)** (h = Height). When balanced, h ≈ log n, so it is very fast.
6. **Worst case**: Inserting in sorted order like 1, 2, 3, 4… keeps attaching to the right only, producing a single-line (Skewed) Tree. h = n, so it is O(n), like a Linked List.
KEY: Traversing a BST Inorder gives ascending sorted output. That is why a BST is good for "inserting and removing while keeping things sorted."
END: A BST is a fork in the road, "smaller goes left, larger goes right," and if it loses balance it can slow down to O(n).

#### Balanced Trees: AVL Trees and Red-Black Trees
ONE: BSTs that fix their shape with **Rotations** on every insert·delete to keep the Height at **O(log n)** at all times. The strict **AVL** and the looser **Red-Black** are the classic examples.
LIKE: If the two sides of a hanging mobile are very different in weight, you shift where the strings hang to level it again. AVL is a strict class president who says "not even a 1-inch difference between sides," and Red-Black is a laid-back class president who says "it's fine as long as one side isn't more than twice the other."
STEP:
1. A plain BST can lean to one side depending on insertion order. That is why we need BSTs that balance themselves.
2. **Rotation**: An operation that swaps the up-down relationship of a parent and child to lift the heavy side. It keeps the BST rule (left < parent < right) intact.
3. **AVL Tree**: At every Node, the Height difference between the left and right Subtrees (**Balance Factor**) is kept at 1 or less. When this breaks, it does one or two rotations depending on the case (LL, RR, LR, RL).
4. **Red-Black Tree**: Nodes are colored red·black and follow rules: the Root is black, two red Nodes cannot appear in a row, every path from a Node down to the Leaves has the same number of black Nodes, and so on.
5. Thanks to these rules, the longest path is never more than twice the shortest, so the Height is guaranteed to be O(log n) (precisely, at most 2·log₂(n + 1)).
6. **Difference**: AVL balances more strictly, so **search is slightly faster**; Red-Black rotates less, so **insert·delete are slightly faster**.
USE: "Sorted Maps" like Java's TreeMap and C++'s std::map are implemented as Red-Black Trees. Red-Black Trees are also used in places like the Linux Kernel's Process Scheduler.
END: Balanced Trees keep the height at log n with rotations. For search-heavy work use AVL; for frequent changes use Red-Black.

### What is a BST (Binary Search Tree)? Why can it become O(n) in the worst case?
E: It is a map of forks in the road for a number-guessing game, going left on "lower" and right on "higher." But if you insert 1, 2, 3, 4… in order, it stops being forks and turns into one long single-lane road.
A: A BST is a Binary Tree where, at every Node, the Left Subtree holds only smaller values and the Right Subtree only larger values, so Search·Insert·Delete are O(h), proportional to the Tree Height h. When Balanced, h = O(log n), but inserting in sorted order makes it grow to one side only (Skewed), so h = n and it becomes O(n), like a Linked List.

### How does an AVL Tree stay balanced?
E: If the two sides of a mobile (a toy hung from the ceiling) are very different in weight, you shift where the strings hang to level it again.
A: An AVL Tree is a BST that keeps the Left·Right Subtree Height difference (Balance Factor) at 1 or less at every Node. When an insert·delete breaks the balance, it does one or two Rotations depending on the LL·RR·LR·RL case to keep the Height at O(log n).

### What are the rules of a Red-Black Tree, and how does it differ from AVL?
E: If AVL is a class president who strictly enforces "not even a 1-inch height difference between sides," a Red-Black Tree is a class president who says "it's fine as long as it's not more than about double." It is less strict, but it rearranges seats less often.
A: A Red-Black Tree keeps its Height at most 2log₂(n + 1) with these rules: ① every Node is Red or Black, ② the Root is Black, ③ Leaves (NIL) are Black, ④ both Children of a Red Node are Black (no two Reds in a row), and ⑤ every path from a Node down to its Leaves has the same number of Black Nodes. AVL balances more strictly, so lookups are a bit faster, while Red-Black does fewer Rotations on insert·delete, which favors places with frequent changes, so it is used in Java's TreeMap, C++'s std::map, the Linux Scheduler (CFS), and more.

## Heaps and Priority Queues

#### Heaps and Priority Queues
ONE: A **Heap** is a Complete Binary Tree where **a parent is always smaller (Min Heap) or larger (Max Heap) than its children**. You can see the minimum (maximum) in O(1) and extract it in O(log n).
LIKE: It is an emergency room waiting list. The most urgent patient is always at the front, not whoever arrived first. When a new patient arrives, they check the condition and swap just a few spots. They do not re-sort the whole line.
STEP:
1. **Min Heap rule**: Every parent ≤ its children. So the Root is always the minimum.
2. Siblings have no order between them. It is not a fully sorted structure but one where "only the top is certain."
3. **Insert**: Put it at the very end (the leftmost empty spot on the last level), and while it is smaller than its parent, swap places and move up (**Sift-Up**). At most the Height, O(log n).
4. **Extract the minimum**: Take out the Root, move the last element to the Root, then swap with the smaller child as it moves down (**Sift-Down**). O(log n).
5. **Peek at the minimum**: Look at the Root and you are done. O(1).
6. **Priority Queue**: The concept of "a Queue that takes out the highest-priority item first," and a Heap is its classic implementation.
USE: Processing tasks by priority, Dijkstra's shortest path, Heap Sort, "find the top k," and computing a running median. Python's `heapq` is a Min Heap (if you need a Max Heap, insert values with a − sign).
END: A Heap is a Tree where "only the top is always the minimum (maximum)," and it is the standard implementation of a Priority Queue.

#### Representing a Heap with an Array and Build-Heap in O(n)
ONE: A Heap is a gap-free Complete Binary Tree, so it is stored **in a single Array**, and parents·children are found by Index arithmetic. Building a Heap from n elements all at once takes only **O(n)**.
LIKE: Think about building a pyramid. The bottom has the most bricks, but those bricks barely have to move, while the few bricks at the top are the only ones that have to move far.
STEP:
1. Put the Tree into an Array level by level from the top, left to right.
2. Starting at index 0, Node i has **parent = (i − 1) // 2**, **left child = 2i + 1**, and **right child = 2i + 2**.
3. No Pointers are needed, so it saves Memory and has good Cache efficiency.
4. **Build-Heap**: Inserting elements one by one is O(n log n). Instead, leaving the Array as it is and doing **Sift-Down in reverse**, from the last parent Node up to the Root, is faster.
5. Half the Nodes are Leaves and do not move. Nodes at height 1 move down at most 1 step, and Nodes at height 2 at most 2 steps, but the higher the Node, the fewer of them there are, halving each level.
6. Adding up all this work gives O(n). Python's `heapq.heapify()` works this way.
KEY: In a 0-indexed Array Heap, the parent of Index 5 is (5 − 1) // 2 = 2. In textbooks that start at 1, parent = i // 2 and children = 2i, 2i + 1.
END: A Heap is represented with one Array (parent (i−1)//2, children 2i+1·2i+2), and building it all at once with Sift-Down from the bottom takes O(n).

### What are a Heap (Binary Heap), Min Heap, and Max Heap?
E: It is an emergency room waiting list. The most urgent patient is always at the front, not whoever arrived first, and when a new patient arrives, they check the condition and swap just a few spots. They do not re-sort the whole line.
A: A Binary Heap is a Complete Binary Tree; in a Min Heap a Parent is always less than or equal to its Children, and in a Max Heap always greater than or equal. The Root is the minimum (maximum), so checking it is O(1), and insertion and Root deletion are O(log n) by swapping places up or down (Sift-Up/Sift-Down). Siblings have no order, so it is not fully sorted, and it is used for Priority Queues·Dijkstra·Heap Sort·Top-K problems. Python's heapq is a Min Heap.

### What are the Parent·Child Indexes when implementing a Heap with an Array?
A: In a 0-indexed Array, Node i has Parent `(i − 1) // 2`, Left Child `2i + 1`, and Right Child `2i + 2` (starting at 1: Parent `i // 2`, Children `2i` and `2i + 1`). Since a Complete Binary Tree has no gaps, the Tree is represented with just an Array and no Pointers.

### Why is Build-Heap, which builds a Heap from n elements, O(n)?
E: In a pyramid, the bottom has the most bricks, but they barely have to move, and the few bricks at the top are the only ones that have to move far.
A: Doing Sift-Down in reverse from the last Internal Node up to the Root, the Leaves (half the Nodes) do not move, and there are at most n/2ʰ⁺¹ Nodes of Height h, so the total work is Σ h · n/2ʰ⁺¹ = O(n). Inserting elements one by one is O(n log n), so this is faster, and Python's `heapq.heapify` works this way.

## Trees for Disk

#### B-Tree
ONE: A Balanced Tree made wide and short by putting **hundreds of Keys** in a single Node. You can find the data you want with **only a few reads** from the slow Disk.
LIKE: It is a library card catalog. Each drawer holds several ranges at once, like "A–C" and "D–F," so opening just a few drawers gets you to the book you want. Opening a drawer (a Disk read) is the most expensive part, so the key is reducing how many times you open one.
STEP:
1. Disk (SSD·HDD) is much slower than RAM, and each read fetches not a small piece but a big chunk (a Page, usually several KB) all at once.
2. A Binary Tree has one Key per Node, so its Height is large. With a billion entries it is about 30 levels, and reading the Disk at every level is far too slow.
3. A **B-Tree** makes each Node the size of one Disk Page and puts hundreds of Keys inside it. It has hundreds of children too.
4. So the Tree becomes very wide and short. With hundreds of children per Node, just 3–4 levels can hold billions of Keys.
5. All Leaves are at the same depth, and on insert·delete it keeps balance by splitting (Split) or merging (Merge) Nodes.
WHY: One Disk access is hundreds to tens of thousands of times slower than a Memory access, so "how many reads" decides performance.
USE: It is the basic structure of database Indexes and File Systems (NTFS, parts of ext4, Btrfs, etc.).
END: A B-Tree makes "one Node = one Disk Page" so it is wide and short, reducing the number of Disk reads.

#### B+Trees and DB Indexes
ONE: A **B+Tree** is a B-Tree that keeps the actual data **only in the bottom Leaves** and **links the Leaves together sideways**. It is especially fast at range queries, which is why most DB Indexes are B+Trees.
LIKE: The upper drawers hold only signposts saying "go this way," and the actual book cards are only in the bottom drawers. The bottom drawers are connected side by side, so you can sweep across them and pull out "every book from A to C."
STEP:
1. **Internal Nodes** (upper Nodes) hold only guide Keys. They have no actual data (or row locations).
2. That lets Internal Nodes hold more Keys, so the Tree gets even shorter.
3. **Leaf Nodes** hold all the actual data, and the Leaves are linked sideways like a Linked List.
4. **Single lookup**: It always goes down to a Leaf, so lookup time is consistent.
5. **Range query** (`WHERE age BETWEEN 20 AND 30`): Find the Leaf with 20 once, then just sweep sideways. There is no need to go back up.
| Aspect | B-Tree | B+Tree |
| Where data lives | Every Node | Leaves only |
| Leaf links | None | Linked sideways |
| Range query | Must move up and down | Sweep across the Leaves |
USE: Most relational DB Indexes, such as MySQL (InnoDB) and PostgreSQL, are B+Trees (they come up again under Indexes in topic 09).
END: A B+Tree keeps data only at the bottom (Leaves) and links them sideways, making range queries fast.

### What is a B-Tree? Why is it used in Databases and File Systems?
E: It is a library card catalog. Each drawer holds several ranges at once, like "A–C" and "D–F," so opening just a few drawers gets you to the book you want. Opening a drawer (a Disk read) is the most expensive part, so the key is reducing how many times you open one.
A: A B-Tree is a Balanced Multi-way Search Tree with several Keys and several Children per Node, where all Leaves are at the same Depth. Node size is matched to the Disk Page size so each read brings in many Keys, which makes the Tree Height very low and cuts the number of slow Disk accesses (I/O) accordingly.

### How does a B+Tree differ from a B-Tree, and why is it better suited for Indexes?
E: A B+Tree keeps only signposts saying "go this way" in the upper drawers, and the actual book cards only in the bottom drawers. The bottom drawers are linked side by side, so you can sweep across them and pull out "every book from A to C."
A: A B+Tree keeps the actual Data (or Record locations) only in Leaf Nodes, Internal Nodes hold only guide Keys, and the Leaves are linked together as a Linked List. Internal Nodes hold more Keys, so the Height is low; every lookup goes to a Leaf, so performance is consistent; and a Range Query (`WHERE age BETWEEN 20 AND 30`) just sweeps across the Leaves, which is very fast. That is why most DB Indexes, like MySQL InnoDB, use B+Trees.

## Trie

#### Trie (Prefix Tree)
ONE: A Tree that **splits strings into individual characters and stores them along branches**. Searching·inserting a word of length L is **O(L)**, regardless of how many words are stored.
LIKE: It is a tree you follow one letter at a time, like the thumb-index tabs of a dictionary. Under "ap" you find "apple," "apply," and "ape" grouped together, so typing just "ap" shows the words below it right away.
STEP:
1. The Root is empty, and each Edge (or Node) represents one character.
2. Inserting "cat" goes down Root → c → a → t, creating Nodes, and marks the last Node as "end of word."
3. Inserting "car" reuses c → a, which already exist, and creates only r. Words with the same leading letters (**Prefix**) share branches.
4. **Search**: You just follow the letters down, so it takes only as long as the word length L. Even with a million words stored, it is O(L).
5. **Prefix search (autocomplete)**: Go down to "ca," then collect every word below it, and you are done.
PRO: Finding by prefix is very fast, and words sharing a prefix are organized together.
CON: Each Node holds several child Pointers, so it uses a lot of Memory.
USE: Search-box autocomplete, spell checking, prefix search in a phone book, and IP address lookup in Routers (longest prefix match).
END: A Trie is a tree you follow down letter by letter, and it is the best at finding "words that start with these letters."

### What is a Trie? Why is it used for Autocomplete?
E: It is a tree you follow one letter at a time, like a dictionary's thumb-index tabs. Words share their leading letters, as in "ap" → "apple," "apply," "ape," so typing just "ap" shows the words below it right away.
A: A Trie (Prefix Tree) is a Tree that splits a String into characters stored on Edges, so Search·Insert of a word of length L is O(L), regardless of how many words are stored. Words with the same Prefix are gathered on one branch, which is great for Autocomplete·Prefix Search·Spell Check, but each Node keeps Child Pointers, so it uses a lot of Memory.

## Graph Representation

#### Two Ways to Store a Graph: Adjacency Matrix vs Adjacency List
ONE: A Graph is stored as a **V × V table (Adjacency Matrix)** or as **a list of neighbors per Vertex (Adjacency List)**. Most real Graphs have few Edges, so the List is the default.
LIKE: An Adjacency Matrix is a distance table between every pair of cities in the country. With 1,000 cities, that is a million cells. An Adjacency List is each person's list of friends' contacts. You only write down as many as they have friends.
STEP:
1. A Graph is made of Vertices (points) and Edges (lines) (topic 01). If edges have direction, it is Directed; if they carry a cost, it is a Weighted Graph.
2. **Adjacency Matrix**: Make a V × V table, and if u and v are connected, write `M[u][v] = 1` (or the weight).
3. A Matrix tells you "are u and v connected?" in O(1). But its Memory is always O(V²), and to see all of one Vertex's neighbors you have to look at an entire row (V cells).
4. **Adjacency List**: For each Vertex, list only its connected neighbors. Memory is O(V + E).
5. With a List, looking at all neighbors takes only as long as the number of neighbors, so BFS·DFS run in O(V + E).
6. **Sparse vs Dense**: Social networks and road networks have very few Edges compared with their number of Vertices (Sparse). Nobody has billions of friends, after all. So Lists are used most of the time. For small Graphs with a lot of Edges (Dense), a Matrix is convenient.
| Approach | Memory | Check u-v connection | See all neighbors | When |
| Adjacency Matrix | O(V²) | O(1) | O(V) | Dense Graphs with many Edges |
| Adjacency List | O(V + E) | O(number of neighbors) | O(number of neighbors) | Most Sparse Graphs |
END: If connection checks are frequent and the Graph is dense, use a Matrix; for almost everything else, use a List.

### What is a Graph? What are Directed·Undirected·Weighted Graphs?
E: It is a subway map. Stations are Vertices, and the tracks between stations are Edges. If there are one-way routes, it is a Directed Graph; if travel times between stations are written on it, it is a Weighted Graph.
A: A Graph is a structure that represents relationships with Vertices (Nodes) and the Edges connecting them. If Edges have direction, it is a Directed Graph (following relationships); if not, an Undirected Graph (friendships); and if Edges carry a cost, a Weighted Graph (road distances). A Tree is one kind of Connected Graph with no Cycles.

### Adjacency Matrix vs Adjacency List: when do you use which?
| Approach | Analogy | Memory | "Is there a u-v Edge?" | See all neighbors | When |
| Adjacency Matrix | A distance table between every pair of cities (V × V cells) | O(V²) | O(1) | O(V) | Dense Graphs with many Edges |
| Adjacency List | Each person's list of friends' contacts | O(V + E) | O(Degree) | O(Degree) | Sparse Graphs with few Edges (most of them) |
A: An Adjacency Matrix is a V × V table that checks whether an Edge exists in O(1) but uses O(V²) Memory, while an Adjacency List stores only each Vertex's neighbor list, so O(V + E) Memory is enough. Most real Graphs (social networks, road networks) are Sparse, so Adjacency Lists are used, and BFS·DFS are O(V + E) on an Adjacency List.

## Disjoint Sets (Union-Find)

#### Union-Find (Disjoint Set)
ONE: A data structure that manages non-overlapping groups and does **"are these two elements in the same group?" (find)** and **"merge two groups" (union)** in nearly O(1).
LIKE: Every club has one president. "Are you two in the same club?" is answered by finding each person's president and comparing, and merging two clubs means putting one president under the other. It gets even faster if anyone who has tracked down their president once reports directly to the president from then on.
STEP:
1. Each element points to "my parent," and each group has a representative (Root) at the top. At first, everyone is their own representative.
2. **find(x)**: Follow parents up to find the representative. If two elements have the same representative, they are in the same group.
3. **union(a, b)**: Find the two representatives and attach one under the other.
4. Attaching naively can stretch the Tree into a single line, making find O(n). So two tricks are used.
5. **Union by Rank**: Attach the shorter Tree under the taller one so the height grows less.
6. **Path Compression**: Connect every Node met on the way up during find directly to the representative. Next time, it is found in one step.
7. Using both tricks together makes each operation effectively constant time (α(n), a function that grows extremely slowly).
```python
parent = list(range(n)); rank = [0] * n

def find(x):
    if parent[x] != x:
        parent[x] = find(parent[x])   # Path Compression
    return parent[x]

def union(a, b):
    ra, rb = find(a), find(b)
    if ra == rb: return False          # already in the same group
    if rank[ra] < rank[rb]: ra, rb = rb, ra
    parent[rb] = ra                    # shorter Tree under the taller one
    if rank[ra] == rank[rb]: rank[ra] += 1
    return True
```
CON: Merging is easy, but you cannot split a group once it has been merged.
USE: Kruskal's Algorithm (connecting every city at minimum cost), finding connected components in a Graph, Cycle checks (connecting two points already in the same group creates a Cycle), and grouping friends on social networks.
END: Union-Find is "find the representative + merge representatives," and the two tricks (Rank, Path Compression) make it nearly O(1).

### What is Union-Find? Why are Path Compression and Union by Rank needed?
E: Every club has one president. "Are you two in the same club?" is answered by finding each person's president and comparing (find), and merging two clubs means putting one president under the other (union). It gets faster if anyone who has tracked down their president once reports directly to the president from then on (Path Compression).
A: Union-Find represents non-overlapping Sets as a Forest of Trees, checks whether two elements are in the same Set with find (finding the Root), and merges two Sets with union. Merging naively can stretch a Tree into a single line, making it O(n), so it uses Union by Rank, which attaches the shorter Tree under the taller one, together with Path Compression, which connects Nodes met during find directly to the Root. With both, each operation is nearly constant time (the Inverse Ackermann Function α(n)), and it is used for Kruskal's MST and finding Connected Components.
```python
parent = list(range(n)); rank = [0] * n

def find(x):
    if parent[x] != x:
        parent[x] = find(parent[x])   # Path Compression
    return parent[x]

def union(a, b):
    ra, rb = find(a), find(b)
    if ra == rb: return False          # already in the same Set
    if rank[ra] < rank[rb]: ra, rb = rb, ra
    parent[rb] = ra                    # shorter Tree under the taller one
    if rank[ra] == rank[rb]: rank[ra] += 1
    return True
```
