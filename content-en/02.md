@intro Computer Architecture covers how a single line of code actually runs inside the machine. It is easier if you picture the computer as a **restaurant kitchen**. The CPU is the chef, Registers are the chef's hands, the Cache is the prep counter, Memory (RAM) is the fridge, and Storage (SSD) is the basement pantry.
@one A computer works by having the CPU fetch and execute Instructions stored in Memory one at a time, and to cut down the time spent waiting on slow Memory it uses a Memory Hierarchy that runs from small, fast Caches to large, slow Disks.

## What a Computer Is Made Of

#### The Four Parts of a Computer: CPU · Memory · Storage · Bus
ONE: A computer is made of a **CPU that calculates**, **Memory that remembers for a short time**, **Storage that keeps things long term**, and a **Bus** that connects the three.
LIKE: Picture a restaurant kitchen. The chef (CPU) does the cooking, today's ingredients sit in the fridge (Memory), and long-term supplies are in the basement pantry (Storage). The hallway used to carry ingredients around is the Bus.
STEP:
1. **CPU (Central Processing Unit)**: The part that actually calculates and makes decisions. It does tiny jobs like "add 3 and 5" or "is this value greater than 10?" billions of times per second.
2. **Memory (RAM)**: The workbench that holds the programs and data the CPU is using right now. It is fast, but everything disappears when the power goes off. This property is called **Volatile**.
3. **Storage (SSD·HDD)**: The warehouse that keeps photos, games, and documents long term. It survives power loss (**Non-Volatile**), but it is much slower than RAM.
4. **Bus**: The road that carries signals between parts. It carries "where" (Address), "what" (Data), and "read or write" (Control).
5. Launching a game works like this: the game files in Storage → are loaded into RAM → and the CPU fetches Instructions from RAM one by one and runs them.
WHY: Fast storage is expensive and small, while big storage is cheap but slow. No single part can be "fast, large, cheap, and persistent" all at once, so the jobs are split up.
USE: Phones, laptops, servers, and game consoles all share this structure. Sayings like "it's slow because it's out of RAM" or "switching to an SSD made it boot faster" all come from this structure.
KEY: RAM is the **workbench** and Storage is the **warehouse**. A program has to be moved from the warehouse to the workbench before it can run.
END: Computer = calculating (CPU) + short-term memory (RAM) + long-term storage (Storage) + connecting road (Bus). The speed gaps between these four are the starting point for understanding all of computer architecture.

#### Von Neumann Architecture (the Stored-Program Idea)
ONE: The idea of putting the program (Instructions) into Memory just like data, and having the CPU take Instructions out of Memory and run them one at a time.
LIKE: It is a kitchen that keeps its recipe cards in the same fridge as the ingredients. Swap in a different recipe card and the same kitchen can make sandwiches or pasta.
STEP:
1. Very early computers (for example, ENIAC) had to be rewired by hand, cable by cable and switch by switch, to change what they did.
2. That led to the idea: "Let's turn Instructions into numbers and store them in Memory too." This is called the **Stored-Program** approach.
3. Now the CPU only has to repeat: fetch an Instruction from Memory → interpret it → run it → fetch the next one.
4. To make the computer do something else, you just load a different program into Memory. That is why one computer can run both games and documents.
WHY: To make a machine do anything by changing only the software, without changing the hardware. The very concept of "installing an app" exists thanks to this idea.
USE: Almost every general-purpose computer (PCs, phones, servers) is based on this approach.
PRO: One machine can run any program, and the structure is simple.
CON: Instructions and data travel to and from Memory over the same road (Bus). The CPU is very fast while Memory is relatively slow, so the CPU sits idle waiting on Memory. This is called the **Von Neumann Bottleneck**.
KEY: To ease this bottleneck, computers place a small, fast **Cache** close to the CPU, and the L1 Cache nearest the CPU is often split into separate parts for Instructions and data.
END: The idea "a program is just data" is the starting point of today's computers, and the effort to ease its cost, the bottleneck, led to Caches and the Memory Hierarchy.

### What is the Von Neumann Architecture?
E: The recipe (Program) and the ingredients (Data) are kept in the same fridge (Memory), and the chef (CPU) takes out the recipe and follows it line by line. Change only the recipe and the same kitchen makes a different dish.
A: The Von Neumann Architecture is the Stored-Program approach in which Program (Instructions) and Data are stored in the same Memory and the CPU fetches and executes Instructions in order. Because Instructions and Data share the same road (Bus), Memory speed limits overall speed, which is called the "Von Neumann Bottleneck."

### What do the CPU, Memory, Storage, and Bus each do?
E: The CPU is the chef, Memory is the fridge holding today's ingredients (emptied when the power is off), Storage is the long-term warehouse (still there when the power is off), and the Bus is the hallway for carrying ingredients.
A: The CPU interprets Instructions and calculates, and Memory (RAM) is Volatile storage that holds running Programs and Data. Storage (SSD·HDD) is Non-Volatile storage that survives power loss, and the Bus carries Address, Data, and Control signals between them.

## How the CPU Works

#### Inside the CPU: Register · ALU · Control Unit · Program Counter
ONE: Inside the CPU are **Registers** that briefly hold values, an **ALU** that calculates, a **Control Unit** that directs, and a **Program Counter** that points to the next job.
LIKE: Think of the chef's body. The hands (Registers) hold ingredients, the knife and cutting board (ALU) do the prep, the head (Control Unit) directs the order, and a finger (Program Counter) marks "the line to read now" in the recipe.
STEP:
1. **Register**: A tiny storage slot inside the CPU. An x86-64 CPU has 16 general-purpose Registers, each holding a 64-Bit (8-Byte) value. It is the fastest storage in the computer.
2. **ALU (Arithmetic Logic Unit)**: The calculator that does arithmetic such as addition and subtraction and logic such as AND, OR, and size comparisons.
3. **Control Unit**: Reads an Instruction and sends signals to each part, such as "this is an addition, so the ALU adds and the result goes into this Register."
4. **Program Counter (PC)**: A special Register that records where in Memory (the Address) the next Instruction to run is. On x86-64 it is called `rip`.
WHY: The CPU is far faster than Memory, so fetching every value from Memory each time would be far too slow. Values being calculated right now are kept in Registers inside the CPU and used immediately.
KEY: A calculation usually goes "load from Memory into a Register → compute with the ALU → leave the result in a Register → store to Memory if needed."
END: Registers are the hands, the ALU is the tool, the Control Unit is the conductor, and the PC is the bookmark. Together the four handle each Instruction.

#### The Instruction Cycle (Fetch → Decode → Execute)
ONE: The CPU endlessly repeats **fetching (Fetch) → interpreting (Decode) → running (Execute)** Instructions.
LIKE: It is like cooking from a recipe: ① read the next line, ② understand "oh, it means chop the onion," and ③ actually chop it. Then go back to ①.
STEP:
1. **Fetch**: Get the Instruction at the Address the PC points to.
2. The PC moves forward so it points at the very next Instruction.
3. **Decode**: The Control Unit works out "what Instruction is this, and what values does it need?"
4. **Execute**: The ALU calculates, a value is read from or written to Memory, or execution jumps to another location.
5. The result is written to a Register (or Memory), and the cycle returns to step 1.
6. **Branch Instructions** that change the flow, like `if` or loops, change the PC to a different Address so execution moves somewhere other than "the very next line."
WHY: Even the most complicated program is ultimately this simple cycle repeated. Knowing this, "a fast CPU" makes sense as "it goes through this cycle a huge number of times per second."
USE: The **Clock** speed used to describe CPUs, such as 3 GHz, means 3 billion beats per second. How many beats one Instruction takes varies by Instruction and by CPU.
END: The CPU's job is an endless loop of "fetch → interpret → run," and the PC leads the order.

#### Pipelining and Hazards
ONE: A technique that splits Instruction processing into stages and **overlaps** several Instructions, so more Instructions finish in the same amount of time.
LIKE: Say you have 3 loads of laundry. If you wash, dry, and fold one load completely before starting the next, it takes a long time. If you put the second load in the washer the moment the first goes into the dryer, the machines never sit idle and the whole job goes faster.
STEP:
1. Split Instruction processing into stages, for example 5 (Fetch · Decode · Execute · Memory access · Write-back).
2. When Instruction 1 moves on to Decode, the now-empty Fetch stage fetches Instruction 2.
3. This way each stage holds a different Instruction at the same time, so ideally one Instruction finishes every beat.
4. Important: the time for **one** Instruction from start to finish (**Latency**) does not shrink. What grows is **the number of Instructions finished per unit of time (Throughput)**.
5. When Instructions overlap, there are situations where the next one cannot proceed right away. These are called **Hazards**.
| Hazard type | What happens | How it is handled |
| Structural | Two Instructions try to use the same part at once | Add more parts or wait your turn |
| Data | The next Instruction needs a result the previous one has not produced yet | Forwarding (pass the result straight along), Stall (pause briefly) |
| Control | You do not know which Instruction to fetch until a Branch is resolved | Branch Prediction |
WHY: To keep every part busy and get more done in the same time. Every modern CPU uses Pipelining.
PRO: Throughput rises a lot.
CON: Hazards cause waiting (Stalls), and when a branch prediction is wrong, the Instructions fetched ahead of time must be thrown away.
END: Pipelining is not about "running one Instruction faster" but about "overlapping many Instructions to finish more."

#### CISC vs RISC
ONE: A design with many complex, varied Instructions is **CISC**, and a design built around simple Instructions of uniform size is **RISC**.
LIKE: CISC is a chef who understands one big order like "make a lasagna." RISC is a chef who takes only short orders like "chop," "add," and "boil," but handles them very quickly and in a steady rhythm.
STEP:
1. The list of Instructions a CPU understands is its **ISA (Instruction Set Architecture)**. It is the contract between the CPU and software.
2. **CISC (Complex Instruction Set Computer)**: One Instruction does a lot of work, and Instructions vary in length. Example: Intel and AMD's **x86**.
3. **RISC (Reduced Instruction Set Computer)**: Instructions are simple and mostly the same length. Memory is accessed only with Load (read) and Store (write) Instructions, and calculations happen between Registers. Examples: **ARM**, **RISC-V**.
4. Simple, regular Instructions make Pipelining easier and the circuitry simpler, so the chip uses less power.
5. Today the line has blurred. Modern x86 chips also break complex Instructions into simple **Micro-ops** internally before running them.
| Aspect | CISC (x86) | RISC (ARM) |
| Instructions | Complex and varied, different lengths | Simple, mostly the same length |
| Strength | Software compatibility built up over decades | Performance per Watt |
| Main use | Many PCs and servers | Phones, tablets, Apple M-series Macs |
WHY: Whether you do the same work with "fewer big Instructions" or "more small Instructions" changes circuit complexity, speed, and power consumption.
END: Both can run the same programs. The difference is whether Instructions are big or small, and RISC (ARM) wins where power matters.

### What is the Instruction Cycle (Fetch → Decode → Execute)?
E: The chef endlessly ① reads the next line of the recipe (Fetch), ② understands that it means "chop the onion" (Decode), and ③ actually chops it (Execute). The finger marking "the next line to read" is the Program Counter.
A: The CPU fetches the Instruction at the Address the Program Counter (PC) points to (Fetch), works out which operation it is (Decode), runs it with the ALU and other parts (Execute), and writes the result to a Register or Memory. The PC advances to point to the next Instruction, or changes to another Address for a Branch Instruction.

### What are the Register, ALU, Control Unit, and Program Counter?
| Part | Analogy | Role |
| Register | The chef's hands | The fastest, smallest storage inside the CPU |
| ALU (Arithmetic Logic Unit) | Knife and cutting board | Performs addition, comparison, and logic operations |
| Control Unit | Head chef | Interprets Instructions and sends signals to each part |
| Program Counter (PC) | Finger on the recipe | Stores the Address of the next Instruction to run |
A: Registers are ultra-fast storage inside the CPU, the ALU performs arithmetic and logic, and the Control Unit interprets Instructions and directs the flow. The PC is the Register that holds the Address of the next Instruction; on x86-64 it is called rip.

### What are Pipelining and Hazards?
E: At a laundromat, finishing washing, drying, and folding one load before starting the next is slow. Washing the second load while the first is drying makes the whole job faster. But if you can't decide on the next step until this load is done, you have to wait; that is a Hazard.
A: Pipelining splits Instruction processing into stages (for example Fetch·Decode·Execute·Memory·Write-back) and overlaps several Instructions to raise Throughput. The running time of one Instruction (Latency) does not shrink. Hazards include Structural Hazards (resource conflicts), Data Hazards (needing a previous Instruction's result), and Control Hazards (Branches), and they are eased with Forwarding, Stalls, and Branch Prediction.

### CISC vs RISC: why is ARM strong on Mobile?
E: CISC is a chef who takes one big order like "make a lasagna," and RISC is a chef who takes only small, simple orders like "chop, add, boil" and handles them quickly.
A: CISC (x86) has many complex Instructions of varying length, while RISC (ARM, RISC-V) uses simple fixed-length Instructions and a Load/Store design. Thanks to its simple design, ARM has good Performance per Watt and is widely used in phones and laptops. Note that modern x86 chips also break Instructions into simple Micro-ops internally before running them.

## Data Representation

#### Bits and Bytes: Everything Is 0 and 1
ONE: A computer stores everything (numbers, text, photos, even sound) as **0s and 1s**. A single 0 or 1 is a **Bit**, and a group of 8 Bits is a **Byte**.
LIKE: Think of light switches. Each one is only on (1) or off (0), but put 8 switches side by side and you get 256 on/off combinations. Assign a number or meaning to each combination and you can represent anything.
STEP:
1. **Why 0 and 1?** For electric circuits, telling apart two states like "high voltage / low voltage" is the most reliable and cheapest thing to build.
2. **1 Bit** = 2 possibilities (0, 1). **2 Bits** = 4 (00, 01, 10, 11). Each extra Bit doubles the number of possibilities.
3. **A Byte (8 Bits)** = 2⁸ = **256 possibilities**. It can hold the numbers 0 through 255.
4. **Numbers** are written in Binary. Where decimal has the 1s, 10s, and 100s places, binary has the 1s, 2s, 4s, and 8s places. Example: 13 = 8 + 4 + 1, so `1101`.
5. **Text** uses a table that assigns a number to each character. **ASCII** numbers 128 English letters, digits, and symbols (for example 'A' = 65). **Unicode** numbers the characters of every writing system, including accented letters, Chinese characters, and emoji (for example 'é' = U+00E9, '中' = U+4E2D, '😀' = U+1F600). The most common way to store these numbers as Bytes is **UTF-8**, where an English letter takes 1 Byte, 'é' takes 2, '中' takes 3, and '😀' takes 4.
6. **Colors** set the brightness of red (R), green (G), and blue (B) light, each from 0 to 255. (255, 0, 0) is red and (255, 255, 255) is white. That gives 256 × 256 × 256 = about 16.77 million colors.
7. **A photo** is colored dots (**Pixels**) laid out in a grid, and **a video** is photos flipped by quickly, dozens per second.
KEY: The same group of Bits means different things depending on **how you interpret it**. Read `01000001` as a number and it is 65; read it as an ASCII character and it is 'A'. That is why file formats (.txt, .png, .mp3) act as agreements that say "read these Bits this way."
USE: File sizes (KB, MB, GB), internet speeds (Mbps = millions of Bits per second), and garbled text (when the Encoding used to save differs from the one used to read) all come from this idea.
END: Everything inside a computer is 0s and 1s, and the "agreement about what those 0s and 1s mean" is what creates numbers, text, colors, and sound.

#### The Limits of Integers: Integer Overflow
ONE: The slot that holds an integer has a fixed size (number of Bits), so going past the largest value it can hold makes the value change into something wrong.
LIKE: It is like a car odometer at 999,999 miles that rolls over to 000,000 after one more mile. There are only 6 digit slots, so there is nowhere to put a 7th digit.
STEP:
1. In languages like C, an `int` is usually **32 Bits**. 32 Bits make 2³² = about 4.3 billion combinations.
2. It also has to hold negative numbers, so half are used for negatives and the other half for zero and positives. The range is **−2,147,483,648 to 2,147,483,647 (about ±2.1 billion)**.
3. Add 1 to 2,147,483,647 and what happens? On typical computers you get the other end, **−2,147,483,648**, just like an odometer rolling over.
4. Watch out: by the rules of C, Overflow of a signed integer (signed int) is **Undefined Behavior**, so you must not rely on the result. For unsigned integers, wrapping back to 0 is defined by the rules.
5. Integers in **Python** grow automatically as large as needed, so this kind of Overflow does not happen. The cost is that they are slower and use more Memory.
WHY: When you handle numbers that keep growing, like money, time, or view counts, Overflow leads to real incidents.
USE: In December 2014, when the view count of "Gangnam Style" reached the maximum of a 32-Bit signed integer (2,147,483,647), YouTube switched view counts to 64-Bit integers. Also, systems that store the seconds since 1970 in a 32-Bit signed integer run out of room on January 19, 2038 (the **Year 2038 Problem**). That is why time is stored in 64 Bits today.
KEY: If big numbers are possible, use 64-Bit integers from the start (C's `long long`, `int64_t`), and check ranges before calculating.
END: A computer integer is "a calculator with a fixed number of digit slots." Overflowing the slots corrupts the value, so think about ranges ahead of time.

#### Floating-Point and 0.1 + 0.2
ONE: A way of storing decimals in the form "digits × a power of 2." It can hold both very large and very small numbers, but most decimals are stored as **approximations**.
LIKE: Think of the scientific notation used in science class, like 6.02 × 10²³. Write down just the digits (6.02) and how many places to move the decimal point (23), and even a huge number is short. But the digits have a fixed number of slots, so the last digit gets rounded.
STEP:
1. **Fixed-Point**: Fixes the position of the decimal point, like "always exactly 2 digits after the point." It is simple, but the range it can hold is narrow.
2. **Floating-Point**: Lets the decimal point move ("float"). The name of the standard is **IEEE 754**.
3. A number is stored in three parts: the **Sign** (+ or −), the **Exponent** (how many places to move the point), and the **Mantissa** (the actual digits). A 64-Bit `double` uses 1 + 11 + 52 Bits.
4. Here is where the problem comes from. Just as 1/3 = 0.3333… never ends in decimal, **0.1 is a never-ending fraction in binary**. The Mantissa has only 52 slots, so it has to be cut off and rounded somewhere.
5. So 0.1 and 0.2 are each stored as "a very slightly different value," and adding them gives `0.30000000000000004`. In the end, `0.1 + 0.2 == 0.3` is `False`.
6. This is not a Bug but normal IEEE 754 behavior, and Python, JavaScript, and Java all behave the same way.
KEY:
- Compare real numbers by "close enough" instead of `==`. In Python, use `math.isclose(a, b)`.
- For money, use integers (in cents) or a base-10 decimal type such as `decimal` instead of floats.
PRO: It represents a wide range, from huge to tiny numbers, with few Bits, and the hardware computes it quickly.
CON: Most decimals are approximations, so small errors appear, and repeated calculations can pile errors up.
END: Floating-Point is a representation that "gives up a little accuracy to get a wide range." So allow for error when comparing, and handle money as integers.

#### Endianness (the Order of Bytes)
ONE: The rule for **which end's Byte goes first** when a multi-Byte number is placed in Memory.
LIKE: It is like how the US writes dates as "10/23/2026" (month first) while much of Europe writes "23/10/2026" (day first). Even for the same date, you misread it if you do not know the order.
STEP:
1. The number `0x12345678` is 4 Bytes: `12`, `34`, `56`, `78`. Here `12` is the most significant part and `78` the least significant.
2. Memory is a line of numbered slots (Addresses), so these 4 Bytes must go into 4 slots in some order.
3. **Big Endian**: The most significant part goes first → `12 34 56 78`. This matches the order people read.
4. **Little Endian**: The least significant part goes first → `78 56 34 12`.
5. Intel and AMD x86 CPUs are Little Endian, while data sent over a network uses Big Endian as the standard (**Network Byte Order**).
WHY: When machines that use different orders exchange data, or when you read a file Byte by Byte, a number is read as a completely different value unless the orders are matched.
USE: You must account for it in network programming (conversion functions such as `htonl`), file format analysis, and reading the Headers of image and audio files.
END: Endianness is an agreement about "which end of the Bytes goes first," and systems using different agreements must always convert.

#### Parity Bits and Hamming Codes (Finding and Fixing Errors)
ONE: Ways of attaching check Bits to data so you can **detect (Parity)** whether a Bit flipped during storage or transmission, or even find where it went wrong and **fix it (Hamming Code)**.
LIKE: Parity is like shipping a friend a box of apples with a note that says "the number of apples is even." If they count an odd number, they know "something went wrong." A Hamming Code attaches several such notes, each covering a different group of slots, so the receiver can tell "which slot is wrong."
STEP:
1. Electrical noise or particles from space occasionally flip a Bit in Memory or on a wire from 0↔1.
2. **Even Parity**: Attach one Bit so the number of 1s in the data is even. Example: `1011` has three 1s (odd), so attach a Parity Bit of 1 and send `1011` + `1`.
3. The receiver counts the 1s; if the count is odd, it knows there is an error.
4. Limits: if 2 Bits flip at once, the count is even again and the error goes unnoticed. And it cannot tell **which** Bit is wrong, so it cannot fix it.
5. **Hamming Code**: Several Parity Bits are arranged so each checks a different group of positions. The combination of checks that fail points to the position of the wrong Bit, which is then flipped back. The classic **Hamming(7,4)** adds 3 Parity Bits to 4 Data Bits, sends 7 Bits, and can fix a 1-Bit error.
USE: Server **ECC Memory** uses Hamming-family codes to fix Bit errors automatically. A QR code still scans when part of it is covered thanks to error-correcting codes too (QR uses a different method called Reed-Solomon).
PRO: Parity costs just one extra Bit, so it is very cheap. A Hamming Code can even fix errors.
CON: Parity only knows that an error exists and cannot fix it. A Hamming Code needs more check Bits.
END: If a few added Bits tell you "whether it is wrong," that is Detection; if they tell you "where it is wrong," that is Correction.

### What are Bits and Bytes? How does a computer store text and colors as 0s and 1s?
E: Eight switches turned on and off make 256 combinations. Assign each combination a meaning, like "number 65 is A" or "this combination is red," and you can write anything in 0s and 1s.
A: A Bit is the smallest unit of information, holding 0 or 1, and 8 Bits make 1 Byte, which represents 256 values. Numbers are stored in binary, text with numbering tables such as ASCII or Unicode (Encodings such as UTF-8), colors as combinations of R·G·B intensity, and images as grids of Pixels. The same Bits can be a number or a character depending on the rule used to interpret them.

### What is Integer Overflow?
E: Just as an odometer at 999999 rolls over to 000000 after one more step, a value changes into something wrong when it goes past the largest number an integer slot can hold.
A: It happens because integers are stored in a fixed number of Bits, so a result outside the representable range does not fit. A 32-Bit signed int ranges over about ±2.1 billion (−2,147,483,648 to 2,147,483,647), and adding 1 to the maximum usually wraps to the minimum. In C, signed Overflow is Undefined Behavior, so you use a 64-Bit type or check the range before calculating. Python integers have arbitrary precision, so they never Overflow.

### How do Fixed-Point and Floating-Point differ?
E: Fixed-Point is like a price tag that nails down "two digits after the decimal point," and Floating-Point is scientific notation like 6.02 × 10²³, which moves the decimal point with "digits × a power" to hold both huge and tiny numbers.
A: Fixed-Point has a fixed decimal point position, so its range is narrow but its Precision is uniform. Floating-Point (IEEE 754) represents a number with a Sign, an Exponent, and a Mantissa to cover a wide range; a 64-Bit double uses 1 Bit for the Sign, 11 Bits for the Exponent, and 52 Bits for the Mantissa.

### Why is 0.1 + 0.2 == 0.3 False?
E: Writing 1/3 in decimal gives 0.3333…, which never ends, so it has to be cut off somewhere. In binary, 0.1 is exactly that kind of never-ending fraction.
A: 0.1 and 0.2 cannot be represented exactly in binary Floating-Point, so each is Rounded to the nearest representable value, and that error makes the sum 0.30000000000000004. So real numbers are compared with `math.isclose()` instead of ==, and money is calculated with `decimal` or integers (in cents).

### What are Big Endian and Little Endian?
E: It is the difference between writing a date as month/day/year, like the US, or day/month/year, like much of Europe.
A: It is the order in which a multi-Byte value is placed in Memory: Big Endian puts the most significant Byte (MSB) at the lowest Address, and Little Endian puts the least significant Byte (LSB) there. Storing 0x12345678 in Little Endian gives the order 78 56 34 12; x86 is Little Endian, and network transmission (Network Byte Order) uses Big Endian.

### How do Parity Bits and Hamming Codes find and fix errors?
E: Parity is a tag that says "the number of apples in this box must be even." If the count is odd, you know something went wrong, but not which apple is the problem. A Hamming Code layers several tags so it can point to exactly which position is wrong.
A: A Parity Bit is a single Bit that makes the number of 1s even (or odd); it can only Detect an odd number of Bit errors, not fix them. A Hamming Code places several Parity Bits over different combinations of positions so it can locate and fix (Correct) a 1-Bit error. The classic Hamming(7,4) adds 3 Parity Bits to 4 Data Bits.

## Memory Hierarchy and Cache

#### The Memory Hierarchy
ONE: A structure that **stacks storage in layers**, from fast but small and expensive storage down to slow but large and cheap storage.
LIKE: A chef keeps things used constantly, like salt, on the counter within reach, today's ingredients in the fridge, and everything else in the basement pantry. Keeping everything on the counter would be nice, but counter space is small and expensive.
STEP:
1. From top to bottom: **Register → L1 Cache → L2 Cache → L3 Cache → RAM → SSD/HDD**.
2. Higher levels are faster, smaller, and more expensive. Lower levels are slower, larger, and cheaper.
3. The CPU first looks for data in the closest level, L1. If it is there (**Cache Hit**) it is used right away; if not (**Cache Miss**), the CPU goes down a level, finds it, and copies it into the level above.
4. Programs strongly tend to reuse data they just used (Locality, which comes next), so most requests are answered by the upper levels.
5. The result is almost Cache-level speed with RAM-and-SSD-level capacity.
| Level | Approximate access time | If L1 took 1 second |
| L1 Cache | about 1 ns | 1 second |
| RAM | about 100 ns | about 1 minute 40 seconds |
| SSD | tens to hundreds of µs | hours to days |
| HDD | several ms | weeks to months |
WHY: Building large capacity from only fast storage is far too expensive, and using only cheap storage leaves the CPU waiting constantly. The hierarchy is a compromise that keeps the strengths of both.
USE: Not just CPU Caches, but web browser Caches, CDNs, and Cache Servers like Redis all work on the same principle: "keep what you use often close by."
END: The Memory Hierarchy is an organizing rule: "frequently used things in fast places, everything else in cheap places."

#### Cache and Locality
ONE: Programs do not use Memory evenly; they tend to reuse **what they just used and what sits next to it**. This property is Locality, and Caches exploit it.
LIKE: The salt you just used, you will use again soon (time). The pepper next to the salt is likely to be used soon too (space). So when a chef goes to the pantry, they bring back the whole spice shelf, not a single bag of salt.
STEP:
1. **Temporal Locality**: Recently used data is used again soon. Examples: a loop variable `i`, a running total `sum`.
2. **Spatial Locality**: Addresses near the one just used are used soon. Example: reading an Array in order: element 0, 1, 2…
3. A Cache fetches data not one Byte at a time but in chunks called **Cache Lines** (usually 64 Bytes on x86). Read element 0 of an Array and its neighbors come along with it.
4. So when you read an Array in order, most accesses from the second element on are Cache Hits.
5. On the other hand, jumping around Memory forces a new chunk to be fetched every time, which is slow.
KEY: Looping over a 2D Array in **Row** order is fast and in **Column** order is slow. Default Arrays in C and NumPy are **Row-Major**, meaning each row is laid out contiguously in Memory, so reading along rows takes advantage of Spatial Locality.
```c
// Fast: read across a row (contiguous in Memory)
for (i = 0; i < N; i++) for (j = 0; j < N; j++) sum += a[i][j];
// Slow: read down a column (jumps N slots at a time in Memory)
for (j = 0; j < N; j++) for (i = 0; i < N; i++) sum += a[i][j];
```
WHY: The same calculation can become several times faster just by changing the order in which Memory is read.
END: A Cache brings "what you'll use again soon and what's next to it" close ahead of time, and code written to match Locality gets faster for free.

#### Cache Mapping and the 3 Causes of Cache Misses
ONE: Mapping is the rule for **which Cache slots** a piece of Memory data may go into, and a Miss is when the data you want is not in the Cache.
LIKE: Think of classroom seating. In one classroom your seat is set by the last digit of your student ID (Direct Mapped), in another you can sit anywhere (Fully Associative), and in a third your table group is set by your number but you can pick any seat at that table (Set Associative).
STEP:
1. A Cache is much smaller than Memory, so many Memory addresses have to share the same Cache slots.
2. **Direct Mapped**: Each address can go into exactly 1 slot. Lookup is easy and fast, but two pieces of data that share a slot keep kicking each other out when used alternately.
3. **Fully Associative**: Data can go into any slot. Slot conflicts are minimal, but the circuitry that compares every slot at once is expensive, so it is hard to use for large Caches.
4. **n-way Set Associative**: The Set (group) an address goes to is fixed, but it can go into any of the n slots in that Set. Most real CPU Caches use this approach.
5. When the slots are full, something has to be evicted. Usually it is the one unused for the longest time (**LRU, Least Recently Used**, or an approximation of it).
| Miss type (3C) | Cause | How to reduce it |
| Compulsory | First access, so it is not in the Cache yet | Prefetch (fetch ahead), larger Cache Lines |
| Capacity | The data in use is bigger than the Cache | Bigger Cache, work on less data at a time |
| Conflict | Fighting over the same slot because of the placement rule | Increase Associativity (n) |
WHY: The mapping scheme changes lookup speed and the Hit rate, and you need to know why Misses happen to decide what to fix.
END: Mapping is a compromise between "easy to find" and "few slot conflicts," and Misses happen because it is the first time (Compulsory), there is not enough room (Capacity), or the placement rule causes fights (Conflict).

#### Write-Through vs Write-Back
ONE: The choice of whether, when a Cache value changes, to **write it to Memory immediately as well (Write-Through)** or **write it later all at once (Write-Back)**.
LIKE: Logging every purchase in the family budget spreadsheet the moment you make it is Write-Through. Jotting purchases in your own notebook and copying them over only when you tidy up the notebook is Write-Back.
STEP:
1. When the CPU changes a value, the Cache's copy changes first. Now the Cache and Memory can disagree.
2. **Write-Through**: Every write also goes to Memory immediately. The two always match, which is simple, but every write must travel to slow Memory.
3. **Write-Back**: Write only to the Cache and set a "changed" flag (**Dirty Bit**).
4. When that Cache slot must be given up for other data (**Eviction**), if the Dirty flag is set, the value is written to Memory once at that point.
5. Even if the same value changes many times, Memory is written only once at the end, so it is much faster.
| Aspect | Write-Through | Write-Back |
| Write speed | Slow | Fast |
| Implementation | Simple | Complex (manages Dirty Bits) |
| Matches Memory | Always | May differ temporarily |
USE: Most modern CPU Caches use Write-Back. Putting a Cache in front of a database raises the same question: "write to the DB right away, or batch it up?"
END: Choose Write-Through when simplicity and consistency matter, and Write-Back when speed matters.

### Why does a Memory Hierarchy exist?
E: A chef keeps frequently used salt on the counter within reach, today's ingredients in the fridge, and everything else in the basement pantry. Keeping everything on the counter would be nice, but counter space is small and expensive.
A: Fast Memory is expensive and small, and large Memory is cheap but slow, so computers use a Hierarchy: Register → L1·L2·L3 Cache → RAM → SSD/HDD. Keeping frequently used Data in the upper levels makes most accesses fast while still providing large, inexpensive capacity.
M: Rough orders of magnitude: L1 Cache about 1 ns, RAM about 100 ns, SSD tens to hundreds of µs, HDD several ms. RAM is about 100 times slower than L1, and HDD is about 100,000 times slower than RAM.

### Explain Locality in Caches.
E: Temporal Locality is "the salt you just used, you'll use again soon," and Spatial Locality is "the pepper next to that salt will be used soon too." So when a chef goes to the pantry, they bring back the whole spice shelf rather than a single spice.
A: Locality is the tendency of a Program to use Memory in clusters rather than evenly. Temporal Locality means recently accessed Data is reused soon (loop variables), and Spatial Locality means nearby Addresses are used soon (iterating an Array). Caches exploit this by fetching Data in Blocks (Cache Lines, usually 64 Bytes on x86).
M: Spatial Locality is why looping over a 2D Array in Row order is fast and in Column order is slow (default C and NumPy Arrays are stored Row-Major).

### What are the Cache Mapping schemes and the 3 kinds of Cache Misses?
E: Direct Mapped is "a classroom where your seat is set by the last digit of your student ID," Fully Associative is "a classroom where you sit anywhere," and Set Associative is "your table is assigned, but you choose your seat at it."
A: Direct Mapped gives each Block exactly one possible slot, Fully Associative allows any slot, and n-way Set Associative allows any of the n slots in a fixed Set. The 3Cs of Misses are Compulsory (first access), Capacity (the Cache is too small), and Conflict (fighting over the same slot).

### What is Write-Through vs Write-Back?
E: Entering every expense into your banking app the moment you make it is Write-Through, and jotting them on a sticky note and copying them over only when you throw the note away is Write-Back.
A: Write-Through writes to the Cache and Memory at the same time, so it is simple and Consistent but slow to write. Write-Back writes only to the Cache, marks the change with a Dirty Bit, and writes to Memory when the Block is evicted (Eviction), which is fast but complex to implement.

## Assembly and Function Calls (x86-64)

#### Stack Frames and call · ret
ONE: Each time a function is called, the **temporary space it needs (a Stack Frame)** is pushed onto the Stack, and when the function finishes, the space is cleared and execution returns to where it was.
LIKE: When you leave the page you are reading to look at a footnote, you slip a bookmark into the current page. If that footnote sends you to another one, you add another bookmark. Coming back, you remove **the most recently added bookmark first**. A structure where "the last thing in comes out first" is a Stack.
STEP:
1. The **Stack** is a Memory area that works like a stack of plates: you add to the top and remove from the top (**LIFO, Last In First Out**).
2. When `main` calls `f()`, the CPU's `call` Instruction pushes the **Return Address** (the address of the Instruction right after the call to `f()`) onto the Stack and jumps to `f`.
3. `f` reserves its own space on top of the Stack. That holds its **Local Variables** and any Register values it needs to save temporarily. This chunk is the **Stack Frame**.
4. When `f` finishes, it clears its space and runs the `ret` Instruction. `ret` pops the Return Address off the Stack and jumps back to it.
5. When a function calls another function, Frames keep piling up, and they disappear one by one in the order the functions finish.
6. On x86-64 the Stack grows **from high addresses toward low addresses**. The Register pointing to the top is `rsp` (the Stack Pointer).
KEY:
- When a function returns, its Local Variables are gone. That is why returning the address of a Local Variable out of a function is dangerous.
- If Recursion goes infinitely deep, the Frames exceed the Stack size and the program crashes with a **Stack Overflow**.
USE: The Call Stack shown when an Error occurs (Python's Traceback) is exactly the list of function calls piled up at that moment. It is the most basic debugging information.
END: A function call = push the return address and jump (`call`) → do the work → pop the address and return (`ret`). The temporary space used in between is the Stack Frame.

#### Calling Conventions
ONE: An agreement made in advance between the calling side and the called side about **"where arguments go, where the result comes back, and who protects which Registers."**
LIKE: It is like the rules for lending a friend your desk for a while. "I'll put the homework in the first drawer (arguments). Leave the answer in the top drawer when you're done (return value). You can use the left drawer, but put things back the way they were (Callee-Saved). Use the right drawer however you like; I'll take out anything I need first (Caller-Saved)."
STEP:
1. A CPU has only a handful of Registers, and every function shares them. Without rules, functions would overwrite each other's values.
2. **Passing arguments**: Under the System V AMD64 convention used by Linux and macOS, the first 6 integer or Pointer arguments go into Registers in the order `rdi, rsi, rdx, rcx, r8, r9`, and the 7th onward go on the Stack.
3. **Return value**: Returned in `rax`.
4. **Caller-Saved**: Registers the called function (Callee) may change freely. If the calling side (Caller) still needs a value after the call, it saves it beforehand.
5. **Callee-Saved**: Registers the called function must save before using and restore before returning.
| Category (System V AMD64) | Registers |
| Arguments 1–6 | rdi, rsi, rdx, rcx, r8, r9 |
| Return value | rax |
| Callee-Saved | rbx, rbp, r12, r13, r14, r15 (and rsp) |
| Caller-Saved | rax, rcx, rdx, rsi, rdi, r8, r9, r10, r11 |
WHY: As long as everyone follows this agreement, code written by different people with different Compilers can call each other. It is why you can use Libraries written by others.
KEY: The agreement differs by operating system. Windows x64 passes arguments in the order `rcx, rdx, r8, r9`. A memory trick for the System V order: "Di Si Dx Cx 8 9."
END: A Calling Convention is the "Register usage rulebook" between functions, and thanks to it, separately built code can call each other safely.

### What is a Stack Frame? What do call and ret do?
E: When you leave the page you're reading to check a footnote, you slip in a bookmark and return to it when you're done. The pile of notepads used for each function call (Local Variables + where to return) is the Stack Frame.
A: A Stack Frame is the Stack area used by one Function Call, holding the Return Address, saved Registers, and Local Variables. call pushes the Address of the next Instruction (the Return Address) onto the Stack and jumps to the function, and ret pops that Address and returns. On x86-64, the Stack grows from high Addresses toward low Addresses.

### What is the difference between Caller-Saved and Callee-Saved Registers?
E: When you lend your desk to a friend (the Callee), the drawers your friend promises to "put back the way they were after using" are Callee-Saved, and the drawers they say "I'll use freely, so take out anything you need first" are Caller-Saved.
A: A Caller-Saved Register may be changed freely by the called function, so the calling side (Caller) saves it first if it needs the value after the call. A Callee-Saved Register must be saved by the called function (Callee) before use and restored before it returns.
| Category (System V AMD64) | Registers |
| Callee-Saved | rbx, rbp, r12, r13, r14, r15 (and rsp) |
| Caller-Saved | rax, rcx, rdx, rsi, rdi, r8, r9, r10, r11 |

### Which Registers are used to pass Function Arguments?
A: Under the System V AMD64 Calling Convention used by Linux and macOS, the first 6 integer or Pointer Arguments are passed in rdi, rsi, rdx, rcx, r8, r9, in that order, and the 7th onward go on the Stack. The Return Value comes back in rax. Windows uses a different convention (rcx, rdx, r8, r9).
M: Memory trick: "Di Si Dx Cx 8 9" (rdi, rsi, rdx, rcx, r8, r9).

## C Memory Model

#### Memory Addresses and Pointers
ONE: Memory is a very long row of Byte slots, each with a number (**Address**), and a **Pointer** is a variable that holds one of those numbers.
LIKE: Picture a hallway lined with billions of lockers, each with a number. A Pointer is not the item itself but a note that says "it's in locker 15."
STEP:
1. Creating a variable reserves a slot somewhere in Memory. `int x = 7;` puts 7 into a 4-Byte slot.
2. `&x` means "the address of x." It gives a number like `0x7ffd1000`.
3. A variable that holds an address, like `int *p = &x;`, is a Pointer.
4. `*p` means "the value in the slot p points to." Following an address like this is called **Dereferencing**. Writing `*p = 10;` changes x to 10.
5. An **Array** is a row of equal-sized slots placed side by side. If you know the address of the first slot, `arr[i]` is found instantly by computing "i slots after the first." That is why `arr[i]` is the same as `*(arr + i)`.
6. Arrays and Pointers are not exactly the same, though. `sizeof(arr)` is the size of the whole Array, while `sizeof(p)` is the size of one Pointer (8 Bytes on a 64-Bit system).
```c
int x = 7;
int *p = &x;   // p holds the address of x
*p = 10;       // write 10 where p points (x) → now x is 10
```
WHY: You can pass "where something is" instead of copying large data wholesale, and a function can change a variable outside itself directly.
KEY: In C, passing a variable to a function passes a **copy** (**Call by Value**). To change the original inside a function, you must pass its address. `swap(&a, &b)`, which exchanges two values, is the classic example.
USE: Pointers are central to data structures like Linked Lists and Trees, Heap Memory, and operating system and hardware control. Python and Java do not expose Pointers directly, but internally they use **References** that point to objects.
END: A Pointer is not "a value" but "the number of the place where a value lives." `&` gets the number, and `*` goes to the number.

#### Stack vs Heap, malloc · free, and Memory Leaks
ONE: The **Stack** is temporary space that is cleaned up automatically when a function ends, and the **Heap** is space the programmer must borrow (`malloc`) and give back (`free`) by hand.
LIKE: The Stack is like paper plates the restaurant clears away for you, and the Heap is like rental gear you borrow and must return yourself. Forget to return it and the free space in the warehouse keeps shrinking. That is a Memory Leak.
STEP:
1. **Stack**: Holds the Local Variables created inside a function. They appear when the function starts and disappear automatically when it ends. Fast, but small (usually a few MB).
2. **Heap**: Holds data whose size is only known at run time, or data that must outlive the function. Borrow space with `malloc(size)` and you get back that space's address (a Pointer).
3. When you are done, you must return it yourself with `free(pointer)`. C will not clean it up for you.
4. **Memory Leak**: If you never call `free` and also lose the address, nobody can use that space until the program ends. On a long-running server this keeps piling up until Memory runs out.
5. **Uninitialized variables**: In C, a Local Variable you never assigned, or space from `malloc`, may still contain leftover **Garbage Values**. Always assign a value before using it (`calloc` gives you space filled with zeros).
6. Tools like **Valgrind** find Leaks, invalid accesses, and uses of uninitialized values.
| Aspect | Stack | Heap |
| Allocation and release | Automatic (function start and end) | Manual (`malloc`·`free`) |
| Speed | Very fast | Relatively slow |
| Size | Small (usually a few MB) | Large (as much as Memory allows) |
| Lifetime | Gone when the function ends | Until you `free` it |
| Common mistake | Recursion too deep → Stack Overflow | Memory Leak, Double Free |
KEY: Languages like Python and Java automatically reclaim Heap space that is no longer used (**Garbage Collection**), so you never call `free`. The cost is the time spent reclaiming.
END: Short-lived use inside a function goes on the Stack; long-lived or variable-size data goes on the Heap. The rule for the Heap: "if you borrowed it, you must return it."

#### Three Memory Errors: Dangling Pointer · Double Free · Buffer Overflow
ONE: C does not check whether you use Memory correctly, so you can make mistakes like using space you already returned, returning it twice, or writing past the end of a slot.
LIKE: In locker terms: still stuffing things into a locker number you already turned in (Dangling Pointer), turning in the same locker twice (Double Free), or cramming so much into one locker that it pushes into the neighbor's (Buffer Overflow).
STEP:
1. **Dangling Pointer**: A Pointer that still holds an address after it was `free`d. Reading or writing through it is called **Use-After-Free**. Other data may already be using that space.
2. **Double Free**: Calling `free` on the same space twice. It corrupts the bookkeeping that manages Memory.
3. **Buffer Overflow**: Writing past the size of an Array. Put 20 items into a 10-slot Array and the extra 10 overwrite neighboring data. C does not check Array lengths for you.
4. All three are **Undefined Behavior**. The program may crash right away, or seem fine and go wrong later, which makes them hard to track down.
WHY: Because they are not just Bugs but **security holes**. Overwrite the Return Address on the Stack with a Buffer Overflow and an attacker can make the program jump to code of their choosing.
KEY:
- Set a Pointer to `NULL` after `free`
- Use functions that check lengths (`fgets` instead of `gets`)
- Check with tools like AddressSanitizer and Valgrind
USE: That is why more and more teams use **Memory-Safe** languages (Rust, Go, Java, Python, and others) that prevent these mistakes in the language itself.
END: C's freedom comes with responsibility: "don't use what you returned, return it only once, and don't go past the number of slots."

#### C Strings and the Null Character
ONE: A C string is an Array of characters with a **Null character (`\0`)** at the end to mark "it ends here."
LIKE: It is like placing an "end of line" sign behind the last person in a queue. C does not record the length of the line separately, so you have to count people one by one until you reach the sign.
STEP:
1. `char s[] = "hi";` is stored in Memory as 3 slots: `'h'`, `'i'`, `'\0'`. There are 2 characters but 3 slots.
2. `strlen(s)` counts until it hits `\0` and returns 2. So finding the length takes time proportional to the number of characters.
3. If you forget the slot for `\0` or it gets overwritten, string functions cannot find the end and keep reading into neighboring Memory. This is another common cause of Buffer Overflows.
KEY: An Array that holds a string always needs **number of characters + 1** slots.
USE: Strings in Python and Java store their length separately and check bounds, so these problems do not happen.
END: A C string = characters + the end marker `\0`. Always budget one slot for the end marker.

#### Struct Padding
ONE: The **empty Bytes (Padding)** a Compiler inserts between Struct members so the CPU can read the data quickly.
LIKE: Imagine putting boxes on a shelf with dividers every 4 spaces. If a big 4-space box goes right after a small 1-space box, the big box straddles a divider and is awkward to pull out. So you leave 3 spaces empty after the small box and line the big box up with a divider.
STEP:
1. A CPU reads fastest when 4-Byte data sits at an address that is a multiple of 4 and 8-Byte data at a multiple of 8. This is called **Alignment**.
2. In `struct { char c; int i; }`, the `char` is 1 Byte and the `int` is 4 Bytes.
3. If `c` sits at address 0, `i` must start at address 4, a multiple of 4. So 3 empty Bytes go into positions 1–3.
4. The result is not 1 + 4 = 5 Bytes but **8 Bytes** (on a typical 64-Bit system).
5. Declaring members **from largest to smallest** reduces Padding.
```c
struct A { char c; double d; char e; };  // 1 + 7 padding + 8 + 1 + 7 padding = 24 Bytes
struct B { double d; char c; char e; };  // 8 + 1 + 1 + 6 padding = 16 Bytes
```
WHY: Misaligned data forces the CPU to read Memory twice, and some CPUs raise an error outright.
USE: It matters in programs that handle millions of Structs and wherever the exact Byte layout counts, such as network Packets and file formats.
PRO: Data can be read quickly and safely.
CON: The empty Bytes waste Memory.
END: Padding is "empty space added to line up with the dividers for speed," and putting larger members first reduces the waste.

### What is a Pointer? How are Arrays and Pointers related?
E: A Pointer is not the item itself but a note saying "it's in locker 15." An Array is a row of side-by-side lockers, so knowing the first number lets you find any other locker a few slots down.
A: A Pointer is a variable that stores the Memory Address of another variable, and `*p` accesses the value at that Address (Dereference). In most expressions an Array's name turns into a Pointer to its first element (Array Decay), so `arr[i]` is the same as `*(arr + i)`. However, `sizeof(arr)` gives the size of the whole Array, so Arrays and Pointers are not exactly the same.

### In C, how does a function change the original variable it was given?
E: If you hand a friend a photocopy of your homework, your homework stays the same no matter what they fix. To let them fix yours, you have to tell them "my locker number."
A: C supports only Call by Value, which passes copies of Arguments, so changing a parameter inside a function leaves the original untouched. To change the original, pass the variable's Address and Dereference the Pointer inside the function. Example: `swap(&a, &b)`.

### What are Stack vs Heap Memory, malloc/free, and Memory Leaks?
E: The Stack is paper plates the restaurant clears for you, and the Heap is rental gear you borrow and must return yourself. Borrow and forget to return, and the free space in the warehouse gradually disappears. That is a Memory Leak.
A: The Stack is a small, fast area where a function's Local Variables are allocated and released automatically, and the Heap is the area you allocate from with malloc in whatever amount you need and release yourself with free. Losing the Address of allocated Heap Memory without freeing it is a Memory Leak, and tools like Valgrind find it.

### What are a Dangling Pointer, a Double Free, and a Buffer Overflow?
| Error | Analogy | Meaning |
| Dangling Pointer | Still using a locker number you turned in | A Pointer to freed Memory (using it is Use-After-Free) |
| Double Free | Returning an item you already returned | Calling free on the same Memory twice |
| Buffer Overflow | Overstuffing a locker so it spills into the next one | Writing beyond an Array's bounds |
A: All three are Bugs that happen because C does not check Memory Safety, and they cause Undefined Behavior. A Buffer Overflow in particular becomes a security Vulnerability that lets an attacker run code by overwriting the Return Address. You prevent them by setting Pointers to NULL after free and using functions that check lengths.

### How does C know where a string ends?
E: Like putting an "end of line" sign at the very end of a queue, a single end marker is attached after the characters.
A: A C string is a char Array with a Null character (`'\0'`) at the end to mark where it stops. So "hi" needs 3 Bytes, and `strlen` counts up to `'\0'`, making it O(n). If the `'\0'` is missing, string functions read past the end of the Array, which can cause a Buffer Overflow.

### Why does Padding get added to a Struct's size?
E: When stacking moving boxes on a shelf, big boxes are easier to pull out if they line up with the shelf dividers. You line them up even if it means leaving empty space after a small box.
A: A CPU reads Data fastest when it is Aligned to an Address that is a multiple of its size, so the Compiler inserts empty Bytes (Padding) between Members. On a typical 64-Bit system, `struct { char c; int i; }` is 8 Bytes, not 1 + 4. Declaring larger Members first reduces Padding.

## Compiling and Linking

#### The 4 Stages of Building a C Program
ONE: C code written by a person becomes a file the CPU can run by going through 4 stages: **Preprocessing → Compile → Assemble → Link**.
LIKE: It is like making a book: ① paste reference material into the manuscript, ② translate it into the machine's language, ③ print it, and ④ bind several chapters into one volume.
STEP:
1. **Preprocessing**: Pastes the contents of a file wherever `#include <stdio.h>` appears and replaces names defined with `#define` with their values. (`hello.c` → `hello.i`)
2. **Compile**: Translates the C code into that CPU's **Assembly** (machine Instructions in human-readable form). Syntax errors are caught here. (`hello.i` → `hello.s`)
3. **Assemble**: Turns the Assembly into machine code made of 0s and 1s, producing an **Object File**. (`hello.s` → `hello.o`)
4. **Link**: Combines your Object Files with Library code such as `printf`, connects the addresses that say "this function lives here," and produces an **Executable**. (`hello.o` → `hello`)
```sh
gcc hello.c -o hello   # runs all 4 stages at once
./hello                # runs the resulting executable
```
WHY: The CPU does not understand C, only machine code. And large programs are split into files that are compiled separately and then combined, so only changed files need recompiling, which is faster.
KEY: An `undefined reference to ...` error is a Link-stage error. It means the function was declared, but its actual code (definition) could not be found.
END: Build = paste (Preprocessing) → translate (Compile) → into machine code (Assemble) → combine (Link).

#### Static Linking vs Dynamic Linking
ONE: **Copying** Library code into the executable is Static Linking, and **loading it from outside** at run time is Dynamic Linking.
LIKE: Static is copying the entire text of the books you cited onto the back of your report. Dynamic is just writing "see the such-and-such book, library third floor" and borrowing it when you need to read it.
STEP:
1. Programs use many Library functions written by others, such as `printf`.
2. **Static Linking**: At the Link stage, the needed Library code is copied into the executable. With just that one file, the program runs anywhere.
3. **Dynamic Linking**: The executable keeps only a note saying "I need this Library." At run time the operating system finds the **Shared Library** (Linux `.so`, Windows `.dll`, macOS `.dylib`) and connects it.
4. When several programs use the same Shared Library, only one copy needs to be loaded into Memory and they share it.
| Aspect | Static | Dynamic |
| Executable size | Large | Small |
| What it needs to run | Just the one file | The right Library must be installed |
| Library security updates | Must rebuild to pick them up | Replace the Library and every program gets it |
| Memory | Separate copy per program | Can be shared across programs |
KEY: Errors like "xxx.dll was not found" happen when a Library needed by Dynamic Linking is missing.
END: Choose Static when it must run reliably on its own, and Dynamic when size and updates matter.

### What are the stages of building a C Program?
E: ① Paste reference material into the manuscript (Preprocessing), ② translate it into the machine's language (Compile·Assemble), and ③ bind the chapters into one volume (Link).
A: The Preprocessor expands #include and #define, the Compiler translates to Assembly, and the Assembler produces a machine-code Object File (.o). Finally, the Linker combines the Object Files and Libraries, connects function Addresses, and produces the Executable.

### What is the difference between Static Linking and Dynamic Linking?
E: Static Linking is copying your whole bibliography onto the back of the book, and Dynamic Linking is writing "see the book on the library's third floor" and borrowing it when you need to read it.
A: Static Linking copies Library code into the Executable so it runs on its own, but the file gets bigger. Dynamic Linking loads Shared Libraries (.so, .dll) at run time, saving space and allowing the Library to be updated separately, but the target computer must have the right Library.

? What does Pipelining directly improve?
- The running time of a single Instruction
- The number of Instructions processed per unit of time (Throughput)
- Memory capacity
- Power consumption
= B
! It overlaps several Instructions to raise Throughput. The running time of a single Instruction does not shrink.

- Memory Leak
- Overflow

? What best explains why YouTube switched view counts from 32-Bit integers to 64-Bit integers in 2014?
- The view count reached the maximum of a 32-Bit signed integer (about 2.1 billion)
- To eliminate Floating-Point error
- To match Endianness with Network Byte Order
- To reduce Cache Misses
= A
! A 32-Bit signed integer can hold only up to 2,147,483,647, so storing larger view counts required a bigger integer slot (64 Bits). That is how you avoid Integer Overflow.
