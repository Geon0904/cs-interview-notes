## Number Systems and Bits

#### Bases: Binary · Decimal · Hexadecimal
ONE: The same number can be written in base 10 (Decimal), base 2 (Binary), or base 16 (Hexadecimal), depending on **how many you group together when you count**.
LIKE: Think about coins. Ten pennies trade for a dime, and ten dimes trade for a dollar: that is base 10. Now imagine coins worth only 1, 2, 4, and 8 cents, and you may hold at most one of each. That is base 2.
STEP:
1. **Decimal (base 10)**: Each place is worth 10 times the one to its right: 1, 10, 100, 1000… It feels natural because we have ten fingers.
2. **Binary (base 2)**: Each place is worth 2 times the one to its right: 1, 2, 4, 8, 16… Each place holds only 0 or 1, which matches a computer's switches (on/off) perfectly.
3. **Decimal → Binary**: Keep dividing by 2 and read the remainders backwards. 13 ÷ 2 = 6 r1, 6 ÷ 2 = 3 r0, 3 ÷ 2 = 1 r1, 1 ÷ 2 = 0 r1 → read backwards: `1101`.
4. **Binary → Decimal**: Add up the place values. `1101` = 8 + 4 + 0 + 1 = 13.
5. **Hexadecimal (base 16)**: After 0–9 it uses A(10), B(11), C(12), D(13), E(14), F(15). **Four binary digits match exactly one hex digit.**
6. **Binary → Hexadecimal**: Split into groups of four. `1101 1110` → `1101`=D, `1110`=E → `0xDE`. In decimal that is 13×16 + 14 = 222.
WHY: Everything inside a computer is binary, but binary is too long for people to read. So we also use hexadecimal, which packs four binary digits into one character.
USE: Hex shows up whenever a computer's internal values are displayed: color codes like `#FF0000` (red), Memory addresses like `0x7ffd1000`, file permissions, and Network addresses.
KEY: `0x` means "what follows is hex," and `0b` means "what follows is binary." `0x10` is 16, while `0b10` is 2.
END: A base is only a difference in how you group while counting; the number is the same. Computers calculate in base 2, and people read it in base 16 because it is shorter.

#### Two's Complement: How Negative Numbers Are Stored
ONE: To make a negative number, flip every Bit of the positive number and add 1. Thanks to this, a computer can **subtract using the same adder circuit it uses to add**.
LIKE: When a three-digit odometer rolls back one step from 000, it shows 999. So we can agree that 999 means "−1." Two's Complement makes the same agreement in 8 Bits: one step below 00000000 is 11111111, and that means −1.
STEP:
1. **The problem**: A Bit has no room for a + or − sign. We need a rule that writes negative numbers with only 0s and 1s.
2. **How to make one**: 5 is `00000101`. Flip every Bit to get `11111010`, then add 1 to get `11111011`. That is −5.
3. **Check it**: 5 + (−5) = `00000101` + `11111011` = `1 00000000`. The leading 1 that overflows the 8 slots is thrown away, so the result is `00000000` = 0. Correct.
4. If the **leftmost Bit** is 0, the number is positive (or zero); if it is 1, the number is negative. That is why the leftmost Bit is also called the **Sign Bit**.
5. **Range**: n Bits hold −2ⁿ⁻¹ through 2ⁿ⁻¹ − 1. 8 Bits hold −128 to 127; 32 Bits hold about −2.1 billion to 2.1 billion.
6. **Overflow**: Going past the range wraps around to the other end. In 8 Bits, 127 + 1 = −128. If adding two positive numbers gives a negative result, Overflow has happened.
WHY: The alternative (using just the leftmost Bit as a sign) produces both a +0 and a −0, and subtraction needs its own circuit. Two's Complement has only one zero and reuses the addition circuit.
USE: Almost every CPU stores integers this way. The same `11111111` reads as 255 when Unsigned and as −1 when Signed.
KEY: The recipe for a negative number is "flip (NOT) + 1." To find the size of a negative number, do the same thing again: "flip + 1."
END: Two's Complement agrees, like an odometer, that the numbers below 0 are the ones at the far end, so a single addition circuit handles both positive and negative math.

#### Bitwise Operations: AND · OR · XOR · Shift
ONE: Operations that compare or shift numbers one Bit at a time.
LIKE: Picture laying two panels of 8 switches on top of each other. AND means "on only where both panels are on," OR means "on if either is on," XOR means "on only where they differ," and Shift means "slide every switch over by one."
STEP:
1. **AND (`&`)**: 1 only when both are 1. `1100 & 1010 = 1000`. Used as a **Mask** to pick out just the Bits you want.
2. **OR (`|`)**: 1 if either is 1. `1100 | 1010 = 1110`. Used to turn specific Bits on.
3. **XOR (`^`)**: 1 when they differ. `1100 ^ 1010 = 0110`. Used to flip specific Bits. XOR with the same value twice and you get the original back.
4. **NOT (`~`)**: Flips every Bit.
5. **Left Shift (`<<`)**: Shifting left by one doubles the value. `0011`(3) << 1 = `0110`(6), as long as nothing overflows.
6. **Right Shift (`>>`)**: Shifting right by one gives the quotient of dividing by 2 (for non-negative numbers). `0110`(6) >> 1 = `0011`(3).
WHY: CPUs process Bit operations extremely fast, and packing many on/off flags into one number saves Memory.
USE: Linux file permissions (read 4, write 2, execute 1, added up into something like `755`), Feature Flags that switch features on and off, checking odd or even (`n & 1`), and Bitmask Algorithms that store a whole subset in one number.
KEY: If `n & 1` is 1, n is odd; if it is 0, n is even. If `x & (1 << k)` is not 0, Bit k is on.
END: Bitwise operations are "stacking and sliding switch panels." AND picks, OR turns on, XOR flips, and Shift doubles or halves.

## Propositional Logic

#### Propositions and Logical Operators (NOT · AND · OR)
ONE: A **Proposition** is a statement that is definitely either True or False, and you combine propositions into bigger statements with NOT, AND, and OR.
LIKE: "It is raining today" is either true or false, so it is a proposition. "This song is great" depends on who you ask, so it is not. A proposition works exactly like a computer's `if` condition.
STEP:
1. **NOT (¬p)**: Flips true to false and false to true. The NOT of "It is raining" is "It is not raining."
2. **AND (p ∧ q)**: True only when both are true. "It is raining and windy."
3. **OR (p ∨ q)**: True if at least one is true, including when both are. "It is raining or windy."
4. **Truth Table**: A table that lists every possible true/false combination and its result. With n propositions there are 2ⁿ combinations.
5. **Tautology**: A formula that is always true no matter what you plug in. Example: p ∨ ¬p ("It is raining or it is not").
6. **Contradiction**: A formula that is always false. Example: p ∧ ¬p ("It is raining and not raining").
| p | q | ¬p | p ∧ q | p ∨ q |
| T | T | F | T | T |
| T | F | F | F | T |
| F | T | T | F | T |
| F | F | T | F | F |
WHY: Every condition in a program (`if`, `while`) is built from propositional logic. You need to know logic precisely to write conditions without mistakes.
USE: `if (age >= 18 and has_ticket)`, the logic circuits in a CPU (AND Gate, OR Gate), and search filters (`A OR B`) are all propositional logic.
END: A proposition is a statement that is either true or false; NOT flips it, AND means "both," and OR means "at least one."

#### Conditionals p → q and the Contrapositive
ONE: "If p then q" (p → q) is false **only when p is true and q is false**. Its contrapositive (¬q → ¬p) always means exactly the same thing.
LIKE: Your mom promises, "If you finish your homework, you can play video games." The only way this promise is broken is if you finish your homework and still are not allowed to play. If you skip your homework, whether you play or not, the promise was not broken.
STEP:
1. **The 4 cases of p → q**: p true, q true → true / p true, q false → **false** / p false, q true → true / p false, q false → true.
2. It can feel odd that the whole statement is true whenever p is false. Think of it as "the condition of the promise never happened, so the promise was not broken."
3. **Contrapositive**: ¬q → ¬p. "If you did not get to play, you did not finish your homework." It **always means the same thing** as the original.
4. **Converse**: q → p. "If you played, you finished your homework." This can differ from the original (you might have been allowed to play without doing homework).
5. **Inverse**: ¬p → ¬q. "If you do not finish your homework, you cannot play." This can also differ. The converse and inverse are contrapositives of each other, so they mean the same as each other.
| Name | Form | Same meaning as the original? |
| Contrapositive | ¬q → ¬p | Always |
| Converse | q → p | Not necessarily |
| Inverse | ¬p → ¬q | Not necessarily |
WHY: Assuming "the converse must be true too" is a classic logic error. When p → q is hard to prove directly, you can prove its equivalent contrapositive instead.
USE: Rewriting negated conditions in code review, designing test cases, and proof by contrapositive in math.
KEY: Even if "If it rains, the ground gets wet" is true, "If the ground is wet, it rained" (the converse) can be false. Someone might have turned on the sprinklers.
END: p → q is false only when "p but not q," and the only rearrangement with the same meaning is the contrapositive (¬q → ¬p).

#### De Morgan's Law
ONE: The rule that **AND and OR swap places** when you move a NOT inside the parentheses.
LIKE: If "It is raining and windy" is false, what is true? Either it is not raining, or it is not windy, or both. The opposite of "both are true" is not "both are false" but "at least one is false."
STEP:
1. **First law**: ¬(p ∧ q) ≡ ¬p ∨ ¬q. The negation of "both" = "at least one is not."
2. **Second law**: ¬(p ∨ q) ≡ ¬p ∧ ¬q. The negation of "at least one" = "neither."
3. Memory trick: the NOT moves inside and attaches to each part, and the operator in the middle flips ∧ ↔ ∨.
4. The same rule works for sets. The complement of (A ∩ B) = the complement of A ∪ the complement of B.
```python
# These two conditions always give the same result
if not (is_member and has_coupon): ...
if (not is_member) or (not has_coupon): ...
```
WHY: To rewrite complicated conditions so they are easier to read, and to express "when it is not the case that…" correctly. Getting a negation wrong is a common source of Bugs.
USE: Simplifying conditions, rewriting SQL like `WHERE NOT (A AND B)`, and logic circuit design (building every other Gate from NAND Gates alone).
END: The opposite of "both" is "at least one is not," and the opposite of "at least one" is "neither."

### When is p → q false? How do the Converse, Inverse, and Contrapositive differ?
E: Your mom promises, "If you finish your homework, you can play video games." The promise is broken only if you finished your homework and still were not allowed to play. If you skipped your homework, playing or not playing does not break the promise.
A: p → q is false only when p is true and q is false. The Contrapositive (¬q → ¬p) always means the same as the original, while the Converse (q → p) and the Inverse (¬p → ¬q) can differ from it.
| Name | Form | Same meaning as the original? |
| Contrapositive | ¬q → ¬p | Always |
| Converse | q → p | Not necessarily |
| Inverse | ¬p → ¬q | Not necessarily (same as the Converse) |

### What is De Morgan's Law?
E: Saying "It is raining and windy" is false means "It is not raining, or it is not windy." When you push a negation inside the parentheses, "and" and "or" trade places.
A: ¬(p ∧ q) ≡ ¬p ∨ ¬q and ¬(p ∨ q) ≡ ¬p ∧ ¬q. In code, it lets you rewrite `if not (a and b)` as `if (not a) or (not b)` to make conditions easier to read.

### What are a Tautology and a Contradiction?
A: A Tautology is a formula that is always true regardless of the variables (p ∨ ¬p), and a Contradiction is one that is always false (p ∧ ¬p). Saying two formulas are Logically Equivalent means "A ↔ B is a Tautology."

## Predicate Logic

#### ∀ (for all), ∃ (there exists), and Negation
ONE: **∀** means "for every x," and **∃** means "there exists some x." Negating "all" gives "at least one is not."
LIKE: To show that "Everyone in our class wears glasses" is wrong, you do not need to check the whole class. You only need to find **one** classmate without glasses.
STEP:
1. Propositional logic only handled whole sentences like "It is raining." **Predicate Logic** handles sentences whose truth depends on the subject x, such as "x wears glasses" = P(x).
2. **∀x P(x)**: Every x satisfies P. "Every student wears glasses."
3. **∃x P(x)**: At least one x satisfies P. "At least one student wears glasses."
4. **Negating ∀**: ¬∀x P(x) ≡ ∃x ¬P(x). "Not all are" = "there is at least one that is not."
5. **Negating ∃**: ¬∃x P(x) ≡ ∀x ¬P(x). "Not even one is" = "none are."
WHY: A single **Counterexample** is enough to break the claim "my program is correct for every input." To show it is correct, on the other hand, you have to prove every case.
USE: Program specifications ("returns sorted output for every input"), database queries (SQL `EXISTS`, `ALL`), and hunting for counterexamples in tests.
KEY: When negating, ∀ ↔ ∃ swap and a NOT attaches to the inner statement. It is the "all / at least one" version of De Morgan's Law.
END: "All" is broken by one counterexample, and "there exists" is proven by one example.

#### The Order of Quantifiers
ONE: **Swapping the order of ∀ and ∃ can completely change the meaning.**
LIKE: "Everyone has a mother" (∀person ∃mother) is true, because each person can have a different mother. But "There is one person who is everyone's mother" (∃mother ∀person) is false.
STEP:
1. **∀x ∃y**: Pick x first, then choose a y that fits that x. y can be different for each x.
2. **∃y ∀x**: Fix one y first, and that single y must work for every x. This is a much stronger claim.
3. Integer example: "For every x there is a y bigger than x" (∀x ∃y, y > x) is true: just choose y = x + 1.
4. But "There is a y bigger than every x" (∃y ∀x, y > x) is false, because there is no largest integer.
5. In general, if ∃y ∀x is true then ∀x ∃y is also true, but not the other way around.
WHY: In math definitions and program specifications, a difference in order alone produces completely different requirements.
USE: The definition of Big-O in algorithm analysis ("there exists a constant c such that for all sufficiently large n…") is a classic ∃∀ statement.
END: ∀∃ means "a custom one for each," and ∃∀ means "one single thing that works for everyone."

### What do ∀ and ∃ mean, and how do you negate them?
E: To refute "Everyone in our class wears glasses," you do not have to ask everyone; you only need to find one person without glasses. The opposite of "everyone" is not "no one" but "at least one person is not."
A: ∀ (Universal Quantifier) means "for all," and ∃ (Existential Quantifier) means "there exists." ¬∀x P(x) ≡ ∃x ¬P(x) and ¬∃x P(x) ≡ ∀x ¬P(x). That is why the claim "it is correct for every input" collapses with a single Counterexample.

### Why does swapping the order of Quantifiers change the meaning?
E: "Everyone has a mother" (∀∃) is true, but "There is one person who is everyone's mother" (∃∀) is false.
A: ∀x∃y lets you choose a different y for each x, while ∃y∀x requires one y that works for every x. For example, over the integers, "for every x there is a y bigger than x" is true, but "there is a y bigger than every x" is false.

## Set · Function · Relation

#### Sets and Set Operations
ONE: A **Set** is a collection of elements with no duplicates, and you combine sets with operations such as union, intersection, and difference.
LIKE: Think about pizza toppings. Given the toppings I like (A) and the toppings my friend likes (B), we can find the ones either of us likes (union), the ones we both like (intersection), and the ones only I like (difference).
STEP:
1. **Set**: There is no order, and adding the same element twice still counts once. {1, 2, 2} = {1, 2}.
2. **Union (A ∪ B)**: Elements in A or B (or both).
3. **Intersection (A ∩ B)**: Elements in both A and B.
4. **Difference (A − B)**: Elements in A but not in B.
5. **Power Set**: The collection of every possible subset. With n elements, each element is either "in" or "out," so there are **2ⁿ** subsets. The Power Set of {a, b} is {∅, {a}, {b}, {a, b}}.
6. **Cartesian Product (A × B)**: Every ordered pair made by picking one from A and one from B. 2 crusts × 3 toppings = 6 pizzas.
WHY: "Collect without duplicates" and "find what overlaps" are extremely common tasks in programming, and set operations are the basic tools for them.
USE: Python's `set` (`a | b`, `a & b`, `a - b`), SQL's `UNION`·`INTERSECT`·`EXCEPT`, and the Cartesian Product that is the starting point of SQL `JOIN`.
KEY: A Power Set size of 2ⁿ also means "an Algorithm that checks every subset is O(2ⁿ)." It becomes impossible to handle as soon as n grows even a little.
END: A Set is "a collection without duplicates"; ∪ combines, ∩ keeps the overlap, and − removes.

#### Function: Injective · Surjective · Bijective
ONE: A **Function** is a rule that assigns exactly one output to each input. Depending on whether outputs repeat and whether any outputs are left unused, it is injective, surjective, or bijective.
LIKE: Think of assigning seats in a movie theater. Each moviegoer (input) gets one seat (output). "No two people share a seat" is injective, "no seat is left empty" is surjective, and "one seat per person with no empty seats" is bijective.
STEP:
1. **Function f: A → B**: Pairs every element of A (the Domain) with exactly one element of B (the Codomain).
2. **Injective**: Different inputs go to different outputs. No outputs are shared.
3. **Surjective**: Every element of B is the output of some input. No outputs are left over.
4. **Bijective**: Both injective and surjective. A and B are matched exactly 1:1.
5. **Inverse Function**: A function that goes back from output to input. It exists only for a Bijective function. If outputs were shared, you would not know which input to go back to; if outputs were left over, some would have nowhere to go back to.
WHY: Asking "can this be undone?" is the same as asking "is it Bijective?" It is the central question when designing encryption, compression, and Encoding.
USE: Encryption must be decryptable, so it must be Bijective. A Hash Function has far more possible inputs than outputs, so it cannot be Injective, which is why Collisions happen.
KEY: For finite sets, if there is a Bijection between A and B, the two sets have the same size. That is why "match them up 1:1" is such a powerful Counting tool.
END: Injective = no sharing, surjective = nothing left over, bijective = both. Only a bijection can be undone.

#### Equivalence Relation
ONE: A relation with all three properties (reflexive, symmetric, transitive), which **splits everything into non-overlapping groups**.
LIKE: Think of the relation "is in the same homeroom as." I am in the same homeroom as myself; if I am in yours, you are in mine; and if A shares a homeroom with B and B with C, then A shares one with C. So the whole school splits neatly into homerooms.
STEP:
1. **Relation**: A rule that says whether two elements "are related or not." Examples: "is in the same homeroom," "is less than."
2. **Reflexive**: Every a is related to itself.
3. **Symmetric**: If a is related to b, then b is related to a.
4. **Transitive**: If a–b and b–c are related, then a–c is related.
5. A relation with all three is an Equivalence Relation, and each group of mutually related elements is called an **Equivalence Class**.
6. Example: "has the same remainder when divided by 3" splits the integers into three groups: remainder 0, 1, and 2.
KEY: "Is less than (<)" is not symmetric, so it is not an equivalence relation. 3 < 5, but 5 < 3 is false.
WHY: Grouping complicated things into "essentially the same" bunches makes problems simpler.
USE: The Union-Find data structure (quickly checking whether two items are in the same group), Connected Components in a Graph (grouping things that are linked), and hash-based grouping.
END: Equivalence relation = reflexive + symmetric + transitive. Whenever you have one, everything splits cleanly into non-overlapping groups.

### What are Union, Intersection, Difference, Power Set, and Cartesian Product?
E: Think about pizza toppings. The Power Set is "every combination of toppings you could choose" (including no toppings at all), and the Cartesian Product is every pair you can make from "crust type × topping type."
A: Union A ∪ B is the elements in either set, Intersection A ∩ B is the elements in both, and Difference A − B is the elements only in A. The Power Set of a Set with n elements has 2ⁿ Subsets, and the Cartesian Product A × B has |A|·|B| Ordered Pairs.

### How do Injective, Surjective, and Bijective Functions differ?
E: Think of assigning theater seats. Injective means "no two people share a seat," Surjective means "no seat is empty," and Bijective means "one seat per person and no empty seats."
A: An Injective Function sends different inputs to different outputs, and a Surjective Function covers every value in the Codomain. A Function that is both is Bijective, and only a Bijective Function has an Inverse Function.

### What is an Equivalence Relation?
E: It is a relation like "is in the same homeroom as." I am in my own homeroom (Reflexive); if I am in yours, you are in mine (Symmetric); and if A and B share a homeroom and B and C do too, then A and C do (Transitive).
A: An Equivalence Relation is a relation that is Reflexive, Symmetric, and Transitive, and it splits the whole Set into non-overlapping groups (Equivalence Classes). "Has the same remainder when divided by 3" is a classic example.

## Proof Techniques

#### Three Paths to a Proof: Direct · Contrapositive · Contradiction
ONE: Ways to show a claim is always true: **Direct Proof** goes forward, **Proof by Contrapositive** goes backward, and **Proof by Contradiction** shows that "if it were not true, something absurd would follow."
LIKE: They are like three ways to solve a maze: walk step by step from the entrance to the exit (direct), trace the path backward from the exit (contrapositive), or show that "if this path were blocked, something impossible would happen" (contradiction).
STEP:
1. **Direct Proof**: Start from the assumption p and chain known facts until you reach the conclusion q. Example: "If n is even, then n² is even" → let n = 2k; then n² = 4k² = 2(2k²), which is even.
2. **Proof by Contrapositive**: Instead of p → q, prove the equivalent ¬q → ¬p. Example: "If n² is even, then n is even" becomes easy as "If n is odd, then n² is odd."
3. **Proof by Contradiction**: Assume the conclusion is false and show that this leads to a contradiction (an impossible result).
4. Classic example: "√2 cannot be written as a fraction." Assume it equals a fraction a/b in lowest terms; it follows that both a and b are even, which contradicts "lowest terms."
5. **Counterexample**: To show that "every ~ is ~" is false, a single counterexample is enough; no proof needed.
WHY: "I tried it a few times and it worked" is not a proof. A proof gives certainty that it works in every case.
USE: Showing an Algorithm always returns the right answer, and reasoning about whether a security protocol is safe.
END: If you get stuck, change direction. If going forward is hard, go backward with the contrapositive; if that is hard too, "assume it is not true" and look for a contradiction.

#### Mathematical Induction
ONE: A way to prove something for every natural number by showing two things: **the first case is true**, and **if any step is true, the next step is true too**.
LIKE: Picture dominoes. If you knock over the first one (Base Case), and every domino is placed so that when it falls the next one falls (Inductive Step), then all of them fall to the very end.
STEP:
1. **Base Case**: Show the smallest case (usually n = 1 or 0) is true.
2. **Inductive Hypothesis**: Assume it is true for n = k.
3. **Inductive Step**: Use that assumption to show it is true for n = k + 1.
4. Example: 1 + 2 + … + n = n(n+1)/2. For n = 1, 1 = 1·2/2 ✓. If it holds for k, the sum for k + 1 is k(k+1)/2 + (k+1) = (k+1)(k+2)/2 ✓.
5. **Strong Induction**: Instead of assuming only "it is true for k," assume "it is true for every value from 1 to k." Use it when you need a smaller step that is not the one right before, such as when a problem is split in half.
WHY: Natural numbers never end, so you cannot check them one by one. Induction proves infinitely many cases at once by showing just two steps.
USE: Proving a recursive function correct (it works on small inputs, and if smaller problems work then bigger ones do) and proving a **Loop Invariant** in a loop.
KEY: Skip the Base Case and the proof collapses. Even if the dominoes are perfectly placed, nothing falls unless you knock over the first one.
END: Induction = the first domino + the chain rule. It is the basic tool for proving recursion and loops correct.

### When do you use Direct Proof, Proof by Contrapositive, or Proof by Contradiction?
E: Direct Proof is following a map from the start to the destination, Proof by Contrapositive is tracing back from the destination, and Proof by Contradiction is showing that "if it were not so, it would make no sense."
A: Direct Proof goes step by step from the assumption to the conclusion, and Proof by Contrapositive proves p → q by showing ¬q → ¬p. Proof by Contradiction assumes the conclusion is false and derives a contradiction; the proof that √2 is irrational is the classic example.

### How do Mathematical Induction and Strong Induction differ?
E: Think of dominoes. If the first domino falls (Base Case) and any falling domino knocks over the next one (Inductive Step), every domino falls. Strong Induction uses the assumption "if all the dominoes before it have fallen."
A: Ordinary Induction shows that if P(k) is true then P(k+1) is true, and Strong Induction shows that if P(1) through P(k) are all true then P(k+1) is true. Both are used directly to prove Loop Invariants and the correctness of Recursive Algorithms.

## Counting

#### The Sum Rule and the Product Rule
ONE: **Add** choices that cannot happen at the same time (Sum Rule), and **multiply** choices made one after another (Product Rule).
LIKE: If lunch is one of 3 sandwiches "or" one of 2 salads, you have 3 + 2 = 5 options. If you pick one of 3 mains "and" one of 2 drinks, you have 3 × 2 = 6 options.
STEP:
1. **Sum Rule**: If cases A and B do not overlap, the number of ways for A or B = A + B.
2. **Product Rule**: If the first choice has a options and the next has b options, the number of ways to make both choices in a row = a × b.
3. Remember it as: "or" means add, "and (then)" means multiply.
4. Example: a 4-digit numeric passcode has 10 × 10 × 10 × 10 = 10,000 possibilities.
5. Example: 8 Bits have 2 × 2 × … × 2 (8 times) = 256 possibilities.
WHY: Every counting technique (permutations, combinations, and so on) comes from these two rules.
USE: Judging how strong a password is (more possibilities make brute-force guessing harder) and counting the cases an Algorithm must check.
KEY: Use the Sum Rule only when the cases do not overlap. If they overlap, correct for it with Inclusion–Exclusion, which comes later.
END: "Or" adds, and "and" multiplies.

#### Permutations and Combinations
ONE: When choosing k items from n, it is a **Permutation if order matters** and a **Combination if order does not**.
LIKE: Electing a class president and vice president is a permutation, because "Alex president, Sam vice president" differs from "Sam president, Alex vice president." Picking 2 students for cleanup duty is a combination, because their order does not matter.
STEP:
1. **Factorial (n!)**: n × (n−1) × … × 1. The number of ways to line up n people. 3! = 6.
2. **Permutation P(n, k)**: The number of ways to pick k of n people and line them up in order = n × (n−1) × … × (n−k+1) = n!/(n−k)!. President and vice president from 5 people = 5 × 4 = 20.
3. **Combination C(n, k)**: Ignores order. The k! orderings of the same k people must count as one, so divide P(n, k) by k!. C(n, k) = n!/(k!(n−k)!). 2 cleanup helpers from 5 people = 20 / 2 = 10.
4. **Symmetry**: C(n, k) = C(n, n−k). Choosing 2 of 5 people = choosing the 3 to leave out.
WHY: You must count "how many cases are there" precisely to compute probabilities and to predict how long an Algorithm will take.
USE: Lottery odds (choosing 6 of 45 numbers = 8,145,060 combinations), counting test combinations, and estimating the running time of a Brute Force Algorithm.
KEY: If you get confused, ask: "If the chosen people swapped places, would that be a different case?" If yes, it is a permutation; if no, a combination.
END: When order matters, use the permutation n!/(n−k)!; when it does not, use the combination n!/(k!(n−k)!).

#### Stars and Bars
ONE: A technique for counting the ways to split **identical items** among **distinct boxes** by turning it into the problem of lining up stars (★) and bars (|).
LIKE: Say you hand out 5 identical candies to 3 kids. Line up the 5 candies and slip in 2 dividers, and you get 3 sections. ★★|★|★★ means "2, 1, 2," and ★★★★★|| means "5, 0, 0."
STEP:
1. Imagine lining up n candies (★) and k−1 dividers (|) in one row. The k−1 dividers create k sections.
2. The whole row has length n + k − 1.
3. Once you decide which positions hold the dividers, one way of splitting is fixed.
4. So the answer is C(n + k − 1, k − 1).
5. For 5 candies and 3 kids, that is C(5 + 3 − 1, 3 − 1) = C(7, 2) = 21 ways.
KEY: This formula allows a kid to get zero candies. If "everyone gets at least 1," hand out 1 to each first and count again with the remaining n − k: C(n − 1, k − 1).
WHY: Cases that would be far too many to list one by one can be counted with a single formula once you turn them into a lineup problem.
USE: Counting ways to split a budget across categories, or the number of non-negative integer solutions to x + y + z = 10.
END: Ways to split n identical items into k places = ways to line up n ★ and (k−1) | = C(n+k−1, k−1).

#### The Inclusion–Exclusion Principle
ONE: When counting overlapping sets, **subtract what you counted twice, then add back what you subtracted too many times**.
LIKE: There are 10 students on the soccer team, 8 on the basketball team, and 3 who play both. How many students play a sport? Saying 10 + 8 = 18 counts the 3 two-sport students twice. So the answer is 18 − 3 = 15.
STEP:
1. **Two sets**: |A ∪ B| = |A| + |B| − |A ∩ B|. Subtract the overlap once.
2. **Three sets**: First add all three (|A| + |B| + |C|), then subtract the three pairwise overlaps.
3. But an element in all three sets was added 3 times at first and subtracted 3 times with the pairwise overlaps, leaving 0. So add it back once at the end.
4. Formula: |A ∪ B ∪ C| = |A| + |B| + |C| − |A∩B| − |A∩C| − |B∩C| + |A∩B∩C|.
5. Rule: add intersections of an odd number of sets and subtract intersections of an even number.
WHY: Using the Sum Rule as is when things overlap gives the wrong answer. Inclusion–Exclusion corrects for the overlap exactly.
USE: Counting with several overlapping conditions, such as "how many numbers from 1 to 100 are multiples of 2 or 3" = 50 + 33 − 16 = 67.
END: Add, subtract the overlaps, and add back what you subtracted too much.

#### The Pigeonhole Principle
ONE: If you put **more than n items into n slots**, some slot must hold 2 or more.
LIKE: If 4 pigeons fly into 3 pigeonholes, however evenly they spread out, some hole ends up with 2 or more pigeons.
STEP:
1. Say there are n slots and at least n + 1 items.
2. Even with exactly 1 item per slot, you can place only n items.
3. The remaining items have to go into slots that are already filled. So some slot has 2 or more.
4. General form: putting N items into k slots means some slot has at least ⌈N/k⌉ items (⌈ ⌉ means round up).
5. Example: among 367 people, two must share a birthday (there are 366 possible birthdays, including February 29).
WHY: It proves "this must exist, even if we do not know where" in a very simple way.
USE: It is why **Collisions are unavoidable** in a Hash Table when there are more possible Keys than slots (Buckets). It also proves that no compression program can shrink every file.
END: More items than slots means something must double up. That is why Hash Collisions cannot be avoided, only handled.

### How do the Sum Rule and Product Rule work, and how do Permutations and Combinations differ?
E: Picking one of 3 sandwiches "or" one of 2 salads gives 3 + 2 = 5 options (Sum Rule), and picking one of 3 mains "and" one of 2 drinks gives 3 × 2 = 6 (Product Rule). Electing a president and vice president is a Permutation, where order matters; picking 2 students for cleanup duty is a Combination, where order does not.
A: Cases that cannot happen together are added, and choices made in sequence are multiplied. A Permutation distinguishes order, P(n, k) = n!/(n−k)!, and a Combination ignores order, C(n, k) = n!/(k!(n−k)!).

### When do you use Stars and Bars?
E: It counts the ways to hand out 5 identical candies to 3 kids. Line up the 5 candies (★) and insert 2 dividers (|); each row like ★★|★|★★ is one way.
A: Use it to split n indistinguishable items into k distinguishable boxes (empty boxes allowed); the answer is C(n + k − 1, k − 1). Splitting 5 candies among 3 kids gives C(7, 2) = 21 ways.

### What is the Inclusion–Exclusion Principle?
E: With 10 students on the soccer team, 8 on the basketball team, and 3 on both, the number of students playing a sport is 10 + 8 − 3 = 15. You subtract once the people you counted twice.
A: It corrects for double counting when you count the size of overlapping Sets: |A ∪ B| = |A| + |B| − |A ∩ B|. With three Sets, subtract the 3 pairwise Intersections and add back the Intersection of all three: |A ∪ B ∪ C| = |A| + |B| + |C| − |A∩B| − |A∩C| − |B∩C| + |A∩B∩C|.

### What is the Pigeonhole Principle, and how does it relate to Hash Collisions?
E: If 4 pigeons go into 3 pigeonholes, some hole must hold 2 or more pigeons.
A: If you put n + 1 or more items into n slots, some slot holds two or more. This principle is why Collisions are guaranteed when there are more possible Keys than Hash Table slots (Buckets).

## Discrete Probability

#### Probability, Expected Value, and Linearity of Expectation
ONE: **Expected Value** is "what you get on average," and the expected value of a sum equals **the sum of the expected values**, even when the parts affect each other.
LIKE: If the older brother gets $50 a month in allowance on average and the younger one gets $30, together they get $80 on average. This stays true even if the older brother sometimes hands part of his allowance to the younger one.
STEP:
1. **Probability**: If every outcome is equally likely, probability = number of outcomes you want ÷ total number of outcomes. The probability of rolling an even number on a die = 3/6 = 1/2.
2. **Random Variable**: A number attached to each outcome. Example: X = the number rolled on a die.
3. **Expected Value E[X]**: Add up each value × its probability. For a die: (1+2+3+4+5+6)/6 = 3.5.
4. **Linearity of Expectation**: E[X + Y] = E[X] + E[Y]. Expected value is "a calculation built only from addition and multiplication," so this always holds even when X and Y are not Independent.
5. **Indicator Variable**: A variable that is 1 if something happens and 0 otherwise. Its expected value equals the probability that the thing happens.
6. Example: n people check their hats and get them back at random. What is the expected number of people who get their own hat? Each person gets their own hat with probability 1/n, and there are n people, so 1/n × n = **1 person**. It is 1 no matter what n is.
WHY: If you break a complicated situation into a sum of small 0/1 events, you can find the average easily even when the events are tangled together.
USE: Analyzing the average number of comparisons in Quicksort, the average number of Collisions in a Hash Table, and the average cost of random loot drops in games.
END: Expected value is "the average outcome," and the average of a sum is the sum of the averages, even without independence.

#### Variance
ONE: **Variance** is a number that measures **how spread out** values are from the average.
LIKE: Two classes can both average 70 on a test, yet one class scored 65–75 across the board while the other mixed 30s and 100s. The second class has the larger Variance.
STEP:
1. Find how far each value is from the average (the deviation).
2. Square each deviation, so negative and positive deviations do not cancel out.
3. The expected value (average) of those squares is the Variance: Var(X) = E[(X − E[X])²].
4. An easier formula to compute: Var(X) = E[X²] − (E[X])².
5. **Standard Deviation** = √Variance. It brings you back to the original units (points, dollars), so it is easier to read.
6. **Variance of a sum**: Var(X + Y) = Var(X) + Var(Y) + 2Cov(X, Y). If the two values rise and fall together (Cov > 0), the sum swings even more.
KEY: Variances simply add only when Cov(X, Y) = 0 (Uncorrelated). If two variables are Independent, Cov = 0, so they add.
WHY: Looking only at the average hides risk. A service that is "fast on average but occasionally very slow" has a large Variance.
USE: Assessing investment risk, the stability of a service's response time, the reliability of experiment results, and the Bias–Variance Trade-off in Machine Learning.
END: The average tells you "where the middle is," and the Variance tells you "how spread out it is."

### Why does Linearity of Expectation hold even without Independence?
E: If the older brother's average allowance is $50 and the younger one's is $30, the average of their total is $80. This calculation does not change even if they pass money back and forth (they depend on each other).
A: E[X + Y] = E[X] + E[Y] holds regardless of Independence because the definition of Expected Value (a sum or integral) is linear. That is why you can break a complicated Random Variable into a sum of small Indicator Variables (0 or 1) and find its average easily.
M: When n people get their hats back at random, the Expected Value of the number who get their own hat is 1 regardless of n (1/n each × n people).

### How do you compute Variance, and when is Var(X + Y) = Var(X) + Var(Y)?
E: Variance is "how spread out the values are from the average." When two values rise and fall together, their sum swings even more, so you cannot just add their Variances.
A: Var(X) = E[X²] − (E[X])². In general Var(X + Y) = Var(X) + Var(Y) + 2Cov(X, Y), so Variances simply add only when the two variables are Uncorrelated (Cov = 0), in particular when they are Independent.

## Sequence · Sum · Recurrence

#### Arithmetic Series and Geometric Series
ONE: Formulas for the sum of a sequence that grows by **adding** the same amount each time (arithmetic) and one that grows by **multiplying** by the same amount each time (geometric).
LIKE: To add 1 through 100, pair the front with the back: 1+100, 2+99, 3+98… Every pair is 101 and there are 50 pairs, so the sum is 5050. A geometric sequence is like "cells that double every day": the last day alone is bigger than all the earlier days combined.
STEP:
1. **Arithmetic Series**: 1 + 2 + … + n = n(n + 1)/2. This is exactly the calculation behind "a nested loop runs about n²/2 times."
2. **Geometric Series**: a + ar + ar² + … + arⁿ⁻¹ = a(rⁿ − 1)/(r − 1) (r ≠ 1).
3. In particular, 1 + 2 + 4 + … + 2ᵏ = 2ᵏ⁺¹ − 1, which is about twice the last term (2ᵏ).
4. So in a sum that doubles each time, "**the last term is almost everything**."
5. When r < 1 it is the opposite: the first term is almost everything. 1 + 1/2 + 1/4 + … never exceeds 2 no matter how long you keep adding.
WHY: Sums like these keep showing up when you count how much work an Algorithm does. Knowing the formulas lets you find the Big-O right away.
USE: When a Dynamic Array fills up, it doubles its size and copies everything over. The total copying is 1 + 2 + 4 + … + n ≈ 2n, so the average cost per element is O(1) (**Amortized Analysis**).
END: An arithmetic sum is on the order of n², and a geometric sum that doubles is "about twice the last term."

#### Recurrence Relation
ONE: "A formula that expresses the value for n in terms of values for smaller n." It is used to describe the running time of recursive Algorithms.
LIKE: It is a rule that explains today in terms of yesterday, like "today's piggy bank total = yesterday's total + $1." If you know the first day's total, you can compute every day.
STEP:
1. Example: Fibonacci is F(n) = F(n−1) + F(n−2), with F(0) = 0 and F(1) = 1.
2. The running time of a recursive Algorithm is written the same way. If a size-n problem is solved by solving two halves and then spending n to combine them, T(n) = 2T(n/2) + n.
3. **Substitution**: Keep expanding the formula until you see a pattern. T(n) = T(n−1) + n = T(n−2) + (n−1) + n = … = 1 + 2 + … + n → O(n²).
4. **Recursion Tree**: Draw the calls as a tree and add up the work on each level. For T(n) = 2T(n/2) + n, each level costs n and there are log n levels, so O(n log n).
5. **Master Theorem**: Recurrences of the form T(n) = aT(n/b) + f(n) can be solved directly with a formula (covered in 07 Algorithms).
WHY: With recursive code, "how many times does it repeat?" is not obvious at a glance. Turning it into a recurrence lets you calculate it.
USE: Merge Sort (O(n log n)), Binary Search (T(n) = T(n/2) + 1 → O(log n)), and the state transitions in Dynamic Programming are all recurrences.
END: A recurrence "describes a big problem in terms of smaller ones," and you solve it by expanding it or drawing it as a tree.

### What are the sum formulas for Arithmetic and Geometric Series?
E: To add 1 through 100, pair the front with the back (1+100, 2+99 …): there are 50 pairs of 101, so the sum is 5050. In a Geometric series, like a cell count that "doubles every time," the last term takes up almost the whole sum.
A: 1 + 2 + … + n = n(n + 1)/2, and a Geometric Series sums to a(rⁿ − 1)/(r − 1). In particular, 1 + 2 + 4 + … + 2ᵏ = 2ᵏ⁺¹ − 1, which is why the total copying cost of a Dynamic Array that doubles in size stays O(n).

### How do you solve a Recurrence Relation?
E: A Recurrence is a rule that "computes today's value from yesterday's." You solve it by substituting backward again and again, or by drawing the work as a tree and adding up the work on each level.
A: Substitution expands the formula several times to find a pattern, and a Recursion Tree adds up the cost of each level. T(n) = T(n−1) + n is O(n²), T(n) = 2T(n/2) + n is O(n log n), and Divide and Conquer recurrences can be solved directly with the Master Theorem (07 Algorithms).

## Number Theory

#### Modular Arithmetic
ONE: A way of calculating where you **look only at the remainder** after dividing by some number m.
LIKE: A clock is the classic example. Five hours after 10 o'clock is not 15 o'clock but 3 o'clock. You only look at the remainder after dividing by 12.
STEP:
1. **a mod m**: The remainder of a divided by m. 15 mod 12 = 3.
2. **Congruence**: a ≡ b (mod m) means a and b leave the same remainder when divided by m. 15 ≡ 3 (mod 12).
3. For addition, subtraction, and multiplication, taking remainders along the way gives the same final result. (a + b) mod m = ((a mod m) + (b mod m)) mod m.
4. So even huge numbers can be computed while staying small, by keeping only the remainder at each step.
5. Division needs care. Instead of ordinary division you must use a "Modular Inverse (a number that multiplies to 1)," and it does not always exist.
WHY: A computer's integer slots have a fixed size. Modular arithmetic lets you work with enormous numbers while staying in range.
USE: Hash Table slot numbers (`hash(key) % number_of_slots`), indexes in a circular queue (`(i + 1) % n`), day-of-week calculations, cryptography (RSA), and the classic Coding Test instruction "print the answer modulo 1,000,000,007."
END: Modular Arithmetic is calculation that "comes back to the start after one full lap," like a clock.

#### Euclidean Algorithm
ONE: A very fast way to find the **greatest common divisor (GCD)** of two numbers by repeatedly replacing them with "the remainder of the larger divided by the smaller."
LIKE: You want to cover a 48 × 18 floor with the largest possible square tiles and no gaps. Two 18×18 tiles leave 48 − 36 = 12; in the remaining 18×12 area a 12×12 tile leaves 6; and the 12×6 area is covered exactly by two 6×6 tiles. The answer is 6.
STEP:
1. Key property: gcd(a, b) = gcd(b, a mod b). Replacing a number with the remainder does not change the GCD.
2. Repeat until b becomes 0; the a at that point is the answer.
3. Example: gcd(48, 18) → gcd(18, 12) → gcd(12, 6) → gcd(6, 0) = 6.
4. Every two steps, the larger number drops below half, so the number of steps is O(log min(a, b)).
5. The least common multiple (LCM) is a × b ÷ gcd(a, b).
```python
def gcd(a, b):
    while b:
        a, b = b, a % b
    return a
```
WHY: Checking divisors one by one is far too slow for big numbers. The Euclidean Algorithm handles numbers with dozens of digits in an instant.
USE: Reducing fractions, lining up repeating schedules (LCM), and computing the Modular Inverse needed to build RSA keys (the Extended Euclidean Algorithm).
END: Repeatedly replacing the larger number with a remainder gives the GCD, and it is very fast (O(log n)).

#### Primes and RSA Encryption
ONE: RSA is encryption built on the fact that multiplying two large **Primes** is easy, but recovering the two primes from their product is extremely hard.
LIKE: Mixing two colors of paint is easy, but looking at the mixed color and working out exactly which two colors went in is hard.
STEP:
1. **Prime**: A number greater than 1 that is divisible only by 1 and itself. 2, 3, 5, 7, 11…
2. **Prime Factorization**: Every integer can be written as a product of primes in exactly one way. 12 = 2 × 2 × 3.
3. Multiplying is easy. A computer multiplies two primes with hundreds of digits in an instant.
4. Going backward is hard. No fast Classical Algorithm is known for factoring a product with hundreds of digits.
5. **RSA**: Secretly choose large primes p and q, and publish n = p × q as part of the **Public Key**. Keep hidden the **Private Key**, which can only be built if you know p and q.
6. Anyone can lock (encrypt) with the Public Key, but only the holder of the Private Key can unlock (decrypt).
WHY: To share secrets on the internet even with someone you have never met, you need encryption where "the locking key can be made public."
USE: HTTPS certificates, digital signatures, and SSH keys use Public Key cryptography such as RSA.
KEY: It is known that a large enough Quantum Computer could factor quickly with Shor's Algorithm, so new encryption that prepares for this (Post-Quantum Cryptography) is being developed.
END: RSA's security comes from the asymmetry "multiplying is easy, factoring is hard."

### What are Modular Arithmetic and Congruence?
E: Think of a clock. Five hours after 10 o'clock is not 15 o'clock but 3 o'clock. Looking only at the remainder after dividing by 12 is Modular Arithmetic.
A: a mod m is the remainder of a divided by m, and a ≡ b (mod m) means m divides a − b evenly. It is used in Hash Functions, Circular Queue indexes, and Cryptography.

### Why is the Euclidean Algorithm fast?
E: To cover a 48 × 18 floor with the largest square tiles, keep cutting the smaller side off the larger one. 48 → remainder 12 → remainder 6 → remainder 0, so the answer is 6.
A: Repeat gcd(a, b) = gcd(b, a mod b) until b is 0. Every two steps the larger number falls below half, so it finishes in O(log min(a, b)) steps.

### How are Primes and Prime Factorization connected to RSA encryption?
E: Mixing two paint colors is easy, but picking the two original colors out of the mix is hard. Likewise, multiplying two large Primes is easy, but finding the two Primes from their product is extremely hard.
A: RSA publishes the product n of large Primes p and q (as part of the Public Key) and hides the Private Key, which can only be built by knowing p and q. Its security rests on the fact that no fast Classical Algorithm is known for the Prime Factorization of large numbers.

## Graph Theory Basics

#### Graph Basics: Vertex · Edge · Degree
ONE: A **Graph** is a structure that shows "what is connected to what" using points (**Vertices**) and the lines between them (**Edges**).
LIKE: Draw a map of friendships. People are points and "are friends" is a line. A subway map is also a Graph: stations are points and the tracks between them are lines.
STEP:
1. **Vertex**: The things themselves. People, cities, web pages.
2. **Edge**: A connection between two Vertices. A friendship, a road, a link.
3. **Undirected / Directed**: Connections can go both ways (friends) or one way (follows, one-way streets).
4. **Weighted**: If Edges carry numbers such as distance or cost, it is a weighted Graph.
5. **Degree**: The number of Edges attached to a Vertex. Like how many friends someone has.
6. **Handshaking Lemma**: The sum of all Degrees is twice the number of Edges, because every handshake involves two hands. So the number of Vertices with odd Degree is always even.
WHY: Many real-world problems are really about "connections." Once they are Graphs, you can solve route finding, recommendations, and network analysis with the same methods.
USE: Directions in map apps, friend suggestions on social networks, web search (link structure), ordering tasks (dependencies), and Network Routing.
END: Graph = points (Vertices) + lines (Edges). The sum of the Degrees is always twice the number of Edges.

#### Tree: A Connected Graph with No Cycles
ONE: A **Tree** is a Graph where every Vertex is connected and **there is no loop (Cycle) at all**. With n Vertices it always has n − 1 Edges.
LIKE: Imagine connecting n islands with bridges so that no route ever loops back to where it started. Each new bridge merges two separate groups of islands into one. To go from n groups down to 1, you need n − 1 bridges.
STEP:
1. **Connected**: There is a path between any two Vertices.
2. **Cycle**: A path that returns to its start without reusing an Edge.
3. **Tree** = Connected + no Cycle.
4. At first the n Vertices are all separate (n groups). An Edge that does not create a Cycle merges two groups into one.
5. Going from n groups to 1 takes exactly n − 1 merges, so there are n − 1 Edges.
6. Add even one more Edge and you connect two points that were already connected, which always creates a Cycle.
KEY: In a Tree there is **exactly one** path between any two Vertices.
WHY: A Tree "connects everyone with the minimum number of links," so it is perfect for representing waste-free networks and hierarchies.
USE: Folder structures, company org charts, HTML document structure (the DOM), and the reason an MST (Minimum Spanning Tree) that connects every city at minimum cost always has V − 1 Edges.
END: Tree = fully connected + no Cycle = exactly n − 1 Edges.

#### Euler Path and Hamiltonian Path
ONE: An **Euler Path** passes through every **line (Edge)** exactly once, and a **Hamiltonian Path** passes through every **point (Vertex)** exactly once.
LIKE: An Euler Path is drawing a figure without lifting your pencil: you must trace every line exactly once. A Hamiltonian Path is a road-trip plan that visits every city exactly once.
STEP:
1. **Euler Path**: Uses every Edge exactly once. If it ends where it started, it is an Euler Circuit.
2. **When it exists (connected Graph)**: With 0 odd-Degree Vertices there is an Euler Circuit; with 2 there is an Euler Path that starts and ends at those two. Otherwise there is none.
3. Why: every point you pass through in the middle pairs an "in" with an "out," so its Degree must be even. Only the start and end points are allowed to be unpaired.
4. You only need to count Degrees to check this condition, so it is very fast.
5. **Hamiltonian Path**: Visits every Vertex exactly once. It looks similar, but no fast way is known to decide whether such a path exists (an **NP-Complete** problem).
WHY: It is the classic example of two problems that look alike, where one is easy and the other is very hard. The lesson is that defining a problem precisely matters.
USE: Euler Paths are used for mail delivery and snowplow routes (every road once) and for stitching together DNA fragments. Hamiltonian Paths connect to the Traveling Salesman Problem (TSP), such as optimizing a delivery order.
END: Euler (every line) is easy to decide with "0 or 2 odd-Degree points," while Hamiltonian (every point) is a hard problem (NP-Complete).

### What are a Vertex, an Edge, and a Degree? Why is the sum of the Degrees twice the number of Edges?
E: People are Vertices, handshakes are Edges, and the number of handshakes one person made is their Degree. Each handshake involves two hands, so adding up everyone's handshake count gives twice the number of handshakes.
A: A Graph consists of Vertices and Edges connecting them, and the Degree is the number of Edges attached to a Vertex. Each Edge raises the Degree of both its endpoints by 1, so Σdeg(v) = 2|E| (the Handshaking Lemma), which is why the number of odd-Degree Vertices is always even.

### Why does a Tree with n Vertices always have n − 1 Edges?
E: To connect n islands with bridges without any loop (Cycle), each new bridge reduces the number of separate groups by one. Turning n groups into 1 takes n − 1 bridges.
A: A Tree is a Connected Graph with no Cycle, so each Edge you add reduces the number of Connected Components by exactly one. Going from n to 1 takes n − 1 Edges, and adding even one more creates a Cycle. This is why an MST (Minimum Spanning Tree) always has V − 1 Edges.

### How do an Euler Path and a Hamiltonian Path differ?
E: An Euler Path is drawing a figure without lifting your pencil (every line once), and a Hamiltonian Path is a trip that visits every city once.
A: An Euler Path passes through every Edge exactly once, and a Hamiltonian Path passes through every Vertex exactly once. A Connected Graph has an Euler Path under a simple rule (0 or 2 odd-Degree Vertices), but deciding whether a Hamiltonian Path exists is NP-Complete.
