## DFA (Deterministic Finite Automaton)

#### What Theory of Computation Asks: How Far Can Machines Go?
ONE: **Theory of Computation** is the field that uses math to ask "which machines can solve which problems?" and "if they can, how fast?"
LIKE: Imagine lining up machines by power. A vending machine that remembers only its current state (DFA), a machine with a stack of plates attached to the vending machine (PDA), and a person with an endlessly long notebook (Turing Machine). The further right you go, the more problems they can solve.
STEP:
1. Here, a "problem" is usually expressed as a **Language**. A language is a set of strings, and a problem is the yes/no question "does this string belong to that set?"
2. Examples: "Does the string have an even number of 1s?", "Do the brackets match?", "Will this program ever stop?"
3. **Automata Theory**: Studies which languages machines with different amounts of memory can recognize.
4. **Computability Theory**: Studies whether there are problems that **no machine can ever solve**.
5. **Complexity Theory**: Classifies solvable problems by **how fast** they can be solved (P, NP).
WHY: This theory is the foundation of Regular Expressions, Compilers, and judgments like "this probably has no fast Algorithm." It keeps you from wasting time on the impossible.
END: Theory of Computation is the ruler that measures "the power of machines" and "the difficulty of problems."

#### DFA: The Simplest Machine
ONE: A **DFA** is a machine that, out of a fixed number of states, **remembers only its current state**, and moves to the next state by fixed rules each time it reads one character.
LIKE: It is a vending machine. It has states like "0¢ inserted" and "25¢ inserted," and each time you insert a coin it moves to the next state according to a table. When it reaches the $1 state, a drink comes out. The vending machine remembers nothing except its current state.
STEP:
1. **Set of States Q**: The states the machine can be in. There are finitely many.
2. **Alphabet Σ**: The characters it can read. Example: {0, 1}.
3. **Transition Function δ**: A table that says "reading this character in this state takes you to which state." A DFA always goes to **exactly one** place (Deterministic).
4. **Start State q₀**: The state it starts in.
5. **Set of Accept States F**: If it is in one of these after reading the whole input, it "accepts (yes)."
6. Example: A DFA for "is the number of 1s even?" needs just two states (even, odd). Reading a 1 switches the state, and a 0 leaves it alone. If it ends in the "even" state, it accepts.
7. The languages a DFA can recognize are called **Regular Languages**.
KEY: A DFA's memory is fixed at "the number of states." So it cannot count quantities that can grow without limit (e.g., exactly how many 0s there were).
USE: Vending machines, traffic lights, game character states, string pattern checks, and the Lexer that splits code into words (Tokens) in a Compiler.
END: A DFA is "a vending machine that remembers only its current state," and the languages such machines recognize are Regular Languages.

#### DFA Minimization and Myhill-Nerode
ONE: The task of finding, among DFAs that recognize the same language, **the one with the fewest states**. If two states **"give the same result no matter what is read next,"** they can be merged into one.
LIKE: Whether two states can be merged is decided by asking "is there some ending you could tack on where one gives a drink and the other doesn't?" If even one such ending exists, the two states do different jobs and cannot be merged.
STEP:
1. **Reachable**: States you cannot get to from the start state are useless, so remove them.
2. **Distinguishable**: Two states p, q are distinguishable if there is some string z such that reading z from them lands only one of them in an accept state.
3. Merge states that cannot be distinguished.
4. If every state is reachable and every pair of states is distinguishable, the DFA is minimal.
5. **Myhill-Nerode Theorem**: The number of states in the minimal DFA equals the number of "groups of strings that give the same result no matter what is appended (Equivalence Classes)."
6. If there are **infinitely many** such groups, no finite DFA can do it, so the language is not Regular. Example: in {0ⁿ1ⁿ}, 0, 00, 000… are all in different groups.
WHY: Fewer states make the machine simpler and faster. And Myhill-Nerode gives an exact criterion for "Regular or not."
END: Merge states with the same future, and the minimum number of states you get is uniquely fixed for each language.

### What are the 5 components of a DFA?
E: It is a vending machine. The states ("0¢ inserted," "25¢ inserted," …), the kinds of coins you can insert (Alphabet), the table of "inserting this coin in this state takes you where" (Transition Function), the start state (Start State), and the states where a drink comes out (Accept States) are all fixed, and its only memory is "the current state."
A: A DFA is (Q, Σ, δ, q₀, F): a finite set of States Q, an input Alphabet Σ, a Transition Function δ: Q × Σ → Q that determines exactly one next State from a State and one character, a Start State q₀, and a set of Accept States F. If it is in F after reading the whole input, it Accepts, and the language a DFA accepts is called a Regular Language.

### How do you prove that a DFA is Minimal?
E: Whether two States can be merged is decided by asking "is there some ending you could tack on where one accepts and the other rejects?" If even one such ending exists, the two States do different jobs and cannot be merged.
A: It is minimal if you show every State is Reachable from the Start State and every pair of States is Distinguishable (appending some Suffix makes only one of them accept). More generally, by the Myhill-Nerode Theorem, the number of States in the minimal DFA equals the number of Equivalence Classes of "indistinguishable strings" the language creates, and if there are infinitely many Equivalence Classes, the language is not Regular.

## NFA (Nondeterministic Finite Automaton)

#### NFAs and ε-Transitions
ONE: An **NFA** is a machine that can go to **several states at once** on the same character, and also has **ε-Transitions** that move without reading a character. It accepts if **even one** of the possible paths reaches an accept state.
LIKE: It is a machine that clones itself at every fork and tries all the paths at once. If even one clone reaches the exit, it succeeds. An ε-Transition is a teleport door you can pass through without inserting a coin.
STEP:
1. In a DFA, once the state and character are fixed, there is **exactly one** next state.
2. In an NFA, there can be **several next states, or none at all**.
3. **ε-Transition**: It can move to another state without reading a character.
4. Think of it as following every possible path at once while reading the input. If any path is in an accept state at the end, it accepts.
5. **Surprising fact**: An NFA looks more powerful than a DFA, but the languages they can recognize are **exactly the same** (both Regular Languages). NFAs are just **easier to design**.
USE: Many cases, like "strings whose third-to-last character is 1," are simple to draw as an NFA but complicated as a DFA. Regex Engines build NFAs internally.
END: An NFA is a machine with "cloning + teleporting," but its power equals a DFA's; it is just easier to design.

#### Subset Construction: NFA to DFA
ONE: If you treat **"the set of states the clones are currently in"** in an NFA as a single DFA state, you can build a DFA that behaves exactly like the NFA without any cloning.
LIKE: If you record "which rooms the clones are currently scattered across" as a single state, then one person with no clones can carry that record and follow along. With n rooms, there are at most 2ⁿ possible "scatter patterns."
STEP:
1. **ε-Closure**: The set of all states reachable from a given state using only ε-Transitions.
2. **The DFA's start state** = the ε-Closure of the NFA's start state.
3. **The DFA's move** = collect "the states each state in the current set can reach on that character," then add their ε-Closure.
4. **The DFA's accept states** = sets that include at least one NFA accept state.
5. Keep computing moves for each newly appearing set, and the DFA is complete.
6. If the NFA has n states, there are 2ⁿ possible sets, so the DFA has at most 2ⁿ states. In some cases, like the language "the n-th character from the end is 1," nearly all of them are actually needed.
WHY: This conversion is the proof that "NFAs and DFAs have the same power." It is also the method used to actually run Regexes fast.
END: Treat the set of clone positions as one state and an NFA becomes a DFA. But the number of states can grow to as many as 2ⁿ.

### How does an NFA differ from a DFA, and what is an ε-Transition?
E: It is a machine that clones itself at every fork and tries all the paths at once. If even one clone reaches the exit, it succeeds, and an ε-Transition is a door you can teleport through without inserting a coin.
A: An NFA can go from one State to several States on the same character and can also have ε-Transitions that move without reading a character (δ: Q × (Σ ∪ {ε}) → a Subset of Q). It accepts if any possible path ends in an Accept State; its expressive power equals a DFA's, and it is simpler to design.

### How do you convert an NFA to a DFA with Subset Construction? Why can there be up to 2ⁿ States?
E: If you treat "which rooms the clones are currently scattered across" as a single State, one person with no clones can keep the record and follow along. With n rooms, there are at most 2ⁿ "scatter patterns."
A: Take each DFA State to be a set of NFA States: the Start State is the ε-Closure of q₀, a Transition is "the ε-Closure of the States the current set's States can reach on that character," and Accept States are the sets containing at least one NFA Accept State. If the NFA has n States, there are 2ⁿ Subsets, so the DFA has at most 2ⁿ States, and some languages, like "the n-th character from the end is 1," actually need 2ⁿ.

## Regular Languages and Regular Expressions

#### Regular Expressions and Kleene's Theorem
ONE: A **Regular Expression** is a pattern language that describes the shape of strings with three operations, **"or (|)," "followed by," and "repeat zero or more times (*),"** and it expresses **exactly the same languages** as DFAs·NFAs.
LIKE: It is a recipe that sketches what strings look like. With just three ingredients, like "a or b, followed by c any number of times," you can write down the shape of every Regular Language.
STEP:
1. **Union (R | S)**: The R shape or the S shape. `cat|dog`.
2. **Concatenation (RS)**: R followed by S. `ab` is a followed by b.
3. **Kleene Star (R*)**: R repeated zero or more times. `a*` is "", "a", "aa", …
4. The languages expressed by patterns built from these three are exactly the Regular Languages.
5. **Kleene's Theorem**: Regular Expressions, NFAs, and DFAs all express the same set of languages. They can be converted into one another.
6. **Regex → NFA**: Build a small NFA for each operation and connect them with ε-Transitions (**Thompson's Construction**).
7. **NFA → Regex**: Remove states one at a time, rewriting the paths that went through each removed state as Regexes on the Edges (**State Elimination**).
KEY: Programming languages' "Regex" has features like Backreferences (`\1`, the same string matched earlier), which make it stronger than mathematical Regular Expressions. So it does not always express only Regular Languages.
USE: Input validation (email formats, etc.), finding patterns in logs, find·replace in editors, and the Lexer in a Compiler use this principle.
END: Regex = or + followed by + repeat. These three have exactly the same power as DFAs·NFAs.

#### Closure Properties of Regular Languages
ONE: If you combine Regular Languages, take their overlap, reverse them, or take a complement, **the result is still a Regular Language**.
LIKE: It is like how no matter how you snap LEGO bricks (Regular Languages) together or cut them apart, the result is still LEGO bricks. They never turn into a different material.
STEP:
1. **Union, Concatenation, Star**: These follow directly from the definition of Regex, so of course it is closed under them.
2. **Complement**: Swapping a DFA's accept and non-accept states gives a DFA that accepts what the original rejected.
3. **Intersection**: Run two DFAs at the same time. Build a **Product Automaton** whose states are pairs (A's state, B's state), and have it accept only when both accept.
4. **Reverse**: Reverse every arrow and swap the start and accept states (as an NFA).
5. **Use**: Also used to show "L is not Regular." If the intersection of L with some Regular Language is a non-Regular language, L cannot be Regular either.
END: Regular Languages are closed under combining·overlapping·reversing·complement, so their nature is preserved no matter how you assemble them, like LEGO.

### What are the three operations of Regular Expressions, and how do you convert between Regular Expressions and NFAs?
E: A Regular Expression is a Pattern language that describes the shape of strings. With just three things, "or (|)," "followed by (writing side by side)," and "repeat zero or more times (*)," you can write down every Regular Language.
A: Regular Expressions are built from Union (R | S), Concatenation (RS), and Kleene Star (R*), and by Kleene's Theorem, Regular Expressions·NFAs·DFAs all express the same languages (Regular Languages). A Regular Expression becomes an NFA through Thompson's Construction, which builds a small NFA for each operation and connects them with ε-Transitions, and an NFA becomes a Regular Expression through State Elimination, which removes States one at a time while writing Regular Expressions on the Edges. Regex Engines in programming and the Lexer (tokenizer) in a Compiler use this principle.
M: Programming languages' "Regex" has features stronger than mathematical Regular Expressions, like Backreferences (\1), so it does not always express only Regular Languages.

### Under which operations are Regular Languages Closed?
A: Regular Languages are closed under Union, Concatenation, Kleene Star, Complement, Intersection, and Reverse, so applying these operations to Regular Languages gives Regular Languages again. The Complement is built by flipping a DFA's Accept·Non-Accept States, and the Intersection is built with a Product Automaton that runs two DFAs at the same time. This Closure Property is also useful for showing "a language is not Regular."

## Non-Regular Languages and the Pumping Lemma

#### The Pumping Lemma: A Tool for Showing a Language Is Not Regular
ONE: A theorem saying that if a language is Regular, **any long enough string must contain "a stretch that can be repeated any number of times or removed without breaking things."** It is used to show that a language is **not** Regular.
LIKE: When a vending machine with only p states reads a string of length p or more, by the pigeonhole principle it visits some state twice. The stretch in between is a loop, so going around it extra times or skipping it goes unnoticed by the machine. But for a language that requires exactly matching numbers of 0s and 1s, adding more 0s makes it wrong.
STEP:
1. **Theorem**: If L is Regular, there is some length p such that every string s in L of length p or more can be split as s = xyz, where |y| > 0 (the loop is not empty), |xy| ≤ p (the loop is within the first p characters), and xyⁱz is also in L for all i ≥ 0.
2. **Showing {0ⁿ1ⁿ} is not Regular**: Assume it is Regular (proof by contradiction).
3. Pick s = 0ᵖ1ᵖ. Its length is 2p, so it meets the condition.
4. Since |xy| ≤ p, x and y are inside the leading 0s. That is, y consists only of 0s.
5. Inserting y one more time (xy²z) makes more 0s than 1s, so it is not in L.
6. This contradicts the theorem, so {0ⁿ1ⁿ} is not Regular.
WHY: It turns the intuition "finite memory can't count endlessly large numbers" into a rigorous proof.
END: If stretching or shrinking the loop inside a long string pushes it out of the language, that language is not Regular.

#### The Limits of the Pumping Lemma and Myhill-Nerode
ONE: The Pumping Lemma is only a **necessary condition** for being Regular, so a language can satisfy it and still **not** be Regular. To decide for certain, use the Myhill-Nerode Theorem.
LIKE: "If it's a person, it breathes" is true, but "if it breathes, it's a person" is false (dogs breathe too). The Pumping Lemma only tells you "if it's Regular, it can be Pumped."
STEP:
1. **Necessary condition**: "Regular → can be Pumped." So "cannot be Pumped → not Regular" is certain.
2. But "can be Pumped → Regular" does not hold.
3. Example: {aⁱbʲcᵏ | if i = 1 then j = k} satisfies the Pumping condition but is not Regular.
4. So the Pumping Lemma is used **only to show "not Regular."**
5. **To show "Regular,"** build a DFA, NFA, or Regex directly.
6. **The definitive criterion**: the Myhill-Nerode Theorem. If the "groups of distinguishable strings" are finite, it is Regular; if infinite, it is not.
END: The Pumping Lemma is a tool that can only prove "not," and the definitive criterion is Myhill-Nerode.

### How do you show with the Pumping Lemma that {0ⁿ1ⁿ} is not Regular?
E: When a vending machine with only p States reads a string of length p or more, by the Pigeonhole Principle it visits some State twice. The stretch in between is a loop, so going around it extra times or skipping it goes unnoticed. But for a language that requires matching numbers of 0s and 1s, adding more 0s makes it wrong.
A: The Pumping Lemma is the theorem "if L is Regular, there is some length p such that every s ∈ L with |s| ≥ p can be split into xyz with |y| > 0 and |xy| ≤ p, and xyⁱz ∈ L for all i ≥ 0." Assume {0ⁿ1ⁿ} is Regular and pick s = 0ᵖ1ᵖ; since |xy| ≤ p, y consists only of 0s, and xy²z has more 0s than 1s, so it is not in L, a contradiction. Therefore it is not Regular.

### Why is "can be Pumped" not enough to make a language Regular?
A: The Pumping Lemma is only a Necessary Condition for Regular Languages, not a sufficient one, so there are languages that can be Pumped but are not Regular. For example, {aⁱbʲcᵏ | if i = 1 then j = k} satisfies the Pumping condition but is not Regular. So the Pumping Lemma is used only to show "not Regular," and to show a language is Regular you build a DFA·NFA·Regular Expression directly. To decide for certain, use the Myhill-Nerode Theorem.

## CFG (Context-Free Grammar) and PDA (Pushdown Automaton)

#### CFG: Rules for Building Sentences
ONE: A **CFG (Context-Free Grammar)** is a grammar that produces valid strings by repeatedly applying only "rules that replace a big chunk with smaller chunks." Most programming language grammars are written as CFGs.
LIKE: It is a table of rules for building sentences. If you keep replacing big chunks with smaller ones, like "Sentence → Subject + Verb," "Subject → Alex | Sam," and "Verb → runs | laughs," valid sentences come out.
STEP:
1. **Variable (Non-Terminal)**: A chunk that can be replaced further. Examples: S (sentence), E (expression).
2. **Terminal**: An actual character that cannot be replaced further. Examples: 0, 1, (, ).
3. **Production Rule**: Of the form A → α. It replaces one Variable with a string. Because there is **exactly one** Variable on the left, it can be replaced regardless of what surrounds it (its context), hence Context-Free.
4. Example: `S → 0S1 | ε` replaces S with 0S1 or with the empty string. Applying it repeatedly produces 01, 0011, 000111…, that is, {0ⁿ1ⁿ}. This is a language a DFA cannot produce.
5. Example: `S → (S) | SS | ε` produces every string of matched brackets.
6. **Parse Tree**: The process of applying rules, drawn as a tree. A Compiler's **Parser** turns code into this tree (a Syntax Tree) to analyze its meaning.
USE: Defining programming language grammars, Compiler Parsers, and analyzing the structure of formats like JSON·HTML.
END: A CFG is "a table of rules that replace chunks with smaller chunks," and it can express nested structures (brackets, 0ⁿ1ⁿ).

#### Ambiguous Grammars
ONE: A grammar that produces **two or more Parse Trees** for the same string. Having several interpretations means the meaning can differ.
LIKE: "I saw the man with the telescope" can mean "I used a telescope to see the man" or "I saw the man who had a telescope." If one sentence has two interpretations, it is ambiguous.
STEP:
1. Consider `a + a * a` under the grammar `E → E + E | E * E | a`.
2. Interpretation ①: (a + a) * a. A Tree that does the addition first.
3. Interpretation ②: a + (a * a). A Tree that does the multiplication first.
4. Both Trees are possible, so the computed result can differ. That is a problem for a Compiler.
5. **Fix**: Build operator **Precedence** and **Associativity** into the grammar. Example: if you split it into layers where an expression (E) is a sum of terms (T) and a term is a product of factors (F), multiplication always binds first.
KEY: There is no general Algorithm to decide whether a CFG is ambiguous (it is Undecidable). So grammars are designed to be unambiguous from the start.
END: Two interpretations means an ambiguous grammar. Build precedence and associativity into the grammar to fix it to one.

#### PDA: A Machine with a Stack
ONE: A **PDA** is an NFA with an **infinite Stack (a stack of plates)** attached. The Stack lets it remember nested structures, and it has **exactly the same power as a CFG**.
LIKE: If you stack one plate for each 0 you read and remove one for each 1, you can tell whether the numbers of 0s and 1s are equal by whether the plates run out exactly at the end. A vending machine with only states cannot count endlessly large numbers, but a stack of plates can be piled as high as you like.
STEP:
1. As a PDA reads characters, it looks at the top of the Stack and puts something on top (push) or takes it off (pop).
2. {0ⁿ1ⁿ}: push on 0, pop on 1, and accept if the Stack is empty at the end.
3. Matched brackets: push on an opening bracket, pop on a closing bracket. Reject if there is nothing to pop along the way or something is left at the end.
4. The languages a **Nondeterministic PDA** recognizes = exactly the **Context-Free Languages** (the languages CFGs produce).
5. A **Deterministic PDA** is weaker than this. That is why real Parsers use grammars that can be handled deterministically (LL, LR grammars).
6. **Limit**: Matching three counts at once, as in {aⁿbⁿcⁿ}, is too much for a single Stack. So it is not Context-Free.
END: PDA = vending machine + a stack of plates. It can count nested structures and has the same power as a CFG.

### What is a CFG? How is it used for programming language grammars and Parsers?
E: It is a table of rules for building sentences. If you just keep applying rules that replace big chunks with smaller ones, like "Sentence → Subject + Verb" and "Subject → Alex | Sam," valid sentences come out.
A: A Context-Free Grammar defines a language with Production Rules A → α that replace one Variable (Non-Terminal) with a string; for example, S → 0S1 | ε produces {0ⁿ1ⁿ}, and S → (S) | SS | ε produces matched brackets. Programming language grammars are usually written as CFGs, and a Compiler's Parser uses the grammar to turn code into a Parse Tree (Syntax Tree).

### What is an Ambiguous Grammar?
E: "I saw the man with the telescope" can mean "I used a telescope to see the man" or "I saw the man who had a telescope." If one sentence has two interpretations, it is ambiguous.
A: A grammar is Ambiguous if some string has two or more different Parse Trees (or Leftmost Derivations). Under E → E + E | E * E | a, a + a * a can have both a Tree that does the addition first and a Tree that does the multiplication first, so the computed result can differ; the ambiguity is removed by building operator Precedence and Associativity into the grammar.

### Why does a PDA need a Stack, and why does it have the same power as a CFG?
E: If you stack one plate for each 0 you read and remove one for each 1, you can tell whether the numbers of 0s and 1s are equal by whether the plates run out exactly at the end. A vending machine with only States cannot count infinitely large numbers.
A: A PDA is an NFA plus an infinite Stack, and the Stack lets it remember nested structures (brackets, {0ⁿ1ⁿ}). The languages a Nondeterministic PDA recognizes are exactly the Context-Free Languages, so it has the same power as a CFG; a Deterministic PDA is weaker, which is why real Parsers use grammars that can be handled deterministically (LL, LR). A language that requires matching three counts at once, like {aⁿbⁿcⁿ}, is too much for a single Stack, so it is not Context-Free.

## Turing Machines

#### Turing Machines and the Church-Turing Thesis
ONE: A **Turing Machine** is the simplest model of a general-purpose computer, which computes by **reading, writing, and moving left and right** on an infinitely long Tape. It can do every computation today's computers can do.
LIKE: It is a person with one endlessly long notebook and a pencil·eraser who reads cells, changes them, and moves left and right by following nothing but a fixed rule table. It looks simple, but it can do any computation.
STEP:
1. **Tape**: A strip of cells that goes on forever. The input is written on it at the start.
2. **Head**: Points to one cell of the Tape, reads and writes it, and moves one cell left or right.
3. **Finite States and a rule table**: "In this state, reading this character, write this character, move this way, and go to this state."
4. **Why it is stronger than a PDA**: A Stack lets you see only the top, but a Tape lets you go anywhere and read and change it. So it can recognize {aⁿbⁿcⁿ} too.
5. **Church-Turing Thesis**: The claim that "what can be computed by an Algorithm = what can be computed by a Turing Machine." It is not a mathematically proven theorem but a **thesis** that is widely accepted because no counterexample has been found.
6. **Turing Complete**: Having the same power as a Turing Machine. Ordinary programming languages like Python, C, and JavaScript are all Turing Complete.
WHY: It defines the exact boundary of "what computers can do." That makes it possible to prove "what no computer can do."
END: A Turing Machine is the simplest general-purpose computer, "an infinite notebook + a rule table," and it is believed to be able to do everything an Algorithm can do.

#### The Hierarchy of Languages: Regular ⊂ Context-Free ⊂ Decidable ⊂ Recognizable
ONE: Depending on a machine's power, the languages it can recognize form **layers** that contain one another. Every language in a lower layer also belongs to the higher layers, but higher layers contain languages that lower-layer machines cannot recognize.
LIKE: It is like driver's license classes. A commercial license lets you drive a regular car too, but a regular license does not let you drive a big rig. The more powerful the machine, the more languages it recognizes.
STEP:
1. **Regular Language**: Recognized by DFA·NFA·Regex. Example: "strings ending in 0."
2. **Context-Free Language**: Recognized by PDA·CFG. Examples: matched brackets, {0ⁿ1ⁿ}, programming language grammars.
3. **Decidable Language**: There is a Turing Machine that **always halts** with a yes/no answer for every input. Examples: {aⁿbⁿcⁿ}, primality testing.
4. **Recognizable Language**: There is a Turing Machine that always halts and accepts on "yes" inputs but may run forever on "no" inputs. Example: "this program eventually halts."
5. Each containment is **proper**. That is, every layer contains some language that is not in the layer below.
| Language | Machine that recognizes it | Example |
| Regular | DFA / NFA / Regex | Email format, "ends in 0" |
| Context-Free | PDA / CFG | Matched brackets, {0ⁿ1ⁿ}, programming grammars |
| Decidable | A Turing Machine that always halts | {aⁿbⁿcⁿ}, primality testing |
| Recognizable | Turing Machine (may not halt when rejecting) | "This program halts" |
END: The stronger the machine, the wider the languages it recognizes. Regular ⊂ Context-Free ⊂ Decidable ⊂ Recognizable.

### What is a Turing Machine? What is the Church-Turing Thesis?
E: It is a machine like a person with one endlessly long notebook and a pencil·eraser who reads cells, changes them, and moves left and right by following nothing but a fixed rule table. It looks simple, but it can do every computation today's computers can do.
A: A Turing Machine is an abstract machine with an infinite Tape, a Head that reads, writes, and moves left and right, and finite States; it is stronger than a PDA because it can freely change the Tape. The Church-Turing Thesis is the claim that "what can be computed by an algorithm is exactly what can be computed by a Turing Machine"; it is not a mathematically proven theorem but a widely accepted thesis. Ordinary programming languages like Python have the same power as a Turing Machine and are called "Turing Complete."

### What is the Hierarchy of languages?
| Language | Recognizing machine | Example |
| Regular Language | DFA / NFA / Regular Expression | Email format checks, "strings ending in 0" |
| Context-Free Language | PDA / CFG | Matched brackets, {0ⁿ1ⁿ}, programming language grammars |
| Decidable Language | A Turing Machine that always halts | {aⁿbⁿcⁿ}, primality testing |
| Recognizable Language | Turing Machine (may not halt when rejecting) | "This program eventually halts" |
A: They nest in the order Regular ⊂ Context-Free ⊂ Decidable ⊂ Recognizable, and each containment is a Proper Subset. Decidable means halting on every input with a yes/no answer, and Recognizable means only having to halt for sure on "yes" inputs.

## Decidability

#### Decidable and Recognizable
ONE: **Decidable** means it can **always halt** with a yes/no answer for every input, and **Recognizable** means it only has to **halt for sure** when the answer is "yes."
LIKE: Decidable is a help-desk agent who eventually answers "yes" or "no" to any question. Recognizable is an agent who will always tell you eventually if the answer is "yes," but for "no" questions might keep thinking forever and never answer.
STEP:
1. **Decider**: A Turing Machine that halts on every input. A language (problem) that has such a machine is Decidable.
2. **Recognizer**: Halts and accepts on "yes" inputs, but on "no" inputs it either rejects and halts or **may run forever**.
3. Example: "Does this program halt on input w?" is Recognizable. Just run it, and if it halts, say "yes." But if it does not halt, you never know how long to wait, so you can never settle on "no."
4. **Important property**: If a language and its complement are **both** Recognizable, the language is Decidable. Run the two machines alternately one step at a time, and one of them is guaranteed to halt.
WHY: It shows that "solvable" also has grades. Some problems let you confirm "yes" but give you no way to confirm "no."
END: Decidable = always answers; Recognizable = always answers only when it's "yes."

#### The Halting Problem
ONE: A "program that, given **any program and input**, always correctly decides **whether that program will halt**" can **never be built**. That is what it means for the Halting Problem to be Undecidable.
LIKE: Suppose there is "a fortune teller who can tell whether any program will halt." Build a contrarian program that asks the fortune teller and **always does the opposite**, then ask about the contrarian program itself, and the fortune teller is wrong no matter what it says.
STEP:
1. **Assumption**: Suppose there is a program H that, for every program M and input w, always answers "yes if M halts on w, no otherwise" (proof by contradiction).
2. **Build the contrarian D**: D takes a program M and asks H(M, M): "If you feed M itself into M, does it halt?"
3. If H says "it halts," D deliberately falls into an infinite loop; if H says "it doesn't halt," D halts right away. It always does the opposite.
4. **What if you feed D itself into D?** If H(D, D) says "it halts," D loops forever (does not halt) → H was wrong. If H(D, D) says "it doesn't halt," D halts → H was wrong again.
5. Either way there is a contradiction, so H cannot exist. This kind of "ask it about itself" proof is called **Diagonalization**.
6. This is not a matter of time or hardware. It is impossible even with a Quantum Computer or infinite time.
WHY: It tells us that "a perfect checker that finds every infinite-loop Bug" or "a program that perfectly identifies every Virus" is impossible in principle. That is why real tools catch only some cases or decide approximately.
USE: To show other problems are Undecidable, you prove "if you could solve that problem, you could solve the Halting Problem too" (Reduction).
END: "An all-knowing fortune teller who predicts halting" cannot exist because of the contrarian program. Some things are impossible for computers in principle.

### Why is the Halting Problem Undecidable?
E: Suppose there is "a fortune teller who can tell whether any program will halt." If you build a contrarian program that asks the fortune teller and always does the opposite, then ask about the contrarian program itself, the fortune teller is wrong no matter what it says.
A: Assume there is a Turing Machine H(M, w) that solves the Halting Problem, and build D, which takes a program M and falls into an Infinite Loop if H(M, M) says "it halts" and halts if it says "it doesn't halt." Feeding D itself into D produces a contradiction both when it halts and when it doesn't, so H cannot exist (Diagonalization). That is why "a perfect Bug checker that finds every Infinite Loop" cannot be built.

## Computational Complexity

#### P and NP: Easy to Solve vs Easy to Check
ONE: **P** is the class of problems that can be **solved quickly (in polynomial time)**, and **NP** is the class of problems where, given an answer, you can **quickly check whether it is right**. Anything in P is also in NP.
LIKE: Think of Sudoku. Filling in every blank is hard, but checking whether someone's filled-in answer is right is easy. "Problems that are easy to check" are NP, and "problems that are also easy to solve" are P.
STEP:
1. **Polynomial Time**: Time expressed as a power of the input size, like O(n), O(n²), O(n³). In theory, this is the standard for "fast (efficient)." Exponential time like O(2ⁿ) is slow.
2. **Decision Problem**: A problem answered yes/no. Optimization problems are handled by rephrasing them, like "is there a path of length at most k?"
3. **P**: Problems that can be **solved** in polynomial time. Examples: sorting, shortest paths, searching a sorted array.
4. **NP**: Problems where, when the answer is "yes," a given proof (**Certificate**) can be **checked** in polynomial time. Example: "Can this Graph be colored with 3 colors?" Given a coloring, you can quickly check that neighbors have different colors.
5. A problem in P can be checked by just solving it directly, so it is also in NP. That is, **P ⊆ NP**.
6. NP stands for "Non-deterministic Polynomial." It does not mean "Not Polynomial."
END: P is easy to solve; NP is easy to check. If it is easy to solve, it is easy to check, so P ⊆ NP.

#### NP-Complete and NP-Hard
ONE: **NP-Hard** problems are **so hard that every NP problem can be turned into them**, and those that **are also in NP** are **NP-Complete**. Solve just one NP-Complete problem quickly, and all of NP is solved quickly.
LIKE: NP-Complete problems are the "final bosses" of the NP world. If you find an easy way to beat one final boss, you can use that method to clear every other stage easily.
STEP:
1. **Polynomial-Time Reduction (Y ≤ₚ X)**: Quickly turning the input of problem Y into the input of problem X so that "Y's answer is yes ⇔ X's answer is yes." Then solving X solves Y too. That is, X is **at least as hard as Y**.
2. **NP-Hard**: Every NP problem can be Reduced to X. X is no easier than any problem in NP.
3. **NP-Complete**: NP-Hard, and X itself is also in NP.
4. **The first NP-Complete problem**: SAT (is there an assignment that makes a logic formula true?). The Cook-Levin Theorem proved it.
5. **How to show a new problem X is NP-Complete**: ① show X is in NP (proofs can be checked quickly), and ② Reduce a known NP-Complete problem (e.g., 3-SAT) **to X**.
6. **A common mistake**: Reducing in the opposite direction (X to 3-SAT) proves nothing. It only means "X is no harder than 3-SAT."
7. **Classic NP-Complete problems**: SAT, 3-SAT, Graph coloring, Hamiltonian Path, the Traveling Salesman Problem (decision version), Subset Sum, the knapsack problem (decision version), Vertex Cover, Clique.
KEY: The Halting Problem is NP-Hard but not in NP. It cannot be solved at all (Undecidable), so it cannot even be checked. NP-Hard includes "possibly harder than NP."
END: If a known hard problem can be turned into a new problem, the new problem is hard too. The representatives of those hard problems are the NP-Complete problems.

#### P vs NP: A Question Nobody Can Answer Yet
ONE: "Is every problem that is easy to check also easy to solve?" In other words, **is P = NP?** It is the biggest **unsolved problem** in computer science.
LIKE: It is the question "is there always a way to solve a Sudoku as quickly as you can check its answer?" Most people believe "no," but nobody has proven it yet.
STEP:
1. P ⊆ NP is certain. The question is whether NP is truly bigger than P.
2. **What most people believe: P ≠ NP**. For decades, countless people have looked for fast solutions to NP-Complete problems, and nobody has found one.
3. **If P = NP and a practical Algorithm came with it**: Integer factorization is also in NP, so much of today's public key cryptography, like RSA, would be at risk.
4. On the other hand, optimization problems that are hard today, like logistics, scheduling, protein structure, and finding mathematical proofs, would become much easier.
5. This problem is one of the Clay Mathematics Institute's seven Millennium Prize Problems, with a $1 million prize for solving it.
END: P vs NP asks "if it's easy to check, is it easy to solve?", and depending on the answer, the worlds of cryptography and optimization would look completely different. Nobody knows yet.

#### What to Do When You Hit an NP-Complete Problem
ONE: Once a problem turns out to be NP-Complete, you stop expecting "a solution that is always fast and exact" and pick one of **approximation · heuristics · restricting the input · brute force for small n**.
LIKE: When finding your way on a mountain with no accurate map, you don't insist on "the perfect shortest route" but use realistic approaches like "a good-enough route," "a route that usually works from experience," or "this mountain is small, so just explore all of it."
STEP:
1. **Approximation Algorithms**: Fast solutions with a guaranteed quality, like within 2 times the optimum. Example: Vertex Cover has a simple 2-approximation Algorithm.
2. **Heuristics and local search**: No guarantees, but they work well in practice. Example: for the Traveling Salesman Problem, improving bit by bit by trying swaps of parts of the route.
3. **Restricting the input**: Even if hard in general, there is often a polynomial-time solution when the input is a Tree or the numbers are small. Example: the knapsack problem is solved with DP (O(nW)) when the weights are small.
4. **Brute force for small n**: If n is around 20–30, even exponential time is fine with Backtracking + pruning.
5. **Use dedicated Solvers**: SAT Solvers and ILP Solvers are exponential time in the theoretical worst case, but they often handle real problems well even when those problems are very large.
WHY: In an interview, recognizing "this problem is NP-Complete, so there's probably no fast solution" and then offering realistic alternatives earns big points.
END: When you hit NP-Complete, let go of perfection and pick the right one of approximation·heuristics·exploiting conditions·small-n search.

### What is the difference between P, NP, NP-Complete, and NP-Hard?
E: Sudoku is hard to solve, but checking whether someone's filled-in answer is right is easy. "Problems that are easy to check" are NP, and "problems that are also easy to solve" are P. NP-Complete problems are the representative hardest problems in NP; solve just one quickly, and all of NP is solved quickly.
A: P is the class of Decision Problems solvable in Polynomial Time, NP is the class where, when the answer is "yes," its proof (Certificate) can be Verified in Polynomial Time, and P ⊆ NP. NP-Hard problems are those to which every NP problem can be Reduced in Polynomial Time (at least as hard as the hardest problems in NP), and those that are also in NP are NP-Complete. SAT, 3-SAT, Vertex Cover, and Hamiltonian Path are NP-Complete, and the Halting Problem is NP-Hard but not in NP.

### How do you prove NP-Completeness with a Polynomial-Time Reduction?
E: To show "this new problem is as hard as a famous hard problem," turn the famous hard problem into the new problem and show "solving the new problem would solve the hard one too." Don't get the direction mixed up.
A: To show problem X is NP-Complete, ① show X ∈ NP (its Certificate can be checked in Polynomial Time), and ② Reduce an already-known NP-Complete problem Y (e.g., 3-SAT) to X in Polynomial Time (Y ≤ₚ X). The Reduction must turn Y's input into X's input so that "Y's answer is yes ⇔ X's answer is yes," and a common mistake is Reducing in the opposite direction (X to Y), which proves nothing. The first NP-Complete problem was SAT, shown by the Cook-Levin Theorem.

### What would happen if P = NP were proven?
A: If P = NP is true and a practical Polynomial-Time Algorithm came with it, every problem whose answer is easy to check could be solved quickly. Prime Factorization is also in NP, so much of today's Public Key cryptography, like RSA, would be at risk, while problems like Scheduling·logistics·searching for mathematical proofs would become much easier. Today many people believe P ≠ NP, but it remains an unproven Open Problem.

### What do you actually do when you hit an NP-Complete problem?
E: It is choosing "a good-enough route," "a route that works from experience," or "explore all of it if the mountain is small," instead of insisting on the perfect shortest route.
A: Since an exact polynomial-time solution is unlikely, pick an alternative that fits the situation: Approximation Algorithms with guaranteed quality (e.g., a 2-approximation for Vertex Cover), Heuristics·Local Search that work well in practice without guarantees, special solutions when the input is a Tree or the values are small (e.g., the O(nW) DP for the knapsack problem), Backtracking + Pruning when n is small, and SAT·ILP Solvers.
