## Complexity 분석

#### Algorithm이란? 좋은 Algorithm의 두 가지 조건
ONE: **Algorithm**은 입력을 원하는 출력으로 바꾸는 **정해진 절차**예요. 좋은 Algorithm은 **항상 맞는 답을 내고(정확성)**, **데이터가 많아져도 빨라야(효율성)** 해요.
LIKE: Algorithm은 요리 레시피예요. 같은 김치찌개도 레시피에 따라 10분이 걸리기도 하고 10시간이 걸리기도 해요. 그리고 아무리 빨라도 맛이 틀리면(정확성) 쓸모가 없어요.
STEP:
1. **입력과 출력**: 예를 들어 "숫자 목록"을 받아 "정렬된 목록"을 내놓는 것이 정렬 Algorithm이에요.
2. **유한성**: 언젠가는 반드시 끝나야 해요.
3. **정확성 (Correctness)**: 가능한 모든 입력에 대해 올바른 답을 내야 해요. 몇 개 해 보고 맞았다는 건 증명이 아니에요.
4. **효율성 (Efficiency)**: 입력 크기 n이 커질 때 시간과 Memory가 **얼마나 빨리 늘어나는지**로 평가해요.
5. 같은 문제를 푸는 Algorithm이 여러 개일 때, 데이터가 작으면 차이가 안 보이지만 커지면 수천, 수만 배 차이가 나요.
WHY: 컴퓨터가 아무리 빨라도 나쁜 Algorithm은 못 구해요. 100만 개를 O(n²)으로 정렬하면 1조 번, O(n log n)이면 약 2천만 번이에요.
USE: 검색 엔진, 지도 길 찾기, 추천, 압축, 암호까지 모든 Software 안에 Algorithm이 있어요. 기술 면접의 Coding Test는 이 능력을 확인하는 시험이에요.
END: Algorithm = 문제 해결 레시피. 맞아야 하고(정확성), 데이터가 커져도 빨라야(효율성) 해요.

#### Time Complexity와 성장률 감각
ONE: **Time Complexity**는 입력 크기 n이 커질 때 **연산 횟수가 어떤 모양으로 늘어나는지**, **Space Complexity**는 추가 Memory가 어떻게 늘어나는지를 나타내요.
LIKE: 손님이 10명에서 1만 명으로 늘 때, 요리 시간이 "손님 수만큼" 늘어나는지, "손님 수의 제곱만큼" 늘어나는지를 보는 거예요. 몇 초인지가 아니라 **늘어나는 모양**을 봐요.
STEP:
1. 실제 시간은 컴퓨터마다 달라서, 대신 **기본 연산을 몇 번 하는지**를 n의 식으로 세요.
2. n이 아주 커지면 가장 빨리 커지는 항이 전부를 차지해요. 그래서 **상수와 작은 항은 버려요**. 3n² + 100n + 5 → O(n²).
3. 이렇게 "커질 때의 모양"만 보는 걸 **Asymptotic(점근적) 분석**이라고 해요.
4. 자주 보는 모양을 느린 증가부터 빠른 증가 순으로 외워 두세요.
| Complexity | 대표 예 | n = 100만일 때 감각 |
| O(1) | 배열 Index 접근, Hash 조회 | 즉시 |
| O(log n) | Binary Search, Balanced Tree | 약 20번 |
| O(n) | 배열 한 번 훑기 | 100만 번 |
| O(n log n) | 좋은 정렬 | 약 2천만 번 |
| O(n²) | 이중 반복문 | 1조 번 (사실상 불가) |
| O(2ⁿ), O(n!) | 모든 부분집합·순열 탐색 | n이 20~30만 넘어도 불가 |
5. **입력 크기로 목표 거꾸로 추정하기**: 컴퓨터는 1초에 대략 수천만~수억 번의 단순 연산을 해요(언어마다 달라요). 그래서 n이 10만이면 O(n²)은 위험하고 O(n log n) 이하를 목표로 잡아요.
KEY: Space Complexity에는 **재귀 호출이 쌓는 Stack**도 들어가요. 깊이 n까지 재귀하면 O(n) Memory를 써요.
END: Complexity는 "n이 커질 때 늘어나는 모양"이에요. 상수는 버리고 가장 큰 항만 봐요.

#### Big-O · Big-Ω · Big-Θ
ONE: **Big-O**는 "이보다 느리진 않다"(상한), **Big-Ω**는 "이보다 빠를 순 없다"(하한), **Big-Θ**는 "딱 이 정도다"(정확한 성장률)라는 뜻이에요.
LIKE: 택시비로 치면 Big-O는 "아무리 막혀도 2만 원은 안 넘어", Big-Ω는 "아무리 안 막혀도 1만 원은 나와", Big-Θ는 "딱 그 정도 나와"예요.
STEP:
1. **Big-O (Upper Bound)**: f(n) = O(g(n))은 "충분히 큰 n에서 f(n)이 g(n)의 상수배보다 작거나 같다"는 뜻이에요. 정확히는 어떤 상수 c > 0과 n₀가 있어서 n ≥ n₀이면 f(n) ≤ c·g(n).
2. **Big-Ω (Lower Bound)**: 반대로 f(n) ≥ c·g(n). "최소한 이만큼은 걸린다".
3. **Big-Θ (Tight Bound)**: O와 Ω를 동시에 만족해요. 위아래가 같은 성장률이에요.
4. 예: 3n² + n은 O(n²)이고, O(n³)이라고 해도 틀린 말은 아니에요(상한일 뿐이니까요). 하지만 Θ(n²)이 가장 정확한 표현이에요.
5. 실무와 면접에서 "이건 O(n log n)이에요"라고 할 때는 보통 Θ의 뜻으로 써요.
KEY: Big-O/Ω/Θ와 **Best · Average · Worst Case**는 다른 이야기예요. Case는 "어떤 입력이냐"(예: 이미 정렬된 입력), Big-O는 "그 경우의 성장률을 어떻게 표현하냐"예요. "Quick Sort는 Worst Case에서 Θ(n²)"처럼 둘을 함께 써요.
END: O는 천장, Ω는 바닥, Θ는 딱 맞는 크기예요. Case(입력의 종류)와는 다른 축이에요.

#### Complexity 계산 요령: 반복문과 재귀
ONE: 반복문은 **"한 번 도는 비용 × 도는 횟수"**, 재귀는 **"호출이 몇 개로 갈라지고 크기가 어떻게 줄어드는지"**로 계산해요.
LIKE: 반복문은 "하루에 몇 쪽 × 며칠"로 읽은 쪽수를 세는 것이고, 재귀는 "일을 몇 명에게 나눠 맡기고, 각자 얼마나 작은 일을 받는지"로 전체 일을 세는 거예요.
STEP:
1. **단일 반복문**: n번 돌고 안에서 O(1) 일을 하면 O(n).
2. **중첩 반복문은 곱하기**: 바깥 n번 × 안쪽 n번 = O(n²).
3. **연달아 있는 반복문은 더하기**: n번 반복 다음에 또 n번 반복하면 O(n + n) = O(n).
4. **반씩 줄어드는 반복문**: `while n > 1: n //= 2`는 O(log n).
5. **입력이 다르면 변수도 다르게**: 배열 A(길이 a)와 B(길이 b)를 각각 훑으면 O(a + b)지, O(n)이라고 뭉뚱그리면 안 돼요. 서로 중첩하면 O(a × b).
6. **재귀**: 호출 하나가 몇 개의 하위 호출을 만들고 각 크기가 얼마인지로 점화식을 세워요. 예: 반씩 두 번 호출하고 합치는 데 n → T(n) = 2T(n/2) + n.
7. **재귀의 Memory**: 동시에 쌓이는 호출 깊이만큼 Stack을 써요.
```python
for i in range(n):          # n번
    for j in range(i, n):   # 평균 n/2번 → 전체 약 n²/2 → O(n²)
        ...
```
END: 중첩은 곱하고, 연달아는 더하고, 반씩 줄면 log, 재귀는 점화식으로 세요.

#### Master Theorem
ONE: 문제를 크기 n/b인 하위 문제 a개로 나누고 합치는 데 f(n)이 드는 재귀 **T(n) = aT(n/b) + f(n)**의 답을 바로 구하는 공식이에요.
LIKE: 큰 일을 a명에게 나눠 맡기고, 결과를 모으는 데 f(n)만큼 일이 들어요. "나눠 맡긴 일의 총량"과 "모으는 일" 중 큰 쪽이 전체 시간을 결정해요.
STEP:
1. 비교 기준값을 구해요: **n^(log_b a)**. 이건 "재귀로 쪼개진 일의 총량"이 어느 정도로 늘어나는지를 나타내요.
2. **f(n)이 확실히 더 작으면**: 재귀 쪽이 지배해요 → Θ(n^(log_b a)).
3. **둘이 같은 차수면**: 층마다 같은 양의 일이 log n층 쌓여요 → Θ(n^(log_b a) · log n).
4. **f(n)이 확실히 더 크면**: 합치는 일이 지배해요 → Θ(f(n)) (정규성 조건이라는 추가 조건을 만족할 때).
| 점화식 | a, b, f(n) | 결과 | 예 |
| T(n) = 2T(n/2) + n | 2, 2, n | Θ(n log n) | Merge Sort |
| T(n) = T(n/2) + 1 | 1, 2, 1 | Θ(log n) | Binary Search |
| T(n) = 3T(n/2) + n | 3, 2, n | Θ(n^1.585) | Karatsuba 곱셈 |
| T(n) = 2T(n/2) + n² | 2, 2, n² | Θ(n²) | 합치는 비용이 지배 |
5. 예: Merge Sort는 a = 2, b = 2라서 n^(log₂2) = n이고 f(n) = n과 같아요. 그래서 Θ(n log n).
WHY: Divide and Conquer Algorithm의 시간을 매번 재귀 트리를 그려 계산하지 않고 바로 구할 수 있어요.
END: n^(log_b a)와 f(n)을 비교해서, 작으면 재귀가, 같으면 log가 한 번 더, 크면 f(n)이 이겨요.

#### Amortized Analysis (분할 상환 분석)
ONE: 가끔 비싼 연산이 있어도, **연속된 연산 전체 비용을 횟수로 나눈 평균**을 구하는 방법이에요. 최악의 순서에서도 보장되는 평균이에요.
LIKE: 헬스장 연회비는 한 번에 크게 내지만, 1년 동안 나눠 보면 하루 비용은 작아요.
STEP:
1. Dynamic Array에 원소를 계속 넣어요. 대부분은 빈칸에 넣기만 하면 돼서 O(1)이에요.
2. 가끔 꽉 차면 2배 크기로 옮기느라 O(n)이 들어요.
3. 하지만 n번 넣는 동안 옮긴 총량은 1 + 2 + 4 + … < 2n이에요.
4. 그래서 n번의 총비용은 O(n), 한 번당 평균 O(1)이에요. 이게 **Amortized O(1)**이에요.
5. **확률적 평균과의 차이**: Hash Table의 "평균 O(1)"은 운(Key 분포)에 기대는 평균이에요. Amortized는 운과 상관없이 어떤 순서로 연산해도 총합이 보장되는 평균이에요.
USE: Dynamic Array의 append, Stack 두 개로 만든 Queue, Union-Find의 연산 비용을 설명할 때 써요.
END: Amortized는 "가끔의 큰 비용을 전체에 나눠 낸 평균"이고, 최악의 순서에서도 지켜지는 약속이에요.

#### Algorithm의 정확성 증명: Loop Invariant
ONE: 반복문이 **매 회차 시작할 때 항상 참인 성질(Loop Invariant)**을 정하고, 그 성질이 처음부터 끝까지 유지됨을 보여서 Algorithm이 옳다는 걸 증명하는 방법이에요.
LIKE: 카드를 정리할 때 "내 왼손에 든 카드는 항상 정렬돼 있다"는 규칙을 지킨다고 해 봐요. 처음에도 맞고(카드 1장), 한 장 더 끼울 때도 맞고, 카드를 다 받았을 때도 맞으면, 결국 전체가 정렬된 거예요.
STEP:
1. **불변식 정하기**: Insertion Sort라면 "i번째 회차를 시작할 때 앞의 i개는 정렬돼 있다".
2. **초기화 (Initialization)**: 반복이 시작되기 전에 참이에요. 앞의 1개는 당연히 정렬돼 있어요.
3. **유지 (Maintenance)**: 한 회차를 돌고 나도 여전히 참이에요. 새 원소를 제자리에 끼우면 앞의 i + 1개가 정렬돼요.
4. **종료 (Termination)**: 반복이 끝났을 때 불변식이 곧 원하는 결과예요. 끝나면 i = n이니 전체가 정렬돼 있어요.
5. 이건 수학적 귀납법(01번 주제)을 반복문에 적용한 것이에요.
WHY: "테스트 몇 개 통과했다"는 모든 입력에서 맞는다는 보장이 아니에요. 불변식은 모든 경우를 한 번에 증명해 줘요.
USE: 면접에서 "이 코드가 왜 맞나요?"라고 물으면 불변식으로 설명하면 논리적으로 답할 수 있어요. Binary Search의 경계 조건 Bug를 잡을 때도 "lo는 항상 답보다 작거나 같다" 같은 불변식이 큰 도움이 돼요.
END: Loop Invariant = 처음에 참 + 매번 유지 + 끝나면 원하는 결과. 반복문 버전의 귀납법이에요.

### Time Complexity와 Space Complexity란?
E: 손님이 10명에서 1만 명으로 늘 때 요리 시간(Time Complexity)과 필요한 조리대 크기(Space Complexity)가 어떻게 늘어나는지를 보는 것입니다. 초 단위가 아니라 "늘어나는 모양"을 봅니다.
A: Time Complexity는 입력 크기 n에 따라 수행하는 기본 연산 횟수가 어떻게 증가하는지, Space Complexity는 추가로 필요한 Memory가 어떻게 증가하는지를 나타냅니다. Hardware와 상관없이 Algorithm끼리 비교하려고 상수와 낮은 차수 항은 버리고 가장 빨리 커지는 항만 봅니다.
M: 빠른 순서: O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ) < O(n!). n = 100만일 때 n log n은 약 2천만, n²은 1조입니다.

### Big-O, Big-Ω, Big-Θ의 정확한 정의와 차이는?
E: 택시비로 치면 Big-O는 "아무리 막혀도 이 정도를 넘진 않아"(Upper Bound, 상한), Big-Ω는 "아무리 빨라도 이 정도는 나와"(Lower Bound, 하한), Big-Θ는 "딱 이 정도야"(Tight Bound, 양쪽)입니다.
A: f(n) = O(g(n))은 어떤 상수 c > 0과 n₀가 있어 n ≥ n₀인 모든 n에서 f(n) ≤ c·g(n)이라는 뜻으로 Asymptotic Upper Bound(점근적 상한)입니다. Ω는 f(n) ≥ c·g(n)인 Lower Bound, Θ는 O와 Ω를 동시에 만족하는 딱 맞는 증가율입니다. 실무에서 "O(n log n)"이라고 할 때는 보통 Θ의 뜻으로 쓰고, Best·Average·Worst Case는 이와 별개로 "어떤 입력인가"의 구분입니다.

### Master Theorem으로 T(n) = aT(n/b) + f(n)을 푸는 법은?
E: 큰 일을 a개의 작은 일로 쪼개고 다시 합치는 비용이 f(n)입니다. "쪼개진 일들의 총량"과 "합치는 비용" 중 큰 쪽이 전체 시간을 결정합니다.
A: f(n)을 n^(log_b a)와 비교합니다. f(n)이 다항식적으로 더 작으면 Θ(n^(log_b a)), 같은 차수면 Θ(n^(log_b a) · log n), 다항식적으로 더 크고 Regularity Condition(정규성 조건)을 만족하면 Θ(f(n))입니다.
| Recurrence | a, b, f(n) | 결과 | 예 |
| T(n) = 2T(n/2) + n | 2, 2, n | Θ(n log n) | Merge Sort |
| T(n) = T(n/2) + 1 | 1, 2, 1 | Θ(log n) | Binary Search |
| T(n) = 3T(n/2) + n | 3, 2, n | Θ(n^log₂3) ≈ n^1.585 | Karatsuba Multiplication |
| T(n) = 2T(n/2) + n² | 2, 2, n² | Θ(n²) | 합치는 비용이 지배 |

### Amortized Analysis(분할 상환 분석)란?
E: 헬스장 연회비는 한 번에 크게 내지만, 1년 동안 나눠 보면 하루 비용은 작습니다.
A: Amortized Analysis는 가끔 비싼 연산이 있어도 연산을 연속으로 할 때의 총비용을 횟수로 나눈 평균 비용을 구하는 방법입니다. 확률적 평균이 아니라 최악의 연산 순서에서도 보장되는 평균이며, Dynamic Array append(평균 O(1))와 Union-Find, Stack 2개로 만든 Queue가 대표 예입니다.

### 반복문과 재귀 함수의 Time Complexity는 어떻게 계산하나요?
E: 반복문은 "하루에 몇 쪽 × 며칠", 재귀는 "일을 몇 명에게 나눠 맡기고 각자 얼마나 작은 일을 받는지"로 셉니다.
A: 반복문은 한 회차의 비용 × 반복 횟수로 계산해 중첩이면 곱하고 연속이면 더하며, 범위가 매번 절반으로 줄면 O(log n)입니다. 재귀는 호출 하나가 만드는 하위 호출 수와 크기로 T(n) = aT(n/b) + f(n) 같은 점화식을 세워 Master Theorem이나 Recursion Tree로 풉니다. 서로 다른 입력은 서로 다른 변수(O(a + b))로 쓰고, Space Complexity에는 재귀 호출 Stack 깊이도 포함합니다.

### Algorithm이 올바르다는 것은 어떻게 증명하나요?
E: "내 왼손 카드는 항상 정렬돼 있다"는 규칙이 처음에도, 한 장 끼울 때마다도, 다 받았을 때도 지켜지면 결국 전부 정렬된 것입니다.
A: 반복문은 Loop Invariant(루프 불변식)로 증명합니다. 매 회차 시작 시 항상 참인 성질을 정하고, 반복 전에 참이고(Initialization), 한 회차 후에도 유지되며(Maintenance), 종료 시 원하는 결과를 뜻함(Termination)을 보입니다. 수학적 귀납법을 반복문에 적용한 것이고, 재귀 Algorithm은 귀납법으로 직접 증명합니다.

#### Sorting과 Stable Sort
ONE: **Sorting**은 원소를 정해진 순서로 줄 세우는 것이고, 값이 같은 원소들의 **원래 순서가 유지되면 Stable Sort**예요.
LIKE: 이미 이름순으로 서 있는 학생들을 키순으로 다시 세울 때, 키가 같은 두 학생의 이름순이 그대로 남아 있으면 Stable Sort예요.
STEP:
1. 정렬된 데이터에서는 Binary Search로 빠르게 찾고, 중복을 쉽게 찾고, 순위를 매길 수 있어요. 그래서 정렬은 많은 Algorithm의 첫 단계예요.
2. **Comparison Sort**: 두 원소를 비교(a < b?)해서 순서를 정해요. Bubble, Insertion, Merge, Quick, Heap.
3. **Non-Comparison Sort**: 값 자체를 Index처럼 써요. Counting, Radix.
4. **In-Place**: 추가 Memory를 거의 안 쓰고 원래 배열 안에서 정렬해요.
5. **Stable**: 같은 값의 원래 순서를 유지해요. Merge, Insertion, Bubble, Counting, Timsort는 Stable. Quick, Heap, Selection은 보통 아니에요.
| Sorting | 평균 | 최악 | 추가 Memory | Stable |
| Bubble · Insertion | O(n²) | O(n²) | O(1) | 예 |
| Selection | O(n²) | O(n²) | O(1) | 아니오 |
| Merge | O(n log n) | O(n log n) | O(n) | 예 |
| Quick | O(n log n) | O(n²) | O(log n) | 아니오 |
| Heap | O(n log n) | O(n log n) | O(1) | 아니오 |
| Counting · Radix | O(n + k) 계열 | O(n + k) 계열 | O(n + k) | 예 |
KEY: Stable이 중요한 순간: "날짜순으로 정렬한 다음 부서별로 정렬"하면, 같은 부서 안에서는 날짜순이 유지돼요. Stable Sort라서 가능한 일이에요.
END: 정렬은 많은 문제의 출발점이고, 같은 값의 원래 순서를 지키면 Stable이에요.

#### 단순 정렬: Bubble · Selection · Insertion
ONE: 세 가지 모두 이해하기 쉽고 추가 Memory가 O(1)이지만, 평균·최악이 **O(n²)**이에요. 그중 **Insertion Sort**는 거의 정렬된 데이터에서 아주 빨라요.
LIKE: Bubble은 옆 사람과 키를 비교해 큰 사람이 뒤로 한 칸씩 가는 것, Selection은 매번 남은 사람 중 가장 작은 사람을 찾아 앞에 세우는 것, Insertion은 카드를 한 장씩 받아 손에 든 정렬된 카드 사이 제자리에 끼우는 거예요.
STEP:
1. **Bubble Sort**: 이웃한 두 원소를 비교해 순서가 틀리면 바꿔요. 한 바퀴 돌 때마다 가장 큰 값이 맨 뒤로 "거품처럼" 올라가요. 한 바퀴 동안 바꾼 게 없으면 이미 정렬된 거라 일찍 끝낼 수 있어요(Best O(n)).
2. **Selection Sort**: 남은 원소 중 최솟값을 찾아 맨 앞과 바꿔요. 입력과 상관없이 항상 O(n²) 비교를 해요. 대신 교환은 최대 n번이라 교환이 비싼 경우엔 의미가 있어요.
3. **Insertion Sort**: 앞부분을 정렬된 상태로 유지하면서, 다음 원소를 그 안의 제자리에 끼워 넣어요.
4. 데이터가 거의 정렬돼 있으면 각 원소가 조금만 움직이면 돼서 O(n)에 가까워요.
5. 원소가 적을 때는 단순해서 오히려 빨라요. 그래서 Timsort 같은 실전 정렬이 작은 구간을 Insertion Sort로 처리해요.
END: 셋 다 O(n²)이지만, 거의 정렬된 작은 데이터에는 Insertion Sort가 실제로 강해요.

#### Merge Sort (병합 정렬)
ONE: 배열을 **반으로 나눠 각각 정렬한 뒤, 정렬된 두 반쪽을 합치는** Divide and Conquer 정렬이에요. 항상 **O(n log n)**이고 Stable해요.
LIKE: 시험지 더미를 반씩 나눠 친구 둘에게 정리시킨 뒤, 정리된 두 더미의 맨 위만 비교하며 작은 것부터 하나씩 내려놓아 합쳐요.
STEP:
1. **Divide**: 배열을 반으로 나눠요. 원소가 하나가 될 때까지 계속 나눠요(하나는 이미 정렬된 상태예요).
2. **Merge**: 정렬된 두 배열을 합쳐요. 두 배열의 맨 앞을 비교해 작은 것을 결과에 넣고 그 배열의 다음 원소로 넘어가요. 한쪽이 바닥나면 나머지를 그대로 붙여요.
3. 합치기는 원소 수만큼, 즉 각 층에서 O(n)이 들어요.
4. 반씩 나누니 층이 log n개예요. 그래서 전체 O(n log n). 점화식 T(n) = 2T(n/2) + n.
5. 입력이 어떻든 똑같이 나누고 합치니 Best·Average·Worst 모두 O(n log n)이에요.
PRO: 항상 O(n log n)이 보장되고 Stable해요. 순서대로 읽기만 해서 Linked List 정렬이나, Memory에 다 안 들어가는 큰 파일 정렬(External Sort)에 좋아요.
CON: 합칠 때 결과를 담을 O(n) 추가 Memory가 필요해요.
END: Merge Sort는 "반으로 나누고, 맨 앞끼리 비교하며 합치기"예요. 항상 n log n, 대신 추가 공간이 필요해요.

#### Quick Sort (퀵 정렬)
ONE: 기준값(**Pivot**)을 하나 골라 **작은 건 왼쪽, 큰 건 오른쪽**으로 나누고(Partition), 양쪽을 다시 같은 방법으로 정렬해요. 평균 O(n log n)이고 실전에서 가장 빠른 편이지만, 최악은 O(n²)이에요.
LIKE: 기준 학생 한 명을 정해 "나보다 작은 사람은 왼쪽, 큰 사람은 오른쪽"으로 나누게 해요. 그다음 왼쪽 무리와 오른쪽 무리에서 각각 또 기준을 정해 나누기를 반복해요.
STEP:
1. **Pivot 고르기**: 배열에서 기준값 하나를 골라요.
2. **Partition**: Pivot보다 작은 원소는 왼쪽, 큰 원소는 오른쪽으로 옮겨요. 이제 Pivot은 최종 자리에 있어요.
3. 왼쪽 부분과 오른쪽 부분을 각각 재귀로 정렬해요. 합치는 단계가 따로 필요 없어요.
4. Pivot이 매번 가운데쯤이면 반씩 나뉘어 O(n log n)이에요.
5. **최악**: Pivot이 매번 최솟값이나 최댓값이면 한쪽이 텅 비어요. 이미 정렬된 배열에서 첫 원소를 Pivot으로 고르면 이렇게 돼서 O(n²)이에요.
6. **해결**: Pivot을 무작위로 고르거나(Random Pivot), 처음·가운데·끝 세 값의 중앙값을 써요(Median-of-Three). 무작위로 고르면 특정한 나쁜 입력이 사라져서 기대 시간이 O(n log n)이 돼요.
PRO: 제자리에서 정렬해 추가 Memory가 적고(재귀 Stack 평균 O(log n)), 연속된 Memory를 훑어 Cache 효율이 좋아서 실제로 매우 빨라요.
CON: 최악 O(n²)이 있고 Stable하지 않아요.
END: Quick Sort는 "기준으로 나누고 양쪽 반복하기"예요. 평균은 가장 빠르지만 Pivot을 잘못 고르면 n²이니 무작위로 골라요.

#### Heap Sort (힙 정렬)
ONE: 배열을 **Max Heap**으로 만든 뒤, 가장 큰 값(Root)을 맨 뒤로 보내기를 반복하는 정렬이에요. **항상 O(n log n)**이면서 **제자리(In-Place)** 정렬이에요.
LIKE: 응급실 대기열(Heap)에서 가장 급한 환자를 하나씩 꺼내 차례대로 세우는 거예요.
STEP:
1. 배열을 Max Heap으로 만들어요(Build-Heap, O(n)). 이제 Root가 최댓값이에요.
2. Root(최댓값)와 맨 끝 원소를 바꿔요. 최댓값이 제자리(맨 뒤)에 갔어요.
3. Heap 크기를 하나 줄이고, 새 Root를 아래로 내려 Heap을 다시 맞춰요(Sift-Down, O(log n)).
4. 이걸 n번 반복하면 뒤에서부터 큰 값 순으로 채워져 정렬이 끝나요.
5. 전체 O(n log n)이고, 추가 배열 없이 원래 배열 안에서 해요.
PRO: 최악에도 O(n log n)이 보장되고, 추가 Memory가 O(1)이에요.
CON: Stable하지 않고, 배열을 여기저기 뛰어다녀 Cache 효율이 낮아서 실제로는 Quick Sort보다 느린 경우가 많아요.
USE: 최악 시간을 꼭 보장해야 할 때 써요. C++의 std::sort가 쓰는 Introsort는 Quick Sort로 하다가 재귀가 너무 깊어지면 Heap Sort로 바꿔 최악을 막아요.
END: Heap Sort는 "최댓값을 하나씩 뒤로 보내기"이고, 최악 보장 + 제자리가 장점이에요.

#### Counting Sort와 Radix Sort
ONE: 원소끼리 비교하지 않고 **값 자체를 Index처럼** 써서, 조건이 맞으면 O(n log n)보다 빠르게 정렬하는 방법이에요.
LIKE: Counting Sort는 시험 점수(0~100점)를 정렬할 때 점수마다 바구니를 놓고 답안지를 던져 넣은 뒤, 바구니 순서대로 꺼내는 거예요. Radix Sort는 우편번호를 끝자리부터 한 자리씩 바구니에 나눠 담기를 반복하는 거예요.
STEP:
1. **Counting Sort**: 값의 범위가 0~k로 좁은 정수일 때 써요. 값마다 몇 개인지 세고(count 배열), 그 개수만큼 차례로 내보내요. O(n + k).
2. k가 n보다 훨씬 크면(예: 값 범위가 10억) count 배열이 너무 커서 못 써요.
3. **Radix Sort**: 숫자를 자릿수별로 나눠서, 가장 낮은 자리부터 높은 자리까지 자리마다 Stable한 Counting Sort를 해요. d자리면 O(d(n + k)).
4. 낮은 자리부터 해도 되는 이유: 각 단계가 Stable해서 앞 단계에서 만든 순서가 같은 자리값 안에서 유지되기 때문이에요.
5. 비교를 안 하니 아래에서 배울 "비교 정렬의 한계 Ω(n log n)"을 피해 가요.
CON: 정수나 고정 길이 문자열처럼 Key 모양이 제한되고, 추가 Memory가 필요해요.
END: 값의 범위가 좁으면 Counting, 자릿수가 정해져 있으면 Radix. 비교를 안 해서 n log n보다 빨라질 수 있어요.

#### 비교 정렬의 한계: 왜 Ω(n log n)일까?
ONE: 원소를 **비교만 해서** 정렬하는 모든 Algorithm은 최악의 경우 **n log n번 정도는 비교해야** 해요. 이보다 빠른 비교 정렬은 존재할 수 없어요.
LIKE: 스무고개를 떠올려 보세요. "예/아니오" 질문만 할 수 있는데 가능한 답이 n!가지(모든 줄 서는 순서)라면, 최소 log₂(n!)번은 물어야 정답을 고를 수 있어요.
STEP:
1. n개 원소를 줄 세우는 방법은 n!가지예요. 정렬은 이 중 정답 하나를 찾아내는 일이에요.
2. 비교 한 번은 "예/아니오" 답 하나를 줘서 가능한 경우를 많아야 절반으로 줄여요.
3. n!가지를 1가지로 줄이려면 최소 log₂(n!)번 비교해야 해요.
4. 수학적으로 log₂(n!)은 약 n log₂ n이에요(Θ(n log n)).
5. 그래서 최악의 경우 Ω(n log n)번보다 적게 비교하는 비교 정렬은 없어요. Merge Sort와 Heap Sort는 이 한계에 딱 맞는 최적 비교 정렬이에요.
KEY: Counting Sort와 Radix Sort가 이 한계보다 빠를 수 있는 건, 비교를 하지 않기 때문이에요.
END: 비교로만 정렬하면 n log n이 벽이에요. 이 벽을 넘으려면 값 자체를 이용(Counting·Radix)해야 해요.

#### Timsort: 실전 정렬
ONE: 실제 데이터에 이미 정렬된 구간이 많다는 점을 이용해 **Insertion Sort와 Merge Sort를 섞은** Hybrid 정렬이에요. Python의 `sort()`/`sorted()`가 이걸 바탕으로 해요.
LIKE: 책장을 정리할 때, 이미 순서대로 꽂혀 있는 묶음은 그대로 두고 그 묶음들끼리만 합치는 똑똑한 정리법이에요.
STEP:
1. 데이터에서 이미 오름차순(또는 내림차순)으로 정렬된 구간(**Run**)을 찾아요. 내림차순 구간은 뒤집어요.
2. Run이 너무 짧으면 Insertion Sort로 일정 길이까지 늘려요(작은 구간에선 Insertion Sort가 빠르니까요).
3. 이렇게 만든 Run들을 규칙에 따라 Merge해요.
4. 이미 정렬된 데이터면 Run 하나로 끝나서 O(n), 최악에도 O(n log n)이고 Stable해요.
USE: Python의 정렬, Java의 Object 배열 정렬이 Timsort 기반이에요.
END: Timsort는 "이미 정렬된 부분은 살리고, 작은 건 Insertion, 큰 건 Merge"로 실전 데이터에 최적화된 정렬이에요.

### Bubble / Selection / Insertion Sort의 동작과 복잡도는?
E: Bubble은 옆사람과 키를 비교해 큰 사람이 뒤로 한 칸씩 옮기는 것, Selection은 매번 남은 사람 중 가장 작은 사람을 찾아 앞에 세우는 것, Insertion은 카드를 한 장씩 받아 손에 든 정렬된 카드 사이 제자리에 끼워 넣는 것입니다.
A: 세 Sorting 모두 Average·Worst O(n²)이고 추가 Memory가 O(1)입니다. Bubble Sort는 인접한 두 원소를 비교·교환(Swap)하고, Selection Sort는 최솟값을 찾아 앞으로 보내며 항상 O(n²) 비교를 하지만 교환은 최대 n번입니다. Insertion Sort는 거의 정렬된 데이터에서 O(n)에 가까워 작은 Array에서 실제로 빠르므로 Timsort 같은 Hybrid Sort의 부품으로 쓰입니다.

### Merge / Heap / Quick Sort의 동작과 복잡도는? Quick Sort 최악이 O(n²)인 경우는?
E: Merge Sort는 시험지 더미를 반씩 나눠 친구들에게 정리시킨 뒤 정리된 두 더미를 맨 위만 비교하며 합치는 것입니다. Quick Sort는 기준 학생(Pivot)을 정해 "나보다 작은 사람은 왼쪽, 큰 사람은 오른쪽"으로 나누는 것을 반복합니다. Heap Sort는 응급실 대기열(Heap)에서 가장 급한 환자를 하나씩 꺼내는 것입니다.
A: Merge Sort는 반으로 나눠 정렬한 뒤 합치는 Divide and Conquer로 항상 O(n log n)이고 Stable하지만 O(n) 추가 Memory가 필요합니다. Heap Sort는 Max Heap을 만들고 Root를 끝으로 보내는 것을 반복해 항상 O(n log n)이고 In-Place(제자리) Sorting입니다. Quick Sort는 Pivot 기준으로 Partition(분할)해 평균 O(n log n)이고 Cache 효율이 좋아 실제로 빠르지만, Pivot이 매번 최솟값이나 최댓값이면(예: 이미 정렬된 Array에서 첫 원소를 Pivot으로) 한쪽에 하나도 없는 분할이 n번 일어나 O(n²)입니다. Random Pivot이나 Median-of-Three(세 값의 중앙값)로 완화합니다.

### Counting / Radix Sort는 어떻게 O(n log n)보다 빠를 수 있나요?
E: Counting Sort는 시험 점수(0~100점)를 정렬할 때 점수마다 바구니를 놓고 답안지를 던져 넣은 뒤 바구니 순서대로 꺼내는 것입니다. Radix Sort는 우편번호를 끝자리부터 한 자리씩 바구니에 나눠 담기를 반복하는 것입니다.
A: 두 Sorting은 원소끼리 비교하지 않고 값 자체를 Index처럼 쓰기 때문에 Comparison Sort의 하한 Ω(n log n)의 적용을 받지 않습니다. Counting Sort는 값의 범위 k가 작은 정수일 때 O(n + k)이고, Radix Sort는 자리마다 Stable한 Counting Sort를 반복해 O(d(n + k))입니다. 대신 정수나 고정 길이 String처럼 Key 형태가 제한되고 추가 Memory가 필요합니다.

### Stable Sort(안정 정렬)란?
E: 이미 이름순으로 서 있는 학생들을 키순으로 다시 세울 때, 키가 같은 두 학생의 이름순이 그대로 유지되면 Stable Sort입니다.
A: Stable Sort는 값이 같은 원소들의 원래 상대 순서를 유지하는 Sorting으로, Merge·Insertion·Bubble·Counting Sort와 Timsort가 Stable하고 Quick·Heap·Selection Sort는 일반적으로 아닙니다. "날짜순 정렬 후 부서별 정렬"처럼 여러 기준으로 차례로 정렬할 때 중요합니다.

### Comparison Sort의 하한이 Ω(n log n)인 이유는?
E: 스무고개처럼 "예/아니오" 질문만 할 수 있다면, 가능한 답이 n!가지(모든 줄 서는 순서)일 때 최소 log₂(n!)번은 물어야 정답을 고를 수 있습니다.
A: Comparison Sort는 비교 결과로 갈라지는 Decision Tree(결정 트리)로 표현되고, n개 원소의 모든 Permutation n!가지를 구분하려면 Leaf가 n!개 이상 필요합니다. Binary Tree의 Height는 최소 log₂(n!)이고 이는 Θ(n log n)이므로, 최악의 경우 Ω(n log n)번보다 적게 비교하는 Comparison Sort는 없습니다.

### Python sorted()가 쓰는 Timsort는?
A: Timsort는 데이터에서 이미 정렬된 구간(Run)을 찾아 짧은 구간은 Insertion Sort로 늘리고 구간들을 Merge하는 Hybrid Sort입니다. 실제 데이터는 부분적으로 정렬된 경우가 많아 매우 빠르고, Best O(n), Worst O(n log n)이며 Stable합니다. Python의 sort/sorted와 Java의 Object Array 정렬이 Timsort 기반입니다.

## Search

#### Binary Search와 Lower · Upper Bound
ONE: **정렬된 배열**에서 가운데 값과 비교해 **찾을 범위를 절반씩** 줄이는 검색이에요. **O(log n)**이라 100만 개도 약 20번이면 찾아요.
LIKE: 사전에서 단어를 찾을 때 가운데를 펼쳐 보고 "더 앞이네" 하면 앞쪽 절반만 보는 걸 반복해요. 1000쪽 사전도 10번 안쪽이면 찾아요.
STEP:
1. **조건**: 배열이 정렬돼 있어야 해요.
2. 범위 [lo, hi]의 가운데 mid를 봐요.
3. 찾는 값과 같으면 끝. 찾는 값이 더 작으면 hi = mid − 1(왼쪽 절반), 더 크면 lo = mid + 1(오른쪽 절반).
4. 범위가 비면 없는 거예요.
5. 매번 절반이 되니 반복 횟수는 log₂ n번이에요.
6. **Lower Bound**: x **이상**인 첫 위치. **Upper Bound**: x **보다 큰** 첫 위치. 둘의 차이가 x의 개수예요. Python은 `bisect_left`, `bisect_right`.
7. **Parametric Search (매개변수 탐색)**: "조건을 만족하는 최솟값"처럼, 답이 어느 지점부터 계속 만족(False…False True…True)하는 모양이면 답 자체를 Binary Search할 수 있어요. 예: "모든 짐을 D일 안에 옮기려면 트럭 용량이 최소 얼마?"
```python
def binary_search(a, x):
    lo, hi = 0, len(a) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if a[mid] == x: return mid
        if a[mid] < x: lo = mid + 1
        else: hi = mid - 1
    return -1
```
KEY: 경계(`<` vs `<=`, `mid` vs `mid ± 1`)를 틀리기 쉬워요. 불변식("답은 항상 [lo, hi] 안에 있다")을 정해 두고 쓰면 실수가 줄어요. C·Java에서는 `lo + hi`가 Overflow할 수 있어 `lo + (hi − lo) / 2`를 써요.
END: 정렬돼 있으면 반씩 버리며 찾아요(O(log n)). 답이 "어느 순간부터 쭉 만족"하는 모양이면 답 자체도 Binary Search할 수 있어요.

### Binary Search의 조건과 복잡도는? Lower Bound / Upper Bound는?
E: 사전에서 단어를 찾을 때 가운데를 펼쳐 "더 앞이네" 하면 앞 절반만 보는 것을 반복합니다. 1000쪽 사전도 10번 안쪽이면 찾습니다.
A: Binary Search는 정렬된 Array에서 가운데 값과 비교해 탐색 범위를 절반씩 줄여 O(log n)에 찾습니다. Lower Bound는 x 이상인 첫 위치, Upper Bound는 x보다 큰 첫 위치이고, 둘의 차가 x의 개수입니다(Python `bisect_left` / `bisect_right`). "조건을 만족하는 최솟값"을 찾는 Parametric Search(매개변수 탐색)에도 같은 원리를 씁니다.
M: `mid = (lo + hi) // 2`에서 언어에 따라 lo + hi가 Overflow할 수 있어 `lo + (hi − lo) // 2`를 쓰기도 합니다(Python 정수는 무한 정밀도라 문제없음).

## Divide and Conquer

#### Divide and Conquer (분할 정복)
ONE: 문제를 **같은 모양의 작은 문제로 나누고(Divide)**, **각각 풀고(Conquer)**, **결과를 합치는(Combine)** 설계 방법이에요.
LIKE: 큰 피자 한 판을 조각으로 나눠 친구들이 각자 먹고 결과를 모으는 거예요. 조각들은 서로 상관없는 독립적인 문제여야 해요.
STEP:
1. **Divide**: 문제를 비슷한 모양의 더 작은 문제들로 나눠요.
2. **Conquer**: 작은 문제를 재귀로 풀어요. 충분히 작으면 바로 풀어요(Base Case).
3. **Combine**: 작은 답들을 합쳐 큰 답을 만들어요.
4. 대표 예: Merge Sort(나누고 합치기), Quick Sort(나누기에 일이 몰림), Binary Search(반만 계속).
5. **Quickselect**: k번째로 작은 원소를 찾을 때 전체를 정렬할 필요 없어요. Quick Sort처럼 Partition한 뒤 k가 있는 쪽만 계속 내려가면 평균 O(n)이에요. Pivot으로 "중앙값들의 중앙값(Median of Medians)"을 쓰면 최악도 O(n)이 보장돼요.
6. **Karatsuba 곱셈**: 큰 수 곱셈을 4번이 아닌 3번의 작은 곱셈으로 나눠 O(n²)을 O(n^1.585)로 줄여요.
7. 시간은 Master Theorem으로 구해요.
KEY: 나눈 작은 문제들이 **서로 겹치면**(같은 계산을 반복하면) Divide and Conquer는 낭비예요. 그럴 땐 답을 저장해 재사용하는 Dynamic Programming을 써요.
END: 나누고, 풀고, 합치기. 작은 문제들이 서로 독립적일 때 쓰고, 겹치면 DP로 가요.

### Divide and Conquer란?
E: 큰 피자 한 판을 여러 조각으로 나눠 친구들이 나눠 먹고, 먹은 결과를 모으는 것입니다. 조각이 서로 상관없는 독립적인 문제여야 합니다.
A: Divide and Conquer(분할 정복)는 문제를 같은 형태의 작은 문제로 나누고(Divide), 재귀적으로 풀고(Conquer), 결과를 합치는(Combine) 설계 방법입니다. Merge Sort, Quick Sort, Binary Search, k번째 원소를 평균 O(n)에 찾는 Quickselect, 곱셈을 4번이 아니라 3번으로 줄여 O(n^1.585)에 큰 수를 곱하는 Karatsuba Algorithm이 대표 예이고, Complexity는 Master Theorem으로 구합니다. Subproblem이 겹치면 같은 계산을 반복하므로 Dynamic Programming이 낫습니다.

## Dynamic Programming

#### Dynamic Programming의 핵심: 두 가지 조건
ONE: **큰 문제의 답을 작은 문제의 답으로 만들 수 있고**, **같은 작은 문제가 여러 번 나올 때**, 작은 답을 한 번만 계산해 **저장하고 재사용**하는 기법이에요.
LIKE: 계단을 1칸 또는 2칸씩 오를 때 10번째 계단에 오르는 방법 수는 "9번째까지의 방법 + 8번째까지의 방법"이에요. 매번 처음부터 세지 않고 계단마다 답을 메모해 두면 한 번에 끝나요.
STEP:
1. **Optimal Substructure (최적 부분 구조)**: 큰 문제의 최적해가 작은 문제의 최적해로 이루어져요.
2. **Overlapping Subproblems (중복 부분 문제)**: 같은 작은 문제가 여러 번 등장해요.
3. Fibonacci를 그냥 재귀로 풀면 F(5)가 F(4)와 F(3)을 부르고, F(4)가 또 F(3)을 불러요. 같은 계산이 기하급수적으로 반복돼서 O(2ⁿ)이에요.
4. 한 번 계산한 F(k)를 저장해 두고 다시 필요하면 꺼내 쓰면, 각 값을 한 번씩만 계산해서 O(n)이 돼요.
5. 두 조건이 모두 있어야 DP가 의미 있어요. 작은 문제가 겹치지 않으면 Divide and Conquer, 지금의 최선만 골라도 되면 Greedy가 더 간단해요.
```python
from functools import lru_cache

@lru_cache(maxsize=None)     # 계산한 값을 저장(Memoization)
def fib(n):
    return n if n < 2 else fib(n - 1) + fib(n - 2)
```
END: DP = "작은 답으로 큰 답 만들기" + "같은 작은 답은 한 번만 계산해서 저장".

#### DP 설계 5단계
ONE: DP 문제는 **상태 정의 → 점화식 → 초기값 → 계산 순서 → 공간 줄이기** 순서로 설계해요. 그중 **상태 정의가 가장 중요**해요.
LIKE: 엑셀 표를 채우는 것과 같아요. 먼저 "각 칸에 무엇을 적을지" 정하고(상태), "이 칸은 옆 칸들로 어떻게 계산하는지" 정하고(점화식), 첫 칸을 채우고(초기값), 어느 방향으로 채울지 정해요(순서).
STEP:
1. **상태 정의**: "dp[i]는 무엇을 뜻하는가"를 한 문장으로 써요. 예: "dp[i] = i번째 계단까지 오르는 방법의 수". 이게 전체의 대부분이에요. 상태만 잘 정하면 나머지는 따라와요.
2. **점화식**: 현재 상태를 더 작은 상태들로 표현해요. 예: dp[i] = dp[i−1] + dp[i−2].
3. **초기값 (Base Case)**: 가장 작은 상태의 값을 정해요. 예: dp[0] = 1, dp[1] = 1.
4. **계산 순서**: 위에서 아래로(재귀 + 저장, Memoization) 또는 아래에서 위로(작은 것부터 표 채우기, Tabulation).
5. **공간 줄이기**: 바로 앞 한두 칸만 필요하면 표 전체를 들고 있을 필요가 없어요. Fibonacci는 변수 두 개면 돼요.
KEY: 상태를 정하는 요령은 "답을 구하려면 무엇을 알아야 하나?"를 묻는 거예요. 배낭 문제라면 "몇 번째 물건까지 봤나"와 "남은 무게"가 필요하니 dp[i][w]가 돼요.
END: 칸의 의미(상태)를 먼저 정하면, 점화식·초기값·순서는 자연스럽게 따라와요.

#### Memoization (Top-Down) vs Tabulation (Bottom-Up)
ONE: DP를 구현하는 두 방법이에요. **Memoization**은 큰 문제부터 재귀로 내려가며 답을 저장하고, **Tabulation**은 작은 문제부터 표를 채워 올라가요.
LIKE: Memoization은 "필요할 때 계산하고 메모해 두기"이고, Tabulation은 "처음부터 순서대로 표를 다 채워 두기"예요.
STEP:
1. **Memoization (Top-Down)**: 재귀 함수로 큰 문제를 부르고, 처음 계산한 값은 저장(Cache)해요. 이미 저장된 값이면 바로 꺼내요.
2. 장점: 점화식을 그대로 옮기면 돼서 직관적이고, 실제로 필요한 작은 문제만 계산해요.
3. 단점: 재귀 호출 비용이 있고, 깊어지면 재귀 깊이 한도(Python 기본 약 1000)에 걸릴 수 있어요.
4. **Tabulation (Bottom-Up)**: 가장 작은 문제부터 반복문으로 표를 채워요. 큰 문제를 풀 때는 필요한 작은 답이 이미 채워져 있어요.
5. 장점: 재귀가 없어 빠르고 안전하며, 앞의 몇 칸만 남기는 공간 최적화가 쉬워요.
6. 단점: 계산 순서를 직접 정해야 하고, 필요 없는 칸까지 채울 수 있어요.
```python
def fib(n):               # Tabulation + 공간 최적화
    a, b = 0, 1
    for _ in range(n):
        a, b = b, a + b
    return a
```
END: 생각하기 쉬운 건 Memoization, 빠르고 안전한 건 Tabulation이에요. 시간 복잡도는 보통 같아요.

#### 대표 DP 문제
ONE: Fibonacci, 배낭 문제, LIS, LCS, Edit Distance는 DP의 기본 틀이에요. 이 다섯 가지 상태 정의를 익히면 대부분의 DP 문제가 그 변형으로 보여요.
LIKE: 요리 기본기(썰기, 볶기, 끓이기)를 익히면 새로운 요리도 그 조합으로 보이는 것과 같아요.
STEP:
1. **Fibonacci / 계단 오르기**: dp[i] = dp[i−1] + dp[i−2]. O(n).
2. **0/1 Knapsack (배낭)**: 무게 제한 W인 배낭에 물건(무게, 가치)을 넣거나 말거나 골라 가치를 최대로. dp[i][w] = "앞 i개 물건으로 무게 w 이하일 때 최대 가치" = max(i번째를 안 넣음 dp[i−1][w], 넣음 dp[i−1][w−wᵢ] + vᵢ). O(nW).
3. **LIS (최장 증가 부분 수열)**: dp[i] = i에서 끝나는 가장 긴 증가 수열 길이 = max(dp[j] + 1) (j < i, a[j] < a[i]). O(n²), Binary Search를 쓰면 O(n log n).
4. **LCS (최장 공통 부분 수열)**: 두 문자열에서 순서를 지키며 공통으로 나오는 가장 긴 수열. 글자가 같으면 dp[i−1][j−1] + 1, 다르면 max(위, 왼쪽). O(nm). diff 도구의 원리예요.
5. **Edit Distance (편집 거리)**: 한 문자열을 다른 문자열로 바꾸는 최소 삽입·삭제·교체 횟수. 같으면 dp[i−1][j−1], 다르면 1 + min(삽입, 삭제, 교체). 맞춤법 교정, DNA 비교에 써요.
KEY: 배낭 문제의 O(nW)는 W가 "숫자의 크기"라서 입력 길이(Bit 수)로 보면 지수적이에요. 이런 걸 **Pseudo-Polynomial(의사 다항)** 시간이라고 해요.
END: 기본 다섯 가지(Fibonacci, 배낭, LIS, LCS, Edit Distance)의 상태 정의를 외워 두면 DP의 절반은 끝나요.

### Dynamic Programming이란? Optimal Substructure와 Overlapping Subproblems는?
E: 계단을 1칸 또는 2칸씩 오를 때 10번째 계단에 오르는 방법 수는 "9번째까지 방법 + 8번째까지 방법"입니다. 매번 처음부터 세지 않고 계단마다 답을 메모해 두면 한 번에 끝납니다.
A: Dynamic Programming(DP, 동적 계획법)은 큰 문제의 답을 작은 문제의 답으로 만들 수 있고(Optimal Substructure, 최적 부분 구조), 같은 작은 문제가 여러 번 나타날 때(Overlapping Subproblems, 중복 부분 문제) 각 답을 한 번만 계산해 저장하고 재사용하는 기법입니다. Fibonacci를 단순 Recursion으로 풀면 O(2ⁿ)이지만 저장하면 O(n)입니다. State(`dp[i]`가 무엇인가), Recurrence(점화식), 초기값, 계산 순서를 정하는 것이 설계의 핵심입니다.

### Memoization(Top-Down) vs Tabulation(Bottom-Up)은?
A: Memoization은 Recursion으로 큰 문제부터 내려가며 계산한 값을 Cache에 저장하는 방식으로, 필요한 Subproblem만 풀고 구현이 직관적이지만 Recursion Depth 제한에 걸릴 수 있습니다. Tabulation은 가장 작은 문제부터 표를 채워 올라가는 반복문 방식으로, Recursion Overhead가 없고 이전 몇 칸만 남겨 Memory를 줄이기 쉽습니다.

### 대표 DP 문제는?
| 문제 | State 정의 | Recurrence(핵심) | Complexity |
| Fibonacci / 계단 오르기 | dp[i] = i번째 값 | dp[i] = dp[i−1] + dp[i−2] | O(n) |
| 0/1 Knapsack (배낭) | dp[i][w] = 앞 i개 물건, 무게 w 이하의 최대 가치 | max(dp[i−1][w], dp[i−1][w−wᵢ] + vᵢ) | O(nW) (Pseudo-Polynomial) |
| LIS (Longest Increasing Subsequence) | dp[i] = i에서 끝나는 LIS 길이 | max(dp[j] + 1), j < i이고 a[j] < a[i] | O(n²), Binary Search 쓰면 O(n log n) |
| LCS (Longest Common Subsequence) | dp[i][j] = 앞 i글자와 앞 j글자의 LCS | 같으면 dp[i−1][j−1] + 1, 다르면 max(위, 왼쪽) | O(nm) |
| Edit Distance (편집 거리) | dp[i][j] = 앞 i글자를 앞 j글자로 바꾸는 최소 연산 | 같으면 dp[i−1][j−1], 다르면 1 + min(삽입, 삭제, 교체) | O(nm) |
A: Fibonacci·Knapsack·LIS·LCS·Edit Distance가 대표적입니다. Knapsack의 O(nW)는 W가 수의 크기라 입력 Bit 수에 대해 지수적이므로 Pseudo-Polynomial Time(의사 다항 시간)이고, Edit Distance는 맞춤법 교정과 DNA 비교에, LCS는 diff 도구에 쓰입니다.

## Greedy Algorithm

#### Greedy Algorithm과 정답 증명
ONE: 매 단계에서 **지금 가장 좋아 보이는 선택**을 하고 **되돌아보지 않는** 방법이에요. 빠르고 단순하지만, 그 선택이 전체 최적을 망치지 않는다는 **증명**이 필요해요.
LIKE: 하루에 회의실 하나에 회의를 최대한 많이 넣으려면 "가장 일찍 끝나는 회의"부터 골라요. 빨리 끝날수록 다음 회의를 넣을 시간이 많이 남으니까요.
STEP:
1. 매 순간 정해진 기준으로 최선을 골라요. 이미 고른 건 바꾸지 않아요.
2. **언제 맞나**: 지금의 최선 선택이 어떤 최적해에 반드시 포함될 수 있고(**Greedy Choice Property**), 남은 문제도 같은 모양일 때(Optimal Substructure)예요.
3. **회의실 배정 (Interval Scheduling)**: 끝나는 시간 순으로 정렬한 뒤, 앞 회의와 겹치지 않으면 고르기를 반복해요. O(n log n)이고 최적이에요.
4. **Exchange Argument (교환 논증)**: 증명 방법이에요. "어떤 최적해가 있다고 할 때, 그 첫 선택을 Greedy의 첫 선택(가장 일찍 끝나는 회의)으로 바꿔도 여전히 가능하고 개수가 줄지 않는다"를 보여요. 이걸 반복하면 Greedy 해도 최적이에요.
5. 대표 Greedy Algorithm: Dijkstra(가장 가까운 곳부터 확정), Kruskal·Prim(가장 싼 다리부터), Huffman Coding(가장 드문 글자끼리 먼저 묶기).
WHY: Greedy는 DP보다 훨씬 빠르고 코드도 짧아요. 맞기만 하면 최고의 선택이에요.
END: Greedy = "지금 최선, 뒤돌아보지 않기". 쓰기 전에 반드시 맞는지 증명하거나 반례를 찾아봐요.

#### Greedy가 틀리는 경우
ONE: 지금의 최선이 나중의 최선을 막을 수 있는 문제에서는 Greedy가 **틀린 답**을 내요. 그럴 땐 DP를 써요.
LIKE: 등산할 때 매 갈림길에서 당장 가장 가파른 오르막만 고르면, 작은 봉우리에 올라가 갇힐 수 있어요. 진짜 정상은 잠깐 내려갔다가 올라가야 나올 수도 있어요.
STEP:
1. **동전 문제**: 동전이 1·3·4원일 때 6원을 가장 적은 개수로 만들기. Greedy(큰 동전부터)는 4 + 1 + 1 = 3개, 최적은 3 + 3 = 2개.
2. 한국 동전(10·50·100·500원)은 Greedy가 맞아요. 단위들이 서로 잘 맞물려 있어서 큰 동전을 쓰는 게 손해가 되는 경우가 없어요. 단위가 달라지면 깨질 수 있어요.
3. **0/1 배낭 문제**: "무게당 가치가 큰 것부터" 담으면 틀릴 수 있어요. 물건을 쪼갤 수 없으니 남는 공간이 아까워지거든요. 그래서 DP로 풀어요.
4. **분할 배낭 (Fractional Knapsack)**: 물건을 쪼갤 수 있으면 "무게당 가치 순" Greedy가 최적이에요.
5. 요령: Greedy를 쓰기 전에 작은 반례를 몇 개 손으로 만들어 보세요. 반례가 하나라도 나오면 DP나 다른 방법을 써요.
END: Greedy는 맞으면 최고지만, 동전(1·3·4원)이나 0/1 배낭처럼 틀리는 경우가 많아요. 반례부터 찾아보세요.

### Greedy Algorithm이란? 언제 최적을 보장하나요?
E: 등산할 때 매 갈림길에서 당장 가장 가파른 길만 고르는 것입니다. 산이 단순하면 정상에 가장 빨리 가지만, 작은 봉우리에 갇힐 수도 있습니다.
A: Greedy는 매 단계에서 지금 가장 좋아 보이는 선택을 하고 되돌리지 않는 방법입니다. Greedy Choice Property(지금의 최선이 어떤 최적해에 포함됨)와 Optimal Substructure가 있을 때만 최적을 보장하므로, 단순하고 빠르지만 반드시 정답임을 증명해야 합니다. Dijkstra, Kruskal·Prim, Huffman Coding이 대표적인 Greedy입니다.

### Interval Scheduling과 Exchange Argument(교환 논증)는?
E: 하루에 회의실 하나에 최대한 많은 회의를 넣으려면 "가장 일찍 끝나는 회의"부터 고릅니다. 빨리 끝날수록 다음 회의를 위한 시간이 더 많이 남기 때문입니다.
A: 겹치지 않는 구간(Interval)을 최대한 많이 고르는 문제는 끝나는 시간 순으로 정렬해 앞에서부터 가능한 것을 고르면 O(n log n)에 최적입니다. Exchange Argument는 "어떤 최적해의 첫 선택을 Greedy의 첫 선택(가장 일찍 끝나는 구간)으로 바꿔도 여전히 가능하고 개수가 줄지 않는다"를 보이고 이를 반복해, Greedy 해도 최적임을 증명하는 방법입니다.

### Greedy가 실패하는 예는?
A: 동전이 1·3·4원일 때 6원을 만들면 Greedy는 4 + 1 + 1(3개)을 고르지만 최적은 3 + 3(2개)입니다. 0/1 Knapsack도 "무게당 가치가 큰 순"으로 담으면 틀릴 수 있어 DP로 풀고, 물건을 쪼갤 수 있는 Fractional Knapsack(분할 배낭)은 그 Greedy가 최적입니다. 한국 동전(10·50·100·500원)처럼 큰 단위가 작은 단위의 배수인 경우에는 Greedy가 맞습니다.

## Graph Search

#### BFS와 DFS
ONE: **BFS**는 가까운 곳부터 **층층이** 퍼져 나가고(Queue), **DFS**는 한 길을 **끝까지** 파고들었다 돌아와요(Stack·재귀). 둘 다 O(V + E)예요.
LIKE: BFS는 호수에 돌을 던졌을 때 물결이 가까운 곳부터 동심원으로 퍼지는 것이고, DFS는 미로에서 한 길로 끝까지 가 보고 막히면 돌아와 다른 길로 가는 거예요.
STEP:
1. **BFS (Breadth-First Search)**: 시작점을 Queue에 넣고, 꺼낸 Vertex의 아직 안 간 이웃을 모두 Queue에 넣기를 반복해요.
2. 거리 1인 곳을 다 본 다음 거리 2인 곳을 봐요. 그래서 처음 발견한 순간이 곧 **최단 거리(Edge 개수 기준)**예요.
3. **DFS (Depth-First Search)**: 한 이웃으로 들어가 그곳의 이웃으로 또 들어가요. 더 갈 곳이 없으면 되돌아와(Backtrack) 다른 길로 가요. 재귀나 Stack으로 구현해요.
4. DFS에서 각 Vertex를 "처음 발견한 시각"과 "다 끝낸 시각"을 기록하면 Cycle 찾기, Topological Sort, SCC를 얻을 수 있어요.
5. 둘 다 모든 Vertex와 Edge를 한 번씩 보니 Adjacency List에서 O(V + E)예요.
6. **방문 표시**가 꼭 필요해요. 안 하면 Cycle에서 같은 곳을 무한히 돌아요.
```python
from collections import deque

def bfs(graph, start):
    dist = {start: 0}
    q = deque([start])
    while q:
        u = q.popleft()
        for v in graph[u]:
            if v not in dist:          # 처음 발견한 순간 = 최단 거리
                dist[v] = dist[u] + 1
                q.append(v)
    return dist
```
| 구분 | BFS | DFS |
| 도구 | Queue | Stack / 재귀 |
| 퍼지는 모양 | 가까운 곳부터 층층이 | 한 길을 끝까지 |
| 잘하는 일 | 가중치 없는 최단 거리 | Cycle 탐지, 위상 정렬, 모든 경우 탐색 |
END: 최단 거리(칸 수)는 BFS, 끝까지 파고들어 구조를 알아내는 건 DFS예요.

#### Topological Sort (위상 정렬)
ONE: 방향이 있고 Cycle이 없는 Graph(**DAG**)에서, 모든 화살표 u → v에 대해 **u가 v보다 앞에 오도록** 줄 세우는 것이에요.
LIKE: 수강 신청 순서예요. "자료구조를 듣기 전에 프로그래밍 기초"처럼 선수 과목을 어기지 않게 과목을 줄 세우는 거예요. A가 B의 선수이고 B가 A의 선수라면 어느 것도 먼저 들을 수 없어요.
STEP:
1. **In-Degree (진입 차수)**: 나에게 들어오는 화살표 수, 즉 "먼저 들어야 하는 과목 수"예요.
2. **Kahn's Algorithm**: In-Degree가 0인(선수 과목이 없는) Vertex를 모두 Queue에 넣어요.
3. 하나 꺼내 결과에 붙이고, 그 Vertex에서 나가는 화살표를 지워요. 그러면 다음 과목들의 In-Degree가 1씩 줄어요.
4. In-Degree가 0이 된 Vertex를 Queue에 넣고 반복해요.
5. 끝났는데 결과에 못 들어간 Vertex가 남아 있으면 Cycle이 있다는 뜻이에요. Cycle 안의 Vertex들은 서로가 서로보다 먼저여야 해서 영원히 In-Degree가 0이 안 되니까요.
6. **DFS 방법**: DFS가 끝나는 순서를 거꾸로 뒤집어도 위상 정렬이 돼요. 둘 다 O(V + E).
KEY: 위상 정렬 결과는 하나로 정해지지 않고 여러 개일 수 있어요. "가능한 순서인가?"를 물으면 모든 화살표가 앞에서 뒤로 향하는지 하나씩 확인해요.
USE: 수강 순서, 빌드 시스템(어떤 파일을 먼저 Compile할지), 패키지 설치 순서, Spreadsheet 수식 계산 순서, 작업 일정.
END: 위상 정렬은 "선행 조건을 어기지 않는 줄 세우기"이고, Cycle이 있으면 불가능해요.

#### SCC (Strongly Connected Component)
ONE: 방향 Graph에서 **서로 오갈 수 있는 Vertex끼리 최대로 묶은 그룹**이에요.
LIKE: 일방통행 길이 많은 도시에서 "서로 갔다가 돌아올 수 있는 동네끼리" 묶은 거예요. 같은 묶음 안에서는 어디든 오갈 수 있어요.
STEP:
1. 방향 Graph에서 A → B로 갈 수 있다고 B → A로 갈 수 있는 건 아니에요.
2. **SCC**: 그룹 안의 모든 두 Vertex가 서로에게 갈 수 있는, 가장 큰 그룹이에요.
3. **Kosaraju Algorithm**: DFS를 한 번 해서 끝나는 순서를 기록하고, 모든 화살표 방향을 뒤집은 Graph에서 그 역순으로 DFS를 다시 해요. 두 번째 DFS 한 번에 닿는 Vertex들이 하나의 SCC예요.
4. **Tarjan Algorithm**: DFS 한 번에 각 Vertex가 "닿을 수 있는 가장 오래된 조상"(Low-Link)을 기록해서 SCC를 찾아요.
5. 둘 다 O(V + E)예요.
6. 각 SCC를 점 하나로 압축하면, 그 Graph는 항상 Cycle이 없는 DAG가 돼요. 그래서 복잡한 Graph를 단순하게 만들 수 있어요.
USE: SNS에서 서로 영향을 주고받는 그룹 찾기, 프로그램의 순환 의존성 찾기, 2-SAT 같은 논리 문제 풀기.
END: SCC는 "서로 오갈 수 있는 무리"이고, 묶어서 하나로 보면 Graph가 DAG로 단순해져요.

### BFS와 DFS의 동작·복잡도·쓰임새는?
E: BFS는 호수에 돌을 던졌을 때 물결이 가까운 곳부터 동심원으로 퍼지는 것, DFS는 미로에서 한 길로 끝까지 가 보고 막히면 돌아와 다른 길로 가는 것입니다.
A: BFS(Breadth-First Search)는 Queue를 써서 시작점에서 가까운 Vertex부터 층별로 방문하므로 Unweighted Graph의 Shortest Path(최소 Edge 수)를 구합니다. DFS(Depth-First Search)는 Stack이나 Recursion으로 한 방향을 끝까지 파고들어 Cycle 탐지, Topological Sort, SCC, Backtracking에 씁니다. Adjacency List에서 둘 다 모든 Vertex와 Edge를 한 번씩 보므로 O(V + E)입니다.
```python
from collections import deque

def bfs(graph, start):
    dist = {start: 0}
    q = deque([start])
    while q:
        u = q.popleft()
        for v in graph[u]:
            if v not in dist:          # 처음 발견한 순간 = 최단 거리
                dist[v] = dist[u] + 1
                q.append(v)
    return dist
```

### Topological Sort란? Cycle이 있으면 왜 불가능한가요?
E: 수강 신청 순서입니다. "자료구조를 듣기 전에 프로그래밍 기초"처럼 선수 과목을 어기지 않게 줄을 세우는 것입니다. A가 B의 선수이고 B가 A의 선수라면 어느 것도 먼저 들을 수 없습니다.
A: Topological Sort(위상 정렬)는 DAG(Directed Acyclic Graph)에서 모든 Edge u → v에 대해 u가 v보다 앞에 오도록 Vertex를 일렬로 나열하는 것입니다. In-Degree(진입 차수)가 0인 Vertex를 Queue에 넣고 하나씩 꺼내며 Edge를 지우는 Kahn's Algorithm이나, DFS가 끝난 순서를 뒤집는 방법으로 O(V + E)에 구합니다. Cycle 안의 Vertex들은 서로가 서로보다 앞서야 해서 모순이 생기므로 불가능하고, Kahn's Algorithm에서 끝까지 못 꺼낸 Vertex가 남으면 Cycle이 있다는 뜻입니다.
M: Topological Sort 결과는 하나로 정해지지 않고 여러 개일 수 있습니다. 시험에서 "가능한 순서인가"를 물으면 모든 Edge의 방향을 하나씩 확인하세요.

### SCC(Strongly Connected Component)란?
E: 일방통행 길이 많은 도시에서 "서로 갔다가 돌아올 수 있는 동네끼리" 묶은 것입니다. 묶음 안에서는 어디든 오갈 수 있습니다.
A: SCC(강결합 요소)는 Directed Graph에서 모든 Vertex 쌍이 서로에게 도달 가능한 최대 Vertex 집합입니다. DFS를 두 번(원래 Graph, 방향을 뒤집은 Graph) 하는 Kosaraju나 DFS 한 번에 Low-Link를 쓰는 Tarjan으로 O(V + E)에 구하고, SCC를 하나의 점으로 압축하면 그 Graph는 항상 DAG가 됩니다.

## Shortest Path

#### Shortest Path 문제와 Relaxation
ONE: 가중치가 있는 Graph에서 가장 짧은 경로를 찾는 문제예요. 모든 Algorithm이 **"u를 거쳐 v로 가는 게 더 짧으면 고친다"(Relaxation)**는 같은 동작을 반복하고, 차이는 **순서**뿐이에요.
LIKE: 친구에게 "우리 집에서 학교까지 20분"이라고 알고 있었는데, 다른 친구가 "편의점을 거쳐 가면 15분이야"라고 알려 주면 기록을 15분으로 고쳐요. 이걸 계속 반복하면 결국 가장 짧은 길이 남아요.
STEP:
1. **Relaxation (완화)**: `if dist[u] + w(u, v) < dist[v]: dist[v] = dist[u] + w(u, v)`.
2. 처음엔 출발점만 0, 나머지는 ∞로 두고 Relaxation을 반복해요.
3. **Single-Source**: 한 출발점에서 모든 곳까지. **All-Pairs**: 모든 두 점 사이.
4. **Negative Cycle (음수 사이클)**: 한 바퀴 돌 때마다 거리가 줄어드는 고리가 있으면, 계속 돌수록 짧아져서 최단 경로가 정의되지 않아요.
5. 상황에 따라 Algorithm을 골라요.
| 상황 | Algorithm | 시간 |
| 가중치 없음 (모두 1) | BFS | O(V + E) |
| DAG (Cycle 없음, 음수 가능) | 위상 정렬 순서로 Relaxation | O(V + E) |
| 한 출발점, 가중치 ≥ 0 | Dijkstra | O((V + E) log V) |
| 한 출발점, 음수 Edge 있음 | Bellman-Ford | O(VE) |
| 모든 쌍 | Floyd-Warshall | O(V³) |
KEY: DAG에서는 위상 정렬 순서로 처리하면, 어떤 Vertex에 도착했을 때 그리로 들어오는 길이 이미 다 계산돼 있어요. 그래서 Edge를 한 번씩만 Relax하면 끝나고(O(V + E)), 가중치에 −1을 곱하면 가장 긴 경로(프로젝트 일정의 Critical Path)도 구해요.
END: 최단 경로 Algorithm은 모두 "더 짧은 길을 찾으면 고치기"이고, 가중치 조건에 따라 고르는 순서가 달라요.

#### Dijkstra Algorithm
ONE: **가장 가까운 미확정 Vertex를 하나씩 확정**하며 퍼져 나가는 최단 경로 Algorithm이에요. **가중치가 모두 0 이상**일 때만 정확해요.
LIKE: 집에서 시작해 "지금까지 알려진 가장 가까운 곳"을 하나씩 확정하며 지도를 넓혀 가요. 한 번 확정한 곳은 다시 보지 않아요. 그런데 "지나가면 시간이 줄어드는 마법 터널(음수 Edge)"이 있으면 이미 확정한 답이 틀릴 수 있어요.
STEP:
1. 출발점 거리는 0, 나머지는 ∞로 둬요.
2. 아직 확정 안 된 Vertex 중 거리가 가장 작은 것을 꺼내 **확정**해요. 이 선택을 빠르게 하려고 Min Heap을 써요.
3. 그 Vertex의 이웃들을 Relax해요(더 짧아지면 거리를 고치고 Heap에 넣어요).
4. 모든 Vertex를 확정할 때까지 반복해요. Binary Heap을 쓰면 O((V + E) log V).
5. **왜 음수에서 틀릴까**: "가장 가까운 걸 꺼냈으니 이보다 짧아질 수 없다"는 가정이 핵심인데, 음수 Edge가 있으면 나중에 다른 길로 돌아와서 더 짧아질 수 있어요.
```python
import heapq

def dijkstra(graph, s):          # graph[u] = [(v, w), ...], w >= 0
    dist = {s: 0}
    pq = [(0, s)]
    while pq:
        d, u = heapq.heappop(pq)
        if d > dist.get(u, float("inf")):
            continue                # 이미 더 짧게 확정됨
        for v, w in graph[u]:
            nd = d + w
            if nd < dist.get(v, float("inf")):
                dist[v] = nd
                heapq.heappush(pq, (nd, v))
    return dist
```
USE: 지도 앱의 길 찾기, Network Routing(OSPF)의 기본 원리예요. 실제 지도 앱은 여기에 목적지 방향 추정(A* 등)을 더해 더 빠르게 해요.
KEY: Dijkstra로 만든 "출발점에서 각 점까지의 최단 경로 모음"은 MST(최소 신장 트리)와 다를 수 있어요. S-A 2, S-B 2, A-B 1인 삼각형에서 최단 경로 Tree는 {S-A, S-B}(합 4), MST는 {A-B, S-A}(합 3)이에요.
END: Dijkstra = "가장 가까운 곳부터 확정"하는 Greedy. 음수 Edge가 없을 때만 써요.

#### Bellman-Ford Algorithm
ONE: **모든 Edge를 Relax하는 일을 V − 1번** 반복하는 최단 경로 Algorithm이에요. 느리지만 **음수 Edge**를 다루고 **Negative Cycle**도 찾아내요.
LIKE: Dijkstra처럼 서두르지 않고, 모든 도로를 한 번씩 확인하는 일을 (도시 수 − 1)번 묵묵히 반복해요. 그래도 더 짧아지는 길이 있다면, 돌수록 줄어드는 마법 고리가 있다는 뜻이에요.
STEP:
1. 출발점 0, 나머지 ∞.
2. 모든 Edge를 한 번씩 Relax해요. 이걸 V − 1번 반복해요.
3. **왜 V − 1번?** Cycle이 없는 최단 경로는 Edge를 최대 V − 1개 써요. i번째 반복이 끝나면 "Edge i개 이하로 가는 최단 거리"가 확정되니, V − 1번이면 충분해요.
4. **Negative Cycle 찾기**: 한 번 더(V번째) 돌렸을 때도 거리가 줄어드는 곳이 있으면 Negative Cycle이 있어요.
5. 시간은 O(VE)로 Dijkstra보다 느려요.
USE: 음수 비용이 있는 문제(환율 차익 찾기: 환율에 log를 씌우면 이득 고리가 Negative Cycle이 돼요), Distance Vector Routing(RIP)의 원리예요.
END: Bellman-Ford = "모든 길 확인을 V−1번". 음수 Edge도 OK, 한 번 더 돌려서 줄면 Negative Cycle이에요.

#### Floyd-Warshall Algorithm
ONE: **모든 두 점 사이**의 최단 거리를 한 번에 구하는 DP예요. "k번 도시를 거쳐 가면 더 빠른가?"를 모든 쌍에 대해 확인해요.
LIKE: "1번 도시를 거쳐 가면 더 빠른가?"를 모든 도시 쌍에 대해 확인하고, 다음엔 2번 도시, 3번 도시… 순서로 경유지 후보를 늘려 가요.
STEP:
1. dist[i][j]를 직접 연결된 거리(없으면 ∞, 자기 자신은 0)로 채워요.
2. 경유지 k를 1번부터 V번까지 차례로 늘리며, 모든 (i, j)에 대해 `dist[i][j] = min(dist[i][j], dist[i][k] + dist[k][j])`를 해요.
3. k번째 단계가 끝나면 dist[i][j]는 "1~k번만 경유할 수 있을 때의 최단 거리"예요. 마지막까지 하면 진짜 최단 거리예요.
4. 반복문 세 개라 O(V³), 표 하나라 O(V²) Memory.
5. 음수 Edge도 다룰 수 있고, 끝난 뒤 dist[i][i] < 0인 곳이 있으면 Negative Cycle이에요.
KEY: k(경유지)를 가장 바깥 반복문에 둬야 해요. 순서를 바꾸면 틀려요.
USE: Vertex가 수백 개 이하인 작은 Graph에서 모든 쌍의 거리가 필요할 때(도시 간 거리표 만들기) 써요.
END: Floyd-Warshall = "경유지를 하나씩 늘리며 모든 쌍 고치기". 코드는 짧고 O(V³)이에요.

### Shortest Path 문제의 종류와 Algorithm 선택은?
| 상황 | Algorithm | 시간 |
| 가중치 없음(모두 1) | BFS | O(V + E) |
| DAG(Cycle 없음, 음수 가능) | Topological Sort 순서로 Relaxation | O(V + E) |
| Single-Source, 가중치 ≥ 0 | Dijkstra (Binary Heap) | O((V + E) log V) |
| Single-Source, 음수 Edge | Bellman-Ford | O(VE) |
| All-Pairs (모든 쌍) | Floyd-Warshall | O(V³) |
A: Shortest Path 문제는 한 Vertex에서 다른 모든 Vertex까지(Single-Source)와 모든 Vertex 쌍 사이(All-Pairs)로 나뉩니다. 가중치가 없으면 BFS, 음수가 없으면 Dijkstra, 음수 Edge가 있으면 Bellman-Ford, 모든 쌍이 필요하고 Vertex가 적으면 Floyd-Warshall을 씁니다. Negative Cycle(음수 사이클)이 있으면 계속 돌수록 작아져 Shortest Path가 정의되지 않습니다.

### Dijkstra의 동작과 복잡도, 음수 Edge에서 실패하는 이유는?
E: 집에서 시작해 "지금까지 알려진 가장 가까운 곳"을 하나씩 확정하며 지도를 넓혀 갑니다. 한 번 확정한 곳은 다시 보지 않는데, 어딘가 "지나가면 시간이 줄어드는 마법 터널(음수 Edge)"이 있으면 이미 확정한 답이 틀릴 수 있습니다.
A: Dijkstra는 출발점 거리를 0, 나머지를 ∞로 두고, Min Heap에서 거리가 가장 작은 미확정 Vertex를 꺼내 확정한 뒤 이웃의 거리를 Relax(완화)하는 것을 반복합니다. Binary Heap을 쓰면 O((V + E) log V)입니다. "꺼낸 Vertex의 거리는 더 줄어들지 않는다"는 가정이 모든 가중치 ≥ 0일 때만 성립하므로, 음수 Edge가 있으면 확정된 거리가 나중에 더 짧아질 수 있어 틀린 답을 냅니다.
```python
import heapq

def dijkstra(graph, s):          # graph[u] = [(v, w), ...], w >= 0
    dist = {s: 0}
    pq = [(0, s)]
    while pq:
        d, u = heapq.heappop(pq)
        if d > dist.get(u, float("inf")):
            continue                # 이미 더 짧게 확정된 Vertex
        for v, w in graph[u]:
            nd = d + w
            if nd < dist.get(v, float("inf")):
                dist[v] = nd
                heapq.heappush(pq, (nd, v))
    return dist
```

### Bellman-Ford는 어떻게 음수 Edge와 Negative Cycle을 다루나요?
E: Dijkstra처럼 서두르지 않고, 모든 도로를 한 번씩 확인하는 일을 (도시 수 − 1)번 묵묵히 반복합니다. 그래도 더 짧아지는 길이 있다면 돌수록 줄어드는 마법 고리(Negative Cycle)가 있다는 뜻입니다.
A: Bellman-Ford는 모든 Edge를 Relax하는 작업을 V − 1번 반복합니다. Shortest Path는 Edge를 최대 V − 1개 쓰므로 그만큼 반복하면 음수 Edge가 있어도 정답이 나오고, 한 번 더 돌렸을 때 값이 또 줄면 Negative Cycle이 있다고 판단합니다. 시간은 O(VE)로 Dijkstra보다 느립니다.

### Floyd-Warshall은?
E: "1번 도시를 거쳐 가면 더 빠른가?"를 모든 도시 쌍에 대해 확인하고, 다음에는 2번 도시, 3번 도시… 순서로 경유지 후보를 늘려 갑니다.
A: Floyd-Warshall은 모든 Vertex 쌍의 최단 거리를 구하는 DP로, `dist[i][j] = min(dist[i][j], dist[i][k] + dist[k][j])`를 경유지 k = 1…V에 대해 반복합니다. 시간 O(V³), 공간 O(V²)이고 음수 Edge도 다룰 수 있으며, 끝난 뒤 `dist[i][i] < 0`인 Vertex가 있으면 Negative Cycle입니다. Vertex가 수백 개 이하일 때 적합합니다.

### DAG에서는 왜 Topological Sort만으로 Shortest Path를 O(V + E)에 구할 수 있나요?
A: DAG를 Topological Sort 순서로 처리하면 어떤 Vertex에 도착했을 때 그리로 들어오는 모든 Edge가 이미 Relax되어 거리가 확정됩니다. 그래서 Edge를 한 번씩만 Relax하면 되고 음수 Edge가 있어도 O(V + E)입니다. 가중치에 −1을 곱하면 Longest Path(프로젝트 일정의 Critical Path, 임계 경로)도 같은 방법으로 구합니다.

### Dijkstra의 Shortest Path Tree는 MST인가요? (자주 틀리는 문항)
E: Shortest Path Tree는 "우리 집에서 각 친구 집까지 가장 빨리 가는 길 모음", MST는 "모든 집을 잇는 도로를 가장 싸게 까는 방법"입니다. 목표가 다르니 답도 다를 수 있습니다.
A: 아닙니다. Shortest Path Tree는 출발점에서 각 Vertex까지의 거리를 각각 최소화하고, MST는 Tree 전체 Edge 합을 최소화하므로 다를 수 있습니다. 예를 들어 S-A 2, S-B 2, A-B 1인 삼각형에서 S 기준 Shortest Path Tree는 {S-A, S-B}(합 4)이지만 MST는 {A-B, S-A}(합 3)입니다. 또 MST는 출발점과 상관없지만 Shortest Path Tree는 출발점마다 달라집니다.

## MST (Minimum Spanning Tree)

#### MST와 Cut Property
ONE: **MST(최소 신장 트리)**는 모든 Vertex를 **Cycle 없이 연결**하면서 **Edge 가중치 합이 최소**인 Tree예요.
LIKE: 섬 마을들을 모두 다리로 연결하되, 총 공사비가 가장 적게 드는 방법이에요. 빙 도는 다리는 필요 없어요.
STEP:
1. **Spanning Tree**: Graph의 모든 Vertex를 포함하는 Tree예요. Edge는 항상 V − 1개(01번 주제의 Tree 성질).
2. **MST**: 그중 Edge 가중치 합이 가장 작은 것이에요. 연결된 방향 없는 가중치 Graph에서 정의돼요.
3. **Cut Property (컷 성질)**: Vertex들을 아무렇게나 두 편으로 나눴을 때, 두 편을 잇는 Edge 중 가장 가벼운 것은 어떤 MST에 반드시 들어갈 수 있어요.
4. 이유: 그 Edge를 안 쓰는 MST가 있다면, 그 MST에서 두 편을 잇는 다른 (더 무거운) Edge를 빼고 이 가벼운 Edge로 바꾸면 합이 같거나 더 작아지니까요.
5. 이 성질 덕분에 "가장 싼 다리부터 놓는" Greedy가 정답이 돼요. Prim과 Kruskal이 모두 여기에 기대요.
USE: 통신망·전력망·도로망을 최소 비용으로 깔기, Clustering(가장 비싼 Edge 몇 개를 빼면 무리가 나뉨).
END: MST는 "모두를 가장 싸게 잇는 Tree"이고, Cut Property 덕분에 Greedy로 구할 수 있어요.

#### Prim vs Kruskal
ONE: **Prim**은 한 점에서 시작해 **영역을 넓히며** 가장 싼 다리를 붙이고, **Kruskal**은 **전체 다리를 가격순으로** 보면서 Cycle만 안 생기면 놓아요.
LIKE: Prim은 한 마을에서 시작해 "우리 영역에서 밖으로 나가는 가장 싼 다리"를 하나씩 놓아 넓히는 것이고, Kruskal은 전체 다리 후보를 가격순으로 줄 세우고, 이미 연결된 마을끼리가 아니면 차례로 놓는 거예요.
STEP:
1. **Prim**: 아무 Vertex 하나에서 시작해요. 지금 Tree와 바깥을 잇는 Edge 중 가장 가벼운 것을 Min Heap으로 골라 Tree에 붙여요. 모든 Vertex가 들어올 때까지 반복해요. O(E log V).
2. **Kruskal**: 모든 Edge를 가중치 순으로 정렬해요. 가벼운 것부터 보면서, 두 끝점이 아직 다른 그룹이면(Union-Find로 확인) 놓고 합쳐요. 같은 그룹이면 놓으면 Cycle이 생기니 건너뛰어요. O(E log E).
3. 둘 다 Cut Property에 기반한 Greedy예요.
| 구분 | Prim | Kruskal |
| 방식 | 한 점에서 영역 넓히기 | Edge를 가격순으로 |
| 핵심 도구 | Min Heap | 정렬 + Union-Find |
| 유리한 Graph | Edge가 많은 Dense | Edge가 적은 Sparse |
END: 영역을 넓히면 Prim, 싼 Edge부터 고르면 Kruskal. 둘 다 정답이고 Graph 모양에 따라 골라요.

### Minimum Spanning Tree란? Cut Property는?
E: 섬 마을들을 모두 연결하는 다리를 놓되 총 공사비를 가장 적게 드는 방법입니다. 마을들을 아무렇게나 두 편으로 나눌 때, 두 편을 잇는 다리 중 가장 싼 것은 항상 놓아도 손해가 없습니다.
A: MST(최소 신장 트리)는 연결된 Undirected Weighted Graph의 모든 Vertex를 Cycle 없이 잇는 Spanning Tree 중 Edge 가중치 합이 최소인 것이며 Edge는 항상 V − 1개입니다. Cut Property(컷 성질)는 Vertex를 두 집합으로 나눌 때 그 경계를 건너는 Edge 중 가장 가벼운 것은 어떤 MST에 반드시 포함된다는 성질로, Prim과 Kruskal의 정확성 근거입니다. 네트워크 배선, 전력망 설계, Clustering에 씁니다.

### Prim과 Kruskal의 동작·복잡도·차이는?
E: Prim은 한 마을에서 시작해 "우리 동네에서 밖으로 나가는 가장 싼 다리"를 하나씩 놓아 영역을 넓히는 것, Kruskal은 전체 다리 후보를 가격순으로 줄 세우고 Cycle만 안 생기면 차례로 놓는 것입니다.
A: Prim은 한 Vertex에서 시작해 Tree와 바깥을 잇는 최소 Edge를 Min Heap으로 골라 더해 O(E log V)이고, Edge가 많은 Dense Graph에 유리합니다. Kruskal은 모든 Edge를 가중치 순으로 정렬한 뒤 Union-Find로 Cycle 여부를 확인하며 더해 O(E log E)이고, Sparse Graph에 유리합니다. 둘 다 Cut Property에 기반한 Greedy Algorithm입니다.

## Network Flow

#### Max Flow와 Min Cut
ONE: 파이프마다 용량이 있을 때 출발지에서 도착지로 보낼 수 있는 **최대 유량(Max Flow)**은, 흐름을 완전히 끊기 위해 잘라야 하는 **가장 얇은 단면의 용량(Min Cut)**과 정확히 같아요.
LIKE: 수도관망에서 정수장(Source)부터 도시(Sink)까지 초당 최대 몇 리터를 보낼 수 있을까요? 그건 관 몇 개를 잘라 물을 완전히 끊을 때, 잘라야 하는 관들의 용량 합 중 가장 작은 값과 같아요. 가장 좁은 병목이 전체를 정해요.
STEP:
1. **Flow Network**: 방향 Graph이고, Edge마다 **Capacity(용량)**가 있어요. 출발점 **Source**, 도착점 **Sink**.
2. **규칙 ①**: 각 Edge의 Flow는 Capacity를 넘을 수 없어요.
3. **규칙 ②**: 중간 Vertex에서는 들어온 만큼 나가야 해요(Flow Conservation).
4. **Max Flow**: 규칙을 지키며 Source에서 Sink로 보낼 수 있는 최대량이에요.
5. **Cut**: Vertex를 Source 쪽과 Sink 쪽으로 나눈 것이에요. Cut의 용량은 Source 쪽에서 Sink 쪽으로 넘어가는 Edge 용량의 합이에요.
6. **Max-Flow Min-Cut Theorem**: Max Flow의 값 = 모든 Cut 중 가장 작은 용량. 물은 아무리 해도 가장 좁은 단면보다 많이 못 지나가고, 실제로 그만큼은 보낼 수 있어요.
WHY: 이 정리 덕분에 매칭, 배정, 이미지 분할처럼 겉보기에 다른 문제들이 하나의 Algorithm으로 풀려요.
END: 최대로 보낼 수 있는 양 = 가장 얇은 병목의 용량이에요.

#### Ford-Fulkerson과 Residual Graph
ONE: **아직 더 보낼 수 있는 길(Augmenting Path)**을 찾아 흘려보내기를 반복해서 Max Flow를 구해요. **되돌리는 길(역방향 Edge)**을 둬서 예전 선택을 고칠 수 있게 해요.
LIKE: 물을 더 보낼 수 있는 길을 찾아 최대한 흘려보내기를 반복해요. 이때 "취소 길"도 만들어 둬서, 예전에 잘못 보낸 물을 돌려보내고 더 좋은 배치로 바꿀 수 있어요.
STEP:
1. **Residual Graph (잔여 그래프)**: 각 Edge에 "앞으로 더 보낼 수 있는 양"(남은 용량)과 "지금 보낸 만큼 되돌릴 수 있는 양"(역방향)을 표시한 Graph예요.
2. Residual Graph에서 Source → Sink로 가는 경로를 하나 찾아요(**Augmenting Path**).
3. 그 경로에서 가장 작은 남은 용량만큼 Flow를 더해요. Residual Graph도 고쳐요.
4. 더 이상 경로가 없을 때까지 반복해요. 그때의 Flow가 Max Flow예요.
5. **역방향 Edge가 중요한 이유**: 먼저 고른 길이 나빴을 수 있어요. 역방향으로 흘려 "취소"하면 다른 길로 돌릴 수 있어서 최적에 도달해요.
6. 용량이 정수면 O(E × f)(f는 Max Flow 값). 경로를 BFS로 찾는 **Edmonds-Karp**는 O(VE²)로, 용량 크기와 상관없는 시간이 보장돼요.
END: Ford-Fulkerson은 "더 보낼 길 찾아 흘리기"의 반복이고, 역방향 Edge로 실수를 고칠 수 있어요.

#### Bipartite Matching (이분 매칭)
ONE: 두 그룹(예: 지원자와 회사) 사이에서 **겹치지 않게 최대한 많은 짝**을 짓는 문제이고, **Max Flow로 바꿔서** 풀 수 있어요.
LIKE: 지원자와 회사를 짝지을 때, 각자 한 곳만 갈 수 있다면 "용량 1짜리 파이프"로 연결하고 물을 최대한 흘려 보내요. 흐른 물의 양이 최대 짝의 수예요.
STEP:
1. **Bipartite Graph**: Vertex가 두 그룹으로 나뉘고, Edge는 그룹 사이에만 있어요.
2. Source를 만들어 왼쪽 그룹의 모든 Vertex로 용량 1 Edge를 이어요.
3. 왼쪽에서 오른쪽으로 "짝이 될 수 있는" Edge를 용량 1로 이어요.
4. 오른쪽 그룹의 모든 Vertex에서 Sink로 용량 1 Edge를 이어요.
5. Max Flow를 구하면, 그 값이 최대 매칭 수예요. Flow가 1인 가운데 Edge들이 실제 짝이에요.
6. 용량이 정수면 Max Flow도 정수로 존재해서, 각 Edge의 Flow가 딱 0 또는 1로 "짝 지음/안 지음"이 돼요.
USE: 작업자–작업 배정, 학생–동아리 배정, 광고–광고 자리 배정.
END: 매칭 문제는 용량 1짜리 파이프 Network로 바꿔 Max Flow로 풀어요. 처음 보는 문제를 아는 문제로 바꾸는 것, 이게 바로 다음에 배울 Reduction이에요.

### Max-Flow Min-Cut Theorem이란?
E: 수도관망에서 정수장(Source)부터 도시(Sink)까지 초당 최대 몇 리터를 보낼 수 있는지는, 관을 몇 개 잘라 물을 완전히 끊을 때 잘라야 하는 관들의 최소 용량 합과 같습니다. 가장 좁은 병목이 전체를 정합니다.
A: Max Flow(최대 유량) 문제는 Edge마다 Capacity(용량)가 있는 Directed Graph에서 Capacity와 Flow Conservation(들어온 만큼 나감)을 지키며 Source에서 Sink로 보낼 수 있는 최대량을 구합니다. Max-Flow Min-Cut Theorem은 그 Max Flow가 Source와 Sink를 분리하는 Cut들 중 Capacity 합이 가장 작은 Cut의 Capacity와 같다는 정리입니다.

### Ford-Fulkerson과 Residual Graph는?
E: 아직 물을 더 보낼 수 있는 길을 찾아 최대한 흘려보내기를 반복합니다. 역방향 "취소 길"도 두어서, 예전에 잘못 보낸 물을 돌려보내 더 좋은 배치로 바꿀 수 있게 합니다.
A: Ford-Fulkerson은 Residual Graph(잔여 그래프)에서 Source→Sink 경로(Augmenting Path, 증가 경로)를 찾아 그 경로의 최소 남은 Capacity만큼 Flow를 더하기를 경로가 없을 때까지 반복합니다. Residual Graph에는 남은 Capacity만큼의 순방향 Edge와 현재 Flow만큼의 역방향 Edge가 있어 이전 선택을 되돌릴 수 있습니다. Capacity가 정수면 O(E · f)(f는 Max Flow)이고, Augmenting Path를 BFS로 찾는 Edmonds-Karp는 O(VE²)입니다.

### Bipartite Matching(이분 매칭)을 Max Flow로 푸는 법은?
E: 지원자와 회사를 짝지을 때, 각자 한 곳에만 갈 수 있다면 "Capacity 1짜리 파이프"로 연결하고 물을 최대한 흘려 보내면 최대 짝 수가 나옵니다.
A: Source에서 왼쪽 Vertex들로, 왼쪽에서 오른쪽으로(가능한 짝), 오른쪽 Vertex들에서 Sink로 Capacity 1인 Edge를 만들면, Max Flow의 값이 곧 Maximum Matching의 크기입니다. 정수 Capacity에서는 정수 Max Flow가 존재하므로 각 Edge의 Flow 0 또는 1이 그대로 "짝을 지었다/안 지었다"가 됩니다.

## Reduction과 Linear Programming

#### Reduction (환원)
ONE: 처음 보는 문제 A를 **이미 풀 줄 아는 문제 B로 번역**해서 푸는 방법이에요. 반대로 "A가 어려우면 B도 어렵다"를 보이는 데도 써요.
LIKE: 자판기에 만 원권이 안 들어가면, 편의점에서 천 원권으로 바꾼 뒤 자판기를 쓰는 것과 같아요. 문제를 내가 쓸 수 있는 모양으로 바꾸는 거예요.
STEP:
1. A의 입력을 B의 입력으로 바꿔요(변환).
2. B를 풀어요.
3. B의 답을 A의 답으로 다시 바꿔요.
4. 변환이 빠르고 B를 빨리 풀 수 있으면, A도 빨리 풀려요.
5. 거꾸로, A가 어렵다고 알려져 있는데 A를 B로 빠르게 바꿀 수 있다면, B도 최소한 A만큼 어려워요. 그래서 "이 문제는 어렵다(NP-Complete)"를 증명할 때도 Reduction을 써요(08번 주제).
USE: 이분 매칭 → Max Flow, 일정 짜기 → Linear Programming, 스도쿠 → SAT(논리식 만족) 문제로 바꿔 SAT Solver로 풀기.
END: Reduction은 "아는 문제로 번역하기"예요. 쉽게 풀 때도, 어렵다는 걸 증명할 때도 써요.

#### LP (Linear Programming)와 ILP
ONE: **LP**는 1차식 조건들 아래에서 1차식 목표를 최대·최소로 만드는 문제이고 빠르게 풀려요. 변수가 **정수**여야 하는 **ILP**는 일반적으로 매우 어려워요.
LIKE: LP는 "밀가루 2.7kg, 설탕 1.3kg"처럼 재료를 소수점까지 자유롭게 정해 이익을 최대로 하는 문제예요. ILP는 "케이크는 2개 또는 3개만, 2.5개는 안 돼"처럼 정수만 허용하는 문제예요. 정수라는 조건 하나 때문에 조합을 하나하나 따져야 하는 상황이 생겨요.
STEP:
1. **LP**: 변수(예: 제품 A, B를 몇 개 만들지), 제약(재료·시간 한도, 예: 2x + y ≤ 10), 목적함수(예: 이익 3x + 2y를 최대로)가 모두 1차식이에요.
2. 변수가 실수면 다항 시간에 풀 수 있어요(Interior Point Method). 실무에서 많이 쓰는 **Simplex Method**는 이론상 최악은 느리지만 실제로는 매우 빨라요.
3. **ILP**: 변수가 정수여야 해요. 사람 수, 트럭 수, "할까 말까(0/1)" 같은 결정이요.
4. ILP는 일반적으로 **NP-Hard**라서 빠른 Algorithm이 알려져 있지 않아요.
5. 그래서 정수 조건을 잠시 풀어 LP로 근사해를 구하거나(**LP Relaxation**), 가지를 나눠 가며 불가능한 가지를 잘라 내는 **Branch and Bound**로 풀어요.
USE: 생산 계획, 배송 경로, 근무표 짜기, 광고 예산 배분 같은 최적화 문제의 공통 틀이에요.
END: 실수면 LP(빠름), 정수면 ILP(어려움). 정수 조건 하나가 문제를 훨씬 어렵게 만들어요.

### Reduction(환원)이란?
E: 처음 보는 문제를 이미 풀 줄 아는 문제로 "번역"하는 것입니다. 자판기에 만 원권이 안 들어가면 편의점에서 천 원권으로 바꾼 뒤 자판기를 쓰는 것처럼요.
A: Reduction은 문제 A의 입력을 문제 B의 입력으로 바꾸고, B의 해를 다시 A의 해로 돌리는 방법입니다. 변환이 빠르고 B를 빨리 풀 수 있으면 A도 빨리 풀리고, 반대로 A가 어렵다면 B도 어렵다는 것을 보여 줍니다. Bipartite Matching을 Max Flow로, Scheduling을 LP로 푸는 것이 실용적 Reduction이고, NP-Complete 증명에도 같은 개념을 씁니다(08 Theory of Computation).

### LP(Linear Programming)와 ILP(Integer Linear Programming)의 차이는? 왜 ILP는 어려울까요?
E: LP는 "밀가루 2.7kg, 설탕 1.3kg"처럼 재료를 소수점까지 자유롭게 정해 이익을 최대화하는 문제이고, ILP는 "케이크는 2개 또는 3개만, 2.5개는 안 됨"처럼 정수만 허용하는 문제입니다. 정수 제약 하나로 가능한 조합을 하나하나 따져야 하는 상황이 생깁니다.
A: LP는 선형 부등식 Constraint 아래에서 선형 Objective Function(목적함수)을 최대·최소화하는 문제로, 변수가 실수이면 다항 시간(Interior Point Method, 내점법)에 풀리고 실무에서는 Simplex Method도 빠릅니다. ILP는 변수가 정수여야 하는데, 일반적으로 NP-Hard라서 다항 시간 Algorithm이 알려져 있지 않고, 정수 제약을 푼 LP Relaxation으로 근사해를 구하거나 Branch and Bound(분기 한정법)로 풉니다.

## Coding Test 필수 기법

#### Two Pointers와 Sliding Window
ONE: 포인터 두 개를 **한 방향으로만** 움직여서, 이중 반복문 O(n²)을 **O(n)**으로 줄이는 기법이에요.
LIKE: Two Pointers는 책장 양 끝에서 두 사람이 가운데로 걸어오며 찾는 것이고, Sliding Window는 기차 창문을 한 칸씩 밀며 창밖 풍경을 보는 거예요. 새로 보이는 칸 하나를 더하고, 사라지는 칸 하나를 빼면 돼요.
STEP:
1. **Two Pointers (양 끝에서)**: 정렬된 배열에서 합이 x인 두 수 찾기. 왼쪽 포인터는 처음, 오른쪽은 끝에서 시작해요.
2. 합이 x보다 작으면 왼쪽을 한 칸 오른쪽으로(합을 키우기), 크면 오른쪽을 한 칸 왼쪽으로(합을 줄이기). 같으면 찾았어요.
3. 각 포인터가 최대 n번만 움직이니 O(n)이에요.
4. **Sliding Window (같은 방향으로)**: "길이 k인 연속 구간의 최대 합"이면, 처음 k개의 합을 구한 뒤 창문을 한 칸 밀 때마다 새로 들어온 값을 더하고 빠진 값을 빼요. 매번 k개를 다시 더할 필요가 없어요.
5. 창문 크기가 변하는 경우도 있어요. "중복 없는 가장 긴 부분 문자열"은 오른쪽을 늘리다가 중복이 생기면 왼쪽을 줄여요.
```python
def max_sum_k(a, k):
    s = best = sum(a[:k])
    for i in range(k, len(a)):
        s += a[i] - a[i - k]     # 들어온 값 더하고, 빠진 값 빼기
        best = max(best, s)
    return best
```
KEY: 신호: "정렬된 배열에서 짝 찾기"는 Two Pointers, "연속된 부분 배열·부분 문자열"은 Sliding Window를 먼저 떠올려요.
END: 포인터를 되돌리지 않고 한 방향으로만 밀면 O(n²)이 O(n)이 돼요.

#### Backtracking (되돌아가기)
ONE: 가능한 선택을 하나씩 시도하다가 **막히면 직전 선택으로 돌아가** 다른 선택을 해 보는 방법이에요. 핵심은 **답이 될 수 없는 길을 일찍 끊는 것(Pruning)**이에요.
LIKE: 미로에서 갈림길마다 한 길을 골라 가 보고, 막히면 마지막 갈림길로 돌아와 다른 길로 가는 거예요. "이 길은 출구 반대 방향"이라는 걸 일찍 알면 끝까지 안 가 봐도 돼요.
STEP:
1. 답을 한 칸씩 채워 가요(예: N-Queen이면 한 줄에 퀸 하나씩).
2. 각 칸에서 가능한 선택을 하나 골라 다음 칸으로 넘어가요(재귀).
3. 규칙을 어기거나 더 진행할 수 없으면, 방금 선택을 취소하고 다른 선택을 시도해요(Backtrack).
4. 끝까지 채우면 답 하나를 찾은 거예요.
5. **Pruning (가지치기)**: 이미 답이 될 수 없다고 판단되면 그 아래는 아예 보지 않아요. 이게 속도를 결정해요.
6. 최악은 지수 시간(O(2ⁿ), O(n!))이지만, 가지치기를 잘하면 실제로는 훨씬 빨라요.
```python
def subsets(nums):
    res, cur = [], []
    def go(i):
        if i == len(nums):
            res.append(cur[:]); return
        cur.append(nums[i]); go(i + 1)   # 넣는 경우
        cur.pop();           go(i + 1)   # 안 넣는 경우 (되돌리기)
    go(0)
    return res
```
USE: 모든 순열·조합·부분집합 만들기, N-Queen, 스도쿠, 미로 찾기. 신호: 문제가 "가능한 모든 경우"를 요구하고 n이 작을 때(보통 20 이하).
END: Backtracking은 "해 보고, 안 되면 돌아가기"이고, 가지치기를 잘할수록 빨라요.

#### Bitmask와 LCA
ONE: **Bitmask**는 켜짐/꺼짐 여러 개를 **정수 하나의 Bit로** 표현하는 기법이고, **LCA**는 Tree에서 두 Node의 **가장 가까운 공통 조상**을 찾는 기법이에요.
LIKE: Bitmask는 스위치 n개의 켜짐/꺼짐 상태를 숫자 하나로 적어 두는 것이고, LCA는 족보에서 두 사람의 가장 가까운 공통 조상을 찾는 거예요.
STEP:
1. **Bitmask**: 원소가 n개인 집합의 부분집합을 n Bit 정수로 표현해요. i번째 Bit가 1이면 i번 원소가 들어 있어요.
2. `mask | (1 << i)`는 i번 넣기, `mask & (1 << i)`는 i번 있는지 확인, `0`부터 `2ⁿ − 1`까지 돌면 모든 부분집합을 볼 수 있어요.
3. **Bitmask DP**: "어떤 도시들을 방문했는지"를 Bitmask로 상태에 넣어 외판원 문제(TSP)를 O(2ⁿ · n²)에 풀어요. n이 20 정도까지만 가능해요.
4. **LCA**: 두 Node에서 각각 위로 올라가다가 처음 만나는 조상이에요. 두 Node 사이 거리를 구할 때 써요(거리 = 깊이 합 − 2 × LCA 깊이).
5. **Binary Lifting**: 각 Node의 1, 2, 4, 8…번째 위 조상을 미리 저장해 두면(전처리 O(n log n)), 큰 점프부터 해서 질문당 O(log n)에 LCA를 찾아요.
END: 작은 집합은 Bitmask로 숫자 하나에 담고, Tree의 공통 조상은 2의 거듭제곱 점프(Binary Lifting)로 빨리 찾아요.

#### 문제 유형을 알아보는 신호
ONE: Coding Test 문제는 대부분 몇 가지 기법의 변형이에요. 문제 속 **신호(키워드)**를 보고 "어떤 기법의 모양인가"를 먼저 떠올리면 빨리 풀려요.
LIKE: 의사가 증상(열, 기침)을 보고 병의 후보를 떠올리는 것과 같아요. 문제의 "증상"을 보면 써야 할 도구 후보가 좁혀져요.
STEP:
1. 먼저 **입력 크기 n**을 봐요. 목표 Complexity가 정해져요. 대략 n ≤ 20이면 O(2ⁿ)도 가능, n ≤ 수천이면 O(n²), n이 10만~100만이면 O(n log n) 이하.
2. 다음으로 문제 속 신호를 보고 기법 후보를 골라요.
3. 후보 기법으로 작은 예시를 손으로 풀어 보고, 되면 구현해요.
| 문제 속 신호 | 먼저 떠올릴 기법 |
| 정렬된 배열, "찾기" | Binary Search, Two Pointers |
| 연속된 부분 배열·부분 문자열 | Sliding Window, 누적합(Prefix Sum) |
| "본 적 있나", 빈도, 짝 찾기 | Hash Map / Hash Set |
| 상위 k개, 계속 최솟값 필요 | Heap |
| 다음으로 큰 원소, 괄호 짝 | Stack (Monotonic Stack) |
| 연결 관계, 최단 거리, 격자 | BFS / DFS |
| 선후 관계, 의존 순서 | Topological Sort |
| 그룹 합치기, 연결 여부 | Union-Find |
| 모든 조합·순열·부분집합 | Backtracking |
| "경우의 수", "최소 비용", 선택의 연속 | Dynamic Programming |
| 정렬 후 매 단계 최선 선택 | Greedy |
| 접두사, 자동완성 | Trie |
| 공간 O(1), 짝수·홀수, 작은 집합 표현 | Bit 연산 |
KEY: 많이 푸는 것보다 **유형을 알아보는 능력**이 중요해요. 푼 문제는 며칠 뒤 처음부터 다시 풀 수 있는지 확인하세요. 풀이를 외우는 건 소용없어요.
END: 입력 크기로 목표 속도를 정하고, 문제 속 신호로 기법을 고르세요.

#### Coding 면접 풀이 흐름
ONE: 코딩 면접은 정답 맞히기 시험이 아니라 **"이 사람과 함께 문제를 풀면 어떨까"**를 보는 자리예요. 생각을 말로 꺼내며 **확인 → 단순한 방법 → 개선 → 구현 → 검증** 순서로 풀어요.
LIKE: 친구와 함께 퍼즐을 푸는 것과 같아요. 혼자 조용히 맞히는 것보다, "이렇게 해 볼까?" 말하면서 같이 푸는 사람이 더 좋은 파트너예요.
STEP:
1. **문제 확인 (3~5분)**: 입력 범위, 중복 허용, 빈 입력, 정렬 여부를 질문해요. 작은 예시를 직접 만들어 이해가 맞는지 확인해요.
2. **단순한 방법부터 말하기**: 가장 무식한(Brute Force) 해법과 그 Complexity를 먼저 말해요. 출발점이 돼요.
3. **개선하기**: 반복되는 계산, 안 쓰는 정보, 불필요한 작업을 찾아요. 입력 크기로 목표 Complexity를 거꾸로 추정해요.
4. **설계 합의**: 코드를 쓰기 전에 접근법을 설명하고 면접관의 동의를 얻어요.
5. **구현 (15~20분)**: 의미 있는 변수 이름, 작은 보조 함수로 나누기. 막히는 세부는 "이런 함수가 있다고 치고" 넘어간 뒤 나중에 채워요.
6. **검증**: 예시를 코드에 직접 따라 돌려 봐요. 빈 입력, 원소 하나, 최댓값, 중복 같은 경계 사례를 확인해요.
7. **Complexity 정리**: 시간과 공간 Complexity를 말하고, 더 개선할 여지가 있는지 언급해요.
KEY: **막혔을 때**는 예시를 더 크게 만들어 손으로 풀고 그 과정을 Algorithm으로 옮기거나, 조건 하나를 빼고 풀어 보거나, 자료구조를 하나씩 대입해 봐요("Hash를 쓰면? Heap을 쓰면? 정렬하면?"). 그리고 침묵하지 말고 지금 무엇을 생각하는지 말해요. 면접관의 힌트는 감점이 아니라 협업이에요.
END: 확인하고, 단순하게 시작하고, 개선하고, 합의하고, 구현하고, 검증하세요. 이 모든 과정을 소리 내어 말하는 게 핵심이에요.

### Coding Test에 자주 나오는 기법은?
| 기법 | 비유 | 언제 | Complexity |
| Two Pointers | 책장 양 끝에서 두 사람이 가운데로 걸어오며 찾기 | 정렬된 Array에서 합이 x인 쌍 | O(n) |
| Sliding Window | 창문을 한 칸씩 밀며 창밖 보기 | 연속 구간의 최대 합, 중복 없는 최장 부분 문자열 | O(n) |
| Backtracking | 미로에서 막히면 되돌아가기 | N-Queen, Combination·Permutation 생성, 스도쿠 | 최악 지수, Pruning(가지치기)으로 줄임 |
| Bitmask | 스위치 n개의 켜짐/꺼짐으로 Subset 표현 | 모든 Subset 탐색, TSP(외판원 순회) DP | O(2ⁿ · n) 안팎 |
| LCA (Lowest Common Ancestor) | 두 사람의 가장 가까운 공통 조상 찾기 | Tree에서 두 Node 사이 거리 | 전처리 O(n log n), 질의 O(log n) (Binary Lifting) |
A: Two Pointers와 Sliding Window는 이중 반복문 O(n²)을 Pointer를 한 방향으로만 움직여 O(n)으로 줄이는 기법이고, Backtracking은 해가 될 수 없는 가지를 일찍 잘라(Pruning) Brute Force(완전 탐색)를 줄입니다. Bitmask는 n ≤ 20 정도의 집합을 정수 하나로 표현해 Subset DP에 쓰고, LCA는 Binary Lifting으로 2ᵏ번째 조상을 미리 저장해 질의당 O(log n)에 구합니다.

### 문제를 보고 어떤 Algorithm 기법을 쓸지 어떻게 알아보나요?
E: 의사가 증상을 보고 병의 후보를 떠올리듯, 입력 크기와 문제 속 신호(정렬됨, 연속 구간, 최단 거리, 경우의 수 등)를 보고 기법 후보를 좁힙니다.
A: 먼저 입력 크기로 목표 Complexity를 추정합니다(n이 10만 이상이면 O(n log n) 이하). 그다음 신호를 봅니다. 정렬된 배열은 Binary Search·Two Pointers, 연속 구간은 Sliding Window·Prefix Sum, 빈도·짝 찾기는 Hash, 상위 k개는 Heap, 최단 거리·격자는 BFS, 의존 순서는 Topological Sort, 그룹 합치기는 Union-Find, 모든 경우는 Backtracking, 경우의 수·최소 비용은 DP를 떠올리고 작은 예시로 검증합니다.

### Coding 면접에서 문제를 어떤 순서로 풀어 나가야 하나요?
E: 친구와 퍼즐을 풀듯, 생각을 말로 꺼내며 확인 → 쉬운 방법 → 개선 → 합의 → 구현 → 검증 순서로 갑니다.
A: 입력 범위와 예외 상황을 질문해 문제를 확인하고, Brute Force 해법과 Complexity를 먼저 말한 뒤, 반복 계산이나 안 쓰는 정보를 찾아 최적화합니다. 접근법을 설명해 동의를 얻은 다음 읽기 쉬운 코드로 구현하고, 예시와 경계 사례(빈 입력, 원소 하나, 중복)를 직접 따라가며 검증한 뒤 시간·공간 Complexity를 정리합니다. 막히면 침묵하지 말고 생각하는 과정을 말합니다.
