## NLP 개요

#### NLP란? 언어를 숫자로 바꾸는 일
ONE: **NLP(자연어 처리)**는 컴퓨터가 사람의 말과 글을 **숫자로 바꿔 이해하고, 또 만들어 내게** 하는 분야예요. 번역, 검색, 챗봇, 스팸 필터, 음성 비서가 모두 NLP예요.
LIKE: 외국어를 배우는 것과 같아요. 문장을 단어로 끊어 읽고(Tokenization), 단어 뜻을 주변 단어로 익히고(Embedding), 품사와 이름을 구분하고(Sequence Labeling), 다음에 올 말을 예측하는 연습(Language Model)을 엄청나게 많이 하면 결국 글을 쓸 수 있게 돼요.
STEP:
1. **컴퓨터는 숫자만 계산해요.** 그래서 글을 먼저 숫자로 바꿔야 해요.
2. **잘게 나누기**: 문장을 처리 단위(Token)로 끊어요.
3. **숫자로 바꾸기**: 각 Token을 Vector(숫자 목록)로 바꿔요. 뜻이 비슷한 단어는 비슷한 Vector가 되도록 해요.
4. **과제 풀기**: 문장 전체를 분류하거나(스팸/정상, 긍정/부정), 단어마다 이름표를 붙이거나(품사, 사람 이름), 새 글을 만들어요(번역, 요약, 대화).
5. **평가와 책임**: 정답 Label이 일관된지, 성능을 제대로 쟀는지, 특정 집단에 불리하지 않은지 함께 봐요.
END: NLP = 언어를 Token으로 끊고 숫자로 바꿔서, 분류하고 이름표 붙이고 글을 만드는 일이에요.

#### 자연어가 컴퓨터에게 어려운 이유
ONE: 사람의 말은 **모호하고(Ambiguity)**, **표현이 끝없이 다양하고(Variability)**, 대부분의 단어가 **드물게 나오고(Sparsity)**, 뜻이 **문맥과 상식에 크게 기대기** 때문에 어려워요.
LIKE: "나는 망원경으로 남자를 봤다"는 내가 망원경을 들었는지, 남자가 망원경을 들었는지 애매해요. 사람은 상황으로 알아차리지만 컴퓨터는 상황을 몰라요.
STEP:
1. **모호성 - 단어**: "배"는 과일, 선박, 신체 중 무엇일까요?
2. **모호성 - 구조**: 같은 문장이 여러 구조로 해석돼요(망원경 예).
3. **다양성**: "배고파", "출출하다", "뭐 좀 먹을까?"는 비슷한 뜻이에요. 신조어·오타·사투리도 계속 생겨요.
4. **희소성 (Zipf's Law)**: 단어 빈도는 몇몇 단어만 아주 흔하고, 대부분의 단어와 표현은 아주 드물어요. 그래서 학습 데이터에서 한 번도 못 본 표현이 계속 나와요.
5. **문맥·상식·의도**: "참 잘했다"가 칭찬인지 반어인지는 상황을 알아야 해요.
END: 모호하고, 다양하고, 드물고, 문맥에 기대서 어려워요. NLP의 모든 기술은 이 네 가지와 싸우는 방법이에요.

#### NLP의 발전 흐름: 규칙 → 통계 → 신경망 → LLM
ONE: NLP는 **사람이 규칙을 짜던 시대** → **데이터에서 확률을 배우는 시대** → **Neural Network가 표현까지 배우는 시대** → **거대 Pre-trained Model(LLM) 시대**로 발전했어요.
LIKE: 외국어를 배우는 방법의 변화와 같아요. 문법책을 외우던 방식(규칙) → 예문을 많이 보며 "이 단어 다음엔 보통 저 단어가 온다"를 익히는 방식(통계) → 단어 뜻을 느낌으로 익히는 방식(Embedding) → 엄청난 양의 책을 읽고 무엇이든 말할 수 있게 된 방식(LLM)이에요.
STEP:
1. **Rule-Based (~1980년대)**: 사람이 문법·규칙·사전을 만들어요. 정확하지만 규칙을 끝없이 추가해야 해서 확장이 안 돼요. 예: ELIZA.
2. **Statistical (1990~2000년대)**: 말뭉치(Corpus)에서 확률을 추정해요. n-gram, Naive Bayes, HMM, CRF. 하지만 Feature는 사람이 설계했어요.
3. **Neural (2010년대 전반)**: word2vec(2013)이 단어 뜻을 Vector로 배우고, LSTM과 Attention이 문장을 처리했어요.
4. **Transformer + Pre-training (2017년 이후)**: Transformer(2017)로 대규모 병렬 학습이 가능해지고, BERT·GPT(2018)가 라벨 없는 텍스트로 먼저 배운 뒤 과제에 맞추는 방식을 표준으로 만들었어요.
5. **LLM (2020년대)**: 규모를 키운 모델에 지시 따르기 학습(Instruction Tuning)과 사람 피드백 학습(RLHF)을 더하자, Prompt만으로 여러 과제를 풀게 됐어요.
END: 규칙 → 통계 → 신경망 → LLM. 사람이 손으로 만들던 부분이 점점 데이터로 배우는 부분으로 바뀌어 왔어요.

### 자연어가 컴퓨터에게 어려운 이유는?
E: "나는 망원경으로 남자를 봤다"는 내가 망원경을 들었는지, 남자가 망원경을 들었는지 애매합니다. 사람은 상황으로 알아차리지만 컴퓨터는 상황을 모릅니다.
A: 첫째 Ambiguity(모호성)로, 한 단어가 여러 뜻을 갖고(배: 과일·선박·신체) 같은 문장이 여러 구조로 해석됩니다. 둘째 Variability(다양성)로, 같은 뜻을 무수히 다른 말로 표현하고 신조어·오타·사투리가 계속 생깁니다. 셋째 Sparsity(희소성)로, 단어 빈도가 Zipf's Law를 따라 대부분의 단어·문구는 드물게 나타나고, 마지막으로 의미가 문맥·상식·화자의 의도(반어)에 크게 기댑니다.

### Rule-Based → Statistical → Neural → LLM으로 이어진 흐름은?
| 시기 | 방식 | 대표 예 |
| ~1980년대 | 사람이 만든 문법·규칙·사전 (Rule-Based) | ELIZA, 규칙 기반 번역 |
| 1990~2000년대 | Corpus(말뭉치)에서 확률을 추정하는 Statistical Model | n-gram, Naive Bayes, HMM, CRF, Statistical Machine Translation |
| 2010년대 전반 | Word Embedding과 Recurrent Neural Network | word2vec(2013), LSTM seq2seq, Attention |
| 2017년 이후 | Transformer와 Pre-training | Transformer(2017), BERT·GPT(2018) |
| 2020년대 | LLM + Instruction Tuning·Human Feedback | GPT-3, ChatGPT, Open LLM |
A: 사람이 규칙을 짠 시대는 정확하지만 확장이 안 되었고, 통계 시대에는 데이터에서 확률을 배웠지만 Feature를 사람이 설계했으며, Neural Network 시대에는 Embedding으로 표현까지 배웠습니다. Transformer로 대규모 병렬 학습이 가능해지자 Label 없는 텍스트로 Pre-training한 모델을 과제에 맞춰 쓰는 방식이 표준이 되었고, 규모를 키운 LLM은 Prompt만으로 여러 과제를 풀게 되었습니다.

## Text Normalization

#### Tokenization과 Regular Expression
ONE: **Tokenization**은 텍스트를 **처리 단위(Token)로 나누는** 첫 단계예요. **Regular Expression**은 문자열 **패턴을 표현하는 언어**로, 나누기·추출·정제에 써요.
LIKE: 외국어 문장을 읽을 때 먼저 단어마다 빗금을 그어 끊어 읽는 것과 같아요. Regular Expression은 "숫자 3개-숫자 4개-숫자 4개 모양을 모두 찾아라" 같은 검색 주문이에요.
STEP:
1. **기본**: 공백과 문장부호로 나눠요. "I love NLP." → I / love / NLP / .
2. **애매한 결정들**: "don't"는 하나? 둘(do + n't)? "New York"은 한 덩어리? "3.14"의 점은 문장 끝이 아니에요. 이메일·URL·이모지도 따로 다뤄요.
3. **한국어**: "학교에서"처럼 조사가 붙어서, 의미 단위로 쪼개는 **형태소 분석(Morphological Analysis)**이 필요해요. 학교 + 에서.
4. **Regular Expression 예**: `\d{3}-\d{4}-\d{4}`는 "숫자 3개-숫자 4개-숫자 4개" 형태의 전화번호를 찾아요.
5. **어디에 쓰나**: Token 경계 규칙, 날짜·전화번호·이메일 추출, HTML 태그 제거 같은 정제, 간단한 규칙 기반 분류기.
END: Tokenization은 끊어 읽기, Regular Expression은 패턴 찾기 주문이에요.

#### Stemming과 Lemmatization
ONE: 단어의 여러 변형을 **하나로 묶는** 두 방법이에요. **Stemming**은 규칙으로 **끝을 잘라 내고**, **Lemmatization**은 사전으로 **기본형을 찾아요**.
LIKE: Stemming은 가위로 단어 끝부분을 싹둑 자르는 것, Lemmatization은 사전을 찾아 기본형을 적는 거예요.
STEP:
1. **목적**: "study, studies, studying"을 하나로 묶어서 Vocabulary를 줄이고 같은 뜻으로 다뤄요.
2. **Stemming**: "-ing, -es, -ed" 같은 접미사를 규칙으로 잘라요(Porter Stemmer). 빠르지만 "studies → studi"처럼 실제 단어가 아닌 결과가 나오기도 해요.
3. **Lemmatization**: 사전과 품사 정보를 써서 실제 기본형(Lemma)을 찾아요. "studies → study", "better(형용사) → good". 정확하지만 느려요.
4. 요즘 Neural Network 모델은 Subword Tokenization을 써서 이 단계를 생략하는 경우가 많아요.
| 비교 | Stemming | Lemmatization |
| 방법 | 규칙으로 잘라 내기 | 사전 + 품사로 기본형 찾기 |
| studies | studi | study |
| better | better | good (형용사일 때) |
| 속도 | 빠름 | 느림 |
END: 빠르게 자르면 Stemming, 정확하게 사전을 찾으면 Lemmatization이에요.

#### Subword Tokenization (BPE)
ONE: 단어를 **자주 쓰는 조각(Subword)** 단위로 나눠요. 흔한 단어는 한 덩어리로, 드문 단어는 아는 조각들로 쪼개서 **처음 보는 단어도 처리**해요. 대표 방법이 **BPE**예요.
LIKE: 자주 쓰는 단어는 통째로 외우고, 처음 보는 단어는 아는 조각으로 쪼개 읽는 거예요. "unhappiness"를 몰라도 "un + happi + ness"로는 읽을 수 있어요.
STEP:
1. **단어 단위의 문제**: Vocabulary가 수십만 개로 커지고, 처음 보는 단어(OOV, Out-of-Vocabulary)는 처리하지 못해요.
2. **문자 단위의 문제**: 처리할 Sequence가 너무 길어지고, 문자 하나에는 뜻이 거의 없어요.
3. **BPE (Byte Pair Encoding) 학습**: 모든 단어를 문자로 쪼개서 시작해요.
4. Corpus에서 **가장 자주 붙어 나오는 인접 쌍**을 찾아 하나의 새 기호로 합쳐요. 예: "e" + "s" → "es".
5. 정해진 Vocabulary 크기가 될 때까지 합치기를 반복해요.
6. **새 텍스트에 적용**: 배운 합치기 규칙을 같은 순서로 적용해요.
7. **결과**: 흔한 단어는 Token 하나, 드문 단어는 여러 조각이 돼서 OOV가 사라져요.
8. GPT 계열은 Byte 단위에서 시작하는 Byte-Level BPE, BERT는 비슷한 WordPiece를 써요.
END: 흔한 건 통째로, 드문 건 조각으로. Vocabulary 크기와 처리 길이의 균형을 잡아요.

### Tokenization이란? Regular Expression은 어디에 쓰이나요?
A: Tokenization(토큰화)은 텍스트를 단어·Subword·문장부호 같은 처리 단위(Token)로 나누는 것으로, "don't", "New York", "3.14", 이메일·URL·이모지 처리 같은 결정이 들어가고 한국어처럼 조사가 붙는 언어는 Morphological Analysis(형태소 분석)가 필요합니다. Regular Expression은 문자열 Pattern을 기술하는 언어로, Token 경계 규칙, 날짜·전화번호·이메일 추출, 텍스트 정제(Cleaning), 간단한 Rule-Based Classifier에 씁니다.

### Stemming과 Lemmatization의 차이는?
E: Stemming(어간 추출)은 가위로 끝부분을 잘라내는 것, Lemmatization(표제어 추출)은 사전을 찾아 기본형을 적는 것입니다.
A: Stemming은 Porter Stemmer처럼 규칙으로 접미사(Suffix)를 잘라 빠르지만 "studies → studi"처럼 실제 단어가 아닌 결과가 나오기도 합니다. Lemmatization은 사전과 품사(POS) 정보로 "studies → study", "better → good"(형용사)처럼 사전에 있는 기본형(Lemma)을 찾아 더 정확하지만 느립니다. 둘 다 단어 변형을 하나로 묶어 Vocabulary를 줄이려는 목적입니다.

### BPE 같은 Subword Tokenization은 왜 필요하고 어떻게 동작하나요?
E: 자주 쓰는 단어는 통째로 외우고, 처음 보는 단어는 아는 조각으로 쪼개 읽습니다. "unhappiness"를 몰라도 "un + happi + ness"로는 읽을 수 있습니다.
A: 단어 단위는 Vocabulary가 너무 커지고 처음 보는 단어(OOV, Out-of-Vocabulary)를 처리하지 못하며, 문자 단위는 Sequence가 너무 길어집니다. BPE(Byte Pair Encoding)는 문자 단위에서 시작해 Corpus에서 가장 자주 붙어 나오는 인접 쌍을 하나의 새 기호로 합치는(Merge) 일을 정해진 Vocabulary 크기가 될 때까지 반복하고, 새 텍스트에는 배운 Merge를 같은 순서로 적용합니다. 그래서 흔한 단어는 Token 하나, 드문 단어는 여러 조각이 되어 OOV가 사라지며, GPT 계열은 Byte-Level BPE, BERT는 비슷한 WordPiece를 씁니다.

## Text Classification

#### Bag-of-Words와 n-gram Feature
ONE: **Bag-of-Words(BoW)**는 문서를 **단어별 등장 횟수 Vector**로 바꾸는 가장 단순한 표현이에요. **순서를 무시**하는 약점이 있어서, 이어진 단어 묶음(**n-gram**)을 Feature로 추가해요.
LIKE: 문장을 단어 카드로 잘라 가방에 쏟아 넣고 개수만 세는 게 BoW예요. 그러면 "좋지 않다"와 "않다, 좋지"가 같아지니까, 두세 단어를 묶은 카드(n-gram)도 함께 넣어요.
STEP:
1. **Vocabulary 만들기**: 학습 데이터의 모든 단어에 번호를 붙여요.
2. **문서 → Vector**: Vocabulary 크기의 Vector에 각 단어가 몇 번 나왔는지(또는 나왔는지 여부)를 적어요. 대부분이 0인 Sparse Vector예요.
3. **약점**: 순서를 무시해서 "개가 사람을 물었다"와 "사람이 개를 물었다"가 같아져요.
4. **n-gram Feature**: 연속된 n개 단어를 하나의 Feature로 추가해요. Bigram "not good"이 있으면 부정을 잡을 수 있어요.
5. **n-gram의 대가**: n이 커질수록 Feature 수가 폭발하고 대부분이 드물어져요(Sparsity).
END: BoW는 단어 개수 세기, n-gram은 짧은 순서까지 잡는 보완책이에요.

#### Naive Bayes vs Logistic Regression 텍스트 분류
ONE: 텍스트 분류의 두 기본 모델이에요. **Naive Bayes**는 **세기만 해서** 빠르고 데이터가 적을 때 강하고, **Logistic Regression**은 Weight를 학습해서 **데이터가 많을 때 보통 더 정확**해요.
LIKE: Naive Bayes는 스팸 메일과 정상 메일에서 각 단어가 몇 번 나왔는지 장부에 적어 두고 비교하는 회계사예요. Logistic Regression은 단어마다 "스팸 쪽 점수"를 연습 문제로 조금씩 조정해 가는 학생이에요.
STEP:
1. **Naive Bayes 학습**: 세기만 해요. P(Class) = 그 Class 문서 비율. P(단어 | Class) = 그 Class에서 그 단어가 나온 비율(+1 Laplace Smoothing으로 0 방지).
2. **Naive Bayes 예측**: log P(Class) + Σ log P(단어 | Class)가 가장 큰 Class를 골라요.
3. **왜 Log?** 작은 확률을 수백 번 곱하면 컴퓨터에서 0이 돼 버려요(Underflow). Log를 취하면 곱셈이 덧셈이 되고, Log는 항상 증가하는 함수라 가장 큰 Class는 그대로예요.
4. **Logistic Regression**: 단어마다 Weight를 두고 Gradient Descent로 학습해요(14번 주제).
5. **핵심 차이**: Naive Bayes는 "단어들이 서로 독립"이라 가정해서, "San"과 "Francisco"처럼 항상 함께 나오는 단어의 증거를 두 번 세요(Double Counting). Logistic Regression은 두 Weight가 증거를 나눠 가져서 중복을 피해요.
| 비교 | Naive Bayes | Logistic Regression |
| 종류 | Generative | Discriminative |
| 학습 | 세기만 하면 끝 | Gradient Descent |
| 데이터 적을 때 | 강함 | 상대적으로 약함 |
| 상관된 Feature | 중복으로 셈 | Weight를 나눠 가짐 |
END: 빠르고 데이터 적을 땐 Naive Bayes, 데이터 많고 정확도가 중요하면 Logistic Regression이에요.

#### Sentiment Analysis (감성 분석)
ONE: 글이 **긍정인지 부정인지(또는 어떤 감정인지)** 판단하는 과제예요. 단어 사전 → 통계 분류기 → Pre-trained Model 순으로 정확해져요.
LIKE: 영화 리뷰를 읽고 별점을 짐작하는 거예요. "최고", "감동"이 보이면 긍정, "지루", "최악"이 보이면 부정. 하지만 "기대했는데 최고는 아니었다"는 단어만 보면 속아요.
STEP:
1. **사전(Lexicon) 방식**: 긍정·부정 단어 목록으로 점수를 매겨요. 가장 단순해요.
2. **분류기 방식**: 라벨 달린 리뷰로 BoW·n-gram Feature에 Naive Bayes나 Logistic Regression을 학습해요.
3. **요령 ① Binary NB**: 감성에서는 단어가 몇 번 나왔는지보다 **나왔는지 여부**가 중요해서, 횟수를 1로 잘라요.
4. **요령 ② 부정 처리**: "not" 뒤의 단어에 NOT_ 표시를 붙여요. "not good" → "NOT_good"으로, 긍정 단어 good과 구별해요.
5. **Pre-trained Model**: BERT 같은 모델을 Fine-tuning하면 반어와 문맥까지 훨씬 잘 잡아요.
END: 사전 → 분류기 → Pre-trained Model. 부정어와 반어를 잡는 게 핵심이에요.

### Bag-of-Words와 n-gram Feature란?
E: 문장을 단어 카드로 자른 뒤 가방에 쏟아 넣고 개수만 세는 것이 BoW입니다. 그러면 "좋지 않다"와 "않다, 좋지"가 같아지므로, 두세 단어를 묶은 카드(n-gram)도 함께 넣습니다.
A: BoW(Bag-of-Words)는 문서를 Vocabulary 크기의 Vector로 만들고 각 단어의 등장 횟수(또는 유무)를 넣는 표현으로 순서를 무시합니다. n-gram Feature는 연속된 n개 단어(Bigram "not good")를 Feature로 추가해 지역적인 순서와 부정(Negation)을 잡지만, n이 커질수록 차원이 폭발하고 Sparse해집니다.

### Naive Bayes Text Classifier는 어떻게 학습하고 예측하나요? Log Probability를 쓰는 이유는?
A: 학습은 세는 것뿐으로, Prior P(c) = Class c 문서 수 / 전체 문서 수, Likelihood P(w | c) = (count(w, c) + 1) / (Class c의 전체 단어 수 + |V|)(Laplace Smoothing)를 구합니다. 예측은 ĉ = argmax_c [log P(c) + Σᵢ log P(wᵢ | c)]로, 문서의 각 단어 확률을 더해 가장 큰 Class를 고릅니다. 작은 확률을 수백 번 곱하면 Floating-Point Underflow로 0이 되므로 Log를 취해 곱을 합으로 바꾸며, Log는 단조 증가(Monotonic)라 argmax 결과는 같습니다.

### Logistic Regression Classifier와 Naive Bayes의 차이는?
A: Naive Bayes는 P(x | c)P(c)를 모델링하는 Generative Model로 단어들의 Conditional Independence를 가정하고 Count만으로 학습해 빠르고 데이터가 적을 때 강합니다. Logistic Regression은 P(c | x)를 직접 모델링하는 Discriminative Model로 Weight를 Gradient Descent로 학습하며, 서로 상관된 Feature("San"과 "Francisco")의 Weight를 나눠 가져 중복 계산(Double Counting)을 피하고 데이터가 많을 때 보통 더 정확합니다.

### Sentiment Analysis(감성 분석)는 어떻게 하나요?
A: 가장 단순하게는 긍정·부정 단어 사전(Lexicon)으로 점수를 매기고, Label 데이터가 있으면 BoW·n-gram Feature에 Naive Bayes나 Logistic Regression을 학습합니다. 감성에서는 단어가 몇 번 나왔는지보다 나왔는지가 중요해 Count를 1로 자르는 Binary Naive Bayes가 잘 동작하고, "not" 뒤 단어에 NOT_ 접두사를 붙여 Negation을 처리합니다. 요즘은 BERT 같은 Pre-trained Model을 Fine-tuning해 반어·문맥까지 더 잘 잡습니다.

## Data Annotation

#### Labeling Guideline과 일치도
ONE: 모델은 **사람이 붙인 Label을 정답으로** 배우기 때문에, Label이 일관돼야 해요. **Guideline**으로 기준을 통일하고, **Inter-Annotator Agreement**로 사람들끼리 얼마나 일치하는지 재요.
LIKE: 채점 기준표가 없으면 같은 답안도 선생님마다 점수가 달라져요. 모델은 그 들쭉날쭉한 점수를 그대로 배워요. 그래서 기준표를 만들고, 선생님들끼리 얼마나 비슷하게 채점하는지 확인해요.
STEP:
1. **Guideline에 담는 것**: Label의 정의, 애매한 경우의 처리법, 예시와 반례.
2. **다듬는 과정**: 일부를 미리 Labeling → 사람들끼리 불일치한 부분 분석 → Guideline 수정을 반복해요.
3. **Label이 들쭉날쭉하면**: 모델 성능의 상한이 낮아지고, 평가 결과도 믿을 수 없어요.
4. **Inter-Annotator Agreement**: 여러 사람이 같은 데이터에 같은 Label을 붙이는 정도예요. 사람의 일치도가 모델 성능의 현실적인 상한이 돼요.
5. **왜 단순 일치율이 아닌가?** 두 사람이 아무렇게나 찍어도 우연히 일치하는 부분이 있어요. Yes/No를 반반 찍으면 절반은 우연히 맞아요.
6. **Cohen's Kappa**: κ = (pₒ − pₑ) / (1 − pₑ). pₒ는 실제 일치 비율, pₑ는 우연히 일치할 확률이에요. 우연을 빼고 진짜 일치 정도를 재요.
7. **예**: pₒ = 0.8, pₑ = 0.5이면 κ = (0.8 − 0.5) / (1 − 0.5) = 0.6. 1이면 완전 일치, 0이면 우연 수준이에요. 세 명 이상은 Fleiss' Kappa를 써요.
END: 기준표(Guideline)로 통일하고, 우연을 뺀 일치도(Kappa)로 Label 품질을 확인해요.

#### Annotation Bias
ONE: Label을 붙이는 사람의 **관점과 선입견**이 Label에 들어가면, 모델이 그 **Bias를 그대로 배워요**.
LIKE: 특정 지역 사투리를 "무례하다"고 느끼는 채점자들만 모아 채점하면, 그 채점표로 배운 학생도 사투리를 무례하다고 판단하게 돼요.
STEP:
1. **사례**: 특정 방언으로 쓴 글을 더 유해하다고 Labeling한 데이터로 학습한 유해 표현 분류기는, 그 집단의 무해한 글을 더 자주 차단해요.
2. **Annotation Artifact**: Guideline의 빈틈 때문에 특정 단어만 보면 정답을 맞힐 수 있는 표면적 단서가 생기면, 모델은 진짜 이해 대신 그 지름길(Shortcut)을 배워요.
3. **완화**: 다양한 배경의 Annotator 구성, 명확한 Guideline, 집단별로 나눠 평가하기.
END: 사람의 선입견은 Label을 거쳐 모델의 Bias가 돼요. 다양한 사람, 명확한 기준, 집단별 평가로 막아요.

### Labeling Guideline은 왜 중요한가요?
E: 채점 기준표가 없으면 같은 답안도 선생님마다 점수가 달라집니다. 모델은 그 들쭉날쭉한 점수를 그대로 배웁니다.
A: Label은 모델이 배울 정답이자 Evaluation의 기준이므로, Guideline은 Label의 정의, 애매한 경우의 처리법, 예시와 반례를 적어 여러 Annotator가 일관되게 Labeling하도록 합니다. Label이 일관되지 않으면 모델 성능의 상한이 낮아지고 평가 결과도 믿을 수 없으며, 예비 Labeling → 불일치 분석 → Guideline 수정을 반복해 다듬습니다.

### Inter-Annotator Agreement와 Cohen's Kappa(κ)는?
E: 두 사람이 동전을 던져 아무렇게나 Label을 붙여도 절반은 우연히 일치합니다. Kappa는 이 "우연히 맞는 부분"을 빼고 진짜로 의견이 같은 정도를 잽니다.
A: Inter-Annotator Agreement(어노테이터 간 일치도)는 여러 사람이 같은 데이터에 같은 Label을 붙이는 정도로, 과제의 난이도와 Label 품질을 보여 주며 사람의 일치도는 모델 성능의 현실적인 상한이 됩니다. Cohen's Kappa는 두 Annotator에 대해 κ = (pₒ − pₑ) / (1 − pₑ)로, pₒ는 실제 일치 비율, pₑ는 각자의 Label 비율로 계산한 우연 일치 확률입니다. 1이면 완전 일치, 0이면 우연 수준이며, 예를 들어 pₒ = 0.8, pₑ = 0.5이면 κ = 0.6입니다. 세 명 이상은 Fleiss' Kappa를 씁니다.

### Annotation Bias는 모델에 어떤 영향을 주나요?
A: 모델은 Label의 패턴을 그대로 배우므로 Annotator의 배경·관점·선입견이 모델의 Bias가 됩니다. 예를 들어 특정 방언(African American English)으로 쓴 글을 더 유해하다고 Labeling한 데이터로 학습한 Toxicity Classifier는 그 집단의 글을 더 자주 차단하고, Guideline의 빈틈에서 생긴 표면적 단서(특정 단어만 보면 정답이 보이는 Annotation Artifact)를 모델이 지름길(Shortcut)로 배웁니다. 다양한 Annotator 구성, 명확한 Guideline, 집단별 Evaluation으로 완화합니다.

## Language Model

#### Language Model과 n-gram
ONE: **Language Model**은 문장이 **얼마나 자연스러운지 확률로 계산**하거나, **다음 단어를 예측**하는 모델이에요. **n-gram Model**은 **바로 앞 n−1개 단어만** 보고 다음 단어를 맞혀요.
LIKE: 휴대폰 자동완성이 "오늘 저녁에" 다음에 "뭐"를 추천하는 것처럼, 바로 앞 몇 단어만 보고 다음 단어를 맞히는 거예요.
STEP:
1. **문장 확률**: P(오늘, 저녁에, 뭐, 먹지) = P(오늘) × P(저녁에 | 오늘) × P(뭐 | 오늘 저녁에) × …. 앞의 모든 단어를 조건으로 다음 단어 확률을 곱해요.
2. **문제**: 앞의 모든 단어 조합을 다 세는 건 불가능해요. 긴 문장은 Corpus에 한 번도 안 나와요.
3. **Markov Assumption**: "다음 단어는 바로 앞 몇 단어에만 달려 있다"고 단순하게 가정해요(14번 주제의 Markov Chain).
4. **Bigram (n = 2)**: 바로 앞 단어 하나만 봐요. P(먹지 | 뭐) = "뭐 먹지"가 나온 횟수 / "뭐"가 나온 횟수.
5. **Trigram (n = 3)**: 바로 앞 두 단어를 봐요.
6. **n의 Trade-off**: n이 크면 문맥을 더 보지만, 대부분의 n-gram이 한 번도 나오지 않는 희소성 문제가 커져요.
END: Language Model = 다음 단어 확률. n-gram은 "바로 앞 몇 단어만 본다"는 가정으로 세기만 해서 계산해요.

#### Perplexity와 Smoothing
ONE: **Perplexity**는 Language Model이 실제 문장을 보고 **얼마나 헷갈려하는지** 재는 지표예요(낮을수록 좋음). **Smoothing**은 한 번도 못 본 단어 조합에도 **작은 확률을 나눠 줘서** 확률이 0이 되는 걸 막아요.
LIKE: Perplexity 10은 다음 단어를 고를 때마다 "10지선다 문제를 찍는 것만큼 헷갈린다"는 뜻이에요. Smoothing은 "시험에 안 나왔던 문제도 나올 수 있다"며 점수를 조금씩 떼어 두는 거예요.
STEP:
1. **Perplexity**: PP = P(문장)^(−1/N). 문장에 준 확률의 역수를 단어 수로 정규화한 값이에요.
2. 평균 Cross-Entropy의 지수와 같아요. 모델이 실제 문장에 높은 확률을 줄수록 낮아져요.
3. **주의**: Vocabulary와 Tokenization이 같은 모델끼리만 비교할 수 있고, 낮은 Perplexity가 실제 과제 성능을 보장하지는 않아요.
4. **0 확률 문제**: 학습 때 못 본 Bigram이 Test 문장에 하나만 있어도 그 확률이 0이 되고, 곱셈 전체가 0, Perplexity는 무한대가 돼요.
5. **Laplace (Add-1) Smoothing**: 모든 Count에 1을 더해요. 간단하지만 못 본 조합에 너무 많이 떼어 줘요.
6. **더 좋은 방법**: Add-k(1보다 작게 더하기), Backoff(긴 n-gram이 없으면 짧은 걸로), Interpolation(여러 n을 섞기), Kneser-Ney(가장 성능이 좋은 고전 방법).
END: Perplexity는 헷갈림의 정도(낮을수록 좋음), Smoothing은 못 본 조합의 0 확률을 막는 장치예요.

### n-gram Language Model과 Markov Assumption은?
E: 휴대폰 자동완성이 "오늘 저녁에" 다음에 "뭐"를 추천하는 것처럼, 바로 앞 몇 단어만 보고 다음 단어를 맞히는 것입니다.
A: Language Model은 단어열의 확률 P(w₁, …, wₙ) = Π P(wᵢ | w₁, …, wᵢ₋₁)을 계산하는 모델이고, n-gram Model은 Markov Assumption으로 전체 역사 대신 직전 n−1개 단어만 봅니다. Bigram은 P(wᵢ | wᵢ₋₁) = C(wᵢ₋₁ wᵢ) / C(wᵢ₋₁)처럼 Corpus Count의 비율(MLE)로 학습합니다. n이 커지면 문맥을 더 보지만 대부분의 n-gram이 한 번도 나오지 않는 Sparsity 문제가 커집니다.

### Perplexity는 무엇을 재나요?
E: 다음 단어를 고를 때 "평균적으로 몇 개 중 하나를 찍는 것만큼 헷갈리는가"입니다. 10이면 매번 10지선다형 문제를 푸는 정도로 헷갈린다는 뜻입니다.
A: Perplexity는 Test 문장 W에 대해 PP(W) = P(w₁ … wₙ)^(−1/N)로, 모델이 단어열에 준 확률의 역수를 길이로 정규화한 값이며, 평균 Negative Log-Likelihood(Cross-Entropy)의 지수와 같습니다. 낮을수록 모델이 실제 텍스트를 덜 놀라워한다는 뜻이라 좋고, Vocabulary와 Tokenization이 같은 모델끼리만 비교할 수 있으며, 낮은 Perplexity가 실제 과제(Downstream Task) 성능을 보장하지는 않습니다.

### Smoothing(Laplace 등)은 왜 필요한가요?
A: 학습 Corpus에 없던 n-gram은 MLE로 확률이 0이 되고, 문장에 그런 n-gram이 하나만 있어도 문장 확률이 0, Perplexity는 무한대가 됩니다. Smoothing은 본 사건의 확률을 조금 떼어 못 본 사건에 나눠 주는 것으로, Laplace는 P(wᵢ | wᵢ₋₁) = (C(wᵢ₋₁ wᵢ) + 1) / (C(wᵢ₋₁) + V)이며 너무 많이 떼어 주기 때문에 Language Model에서는 Add-k, Backoff, Interpolation, Kneser-Ney가 더 좋습니다.

## Neural Network 기반 NLP

#### Neural Network가 n-gram보다 나은 점
ONE: Neural Network는 단어를 **비슷한 뜻이면 비슷한 Vector**로 표현해서 **처음 보는 조합도 일반화**하고, RNN·LSTM은 **정해진 Window보다 긴 문맥**을 요약해요.
LIKE: n-gram은 "고양이가 잔다"를 외워도 "강아지가 잔다"는 처음 보는 조합이라 몰라요. Neural Network는 고양이와 강아지가 비슷한 Vector라서 "강아지가 잔다"도 자연스럽다고 판단해요.
STEP:
1. **Feedforward로 분류**: 문장의 단어 Embedding들을 평균내서(Pooling) 고정 길이 Vector로 만들고, Hidden Layer → Softmax로 분류해요. 손으로 만든 Feature가 필요 없지만 평균내면 순서는 사라져요.
2. **n-gram의 한계 ①**: 정해진 Window 밖의 문맥은 못 봐요.
3. **n-gram의 한계 ②**: 단어를 서로 무관한 기호로 봐서 비슷한 단어끼리 지식을 나누지 못해요.
4. **n-gram의 한계 ③**: n을 늘리면 세야 할 조합이 기하급수적으로 늘어요.
5. **RNN·LSTM Language Model**: Hidden State로 원리상 전체 앞 문맥을 요약하고, 문맥 길이가 늘어도 Parameter 수는 그대로예요(15번 주제).
6. **한계**: 학습이 느리고(순차 계산), 아주 긴 문맥은 여전히 어려워요. 이 문제를 Transformer가 풀었어요.
END: 비슷한 단어는 비슷한 Vector라 일반화되고, 순환 구조로 긴 문맥을 요약해요.

### Feedforward Neural Network로 텍스트를 분류하는 방법은?
A: 문장을 고정 길이 Vector로 만들어 입력합니다. Word Embedding들을 평균·합산(Pooling)하거나 BoW·TF-IDF Vector를 입력으로 써서 Hidden Layer(ReLU)를 거친 뒤 Softmax Output Layer와 Cross-Entropy로 학습하며, 수작업 Feature 없이 표현을 배우고 비선형 조합을 잡을 수 있지만 Pooling하면 단어 순서는 사라집니다.

### RNN·LSTM Language Model은 n-gram보다 무엇이 나은가요?
A: n-gram은 정해진 Window 밖의 문맥을 보지 못하고 단어를 서로 무관한 기호로 보아 한 번도 못 본 조합을 일반화하지 못하며, n을 늘리면 Parameter가 기하급수적으로 늘어납니다. RNN·LSTM Language Model은 Hidden State로 원리상 전체 역사를 요약하고, 비슷한 단어는 비슷한 Embedding을 갖게 해 "고양이가 잔다"를 본 뒤 "강아지가 잔다"에도 높은 확률을 주며, 문맥 길이가 늘어도 Parameter 수는 그대로입니다. 대신 학습이 느리고, 아주 긴 문맥은 여전히 어렵습니다.

## Word Embedding

#### One-Hot의 한계와 Distributional Hypothesis
ONE: **One-Hot Vector**는 단어마다 칸 하나만 1인 Vector라 **모든 단어가 서로 똑같이 달라서** 뜻을 담지 못해요. **"비슷한 문맥에 나오는 단어는 뜻이 비슷하다"(Distributional Hypothesis)**는 생각이 의미 있는 Vector(Embedding)의 출발점이에요.
LIKE: 처음 보는 단어라도 "사람들이 아침에 뜨겁게 마시고 카페인이 들어 있다"는 문장들에 나오면 커피와 비슷한 거라고 짐작할 수 있어요. 단어의 뜻은 그 단어가 어울리는 친구들(주변 단어)에서 드러나요.
STEP:
1. **One-Hot**: Vocabulary가 5만 개면 5만 차원 Vector에 자기 칸만 1이에요.
2. **문제**: 모든 단어 쌍이 서로 직교(Orthogonal)해서, "호텔"과 "모텔"의 유사도도, "호텔"과 "바나나"의 유사도도 똑같이 0이에요.
3. **Distributional Hypothesis**: "You shall know a word by the company it keeps(단어는 그 친구들을 보면 안다)". 주변 단어 통계가 뜻을 알려 줘요.
4. **Embedding**: 이 생각으로 만든 **조밀한(Dense) 저차원** Vector예요. 보통 수백 차원이고 모든 칸에 의미 있는 숫자가 들어 있어요.
5. 뜻이 비슷한 단어는 Vector 공간에서 가까이 모여요.
| 비교 | One-Hot | Embedding |
| 차원 | Vocabulary 크기 (수만) | 수백 |
| 값 | 거의 0 (Sparse) | 모두 의미 있는 숫자 (Dense) |
| 유사도 | 모든 쌍이 0 | 비슷한 뜻이면 가까움 |
END: One-Hot은 모두 똑같이 달라 뜻이 없어요. 주변 단어로 뜻을 배운 Embedding은 비슷한 단어끼리 가까워요.

#### TF-IDF와 PPMI: 중요한 단어 찾기
ONE: **TF-IDF**는 **이 문서에서는 자주 나오지만 다른 문서에는 드문** 단어에 높은 점수를 줘요. **PPMI**는 두 단어가 **우연보다 얼마나 자주 함께 나오는지** 재요.
LIKE: 축구 기사에서 "골", "선수"는 자주 나오고 다른 기사에는 드무니 이 기사를 잘 설명하는 단어예요(TF-IDF 높음). "그리고", "있다"는 어느 기사에나 나오니 점수가 낮아요.
STEP:
1. **TF (Term Frequency)**: 이 문서 안에서 단어가 나온 횟수예요. 많을수록 중요해요.
2. **IDF (Inverse Document Frequency)**: log(전체 문서 수 / 그 단어가 나온 문서 수). 적은 문서에만 나올수록 커요.
3. **TF-IDF = TF × IDF**: "the", "그리고" 같은 흔한 단어는 낮추고, 문서를 특징짓는 단어는 높여요. 검색 엔진과 문서 분류의 고전 기법이에요.
4. **PMI (Pointwise Mutual Information)**: log₂ [P(w, c) / (P(w)P(c))]. 두 단어가 함께 나올 확률이 따로따로일 때보다 몇 배인지예요(14번 주제의 Lift와 같은 아이디어).
5. **PPMI**: PMI의 음수는 믿기 어려워서 0으로 잘라요.
6. PPMI는 드문 단어를 과대평가하는 경향이 있어서, 문맥 확률을 0.75제곱해 보정해요.
END: TF-IDF는 "이 문서만의 단어", PPMI는 "우연보다 자주 함께하는 단어"를 찾아요.

#### Word2Vec과 GloVe
ONE: **Word2Vec**은 **주변 단어 맞히기 퀴즈**를 풀면서 단어 Vector를 배우고, **GloVe**는 **전체 Corpus의 동시 등장 횟수 표**에서 Vector를 배워요.
LIKE: Skip-gram은 단어 하나를 보고 주변에 올 친구들을 맞히는 퀴즈, CBOW는 친구들을 보고 가운데 빈칸을 맞히는 퀴즈예요. Negative Sampling은 퀴즈를 "이 둘은 진짜 친구인가, 아무나 뽑은 남인가"만 맞히는 쉬운 O/X 문제로 바꾼 거예요.
STEP:
1. **아이디어**: 예측 퀴즈를 잘 풀도록 학습하면, 그 과정에서 얻은 Weight가 단어의 뜻을 담은 Vector가 돼요.
2. **Skip-gram**: 중심 단어 → 주변 단어 예측.
3. **CBOW (Continuous Bag-of-Words)**: 주변 단어들 → 중심 단어 예측.
4. **문제**: 매번 Vocabulary 전체(수만 개)에 대해 Softmax를 계산하면 너무 비싸요.
5. **Negative Sampling**: 진짜 (단어, 주변 단어) 쌍은 1, 무작위로 뽑은 가짜 쌍 k개는 0으로 구분하는 작은 이진 분류로 바꿔서 학습이 훨씬 빨라져요.
6. **GloVe**: 먼저 Corpus 전체에서 "단어 A와 B가 함께 나온 횟수" 표를 만들어요. 그다음 두 Vector의 Dot Product가 그 횟수의 Log에 가까워지도록 학습해요.
7. **차이**: Word2Vec은 지역 Window를 훑으며 예측(Prediction-Based), GloVe는 전역 통계를 직접 사용(Count-Based). 실제 성능은 과제에 따라 비슷해요.
END: Word2Vec은 주변 단어 퀴즈로, GloVe는 동시 등장 횟수 표로 단어 뜻을 Vector에 담아요.

#### Cosine Similarity와 Word Analogy
ONE: 두 단어 Vector가 얼마나 비슷한지는 **방향이 얼마나 같은지(Cosine Similarity)**로 재요. Embedding 공간에서는 **관계가 방향으로** 나타나기도 해서 **king − man + woman ≈ queen** 같은 계산이 돼요.
LIKE: 두 사람이 같은 방향을 가리키고 있으면 팔 길이가 달라도 "같은 곳을 가리킨다"고 해요. Cosine Similarity는 Vector의 길이가 아니라 가리키는 방향을 비교해요.
STEP:
1. **Cosine Similarity**: cosθ = a·b / (‖a‖‖b‖). 1이면 같은 방향, 0이면 무관, −1이면 반대예요.
2. **왜 길이를 무시?** 흔한 단어는 Vector가 길어지는 경향이 있어서, 길이를 빼야 뜻만 비교할 수 있어요.
3. **Analogy**: "man → king"의 차이 방향이 "woman → queen"의 차이 방향과 비슷해요.
4. 그래서 vec(king) − vec(man) + vec(woman)에 가장 가까운 Vector를 찾으면(입력 단어 제외) queen이 나와요.
5. **주의**: 일부 관계에서만 잘 되고, "입력 단어 제외" 규칙에 기대는 부분이 있어요.
END: 방향이 같으면 비슷한 뜻이고, 관계도 방향으로 나타날 수 있어요.

#### Static vs Contextual Embedding
ONE: **Static Embedding**(word2vec, GloVe)은 단어마다 **Vector가 딱 하나**라 다의어를 구분 못 해요. **Contextual Embedding**(BERT 등)은 **문장마다 다른 Vector**를 만들어요.
LIKE: Static Embedding은 사전에 뜻을 하나만 적어 둔 거라 "배를 타다"와 "배를 먹는다"의 배가 같아져요. Contextual Embedding은 문장을 읽을 때마다 그 문장에 맞는 뜻을 새로 만들어 줘요.
STEP:
1. **Static**: 학습이 끝나면 "배"의 Vector는 하나로 고정돼요. 과일·선박·신체의 뜻이 한 Vector에 섞여요(Polysemy 문제).
2. **Contextual**: 문장 전체를 모델(ELMo, BERT)에 통과시켜서, 같은 "배"라도 문맥에 따라 다른 Vector를 만들어요.
3. **장점**: 다의어를 구분하고, 훨씬 정확해요.
4. **단점**: 단어마다 표를 찾기만 하면 되는 Static과 달리, 매번 모델 전체를 돌려야 해서 비싸요.
END: 단어당 하나면 Static, 문장마다 새로 만들면 Contextual. Contextual이 정확하지만 비싸요.

#### Embedding 속 사회적 Bias
ONE: Embedding은 학습 텍스트의 **고정관념까지 배워요**. 단어 집합 사이의 유사도 차이로 **측정**하고, 지우기만으로는 충분하지 않아 **실제 과제에서 다시 평가**해야 해요.
LIKE: 옛날 신문만 읽고 자란 사람은 "간호사는 여자, 엔지니어는 남자"라는 고정관념을 배울 수 있어요. Embedding도 읽은 글의 편견을 그대로 배워요.
STEP:
1. **사례**: "man : computer programmer :: woman : homemaker" 같은 Analogy 결과가 보고됐어요.
2. **WEAT로 측정**: 대상 단어 집합(남성·여성 이름)과 속성 단어 집합(경력·가족)의 Cosine Similarity 차이를 비교해요.
3. **Gender Direction으로 측정**: he − she 방향에 직업 단어들을 투영해서 한쪽으로 치우쳤는지 봐요.
4. **Debiasing의 한계**: Gender Direction을 지우면 겉으로 보이는 지표는 줄지만, Bias가 다른 형태로 남는다는 연구가 있어요.
5. 그래서 실제 과제(Downstream Task)에서 집단별로 다시 평가해야 해요.
END: Embedding은 글 속 편견을 배워요. 측정하고, 지우는 것만 믿지 말고 실제 과제에서 다시 확인해요.

### One-Hot Vector의 한계와 Distributional Hypothesis는?
E: 처음 보는 단어도 "사람들이 아침에 뜨겁게 마시고 카페인이 들어 있다"는 문장들에 나오면 커피와 비슷한 것이라고 짐작합니다. 단어의 뜻은 그 단어가 어울리는 친구들(주변 단어)에서 드러납니다.
A: One-Hot Vector는 Vocabulary 크기만큼 수만 차원에 거의 0인 Sparse Vector이고, 모든 단어 쌍이 Orthogonal해 "호텔"과 "모텔"의 유사도도 "호텔"과 "바나나"의 유사도도 0이라 의미를 담지 못합니다. Distributional Hypothesis(분포 가설)는 비슷한 문맥에 나타나는 단어는 비슷한 뜻을 갖는다는 가설(Harris, Firth: "You shall know a word by the company it keeps")로, 주변 단어 통계로 조밀한(Dense) 저차원 Vector(Embedding)를 만드는 모든 방법의 바탕입니다.

### TF-IDF와 PPMI는 단어의 중요도를 어떻게 재나요?
A: TF-IDF는 한 문서 안에서 자주 나오는(TF, Term Frequency) 동시에 전체 문서 중 적은 문서에만 나오는(IDF = log(N/df), Inverse Document Frequency) 단어에 높은 가중치를 주어 "the" 같은 흔한 단어를 낮추고 문서를 특징짓는 단어를 높입니다. PPMI(Positive Pointwise Mutual Information)는 단어 w와 문맥 c가 우연보다 얼마나 자주 함께 나오는지를 PMI = log₂ [P(w, c) / (P(w)P(c))]로 재고 음수는 0으로 자른 값으로, Word-Context Co-occurrence Matrix를 만들 때 쓰이며 드문 단어를 과대평가하는 경향이 있어 문맥 확률을 α = 0.75 거듭제곱으로 보정합니다.

### Word2Vec(Skip-gram, CBOW)과 Negative Sampling은?
E: Skip-gram은 단어 하나를 보고 주변에 올 친구들을 맞히는 퀴즈, CBOW는 친구들을 보고 가운데 빈칸을 맞히는 퀴즈입니다. Negative Sampling은 "이 둘은 진짜 친구인가, 아무나 뽑은 남인가"만 맞히게 해 퀴즈를 쉬운 O/X 문제로 바꾼 것입니다.
A: Word2Vec은 예측 과제를 풀면서 얻은 Weight를 단어 Vector로 쓰는 방법으로, Skip-gram은 중심 단어로 주변 단어를, CBOW(Continuous Bag-of-Words)는 주변 단어들로 중심 단어를 예측합니다. 매번 Vocabulary 전체에 대한 Softmax는 비싸기 때문에, Negative Sampling은 실제 (단어, 문맥) 쌍은 1, 빈도의 0.75제곱 분포에서 뽑은 k개의 가짜 쌍은 0으로 구분하는 Logistic Regression 문제로 바꿔 학습을 크게 빠르게 합니다.

### GloVe는 Word2Vec과 무엇이 다른가요?
A: Word2Vec은 Corpus를 훑으며 지역 Window 안의 예측 문제로 학습하는 Prediction-Based 방법이고, GloVe는 Corpus 전체의 Word-Word Co-occurrence 횟수 Matrix를 먼저 만든 뒤 두 단어 Vector의 Dot Product가 Co-occurrence 횟수의 Log에 가까워지도록(Weighted Least Squares) 학습하는 Count-Based 방법입니다. 전역(Global) 통계를 직접 쓴다는 점이 다르고, 실제 성능은 과제에 따라 비슷합니다.

### Cosine Similarity와 Word Analogy(king − man + woman ≈ queen)는?
A: 두 단어 Vector의 유사도는 길이 영향을 없앤 Cosine Similarity cosθ = a·b / (‖a‖‖b‖)로 잽니다(빈도가 높은 단어는 Vector가 길어지는 경향이 있음). Embedding Space에서는 관계가 방향으로 나타나는 경우가 있어, vec(king) − vec(man) + vec(woman)에 가장 가까운 Vector(입력 단어 제외)를 찾으면 queen이 나옵니다. 다만 이런 Analogy는 일부 관계에서만 잘 되고 입력 단어를 제외하는 규칙에 기대는 부분이 있습니다.

### Static Embedding과 Contextual Embedding(BERT 등)의 차이는?
E: Static Embedding은 사전에 뜻을 하나만 적어 둔 것이라 "배를 타다"와 "배를 먹는다"의 배가 같아집니다. Contextual Embedding은 문장을 읽을 때마다 뜻을 새로 만들어 줍니다.
A: word2vec·GloVe 같은 Static Embedding(정적 임베딩)은 단어 종류당 Vector가 하나라 다의어(Polysemy)를 구분하지 못하고, ELMo·BERT 같은 Contextual Embedding(문맥 임베딩)은 문장 전체를 모델에 통과시켜 Token마다 문맥에 따라 다른 Vector를 만듭니다. Contextual Embedding이 훨씬 정확하지만 모델 전체를 돌려야 해 비용이 큽니다.

### Embedding에 담긴 사회적 Bias는 어떻게 측정하나요?
A: Embedding은 학습 텍스트의 고정관념도 배워, "man : computer programmer :: woman : homemaker" 같은 Analogy 결과가 보고되었습니다. 측정에는 Target 단어 집합(예: 남성·여성 이름)과 Attribute 단어 집합(예: 경력·가족)의 Cosine Similarity 차이를 비교하는 WEAT(Word Embedding Association Test), Gender Direction(he − she)으로 직업 단어를 투영하는 방법이 있습니다. Gender Direction을 제거하는 Debiasing은 표면적 지표는 줄여도 Bias가 다른 형태로 남는다는 연구가 있어, Downstream Task에서 집단별로 다시 평가해야 합니다.

## Evaluation과 Fairness

#### NLP 평가와 통계적 유의성
ONE: 양성이 드문 NLP 과제(스팸, 혐오 표현)는 **Precision·Recall·F1**로 평가해요. 두 모델의 점수 차이가 **우연이 아닌지**는 **Paired Bootstrap** 같은 검정으로 확인해요.
LIKE: Test 문제를 무작위로 다시 뽑아 수천 번 시험을 다시 봤는데도 B가 A를 거의 항상 이긴다면 실력 차이라고 볼 수 있어요. 가끔만 이기면 운일 수 있어요.
STEP:
1. **Precision**: 양성이라고 한 것 중 맞은 비율. **Recall**: 실제 양성 중 찾아낸 비율. **F1**: 둘의 조화평균(14번 주제).
2. **Macro Average**: Class별 점수를 똑같이 평균해서 작은 Class 성능이 드러나요.
3. **Micro Average**: 모든 결정을 합쳐 계산해서 큰 Class에 좌우돼요.
4. **유의성 문제**: Test Set에서 B가 A보다 1점 높아도, 다른 Test Set이었다면 뒤집힐 수 있어요.
5. **Paired Test**: 같은 Test Set에서 비교하니 짝지어진(Paired) 검정을 써요.
6. **Paired Bootstrap Test**: Test Set을 복원 추출해 가상의 Test Set을 수천 개 만들고, 점수 차이가 우연히 그만큼 클 확률(p-value)을 구해요(13번 주제).
7. **그 밖에**: Permutation Test, McNemar's Test. 여러 Seed로 학습해 편차를 보고하는 것도 중요해요.
END: 드문 양성은 Precision·Recall·F1으로, 차이가 진짜인지는 Paired Bootstrap으로 확인해요.

#### NLP의 Bias와 Fairness
ONE: NLP 모델은 **특정 방언·정체성 단어·성별**에 불리하게 동작할 수 있어요. **집단별 평가**로 측정하고, 데이터 보강·Guideline 개선·**문서화**로 대응해요.
LIKE: 번역기가 성별 구분 없는 언어의 문장을 "그는 의사, 그녀는 간호사"로 번역한다면, 원문에 없던 고정관념을 끼워 넣은 거예요.
STEP:
1. **사례 ① 유해 표현 분류**: 특정 방언이나 정체성 단어가 들어간 무해한 문장을 유해하다고 판정해요.
2. **사례 ② 번역**: 성별 없는 대명사를 직업에 따라 he/she로 고정관념대로 번역해요.
3. **사례 ③ 상호참조(Coreference)**: 직업에 따라 대명사를 다른 성별에 연결해요.
4. **측정**: 집단별로 나눈 평가 데이터로 성능을 비교해요.
5. **Counterfactual Augmentation**: 문장의 성별 단어를 바꿔 넣은 데이터를 추가해서 모델이 성별에 따라 다르게 판단하지 않게 해요.
6. **문서화**: Model Card(모델의 용도·한계·평가 결과)와 Datasheet(데이터의 출처·구성)로 한계를 기록해요.
END: 집단별로 나눠 재고, 바꿔 넣은 데이터로 보강하고, 한계를 문서로 남겨요.

### NLP Classification 평가에서 Precision·Recall·F1과 Macro·Micro Average는?
A: Precision(정밀도)은 모델이 양성이라고 한 것 중 맞은 비율, Recall(재현율)은 실제 양성 중 찾아낸 비율, F1은 둘의 Harmonic Mean이며, 스팸·혐오 표현처럼 양성이 드문 과제에서 Accuracy보다 중요합니다. Multi-Class에서 Macro Average는 Class별 점수를 똑같이 평균해 작은 Class의 성능을 드러내고, Micro Average는 모든 결정을 모아 계산해 큰 Class에 좌우됩니다(14 Machine Learning 참고).

### 두 모델의 차이가 우연인지 어떻게 확인하나요?
E: Test 문제를 무작위로 다시 뽑아 수천 번 시험을 다시 봤는데도 B가 A를 거의 항상 이긴다면 실력 차이라고 봅니다.
A: 같은 Test Set에서 두 모델을 비교하므로 Paired(짝지어진) Test를 씁니다. Paired Bootstrap Test는 Test Set을 복원 추출해 수천 개의 가상 Test Set을 만들고 점수 차이가 우연히 그만큼 커질 확률로 p-value를 구하며, Approximate Randomization(Permutation) Test나 McNemar's Test도 씁니다. 여러 Seed로 학습해 편차를 보고하는 것도 중요합니다.

### NLP 모델의 Bias와 Fairness 문제 사례와 대응은?
A: Toxicity Classifier가 특정 방언이나 정체성 단어("gay", "Muslim")가 들어간 무해한 문장을 유해하다고 판정하거나, 성별 구분 없는 대명사를 번역할 때 "he is a doctor, she is a nurse"처럼 고정관념을 넣거나, Coreference(상호참조) 모델이 직업에 따라 성별을 다르게 연결하는 사례가 있습니다. 집단별로 나눈 Evaluation Set으로 측정하고, Data Augmentation·Counterfactual Augmentation(성별 단어 바꿔 넣기), Guideline 개선, Model Card·Datasheet로 한계를 문서화하는 방식으로 대응합니다.

## Sequence Labeling

#### POS Tagging · NER · BIO Tagging
ONE: **Sequence Labeling**은 문장의 **단어마다 이름표**를 붙이는 과제예요. **POS Tagging**은 품사, **NER**은 사람·회사·장소 같은 이름을 찾아요. 여러 단어짜리 이름은 **BIO Tagging**으로 표시해요.
LIKE: 문장의 단어마다 색연필로 이름표를 붙이는 일이에요. POS Tagging은 "명사·동사·형용사" 이름표, NER은 "사람·회사·장소" 이름표예요.
STEP:
1. **POS (Part-of-Speech) Tagging**: The/한정사 cat/명사 sleeps/동사.
2. **NER (Named Entity Recognition)**: 사람(PER), 조직(ORG), 장소(LOC) 같은 Entity의 **범위**를 찾아 종류를 붙여요.
3. **문제**: "New York"처럼 여러 단어로 된 Entity를 단어 단위 Label로 어떻게 표시할까요?
4. **BIO Tagging**: **B** = Entity의 시작(Begin), **I** = Entity의 내부(Inside), **O** = Entity 밖(Outside).
5. **예**: "Jane Villanueva of United Airlines" → B-PER I-PER O B-ORG I-ORG.
6. **예**: "I flew to New York" → O O O B-LOC I-LOC.
END: 단어마다 이름표를 붙이고, 여러 단어짜리 이름은 B(시작)·I(안)·O(밖)로 표시해요.

#### HMM: 숨은 상태와 관측
ONE: **HMM(Hidden Markov Model)**은 **볼 수 없는 숨은 상태**(품사)가 Markov Chain을 따라 바뀌고, 각 상태가 **보이는 관측값**(단어)을 내놓는다고 보는 모델이에요.
LIKE: 친구의 기분(숨은 상태)은 볼 수 없고 보내는 이모티콘(관측)만 보여요. 기분은 어제 기분에 따라 바뀌고(Transition), 각 기분일 때 어떤 이모티콘을 보낼지 경향이 있어요(Emission). 이모티콘들만 보고 그날그날의 기분을 추측하는 거예요.
STEP:
1. **Hidden State**: 품사 Tag. 문장에 적혀 있지 않아서 직접 볼 수 없어요.
2. **Observation**: 실제 단어. 볼 수 있어요.
3. **Transition Probability** P(다음 Tag | 이전 Tag): 한정사(the) 뒤에는 명사가 자주 와요.
4. **Emission Probability** P(단어 | Tag): 명사일 때 "cat"이 나올 확률.
5. **학습**: 품사가 달린 Corpus에서 세기만 하면 돼요. "한정사 다음 명사"가 몇 번, "명사일 때 cat"이 몇 번.
6. **예측**: 단어들이 주어지면 가장 그럴듯한 Tag 열을 찾아요(Viterbi).
END: 숨은 상태는 Transition으로 이어지고, 각 상태는 Emission으로 단어를 내놓아요.

#### Viterbi Algorithm과 CRF
ONE: **Viterbi**는 가능한 Tag 열 중 **가장 확률이 높은 것**을 Dynamic Programming으로 빠르게 찾아요. **CRF**는 HMM과 달리 **다양한 Feature를 자유롭게 쓰는** Discriminative 모델이에요.
LIKE: 여러 갈림길이 있는 길에서 최단 경로를 찾을 때, 매 갈림길마다 "여기까지 오는 가장 좋은 길"만 기억해 두면 모든 경로를 다 비교할 필요가 없어요.
STEP:
1. **모든 경로 보기**: Tag가 N개, 문장 길이가 T면 가능한 Tag 열이 Nᵀ개라 불가능해요.
2. **핵심 관찰**: "시점 t에 Tag s로 끝나는 최선의 경로"는 "시점 t−1의 각 Tag까지의 최선 경로"에 Transition·Emission 확률을 곱한 것 중 최댓값이에요(Optimal Substructure).
3. 같은 부분 문제가 계속 재사용되니 **Dynamic Programming**이에요(07번 주제).
4. 표를 채우면서 "어디서 왔는지" 화살표(Backpointer)를 남기고, 끝에서 거꾸로 따라가 경로를 복원해요.
5. **복잡도**: 각 시점(T)마다 각 Tag(N)에 대해 이전 Tag N개를 비교하니 **O(N²T)**예요.
6. **CRF (Conditional Random Field)**: HMM은 "현재 단어는 현재 Tag에만 달려 있다"는 강한 가정을 둬요. CRF는 P(Tag 열 | 단어 열)을 직접 모델링해서 대문자 여부, 접미사, 앞뒤 단어 같은 서로 겹치는 Feature를 자유롭게 써요. 보통 더 정확해요.
7. CRF도 예측(Decoding)은 Viterbi를 쓰고, 학습은 더 무거워요. Neural Network 위에 CRF를 얹은 BiLSTM-CRF도 쓰였어요.
END: Viterbi는 "여기까지의 최선"만 기억해 O(N²T)로 풀고, CRF는 더 많은 Feature를 쓰는 HMM의 발전형이에요.

### POS Tagging과 NER(Named Entity Recognition)이란? BIO Tagging은?
E: 문장의 단어마다 색연필로 이름표를 붙이는 일입니다. POS Tagging은 "명사·동사·형용사", NER은 "사람·회사·장소" 이름표입니다.
A: POS(Part-of-Speech) Tagging(품사 태깅)은 각 Token에 품사를 붙이는 과제이고, NER(개체명 인식)은 문장에서 사람(PER)·조직(ORG)·장소(LOC) 같은 Entity의 범위(Span)를 찾아 종류를 붙이는 과제입니다. 여러 단어로 된 Entity를 Token 단위 Label로 바꾸기 위해 BIO Tagging을 쓰는데, B는 Entity의 시작(Begin), I는 Entity의 내부(Inside), O는 Entity 밖(Outside)이며 "Jane Villanueva of United Airlines"는 B-PER I-PER O B-ORG I-ORG가 됩니다.

### HMM(Hidden Markov Model)의 Transition Probability와 Emission Probability는?
E: 친구의 기분(숨은 상태)은 볼 수 없고 보내는 이모티콘(관측)만 보입니다. 기분은 어제 기분에 따라 바뀌고(Transition), 각 기분에서 어떤 이모티콘을 보낼지가 정해져 있습니다(Emission).
A: HMM은 관측할 수 없는 Hidden State(품사 Tag)가 Markov Chain을 따라 바뀌고 각 State가 관측값(단어)을 내놓는다고 보는 Generative Model입니다. Transition Probability(전이 확률) P(tᵢ | tᵢ₋₁)는 이전 Tag에서 다음 Tag로 갈 확률(한정사 뒤에는 명사가 자주 옴), Emission Probability(방출 확률) P(wᵢ | tᵢ)는 그 Tag일 때 그 단어가 나올 확률이며, 둘 다 Tagging된 Corpus의 Count로 추정합니다.

### Viterbi Algorithm은 왜 Dynamic Programming이고, 복잡도는?
A: Viterbi는 가장 확률이 높은 Tag 열을 찾는 Algorithm으로, 시점 t에 State s로 끝나는 최선의 경로는 시점 t−1의 각 State까지의 최선 경로에 Transition·Emission 확률을 곱한 것 중 최댓값이라는 Optimal Substructure가 있고 같은 Subproblem이 계속 재사용되므로 Dynamic Programming입니다(07 Algorithm 참고). 표에 값을 채우고 Backpointer(역추적 포인터)로 경로를 복원하며, Tag가 N개, 문장 길이가 T이면 모든 경로를 보는 O(Nᵀ) 대신 O(N²T)입니다.

### CRF는 HMM과 무엇이 다른가요?
A: HMM은 P(단어, Tag)를 모델링하는 Generative Model이라 현재 단어는 현재 Tag에만 달린다는 강한 가정을 두지만, (Linear-Chain) CRF(Conditional Random Field)는 P(Tag 열 | 단어 열)을 직접 모델링하는 Discriminative Model이라 대문자 여부·접미사·앞뒤 단어 같은 서로 겹치는 Feature를 자유롭게 쓸 수 있고 보통 더 정확합니다. Decoding은 여전히 Viterbi를 쓰고, 학습은 Forward-Backward Algorithm으로 Gradient를 구해 더 무겁습니다. Neural Network 시대에는 BiLSTM-CRF처럼 Neural Network 출력 위에 CRF를 얹기도 합니다.

## Transformer와 LLM

#### BERT와 GPT: 빈칸 채우기 vs 이어 쓰기
ONE: **BERT**는 Transformer **Encoder**로 문장 **양쪽을 다 보며 빈칸을 맞혀** 이해에 강하고, **GPT**는 **Decoder**로 **앞부분만 보고 다음 단어를 이어 써서** 생성에 강해요.
LIKE: BERT는 빈칸 채우기 문제를 푸는 독자라 빈칸 앞뒤를 모두 봐요. GPT는 이어 쓰기를 하는 작가라 지금까지 쓴 앞부분만 보고 다음 단어를 써요.
STEP:
1. **BERT 구조**: Transformer Encoder만 써요. 모든 Token이 앞뒤 모든 Token을 봐요(Bidirectional).
2. **BERT 학습 (MLM)**: Token의 약 15%를 가리고 맞혀요. "나는 [MASK]에 갔다" → 학교.
3. **BERT의 강점**: 문장 분류, NER, 검색 같은 **이해** 과제.
4. **GPT 구조**: Transformer Decoder만 써요. 각 Token은 **자기 앞의 Token만** 봐요(Causal Attention). 뒤를 보면 정답을 미리 보는 셈이라 가려요.
5. **GPT 학습**: 다음 Token 예측(Next Token Prediction). "나는 학교에" → 갔다.
6. **GPT의 강점**: 텍스트 **생성**. 규모를 키우면 Prompt만으로 다양한 과제를 풀어서 현재 LLM의 주류 구조예요.
7. **Encoder-Decoder**: 둘 다 쓰는 T5, 원래 Transformer는 번역·요약에 써요.
| 비교 | BERT | GPT |
| 구조 | Encoder | Decoder |
| 보는 방향 | 양방향 | 앞쪽만 (Causal) |
| 학습 목표 | 가린 Token 맞히기 (MLM) | 다음 Token 예측 |
| 강점 | 이해 (분류, NER, 검색) | 생성 (대화, 글쓰기) |
END: 양쪽을 보는 BERT는 이해, 앞만 보고 이어 쓰는 GPT는 생성에 강해요.

#### LLM은 어떻게 글을 쓰나: Next Token과 Sampling
ONE: LLM은 **다음 Token의 확률 분포**를 계산하고, 거기서 **하나를 골라 붙이고**, 그걸 다시 입력에 넣어 **반복**하며 글을 써요. 어떻게 고르느냐(**Sampling**)에 따라 글의 성격이 달라져요.
LIKE: 끝말잇기처럼 한 단어씩 이어 가는데, 매번 "다음에 올 만한 단어 후보와 그 확률표"를 보고 하나를 골라요. 항상 1등만 고르면 무난하지만 단조롭고, 가끔 2~3등도 고르면 더 다양하지만 엉뚱해질 수 있어요.
STEP:
1. **입력**: Prompt를 Token으로 나눠 모델에 넣어요.
2. **확률 계산**: 모델이 Vocabulary 전체에 대해 다음 Token의 확률(Softmax)을 내요.
3. **고르기 (Decoding)**: 가장 확률이 높은 Token만 고르면 **Greedy**, 확률에 따라 무작위로 뽑으면 **Sampling**이에요.
4. **반복**: 고른 Token을 입력 끝에 붙이고 다시 2번으로. 끝 Token이 나오거나 길이 제한까지 반복해요(Autoregressive).
5. **Temperature**: 점수(Logit)를 T로 나눈 뒤 Softmax해요. T < 1이면 1등에 더 몰려 안정적이고, T > 1이면 고르게 퍼져 다양하지만 엉뚱해질 수 있어요.
6. **Top-k / Top-p**: 확률 상위 k개, 또는 누적 확률 p까지의 후보 안에서만 뽑아서 아주 엉뚱한 Token을 막아요.
7. **KV Cache**: 앞 Token들의 Key·Value를 저장해 두고 재사용해서, 매 Token마다 처음부터 다시 계산하지 않아요(15번 주제).
KEY: LLM은 "사실을 찾아보는" 게 아니라 "그럴듯한 다음 Token을 고르는" 방식이라, 모르는 것도 유창하게 지어낼 수 있어요. 이게 Hallucination의 근본 원인이에요.
END: 확률표를 계산하고, 하나 고르고, 붙이고, 반복. Temperature와 Top-p가 안정성과 다양성의 균형을 정해요.

#### Pre-training · Fine-tuning · Prompting
ONE: LLM은 **라벨 없는 대량 텍스트로 일반 지식을 먼저 배우고(Pre-training)**, **적은 데이터로 특정 용도에 맞추고(Fine-tuning)**, 사용할 때는 **입력에 지시와 예시를 넣어(Prompting)** 원하는 동작을 끌어내요.
LIKE: 외국어로 된 책을 수만 권 읽어 언어 감각을 익히고(Pre-training), 통역사 실무 교육을 따로 받고(Fine-tuning), 실제 일할 때는 "이 문서를 존댓말로 요약해 주세요, 예시는 이렇습니다"라는 요청서(Prompt)를 받는 거예요.
STEP:
1. **Pre-training**: 다음 Token 예측이나 가린 Token 맞히기 같은 Self-Supervised 목표로 웹·책 텍스트를 학습해요. 사람이 정답을 붙일 필요가 없어 엄청난 양으로 배울 수 있어요.
2. **Fine-tuning**: 작은 라벨 데이터로 추가 학습해 특정 과제에 맞춰요.
3. **Instruction Tuning**: "지시 → 좋은 응답" 쌍으로 학습해서 지시를 따르는 모델로 만들어요.
4. **RLHF**: 사람이 여러 응답 중 더 좋은 것을 고른 데이터로 보상 모델을 만들고, 강화 학습으로 사람이 선호하는 응답을 하도록 맞춰요(14번 주제).
5. **Prompting**: Weight를 바꾸지 않고 입력만 바꿔요. 예시 없이 지시만 하면 **Zero-Shot**, 예시 몇 개를 보여 주면 **Few-Shot**(In-Context Learning)이에요.
6. **효율적 Fine-tuning**: 거대 모델 전체를 고치는 대신 LoRA처럼 작은 추가 Parameter만 학습해요.
END: 많이 읽고(Pre-training), 실무 교육을 받고(Fine-tuning), 요청서를 받아 일해요(Prompting).

#### Hallucination과 RAG
ONE: **Hallucination**은 LLM이 **유창하지만 사실이 아닌** 내용을 만들어 내는 현상이에요. **RAG**는 질문과 관련된 **자료를 먼저 찾아서 Prompt에 넣고** 그걸 근거로 답하게 해서 줄여요.
LIKE: Hallucination은 기억에만 의존하는 학생이 모르는 문제에도 그럴듯한 답을 지어내는 거예요. RAG는 오픈북 시험처럼 관련 자료를 찾아 펼쳐 놓고 답하게 하는 거예요.
STEP:
1. **Hallucination의 원인**: 다음 Token 예측은 "사실"이 아니라 "그럴듯함"을 학습해요. 학습 데이터에 없거나 오래된 지식에도 답하려고 해요.
2. **RAG 1단계 - 준비**: 문서들을 조각내 Embedding Vector로 바꿔 Vector DB에 저장해요.
3. **RAG 2단계 - 검색 (Retrieval)**: 질문도 Vector로 바꿔 가장 비슷한 문서 조각을 찾아요(Vector Search). 단어 일치 기반의 BM25를 함께 쓰기도 해요.
4. **RAG 3단계 - 생성 (Generation)**: 찾은 문서를 Prompt에 넣고 "이 자료를 근거로 답하라"고 해요(Grounding).
5. **장점**: 최신 정보·사내 문서를 반영하고, 출처를 보여 줄 수 있어요. 모델을 다시 학습하지 않아도 돼요.
6. **한계**: 검색이 틀리거나 모델이 문서를 잘못 읽으면 여전히 틀려요.
7. **보완 장치**: 검색 품질 평가, 출처 인용(Citation), 근거가 없으면 "모른다"고 답하게 하기.
END: 기억에만 기대면 지어내요. 자료를 찾아 펼쳐 놓고 답하게 하는 RAG로 근거 있는 답을 만들어요.

### BERT(Encoder)와 GPT(Decoder)의 차이는?
E: BERT는 빈칸 채우기 문제를 푸는 독자라 빈칸 양쪽을 모두 보고, GPT는 이어 쓰기를 하는 작가라 지금까지 쓴 앞부분만 보고 다음 단어를 씁니다.
A: BERT는 Transformer Encoder만 쓰고 Bidirectional(양방향) Attention으로 문장 전체를 보며, Token 일부(약 15%)를 가리고 맞히는 MLM(Masked Language Modeling)으로 Pre-training해 Classification·NER·Search 같은 이해 과제에 강합니다. GPT는 Decoder만 쓰고 Mask로 앞 Token만 보는 Causal Attention으로 다음 Token을 예측(Next Token Prediction)하며 학습해 텍스트 Generation에 강하고, 규모를 키우면 Prompt만으로 다양한 과제를 풀 수 있어 현재 LLM의 주류 구조입니다. Encoder-Decoder를 모두 쓰는 T5·원래 Transformer는 번역·요약에 쓰입니다.

### Pre-training과 Fine-tuning, Prompting이란?
A: Pre-training(사전 학습)은 Label 없는 대규모 텍스트로 Next Token Prediction·Mask 예측 같은 Self-Supervised 목표를 학습해 언어 일반 지식을 얻는 단계이고, Fine-tuning은 그 모델을 작은 Label 데이터로 추가 학습해 특정 과제에 맞추는 단계입니다(Instruction Tuning·RLHF로 대화형 모델을 만드는 것도 포함). Prompting은 Weight를 바꾸지 않고 입력에 지시문과 예시를 넣어 원하는 동작을 끌어내는 것으로, 예시 없이는 Zero-Shot, 몇 개를 보여 주면 Few-Shot(In-Context Learning)이라고 합니다.

### RAG(Retrieval-Augmented Generation)와 Hallucination은?
E: Hallucination(환각)은 기억에만 의존하는 학생이 모르는 문제에도 그럴듯한 답을 지어 내는 것이고, RAG는 오픈북 시험처럼 관련 자료를 찾아 펼쳐 놓고 답하게 하는 것입니다.
A: Hallucination은 LLM이 유창하지만 사실이 아니거나 근거가 없는 내용을 생성하는 현상으로, Next Token Prediction이 "그럴듯함"을 학습하고 학습 데이터에 없거나 오래된 지식에도 답하려 하기 때문에 생깁니다. RAG는 질문과 관련된 문서를 Embedding 기반 Vector Search나 BM25로 찾아 Prompt에 넣고 그 내용을 근거(Grounding)로 답하게 해 최신·사내 지식을 반영하고 출처를 제시할 수 있게 합니다. 단, Retrieval이 틀리거나 모델이 문서를 잘못 읽으면 여전히 틀릴 수 있어 Retrieval 품질 평가, 출처 인용(Citation), 모르면 모른다고 답하기 같은 장치를 함께 씁니다.

### LLM은 어떻게 텍스트를 생성하나요? Temperature와 Top-p는?
E: 끝말잇기처럼 한 단어씩 이어 가는데, 매번 "다음에 올 만한 단어와 확률표"를 보고 하나를 고릅니다. Temperature를 낮추면 1등만 고르는 모범생, 높이면 가끔 엉뚱한 단어도 고르는 자유로운 작가가 됩니다.
A: LLM은 Autoregressive 방식으로, 입력 Token열에 대해 다음 Token의 확률 분포를 Softmax로 계산하고 하나를 선택해 입력 끝에 붙이는 과정을 종료 Token이나 길이 제한까지 반복합니다. 가장 확률이 높은 Token만 고르면 Greedy Decoding, 분포에서 뽑으면 Sampling이며, Temperature T는 Logit을 T로 나눠 T < 1이면 분포를 뾰족하게(안정적), T > 1이면 평평하게(다양함) 만듭니다. Top-k는 상위 k개, Top-p(Nucleus Sampling)는 누적 확률 p까지의 후보 안에서만 Sampling해 엉뚱한 Token을 막고, 이전 Token의 Key·Value를 저장하는 KV Cache로 반복 계산을 줄입니다.

## QUIZ

? 사전과 품사 정보를 써서 "studies"를 "study"로, "better"를 "good"으로 바꾸는 것은?
- Stemming
- Lemmatization
- Tokenization
- BPE
= B
! 사전에 있는 기본형을 찾는 것이 Lemmatization입니다. Stemming은 규칙으로 잘라 "studi"가 되고 better를 good으로 바꾸지 못합니다.

? Test 문장에 학습 때 본 적 없는 Bigram이 있어 문장 확률이 0이 되었습니다. 필요한 것은?
- 더 큰 n
- Lemmatization
- One-Hot Encoding
- Smoothing
= D
! Smoothing은 못 본 사건에도 작은 확률을 나눠 줍니다. n을 키우면 못 본 n-gram이 오히려 늘어납니다.

? 같은 Test Set에서 Language Model A의 Perplexity는 80, B는 120입니다(같은 Vocabulary). 옳은 것은?
- A가 Test 텍스트에 더 높은 확률을 준다
- B가 더 좋은 모델이다
- A가 모든 Downstream Task에서 더 좋다
- 둘은 비교할 수 없다
= A
! Perplexity는 확률의 역수를 정규화한 값이라 낮을수록 Test 텍스트에 높은 확률을 줍니다. 하지만 Downstream Task 성능까지 보장하지는 않습니다.

? 두 Annotator의 실제 일치 비율이 0.8, 우연 일치 확률이 0.5일 때 Cohen's Kappa는?
- 0.3
- 0.4
- 0.6
- 0.8
= C
! κ = (0.8 − 0.5) / (1 − 0.5) = 0.6입니다.

? BIO Tagging에서 "I flew to New York"의 "New"에 붙는 Tag는? (York는 I-LOC)
- O
- I-LOC
- B-PER
- B-LOC
= D
! Entity의 첫 Token은 B-, 이어지는 Token은 I-이므로 New는 B-LOC, York는 I-LOC입니다.

? Tag N개, 문장 길이 T일 때 Viterbi Algorithm의 Time Complexity는?
- O(Nᵀ)
- O(N²T)
- O(NT²)
- O(T log N)
= B
! 각 시점(T)마다 각 State(N)에 대해 이전 State N개를 비교하므로 O(N²T)입니다. O(Nᵀ)는 모든 경로를 전부 보는 경우입니다.

? GPT류 모델의 Pre-training 목표에 대한 설명으로 옳은 것은?
- 앞 Token만 보고 다음 Token을 예측한다
- 문장 양쪽을 보고 가려진 Token을 맞힌다
- Label된 감성 데이터로만 학습한다
- Term-Document Matrix를 SVD한다
= A
! GPT는 Causal Attention으로 다음 Token을 예측합니다. B는 BERT의 MLM, D는 LSA입니다.

? "강둑(bank)에 앉았다"와 "은행(bank)에 갔다"의 bank를 서로 다른 Vector로 표현하려면?
- One-Hot Vector
- word2vec
- BERT 같은 Contextual Embedding
- TF-IDF
= C
! word2vec·One-Hot·TF-IDF는 단어마다 하나의 표현만 갖고, Contextual Embedding은 문장에 따라 다른 Vector를 만듭니다.

? LLM이 다음 Token을 고를 때 Temperature를 0.2처럼 낮추면?
- 분포가 평평해져 더 다양한 Token이 나온다
- 분포가 뾰족해져 확률이 높은 Token이 더 자주 선택된다
- 모델의 Weight가 바뀐다
- Vocabulary 크기가 줄어든다
= B
! Logit을 T로 나누므로 T < 1이면 점수 차이가 커져 분포가 뾰족해집니다. Weight나 Vocabulary는 바뀌지 않습니다.
