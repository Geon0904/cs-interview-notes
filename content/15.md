@one Deep Learning은 Linear Transformation과 비선형 Activation Function을 여러 Layer 쌓은 Neural Network를 Backpropagation과 Gradient Descent로 학습해 원시 데이터에서 Representation을 자동으로 배우며, 데이터 구조에 맞는 Architecture(이미지는 CNN, Sequence는 RNN·Transformer)와 Regularization·Normalization Layer·좋은 Optimizer로 깊은 망을 안정적으로 학습합니다.

## 기본 개념

#### Deep Learning이란? 특징까지 스스로 배우기
ONE: **Deep Learning**은 **여러 층(Layer)**으로 된 Neural Network가 원본 데이터에서 **특징(Feature)까지 스스로 배우는** Machine Learning이에요.
LIKE: 조립 공장을 떠올려 보세요. 원자재(픽셀)가 첫 공정에서 "선"이 되고, 다음 공정에서 "모양", 그다음 "눈·귀", 마지막 공정에서 "고양이"라는 완성품이 돼요. 각 공정이 무엇을 할지는 사람이 정하지 않고 공장이 스스로 익혀요.
STEP:
1. **전통적 ML**: 사람이 Feature를 골라 줘요. "귀가 뾰족한가? 수염이 있나?" 그다음 모델이 판단해요.
2. 그런데 사진·소리·글처럼 **정리되지 않은 데이터(Unstructured Data)**는 좋은 Feature를 사람이 만들기 너무 어려워요.
3. **Deep Learning**: 픽셀을 그대로 넣으면, 앞쪽 Layer는 단순한 특징(선, 색)을, 뒤쪽 Layer는 복잡한 특징(물체의 부분, 물체)을 배워요. 이걸 **Representation Learning**이라고 해요.
4. **Neuron 하나가 하는 일**: 입력마다 Weight를 곱해 더하고(Weighted Sum), Bias를 더한 뒤, Activation Function을 통과시켜요.
5. **Layer**: Neuron 여러 개가 나란히 있는 한 층. 입력층 → 숨은 층(Hidden Layer) 여러 개 → 출력층.
6. **"Deep"**: Hidden Layer가 여러 개라는 뜻이에요.
PRO: 사진·음성·텍스트에서 압도적인 성능, Feature를 사람이 만들 필요가 적어요.
CON: 데이터와 계산(GPU)이 많이 필요하고, 왜 그렇게 판단했는지 해석이 어려워요.
END: Deep Learning = 여러 공정을 거치며 특징까지 스스로 배우는 Neural Network예요.

#### Perceptron과 XOR 문제
ONE: **Perceptron**은 입력의 가중합으로 **직선 하나**를 그어 둘로 나누는 가장 단순한 Neuron이에요. 직선 하나로는 **XOR**을 풀 수 없어서, 층을 쌓은 **MLP**가 필요해요.
LIKE: 바둑판 네 칸에 왼쪽 위·오른쪽 아래는 흰 돌, 오른쪽 위·왼쪽 아래는 검은 돌이 있다고 해 봐요. 자 하나를 어떻게 대도 흰 돌과 검은 돌을 가를 수 없어요. 자 두 개를 쓰면 가를 수 있어요.
STEP:
1. **Perceptron**: 입력 × Weight를 더하고 Bias를 더해, 0보다 크면 1, 아니면 0을 내요.
2. 이 규칙은 결국 **직선(고차원에서는 평면) 하나**로 공간을 둘로 나누는 거예요.
3. **AND, OR**: 직선 하나로 나눌 수 있어서 Perceptron이 풀어요.
4. **XOR**: 두 입력이 다를 때만 1. (0,1)과 (1,0)이 1, (0,0)과 (1,1)이 0이라 대각선끼리 같아서 직선 하나로 못 나눠요(Not Linearly Separable).
5. **MLP (Multi-Layer Perceptron)**: 중간에 Hidden Layer를 두면, 첫 층이 직선 두 개를 긋고 다음 층이 그 결과를 조합해서 XOR을 풀어요. Hidden Neuron 2개면 충분해요.
6. 이 한계가 1969년에 지적되면서 Neural Network 연구가 한동안 침체됐고, 다층망을 학습시키는 Backpropagation이 널리 알려지면서(1986) 다시 살아났어요.
END: 직선 하나(Perceptron)로 못 푸는 문제는 층을 쌓아(MLP) 풀어요.

#### Non-Linearity: 왜 Activation Function이 필요한가
ONE: Layer 사이에 **비선형 함수(Activation Function)**가 없으면, 아무리 많이 쌓아도 **Layer 하나와 똑같아요**. 비선형이 있어야 깊이가 의미를 가져요.
LIKE: 확대·회전 복사기를 100대 이어 붙여도 결과는 "한 번 확대·회전"한 것과 같아요. 중간에 종이를 접거나 자르는 기계(비선형)가 있어야 새로운 모양이 만들어져요.
STEP:
1. **Linear (선형)**: 입력을 상수배하고 더하는 것만 하는 변환이에요. Wx + b.
2. Linear를 두 번 하면 W₂(W₁x) = (W₂W₁)x로, Matrix 하나를 곱한 것과 같아요.
3. 그래서 Linear Layer만 100개 쌓으면 Linear Layer 1개와 표현력이 같아요.
4. **Activation Function**: 각 Neuron의 출력에 비선형 함수(ReLU 등)를 씌워요. 이게 "종이 접기" 역할이에요.
5. **Universal Approximation Theorem**: 비선형 Activation이 있는 Hidden Layer 하나짜리 Network도 Neuron이 충분하면 연속 함수를 원하는 정확도로 근사할 수 있어요.
6. **ReLU로 곡선 만들기**: ReLU 하나는 "한 번 꺾인 직선"이에요. 꺾이는 위치와 기울기가 다른 ReLU를 많이 더하면 꺾은선이 촘촘해져 곡선에 가까워져요. 짧은 빨대를 이어 원을 만드는 것과 같아요.
KEY: 이 정리는 "그런 Weight가 존재한다"는 뜻이지, 학습으로 찾을 수 있다거나 Neuron이 몇 개면 된다는 보장은 아니에요. 실제로는 넓게 하나보다 **깊게 여러 층** 쌓는 쪽이 훨씬 효율적이에요.
END: 비선형이 없으면 깊어도 직선 하나. Activation Function이 Network에 곡선을 그릴 힘을 줘요.

#### Bias의 역할
ONE: **Bias**는 Neuron의 가중합에 더하는 상수예요. Neuron이 반응하는 **기준점을 옮겨** 줘요.
LIKE: y = ax만 있으면 모든 직선이 원점을 지나야 해요. y = ax + b의 b가 있어야 직선을 위아래로 옮겨 원하는 곳에 놓을 수 있어요.
STEP:
1. Neuron: z = w₁x₁ + w₂x₂ + … + **b**.
2. b가 없으면 입력이 모두 0일 때 z도 항상 0이에요.
3. 경계선 wᵀx = 0도 항상 원점을 지나야 해서 표현력이 줄어요.
4. b가 있으면 "얼마나 쉽게 켜질지(Threshold)"를 Neuron마다 학습할 수 있어요.
5. 바로 뒤에 Batch Normalization이 있으면, BN의 β가 같은 역할을 해서 Bias를 생략하기도 해요.
END: Weight는 기울기, Bias는 위치. Bias 덕분에 경계선을 원하는 곳에 놓을 수 있어요.

### Deep Learning은 무엇인가요? Machine Learning과의 차이는?
E: 전통적 Machine Learning에서는 사람이 "고양이는 귀가 뾰족하고 수염이 있다"처럼 특징을 골라 주어야 했지만, Deep Learning은 사진 픽셀만 주면 선 → 모양 → 귀·눈 → 고양이 순서로 특징을 스스로 만들어 냅니다.
A: Deep Learning은 여러 Layer의 Artificial Neural Network로 입력에서 출력까지의 Representation(표현)을 단계적으로 학습하는 Machine Learning의 한 분야입니다. 전통적 ML이 사람이 만든 Feature에 크게 의존하는 반면 Deep Learning은 Feature Extraction까지 함께 학습(Representation Learning)해 이미지·음성·텍스트 같은 Unstructured Data에 강하며, 대신 더 많은 데이터와 연산이 필요하고 해석이 어렵습니다.

### Perceptron과 MLP는? Perceptron이 XOR을 못 푸는 이유는?
E: XOR은 바둑판 네 칸에서 대각선끼리 같은 색인 모양입니다. 자 하나(직선)로는 두 색을 가를 수 없고, 자 두 개를 써야 합니다.
A: Perceptron은 입력의 Weighted Sum에 Bias를 더해 Step Function으로 0/1을 내는 Linear Classifier라 Decision Boundary가 직선(Hyperplane) 하나이고, XOR은 직선 하나로 나눌 수 없는(Not Linearly Separable) 문제입니다. MLP(Multi-Layer Perceptron)는 비선형 Activation을 가진 Hidden Layer를 두어 입력 공간을 Linearly Separable한 공간으로 바꾸므로, Hidden Neuron 2개만으로도 XOR을 풀 수 있습니다.

### Non-Linearity의 의미와 필요성은?
E: 확대·회전 복사기를 백 대 이어 붙여도 결국 "한 번 확대·회전"한 것과 같습니다. 중간에 종이를 접거나 자르는 기계(Non-Linear)를 넣어야 새로운 모양이 나옵니다.
A: Non-Linearity(비선형)는 출력이 입력의 상수배·합으로 표현되지 않는다는 뜻입니다. Activation Function 없이 Linear Layer만 쌓으면 W₂(W₁x) = (W₂W₁)x처럼 아무리 깊어도 Linear Layer 하나와 같아지므로, Layer 사이에 ReLU 같은 비선형 함수를 넣어야 깊이가 의미를 갖고 복잡한 함수를 표현할 수 있습니다.

### ReLU로 어떻게 곡선 함수를 근사하나요? (Universal Approximation Theorem)
E: 짧은 빨대를 많이 이어 붙이면 원도 그릴 수 있습니다. ReLU 하나는 "꺾인 직선" 하나이고, 이를 여러 개 더하면 꺾인 점이 많은 꺾은선이 되어 곡선에 점점 가까워집니다.
A: ReLU Network는 Piecewise Linear Function(조각별 선형 함수)이고, 위치와 기울기가 다른 ReLU들을 더하면 원하는 곳에서 꺾이는 꺾은선을 만들 수 있어 Neuron을 늘릴수록 곡선을 더 정밀하게 따라갈 수 있습니다. Universal Approximation Theorem(보편 근사 정리)은 다항식이 아닌 Activation Function(ReLU 포함)을 쓴 Hidden Layer 하나짜리 Network가 Neuron만 충분하면 유계 구간의 연속 함수를 원하는 정확도로 근사할 수 있다는 정리입니다. 다만 "그런 Weight가 존재한다"는 뜻일 뿐 필요한 Neuron 수나 학습으로 찾을 수 있는지는 보장하지 않으며, 실제로는 깊게 쌓는 쪽이 훨씬 적은 Neuron으로 효율적입니다.

### Bias는 왜 있는 걸까?
E: y = ax만 있으면 모든 직선이 원점을 지나야 합니다. y = ax + b의 b가 있어야 직선을 위아래로 옮길 수 있습니다.
A: Bias(편향)는 Neuron의 Weighted Sum에 더하는 상수로, Activation이 일어나는 기준점(Threshold)을 옮겨 줍니다. Bias가 없으면 Decision Boundary가 wᵀx = 0으로 항상 원점을 지나야 하고 입력이 0일 때 출력이 고정되어 표현력이 줄어듭니다. (다만 바로 뒤에 BN이 있으면 BN의 β가 같은 역할을 해서 Bias를 생략하기도 합니다.)

## Activation Function과 Loss Function

#### Loss Function: 얼마나 틀렸는지 숫자 하나로
ONE: **Loss Function**은 모델의 예측이 정답과 **얼마나 다른지**를 숫자 하나로 나타내요. 학습은 이 숫자를 **줄이는 과정**이에요.
LIKE: 공장 출고 검사에서 불량 점수를 매기는 거예요. 불량 점수가 높으면 공정을 고치고, 낮아질 때까지 반복해요.
STEP:
1. **Regression (숫자 예측)**: **MSE** = 오차 제곱의 평균. 큰 오차에 큰 벌점.
2. **Classification (범주 예측)**: **Cross-Entropy** = −log(정답 Class에 준 확률). 정답에 확률 0.9를 주면 벌점 약 0.1, 0.01을 주면 약 4.6으로, 틀리게 확신할수록 벌점이 크게 늘어요.
3. **Loss vs Cost**: 보통 샘플 하나의 오차를 Loss, 전체 평균(+ Regularization)을 Cost라고 불러요. 실무에서는 섞어 써요.
4. **왜 Classification에 MSE를 안 쓸까?** Sigmoid·Softmax와 MSE를 같이 쓰면 확신에 차서 틀릴 때 Gradient가 오히려 작아져 학습이 느려요. Cross-Entropy는 그때 Gradient가 커서 빨리 고쳐져요.
5. **Monitoring용 Metric**: 학습은 Cross-Entropy로 하되, Accuracy나 MSE(확률의 MSE = Brier Score)는 따로 계산해서 기록만 할 수 있어요.
END: Loss는 불량 점수. Regression은 MSE, Classification은 Cross-Entropy가 기본이에요.

#### Activation Function 비교: Sigmoid · Tanh · ReLU
ONE: Activation Function은 Neuron의 출력을 비선형으로 바꿔요. **Sigmoid·Tanh**는 양 끝에서 기울기가 사라지는 문제가 있어서, Hidden Layer에는 주로 **ReLU 계열**을 써요.
LIKE: Sigmoid는 밝기 조절기 같아요. 중간에서는 잘 반응하지만 끝까지 돌리면 더 돌려도 밝기가 거의 안 바뀌어요(Saturation). ReLU는 "음수면 끄고, 양수면 그대로 통과"하는 단순한 스위치예요.
STEP:
1. **Sigmoid**: 출력 0~1. 확률 출력에 좋지만, 미분이 최대 **0.25**라 층을 지날 때마다 Gradient가 줄어요. 입력이 크거나 작으면 기울기가 거의 0이에요.
2. **Tanh**: 출력 −1~1. 0을 중심으로 대칭이라 Sigmoid보다 낫지만, 여전히 양 끝에서 Saturation돼요.
3. **ReLU**: max(0, x). 양수에서 기울기가 1이라 Gradient가 잘 전달되고, 비교만 하면 돼서 계산이 빨라요. 음수 입력에는 0을 내서 일부 Neuron만 켜져요(Sparse).
4. **Dying ReLU**: 어떤 Neuron의 입력이 항상 음수가 되면 출력도 기울기도 0이라 영원히 학습되지 않아요. 고장 나서 "꺼짐"에 고정된 스위치예요.
5. **LeakyReLU**: 음수에서도 작은 기울기(예: 0.01)를 남겨 Dying ReLU를 막아요.
6. **GELU·SiLU**: ReLU를 부드럽게 만든 버전으로, Transformer에서 많이 써요.
| 함수 | 출력 범위 | 장점 | 단점 |
| Sigmoid | 0 ~ 1 | 확률로 해석 | Saturation, 미분 최대 0.25 |
| Tanh | −1 ~ 1 | 0 중심 | Saturation |
| ReLU | 0 ~ ∞ | 빠름, Gradient 잘 전달 | Dying ReLU |
| LeakyReLU | −∞ ~ ∞ | Dying ReLU 완화 | 기울기 α를 정해야 함 |
| GELU | 약간의 음수 포함 | 부드러움 | 계산이 조금 더 비쌈 |
END: Hidden Layer는 ReLU 계열(Transformer는 GELU), Sigmoid·Tanh는 출력층이나 LSTM Gate에 주로 써요.

#### 마지막 Layer와 Loss의 짝
ONE: 출력층은 **예측할 값의 종류**에 맞춰 고르고, Loss도 그에 맞는 **짝**을 써요.
LIKE: 공장 마지막 포장 공정은 제품 종류에 맞춰 달라요. 액체는 병에, 과자는 봉지에 담듯, 숫자 예측·Yes/No·여러 개 중 하나·여러 개 동시 선택마다 포장(출력층)이 달라요.
STEP:
1. **숫자 하나 예측 (Regression)**: Unit 1개, Activation 없음 → MSE·MAE.
2. **Yes / No (Binary)**: Unit 1개 + Sigmoid → Binary Cross-Entropy.
3. **여러 개 중 하나 (Multi-Class)**: Unit K개 + Softmax(합이 1) → Cross-Entropy.
4. **여러 개 동시 가능 (Multi-Label)**: Unit K개 + 각각 Sigmoid → Class별 BCE. 예: 사진에 "고양이"와 "소파"가 모두 있음.
5. **실무 요령**: 마지막에 Sigmoid·Softmax를 직접 넣지 않고, 활성화 전 점수(**Logit**)를 PyTorch의 BCEWithLogitsLoss·CrossEntropyLoss에 넘겨요. 내부에서 Log와 함께 안정적으로 계산해서 숫자가 넘치거나 0이 되는 문제를 막아요.
END: 숫자는 Identity + MSE, 이진은 Sigmoid + BCE, 하나 고르기는 Softmax + CE, 여러 개는 Sigmoid들 + BCE예요.

### Cost Function과 Activation Function은?
A: Loss(Cost) Function은 모델의 예측이 정답과 얼마나 다른지를 하나의 숫자로 나타낸 것으로(Regression은 MSE, Classification은 Cross-Entropy), 학습은 이 값을 최소화하는 과정입니다. 보통 샘플 하나의 오차를 Loss, 전체 평균(Regularization 항 포함)을 Cost라고 부릅니다. Activation Function은 각 Neuron의 Weighted Sum에 적용하는 비선형 함수로 Neural Network에 비선형 표현력을 줍니다.

### 알고 있는 Activation Function은? (Sigmoid, Tanh, ReLU, LeakyReLU 등)
| 함수 | 식 | 출력 범위 | 특징 |
| Sigmoid | 1/(1 + e⁻ˣ) | (0, 1) | 확률 출력에 적합, 미분 최대 0.25, 양 끝에서 Saturation, 출력 중심이 0이 아님 |
| Tanh | (eˣ − e⁻ˣ)/(eˣ + e⁻ˣ) | (−1, 1) | Zero-Centered, 미분 최대 1, 여전히 Saturation |
| ReLU | max(0, x) | [0, ∞) | 계산이 싸고 양수에서 기울기 1, 음수에서 0 |
| LeakyReLU | x ≥ 0이면 x, 아니면 αx(예: 0.01) | (−∞, ∞) | 음수에도 작은 기울기로 Dying ReLU 완화 |
| GELU, SiLU | x·Φ(x), x·σ(x) | 약간의 음수 포함 | 부드러운 ReLU, Transformer에서 많이 씀 |
| Softmax | e^(zᵢ)/Σe^(zⱼ) | (0, 1), 합 1 | Multi-Class Classification 출력층 |
A: Hidden Layer에는 보통 ReLU 계열(Transformer는 GELU)을, Output Layer에는 과제에 따라 Sigmoid·Softmax·Identity(항등) 함수를 씁니다. Sigmoid·tanh는 입력이 커지면 기울기가 0에 가까워지는 Saturation(포화) 문제가 있어, 요즘 Hidden Layer보다는 출력이나 LSTM Gate에 주로 씁니다.

### 요즘 Sigmoid보다 ReLU를 많이 쓰는 이유는?
A: Sigmoid의 미분은 최대 0.25라 Layer를 거칠 때마다 기울기가 줄고 Saturation 구간에서는 거의 0이 되어 깊은 망에서 Vanishing Gradient가 생기지만, ReLU는 양수 구간에서 기울기가 1이라 Gradient가 잘 전달됩니다. 또 지수 계산 없이 비교만 하면 돼 빠르고, 음수 입력에 0을 내 Sparse Activation을 만들며, 실제로 수렴이 훨씬 빨랐습니다.

### ReLU의 문제점은? (Dying ReLU)
E: 스위치가 "꺼짐" 위치에서 고장 나면 다시 켜질 일이 없습니다.
A: ReLU는 음수 입력에서 출력과 기울기가 모두 0이므로, 큰 Learning Rate 등으로 Weight·Bias가 크게 바뀌어 어떤 Neuron의 입력이 항상 음수가 되면 그 Neuron은 더 이상 갱신되지 않는 Dead Neuron이 됩니다. LeakyReLU·PReLU·ELU 같은 변형, 적절한 Learning Rate, He Initialization으로 완화합니다. 출력이 Zero-Centered가 아니고 위로 제한이 없다는 것도 작은 단점입니다.

### 마지막 Layer는 어떻게 구성하나요?
| 과제 | Output Layer | Loss Function |
| Regression | Unit 1개(또는 Target 수), Activation 없음 | MSE, MAE, Huber |
| Binary Classification | Unit 1개 + Sigmoid | BCE (Binary Cross-Entropy) |
| Multi-Class (답 하나) | Unit K개 + Softmax | Categorical Cross-Entropy |
| Multi-Label (답 여러 개) | Unit K개 + 각각 Sigmoid | Class별 BCE |
A: Output Layer는 예측할 값의 종류에 맞춰 위 표처럼 고릅니다. 실무에서는 수치 안정성(Numerical Stability)을 위해 마지막에 Sigmoid·Softmax를 직접 넣지 않고 Logit(활성화 전 점수)을 PyTorch의 BCEWithLogitsLoss나 CrossEntropyLoss에 넘기며, 이 함수들이 내부에서 안정적으로 Activation과 Log를 함께 계산합니다.

### 학습은 BCE Loss로 하되 상황을 MSE Loss로 보고 싶다면?
A: Backpropagation에는 BCE만 쓰고, 예측 확률과 정답 사이의 MSE는 Monitoring용 Metric으로만 따로 계산해 기록합니다. PyTorch에서는 `loss = bce(logits, y)`로 backward하고, `torch.no_grad()` 안에서 `mse = ((torch.sigmoid(logits) - y) ** 2).mean()`을 구해 TensorBoard 등에 남기며, Keras는 `metrics`에 `'mse'`를 추가하면 됩니다. 확률의 MSE는 Brier Score라고 부르며 확률이 얼마나 잘 맞는지(Calibration)를 보여 줍니다.

## Gradient Descent와 Backpropagation

#### Gradient Descent: 내리막으로 한 걸음씩
ONE: **Gradient Descent**는 Loss를 줄이는 방향(Gradient의 **반대 방향**)으로 Weight를 **조금씩** 옮기기를 반복하는 방법이에요.
LIKE: 눈을 가리고 골짜기 가장 낮은 곳을 찾는 거예요. 발로 땅의 기울기를 느끼고 내리막 쪽으로 한 발짝씩 가요. 보폭이 너무 크면 골짜기를 넘어가 버리고, 너무 작으면 해가 져요.
STEP:
1. **Gradient**: Loss를 각 Weight로 미분한 값들의 모음이에요. "어느 쪽으로 가면 Loss가 가장 빨리 **커지는지**"를 가리켜요.
2. **업데이트**: θ ← θ − η × Gradient. 반대 방향으로 가야 Loss가 줄어요.
3. **Learning Rate (η)**: 보폭이에요. 가장 중요한 Hyperparameter예요.
4. **왜 꼭 Gradient?** Weight가 수십억 개인데 하나씩 바꿔 보며 Loss를 재는 건 불가능해요. Gradient는 Backpropagation 한 번으로 **모든 Weight의 방향을 동시에** 알려 줘요.
5. **그래프로 보면**: 교과서 그림은 가로축 Weight, 세로축 Loss예요. 실제로는 축이 Weight 수만큼 있어서 그릴 수 없으니, 가로축 학습 Step, 세로축 Loss인 **Learning Curve**를 봐요.
6. **Loss가 가끔 오르는 이유**: 보폭이 너무 커서 골짜기를 넘거나(Overshooting), Mini-Batch마다 다른 데이터로 방향을 추정해서 흔들려요(Stochastic Noise). Validation Loss만 오르면 Overfitting 신호예요.
END: Gradient의 반대 방향으로 Learning Rate만큼 이동하기를 반복하면 Loss가 줄어요.

#### Backpropagation: 책임을 거꾸로 나누기
ONE: **Backpropagation**은 출력의 오차를 **뒤에서 앞으로** 거슬러 올라가며, Chain Rule로 **모든 Weight가 오차에 얼마나 책임 있는지(Gradient)**를 한 번에 계산하는 방법이에요.
LIKE: 빵 공장에서 완성된 빵이 너무 짰어요. 굽기 담당 → 반죽 담당 → 재료 계량 담당 순으로 거꾸로 거슬러 올라가며 "내 단계가 짠맛에 얼마나 기여했나"를 따져서 각자 조금씩 고쳐요.
STEP:
1. **Forward Pass**: 입력을 앞에서 뒤로 통과시켜 예측과 Loss를 계산해요. 중간값은 저장해 둬요.
2. **Backward Pass**: 출력층에서 시작해 Loss의 미분을 앞쪽으로 전달해요.
3. **Chain Rule (연쇄 법칙)**: Loss가 y를 거쳐 z를 거쳐 w에 연결돼 있으면, ∂Loss/∂w = ∂Loss/∂y × ∂y/∂z × ∂z/∂w예요. 각 단계의 "국소 미분"을 곱하면 돼요(12번 주제).
4. **재사용 덕분에 빠름**: 뒤 Layer에서 이미 계산한 미분을 앞 Layer가 그대로 이어서 써요. 그래서 전체 비용이 Forward Pass와 같은 자릿수예요.
5. **업데이트**: 구한 Gradient로 Gradient Descent가 Weight를 고쳐요.
6. **Autograd (자동 미분)**: 계산을 덧셈·곱셈 같은 작은 연산 Node의 Graph(Computational Graph)로 기록해 두고, 거꾸로 따라가며 자동으로 미분해요. PyTorch의 `loss.backward()`가 이 일을 해요.
END: 앞으로 계산하고(Forward), 뒤로 책임을 나눠요(Backward). Chain Rule 덕분에 모든 Weight의 Gradient를 한 번에 구해요.

#### Vanishing · Exploding Gradient
ONE: 앞쪽 Layer의 Gradient는 뒤쪽 Layer들의 미분을 **계속 곱한 값**이라, 곱하는 값이 1보다 작으면 **사라지고(Vanishing)**, 크면 **폭발해요(Exploding)**.
LIKE: 귓속말 게임에서 사람이 많을수록 말이 점점 작아져 사라지거나, 반대로 점점 부풀려져 엉뚱해지는 것과 같아요.
STEP:
1. Backpropagation에서 앞쪽 Layer의 Gradient = 뒤쪽 Layer들의 (Activation 미분 × Weight)를 차례로 곱한 값이에요.
2. **Vanishing**: Sigmoid 미분은 최대 0.25예요. 10층이면 0.25¹⁰ ≈ 0.000001로 거의 0이 돼서 앞쪽 Layer가 학습되지 않아요.
3. **Exploding**: 곱하는 값이 1보다 크면 지수적으로 커져서 Weight가 튀고 Loss가 NaN이 돼요.
4. **RNN에서 특히 심함**: 같은 Weight를 시간 Step마다 반복해서 곱하기 때문이에요.
5. **Vanishing 해결**: ReLU, 좋은 초기화(He·Xavier), Batch·Layer Normalization, Residual Connection, LSTM의 Gate.
6. **Exploding 해결**: **Gradient Clipping**(Gradient 크기가 기준을 넘으면 잘라 줄이기).
END: 작은 수를 계속 곱하면 사라지고, 큰 수를 곱하면 폭발해요. ReLU·초기화·Normalization·Residual·Clipping으로 막아요.

### Gradient Descent를 쉽게 설명한다면?
E: 눈을 가린 채 골짜기 가장 낮은 곳을 찾는다면, 발로 땅의 기울기를 느끼고 내리막 쪽으로 한 발짝씩 움직이면 됩니다. 보폭이 너무 크면 골짜기를 넘어가고, 너무 작으면 해가 집니다.
A: Gradient Descent(경사하강법)는 Loss를 Parameter로 미분한 Gradient(Loss가 가장 빨리 커지는 방향)의 반대 방향으로 Parameter를 조금씩 옮기는 일을 반복하는 Optimization 방법으로, θ ← θ − η∇L(θ)이고 η(Learning Rate)가 보폭입니다.

### 왜 꼭 Gradient를 써야 할까? 그 그래프의 가로축·세로축은? 실제로는 어떻게 그려질까?
A: 수백만~수천억 개의 Parameter를 하나씩 바꿔 보며 Loss를 확인하는 것은 불가능하지만, Gradient는 모든 Parameter에 대해 "어느 쪽으로 얼마나 바꾸면 Loss가 줄어드는지"를 Backpropagation 한 번(Forward Pass와 비슷한 비용)으로 알려 줍니다. 교과서 그림의 가로축은 Parameter(Weight) 값, 세로축은 Loss입니다. 실제로는 축이 Parameter 수만큼 있는 초고차원 지형(Loss Landscape)이라 그릴 수 없어서, 가로축을 학습 단계(Step·Epoch), 세로축을 Loss로 둔 Learning Curve를 보며, 이 곡선은 Mini-Batch 잡음 때문에 오르내리며 전체적으로 내려갑니다.

### GD 중에 때때로 Loss가 증가하는 이유는?
A: Learning Rate가 너무 커서 골짜기를 넘어 반대편 더 높은 곳으로 뛰어넘거나(Overshooting), Mini-Batch마다 다른 샘플로 Gradient를 추정해 방향이 흔들리기 때문입니다(Stochastic Noise). Momentum이 관성으로 넘치거나 Learning Rate Schedule이 다시 커지는 경우에도 오르며, Validation Loss만 오르는 것은 Overfitting 신호입니다. Loss가 계속 튀면 Learning Rate를 낮추거나 Gradient Clipping을 씁니다.

### Backpropagation을 쉽게 설명한다면?
E: 빵 공장에서 최종 빵이 너무 짰다면, 굽기 담당 → 반죽 담당 → 재료 계량 담당 순으로 거꾸로 거슬러 올라가며 "내 단계가 짠맛에 얼마나 기여했나"를 따져 각자 조금씩 고칩니다.
A: Backpropagation(역전파)은 Forward Pass로 Loss를 계산한 뒤, Output Layer에서 Input Layer 방향으로 Chain Rule(연쇄 법칙)을 적용해 모든 Weight에 대한 Loss의 미분을 한 번에 구하는 Algorithm입니다. 뒤 Layer에서 계산한 미분을 앞 Layer가 재사용하므로 비용이 Forward Pass와 같은 자릿수이고, 구한 Gradient로 Gradient Descent가 Weight를 갱신합니다.

### Computational Graph와 Autograd(자동 미분)는?
A: Computational Graph는 식을 덧셈·곱셈 같은 기본 연산 Node로 나눈 Directed Graph이고, Automatic Differentiation(자동 미분)은 Forward Pass 때 Graph와 중간값을 기록해 두었다가 역방향으로 각 Node의 Local Gradient를 Chain Rule로 곱해 나가는 방법(Reverse Mode)입니다. Numerical Differentiation(근사치)과 달리 정확하고, Symbolic Differentiation과 달리 식이 폭발하지 않으며, PyTorch의 `loss.backward()`가 이 일을 합니다.

### Vanishing Gradient와 Exploding Gradient는 왜 생기나요?
E: 귀엣말 게임에서 사람이 많을수록 말이 작아져 사라지거나, 반대로 점점 부풀려져 엉뚱해집니다.
A: Backpropagation에서 앞쪽 Layer의 Gradient는 뒤쪽 Layer들의 미분(Activation Function 미분 × Weight)을 계속 곱한 값이라, 곱하는 값이 1보다 작으면(Sigmoid 미분 ≤ 0.25) Layer 수에 따라 지수적으로 작아지고(Vanishing), 1보다 크면 지수적으로 커집니다(Exploding). RNN은 같은 Weight를 Time Step마다 곱해 특히 심합니다. ReLU, He·Xavier Initialization, Batch·Layer Normalization, Residual Connection, LSTM Gate로 Vanishing을, Gradient Clipping으로 Exploding을 막습니다.

## Loss Landscape와 Local Minimum

#### 고차원 지형과 Saddle Point
ONE: Deep Learning의 Loss 지형은 울퉁불퉁하지만, 고차원에서는 갇히는 진짜 웅덩이보다 **말안장 모양(Saddle Point)**이 훨씬 많고, 웅덩이들도 대부분 **충분히 낮아서** 실제로는 잘 학습돼요.
LIKE: 2차원 산에서는 작은 웅덩이에 갇히기 쉬워요. 하지만 방향이 백만 개인 지형에서 **모든 방향이 동시에 오르막**인 웅덩이는 드물어요. 대부분은 어느 방향으로는 내리막이 남아 있는 말안장이에요.
STEP:
1. **Local Minimum**: 모든 방향이 오르막인 웅덩이 바닥.
2. **Saddle Point**: 어떤 방향은 오르막, 어떤 방향은 내리막인 점. Gradient가 0이라 잠깐 멈출 수 있지만 빠져나갈 길이 있어요.
3. 고차원에서 Gradient가 0인 점은 대부분 Saddle Point예요.
4. 연구에 따르면 큰 Network의 Local Minimum들은 Loss 값이 Global Minimum과 크게 다르지 않아요.
5. Parameter가 아주 많으면(Over-Parameterization) 지형이 더 완만해져요.
6. **탈출 도구**: Mini-Batch SGD의 잡음(흔들어서 튀어나오기), Momentum(관성으로 턱 넘기), 큰 Learning Rate로 시작하거나 주기적으로 다시 키우기(Warm Restart), 다른 초기값으로 여러 번 학습.
7. **Global Minimum인지 알 수 있나?** 일반적으로는 몰라요. 그리고 Training Loss의 Global Minimum은 오히려 Overfitting일 수 있어서, 목표는 **Validation 성능이 좋은 해**예요.
END: 고차원에서는 웅덩이보다 안장이 문제이고, SGD 잡음과 Momentum이 빠져나오게 도와요. 목표는 Global Minimum이 아니라 잘 일반화되는 해예요.

### Local Minimum 문제에도 불구하고 Deep Learning이 잘 되는 이유는?
E: 2차원 산에서는 웅덩이에 갇히기 쉽지만, 방향이 백만 개인 지형에서 모든 방향이 동시에 오르막인 진짜 웅덩이는 드물고, 대부분은 어느 방향으로는 내리막이 남아 있는 말안장 모양(Saddle Point)입니다.
A: 고차원 Loss Landscape에서 Gradient가 0인 점은 대부분 Local Minimum이 아니라 Saddle Point이고, 연구들에 따르면 큰 Neural Network의 Local Minimum들은 Loss 값이 Global Minimum과 크게 다르지 않습니다. Parameter가 많은 Over-Parameterization이 지형을 더 완만하게 만들고, SGD의 잡음과 Momentum이 Saddle Point를 빠져나오게 돕기 때문에 실제로는 "충분히 좋은" 해에 도달합니다.

### GD가 Local Minimum을 피하는 방법은?
A: Mini-Batch SGD의 잡음으로 얕은 웅덩이를 튀어나오게 하고, Momentum의 관성으로 작은 턱을 넘으며, 초반에 큰 Learning Rate를 쓰거나 주기적으로 Learning Rate를 다시 키우는 Schedule(Warm Restart)을 씁니다. 또 서로 다른 Initialization으로 여러 번 학습해 가장 좋은 것을 고르거나 Ensemble합니다.

### 찾은 해가 Global Minimum인지 알 수 있는 방법은?
A: Non-Convex 함수에서는 일반적으로 알 수 없습니다. 다만 Loss의 하한을 아는 경우(Cross-Entropy는 0 이상) Training Loss가 그 하한에 거의 닿으면 Training Data 기준으로는 Global Minimum에 가깝다고 말할 수 있고, 여러 Initialization의 결과를 비교해 확인하기도 합니다. 실무에서는 Training Loss의 Global Minimum이 오히려 Overfitting일 수 있으므로, Validation 성능이 좋은 해를 찾는 것이 목표입니다.

## Optimizer

#### SGD · Momentum · RMSprop · Adam
ONE: Optimizer는 Gradient를 보고 **어느 방향으로 얼마나** 움직일지 정하는 방법이에요. **Momentum**은 관성, **RMSprop**은 방향별 보폭 조절, **Adam**은 둘을 합친 거예요.
LIKE: SGD는 매 걸음 발밑 경사만 보고 걷기, Momentum은 언덕을 굴러가는 공처럼 이전 속도를 이어 가기, RMSprop은 자주 가파르던 방향은 조심스럽게 작은 보폭으로 걷기, Adam은 굴러가는 공이 지형에 맞춰 보폭까지 조절하는 거예요.
STEP:
1. **SGD**: 전체 데이터 대신 무작위로 뽑은 Mini-Batch로 Gradient를 추정해서 바로 이동해요. **Stochastic(확률적)**은 "무작위로 뽑은 일부로 추정한다"는 뜻이에요. 평균적으로는 전체 Gradient와 같지만 잡음이 있어요.
2. **Momentum**: 지난 이동 방향을 누적한 "속도" v를 써요. v ← βv + g. 같은 방향이 계속되면 가속하고, 지그재그로 흔들리면 서로 상쇄돼서 진동이 줄어요.
3. **RMSprop**: Weight마다 최근 Gradient 크기(제곱 평균)를 기억하고 그걸로 나눠요. 늘 가파르던 방향은 보폭을 줄이고, 완만하던 방향은 키워요(Adaptive Learning Rate).
4. **Adam**: Momentum(방향의 평균) + RMSprop(크기의 평균). 처음에 0으로 시작해서 생기는 치우침을 보정(Bias Correction)해요. 기본값 β₁ = 0.9, β₂ = 0.999, η = 0.001로도 잘 동작해서 가장 널리 써요.
5. **AdamW**: Weight Decay를 Adam의 보폭 조절과 분리한 버전으로, Transformer 학습의 표준이에요.
6. **SGD + Momentum**: 잘 튜닝하면 Generalization이 더 좋다는 보고가 많아서 이미지 모델에서 여전히 써요.
| Optimizer | 핵심 아이디어 | 비유 |
| SGD | Mini-Batch Gradient로 바로 이동 | 발밑만 보고 걷기 |
| Momentum | 지난 방향 누적 | 굴러가는 공 |
| RMSprop | 방향별 보폭 자동 조절 | 가파른 곳은 조심 |
| Adam | Momentum + RMSprop | 보폭 조절하는 공 |
END: 관성(Momentum)과 방향별 보폭(RMSprop)을 합친 Adam이 기본값, Transformer는 AdamW예요.

#### Mini-Batch 크기와 Learning Rate Schedule
ONE: **Mini-Batch** 크기는 속도·안정성·Generalization의 균형이고, **Learning Rate Schedule**은 처음엔 크게 나중엔 작게 보폭을 바꾸는 계획이에요. 초반에 서서히 올리는 **Warmup**도 써요.
LIKE: 시식단 규모를 정하는 것과 같아요. 시식단이 작으면 빨리 자주 피드백을 받지만 의견이 들쭉날쭉하고, 크면 의견은 안정적이지만 한 번 모으는 데 오래 걸려요. 그리고 처음엔 큰 폭으로 레시피를 바꾸다가 완성에 가까워지면 소금 한 꼬집씩 조절해요.
STEP:
1. **작은 Batch의 장점**: Memory가 적게 들고, 같은 Epoch에 더 자주 업데이트하고, 잡음이 일종의 Regularization이 될 수 있어요.
2. **작은 Batch의 단점**: 흔들림이 커서 더 작은 Learning Rate가 필요하고, GPU 병렬성을 다 못 써서 전체 시간이 길어지고, Batch Normalization 통계가 부정확해져요.
3. **Step Decay**: 일정 Epoch마다 Learning Rate를 줄여요(예: 1/10).
4. **Cosine Annealing**: 코사인 곡선처럼 부드럽게 줄여요.
5. **Warmup**: 처음 몇 천 Step 동안 Learning Rate를 0 근처에서 목표값까지 서서히 올려요. Weight가 무작위이고 Adam의 통계가 불안정한 초반에 발산하는 걸 막아요. Transformer와 큰 Batch 학습에서는 거의 필수예요.
END: Batch는 속도와 안정성의 균형, Learning Rate는 Warmup으로 올린 뒤 점점 줄여요.

### SGD, RMSprop, Adam을 설명한다면? Momentum의 수식은?
E: SGD는 매 걸음 발밑 경사만 보고 걷기, Momentum은 굴러가는 공처럼 이전 속도를 이어가기, RMSprop은 자주 가파르던 방향은 조심스럽게 작은 보폭으로, 완만하던 방향은 큰 보폭으로 걷기, Adam은 둘을 합친 것입니다.
| 방법 | 갱신 식 (g는 Gradient) | 핵심 |
| SGD | θ ← θ − ηg | 가장 단순, 잘 튜닝하면 Generalization이 좋다는 보고가 많음 |
| Momentum | v ← βv + g, θ ← θ − ηv (β ≈ 0.9) | 지난 방향을 누적해 진동을 줄이고 가속 |
| RMSprop | s ← ρs + (1 − ρ)g², θ ← θ − ηg / (√s + ε) | Parameter별로 최근 Gradient 크기에 따라 보폭 자동 조절 |
| Adam | m ← β₁m + (1 − β₁)g, v ← β₂v + (1 − β₂)g², Bias Correction m̂ = m/(1 − β₁ᵗ), v̂ = v/(1 − β₂ᵗ), θ ← θ − ηm̂ / (√v̂ + ε) | Momentum + RMSprop, 기본값 β₁ = 0.9, β₂ = 0.999, η = 0.001 |
A: SGD는 Mini-Batch Gradient로 바로 갱신하고, Momentum은 Gradient의 Exponential Moving Average(지수 이동 평균)로 속도를 만들어 진동을 줄이며, RMSprop은 Gradient 제곱의 이동 평균으로 나눠 Parameter별 Learning Rate를 조절합니다(Adaptive Learning Rate). Adam은 이 둘을 합쳤고 초기 0으로 인한 Bias를 보정하며 기본값으로도 잘 동작해 가장 널리 쓰이고, Weight Decay를 분리한 AdamW가 Transformer 학습의 표준입니다.

### SGD에서 Stochastic의 의미는?
A: 전체 데이터의 Gradient 대신 무작위로 뽑은 샘플 하나나 Mini-Batch로 Gradient를 추정한다는 뜻입니다. 이 추정은 평균적으로는 전체 Gradient와 같지만(Unbiased) 잡음이 있어, 한 번 갱신이 훨씬 싸고 잡음이 Saddle Point 탈출에도 도움이 됩니다.

### Mini-Batch를 작게 할 때의 장단점은?
A: 작은 Batch는 Memory를 적게 쓰고 같은 Epoch에 갱신을 더 자주 하며, Gradient 잡음이 일종의 Regularization처럼 작용해 Generalization에 도움이 된다는 보고가 있습니다. 반면 잡음이 커서 학습이 불안정하고 더 작은 Learning Rate가 필요하며, GPU 병렬성을 다 쓰지 못해 전체 시간이 길어지고, Batch Normalization의 통계가 부정확해집니다.

### Learning Rate Scheduling과 Warmup은?
A: 처음에는 큰 Learning Rate로 빠르게 내려가고 나중에는 작게 줄여 세밀하게 수렴하도록, 일정 Epoch마다 줄이는 Step Decay, 코사인 곡선으로 줄이는 Cosine Annealing 등을 씁니다. Warmup은 학습 초반 몇 천 Step 동안 Learning Rate를 0 근처에서 목표값까지 서서히 올리는 것으로, Weight가 무작위이고 Adam의 통계가 불안정한 초반의 발산(Divergence)을 막아 Transformer·큰 Batch 학습에서 거의 필수입니다.

## 학습 설정

#### Parameter vs Hyperparameter
ONE: **Parameter**는 학습으로 **자동으로 정해지는 값**(Weight, Bias)이고, **Hyperparameter**는 학습 전에 **사람이 정하는 설정**(Learning Rate, Batch Size, Layer 수 등)이에요.
LIKE: 빵을 구울 때 오븐 온도와 굽는 시간은 요리사가 정하는 설정(Hyperparameter)이고, 반죽이 부풀며 만들어지는 맛과 식감(Parameter)은 굽는 과정에서 정해져요.
STEP:
1. **Parameter**: Weight, Bias. Gradient Descent가 데이터로 찾아요. 수백만~수천억 개.
2. **Hyperparameter**: Learning Rate, Batch Size, Epoch 수, Layer 수, Neuron 수, Dropout 비율, Weight Decay 강도, Optimizer 종류.
3. Hyperparameter는 Gradient로 학습되지 않아서 여러 번 시도해 Validation 성능으로 골라요.
4. **고르는 법**: 모든 조합 시도(Grid Search), 무작위 조합 시도(Random Search, 보통 Grid보다 효율적), 지금까지 결과로 다음 시도를 똑똑하게 고르기(Bayesian Optimization).
END: 학습이 정하면 Parameter, 사람이 정하면 Hyperparameter. Hyperparameter는 Validation으로 골라요.

#### Weight Initialization
ONE: Weight를 **어떤 값으로 시작하느냐**가 학습 성공을 좌우해요. 모두 같은 값이면 Neuron들이 똑같이 배우고, 너무 크거나 작으면 신호가 폭주하거나 사라져요. 그래서 **층마다 신호 크기가 유지되도록** 무작위로 시작해요.
LIKE: 공장의 모든 작업자에게 똑같은 매뉴얼을 주고 똑같은 피드백을 주면 모두 똑같은 일만 하게 돼요. 처음에 조금씩 다르게 시작해야 각자 다른 역할을 맡아요.
STEP:
1. **모두 0 (또는 같은 값)**: 같은 Layer의 Neuron들이 같은 출력, 같은 Gradient를 받아서 영원히 똑같아요(Symmetry 문제).
2. **너무 큰 무작위 값**: 층을 지날수록 신호가 커져 폭발하거나, Sigmoid·Tanh가 Saturation돼요.
3. **너무 작은 값**: 층을 지날수록 신호가 0으로 사라져요.
4. **Xavier (Glorot)**: Var(W) = 2 / (n_in + n_out). 입력·출력 Neuron 수에 맞춰 분산을 정해요. Sigmoid·Tanh에 맞아요.
5. **He (Kaiming)**: Var(W) = 2 / n_in. ReLU가 절반을 0으로 만드는 걸 보정하려고 2배로 잡았어요. ReLU 계열에 써요.
END: 같은 값은 대칭 문제, 크기가 틀리면 폭주·소실. ReLU엔 He, Sigmoid·Tanh엔 Xavier로 시작해요.

#### Data Normalization
ONE: 입력 Feature들의 **범위를 비슷하게** 맞추는 거예요. 평균 0·분산 1로 맞추거나, 픽셀을 255로 나눠요. 학습이 **빠르고 안정적**이 돼요.
LIKE: 레시피에 설탕은 "g"으로, 소금은 "kg"으로 적혀 있으면 헷갈려서 양 조절이 엉망이 돼요. 단위를 맞춰야 조절이 쉬워요.
STEP:
1. Feature 범위가 다르면 Loss 지형이 한 방향으로 길쭉한 골짜기가 돼요.
2. 그러면 Gradient Descent가 골짜기 벽을 지그재그로 왔다 갔다 하며 느리게 내려가요.
3. 범위를 맞추면 지형이 둥근 그릇에 가까워져서 곧장 내려가요.
4. 큰 입력은 Sigmoid·Tanh를 Saturation시켜 Gradient를 죽이는데, Normalization이 이것도 막아요.
5. 평균·분산은 **Training Data에서만** 계산하고, Validation·Test에는 그 값을 그대로 써요(14번 주제의 Data Leakage).
END: 단위를 맞추면 지형이 둥글어져 빨리 내려가요. 통계는 Training Data로만 구해요.

### Hyperparameter는 무엇이고 Parameter와 무엇이 다른가요?
E: 요리에서 오븐 온도와 굽는 시간은 요리사가 정하는 설정(Hyperparameter)이고, 반죽이 스스로 부풀어 만드는 맛과 식감(Parameter)은 과정 중에 결정됩니다.
A: Parameter는 Weight·Bias처럼 학습으로 데이터에서 자동으로 정해지는 값이고, Hyperparameter는 Learning Rate·Batch Size·Layer 수·Dropout 비율·Epoch 수처럼 학습 전에 사람이 정하는 설정입니다. Hyperparameter는 Validation Set 성능을 보며 Grid·Random Search나 Bayesian Optimization으로 고릅니다.

### Weight Initialization 방법과 많이 쓰는 것은? (Xavier, He)
A: 모든 Weight를 0이나 같은 값으로 두면 같은 Layer의 Neuron들이 똑같이 학습되는 Symmetry(대칭) 문제가 생기고, 너무 크거나 작으면 Layer를 지날수록 신호와 Gradient가 폭주하거나 사라집니다. 그래서 Layer마다 출력의 분산이 유지되도록 무작위 초기화하며, Xavier(Glorot)는 Var(W) = 2/(n_in + n_out)으로 Sigmoid·tanh에, He(Kaiming)는 ReLU가 절반을 0으로 만드는 것을 보정해 Var(W) = 2/n_in으로 ReLU 계열에 씁니다. 요즘 ReLU Network에는 He Initialization이 가장 흔합니다.

### Data Normalization은 무엇이고 왜 필요한가요?
A: 입력 Feature를 평균 0·분산 1로 맞추거나 픽셀을 255로 나누는 등 범위를 비슷하게 만드는 것입니다. Feature 규모가 다르면 Loss Landscape가 한 방향으로 길쭉해져 Gradient Descent가 지그재그로 느리게 수렴하고, 큰 입력은 Activation Function을 Saturation시키기 때문에, Normalization하면 학습이 빠르고 안정적입니다. 통계는 Training Data에서만 구합니다.

## Data Split

#### Train · Validation · Test를 나누는 이유
ONE: **Training Set**으로 배우고, **Validation Set**으로 설정을 고르고, **Test Set**으로 마지막에 **딱 한 번** 실력을 재요. Test를 고르는 데 쓰면 점수가 부풀려져요.
LIKE: 문제집(Training)으로 공부하고, 모의고사(Validation)를 보며 공부 방법을 바꾸고, 수능(Test)은 딱 한 번 봐요. 모의고사에 맞춰 공부법을 여러 번 바꿨다면 모의고사 점수는 이미 실제 실력보다 부풀려져 있어요.
STEP:
1. **Training Set**: Weight를 학습하는 데 써요. 모델이 외울 수 있어서 이 점수는 너무 낙관적이에요.
2. **Validation Set**: Hyperparameter 고르기, 언제 학습을 멈출지(Early Stopping), 어떤 모델을 쓸지 고르는 데 써요.
3. **Test Set**: 모든 선택이 끝난 뒤 최종 성능을 한 번 재요.
4. **왜 Validation을 따로?** Test 점수를 보며 고르면, 그 선택 자체가 Test에 맞춰져서 Test 점수가 더 이상 "처음 보는 데이터" 점수가 아니에요.
5. **Test 오염(Contamination)**: Test 정보가 어떤 경로로든 학습·선택에 섞인 상태예요. Train·Test에 같은 샘플이 중복되거나, Test 점수를 보며 반복 튜닝하거나, Test 통계로 전처리하거나, LLM 학습 데이터에 Benchmark 문제가 섞인 경우예요.
END: 공부는 Training, 공부법 조정은 Validation, 실전은 Test 한 번이에요.

### Training Set과 Test Set을 분리하는 이유는? Validation Set이 따로 있는 이유는?
E: 문제집(Training)으로 공부하고, 모의고사(Validation)를 보며 공부 방법을 바꾸고, 수능(Test)은 딱 한 번 봅니다. 모의고사를 여러 번 보며 공부법을 맞췄다면 모의고사 점수는 이미 실력보다 부풀려져 있습니다.
A: Training Data 성능은 모델이 외워 버릴 수 있어 낙관적이므로, 한 번도 보지 않은 Test Set으로 Generalization 성능을 추정합니다. Hyperparameter Tuning, Early Stopping, Model Selection에 Test Set을 쓰면 그 선택 자체가 Test에 맞춰져 점수가 부풀려지므로, 이 역할을 따로 맡는 Validation Set을 둡니다.

### Test Set이 오염(Contamination)되었다는 말의 뜻은?
A: Test Data의 정보가 어떤 경로로든 학습이나 선택 과정에 들어가 더 이상 "처음 보는 데이터"가 아니게 된 상태입니다. Train·Test 간 중복 샘플, Test 점수를 보며 반복 튜닝, Test 통계를 쓴 전처리, LLM Pre-training 데이터에 Benchmark 문제가 섞인 경우가 대표적이며, 이때 Test 점수는 실제 성능보다 높게 나옵니다.

## Overfitting과 Regularization

#### Overfitting 대처법 한눈에
ONE: **Regularization**은 학습 데이터 성능이 아니라 **처음 보는 데이터 성능**을 높이기 위해 학습에 거는 모든 제약이에요. 데이터·모델·학습 과정 세 곳에서 손볼 수 있어요.
LIKE: 기출문제만 외우는 학생을 고치려면 문제를 더 다양하게 주고(데이터), 외울 칸을 줄이고(모델), 모의고사 점수가 떨어지기 시작하면 그만 외우게 해요(학습 과정).
STEP:
1. **데이터 늘리기**: 데이터를 더 모으거나, 있는 데이터를 살짝 바꿔 늘려요(**Data Augmentation**: 이미지 뒤집기·자르기·회전·색 바꾸기, 텍스트 동의어 바꾸기).
2. **모델 줄이기**: Layer나 Neuron을 줄여요.
3. **Weight Decay (L2)**: Weight가 커지지 않게 벌점을 줘요(14번 주제).
4. **Dropout**: 학습 중 Neuron을 무작위로 꺼요.
5. **Early Stopping**: Validation Loss가 더 이상 좋아지지 않으면 학습을 멈추고, 가장 좋았던 시점의 Weight를 써요.
6. **Batch Normalization**: 약한 Regularization 효과도 있어요.
7. **Ensemble**: 여러 모델의 예측을 평균해요.
8. **Transfer Learning**: 큰 데이터로 미리 배운 모델에서 시작하면 적은 데이터로도 덜 외워요.
END: 데이터를 늘리고, 모델을 단순하게, Weight에 벌점을, Neuron을 무작위로 끄고, 적당할 때 멈춰요.

#### Dropout
ONE: **Dropout**은 학습할 때 매 Step마다 Neuron을 **확률 p로 무작위로 꺼서**, 특정 Neuron에 의존하지 않게 만드는 방법이에요.
LIKE: 팀 프로젝트에서 매일 무작위로 몇 명을 쉬게 하면, 특정 에이스 한 명에게만 의존하지 않고 모두가 일을 조금씩 할 줄 알게 돼요.
STEP:
1. 학습 중 매 Step, 각 Neuron을 확률 p(예: 0.5)로 꺼요(출력을 0으로).
2. 그러면 Neuron들이 "옆 Neuron이 해 주겠지" 하며 서로 의존(Co-Adaptation)하지 못해요.
3. 매번 다른 작은 Network를 학습하는 셈이라, 많은 Network를 평균하는 **Ensemble 효과**가 있어요.
4. **추론할 때는 아무것도 끄지 않아요.**
5. **크기 맞추기 (Inverted Dropout)**: 학습 때 살아남은 Neuron의 출력을 1/(1 − p)배로 키워 둬요. 그러면 추론 때 그대로 써도 평균 크기가 같아요.
6. PyTorch에서는 `model.eval()`로 바꾸면 Dropout이 꺼져요.
END: 학습 때 무작위로 끄고 추론 때는 다 켜요. 서로 의존하지 않게 만들어 덜 외워요.

#### Batch Normalization과 Layer Normalization
ONE: **Batch Normalization**은 Mini-Batch 안에서 각 Feature를 **평균 0·분산 1로 맞춘 뒤** 다시 학습 가능한 크기로 조정하는 Layer예요. **Layer Normalization**은 같은 일을 **샘플 하나 안에서** 해요.
LIKE: 반마다 시험 난이도가 달라 점수 비교가 어려우면 반 평균을 빼고 표준편차로 나눈 표준점수로 바꿔요(BN). 그런데 실제 시험장에 수험생이 한 명뿐이면 반 평균을 낼 수 없으니, 그동안 모아 둔 전체 평균을 써요. LN은 반 평균 대신 학생 한 명의 과목 점수들끼리 표준점수를 내는 거예요.
STEP:
1. **BN 학습 때**: Mini-Batch에서 각 Channel(Feature)의 평균·분산을 구해 정규화해요.
2. 그다음 학습 가능한 γ(크기)와 β(위치)로 다시 조정해요. 필요하면 원래대로 되돌릴 수도 있게요.
3. **효과**: 더 큰 Learning Rate를 쓸 수 있고, 빨리 수렴하고, 초기화에 덜 민감하고, 약한 Regularization 효과가 있어요. (처음엔 Internal Covariate Shift를 줄인다고 설명했지만, 이후 Loss 지형을 매끄럽게 한다는 설명이 제시됐어요.)
4. **BN 추론 때**: Batch 통계 대신 학습 중 모아 둔 **Running Mean·Var**를 써요. PyTorch에서 `model.eval()`을 꼭 호출해야 해요. 잊으면 Batch 구성에 따라 예측이 달라지고, Batch Size 1이면 엉뚱한 값이 나와요.
5. **LN**: 샘플 하나의 모든 Feature로 평균·분산을 구해요. Batch Size와 상관없고 학습·추론 동작이 같아요.
6. **어디에 쓰나**: BN은 Batch가 충분히 큰 CNN에, LN은 길이가 다른 Sequence를 다루는 RNN·Transformer에 써요.
END: BN은 Batch 방향으로(추론 땐 Running 통계), LN은 샘플 하나 안에서 정규화해요. CNN엔 BN, Transformer엔 LN이에요.

### Overfitting일 경우 어떻게 대처해야 할까요? Regularization이란?
A: Regularization(정규화)은 Training 오차가 아니라 Generalization 오차를 줄이기 위해 학습에 가하는 모든 제약을 말합니다. Overfitting이면 데이터를 늘리거나 Augmentation(회전·자르기·잡음)하고, 모델을 작게 하거나, Weight Decay(L2), Dropout, Early Stopping, Batch Normalization, Ensemble, Pre-trained Model의 Transfer Learning을 씁니다.

### Dropout의 효과는?
E: 팀 프로젝트에서 매일 무작위로 몇 명을 쉬게 하면, 특정 한 명에게만 의존하지 않고 모두가 일을 조금씩 할 줄 알게 됩니다.
A: Dropout은 학습 중 매 Step Neuron을 확률 p로 무작위로 꺼서 Neuron들이 서로에게 지나치게 의존(Co-Adaptation)하는 것을 막고, 매번 다른 작은 Network를 학습해 평균내는 Ensemble 효과를 냅니다. 보통 학습 때 남은 Neuron을 1/(1 − p)배로 키워(Inverted Dropout) 추론 때는 아무것도 끄지 않고 그대로 씁니다.

### Batch Normalization의 효과는? 학습 후 실제 사용 시 주의할 점은?
E: 반마다 시험 난이도가 달라 점수를 비교하기 어려우면 반 평균을 빼고 표준편차로 나눈 표준점수로 바꿉니다. 다만 실제 시험장에서는 수험생 한 명만 있어도 채점해야 하므로, 그동안 모아 둔 "전체 평균"을 씁니다.
A: BN(Batch Normalization)은 Mini-Batch 안에서 각 Channel(Feature)을 평균 0·분산 1로 정규화한 뒤 학습 가능한 γ·β로 다시 Scale·Shift하는 Layer로, 더 큰 Learning Rate와 빠른 수렴을 가능하게 하고 Initialization에 덜 민감하게 하며 약한 Regularization 효과도 있습니다(처음엔 Internal Covariate Shift를 줄인다고 설명했지만 이후 Loss Landscape를 매끄럽게 한다는 설명이 제시됨). 추론 때는 Batch 통계 대신 학습 중 모은 Running Mean·Var를 써야 하므로 PyTorch에서 `model.eval()`을 호출하고(Dropout도 꺼짐), 다시 학습할 때는 `model.train()`으로 돌리며, 추론은 `torch.no_grad()` 안에서 합니다. eval을 잊으면 Batch 구성에 따라 예측이 달라지고 Batch Size 1에서는 엉뚱한 값이 나옵니다.

### Layer Normalization은 BN과 무엇이 다른가요?
A: BN은 같은 Feature를 Batch 방향으로 모아 정규화하고, LN(Layer Normalization)은 샘플 하나의 모든 Feature를 모아 정규화합니다. 그래서 LN은 Batch Size에 영향을 받지 않고 학습·추론 동작이 같아 길이가 다른 Sequence를 다루는 RNN·Transformer에 쓰이고, BN은 Batch가 충분히 큰 CNN에 주로 쓰입니다.

## CNN (Convolutional Neural Network)

#### Convolution: 돋보기로 훑기
ONE: **Convolution**은 작은 **Filter(돋보기)**를 이미지 위에서 밀며, 각 위치에 특정 패턴(선, 모서리)이 **얼마나 있는지 점수**를 매겨 **Feature Map**을 만드는 연산이에요.
LIKE: "세로선 찾기 돋보기"로 사진을 왼쪽 위부터 한 칸씩 훑으며 "여기 세로선이 있나?"를 점수로 적는 거예요. 돋보기를 여러 개 쓰면(세로선, 가로선, 동그라미) 점수표도 여러 장 생겨요.
STEP:
1. **Filter (Kernel)**: 3×3 같은 작은 숫자 격자예요. 이 숫자들이 학습되는 Weight예요.
2. **Convolution**: Filter를 이미지의 한 부분에 겹쳐 대응하는 칸끼리 곱해 더해요(Dot Product). 그 위치의 점수가 돼요.
3. Filter를 옆으로 밀며 반복해서 점수표(**Feature Map**)를 만들어요.
4. **Stride**: Filter를 한 번에 몇 칸씩 옮기는지예요. 2면 출력 크기가 대략 절반이 돼요.
5. **Padding**: 가장자리도 보려고 테두리에 0을 둘러요. 출력 크기를 유지할 수 있어요.
6. **출력 크기**: ⌊(W − K + 2P) / S⌋ + 1. 예: 32×32에 5×5 Filter, P = 0, S = 1이면 (32 − 5) / 1 + 1 = 28 → 28×28.
7. **Pooling**: 구역별로 가장 큰 값(Max Pooling)이나 평균만 남겨 크기를 줄여요. 학습할 Weight가 없고, 위치가 조금 바뀌어도 결과가 덜 흔들려요.
8. **층을 쌓으면**: 앞 층은 선·모서리, 중간 층은 눈·바퀴 같은 부분, 뒤 층은 얼굴·자동차 같은 물체를 찾아요.
END: Filter로 훑어 패턴 점수표를 만들고(Convolution), 크기를 줄이며(Pooling), 층을 쌓아 선 → 부분 → 물체로 올라가요.

#### CNN이 이미지에 강한 이유
ONE: CNN은 각 Neuron이 **주변 픽셀만 보고(Local Connectivity)**, 같은 Filter를 **이미지 전체에 재사용(Weight Sharing)**해서, MLP보다 **Weight가 훨씬 적고** 위치가 바뀌어도 같은 패턴을 찾아요.
LIKE: 숨은그림찾기에서 "고양이 모양 찾기 돋보기" 하나로 그림 전체를 훑으면 돼요. 그림의 칸마다 다른 돋보기를 만들 필요가 없어요.
STEP:
1. **MLP의 문제**: 224×224×3 이미지를 Hidden Neuron 1,000개에 모두 연결하면 첫 Layer만 약 1.5억 개 Weight가 필요해요.
2. 게다가 MLP는 픽셀을 한 줄로 펼쳐서 "옆 픽셀"이라는 공간 구조를 무시해요.
3. **Local Connectivity**: 이미지의 의미 있는 패턴(선, 모서리)은 가까운 픽셀끼리 만들어요. 그래서 주변만 봐도 돼요.
4. **Weight Sharing**: 세로선은 이미지 어디에 있든 세로선이에요. 같은 Filter를 재사용하니 Weight가 엄청 줄어요.
5. **Translation Equivariance**: 고양이가 왼쪽에 있든 오른쪽에 있든 같은 Filter가 반응해요.
6. **MLP도 될까?** MNIST처럼 작고 가운데 정렬된 숫자 이미지는 MLP로도 약 98%가 나와요. 하지만 큰 실제 사진에서는 데이터가 훨씬 많이 필요해요.
7. 초대규모 데이터가 있으면 Convolution 없이 Transformer로 이미지를 다루는 **ViT**도 경쟁력이 있어요.
END: 주변만 보고, 같은 Filter를 재사용하니 Weight가 적고 위치에 강해요. 그래서 이미지엔 CNN이에요.

#### ResNet과 Residual Connection
ONE: **Residual Connection**은 Block의 출력을 **y = F(x) + x**로 만들어서, 입력을 그대로 넘겨주는 **지름길**을 둬요. 덕분에 100층이 넘는 아주 깊은 Network도 학습할 수 있게 됐어요.
LIKE: 긴 계단 옆에 엘리베이터를 놓은 거예요. 각 층은 "원래 것에서 조금만 고칠 부분"만 배우면 되고, 신호는 엘리베이터로 바로 오르내릴 수 있어요.
STEP:
1. **문제 (Degradation)**: 그냥 Layer를 늘리면 Overfitting이 아닌데도 **Training 오차조차** 커지는 현상이 있었어요. 깊은 망을 학습시키기 어려웠던 거예요.
2. **아이디어**: Layer가 목표 전체 H(x)를 배우는 대신, 입력과의 **차이(Residual)** F(x) = H(x) − x만 배우게 해요. 출력은 F(x) + x.
3. **필요 없는 Layer**: F(x) ≈ 0으로 배우면 그냥 입력을 통과시키는 Layer가 돼요. 쓸모없는 Layer가 성능을 망치지 않아요.
4. **Gradient 지름길**: Backpropagation 때 +x 경로로 Gradient가 줄어들지 않고 앞쪽까지 전달돼요. Vanishing Gradient가 크게 줄어요.
5. **결과**: ResNet(2015)은 152층 Network를 학습시켜 ImageNet 대회에서 우승했어요.
6. Transformer도 모든 Block에 Residual Connection을 써요.
END: 입력을 그대로 더해 주는 지름길 덕분에 각 층은 조금만 고치면 되고, Gradient도 막힘없이 흘러요.

### Convolution, Filter, Stride, Padding, Pooling이란? 출력 크기 공식은?
E: 돋보기(Filter)로 사진을 왼쪽 위부터 한 칸씩 훑으며 "여기에 세로선이 있나?"를 점수로 적는 것이 Convolution입니다. 한 번에 몇 칸씩 옮기는지가 Stride, 가장자리도 보려고 테두리에 0을 두르는 것이 Padding, 구역별로 가장 큰 점수만 남겨 크기를 줄이는 것이 Pooling입니다.
A: Convolution Layer는 작은 Filter(Kernel)를 입력 위에서 밀며 각 위치의 Dot Product를 계산해 Feature Map을 만들고, Filter 값은 학습되는 Weight입니다. 입력 크기 W, Filter K, Padding P, Stride S일 때 출력 크기는 ⌊(W − K + 2P)/S⌋ + 1이며, 예를 들어 32×32에 5×5 Filter, P = 0, S = 1이면 28×28입니다. Pooling(Max·Average)은 학습 Parameter 없이 크기를 줄여 연산량을 줄이고 작은 위치 변화에 덜 민감하게 합니다.

### CNN이 MLP보다 이미지에 강한 이유는? CNN이 아닌 MLP로 해도 잘 될까?
A: CNN은 각 Neuron이 주변 픽셀만 보는 Local Connectivity(지역 연결)와, 같은 Filter를 이미지 전체에 재사용하는 Weight Sharing(가중치 공유) 덕분에 Parameter가 훨씬 적고, 고양이가 어느 위치에 있든 같은 Filter가 반응하며(Translation Equivariance), Layer를 쌓을수록 선 → 모양 → 물체로 계층적 특징을 배웁니다. MLP도 MNIST처럼 작고 가운데 정렬된 이미지에서는 약 98% 정확도로 잘 되지만, 224×224×3 이미지를 Hidden Neuron 1,000개에 연결하면 첫 Layer만 약 1.5억 개 Weight가 필요하고 공간 구조를 무시해 데이터가 훨씬 많이 필요합니다. (다만 초대규모 데이터가 있으면 ViT·MLP-Mixer처럼 Convolution이 없는 구조도 경쟁력이 있습니다.)

### ResNet의 Residual Connection은 왜 깊은 망을 학습 가능하게 하나요?
E: 긴 계단 옆에 엘리베이터를 놓은 것입니다. 각 층은 "원래 것에서 조금만 고칠 부분"만 배우면 되고, 신호는 엘리베이터로 바로 오갈 수 있습니다.
A: Residual Connection(Skip Connection)은 Block의 출력을 y = F(x) + x로 만들어 Layer가 목표 함수 전체가 아니라 Residual F(x)만 배우게 합니다. Backpropagation 때 Gradient가 +x 경로(Identity Mapping)를 통해 줄어들지 않고 앞쪽 Layer까지 전달되고, 필요 없는 Layer는 F(x) ≈ 0으로 쉽게 Identity Function이 될 수 있어, Layer를 늘리면 오히려 Training 오차가 커지는 Degradation 문제를 해결하고 152층 같은 깊은 망을 학습시켰습니다. Transformer도 모든 Block에 Residual Connection을 씁니다.

## Sequence Model

#### Time Series와 AR Model
ONE: **Time Series**는 **시간 순서가 의미를 갖는** 데이터예요. **AR(p) Model**은 현재 값을 **직전 p개 값의 가중합 + 잡음**으로 예측해요.
LIKE: 내일 기온을 "오늘·어제·그제 기온의 가중 평균 + 약간의 운"으로 예측하는 거예요.
STEP:
1. **Time Series 예**: 주가, 기온, 매출, 센서 값, 웹 트래픽.
2. **특징**: 가까운 시점끼리 비슷해요(Autocorrelation). 그래서 "샘플들이 서로 독립"이라는 보통 ML의 가정이 깨져요.
3. **AR(p) (Autoregressive, 자기회귀)**: xₜ = c + φ₁xₜ₋₁ + … + φₚxₜ₋ₚ + εₜ. 자기 자신의 과거로 자신을 Regression해요.
4. 계수 φ는 Least Squares 등으로 추정해요.
5. **나누기 주의**: Training·Validation은 반드시 **과거 → 미래 순서**로 나눠야 해요. 무작위로 섞으면 미래로 과거를 맞히는 셈이에요(Data Leakage).
END: 시간 순서가 중요한 데이터는 과거 값으로 현재를 예측하고, 반드시 과거로 배우고 미래로 검증해요.

#### RNN: 요약 메모를 고쳐 쓰며 읽기
ONE: **RNN**은 순서대로 하나씩 읽으면서 **이전까지의 요약(Hidden State)**과 **현재 입력**을 합쳐 새 요약을 만들어요. 하지만 **길어지면 앞부분을 잊고**, 순서대로 계산해야 해서 **느려요**.
LIKE: 책을 한 단어씩 읽으며 머릿속 요약 메모를 계속 고쳐 쓰는 거예요. 메모장 크기가 정해져 있어서, 책이 길어지면 첫 장 내용은 점점 흐려져요.
STEP:
1. **매 시점**: hₜ = tanh(Wₕhₜ₋₁ + Wₓxₜ + b). 이전 요약 hₜ₋₁과 현재 단어 xₜ로 새 요약 hₜ를 만들어요.
2. **같은 Weight 공유**: 모든 시점에 같은 Wₕ, Wₓ를 써서 길이가 다른 문장도 처리해요.
3. **학습 (BPTT)**: 시간 축으로 펼친 Network에 Backpropagation을 적용해요(Backpropagation Through Time).
4. **긴 문장에 약한 이유**: Gradient가 같은 Wₕ와 tanh 미분을 시점 수만큼 반복해서 곱해서, 먼 과거로 갈수록 사라지거나 폭발해요(Long-Term Dependency 문제).
5. **느린 이유**: hₜ를 구하려면 hₜ₋₁이 먼저 있어야 해서 순서대로만 계산할 수 있어요. GPU 병렬화가 어려워요.
END: RNN은 요약을 이어 쓰며 순서를 기억하지만, 길면 잊고 병렬화가 어려워요.

#### LSTM과 GRU: 지우개와 펜이 달린 메모장
ONE: **LSTM**은 별도의 장기 기억 통로(**Cell State**)와 **세 개의 Gate**(잊기·쓰기·꺼내기)를 둬서, 무엇을 기억하고 무엇을 잊을지 스스로 정해 **긴 문장도 기억해요**.
LIKE: 메모장(Cell State)에 지우개(Forget Gate), 펜(Input Gate), "지금 말할 부분만 보여 주는" 가림판(Output Gate)을 단 거예요.
STEP:
1. **Cell State cₜ**: 정보가 길게 흘러가는 컨베이어 벨트예요.
2. **Forget Gate fₜ**: 이전 기억을 얼마나 남길지 0~1로 정해요. 0이면 지우고 1이면 그대로.
3. **Input Gate iₜ**: 새 정보 후보를 얼마나 적을지 정해요.
4. **Output Gate oₜ**: 기억 중 얼마나 꺼내서 출력할지 정해요.
5. **갱신**: cₜ = fₜ ⊙ cₜ₋₁ + iₜ ⊙ c̃ₜ. 핵심은 **덧셈 경로**라는 거예요. 곱셈을 반복하는 RNN과 달리 Gradient가 오래 살아남아요.
6. **출력**: hₜ = oₜ ⊙ tanh(cₜ).
7. **GRU**: Gate를 2개(Update, Reset)로 줄이고 Cell State와 Hidden State를 합쳤어요. Parameter가 적고 빠르며, 성능은 비슷한 경우가 많아요.
END: LSTM = 지우개·펜·가림판이 달린 메모장. 덧셈 경로 덕분에 오래 기억해요. GRU는 더 가벼운 버전이에요.

### Time Series 데이터와 AR(p) Model이란?
E: 내일 기온을 "오늘·어제·그제 기온의 가중 평균 + 약간의 운"으로 예측하는 것입니다.
A: Time Series(시계열)는 시간 순서가 의미를 갖는 데이터로, 인접한 값끼리 상관(Autocorrelation)이 있어 샘플이 독립이라는 가정이 깨집니다. AR(p)(Autoregressive, 자기회귀) Model은 xₜ = c + φ₁xₜ₋₁ + … + φₚxₜ₋ₚ + εₜ처럼 현재 값을 직전 p개 값의 Linear Combination과 잡음으로 설명하며, 계수는 Least Squares 등으로 추정합니다. Training·Validation은 반드시 과거 → 미래 순서로 나눕니다.

### RNN은 어떻게 순서를 기억하고, 왜 긴 문장에 약한가요? (BPTT)
E: 책을 한 단어씩 읽으며 머릿속 요약 메모를 계속 고쳐 쓰는 것입니다. 메모장 크기는 정해져 있어서 책이 길어지면 첫 장 내용은 점점 흐려집니다.
A: RNN(Recurrent Neural Network)은 매 시점 hₜ = tanh(Wₕhₜ₋₁ + Wₓxₜ + b)처럼 이전 Hidden State와 현재 입력을 합쳐 새 State를 만들고, 같은 Weight를 모든 시점에 공유해 길이가 다른 Sequence를 처리합니다. 학습은 시간 축으로 펼친 Network에 Backpropagation을 적용하는 BPTT(Backpropagation Through Time)로 하는데, Gradient가 같은 Wₕ와 tanh 미분을 시점 수만큼 반복해서 곱하므로 Vanishing·Exploding해 먼 과거의 정보를 배우기 어렵고(Long-Term Dependency 문제), 순서대로 계산해야 해서 병렬화도 어렵습니다.

### LSTM의 세 Gate와 Cell State는? GRU와의 차이는?
E: LSTM은 메모장(Cell State)에 지우개(Forget Gate), 펜(Input Gate), "지금 말할 부분만 보여 주는" 가림판(Output Gate)을 달아, 무엇을 잊고 무엇을 적고 무엇을 꺼낼지 스스로 정합니다.
A: LSTM(Long Short-Term Memory)은 Hidden State 외에 Cell State cₜ를 두고, Forget Gate fₜ가 이전 기억을 얼마나 남길지, Input Gate iₜ가 새 후보 c̃ₜ를 얼마나 더할지, Output Gate oₜ가 얼마나 내보낼지를 Sigmoid(0~1)로 정합니다. Cell 갱신이 cₜ = fₜ ⊙ cₜ₋₁ + iₜ ⊙ c̃ₜ로 곱셈이 아닌 덧셈 경로라 Gradient가 오래 살아남고, 출력은 hₜ = oₜ ⊙ tanh(cₜ)입니다. GRU(Gated Recurrent Unit)는 Update·Reset Gate 2개로 Cell State와 Hidden State를 합쳐 Parameter가 적고 빠르며 성능은 비슷한 경우가 많습니다.

## Attention과 Transformer

#### Attention: 어디를 볼지 스스로 정하기
ONE: **Attention**은 지금 처리하는 위치가 **다른 모든 위치 중 어디를 얼마나 참고할지** 가중치로 정해서 정보를 모으는 방법이에요. **Query·Key·Value** 세 가지로 동작해요.
LIKE: 도서관에서 내 궁금증(Query)을 책등의 제목(Key)과 비교해서, 관련 있는 책일수록 더 많이 읽고, 그 책들의 내용(Value)을 관련도만큼 섞어 답을 만드는 거예요.
STEP:
1. **예**: "그 동물은 너무 피곤해서 길을 건너지 않았다"에서 "그"가 무엇을 가리키는지 알려면 "동물"을 많이 참고해야 해요.
2. **Query (Q)**: 지금 위치가 찾고 싶은 것. **Key (K)**: 각 위치가 가진 "색인 정보". **Value (V)**: 각 위치의 실제 내용.
3. **유사도**: Q와 각 K의 Dot Product로 "얼마나 관련 있나" 점수를 매겨요.
4. **가중치**: 점수를 √dₖ로 나눈 뒤 Softmax로 합이 1인 비율로 바꿔요.
5. **결과**: 그 비율로 V들을 가중 평균해요.
6. **공식**: Attention(Q, K, V) = softmax(QKᵀ / √dₖ) V.
7. **√dₖ로 나누는 이유**: 차원이 크면 Dot Product 값이 커져서 Softmax가 한쪽에 몰리고(Saturation) Gradient가 작아져요. 나눠서 크기를 맞춰요.
8. **Self-Attention**: Q·K·V를 모두 같은 문장에서, 서로 다른 Weight Matrix를 곱해 만들어요.
9. **Multi-Head Attention**: 이걸 여러 세트로 병렬로 해요. 한 Head는 문법 관계를, 다른 Head는 의미 관계를 보는 식으로 다양한 관점을 동시에 봐요.
END: Query로 Key를 찾아 관련도만큼 Value를 섞어요. 문장 속 어디를 볼지 모델이 스스로 정해요.

#### Transformer가 RNN을 대체한 이유
ONE: **Transformer**는 순환 없이 **Self-Attention으로 모든 위치를 한 번에** 처리해요. 그래서 **병렬 학습**이 되고 **먼 단어 관계**도 잘 배워, 2017년 이후 LLM의 기반이 됐어요.
LIKE: RNN은 한 줄로 서서 귓속말을 전하는 거라 느리고 말이 흐려져요. Transformer는 모두가 한 회의실에 모여 동시에 서로를 보는 거예요. 단, 회의실에는 자리 순서가 없으니 각자 번호표(Positional Encoding)를 달아야 순서를 알아요.
STEP:
1. **병렬화**: RNN은 앞 단어 계산이 끝나야 다음 단어를 계산해요. Transformer는 모든 단어를 동시에 계산해서 GPU를 꽉 채워 써요.
2. **먼 관계**: RNN은 100단어 떨어진 관계를 100단계 거쳐 전달해요. Transformer는 어느 두 위치든 **한 단계**로 연결돼요.
3. **Scaling**: 모델·데이터를 키울수록 성능이 잘 올라서 거대 언어 모델(LLM)이 가능해졌어요.
4. **약점**: 모든 쌍을 비교해서 Attention 비용이 문장 길이 n에 대해 **O(n²)**예요. 긴 문서에서 비싸요.
5. **Positional Encoding이 필요한 이유**: Self-Attention은 단어 순서를 섞어도 결과가 똑같이 자리만 바뀌어요. "개가 사람을 물었다"와 "사람이 개를 물었다"를 구별하려면 위치 정보를 넣어 줘야 해요. 사인·코사인 값(Sinusoidal), 학습된 위치 Embedding, RoPE 같은 방법이 있어요.
6. **Block 구조**: Multi-Head Self-Attention → Feed-Forward Network, 각 단계마다 Residual Connection + Layer Normalization.
7. **세 가지 형태**: Encoder만(BERT, 이해에 강함), Decoder만(GPT, 생성에 강함), 둘 다(원래 Transformer, T5, 번역).
| 비교 | RNN | Transformer |
| 처리 방식 | 순서대로 하나씩 | 모든 위치 동시에 |
| 병렬화 | 어려움 | 쉬움 |
| 먼 단어 관계 | 길수록 약해짐 | 한 단계로 연결 |
| 길이 n에 대한 비용 | O(n) 순차 | O(n²) Attention |
END: 모두가 동시에 서로를 보니 빠르고 먼 관계도 잘 잡아요. 대신 순서는 번호표로 알려 줘야 하고 길이가 길면 비싸요.

### Attention이란? Query·Key·Value는?
E: 도서관에서 내 궁금증(Query)을 책등의 제목(Key)과 비교해 관련 있는 책일수록 더 많이 읽고, 그 책들의 내용(Value)을 관련도만큼 섞어 답을 만드는 것입니다.
A: Attention은 현재 위치가 다른 모든 위치 중 어디를 얼마나 참고할지를 학습된 가중치로 정해 정보를 모으는 방법입니다. Scaled Dot-Product Attention은 Attention(Q, K, V) = softmax(QKᵀ/√dₖ)V로, Query와 각 Key의 Dot Product로 유사도를 구해 Softmax로 가중치를 만든 뒤 Value를 가중 평균하며, √dₖ로 나누는 것은 Dot Product가 커져 Softmax가 Saturation되는 것을 막기 위해서입니다. Q·K·V는 같은 입력에 서로 다른 Weight Matrix를 곱해 만들고(Self-Attention), 여러 세트를 병렬로 쓰는 것이 Multi-Head Attention입니다.

### Transformer가 RNN을 대체한 이유는? Positional Encoding은 왜 필요한가요?
E: RNN은 한 줄로 서서 귀엣말을 전하는 것이라 느리고 말이 흐려지지만, Transformer는 모두가 한 회의실에 모여 동시에 서로를 보는 것입니다. 단, 회의실에서는 자리 순서가 없으니 각자 번호표(Positional Encoding)를 달아야 순서를 압니다.
A: Transformer는 순환 없이 Self-Attention으로 모든 위치를 한 번에 처리해 GPU에서 병렬 학습이 가능하고, 어느 두 위치든 한 단계로 연결되어 Long-Range Dependency를 잘 배우며, 모델·데이터를 키울수록 성능이 잘 오릅니다. 대신 Attention 비용이 Sequence 길이 n에 대해 O(n²)입니다. Self-Attention은 입력 순서를 바꿔도 결과가 똑같이 자리만 바뀌는 연산(Permutation Equivariant)이라 순서 정보가 없으므로, Sinusoidal Positional Encoding, 학습된 Positional Embedding, RoPE 같은 방법으로 위치 정보를 넣어 줍니다.

## Generative Model과 적은 데이터 학습

#### Generative Model: GAN · Autoencoder · VAE
ONE: **Generative Model**은 데이터를 분류하는 대신 **새 데이터를 만들어 내는** 모델이에요. **GAN**은 위조범과 경찰의 대결로, **Autoencoder**는 압축했다 복원하며, **VAE**는 압축 공간을 확률 분포로 만들어 새 샘플을 뽑아요.
LIKE: GAN은 위조지폐범(Generator)과 경찰(Discriminator)의 대결이에요. 경찰이 가짜를 잘 잡을수록 위조범 실력도 늘어 결국 진짜 같은 지폐가 나와요. Autoencoder는 긴 글을 한 줄 요약으로 줄였다가 다시 풀어 쓰는 연습이에요.
STEP:
1. **GAN의 Generator**: 무작위 잡음을 받아 가짜 샘플(이미지)을 만들어요.
2. **GAN의 Discriminator**: 진짜인지 가짜인지 판별해요.
3. 둘이 서로 이기려고 경쟁하며(Minimax Game) 함께 실력이 늘어요.
4. **GAN의 장단점**: 선명한 이미지를 만들지만, 학습이 불안정하고 비슷한 것만 만드는 **Mode Collapse**가 생길 수 있어요.
5. **Autoencoder**: Encoder가 입력을 작은 Vector(Latent)로 압축하고, Decoder가 다시 복원해요. 복원 오차를 줄이도록 학습해요. 차원 축소, 잡음 제거, 이상 탐지(복원이 잘 안 되면 이상)에 써요.
6. **VAE**: Encoder가 Latent의 **분포(평균·분산)**를 내고, 그 분포가 표준 정규 분포에 가깝도록 학습해요. 그래서 그 공간에서 아무 점이나 뽑아 Decoder에 넣으면 새 데이터가 나와요.
7. **Boltzmann Machine**: Energy가 낮은 상태일수록 자주 나오게 하는 확률 모델이에요. 이를 단순화한 RBM을 쌓아 층별로 미리 학습한 Deep Belief Network(2006)가 Deep Learning 부활의 계기 중 하나였어요. 지금은 거의 쓰지 않아요.
8. **요즘은**: 이미지 생성에는 잡음을 조금씩 걷어 내며 그림을 만드는 Diffusion Model이 주류가 됐고, 텍스트 생성은 Transformer LLM이 맡아요.
END: 경쟁으로 만들면 GAN, 압축·복원하면 Autoencoder, 압축 공간에서 뽑아 만들면 VAE예요.

#### Transfer Learning과 적은 데이터 학습
ONE: **Transfer Learning**은 큰 데이터로 **미리 배운 모델의 지식을 새 과제에 재사용**하는 방법이에요. Neural Network의 가장 큰 약점인 "데이터가 많이 필요하다"를 해결해요.
LIKE: 피아노를 치던 사람은 오르간을 처음부터 배우지 않아요. 손가락 쓰는 법은 그대로 두고 페달만 새로 익혀요. 그리고 아이가 기린 사진 한 장만 보고도 동물원에서 기린을 알아보는 것처럼, 적은 예시로 배우는 방법(One-Shot)도 있어요.
STEP:
1. **Neural Network의 약점**: 라벨 붙은 데이터가 많이 필요하고, 계산이 비싸고, 해석이 어려워요.
2. **Pre-training**: ImageNet(이미지)이나 웹 텍스트처럼 큰 데이터로 일반적인 지식을 먼저 배워요.
3. **Feature Extraction 방식**: 미리 배운 몸통(Backbone)은 고정(Freeze)하고, 마지막 Layer만 새 과제용으로 학습해요. 데이터가 아주 적을 때 좋아요.
4. **Fine-tuning 방식**: 작은 Learning Rate로 일부 또는 전체 Weight를 새 데이터에 맞춰 조금씩 고쳐요.
5. **PEFT (LoRA 등)**: 거대 모델은 전체를 고치기엔 너무 비싸서, 작은 추가 Parameter만 학습해요.
6. **One-Shot / Few-Shot Learning**: Class당 예시 1개(또는 몇 개)로 배워요. "두 사진이 같은 사람인가?"를 판단하는 거리를 배우는 Siamese Network(얼굴 인식)가 대표적이에요.
7. **LLM의 In-Context Learning**: Prompt 안에 예시 몇 개만 보여 줘도 Weight를 바꾸지 않고 과제를 수행해요.
END: 큰 데이터로 미리 배운 지식을 가져와 조금만 고치면, 적은 데이터로도 높은 성능을 내요.

### Boltzmann Machine은 무엇인가요?
A: Boltzmann Machine은 이진 확률 Unit들이 대칭 Weight로 연결된 Energy-Based Model로, 상태 x의 확률을 P(x) ∝ exp(−E(x))로 정의해 Energy가 낮은 상태일수록 자주 나오게 합니다. 일반 Boltzmann Machine은 학습이 매우 어려워, Visible Layer와 Hidden Layer 사이에만 연결을 둔 RBM(Restricted Boltzmann Machine)을 Contrastive Divergence(CD)로 근사 학습하는 방식이 쓰였고, RBM을 쌓은 Deep Belief Network의 Layer별 Pre-training(2006)이 Deep Learning 부활의 계기가 되었습니다. 지금은 다른 Generative Model에 밀려 거의 쓰이지 않습니다.

### GAN의 Generator와 Discriminator는? Autoencoder와 VAE는?
E: GAN은 위조지폐범(Generator)과 경찰(Discriminator)의 대결입니다. 경찰이 가짜를 잘 잡을수록 위조범의 실력도 늘어 결국 진짜 같은 지폐가 나옵니다. Autoencoder는 긴 글을 한 줄 요약으로 줄였다가 다시 풀어 쓰는 연습입니다.
A: GAN(Generative Adversarial Network)에서 Generator G는 무작위 Noise z를 가짜 샘플로 바꾸고 Discriminator D는 진짜와 가짜를 구별하며, 둘은 min_G max_D E[log D(x)] + E[log(1 − D(G(z)))]라는 게임(Minimax)을 하고, 선명한 샘플을 만들지만 학습이 불안정하고 비슷한 것만 만드는 Mode Collapse가 생길 수 있습니다. Autoencoder는 Encoder가 입력을 저차원 Latent Vector로 압축하고 Decoder가 복원하도록 Reconstruction Error를 줄이며 Dimensionality Reduction·Denoising·Anomaly Detection에 쓰입니다. VAE(Variational Autoencoder)는 Encoder가 Latent Variable의 분포(평균·분산)를 내고 Reparameterization Trick으로 Sampling하며, Reconstruction Error와 Latent 분포를 Standard Normal에 가깝게 하는 KL 항을 함께 최소화(ELBO 최대화)해, Latent Space에서 샘플을 뽑아 새 데이터를 생성할 수 있습니다.

### GAN에서 Generator 쪽에도 BN을 적용해도 될까?
A: 적용할 수 있고, 대표적인 DCGAN은 Generator와 Discriminator 모두에 BN을 쓰되 Generator의 Output Layer와 Discriminator의 Input Layer에는 쓰지 않아 학습을 안정화했습니다. 다만 BN은 같은 Batch의 샘플끼리 통계를 공유해 생성 결과가 Batch 구성에 서로 영향을 받고, 추론 때 Batch가 작으면 문제가 생길 수 있으며, Discriminator에 진짜·가짜를 섞어 넣으면 통계가 오염됩니다. 그래서 최근 모델은 Instance Normalization, AdaIN·Weight Modulation(StyleGAN), Discriminator의 Spectral Normalization 같은 대안을 자주 씁니다.

### Neural Network의 가장 큰 단점은? One-Shot Learning이란?
E: 아이는 기린 사진 한 장만 보고도 동물원에서 기린을 알아봅니다. 일반 Neural Network는 기린 사진이 수천 장 필요합니다.
A: 가장 큰 단점은 Label이 달린 데이터가 많이 필요하다는 것(그리고 연산 비용과 해석 어려움)입니다. One-Shot Learning은 Class당 예시 하나(Few-Shot은 몇 개)만으로 새 Class를 인식하는 것으로, Siamese Network처럼 "두 입력이 같은가"를 판단하는 거리(Similarity)를 배워 등록된 사진 한 장과 비교하거나(얼굴 인식), Prototypical Network·Meta-Learning(MAML)으로 "빨리 배우는 법"을 배웁니다. 요즘은 거대 Pre-trained Model의 Transfer Learning과 LLM의 Prompt 속 예시(In-Context Few-Shot)도 같은 문제를 푸는 방법입니다.

### Transfer Learning과 Fine-tuning이란?
E: 피아노를 치던 사람은 오르간을 처음부터 배우지 않고 손가락 쓰는 법은 그대로 두고 페달만 새로 익힙니다.
A: Transfer Learning(전이 학습)은 ImageNet이나 웹 텍스트처럼 큰 데이터로 미리 학습한 모델의 지식을 새 과제에 재사용하는 것입니다. Backbone을 고정(Freeze)하고 마지막 Layer만 새로 학습하는 Feature Extraction 방식과, 작은 Learning Rate로 일부 또는 전체 Weight를 새 데이터에 맞춰 조정하는 Fine-tuning이 있으며, 대형 모델에서는 일부 Parameter만 학습하는 LoRA 같은 PEFT(Parameter-Efficient Fine-Tuning)를 씁니다. 적은 데이터로도 높은 성능을 내는 것이 핵심 장점입니다.

## 구현과 도구

#### PyTorch와 TensorFlow, 그리고 Debugging 요령
ONE: **PyTorch**는 코드가 실행되는 순간 계산 Graph가 만들어져 **Python처럼 자연스럽고 Debugging이 쉬워** 연구의 주류이고, **TensorFlow**는 Keras와 **배포 도구**가 강점이에요. 지금은 차이가 많이 줄었어요.
LIKE: PyTorch는 요리하면서 바로바로 맛보고 고치는 방식이고, TensorFlow(1.x)는 레시피를 미리 다 짜 두고 한 번에 요리하는 방식이었어요. 지금은 둘 다 두 방식을 모두 지원해요.
STEP:
1. **PyTorch**: Define-by-Run(실행하며 Graph 생성). 일반 Python 코드처럼 print·디버거를 쓸 수 있어요. 2.x부터 `torch.compile`로 Graph 최적화도 해요.
2. **TensorFlow**: 1.x는 Static Graph였고, 2.x부터 즉시 실행(Eager)이 기본이에요. Keras, TF Serving, TF Lite(모바일) 같은 배포 도구가 강점이에요.
3. **Debugging 요령 ① 작은 Batch로 Overfit**: 데이터 몇 개에 일부러 외우게 해서 Loss가 거의 0이 되는지 봐요. 안 되면 모델이나 Loss 코드에 Bug가 있어요.
4. **② 초기 Loss 확인**: Class 10개 Softmax면 처음 Loss가 약 ln 10 ≈ 2.3이어야 해요.
5. **③ 데이터 눈으로 보기**: 입력 이미지와 Label을 직접 그려서 짝이 맞는지 확인해요.
6. **④ Shape·dtype·device 출력**, Gradient 크기와 NaN 감시.
7. **흔한 실수**: `model.train()`/`eval()` 전환 잊기, `optimizer.zero_grad()` 누락, Softmax를 두 번 적용하기.
8. Seed를 고정해 재현 가능하게 하고, 문제가 있으면 Learning Rate부터 바꿔 봐요.
END: 연구는 PyTorch, 배포 도구는 TensorFlow가 강했지만 차이는 줄었어요. Debugging은 "작은 데이터로 외우게 해 보기"부터 시작해요.

### TensorFlow와 PyTorch의 특징과 차이는?
A: PyTorch는 코드가 실행되는 순간 Graph가 만들어지는 Dynamic 방식(Define-by-Run)이라 Python처럼 자연스럽고 Debugging이 쉬워 연구와 최근 오픈소스 모델의 주류이며, 2.x부터 `torch.compile`로 Graph 최적화도 합니다. TensorFlow는 1.x에서 Static Graph였지만 2.x부터 Eager Execution(즉시 실행)이 기본이고 `tf.function`으로 Graph를 만들며, 고수준 API Keras와 TF Serving·TF Lite·TF.js 같은 배포 도구가 강점입니다. 지금은 기능 차이가 많이 줄어 팀과 배포 환경에 맞춰 고릅니다.

### TF·PyTorch를 사용할 때 Debugging 노하우는?
A: 먼저 작은 Batch 하나에 일부러 Overfitting시켜 Loss가 거의 0까지 내려가는지 확인하고(안 되면 모델·Loss 코드에 Bug), 초기 Loss가 예상값과 맞는지 봅니다(Class 10개 Softmax면 약 ln 10 ≈ 2.3). 입력 이미지와 Label을 직접 시각화해 Data Pipeline을 점검하고, Tensor shape·dtype·device를 출력하며, Gradient 크기와 NaN을 Monitoring합니다(`torch.autograd.set_detect_anomaly`). `model.train()`/`eval()` 전환, `optimizer.zero_grad()` 누락, Softmax를 두 번 적용하는 실수가 흔하며, Seed를 고정해 재현성(Reproducibility)을 확보하고 Learning Rate부터 바꿔 봅니다.

### numpy로 MNIST MLP Classifier를 만들면 몇 줄이고 몇 시간 걸릴까? Backpropagation은 몇 줄이고 CNN으로 바꾸면? Framework로는?
A: 정답이 있는 질문이 아니라 구현 경험을 보는 질문이라, 구성 요소를 나눠 검토한 어림값으로 답합니다. Hidden Layer 1개 MLP는 데이터 로딩·One-Hot 변환·Initialization·Forward Pass(ReLU, Softmax)·Cross-Entropy·Backpropagation·Mini-Batch SGD Loop·Accuracy 계산까지 대략 50~100줄이고, 그중 Backpropagation은 Softmax+Cross-Entropy의 Gradient가 "예측 − 정답"으로 간단해져 Layer당 2~3줄, 합쳐 10줄 안팎입니다. 개념을 아는 사람이면 1~3시간 안에 Test Accuracy 약 97~98%까지 갈 수 있고, 시간의 대부분은 shape 실수와 Gradient Debugging입니다. CNN으로 바꾸면 Convolution과 Pooling의 Forward·Backward(im2col 등)를 직접 써야 해서 수십~100줄 정도가 더 들고 속도도 느립니다. PyTorch·Keras로는 Dataset·Layer·Autograd가 제공되어 30~50줄, 익숙하면 수십 분~1시간이면 충분합니다.

## GPU와 자원

#### GPU가 빠른 이유와 여러 GPU 쓰기
ONE: Neural Network 계산은 대부분 **서로 독립적인 곱셈·덧셈이 엄청나게 많은 Matrix 곱셈**이라, **수천 개의 Core로 동시에** 계산하는 GPU가 훨씬 빨라요. GPU 여러 개는 **데이터를 나누거나(Data Parallel)** **모델을 나눠(Model Parallel)** 써요.
LIKE: CPU는 무엇이든 잘하는 요리사 몇 명, GPU는 감자만 깎는 보조 요리사 수천 명이에요. 감자 만 개를 깎아야 한다면 후자가 훨씬 빨라요.
STEP:
1. **CPU**: 복잡한 일을 빠르게 처리하는 강력한 Core 몇 개~수십 개.
2. **GPU**: 단순한 계산을 하는 Core 수천 개 + CPU보다 훨씬 넓은 Memory Bandwidth.
3. Matrix 곱셈은 각 칸의 계산이 서로 독립이라 수천 개 Core가 동시에 처리할 수 있어요.
4. **Tensor Core와 Mixed Precision**: FP16·BF16 같은 작은 숫자 형식으로 Matrix 곱을 더 빠르게 해요.
5. **Data Parallelism**: 모델을 GPU마다 복사하고 Batch를 나눠 계산한 뒤, Gradient를 평균(All-Reduce)해서 모두 같은 Weight로 갱신해요. 모델이 GPU 하나에 들어갈 때 써요. PyTorch는 DistributedDataParallel(DDP)을 권장해요.
6. **Model Parallelism**: 모델이 GPU 하나에 안 들어갈 때 Layer를 나눠 담거나(Pipeline), 한 Layer의 Matrix를 쪼개 담아요(Tensor).
7. **FSDP·ZeRO**: Parameter·Gradient·Optimizer State를 GPU들에 나눠 저장해서 Memory를 아껴요.
END: 독립적인 계산이 엄청 많으니 Core가 많은 GPU가 빨라요. 여럿이면 데이터를 나누거나 모델을 나눠요.

#### 학습에 필요한 GPU Memory 계산
ONE: 학습 Memory = **Parameter + Gradient + Optimizer State + Activation**이에요. FP32와 Adam이면 Parameter 하나당 약 **16 Byte**가 들어요.
LIKE: 공장을 돌리려면 기계(Parameter)뿐 아니라, 고칠 점 메모(Gradient), 작업 일지(Optimizer State), 공정마다 쌓아 둔 중간 제품(Activation)을 둘 공간도 필요해요.
STEP:
1. **Parameter**: FP32면 하나당 4 Byte.
2. **Gradient**: Parameter마다 하나씩, 4 Byte.
3. **Adam의 Optimizer State**: m과 v 두 개, 8 Byte.
4. **합계**: 약 16 Byte × Parameter 수. 10억 개 모델이면 Activation을 빼고도 약 16GB.
5. **Activation**: Backpropagation에 쓰려고 저장한 중간 출력이에요. Batch Size·문장 길이·Layer 수에 비례해서 늘어요.
6. **추론**: 대체로 Parameter만 있으면 돼요. 70억 개 모델을 FP16(2 Byte)으로 올리면 약 14GB이고, LLM은 KV Cache가 추가돼요.
7. **부족할 때**: Batch 줄이기, Mixed Precision(FP16·BF16), Activation을 다시 계산하는 Gradient Checkpointing, 작은 Batch 여러 번의 Gradient를 모으는 Gradient Accumulation, 숫자를 더 작게 저장하는 Quantization.
END: 학습은 Parameter당 약 16 Byte + Activation, 추론은 대체로 Parameter 크기만큼이에요.

### Deep Learning에 GPU를 쓰면 좋은 이유는?
E: CPU는 무엇이든 잘하는 요리사 몇 명, GPU는 감자만 깎는 수천 명의 보조 요리사입니다. 감자 만 개를 벗겨야 한다면 후자가 훨씬 빠릅니다.
A: Neural Network 연산의 대부분은 서로 독립적인 곱셈·덧셈이 엄청나게 많은 Matrix Multiplication이고, GPU는 수천 개의 Core로 이를 동시에 처리하며 Memory Bandwidth도 CPU보다 훨씬 넓습니다. Tensor Core가 FP16·BF16 Mixed Precision Matrix 곱을 더 가속하고, CUDA·cuDNN 같은 최적화 Library가 있어 학습이 수십 배 이상 빨라집니다.

### GPU를 두 개 다 쓰고 싶다면? (Data Parallelism vs Model Parallelism)
A: Data Parallelism은 모델을 두 GPU에 복사하고 Batch를 반씩 나눠 계산한 뒤 Gradient를 평균(All-Reduce)해 같은 Weight로 갱신하는 방식으로, 모델이 GPU 하나에 들어갈 때 쓰며 PyTorch에서는 DataParallel보다 DistributedDataParallel(DDP)을 권장합니다. Model Parallelism은 모델이 한 GPU에 안 들어갈 때 Layer를 나눠 담거나(Pipeline Parallelism) 한 Layer의 Matrix를 쪼개 담는(Tensor Parallelism) 방식이며, Parameter·Gradient·Optimizer State를 GPU들에 나눠 저장하는 FSDP·ZeRO도 널리 씁니다.

### 학습 시 필요한 GPU Memory는 어떻게 계산하나요?
A: 학습 Memory는 Parameter + Gradient + Optimizer State + Activation(Backpropagation을 위해 저장하는 중간 출력)입니다. FP32에 Adam이면 Parameter 4 Byte + Gradient 4 Byte + Adam의 m·v 8 Byte로 Parameter당 약 16 Byte라 10억 개 모델은 Activation을 빼고도 약 16GB가 필요하고, Activation은 Batch Size·Sequence 길이·Layer 수에 비례해 늘어납니다. 추론은 대체로 Parameter만 있으면 되어 70억 개 모델을 FP16으로 올리면 약 14GB(+LLM은 KV Cache)이며, 부족하면 Batch 축소, Mixed Precision, Gradient Checkpointing, Gradient Accumulation, Quantization을 씁니다.
