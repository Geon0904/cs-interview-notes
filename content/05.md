## 언어 공통 개념

#### Programming Language의 실행 방식: Compile · Interpret · Bytecode
ONE: 사람이 쓴 코드를 CPU가 이해하는 기계어로 바꾸는 방법은 **미리 통째로 번역(Compile)**, **실행하면서 해석(Interpret)**, 그리고 둘의 중간인 **Bytecode + Virtual Machine**이 있어요.
LIKE: Compile은 책 한 권을 미리 통째로 번역해 두는 것이고, Interpret는 통역사가 옆에서 문장을 바로바로 통역하는 거예요. 번역본은 읽기 빠르고, 통역은 바로 시작할 수 있어요.
STEP:
1. CPU는 기계어(0과 1로 된 명령)만 알아요. 사람이 쓴 코드(Source Code)는 반드시 번역해야 해요.
2. **Compiled Language (C, C++, Rust, Go)**: 실행 전에 Compiler가 Source 전체를 기계어 실행 파일로 번역해요. 실행이 빠르고, 많은 오류를 실행 전에 잡아요. 대신 고칠 때마다 다시 Compile해야 해요.
3. **Interpreted 방식**: 실행하면서 코드를 해석해요. 고치고 바로 실행해 볼 수 있어 개발이 빨라요. 대신 실행이 느려요.
4. **중간 방식 (Java, Python)**: Source를 먼저 **Bytecode**라는 중간 언어로 바꾸고, **Virtual Machine(VM)**이 그 Bytecode를 실행해요. Bytecode는 특정 CPU에 묶이지 않아서 같은 코드가 여러 OS에서 돌아요.
5. **JIT (Just-In-Time) Compile**: 실행 중에 자주 쓰는 부분을 그때그때 기계어로 바꿔 빠르게 만드는 기술이에요. Java의 JVM, JavaScript 엔진, PyPy가 써요.
WHY: "빨리 실행"과 "빨리 개발" 중 무엇이 중요한지에 따라 언어와 실행 방식을 골라요.
END: 미리 다 번역하면 Compile(빠른 실행), 실행하며 해석하면 Interpret(빠른 개발). Python과 Java는 Bytecode를 VM이 실행하는 중간 방식이에요.

#### Type System: Static vs Dynamic, Strong vs Weak
ONE: **Static/Dynamic**은 "Type을 **언제** 정하나(실행 전 vs 실행 중)", **Strong/Weak**는 "다른 Type끼리 **멋대로 섞어** 주나"의 기준이에요.
LIKE: Static Typing은 상자에 "사과만"이라고 미리 적어 두는 것, Dynamic Typing은 넣는 순간 그 상자의 종류가 정해지는 거예요. Strong Typing은 사과와 숫자를 더하라고 하면 거절하고, Weak Typing은 알아서 바꿔서 더해 버려요.
STEP:
1. **Type(자료형)**: 값의 종류예요. 정수(int), 실수(float), 문자열(str) 등.
2. **Static Typing (Java, C++, Go)**: Variable의 Type을 Compile할 때 정해요. `int x = 3;` Type이 안 맞으면 실행 전에 오류가 나요.
3. **Dynamic Typing (Python, JavaScript)**: 실행 중에 값이 들어올 때 Type이 정해져요. `x = 3` 다음에 `x = "hi"`도 돼요.
4. **Strong Typing (Python)**: 다른 Type끼리 자동으로 바꿔 주지 않아요. `"1" + 1`은 TypeError예요.
5. **Weak Typing (JavaScript)**: 알아서 바꿔 계산해요. `"1" + 1`은 `"11"`이 돼요. 편하지만 예상 못 한 결과가 나오기 쉬워요.
6. 두 기준은 따로예요. Python은 **Dynamic + Strong**, JavaScript는 **Dynamic + Weak**, Java는 **Static + Strong**이에요.
PRO: Static은 오류를 미리 잡고 도구(자동 완성)가 똑똑해져요. Dynamic은 짧고 유연하게 쓸 수 있어요.
CON: Static은 코드가 길어지고, Dynamic은 Type 오류를 실행해 봐야 알 수 있어요.
USE: Python에서도 `def add(a: int, b: int) -> int:`처럼 **Type Hint**를 쓰고 mypy 같은 도구로 검사하면 Static Typing의 장점을 일부 얻을 수 있어요.
END: Static/Dynamic은 "언제 정하나", Strong/Weak는 "멋대로 섞나"예요. Python은 실행 중에 정하지만 멋대로 섞지는 않아요.

#### Variable은 이름표: Reference와 Argument 전달
ONE: Python의 Variable은 값을 담는 상자가 아니라 **Object에 붙이는 이름표**예요. 함수에 넘길 때도 "같은 Object를 가리키는 이름표"를 하나 더 만들어 줘요(**Call by Object Reference**).
LIKE: `b = a`는 물건을 복사하는 게 아니라, 같은 물건에 포스트잇을 한 장 더 붙이는 거예요. 그래서 b로 물건을 고치면 a로 봐도 고쳐져 있어요. 하지만 b 포스트잇을 떼어 다른 물건에 붙이면 a는 그대로예요.
STEP:
1. `a = [1, 2]`는 list Object를 만들고 거기에 `a`라는 이름표를 붙여요.
2. `b = a`는 같은 list에 `b` 이름표를 하나 더 붙여요. 복사가 아니에요.
3. `b.append(3)`으로 물건을 고치면, `a`로 봐도 `[1, 2, 3]`이에요.
4. `b = [9]`는 `b` 이름표를 떼어 새 list에 붙이는 거예요. `a`는 여전히 원래 list를 가리켜요.
5. **함수 Argument**: 함수에 `a`를 넘기면, 함수 안의 Parameter가 같은 Object에 붙은 새 이름표가 돼요.
6. 그래서 함수 안에서 list를 **고치면** 밖에도 보이지만, Parameter에 **새 Object를 대입하면** 밖은 그대로예요.
```python
def change(lst):
    lst.append(4)   # 같은 list를 고침 → 밖에서도 보임
    lst = [0]       # 이름표를 새 list로 옮김 → 밖은 그대로

a = [1, 2, 3]
change(a)
print(a)  # [1, 2, 3, 4]
```
KEY: 다른 언어의 용어로는 C가 **Call by Value**(복사본 전달), C++의 참조(&)가 **Call by Reference**(변수 자체 전달)예요. Python은 둘 다 아니고 "Reference를 값으로 전달"하는 **Call by Sharing**이에요.
WHY: 이걸 모르면 "함수에 넘겼더니 원본이 바뀌었다"거나 "바꿨는데 안 바뀌었다"는 Bug를 이해할 수 없어요.
END: Variable은 이름표예요. 물건을 고치면 모든 이름표에서 보이고, 이름표를 옮기면 그 이름표만 바뀌어요.

#### Garbage Collection (자동 메모리 정리)
ONE: 더 이상 아무도 쓰지 않는 Object를 **언어가 자동으로 찾아 Memory를 돌려받는** 기능이에요. 대표 방식은 **Reference Counting**과 **Tracing**이에요.
LIKE: Reference Counting은 물건마다 "이름표가 몇 개 붙었나" 세다가 0개가 되면 바로 버리는 것이고, Tracing은 가끔 창고 전체를 돌면서 "아무 데서도 이어지지 않는 물건"을 한꺼번에 치우는 거예요.
STEP:
1. C에서는 `malloc`으로 빌린 Memory를 직접 `free`해야 했어요. 잊으면 Memory Leak, 두 번 하면 Double Free.
2. **Reference Counting**: Object마다 "나를 가리키는 Reference 수"를 세요. 0이 되는 순간 바로 해제해요. 즉시 정리돼서 좋아요.
3. 약점: A가 B를, B가 A를 가리키면(**Circular Reference, 순환 참조**) 밖에서 아무도 안 써도 서로의 Count가 1이라 영원히 안 지워져요.
4. **Tracing GC (Mark-and-Sweep)**: 프로그램이 확실히 쓰고 있는 출발점(Root: 전역 변수, 실행 중인 함수의 변수)에서 따라갈 수 있는 Object에 표시(Mark)하고, 표시 안 된 것을 쓸어 담아요(Sweep). 순환 참조도 치울 수 있어요.
5. **Generational GC**: "대부분의 Object는 금방 버려진다"는 관찰을 이용해, 새로 만든 Object는 자주, 오래 살아남은 Object는 가끔 검사해요.
6. **CPython**은 Reference Counting을 기본으로 쓰고, 순환 참조는 Generational GC(`gc` 모듈)가 주기적으로 처리해요. Java는 Tracing GC를 써요.
PRO: 프로그래머가 Memory 해제를 신경 쓰지 않아도 돼서 Memory 오류가 크게 줄어요.
CON: 정리하는 데 시간이 들고, Tracing GC는 정리하는 동안 프로그램이 잠깐 멈출 수 있어요(Stop-the-World).
END: GC는 "안 쓰는 물건을 자동으로 치우는 청소부"예요. Python은 이름표 세기(Reference Counting)에 순환 참조용 청소(GC)를 더해 써요.

### Compiled Language와 Interpreted Language의 차이는?
E: Compile은 책 한 권을 미리 통째로 번역해 두는 것, Interpreter는 통역사가 옆에서 한 문장씩 바로 통역하는 것입니다. 번역본은 읽기 빠르고, 통역은 바로 시작할 수 있습니다.
A: Compiled Language(C, Rust)는 실행 전에 Source를 기계어로 번역해 실행이 빠르고 오류를 미리 잡습니다. Interpreter 방식은 실행 중에 코드를 해석해 개발·수정이 빠르지만 느립니다. 실제로는 둘의 중간도 많아서 Java와 Python은 Bytecode로 Compile한 뒤 Virtual Machine이 실행합니다.

### Static Typing vs Dynamic Typing, Strong Typing vs Weak Typing은?
E: Static Typing은 "이 상자에는 사과만"이라고 미리 적어 두는 것, Dynamic Typing은 넣는 순간 종류가 정해지는 것입니다. Strong Typing은 사과와 숫자를 더하라면 거절하고, Weak Typing은 알아서 바꿔 더해 버립니다.
A: Static Typing(Java, C++)은 Variable의 Type이 Compile 때 정해지고, Dynamic Typing(Python, JavaScript)은 실행 중 값에 따라 정해집니다. Python은 Dynamic이지만 Strong Typing이라 `"1" + 1`은 TypeError이고, JavaScript는 Weak Typing이라 `"11"`이 됩니다.

### Call by Value, Call by Reference, Python의 Argument 전달은?
E: Call by Value는 복사본을 주는 것, Call by Reference는 원본 자체를 주는 것입니다. Python은 "같은 물건에 붙은 이름표를 하나 더 만들어 주는" 방식입니다. 함수 안에서 물건을 고치면 밖에서도 바뀌지만, 이름표를 다른 물건에 옮겨 붙이면 밖은 그대로입니다.
A: Call by Value는 값을 복사해 넘겨 함수 안 변경이 밖에 영향을 주지 않고, Call by Reference는 Variable 자체를 넘겨 함수 안에서 바꾸면 밖도 바뀝니다. Python은 Object에 대한 Reference를 값으로 넘기는 Call by Object Reference(Call by Sharing)라서, list처럼 Mutable Object를 내부에서 수정하면 호출한 쪽에도 보이지만 Parameter에 새 Object를 대입하면 바깥 Variable은 바뀌지 않습니다.
```python
def change(lst):
    lst.append(4)   # 같은 list를 수정 → 밖에도 보임
    lst = [0]       # 이름표를 새 list로 옮김 → 밖은 그대로

a = [1, 2, 3]
change(a)
print(a)  # [1, 2, 3, 4]
```

### Garbage Collection 방식은?
E: Reference Counting은 물건마다 "이름표 몇 개 붙었는지" 세다가 0개가 되면 바로 버리는 것, Tracing은 가끔 창고를 돌며 "아무에게도 이어지지 않은 물건"을 한꺼번에 치우는 것입니다.
A: Reference Counting은 Object를 가리키는 Reference 수가 0이 되는 즉시 해제하지만 서로를 가리키는 Circular Reference(순환 참조)를 못 치웁니다. Tracing GC(Mark-and-Sweep, Generational GC)는 Root에서 닿을 수 없는 Object를 찾아 해제합니다. CPython은 Reference Counting을 기본으로 쓰고, Circular Reference는 Generational Cyclic GC(gc 모듈)로 처리합니다.

## Python 언어 특성

#### Python의 특징과 실행 과정
ONE: Python은 **읽기 쉬운 문법**, **자동 Memory 관리**, **방대한 Library**를 가진 범용 언어예요. 코드는 Bytecode로 바뀐 뒤 Python Virtual Machine이 실행해요.
LIKE: Python은 자동 변속기 자동차 같아요. 기어(Memory 관리, 자료구조 크기 조절)를 차가 알아서 바꿔 줘서 운전이 쉬워요. 대신 수동 변속기(C)를 잘 다루는 사람만큼 극한의 속도를 내기는 어려워요.
STEP:
1. **읽기 쉬운 문법**: 중괄호 대신 **Indentation(들여쓰기)**으로 Block을 구분해요. 그래서 들여쓰기가 틀리면 IndentationError가 나요.
2. **언어가 대신 해 주는 일**: C로 수십 줄이 필요한 일이 Python에서는 몇 줄이면 돼요. Memory 해제, 크기가 자동으로 늘어나는 list, Hash Table인 dict, 끝없이 커지는 정수를 언어가 대신 처리하니까요.
3. **실행 과정**: `.py` Source → Bytecode로 Compile(import한 Module은 `__pycache__` 폴더에 `.pyc`로 저장) → **Python Virtual Machine**이 Bytecode를 한 명령씩 실행.
4. 기계어 실행 파일을 따로 만들지 않아서 "Interpreted Language"라고 불러요. "한 줄씩 해석한다"는 흔한 설명은 정확하지 않아요. 먼저 전체를 Bytecode로 바꾼 다음 실행해요.
5. **대가는 속도**: 같은 계산을 순수 Python으로 하면 C보다 훨씬 느려요. 그래서 무거운 계산은 C로 만든 Library(NumPy 등)에 맡기는 게 일반적이에요.
6. **Python vs CPython**: Python은 언어의 규칙(명세)이고, **CPython**은 그 규칙을 C로 구현한 표준 Interpreter예요(python.org에서 받는 것). 그 밖에 JIT로 빠른 **PyPy**, 작은 기기용 **MicroPython** 등이 있어요. GIL이나 Small Integer Cache 같은 특징은 CPython의 구현 방식이에요.
USE: 데이터 분석, AI(PyTorch, TensorFlow), 웹 서버(Django, FastAPI), 업무 자동화 Script, 교육에 널리 쓰여요.
END: Python은 "개발 속도를 얻고 실행 속도를 조금 내준" 언어이고, 무거운 계산은 C로 만든 Library로 보완해요.

#### Python 코드 스타일: PEP 8 · Comment · Docstring
ONE: **PEP 8**은 Python 공식 코드 스타일 안내서이고, 코드 설명은 `#` **Comment**와 함수·Class 첫 줄의 **Docstring**으로 남겨요.
LIKE: 같은 반 친구들이 공책 정리 규칙(제목은 빨간색, 날짜는 오른쪽 위)을 맞추면 서로의 공책을 빨리 읽을 수 있어요. PEP 8은 Python 개발자들의 공책 정리 규칙이에요.
STEP:
1. **들여쓰기**: Space 4칸.
2. **이름 짓기**: 함수·Variable은 `snake_case`(소문자 + 밑줄), Class는 `CapWords`(단어 첫 글자 대문자), 상수는 `UPPER_CASE`.
3. **한 줄 길이**: 79자 이내를 권장해요(팀에 따라 더 길게 쓰기도 해요).
4. **Case Sensitive**: `name`과 `Name`은 서로 다른 Variable이에요.
5. **Comment**: `#` 뒤에 써요. 여러 줄 Comment는 줄마다 `#`을 붙이는 게 정석이에요.
6. **Docstring**: 함수·Class·Module의 맨 첫 줄에 쓰는 `"""설명"""` 문자열이에요. `help(함수)`나 `함수.__doc__`으로 읽을 수 있어요. 삼중 따옴표는 Comment가 아니라 문자열이라는 점이 달라요.
USE: black, ruff, flake8 같은 도구가 PEP 8에 맞춰 자동으로 검사하고 정리해 줘요.
WHY: 코드는 쓰는 시간보다 읽히는 시간이 훨씬 길어요. 모두가 같은 스타일로 쓰면 남의 코드를 내 코드처럼 빨리 읽을 수 있어요.
END: PEP 8은 Python의 공통 맞춤법이고, 설명은 Comment(#)와 Docstring(""")으로 남겨요.

### What are the key features of Python?
A: Python은 읽기 쉬운 문법(Indentation으로 Block 구분), Dynamic Typing, 자동 Memory 관리, Object-Oriented·Functional·Procedural을 모두 지원하는 Multi-Paradigm 언어입니다. 풍부한 Standard Library와 생태계(NumPy, pandas, PyTorch)가 있고 여러 OS에서 동일하게 돕니다.
P: English: Python is a readable, dynamically typed, garbage-collected, multi-paradigm language with a huge standard library and ecosystem.

### What type of language is Python? Programming or scripting?
A: Python은 범용 Programming Language이면서 자동화 Script에도 널리 쓰입니다. "Scripting Language"는 엄밀한 분류가 아니라 쓰임새에 가까운 말이라, Python으로 웹 서비스·데이터 분석·AI 같은 대규모 Application도 만듭니다.

### Python is an interpreted language. Explain.
E: Python은 책을 통째로 기계어로 번역하지 않고, 먼저 중간 언어(Bytecode) 메모로 바꾼 뒤 통역사(Virtual Machine)가 한 줄씩 읽으며 실행합니다.
A: CPython은 .py Source를 Bytecode로 Compile하고(Module은 `__pycache__`의 .pyc로 Cache), 이 Bytecode를 Python Virtual Machine이 한 명령씩 해석해 실행합니다. 기계어 Executable을 따로 만들지 않아 Interpreted Language라고 부르며, PyPy 같은 구현은 JIT로 실행 중 기계어를 만들기도 합니다.

### What makes CPython different from Python?
A: Python은 언어 명세(Specification)이고, CPython은 그 명세를 C로 구현한 표준(Reference) Implementation으로 python.org에서 받는 것이 CPython입니다. 다른 Implementation으로는 JIT를 쓰는 PyPy, JVM에서 도는 Jython, Microcontroller용 MicroPython 등이 있고, GIL·Reference Counting·Small Integer Cache 같은 특징은 CPython의 구현 세부사항입니다.

### What is the process of compilation and linking in Python?
A: C처럼 따로 Compile·Link 단계를 실행하지 않습니다. 실행하거나 import할 때 Interpreter가 자동으로 Source를 Bytecode로 Compile하고, 다른 Module과의 연결은 import 시점에 동적으로 이루어집니다. C로 작성한 Extension Module은 미리 Compile·Link해 Shared Library(.so, .pyd)로 만든 뒤 import합니다.

## Data Type과 Operator

#### Built-in Type과 Mutable · Immutable
ONE: Python의 기본 Type은 숫자·문자열·list·tuple·dict·set 등이 있고, 만든 뒤 **내용을 바꿀 수 있으면 Mutable**, **바꿀 수 없으면 Immutable**이에요.
LIKE: Mutable은 지우고 다시 쓸 수 있는 화이트보드, Immutable은 한 번 찍으면 못 바꾸는 도장이에요. 도장의 글자를 바꾸고 싶으면 새 도장을 파야 해요.
STEP:
1. **숫자**: int(정수), float(실수), complex(복소수), bool(True/False).
2. **순서 있는 묶음(Sequence)**: str(문자열), list, tuple, range.
3. **Key-Value**: dict. **집합**: set, frozenset.
4. **없음**: None.
5. **Mutable**: list, dict, set, bytearray. 만든 뒤 내용을 고칠 수 있어요.
6. **Immutable**: int, float, str, tuple, frozenset. "바꾸는" 것처럼 보이면 사실은 새 Object가 만들어진 거예요. `s = "hi"; s += "!"`는 새 문자열을 만들어 `s` 이름표를 옮겨 붙인 거예요.
7. **Type 변환**: `int("3")`, `str(10)`, `list("abc")`처럼 명시적으로 바꿔요. int와 float를 섞으면 float가 되지만, str과 int는 자동으로 섞이지 않아요.
KEY: **dict의 Key와 set의 원소는 Hashable(보통 Immutable)해야 해요.** dict는 Key의 Hash 값으로 저장 위치를 정하는데, Key 내용이 바뀌면 Hash도 바뀌어서 다시는 찾을 수 없게 되니까요.
WHY: Mutable Object를 여러 이름표가 공유하면 한쪽의 수정이 다른 쪽에 보여요. 어떤 Type이 Mutable인지 알아야 이런 Bug를 피할 수 있어요.
END: 바꿀 수 있으면 Mutable(list·dict·set), 못 바꾸면 Immutable(숫자·str·tuple). Key는 Immutable이어야 해요.

#### list · tuple · dict · set 언제 무엇을 쓸까
ONE: 순서 있는 목록은 **list**, 바뀌지 않는 묶음은 **tuple**, 이름으로 찾는 건 **dict**, 중복 없는 모음과 빠른 "있나?" 검사는 **set**이에요.
LIKE: list는 순서대로 적은 장보기 목록, tuple은 한 번 정하면 안 바뀌는 생년월일, dict는 단어를 찾으면 뜻이 나오는 사전, set은 중복 없이 모은 스티커 앨범이에요.
STEP:
1. **list**: 순서가 있고, 추가·삭제·수정이 자유로워요. 끝에 넣고 빼기(`append`, `pop()`)는 평균 O(1)이지만, 맨 앞에 넣고 빼기(`insert(0, x)`, `pop(0)`)는 뒤 원소를 모두 밀어야 해서 O(n)이에요.
2. **tuple**: list와 비슷하지만 바꿀 수 없어요. 좌표 `(x, y)`처럼 고정된 묶음에 쓰고, 원소가 모두 Hashable하면 dict Key로도 쓸 수 있어요.
3. **dict**: Key로 Value를 평균 O(1)에 찾는 Hash Table이에요. Python 3.7부터 넣은 순서가 유지돼요. 없는 Key는 `d.get(k, 기본값)`으로 안전하게 꺼내요.
4. **set**: 중복을 자동으로 없애고, `x in s` 검사가 평균 O(1)이에요. 합집합(`|`), 교집합(`&`), 차집합(`-`)도 돼요.
5. **"x in 컨테이너"의 속도**: list는 처음부터 하나씩 확인해서 O(n), set·dict는 Hash로 바로 찾아서 평균 O(1)이에요.
| 쓰임 | 고를 것 |
| 순서대로 모으고 자주 고침 | list |
| 고정된 값 묶음, dict Key | tuple |
| 이름(Key)으로 값 찾기 | dict |
| 중복 제거, 빠른 포함 검사 | set |
| 양쪽 끝에서 자주 넣고 빼기 | collections.deque |
KEY: 숫자만 잔뜩 담아 계산할 거라면 list 대신 **NumPy Array**가 훨씬 빠르고 Memory도 적게 써요.
END: 순서는 list, 고정은 tuple, 찾기는 dict, 중복 없애기와 "있나?"는 set이에요.

#### Indexing과 Slicing, 문자열 다루기
ONE: **Index**로 원소 하나를, **Slice**로 구간을 꺼내요. 음수 Index는 뒤에서부터 세고, `[::-1]`은 뒤집은 새 Sequence를 만들어요.
LIKE: 줄 선 사람들을 앞에서 0번, 1번… 으로 셀 수도 있고, 뒤에서 −1번(맨 끝), −2번… 으로 셀 수도 있어요. Slice는 "3번부터 6번 앞까지 나와 주세요"처럼 한 구간을 뽑는 거예요.
STEP:
1. **Index는 0부터** 시작해요. `s = "python"`이면 `s[0]`은 `'p'`.
2. **음수 Index**: 뒤에서부터 세요. `s[-1]`은 마지막 글자 `'n'`. 길이를 몰라도 끝에 접근할 수 있어요.
3. **Slice `[start:stop:step]`**: start부터 stop **바로 앞**까지, step 간격으로 꺼내요. `s[1:4]`는 `'yth'`.
4. 생략하면 처음·끝·1칸이 기본값이에요. `s[:2]`는 `'py'`, `s[::2]`는 `'pto'`.
5. **`[::-1]`**: step이 −1이라 거꾸로 꺼내요. 원본은 그대로 두고 뒤집힌 새 Sequence를 만들어요.
6. **len()**: 원소 수를 알려 줘요. 내부적으로 Object의 `__len__`을 불러요.
7. **문자열 Method**: `lower()`(소문자), `upper()`(대문자), `capitalize()`(첫 글자만 대문자), `title()`(단어마다 첫 글자 대문자), `split(sep)`(잘라서 list로), `" ".join(list)`(list를 하나로), `strip()`(양쪽 공백 제거).
KEY: 문자열은 Immutable이라 모든 문자열 Method는 원본을 바꾸지 않고 **새 문자열을 돌려줘요**. `s.upper()`만 쓰고 결과를 안 받으면 아무 일도 안 일어나요.
END: Index는 하나, Slice는 구간, 음수는 뒤에서, `[::-1]`은 뒤집기예요.

#### is와 ==, in과 not
ONE: **==**는 "**값**이 같은가", **is**는 "**아예 같은 Object**인가"를 물어요. **in**은 "안에 들어 있나", **not**은 "반대로"예요.
LIKE: ==는 "두 책의 내용이 같은가", is는 "이 둘이 아예 같은 한 권의 책인가"를 묻는 거예요. 똑같이 인쇄된 책 두 권은 ==지만 is는 아니에요.
STEP:
1. `a = [1, 2]; b = [1, 2]`이면 `a == b`는 True(값이 같음), `a is b`는 False(서로 다른 Object).
2. `c = a`이면 `a is c`는 True(같은 Object에 붙은 두 이름표).
3. **None 비교는 `is`**: `if x is None:`. None은 프로그램에 딱 하나뿐인 Object라서 is가 정확하고 빨라요.
4. **in**: `3 in [1, 2, 3]` → True. list는 하나씩 확인(O(n)), set·dict는 Hash로 바로 확인(평균 O(1)).
5. **not**: 논리 부정. `not in`은 "안에 없나"예요.
KEY: 숫자나 문자열 비교에 is를 쓰면 안 돼요. CPython은 −5~256 정수 같은 일부 값을 미리 하나만 만들어 재사용(**Interning**)해서 우연히 True가 나올 때가 있지만, 이건 구현 세부 사항이라 믿으면 안 돼요. 값 비교는 항상 ==예요.
END: 값은 ==, 정체는 is, None은 is None, 들어 있나는 in이에요.

A: Numeric(int, float, complex, bool), Sequence(str, list, tuple, range), Mapping(dict), Set(set, frozenset), Binary(bytes, bytearray, memoryview), None이 있습니다. 이 중 list·dict·set·bytearray는 Mutable, 나머지는 Immutable입니다.

### Mutable과 Immutable Object, 왜 dict의 Key는 Immutable이어야 하나요?
E: 도서관 사물함을 "주인 이름의 획수"로 배정했는데 주인이 개명하면 다시 찾을 수 없습니다. Key는 바뀔 수 없는 것이어야 합니다.
A: Mutable(가변) Object는 만든 뒤 내용을 바꿀 수 있고(list, dict, set), Immutable(불변) Object는 바꿀 수 없어 "변경"하면 새 Object가 생깁니다(int, str, tuple). dict는 Key의 Hash 값으로 위치를 정하므로 Key가 바뀌면 찾을 수 없어, Hashable한(보통 Immutable인) Object만 Key가 될 수 있습니다.

### What is the difference between list and tuple?
E: list는 지우고 다시 쓸 수 있는 화이트보드, tuple은 한 번 찍으면 못 바꾸는 도장입니다.
A: list는 Mutable이라 원소를 추가·삭제·수정할 수 있고, tuple은 Immutable이라 만든 뒤 바꿀 수 없습니다. tuple은 원소가 모두 Hashable이면 dict Key가 될 수 있고 조금 더 가볍습니다. 그래서 좌표 (x, y)처럼 고정된 묶음은 tuple, 바뀌는 목록은 list를 씁니다.

### What is a dictionary in Python?
E: 단어(Key)를 찾으면 뜻(Value)이 바로 나오는 사전입니다.
A: dict는 Key-Value 쌍을 저장하는 Hash Table로, Key로 Value를 평균 O(1)에 찾습니다. Key는 Hashable해야 하고, Python 3.7부터는 삽입 순서(Insertion Order)가 유지되는 것이 언어 사양입니다. `d.get(k, default)`를 쓰면 없는 Key에서 KeyError를 피합니다.

### What is the difference between Python arrays and lists? How to add / remove values?
E: list는 아무 물건이나 넣는 잡동사니 가방, array는 같은 크기 칸만 있는 계란판입니다. 계란판은 계란만 담을 수 있지만 촘촘하고 가볍습니다.
A: list는 서로 다른 Type의 Object를 담을 수 있고, array 모듈의 Array는 Type Code('i', 'f' 등)로 정한 한 가지 숫자 Type만 담아 Memory를 덜 씁니다. 수학 계산이 목적이면 보통 NumPy Array를 씁니다. 추가는 append(맨 끝 하나), extend(여러 개), insert(i, x)로, 삭제는 remove(x)(값으로 첫 번째 하나), pop(i)(위치로 꺼내며 반환), `del lst[i]`로 합니다.
M: append와 pop()(끝)은 평균 O(1), insert(0, x)와 pop(0)은 뒤 원소를 모두 밀어야 해서 O(n)입니다. 앞쪽을 자주 빼면 collections.deque를 씁니다.

### What is type conversion in Python?
A: 값을 다른 Type으로 바꾸는 것으로, `int("3")`, `float("2.5")`, `str(10)`, `list("abc")`, tuple(), set(), dict()처럼 Explicit(명시적)으로 변환합니다. `1 + 2.0`처럼 int와 float를 섞으면 float가 되는 Implicit(암시적) 변환도 있지만, str과 int는 자동으로 바뀌지 않아 TypeError가 납니다.

### What are negative indexes? What does [::-1] do? What does len() do?
E: 뒤에서부터 줄을 세면 맨 끝 사람이 −1번입니다. `[::-1]`은 "처음부터 끝까지, 한 칸씩 거꾸로" 줄을 다시 세운 새 줄입니다.
A: Negative Index는 끝에서부터 세는 위치라 `lst[-1]`은 마지막 원소이고, 길이를 몰라도 끝에 접근할 수 있어 편리합니다. `[::-1]`은 Step이 −1인 Slice로 순서를 뒤집은 새 Sequence를 만들고(원본은 그대로), len()은 Object의 원소 수를 돌려주며 내부적으로 `__len__`을 호출합니다.

### What is the purpose of is, not and in operators?
E: ==는 "두 책의 내용이 같은가", is는 "아예 같은 한 권의 책인가"를 묻는 것입니다.
A: is는 두 Variable이 같은 Object인지(Identity, 동일성)를, ==는 값이 같은지(Equality, 동등성)를 비교합니다. not은 논리 부정이고, in은 원소가 Container에 있는지 확인하는 Membership Operator입니다(list는 O(n), set·dict는 평균 O(1)). None과 비교할 때는 `x is None`을 씁니다.

### How to capitalize the first letter / convert to lowercase? What is split used for?
A: `s.capitalize()`는 첫 글자를 대문자로, 나머지는 소문자로 바꾸고(나머지를 그대로 두려면 `s[:1].upper() + s[1:]`), `s.title()`은 단어마다 첫 글자를 대문자로 바꿉니다. `s.lower()`는 모두 소문자로 바꾸고, 대소문자 무시 비교에는 casefold()가 더 정확합니다. `s.split(sep)`은 구분자(Separator)로 String을 잘라 list를 만들고, 인자가 없으면 연속된 공백(Whitespace)을 기준으로 자릅니다. String은 Immutable이라 모두 새 String을 반환합니다.

## Control Flow와 Function

#### Function과 First-Class Object
ONE: **Function**은 이름을 붙여 다시 쓰는 코드 묶음이고, Python에서는 Function도 Object라서 **Variable에 담고, 넘기고, 돌려줄 수** 있어요(**First-Class Object**).
LIKE: Function은 레시피 카드예요. 카드를 상자에 보관할 수도, 친구에게 건넬 수도, "이 카드대로 해 줘"라며 다른 요리사에게 맡길 수도 있어요.
STEP:
1. `def` 키워드로 만들고, Argument를 받아 `return`으로 값을 돌려줘요. `return`이 없으면 None을 돌려줘요.
2. **Variable에 담기**: `f = print` 다음 `f("hi")`가 돼요.
3. **Argument로 넘기기**: `sorted(words, key=len)`은 len Function을 넘겨서 "길이 기준으로 정렬해"라고 말해요.
4. **돌려주기**: Function이 Function을 만들어 돌려줄 수 있어요. 이게 Closure와 Decorator의 바탕이에요.
5. **제어문 도우미**: `break`는 반복문을 즉시 탈출, `continue`는 이번 회차만 건너뛰기, `pass`는 아무것도 안 하고 자리만 채우기예요.
6. **한 줄 조건식(Ternary)**: `label = "성인" if age >= 18 else "미성년"`.
WHY: Function을 값처럼 다룰 수 있으면 "무엇을 할지"를 나중에 끼워 넣는 유연한 코드를 쓸 수 있어요.
END: Function은 다시 쓰는 코드 묶음이고, Python에서는 값처럼 담고 넘기고 돌려줄 수 있어요.

#### lambda · map · Comprehension
ONE: **lambda**는 이름 없는 한 줄짜리 Function, **map**은 모든 원소에 같은 Function을 적용하는 도구, **Comprehension**은 이걸 더 읽기 쉽게 한 줄로 쓰는 Python 문법이에요.
LIKE: lambda는 한 번 쓰고 버리는 일회용 메모 지시문이고, map은 컨베이어 벨트 위 물건 하나하나에 같은 작업을 하는 기계예요.
STEP:
1. **lambda**: `lambda x: x * 2`는 "x를 받아 x × 2를 돌려주는 Function"이에요. 식(Expression) 하나만 쓸 수 있어요.
2. 주로 짧게 넘길 때 써요. `sorted(people, key=lambda p: p["age"])`는 나이순 정렬.
3. **map(function, iterable)**: 각 원소에 Function을 적용해요. 결과를 바로 만들지 않고 필요할 때 하나씩 만드는 Lazy Iterator라서, list가 필요하면 `list(map(...))`로 감싸요.
4. **filter(function, iterable)**: 조건이 True인 원소만 남겨요.
5. **List Comprehension**: `[x * 2 for x in nums if x > 0]`처럼 "변환 + 조건"을 한 줄로 써요. map·filter보다 읽기 쉬워서 Python에서 더 많이 써요.
6. dict와 set도 돼요: `{k: v for k, v in pairs}`, `{x % 3 for x in nums}`.
```python
nums = [1, -2, 3]
doubled = list(map(lambda x: x * 2, nums))   # [2, -4, 6]
positive_doubled = [x * 2 for x in nums if x > 0]  # [2, 6]
```
KEY: Comprehension이 한 줄을 넘어갈 만큼 복잡해지면 그냥 for 문으로 풀어 쓰는 게 더 읽기 좋아요.
END: lambda는 일회용 Function, map은 "모두에게 같은 작업", Comprehension은 그걸 더 읽기 좋게 쓰는 방법이에요.

#### *args와 **kwargs
ONE: **`*args`**는 개수가 정해지지 않은 위치 Argument를 **tuple로**, **`**kwargs`**는 이름 붙은 Argument를 **dict로** 모아 받아요.
LIKE: `*args`는 "받은 물건을 순서대로 가방에 다 넣기", `**kwargs`는 "이름표 붙은 물건을 이름별 서랍에 다 넣기"예요.
STEP:
1. `def f(*args)`로 정의하면 `f(1, 2, 3)`의 Argument들이 `args = (1, 2, 3)`으로 들어와요.
2. `def f(**kwargs)`로 정의하면 `f(a=1, b=2)`가 `kwargs = {"a": 1, "b": 2}`로 들어와요.
3. 이름 `args`, `kwargs`는 관례일 뿐이고, 중요한 건 `*`와 `**`예요.
4. **호출할 때 풀기(Unpacking)**: `f(*[1, 2])`는 `f(1, 2)`와 같고, `f(**{"a": 1})`은 `f(a=1)`과 같아요.
5. 받은 Argument를 다른 Function에 그대로 넘길 때 특히 유용해요: `def wrapper(*args, **kwargs): return func(*args, **kwargs)`.
USE: `print()`처럼 Argument 개수가 자유로운 Function, Decorator, 상위 Class의 `__init__`에 Argument를 그대로 넘길 때 써요.
END: `*`는 순서대로 모아 tuple, `**`는 이름별로 모아 dict. 호출할 때 쓰면 반대로 풀어 줘요.

#### Decorator
ONE: Function을 받아 **기능을 덧붙인 새 Function을 돌려주는** Function이에요. `@이름`을 Function 위에 쓰면 원래 코드를 고치지 않고 기능을 더할 수 있어요.
LIKE: 선물(Function)은 그대로 두고 포장지를 두르는 거예요. 포장지가 "열기 전에 시간 재기", "열 자격이 있는지 확인하기" 같은 일을 대신 해 줘요.
STEP:
1. Function이 Object라서 Function을 Argument로 받고, 새 Function을 만들어 돌려줄 수 있어요.
2. Decorator는 원래 Function을 감싸는 `wrapper` Function을 만들어요. wrapper는 앞뒤로 추가 작업을 하고, 가운데서 원래 Function을 불러요.
3. `@timer`를 `def work():` 위에 쓰면, Python이 `work = timer(work)`를 대신 실행해요.
4. 이제 `work()`를 부르면 사실은 wrapper가 실행돼요.
5. `functools.wraps`를 붙이면 원래 Function의 이름과 Docstring이 유지돼요.
```python
import functools, time

def timer(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = func(*args, **kwargs)      # 원래 Function 실행
        print(f"{func.__name__}: {time.perf_counter() - start:.3f}초")
        return result
    return wrapper

@timer          # work = timer(work)
def work():
    time.sleep(0.1)
```
USE: 실행 시간 측정, Logging, 로그인 확인(웹 Framework의 `@login_required`), 결과 저장(`@functools.lru_cache`), URL 연결(Flask의 `@app.route("/")`)에 써요.
WHY: 여러 Function에 공통으로 필요한 일을 Function마다 복사하지 않고 한 곳에서 관리할 수 있어요.
END: Decorator는 Function에 포장지를 두르는 것이고, `@deco`는 `func = deco(func)`의 줄임말이에요.

#### Closure와 Default Argument 함정
ONE: **Closure**는 안쪽 Function이 **자기를 감싼 Function의 Variable을 기억해** 계속 쓰는 것이에요. 그리고 Default Argument는 **Function을 정의할 때 한 번만** 만들어진다는 함정이 있어요.
LIKE: Closure는 Function이 태어난 방의 물건을 배낭에 넣고 다니는 것이에요. Default Argument 함정은 "빈 장바구니를 기본으로 드려요"라고 했는데, 알고 보니 모든 손님에게 같은 바구니 하나를 돌려쓰는 상황이에요.
STEP:
1. **Closure 예**: `def counter(): n = 0` 안에 `def inc(): nonlocal n; n += 1; return n`을 만들어 `inc`를 돌려줘요.
2. `counter()`는 이미 끝났는데도, 돌려받은 `inc`는 `n`을 기억하고 부를 때마다 1, 2, 3을 돌려줘요.
3. 이렇게 상태를 몰래 들고 다니는 Function을 만들 수 있어서, Class 없이 간단한 상태를 표현할 때 써요. Decorator도 Closure로 동작해요.
4. **Default Argument 함정**: `def add(x, lst=[])`에서 `[]`는 **Function을 정의할 때 딱 한 번** 만들어져요.
5. 그래서 `add(1)` → `[1]`, 그다음 `add(2)` → `[1, 2]`처럼 호출 사이에 같은 list가 계속 쌓여요.
6. **해결**: 기본값을 None으로 두고 안에서 새로 만들어요.
```python
def add(x, lst=None):
    if lst is None:
        lst = []        # 호출할 때마다 새 list
    lst.append(x)
    return lst
```
KEY: Default Argument에 list·dict·set 같은 Mutable Object를 직접 쓰지 마세요. 면접 단골 문제예요.
END: Closure는 "태어난 곳의 Variable을 기억하는 Function"이고, Default Argument는 한 번만 만들어지니 Mutable 기본값은 None으로 대신해요.

### What are functions in Python?
A: Function은 def로 정의하는 재사용 가능한 코드 묶음으로, Argument를 받아 return으로 값을 돌려주고 return이 없으면 None을 돌려줍니다. Python에서 Function은 First-Class Object(일급 객체)라 Variable에 담거나 다른 Function의 Argument·Return Value로 쓸 수 있습니다.

### How does break, continue and pass work?
E: 운동장 10바퀴를 돌 때 break는 "오늘 운동 끝", continue는 "이번 바퀴는 건너뛰고 다음 바퀴", pass는 "아무것도 안 하고 그냥 지나감"입니다.
A: break는 가장 가까운 Loop를 즉시 빠져나가고, continue는 이번 반복의 나머지를 건너뛰고 다음 반복으로 갑니다. pass는 아무 일도 하지 않는 Statement로, 문법상 Statement가 필요한 빈 Function·Class·if Block을 자리만 잡아둘 때 씁니다.

### How can the ternary operator be used in Python?
A: Python의 Ternary Operator(삼항 연산자)는 `value_if_true if condition else value_if_false` 형태입니다. 예를 들어 `label = "성인" if age >= 18 else "미성년"`처럼 한 줄로 조건에 따른 값을 고릅니다.

### What is a lambda function? What is the map function?
E: lambda는 이름표 없이 한 번 쓰고 버리는 일회용 메모 지시문이고, map은 컨베이어 벨트 위 물건 하나하나에 같은 작업을 하는 기계입니다.
A: lambda는 `lambda x: x * 2`처럼 식(Expression) 하나만 갖는 Anonymous Function(이름 없는 함수)으로, `sorted(…, key=lambda p: p[1])`처럼 짧게 넘길 때 씁니다. `map(function, iterable)`은 각 원소에 Function을 적용하는 Lazy Iterator를 돌려주므로 list가 필요하면 list()로 감쌉니다. 간단한 경우에는 List Comprehension `[x * 2 for x in xs]`이 더 읽기 쉽습니다.

### What does *args, **kwargs mean? Why would we use it?
E: `*args`는 "잡동사니 가방에 받은 물건을 순서대로 다 넣기", `**kwargs`는 "이름표 붙은 물건을 이름별 서랍에 다 넣기"입니다.
A: `*args`는 개수가 정해지지 않은 Positional Argument를 tuple로, `**kwargs`는 개수가 정해지지 않은 Keyword Argument를 dict로 받습니다. Argument 개수가 가변인 Function, 받은 Argument를 다른 Function에 그대로 넘기는 Decorator·Wrapper에 씁니다. 호출할 때는 `f(*lst, **d)`처럼 풀어서(Unpacking) 넘길 수도 있습니다.

### What are decorators in Python?
E: 선물(Function)을 바꾸지 않고 포장지를 두르는 것입니다. 포장지가 "열기 전에 시간 재기", "열 자격 확인하기" 같은 일을 더해 줍니다.
A: Decorator는 Function을 Argument로 받아 기능을 덧붙인 새 Function을 돌려주는 Function으로, `@name`을 Function 위에 쓰면 `func = name(func)`과 같습니다. Logging·실행 시간 측정·권한 검사·Caching(`functools.lru_cache`) 같은 공통 기능을 원래 코드를 고치지 않고 붙일 때 씁니다. 원래 Function의 이름·Docstring을 유지하려면 `functools.wraps`를 씁니다.
```python
import functools, time

def timer(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = func(*args, **kwargs)
        print(f"{func.__name__}: {time.perf_counter() - start:.3f}초")
        return result
    return wrapper

@timer
def work():
    time.sleep(0.1)
```

### Closure란? Default Argument에 list를 쓰면 생기는 함정은?
E: Closure는 Function이 태어난 방의 물건을 배낭에 넣고 다니는 것입니다. Default Argument 함정은 "빈 장바구니를 기본으로 드립니다"라고 했는데 사실 모든 손님에게 같은 바구니 하나를 돌려쓰는 상황입니다.
A: Closure는 안쪽 Function이 자신을 감싼 Function의 Variable을 기억해, 바깥 Function이 끝난 뒤에도 그 값을 쓸 수 있는 Function입니다. Default Argument는 Function을 정의할 때 딱 한 번만 만들어지므로, `def f(x, lst=[])`처럼 Mutable Object를 쓰면 호출마다 같은 list가 계속 쌓입니다. 그래서 `lst=None`으로 두고 Function 안에서 새 list를 만듭니다.

## Iterator와 Generator

#### Iterable과 Iterator
ONE: **Iterable**은 하나씩 꺼낼 수 있는 **묶음**(list, str, dict 등)이고, **Iterator**는 그 묶음에서 **다음 값을 하나씩 꺼내 주는 책갈피**예요.
LIKE: Iterable은 책 한 권이고, Iterator는 그 책에 끼운 책갈피예요. 한 권의 책에 책갈피를 몇 개든 새로 끼울 수 있고, 책갈피는 앞으로만 한 장씩 넘어가요.
STEP:
1. **Iterable**: `iter(obj)`를 하면 Iterator를 만들어 주는 Object예요(내부적으로 `__iter__`).
2. **Iterator**: `next(it)`를 할 때마다 다음 값을 돌려주고(`__next__`), 더 없으면 **StopIteration**을 일으켜요.
3. **for 문의 정체**: `for x in lst:`는 내부적으로 `it = iter(lst)`를 만들고, `next(it)`를 반복하다가 StopIteration이 나면 멈춰요.
4. Iterator는 **한 번 다 쓰면 끝**이에요. 다시 처음부터 돌고 싶으면 Iterable에서 새 Iterator를 만들어야 해요.
5. `map`, `filter`, `zip`, 파일 Object는 Iterator라서 한 번만 돌 수 있어요.
```python
it = iter([10, 20])
next(it)  # 10
next(it)  # 20
next(it)  # StopIteration
```
WHY: "모든 값을 미리 만들어 두지 않고, 필요할 때 하나씩 꺼내기"가 가능해져서 Memory를 아끼고 끝없는 데이터도 다룰 수 있어요.
END: Iterable은 책, Iterator는 책갈피예요. for 문은 책갈피를 한 장씩 넘기는 문법이에요.

#### Generator와 Lazy Evaluation
ONE: **Generator**는 `yield`로 값을 **하나씩 만들어 내보내고 멈췄다가, 다음 요청 때 이어서** 실행하는 Function이에요. 값을 미리 다 만들지 않아 Memory를 거의 안 써요.
LIKE: 만두 1만 개를 미리 다 빚어 냉장고에 쌓아 두는 대신, 주문이 올 때마다 하나씩 빚어 주는 가게예요. 냉장고(Memory)가 거의 필요 없어요.
STEP:
1. Function 안에 `yield`가 있으면, 부를 때 실행되지 않고 Generator Object를 돌려줘요.
2. `next()`를 부르면 첫 `yield`까지 실행하고, 그 값을 내보내고 **그 자리에서 멈춰요**.
3. 다시 `next()`를 부르면 멈춘 곳부터 이어서 다음 `yield`까지 실행해요.
4. Function이 끝나면 StopIteration이 나요. Generator는 Iterator라서 for 문에서 바로 쓸 수 있어요.
5. 이렇게 필요할 때만 계산하는 것을 **Lazy Evaluation(지연 평가)**이라고 해요.
6. **Generator Expression**: `(x * x for x in range(10))`처럼 괄호로 쓰면 list를 만들지 않고 Generator가 돼요.
7. **range**도 Lazy해요. Python 3의 `range(10**9)`는 숫자 10억 개를 만들지 않고 필요할 때 계산해요(Python 2의 xrange가 이렇게 바뀐 거예요).
```python
def read_lines(path):
    with open(path) as f:
        for line in f:
            yield line.strip()   # 한 줄 내보내고 멈춤

for line in read_lines("big.log"):   # 10GB 파일도 한 줄씩
    ...
```
USE: 아주 큰 파일을 한 줄씩 처리하기, 끝없는 수열 만들기, 데이터 처리 Pipeline 만들기에 써요.
CON: 한 번 다 돌면 다시 쓸 수 없고, 중간 값에 Index로 바로 접근할 수 없어요.
END: Generator는 "주문 들어올 때마다 하나씩 만드는" Function이에요. 큰 데이터를 적은 Memory로 다룰 수 있어요.

### What's the difference between iterator and iterable?
E: Iterable은 책 한 권, Iterator는 그 책에 끼운 책갈피입니다. 책에서 책갈피를 몇 개든 새로 만들 수 있고, 책갈피는 앞으로만 한 장씩 넘어갑니다.
A: Iterable은 `__iter__`로 Iterator를 만들 수 있는 Object(list, str, dict 등)이고, Iterator는 `__next__`로 다음 값을 하나씩 돌려주다가 끝나면 StopIteration을 일으키는 Object입니다. Iterator는 한 번 다 쓰면 끝이고, for 문은 내부적으로 iter()와 next()를 호출합니다.

### What are generators in Python?
E: 만두 1만 개를 미리 다 빚어 두는 대신, 주문이 올 때마다 하나씩 빚어 주는 가게입니다. 냉장고(Memory)가 거의 필요 없습니다.
A: Generator는 yield를 쓰는 Function으로 만드는 Iterator로, 값을 하나 내보낼 때마다 멈추고 다음 요청 때 멈춘 곳부터 이어서 실행합니다. 값을 미리 모두 만들지 않아(Lazy Evaluation) Memory를 거의 쓰지 않으므로 큰 파일을 한 줄씩 읽거나 무한 수열을 다룰 때 좋고, `(x * x for x in range(10))`처럼 Generator Expression으로도 만듭니다.

### What is the difference between range and xrange?
A: Python 2에서 range는 모든 숫자를 담은 list를 만들고 xrange는 필요할 때 숫자를 만드는 Object였습니다. Python 3에서는 xrange가 없어지고 range가 xrange처럼 Lazy하게 계산하는 Object가 되었습니다. 그래서 range(10⁹)도 Memory를 거의 쓰지 않습니다.

## Namespace와 Module

#### Namespace와 LEGB Rule
ONE: **Namespace**는 "이름 → Object" 연결표이고, Python은 이름을 **Local → Enclosing → Global → Built-in** 순서로 찾아요(**LEGB Rule**).
LIKE: 같은 "민수"라도 우리 반 민수와 옆 반 민수는 다른 사람이에요. Namespace는 "어느 반 출석부인가"이고, Python은 이름을 찾을 때 우리 반 → 바깥 반 → 학교 전체 → 교육청 순서로 출석부를 확인해요.
STEP:
1. **Local**: 지금 실행 중인 Function 안의 이름.
2. **Enclosing**: 이 Function을 감싸는 바깥 Function의 이름(Closure의 경우).
3. **Global**: 이 Module(.py 파일) 최상위의 이름.
4. **Built-in**: `print`, `len` 같은 Python 기본 이름.
5. 가장 안쪽부터 찾고, 처음 찾은 걸 써요. 어디에도 없으면 NameError예요.
6. **Global Variable 바꾸기**: Function 안에서 Global Variable을 **읽기**만 하는 건 되지만, **새 값을 대입**하면 그 이름은 Local Variable로 취급돼요. Global을 바꾸려면 `global x`, 감싸는 Function의 Variable을 바꾸려면 `nonlocal x`를 써요.
```python
x = "global"
def outer():
    x = "enclosing"
    def inner():
        print(x)     # enclosing (Local에 없으니 바깥을 찾음)
    inner()
```
KEY: `list = [1, 2]`처럼 Built-in 이름을 Variable로 쓰면, 그 Module에서는 원래 `list()`를 못 쓰게 돼요. Built-in 이름은 피하세요.
WHY: Namespace가 나뉘어 있어서 서로 다른 파일과 Function에서 같은 이름을 써도 충돌하지 않아요.
END: 이름은 L → E → G → B 순서로 찾고, 바깥 Variable을 바꾸려면 global·nonlocal을 써요.

#### Module · Package · import
ONE: **Module**은 코드가 담긴 `.py` 파일 하나, **Package**는 Module들을 모은 폴더, **Library**는 재사용할 수 있게 모아 둔 Module·Package 묶음이에요.
LIKE: Module은 요리법 한 장, Package는 요리법을 모아 둔 바인더, Library는 바인더가 꽂힌 책장이에요.
STEP:
1. **Module**: Function·Class·Variable을 담은 `.py` 파일이에요. `math.py`가 있으면 `import math`로 가져와요.
2. **Package**: 여러 Module을 담은 폴더예요(보통 `__init__.py` 포함). `import a.b`처럼 점으로 접근해요.
3. **import 방법**: `import math`, `from math import sqrt`, `import numpy as np`. `from x import *`는 어떤 이름이 들어왔는지 알기 어려워서 피해요.
4. **찾는 순서**: Python은 `sys.path`에 있는 폴더들을 차례로 뒤져 Module을 찾아요. **PYTHONPATH** 환경 변수로 폴더를 추가할 수 있어요.
5. 한 번 import한 Module은 `sys.modules`에 저장돼서, 다시 import해도 코드가 다시 실행되지 않아요.
6. **Standard Library**: 설치 없이 쓰는 기본 Module이에요. os, sys, math, random, datetime, json, re, collections, itertools, functools 등.
7. **외부 Library**: `pip install`로 설치해요. 데이터·AI는 NumPy, pandas, scikit-learn, PyTorch, 웹은 Django, Flask, FastAPI, requests.
KEY: 처음 보는 Library는 `help(obj)`(설명서)와 `dir(obj)`(가진 기능 목록)로 탐색할 수 있어요.
END: 파일은 Module, 폴더는 Package, 묶음은 Library. import는 sys.path에서 찾아 한 번만 실행해요.

### What is namespace in Python?
E: 같은 "민수"라도 우리 반 민수와 옆 반 민수는 다른 사람입니다. Namespace는 "어느 반의 출석부인가"입니다. Python은 이름을 찾을 때 내 반 → 바깥 반 → 학교 전체 → 교육청 순서로 출석부를 뒤집니다.
A: Namespace는 이름과 Object를 연결한 Mapping으로, 같은 이름이 서로 다른 곳에서 충돌하지 않게 합니다. Python은 이름을 Local → Enclosing(감싸는 Function) → Global(Module) → Built-in 순서로 찾고, 이를 LEGB Rule이라고 합니다.

### What are local variables and global variables?
A: Local Variable은 Function 안에서 만들어져 그 Function 안에서만 보이고, Global Variable은 Module 최상위에서 만들어져 Module 전체에서 보입니다. Function 안에서 Global Variable을 읽기만 하는 것은 되지만, 새 값을 대입하려면 global Keyword가 필요하고, 감싸는 Function의 Variable은 nonlocal을 씁니다.

### What are Python modules and packages? Name some built-in modules.
E: Module은 요리법 한 장(.py 파일), Package는 요리법을 모아 둔 바인더(폴더), Library는 바인더가 꽂힌 책장입니다.
A: Module은 Function·Class·Variable을 담은 .py 파일이고, Package는 여러 Module을 담은 Directory로(보통 `__init__.py` 포함) `import a.b`처럼 점으로 접근합니다. 자주 쓰는 Built-in Module은 os, sys, math, random, datetime, json, re, collections, itertools, functools입니다.

### How to import modules? What is PYTHONPATH?
A: `import math`, `from math import sqrt`, `import numpy as np`처럼 가져오고, `from x import *`는 이름이 섞일 수 있어 피합니다. Python은 sys.path에 있는 Directory를 차례로 뒤져 Module을 찾고, PYTHONPATH는 여기에 Directory를 추가하는 Environment Variable입니다. 한 번 import한 Module은 sys.modules에 Cache되어 다시 import해도 다시 실행되지 않습니다.

### What are Python libraries? Name a few.
A: Library는 재사용할 수 있는 Module·Package 묶음으로, Standard Library와 pip으로 설치하는 외부(Third-Party) Library가 있습니다. 데이터·AI에는 NumPy, pandas, Matplotlib, scikit-learn, PyTorch, TensorFlow를, 웹에는 Django, Flask, FastAPI, requests를 많이 씁니다.

### What is the usage of help() and dir()?
A: help(obj)는 Object의 Docstring과 사용법 설명을 보여 주고, dir(obj)는 그 Object가 가진 Attribute·Method 이름 목록을 돌려줍니다. Argument 없이 dir()을 부르면 현재 Scope의 이름들을 보여 주어, 처음 보는 Library를 탐색할 때 유용합니다.

## Memory 관리

#### Python의 Memory 관리
ONE: Python은 모든 Object를 자기 전용 Heap에 만들고, **Reference Count가 0이 되면 즉시 해제**하며, 순환 참조는 **Garbage Collector**가 주기적으로 치워요.
LIKE: Python은 물건마다 "이름표가 몇 개 붙었나"를 세어 두다가 0개가 되면 바로 치워요. 서로만 가리키며 고립된 물건 무더기는 청소부가 가끔 따로 돌며 치워요.
STEP:
1. Python의 모든 값(숫자, 문자열, Function까지)은 Object이고, **Private Heap**이라는 전용 Memory 공간에 만들어져요.
2. 작은 Object는 **pymalloc**이라는 전용 할당기가 빠르게 자리를 줘요.
3. Object마다 Reference Count가 있어요. 이름표를 붙이면 +1, 떼면(변수 삭제, 다른 값 대입, 함수 종료) −1.
4. Count가 0이 되는 순간 즉시 Memory를 돌려받아요.
5. 순환 참조(서로를 가리키는 Object들)는 Count가 0이 안 돼서, **Generational GC**(`gc` 모듈)가 주기적으로 찾아 해제해요.
6. 프로그래머는 `free`를 쓸 필요가 없어요. `del x`는 Object를 지우는 게 아니라 이름표 `x`를 떼는 거예요.
KEY: Python이 끝날 때 모든 Object가 정리되지 않을 수 있지만(순환 참조나 C Library가 잡은 Memory), Process가 끝나면 OS가 그 Process의 Memory를 통째로 회수하니 실제 Leak은 아니에요.
CON: 이름표를 다른 곳(전역 list, Cache 등)에 계속 남겨 두면 Count가 0이 안 돼서, GC가 있어도 Memory가 계속 늘어날 수 있어요.
END: Python은 이름표 세기(Reference Counting)로 즉시 치우고, 순환 참조는 GC가 따로 치워요.

#### Shallow Copy vs Deep Copy
ONE: **Shallow Copy**는 바깥 그릇만 새로 만들고 안의 내용물은 원본과 **공유**하고, **Deep Copy**는 안쪽까지 **전부 새로** 만들어요.
LIKE: 서랍장을 Shallow Copy하면 서랍장 껍데기만 새로 사고, 서랍 안의 상자는 원래 것을 같이 써요. Deep Copy는 상자와 그 안의 물건까지 전부 새로 사요.
STEP:
1. **대입(`b = a`)**: 복사가 아니에요. 같은 Object에 이름표만 하나 더 붙여요.
2. **Shallow Copy**: `copy.copy(a)`, `a[:]`, `list(a)`, `a.copy()`. 바깥 list는 새것이지만, 안에 든 Object들은 원본과 같은 것을 가리켜요.
3. 그래서 안쪽이 숫자처럼 Immutable이면 문제없지만, 안쪽이 list처럼 Mutable이면 한쪽에서 안쪽을 고칠 때 다른 쪽도 바뀌어요.
4. **Deep Copy**: `copy.deepcopy(a)`. 안쪽 Object까지 재귀적으로 전부 새로 만들어서 완전히 독립된 사본이 돼요.
5. Deep Copy는 느리고 Memory를 더 쓰니 꼭 필요할 때만 써요.
```python
import copy
a = [[1, 2], [3, 4]]
b = copy.copy(a)      # Shallow
c = copy.deepcopy(a)  # Deep
a[0].append(99)
print(b[0])  # [1, 2, 99]  ← 안쪽을 공유
print(c[0])  # [1, 2]      ← 완전히 독립
```
KEY: 2차원 list를 `[[0] * 3] * 3`으로 만들면 같은 안쪽 list 하나를 세 번 가리키게 돼서, 한 칸을 바꾸면 세 줄이 다 바뀌어요. `[[0] * 3 for _ in range(3)]`으로 만들어야 해요.
END: 대입은 이름표 추가, Shallow는 바깥만 새로, Deep은 전부 새로예요.

#### Object Interning
ONE: 같은 값의 Immutable Object를 **하나만 만들어 두고 재사용**해서 Memory와 비교 시간을 아끼는 최적화예요.
LIKE: 자주 쓰는 "참 잘했어요" 도장을 반 전체가 하나만 만들어 두고 빌려 쓰는 거예요. 도장 글자가 바뀌지 않으니 나눠 써도 안전해요.
STEP:
1. CPython은 자주 쓰는 작은 정수 −5~256을 미리 만들어 두고, 이 값이 필요할 때마다 같은 Object를 줘요.
2. 이름처럼 생긴 짧은 문자열(Variable 이름, dict Key 등)도 자동으로 하나만 만들어 재사용하는 경우가 많아요.
3. `sys.intern(s)`로 직접 Interning할 수도 있어요. 같은 문자열을 아주 많이 비교할 때 빨라져요.
4. Immutable이라 가능한 일이에요. 값이 바뀔 수 있다면 나눠 쓰면 서로 영향을 주니까요.
KEY: Interning은 CPython의 구현 세부 사항이라 버전이나 상황에 따라 달라요. 그래서 `a is b`로 값을 비교하면 우연히 맞다가 틀릴 수 있어요. 값 비교는 항상 ==예요.
END: Interning은 "같은 값은 하나만 만들어 함께 쓰기"이고, 그래서 is가 가끔 True가 나오지만 믿고 쓰면 안 돼요.

### How is memory managed in Python?
E: Python은 물건마다 "이름표 몇 개 붙었는지" 세어 두다가 0개가 되면 바로 치우고, 서로만 가리키며 고립된 물건 무더기는 가끔 따로 청소합니다.
A: Python의 모든 Object는 Python Memory Manager가 관리하는 Private Heap에 생기고, 작은 Object는 pymalloc이 빠르게 할당합니다. CPython은 Reference Count가 0이 되는 즉시 Object를 해제하고, Reference Counting으로 못 잡는 Circular Reference는 Generational Garbage Collector(gc 모듈)가 주기적으로 찾아 해제합니다. 프로그래머가 직접 free할 필요는 없습니다.

### What is the difference between deep and shallow copy?
E: 서랍장을 Shallow Copy하면 서랍장 껍데기만 새로 사고 서랍 안의 상자는 원래 것을 같이 씁니다. Deep Copy는 상자와 그 안의 물건까지 전부 새로 삽니다.
A: Shallow Copy(`copy.copy`, `lst[:]`, `list(lst)`)는 바깥 Container만 새로 만들고 안의 Object는 원본과 공유하므로, 중첩 list의 안쪽을 바꾸면 원본도 바뀝니다. Deep Copy(`copy.deepcopy`)는 안쪽 Object까지 재귀적으로 새로 만들어 완전히 독립된 사본을 만듭니다.
```python
import copy
a = [[1, 2], [3, 4]]
b = copy.copy(a)      # Shallow Copy
c = copy.deepcopy(a)  # Deep Copy
a[0].append(99)
print(b[0])  # [1, 2, 99]  ← 안쪽 list를 공유
print(c[0])  # [1, 2]      ← 독립
```

### What is object interning?
E: 자주 쓰는 "안녕하세요" 도장을 하나만 만들어 두고 모두 빌려 쓰는 것입니다. 값이 바뀌지 않으니 나눠 써도 안전합니다.
A: Interning은 같은 값의 Immutable Object를 하나만 만들어 재사용해 Memory와 비교 시간을 아끼는 최적화입니다. CPython은 −5~256의 Small Integer와 Identifier처럼 생긴 일부 String을 Interning하고, `sys.intern()`으로 직접 할 수도 있습니다. 구현 세부사항이므로 값 비교에 is를 쓰면 안 되고 ==를 써야 합니다.

### Whenever Python exits, why isn't all the memory de-allocated?
A: Python 공식 FAQ에 따르면, 종료 시 Module Global Namespace에서 참조되는 Object, 특히 Circular Reference가 있는 Object는 항상 해제되지는 않고, C Library가 할당한 일부 Memory는 Python이 해제할 수 없습니다. 다만 Process가 끝나면 OS가 그 Process의 Memory를 통째로 회수하므로 실제 Memory Leak으로 이어지지는 않습니다.

## OOP (Object-Oriented Programming)

P: 이 묶음의 비유: Class는 **붕어빵 틀**, Object(Instance)는 그 틀로 구운 **붕어빵 하나하나**입니다. 틀은 하나지만 붕어빵마다 안의 소(팥·슈크림)는 다를 수 있습니다.

#### Class와 Object, __init__과 self
ONE: **Class**는 Object를 만드는 **설계도(틀)**, **Object(Instance)**는 그 틀로 만든 **실제 물건**이에요. `__init__`은 만들 때 초기값을 채우고, `self`는 "지금 이 Object 자신"을 가리켜요.
LIKE: Class는 붕어빵 틀, Object는 그 틀로 구운 붕어빵 하나하나예요. 틀은 하나지만 붕어빵마다 안의 소(팥·슈크림)는 다를 수 있어요. `__init__`은 붕어빵이 틀에서 나오자마자 소를 채우는 단계이고, `self`는 "지금 손에 든 바로 이 붕어빵"이에요.
STEP:
1. **Class 만들기**: `class Dog:`. 빈 Class는 `class Empty: pass`.
2. **Object 만들기**: `d = Dog("코코")`. 같은 Class로 Object를 몇 개든 만들 수 있어요.
3. **Attribute**: Object가 가진 데이터예요. `d.name`.
4. **Method**: Class 안에 정의한 Function이에요. Object의 데이터를 다뤄요.
5. **`__init__`**: Object가 만들어진 직후 자동으로 불려서 Attribute를 채워요. 엄밀히 Object를 "만드는" 건 `__new__`이고 `__init__`은 "초기화"만 해요.
6. **`self`**: Method의 첫 번째 Parameter로, 그 Method를 부른 Object 자신이에요. `d.bark()`는 사실 `Dog.bark(d)`로 실행돼요. `self`는 예약어가 아니라 관례적인 이름이에요.
```python
class Dog:
    def __init__(self, name):
        self.name = name          # 이 Object의 Attribute
    def bark(self):
        return f"{self.name}: 멍!"

d = Dog("코코")
d.bark()   # Dog.bark(d) → '코코: 멍!'
```
WHY: 데이터와 그 데이터를 다루는 기능을 한 덩어리로 묶으면, 큰 프로그램을 "물건들의 협력"으로 정리할 수 있어요.
END: Class는 틀, Object는 붕어빵, `__init__`은 소 채우기, `self`는 지금 이 붕어빵이에요.

#### Inheritance (상속)와 MRO
ONE: **Inheritance**는 부모 Class의 기능을 자식 Class가 **물려받아 재사용하고, 필요한 부분만 바꾸는(Overriding)** 것이에요.
LIKE: "동물" 틀을 물려받아 "강아지" 틀을 만들면, 이름·나이 같은 공통 부분은 다시 만들 필요 없이 "짖기"만 새로 정하면 돼요.
STEP:
1. `class Dog(Animal):`처럼 괄호 안에 부모 Class를 적어요.
2. 자식은 부모의 Attribute와 Method를 그대로 쓸 수 있어요.
3. **Overriding**: 부모와 같은 이름의 Method를 자식이 다시 정의하면, 자식 것이 쓰여요.
4. **super()**: 자식 Method 안에서 부모의 Method를 부를 때 써요. 예: `super().__init__(name)`.
5. **Multiple Inheritance**: Python은 부모를 여러 개 가질 수 있어요. `class C(A, B):`.
6. **MRO (Method Resolution Order)**: 부모가 여럿일 때 Method를 어느 순서로 찾을지 정한 규칙이에요(C3 Algorithm). `C.__mro__`로 확인할 수 있고, super()도 이 순서의 "다음 Class"를 불러요.
```python
class Animal:
    def __init__(self, name):
        self.name = name
    def speak(self):
        return "..."

class Dog(Animal):          # Animal을 물려받음
    def speak(self):        # Overriding
        return f"{self.name}: 멍멍"

Dog("코코").speak()  # '코코: 멍멍'
```
CON: 상속을 깊게 쌓으면 어디서 무엇이 바뀌는지 추적하기 어려워져요. 그래서 "상속보다 조합(Composition)"이라는 원칙도 있어요(10번 주제).
END: 상속은 물려받고 필요한 것만 바꾸는 것이고, 부모가 여럿이면 MRO 순서로 찾아요.

#### Polymorphism · Encapsulation · Abstraction
ONE: OOP의 핵심 세 가지예요. **같은 명령에 각자 다르게 반응(다형성)**, **안은 숨기고 버튼만 보여 주기(캡슐화)**, **"무엇을 해야 하는지"만 정하기(추상화)**.
LIKE: "소리 내!"라고 하면 개는 멍멍, 고양이는 야옹(Polymorphism). TV 리모컨은 회로는 숨기고 버튼만 보여 줘요(Encapsulation). "탈것이라면 무엇이든 '출발하기'가 있어야 한다"고 정해 두면, 자전거든 자동차든 각자 방식으로 출발해요(Abstraction).
STEP:
1. **Polymorphism (다형성)**: 같은 Method 이름으로 서로 다른 Type의 Object를 다뤄요. `for a in animals: a.speak()`는 Object마다 다른 소리를 내요.
2. Python은 Type보다 "그 Method가 있느냐"를 봐요. "오리처럼 걷고 꽥꽥거리면 오리"라는 뜻으로 **Duck Typing**이라고 해요.
3. `+`가 숫자에서는 더하기, 문자열에서는 이어 붙이기인 것도 다형성이에요(Operator Overloading, `__add__`).
4. **Encapsulation (캡슐화)**: 데이터와 그걸 다루는 Method를 한 Class에 묶고, 내부는 숨겨요.
5. Python에는 Java의 `private` 같은 강제 규칙이 없어요. 대신 `_name`은 "내부용이니 밖에서 쓰지 마세요"라는 약속이고, `__name`은 이름이 `_Class__name`으로 바뀌어(Name Mangling) 자식 Class와 이름이 충돌하지 않게 해요. 그래도 접근 자체는 가능해요.
6. **Abstraction (추상화)**: `abc` 모듈의 `ABC`와 `@abstractmethod`로 "반드시 구현해야 할 Method"를 정해요. 구현하지 않은 자식 Class는 Object를 만들 수 없어요.
WHY: 다형성은 새 Type을 추가해도 기존 코드를 고치지 않게 해 주고, 캡슐화는 내부를 바꿔도 밖이 깨지지 않게 해 주고, 추상화는 여러 구현이 지켜야 할 약속을 정해 줘요.
END: 같은 명령 다른 동작(다형성), 안은 숨기기(캡슐화), 할 일만 정하기(추상화)예요.

#### @classmethod · @staticmethod · @property
ONE: Method의 종류를 정하는 Decorator예요. **@classmethod**는 Class 자체를, **@staticmethod**는 아무것도 안 받고, **@property**는 Method를 Attribute처럼 읽게 해요.
LIKE: 일반 Method는 붕어빵 하나를 다루고, @classmethod는 붕어빵 틀 자체를 다루고, @staticmethod는 가게에 놓인 계산기(가게와 관련은 있지만 특정 붕어빵과는 무관), @property는 뒤에서 계산되지만 겉으로는 그냥 붙어 있는 가격표예요.
STEP:
1. **일반 Method**: 첫 Argument가 `self`(Object). Object별 데이터를 다뤄요.
2. **@classmethod**: 첫 Argument가 `cls`(Class). `Date.from_string("2026-10-23")`처럼 다른 방식으로 Object를 만드는 **Alternative Constructor**에 많이 써요. 자식 Class에서 부르면 `cls`가 자식 Class라서 자식 Object가 만들어져요.
3. **@staticmethod**: `self`도 `cls`도 안 받아요. Class와 관련된 도우미 Function을 Class 안에 정리해 둘 때 써요.
4. **@property**: `obj.area()` 대신 `obj.area`처럼 괄호 없이 읽게 해요. `@area.setter`를 쓰면 값을 넣을 때 검사도 할 수 있어요(예: 음수 금지).
| 종류 | 첫 Argument | 언제 쓰나 |
| 일반 Method | self | Object별 데이터 다루기 |
| @classmethod | cls | Alternative Constructor, Class 전체 설정 |
| @staticmethod | 없음 | 관련 도우미 Function |
| @property | self | 계산된 값을 Attribute처럼, 값 검사 |
END: Object를 다루면 일반 Method, Class를 다루면 @classmethod, 둘 다 필요 없으면 @staticmethod, Attribute처럼 보이게 하려면 @property예요.

#### Magic Method와 Monkey Patching
ONE: **Magic Method**는 `__이름__` 형태의 특수 Method로, Python 문법(`+`, `len()`, `print()`)이 내부에서 불러요. **Monkey Patching**은 실행 중에 Class나 Module의 기능을 바꿔치기하는 거예요.
LIKE: Magic Method는 붕어빵 틀에 "+ 버튼을 누르면 이렇게 해", "몇 개냐고 물으면 이렇게 답해" 같은 반응 규칙을 새겨 두는 거예요. Monkey Patching은 공연 중인 인형의 팔을 몰래 다른 팔로 바꿔 끼우는 거예요.
STEP:
1. **Magic Method (Dunder Method)**: 이름 양쪽에 밑줄 두 개(double underscore)가 붙어요.
2. `print(obj)` → `__str__`, 개발자용 표시 → `__repr__`, `a == b` → `__eq__`, `len(obj)` → `__len__`, `a + b` → `__add__`, `for x in obj` → `__iter__`.
3. 내가 만든 Class에 이걸 정의하면, 내 Object도 Built-in Type처럼 `+`, `len()`, for 문을 쓸 수 있어요.
4. **Monkey Patching**: 실행 중에 `SomeClass.method = new_function`처럼 바꿔치기해요.
5. Test에서 실제 외부 API 대신 가짜(Mock)를 넣을 때 유용해요(`unittest.mock.patch`).
CON: 실제 서비스 코드에서 Monkey Patching을 남용하면 "코드에 적힌 것과 실제 동작이 다른" 상태가 돼서 추적이 매우 어려워요.
END: Magic Method는 문법과 내 Class를 연결하는 고리이고, Monkey Patching은 실행 중 바꿔치기예요(Test에서만 조심해서).

### Does Python have OOP concepts? How are classes created? How to create an empty class?
A: Python은 Class·Inheritance·Polymorphism·Encapsulation을 모두 지원하고, 숫자·Function·Class까지 모든 것이 Object입니다. Class는 class Keyword로 만들고, 내용이 없는 빈 Class는 `class Empty: pass`처럼 pass를 넣어 만듭니다.

### What is __init__? What is self?
E: `__init__`은 붕어빵이 틀에서 나오자마자 소를 채우는 단계이고, self는 "지금 손에 들고 있는 바로 이 붕어빵"입니다.
A: `__init__`은 Object가 만들어진 직후 자동으로 호출되어 Attribute를 초기화하는 Method입니다. 엄밀히 Object를 만드는 것은 `__new__`이고 `__init__`은 초기화(Initialization)만 합니다. self는 Method가 호출된 그 Instance 자신을 가리키는 첫 번째 Parameter로, `obj.method()`는 사실 `Class.method(obj)`로 실행됩니다. self는 예약어(Keyword)가 아니라 관례적인 이름입니다.

### Explain inheritance with an example. Does Python support multiple inheritance?
E: "동물" 틀을 물려받아 "강아지" 틀을 만들면, 이름·나이 같은 공통 부분은 다시 만들지 않고 "짖기"만 바꾸면 됩니다.
A: Inheritance(상속)는 Parent Class의 Attribute·Method를 Child Class가 물려받아 재사용하고 필요한 부분만 고치는(Overriding) 것입니다. Python은 Multiple Inheritance를 지원하고, Method를 찾는 순서는 C3 Algorithm으로 정한 MRO(Method Resolution Order)를 따르며 `ClassName.__mro__`로 확인합니다. super()는 MRO상 다음 Class의 Method를 부릅니다.
```python
class Animal:
    def __init__(self, name):
        self.name = name
    def speak(self):
        return "..."

class Dog(Animal):          # Animal을 상속
    def speak(self):        # Overriding
        return f"{self.name}: 멍멍"

print(Dog("코코").speak())  # 코코: 멍멍
```

### What is polymorphism? Define encapsulation. How do you do data abstraction?
| 개념 | 비유 | Python에서는 |
| Polymorphism (다형성) | "소리 내"라고 하면 개는 멍멍, 고양이는 야옹 | 같은 Method 이름이 Object마다 다르게 동작. Overriding, Duck Typing, Operator Overloading(`__add__`) |
| Encapsulation (캡슐화) | 리모컨 안의 회로는 숨기고 버튼만 보여 줌 | Data와 Method를 한 Class에 묶고, 내부는 `_name`·@property로 감춤 |
| Abstraction (추상화) | "탈 것"이라면 무엇이든 "출발하기"가 있어야 함 | abc 모듈의 ABC와 @abstractmethod로 반드시 구현할 Method를 정함 |
A: Polymorphism은 같은 Interface로 서로 다른 Type을 다루는 것이고, Python은 Type보다 "그 Method가 있느냐"를 보는 Duck Typing을 씁니다. Encapsulation은 Data와 그 Data를 다루는 Method를 묶고 내부 구현을 감추는 것이며, Abstraction은 abc 모듈의 Abstract Class로 "무엇을 해야 하는지"만 정하고 "어떻게"는 Child에게 맡기는 것입니다.

### Does Python make use of access specifiers?
A: Java의 private·protected 같은 강제 Access Modifier는 없고 이름 규칙(Naming Convention)으로 표현합니다. `_name`은 "내부용이니 밖에서 쓰지 마세요"라는 약속이고, `__name`은 Class 이름이 붙은 `_ClassName__name`으로 바뀌는 Name Mangling이 일어나 Child Class와의 이름 충돌을 막습니다. 그래도 접근 자체는 가능하므로 완전한 비공개(Private)는 아닙니다.

### What does object() do?
A: object는 모든 Class의 최상위 Parent Class이고, object()는 아무 기능도 없는 기본 Instance를 만듭니다. `__dict__`가 없어 Attribute를 추가할 수 없고, 다른 어떤 값과도 같지 않아서 "값이 없음"을 None과 구분해야 할 때 Sentinel 값으로 쓰기도 합니다.

### What is @classmethod, @staticmethod, @property?
| Decorator | 첫 번째 Argument | 언제 쓰나 | 비유 |
| (일반 Method) | self (Instance) | Object별 Data를 다룰 때 | 붕어빵 하나를 다룸 |
| @classmethod | cls (Class) | Alternative Constructor(대체 생성자), Class 전체 설정 | 틀 자체를 다룸 |
| @staticmethod | 없음 | Class와 관련된 도우미(Helper) Function | 가게에 둔 계산기 |
| @property | self | Method를 Attribute처럼 읽고, 값 검사 추가 | 표시된 가격표 (뒤에서 계산) |
A: @classmethod는 Class를 cls로 받아 `Date.from_string("2026-10-23")` 같은 Alternative Constructor에 쓰고, 상속하면 Child Class가 cls로 들어옵니다. @staticmethod는 self도 cls도 받지 않는 Function을 Class 안에 묶어 둔 것이고, @property는 `obj.area`처럼 괄호 없이 읽히는 Attribute를 만들고 Setter로 대입 값을 검사합니다.

### What is monkey patching?
E: 이미 다 만든 인형의 팔을 공연 중에 몰래 다른 팔로 바꿔 끼우는 것입니다.
A: Monkey Patching은 실행 중(Runtime)에 Class나 Module의 Attribute·Method를 다른 것으로 바꿔치기하는 것입니다. Test에서 외부 API 호출을 가짜(Mock)로 바꿀 때(`unittest.mock.patch`) 유용하지만, 운영(Production) 코드에서 남용하면 동작을 추적하기 어렵습니다.

### Magic Method란?
A: Magic Method(Dunder Method)는 이름 양쪽에 밑줄 두 개가 붙은 특수 Method로, Python 문법과 Built-in Function이 내부적으로 호출합니다. print(obj)는 `__str__`, 개발자용 표현은 `__repr__`, ==는 `__eq__`, len()은 `__len__`, +는 `__add__`를 부릅니다.

## Concurrency (동시성)

#### GIL (Global Interpreter Lock)
ONE: CPython에서 **한 순간에 한 Thread만 Python Bytecode를 실행**하게 하는 전역 Lock이에요. 그래서 Thread를 늘려도 순수 Python 계산은 빨라지지 않아요.
LIKE: 요리사가 여러 명 있어도 칼이 하나뿐인 주방이에요. 요리사(Thread)가 늘어도 썰기(Python 코드 실행)는 한 명씩만 해요. 하지만 재료 배달을 기다리는 동안(I/O)에는 칼을 내려놓아서 다른 요리사가 쓸 수 있어요.
STEP:
1. CPython은 Reference Counting으로 Memory를 관리해요. 여러 Thread가 동시에 Count를 고치면 꼬일 수 있어요(Race Condition).
2. 모든 Object마다 Lock을 거는 대신, Interpreter 전체에 Lock 하나(GIL)를 걸어 단순하고 안전하게 만들었어요.
3. 그래서 CPU를 많이 쓰는 계산(**CPU-Bound**)은 Thread를 4개 써도 한 번에 하나만 돌아서 빨라지지 않아요.
4. 반면 파일 읽기·Network 대기(**I/O-Bound**) 중에는 GIL이 풀려서, 다른 Thread가 그동안 일할 수 있어요. 그래서 I/O 작업에는 Thread가 효과가 있어요.
5. NumPy 같은 C Extension은 무거운 계산 중에 GIL을 풀 수 있어서 여러 Core를 쓸 수 있어요.
6. Python 3.13부터는 GIL 없이 도는 빌드(**Free-Threaded**)를 선택적으로 제공해요.
WHY: "왜 Python은 Thread를 늘려도 안 빨라지나요?"는 면접 단골 질문이에요. 답은 GIL이고, 해결책은 작업 종류에 따라 달라요(다음 개념).
END: GIL은 "칼 하나뿐인 주방"이에요. 계산은 Thread로 안 빨라지고, 기다리는 일(I/O)에는 Thread가 효과가 있어요.

#### threading vs multiprocessing vs asyncio
ONE: 기다리는 일이 많으면 **threading**이나 **asyncio**, CPU 계산이 많으면 **multiprocessing**을 써요.
LIKE: threading은 한 주방에 요리사를 여러 명 두는 것(칼은 하나), multiprocessing은 주방을 여러 개 차리는 것(주방마다 칼이 있음), asyncio는 요리사 한 명이 여러 냄비를 동시에 올려 두고 끓는 순서대로 돌보는 거예요.
STEP:
1. **작업 종류 먼저 보기**: CPU-Bound(계산이 대부분)인가, I/O-Bound(기다림이 대부분)인가?
2. **threading**: 한 Process 안에 여러 Thread. GIL을 공유해서 계산은 안 빨라지지만, I/O를 기다리는 동안 다른 Thread가 일해요. 공유 데이터는 `threading.Lock`으로 보호해요.
3. **multiprocessing**: Process를 여러 개 만들어요. Process마다 Interpreter와 GIL이 따로 있어서 여러 Core에서 진짜로 동시에 계산해요. 대신 Process끼리 데이터를 주고받는 비용이 커요.
4. **asyncio**: Thread 하나에서 **Event Loop**가 여러 작업을 번갈아 실행해요. 한 작업이 `await`로 기다리는 동안 다른 작업을 진행해요. 수천 개의 Network 연결을 가볍게 처리할 수 있어요.
5. `concurrent.futures`의 `ThreadPoolExecutor`와 `ProcessPoolExecutor`로 같은 모양의 코드로 둘을 바꿔 가며 쓸 수 있어요.
| 방식 | 동작 | 잘 맞는 일 |
| threading | 한 Process, 여러 Thread, GIL 공유 | 파일·Network 대기가 많은 일 |
| multiprocessing | 여러 Process, Process마다 GIL | 여러 Core로 무거운 계산 |
| asyncio | Thread 하나, Event Loop | 아주 많은 동시 Network 연결 |
END: 계산은 multiprocessing, 기다림은 threading, 엄청 많은 기다림은 asyncio예요.

### What is GIL?
E: 주방에 요리사가 여러 명 있어도 칼이 하나뿐인 Python 주방입니다. 요리사(Thread)가 늘어도 썰기(Python 코드 실행)는 한 명씩만 하지만, 재료 배달을 기다리는 동안(I/O)에는 칼을 내려놓아 다른 요리사가 씁니다.
A: GIL(Global Interpreter Lock)은 CPython에서 한 순간에 한 Thread만 Python Bytecode를 실행하게 하는 전역 Lock으로, Reference Counting 같은 내부 Memory 관리를 단순하고 안전하게 만듭니다. 그래서 CPU-Bound 작업은 Thread를 늘려도 빨라지지 않지만, I/O 대기 중에는 GIL이 풀려 Thread가 효과가 있고 NumPy 같은 C Extension도 계산 중 GIL을 풀 수 있습니다. Python 3.13부터는 GIL 없이 도는 실험적 빌드(Free-Threaded)도 제공됩니다.

### How is multithreading achieved in Python? threading vs multiprocessing vs asyncio
| 방식 | 어떻게 도나 | 잘 맞는 일 |
| threading | 한 Process 안 여러 Thread, GIL 공유 | 파일·Network 대기가 많은 I/O-Bound 작업 |
| multiprocessing | Process마다 별도 Interpreter와 GIL | 여러 Core를 쓰는 CPU-Bound 작업 |
| asyncio | Thread 하나에서 Event Loop가 작업을 번갈아 실행 | 수천 개의 동시 Network 연결 |
A: threading 모듈(또는 `concurrent.futures.ThreadPoolExecutor`)로 Thread를 만들고, 공유 Data는 `threading.Lock`으로 보호합니다. GIL 때문에 CPU 계산은 multiprocessing으로 Core를 나눠 쓰고, 동시 연결이 매우 많은 Network 작업은 asyncio의 async/await가 효율적입니다.

## Standard Library와 NumPy

#### Exception Handling과 with 문
ONE: **try/except**로 오류(Exception)를 잡아 수습하고, **with 문**으로 파일·Lock 같은 자원을 **어떤 경우에도 확실히 정리**해요.
LIKE: try는 "일단 해 보고", except는 "안 되면 이렇게 수습", finally는 "성공하든 실패하든 나갈 때 불은 끄기"예요. with는 들어갔다 나오면 자동으로 닫히는 문이에요.
STEP:
1. **try**: 오류가 날 수 있는 코드를 넣어요.
2. **except 오류종류**: 그 오류가 나면 실행돼요. `except ValueError:`처럼 구체적인 종류를 잡아요.
3. **else**: 오류가 없을 때만 실행돼요.
4. **finally**: 오류가 있든 없든 항상 실행돼요. 정리 작업을 넣어요.
5. **raise**: 내가 직접 오류를 일으켜요. 잘못된 입력을 알릴 때 써요.
6. **with 문**: `with open("a.txt") as f:` Block을 벗어나는 순간, 오류가 나도 파일이 자동으로 닫혀요. 내부적으로 **Context Manager**(`__enter__`/`__exit__`)를 써요.
```python
try:
    n = int(input())
except ValueError:
    print("숫자를 입력하세요")
else:
    print(n * 2)
finally:
    print("끝")
```
KEY: 모든 오류를 삼키는 빈 `except:`는 피하세요. Ctrl+C 같은 것까지 막고, 진짜 Bug를 숨겨 버려요.
END: 오류는 try/except로 수습하고, 정리는 finally나 with로 확실히 해요.

#### NumPy Array가 list보다 빠른 이유
ONE: NumPy Array는 **같은 Type의 숫자를 Memory에 나란히** 저장하고, 반복문 없이 **C로 한꺼번에 계산(Vectorization)**해서 list보다 훨씬 빠르고 가벼워요.
LIKE: list는 칸마다 "진짜 물건은 창고 어딘가에 있음"이라는 쪽지만 들어 있는 상자예요. NumPy Array는 같은 크기의 숫자가 나란히 담긴 계란판이라, 판째로 계산기에 넣을 수 있어요.
STEP:
1. **list의 구조**: 각 칸에는 Object의 주소만 있고, 실제 숫자 Object는 Memory 여기저기에 흩어져 있어요. 숫자 하나도 Type 정보 등을 가진 큰 Object예요.
2. **NumPy Array의 구조**: 같은 Type(예: 64 Bit 실수)의 값만, 연속된 Memory에 촘촘히 저장해요. Memory를 적게 쓰고 Cache 효율도 좋아요(02번 주제의 Locality).
3. **Vectorization**: `a + b`, `a * 2`를 쓰면 Python 반복문 없이 C 코드가 전체를 한꺼번에 계산해요. 경우에 따라 수십 배 이상 빨라요.
4. **Broadcasting**: 크기가 다른 Array끼리도 규칙에 맞게 늘려서 계산해 줘요. `a + 1`은 모든 원소에 1을 더해요.
5. Matrix 곱(`a @ b`), 통계(`mean`, `std`) 같은 함수가 풍부해서 데이터 분석과 AI의 기본 도구예요.
```python
import numpy as np
a = np.arange(1_000_000)
b = a * 2          # 반복문 없이 100만 개를 한 번에
```
CON: 크기가 고정이라 원소를 자주 넣고 빼거나, 서로 다른 Type을 섞어 담을 때는 list가 나아요.
END: NumPy는 "같은 Type을 나란히 + C로 한꺼번에 계산"해서 빨라요. 숫자 계산은 NumPy, 잡다한 목록은 list예요.

#### Serialization: pickle과 JSON
ONE: Object를 **파일로 저장하거나 Network로 보낼 수 있는 Byte로 바꾸는 것**이 Serialization(직렬화)이고, 되돌리는 것이 Deserialization이에요.
LIKE: Pickling은 조립된 레고를 설명서와 함께 상자에 담아 보관하는 것이고, Unpickling은 상자를 열어 똑같이 다시 조립하는 거예요.
STEP:
1. 프로그램 안의 Object는 Memory 속에만 있어요. 저장하거나 다른 곳으로 보내려면 Byte로 바꿔야 해요.
2. **pickle**: Python Object를 거의 그대로 Byte로 바꿔요(`pickle.dump` / `dumps`). 되돌릴 땐 `load` / `loads`.
3. pickle은 Python 전용이라 다른 언어에서는 읽을 수 없어요.
4. **위험**: Unpickling은 데이터 안에 숨겨진 코드를 실행할 수 있어요. **믿을 수 없는 곳에서 온 pickle 데이터는 절대 열면 안 돼요.**
5. **JSON**: 사람이 읽을 수 있는 텍스트 형식이고, 거의 모든 언어가 지원해요(`json.dumps` / `loads`). 다른 프로그램·언어와 데이터를 주고받을 때는 JSON을 써요. 대신 dict·list·숫자·문자열 같은 기본 Type만 담을 수 있어요.
| 구분 | pickle | JSON |
| 형식 | Binary (Python 전용) | 텍스트 (언어 무관) |
| 담을 수 있는 것 | 거의 모든 Python Object | 기본 Type만 |
| 보안 | 믿을 수 없는 데이터는 위험 | 비교적 안전 |
END: Serialization은 Object를 Byte로 포장하는 것이에요. Python 내부용은 pickle, 바깥과 주고받을 땐 JSON이에요.

#### 자주 쓰는 Standard Library: random · re · os
ONE: Python은 설치 없이 쓰는 기본 도구가 많아요. **random**(무작위), **re**(Regular Expression), **os·pathlib·shutil**(파일 다루기)이 대표적이에요.
LIKE: Python을 사면 기본으로 들어 있는 공구 세트예요. 주사위(random), 글자 찾기 돋보기(re), 파일 정리함(os)이 들어 있어요.
STEP:
1. **random**: `random.random()`은 0 이상 1 미만 실수, `random.randint(a, b)`는 a 이상 b 이하 정수, `random.choice(seq)`는 하나 고르기, `random.shuffle(lst)`는 list를 제자리에서 섞어요(결과로 None을 돌려줘요).
2. 같은 결과를 다시 만들고 싶으면 `random.seed(42)`처럼 Seed를 고정해요.
3. 비밀번호·Token처럼 보안이 중요한 무작위 값은 random이 아니라 **secrets** 모듈을 써요. random은 예측 가능해서 보안용이 아니에요.
4. **re**: 글자 패턴으로 찾고 바꿔요. `re.split(r"[,;]\s*", "a, b;c")` → `['a', 'b', 'c']`, `re.sub(r"\d", "#", "a1b22")` → `'a#b##'`, `re.subn`은 바꾼 횟수까지 돌려줘요.
5. **파일 삭제**: `os.remove(path)` 또는 `pathlib.Path(path).unlink()`. 빈 폴더는 `os.rmdir()`, 내용이 있는 폴더는 `shutil.rmtree()`.
KEY: 없는 파일을 지우려 하면 FileNotFoundError가 나요. 미리 확인하거나 try/except로 처리해요.
END: 무작위는 random(보안용은 secrets), 패턴은 re, 파일은 os·pathlib·shutil이에요.

### How can you generate random numbers? How can you randomize a list in place?
A: random 모듈을 씁니다. `random.random()`은 0 이상 1 미만의 실수, `random.randint(a, b)`는 a 이상 b 이하의 정수, `random.choice(seq)`는 임의의 원소를 고릅니다. `random.shuffle(lst)`는 list를 제자리(In-Place)에서 섞고 None을 돌려주며, 재현이 필요하면 `random.seed()`를, 비밀번호·Token처럼 보안이 필요하면 secrets 모듈을 씁니다.

### Explain split(), sub(), subn() methods of the re module.
A: `re.split(pattern, string)`은 Regular Expression에 맞는 곳에서 String을 잘라 list로 돌려주고, `re.sub(pattern, repl, string)`은 맞는 부분을 바꾼 새 String을, `re.subn()`은 (새 String, 바꾼 횟수) tuple을 돌려줍니다.
```python
import re
re.split(r"[,;]\s*", "a, b;c")   # ['a', 'b', 'c']
re.sub(r"\d", "#", "a1b22")       # 'a#b##'
re.subn(r"\d", "#", "a1b22")      # ('a#b##', 3)
```

### What is pickling and unpickling?
E: Pickling은 조립된 레고를 설명서와 함께 상자에 담아 보관하는 것, Unpickling은 상자를 열어 똑같이 다시 조립하는 것입니다.
A: Pickling은 pickle 모듈로 Python Object를 Byte Stream으로 Serialization(직렬화)하는 것(dump/dumps)이고, Unpickling은 그 Byte Stream을 다시 Object로 복원(Deserialization)하는 것(load/loads)입니다. Unpickling은 임의의 코드를 실행할 수 있어 믿을 수 없는 Data는 절대 Unpickling하면 안 되고, 다른 언어와 Data를 주고받을 때는 JSON을 씁니다.

### How can files be deleted in Python?
A: `os.remove(path)`나 `pathlib.Path(path).unlink()`로 파일을 지우고, 빈 Directory는 `os.rmdir()`, 내용이 있는 Directory는 `shutil.rmtree()`로 지웁니다. 파일이 없으면 FileNotFoundError가 나므로 미리 확인하거나 Exception을 처리합니다.

### What advantages do NumPy arrays offer over nested lists? Is NumPy better than lists?
E: list는 상자마다 "진짜 물건은 창고 어딘가에"라는 쪽지만 들어 있는 것이고, NumPy Array는 같은 크기의 숫자가 나란히 담긴 계란판입니다. 계란판은 한 번에 통째로 계산기에 넣을 수 있습니다.
A: NumPy Array는 같은 Type의 값을 연속된 Memory에 저장해 Memory를 적게 쓰고 Cache 효율이 좋습니다. Loop 없이 `a + b`, `a * 2` 같은 Vectorized 연산을 C로 처리해 많게는 수십 배 이상 빠르고, Broadcasting·Matrix 연산·통계 함수를 제공합니다. 다만 크기가 고정되어 원소를 자주 추가·삭제하거나 서로 다른 Type을 섞을 때는 list가 낫습니다.

### Exception Handling과 with 문은?
E: try는 "일단 해 보고", except는 "안 되면 이렇게 수습", finally는 "성공하든 실패하든 불은 끄고 나가기"입니다. with는 문을 열면 나올 때 자동으로 닫히는 문입니다.
A: try/except는 Exception을 잡아 처리하고, else는 Exception이 없을 때, finally는 항상 실행됩니다. with 문은 Context Manager(`__enter__`/`__exit__`)를 써서 `with open("a.txt") as f:`처럼 Block을 벗어날 때 Exception이 나도 파일·Lock 같은 자원을 확실히 정리합니다. 모든 Exception을 삼키는 `except:` 대신 구체적인 Exception Type을 잡는 것이 좋습니다.
