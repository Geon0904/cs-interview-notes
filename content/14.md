## AI 기초: Agent · Search · Reasoning

#### AI와 Rational Agent
ONE: AI를 보는 가장 쓸모 있는 관점은 **Rational Agent(합리적 에이전트)**예요. 주변을 **인식(Sensor)**하고 **행동(Actuator)**해서, **성과 척도를 최대화하는 행동**을 고르는 존재예요.
LIKE: 로봇 청소기를 떠올려 보세요. 센서로 먼지와 장애물을 느끼고(인식), 바퀴와 솔로 움직이며(행동), "짧은 시간에 집을 깨끗하게"라는 목표 점수를 최대로 하려고 해요. 사람처럼 생각하는지는 중요하지 않고, 결과적으로 올바르게 행동하면 돼요.
STEP:
1. **Agent**: 환경을 인식하고 행동하는 모든 것이에요. 로봇, 게임 AI, 추천 시스템, 챗봇.
2. **Rational (합리적)**: 지금까지 알게 된 정보로 **성과 척도의 기댓값이 가장 큰 행동**을 고르는 거예요. 모든 걸 아는 전지전능함과는 달라요.
3. **환경의 성질**: 완전히 보이는가/일부만 보이는가, 결과가 정해져 있나/확률적인가, 지금 행동이 미래에 영향을 주나, 혼자인가/상대가 있나.
4. 체스는 "완전히 보이고, 결과가 정해져 있고, 칸이 나뉜" 쉬운 환경이에요. 자율주행은 그 반대쪽 끝이에요(일부만 보이고, 확률적이고, 연속적이고, 다른 차들이 있음).
5. **Agent의 종류 (단순 → 복잡)**: 지금 보이는 것에만 규칙으로 반응(Simple Reflex) → 안 보이는 상태도 추적(Model-Based) → 목표에 이르는 순서를 계획(Goal-Based) → 여러 방법 중 가장 만족스러운 것 선택(Utility-Based) → 경험으로 스스로 개선(Learning Agent).
6. **Machine Learning**은 Agent가 "경험으로 스스로 개선"하게 만드는 방법이에요. 이 주제의 나머지가 그 이야기예요.
END: AI = 인식하고 행동해서 목표를 최대화하는 Rational Agent. 환경이 어려울수록 더 정교한 Agent가 필요해요.

#### Search: 문제를 길 찾기로 풀기
ONE: 많은 문제는 **"시작 상태에서 목표 상태까지 가는 행동 순서 찾기"**로 바꿀 수 있어요. 어떤 정보를 쓰느냐에 따라 **BFS·DFS·UCS·A\*** 같은 탐색 전략이 나뉘어요.
LIKE: 낯선 도시에서 목적지를 찾는다고 해 봐요. 아무 정보 없이 가까운 골목부터 다 둘러볼 수도(BFS), 한 길로 끝까지 가 볼 수도(DFS), 지금까지 걸은 거리만 보고 갈 수도(UCS), "목적지까지 직선거리"라는 힌트를 함께 쓸 수도(A*) 있어요.
STEP:
1. **문제 정의**: 시작 상태, 가능한 행동, 행동의 결과, 목표 판정, 경로 비용을 정하면 탐색 문제가 돼요. 예: 퍼즐, 길 찾기, 일정 짜기.
2. **BFS (너비 우선)**: 가까운 것부터 층층이. 비용이 모두 같으면 최단 경로를 보장하지만 Memory를 아주 많이 써요.
3. **UCS (균일 비용)**: 지금까지의 비용이 가장 작은 것부터. 비용이 달라도 최적이에요(Dijkstra와 같은 아이디어).
4. **DFS (깊이 우선)**: 한 길을 끝까지. Memory는 적지만 최적을 보장하지 않고, 끝없는 공간에서는 빠져나오지 못할 수 있어요.
5. **Iterative Deepening (반복 심화)**: 깊이 1까지, 2까지, 3까지… 제한을 늘리며 DFS를 반복해요. DFS의 적은 Memory와 BFS의 완전성을 함께 얻어요.
6. **Greedy Best-First**: "목표까지 남은 거리 추정치(Heuristic)"가 가장 작은 곳부터. 빠르지만 최적을 보장하지 않아요.
7. **A\***: **지금까지 비용 + 남은 거리 추정치**가 가장 작은 곳부터. 추정치가 실제보다 **크게 잡지 않으면(Admissible)** 최적 경로를 보장해요.
| 전략 | 쓰는 정보 | 최적성 | Memory |
| BFS | 없음 | 비용이 같을 때 | 매우 큼 |
| UCS | 지금까지 비용 | 예 | 큼 |
| DFS | 없음 | 아니오 | 작음 |
| Iterative Deepening | 없음 | 비용이 같을 때 | 작음 |
| Greedy Best-First | 남은 거리 추정 | 아니오 | 큼 |
| A* | 지금까지 + 추정 | 추정이 과대평가하지 않으면 | 큼 |
KEY: 좋은 Heuristic은 **문제의 제약을 일부 풀어 버린 쉬운 문제의 정답**에서 나와요. 퍼즐 조각이 다른 조각을 통과할 수 있다고 가정하면, 각 조각의 목표 위치까지 거리의 합이 실제 비용을 넘지 않는 좋은 추정치가 돼요.
END: 문제를 상태와 행동으로 바꾸면 탐색 문제가 돼요. 힌트(Heuristic)를 잘 쓰는 A*가 최적이면서 빨라요.

#### Local Search: 좋은 답 하나만 찾기
ONE: 경로가 아니라 **좋은 최종 상태 하나**만 필요할 때, 현재 답을 **조금씩 고쳐 가며** 개선하는 방법이에요. Hill Climbing, Simulated Annealing, Genetic Algorithm이 대표적이에요.
LIKE: 안개 낀 산에서 가장 높은 곳을 찾는데 지도가 없어요. 한 걸음씩 더 높은 쪽으로 오르면(Hill Climbing) 작은 언덕 꼭대기에 갇힐 수 있어요. 그래서 처음에는 가끔 내려가는 것도 허락하거나(Simulated Annealing), 여러 사람이 흩어져 찾다가 잘 찾은 사람들의 방법을 섞어요(Genetic Algorithm).
STEP:
1. **Hill Climbing**: 지금보다 나은 이웃 상태로 계속 이동해요. 단순하지만 **Local Optimum**(주변에서만 최고인 곳)에 갇혀요.
2. **Simulated Annealing**: 금속을 천천히 식히는 담금질에서 따온 이름이에요. 처음(온도가 높을 때)에는 나쁜 방향으로 가는 것도 가끔 허용하고, 점점 허용 확률을 줄여요. 작은 언덕을 빠져나올 기회를 줘요.
3. **Genetic Algorithm**: 여러 답(개체)을 동시에 두고, 좋은 답끼리 섞고(교배), 가끔 무작위로 바꾸고(변이), 좋은 답만 살아남게 하기를 반복해요.
4. **연속 공간에서는**: 같은 아이디어가 **Gradient Descent**예요. 경사를 따라 Loss가 낮아지는 쪽으로 조금씩 이동해요(아래 Optimization).
USE: 시간표 짜기, 배송 경로 최적화, 회로 배치, Neural Network 학습(Gradient Descent).
END: 경로가 필요 없으면 지금 답을 조금씩 고쳐요. 갇히지 않으려면 가끔 나쁜 쪽도 허용하거나 여러 답을 섞어요.

#### Game Search: Minimax · Alpha-Beta · MCTS
ONE: 상대가 있는 게임에서는 **"상대도 최선을 다한다"**고 가정하고 수를 고르는 **Minimax**를 써요. 볼 필요 없는 가지를 잘라 내는 **Alpha-Beta Pruning**, 무작위 대국을 많이 해 보는 **MCTS**로 더 멀리 봐요.
LIKE: 틱택토에서 "내가 여기 두면 상대는 나에게 가장 불리한 곳에 둘 거고, 그러면 나는…"을 끝까지 생각해 보는 거예요. 그리고 "이 수는 이미 앞에서 본 수보다 확실히 나쁘다"는 걸 알면 더 깊이 볼 필요가 없어요.
STEP:
1. **Game Tree**: 내 수, 상대 수, 내 수…를 번갈아 펼친 나무예요.
2. **Minimax**: 내 차례에는 점수가 **최대**인 수를, 상대 차례에는 (나에게) 점수가 **최소**인 수를 고른다고 가정하고 아래에서부터 점수를 올려 계산해요.
3. **Alpha-Beta Pruning**: 결과에 영향을 줄 수 없는 가지를 건너뛰어요. 좋은 수부터 먼저 살펴보면, 같은 시간에 약 **두 배 깊이**까지 볼 수 있어요.
4. **깊이 제한 + 평가 함수**: 체스는 끝까지 볼 수 없으니, 일정 깊이에서 "지금 형세 점수"를 추정해요(말의 가치 합 등).
5. **MCTS (Monte Carlo Tree Search)**: 평가 함수를 만들기 어려운 게임에서, 각 수 뒤에 무작위 대국을 아주 많이 시뮬레이션해 승률로 수를 평가해요.
6. 바둑 AI **AlphaGo**는 MCTS와 Neural Network(수의 가능성과 형세를 평가)를 결합해 2016년 이세돌 9단을 이겼어요.
END: 상대도 최선을 다한다고 보고(Minimax), 필요 없는 가지는 자르고(Alpha-Beta), 어려우면 많이 두어 보며(MCTS) 수를 골라요.

#### CSP (Constraint Satisfaction Problem)
ONE: **변수**, 각 변수가 가질 수 있는 **값의 범위**, 변수들 사이의 **제약**으로 정의되는 문제예요. 스도쿠, 시간표, 지도 색칠이 대표적이에요.
LIKE: 시간표 짜기를 생각해 보세요. 과목(변수)마다 넣을 수 있는 시간(값)이 있고, "같은 선생님 수업은 겹치면 안 된다" 같은 규칙(제약)이 있어요. 모든 규칙을 만족하는 배치를 찾는 문제예요.
STEP:
1. **변수**: 값을 정해야 할 것들. 스도쿠의 빈칸 81개.
2. **Domain (값의 범위)**: 각 변수가 가질 수 있는 값. 1~9.
3. **Constraint (제약)**: 같은 행·열·3×3 칸에 같은 숫자 불가.
4. 기본 풀이는 **Backtracking**이에요. 하나씩 값을 정하다가 규칙을 어기면 되돌아가요(07번 주제).
5. **요령 ① MRV**: 남은 선택지가 **가장 적은 변수부터** 정해요. 막힐 곳을 먼저 처리하면 실패를 일찍 발견해요.
6. **요령 ② LCV**: 다른 변수의 선택지를 **가장 적게 줄이는 값부터** 시도해요. 성공 가능성을 높여요.
7. **요령 ③ 제약 전파 (Forward Checking 등)**: 값을 하나 정할 때마다 이웃 변수에서 불가능해진 값을 즉시 지워요. 선택지가 0이 된 변수가 생기면 바로 되돌아가요.
USE: 시간표·근무표 짜기, 회의실 배정, 스도쿠, 회로 설계, SAT Solver(논리 문제를 CSP로 풀기).
END: CSP = 변수 + 값 + 제약. Backtracking에 "어려운 것부터, 여지를 남기는 값부터, 즉시 지우기"를 더하면 훨씬 빨라져요.

#### Logic과 Planning: 규칙으로 추론하기
ONE: 지식을 **논리식**으로 적어 두고 규칙에 따라 새 사실을 **추론**하거나, 행동을 **"전제 조건 → 효과"**로 적어 목표까지의 **행동 순서를 계획**하는 방법이에요.
LIKE: "모든 사람은 죽는다", "소크라테스는 사람이다"를 알면 "소크라테스는 죽는다"를 끌어낼 수 있어요. Planning은 요리처럼 "물이 끓으면(전제) 면을 넣을 수 있고, 넣으면 면이 익는다(효과)"를 이어 붙여 "라면 완성"까지의 순서를 찾는 거예요.
STEP:
1. **Propositional Logic (명제 논리)**: 참/거짓인 문장들을 AND·OR·NOT·→로 엮어 추론해요(01번 주제). 모든 경우를 따지거나 추론 규칙(Resolution)을 써요.
2. **SAT Solver**: "이 논리식을 참으로 만드는 값이 있나?"를 푸는 도구예요. NP-Complete 문제지만(08번 주제), 실제로는 아주 큰 문제도 잘 풀어 내요.
3. **First-Order Logic (1차 논리)**: "모든", "어떤" 같은 양화사와 대상·관계를 표현할 수 있어 훨씬 표현력이 크지만, 추론이 어려워요.
4. **Planning**: 행동을 "전제 조건"과 "효과"로 기술하고, 초기 상태에서 목표 상태까지 가는 행동 순서를 찾아요. 탐색 문제지만 상태가 사실들의 집합이라 더 강한 Heuristic을 쓸 수 있어요.
5. 실제 Planning은 시간·자원 제약, 큰 작업을 작은 작업으로 나누기(계층적 분해), 예상과 다른 상황에서 다시 계획하기를 다뤄야 해요.
WHY: 데이터에서 배우는 Machine Learning과 달리, 명확한 규칙이 있는 영역(법 규정, 설정 검증, 로봇 작업 순서)에서는 논리와 계획이 정확하고 설명 가능한 답을 줘요.
END: 사실과 규칙으로 새 사실을 끌어내면 Logic, 행동의 전제·효과를 이어 목표까지 가면 Planning이에요.

### Rational Agent란 무엇인가요?
E: 로봇 청소기처럼 센서로 주변을 느끼고, 바퀴로 움직이며, "짧은 시간에 깨끗하게"라는 점수를 최대로 하는 행동을 고르는 존재입니다.
A: Rational Agent는 Sensor로 Environment를 인식(Percept)하고 Actuator로 행동하며, 지금까지의 인식과 지식을 바탕으로 Performance Measure의 기댓값을 최대화하는 행동을 고르는 Agent입니다. 사람처럼 생각하는지가 아니라 결과적으로 올바르게 행동하는지를 기준으로 하며, Environment가 부분 관찰·확률적·동적·다중 Agent일수록 Model-Based, Goal-Based, Utility-Based, Learning Agent처럼 더 정교한 구조가 필요합니다.

### A* Search는 어떻게 동작하고, 언제 최적 경로를 보장하나요?
E: "지금까지 걸어온 거리 + 목적지까지 직선거리"가 가장 짧은 길부터 살펴보는 길 찾기입니다. 직선거리는 실제로 가야 할 거리보다 길 수 없으므로 믿을 만한 힌트가 됩니다.
A: A*는 각 Node를 f(n) = g(n) + h(n)으로 평가해 가장 작은 것부터 확장합니다. g(n)은 시작점에서 n까지의 실제 비용, h(n)은 n에서 목표까지의 추정 비용(Heuristic)입니다. h가 실제 비용을 과대평가하지 않으면(Admissible) Tree Search에서 최적이고, Graph Search에서는 Consistent(일관된) Heuristic일 때 최적이 보장됩니다. 좋은 Heuristic은 문제 제약을 완화한 쉬운 문제의 정답에서 얻습니다.

### Minimax와 Alpha-Beta Pruning이란?
E: 틱택토에서 "내가 여기 두면 상대는 나에게 가장 나쁜 곳에 둘 것"이라고 가정하고 끝까지 따져 보는 것이 Minimax, 이미 더 나쁘다고 확인된 수는 끝까지 보지 않고 건너뛰는 것이 Alpha-Beta Pruning입니다.
A: Minimax는 Game Tree에서 내 차례(Max)는 최대 점수, 상대 차례(Min)는 최소 점수를 고른다고 가정하고 Leaf의 평가값을 위로 전파해 최선의 수를 찾습니다. Alpha-Beta Pruning은 지금까지 Max가 보장받은 최솟값 α와 Min이 보장받은 최댓값 β를 들고 다니며, 결과에 영향을 줄 수 없는 가지를 건너뛰어 같은 결과를 더 빨리 얻습니다. 수 순서가 좋으면 탐색량이 약 O(b^(d/2))로 줄어 같은 시간에 두 배 깊이까지 봅니다.

### CSP란? Backtracking을 빠르게 하는 요령은?
E: 시간표 짜기처럼 과목(변수)마다 넣을 시간(값)을 고르되 "같은 선생님은 겹치면 안 된다" 같은 규칙(제약)을 모두 지키는 배치를 찾는 문제입니다.
A: CSP(Constraint Satisfaction Problem)는 변수, 각 변수의 Domain, 변수 간 Constraint로 정의되며 스도쿠·시간표·지도 색칠이 대표적입니다. 기본은 Backtracking이고, 남은 값이 가장 적은 변수부터 고르는 MRV(Minimum Remaining Values), 다른 변수의 선택지를 가장 적게 줄이는 값부터 시도하는 LCV(Least Constraining Value), 값을 정할 때마다 이웃의 불가능한 값을 지우는 Forward Checking·Arc Consistency(제약 전파)를 더하면 크게 빨라집니다.

## Machine Learning 기본

#### Machine Learning이란? 규칙 대신 데이터로
ONE: **Machine Learning**은 사람이 규칙을 직접 짜는 대신, **데이터에서 규칙을 스스로 찾게** 하는 방법이에요. 목표는 **처음 보는 데이터에서도 잘 맞히는 것(Generalization)**이에요.
LIKE: 시험 공부와 같아요. 기출문제(Training Data)로 공부하고, 모의고사(Validation Data)로 실력을 점검하고, 실제 시험(Test Data)에서 점수를 받아요. 기출문제 답만 외우면(Overfitting) 실제 시험을 망쳐요.
STEP:
1. **전통적 프로그래밍**: 사람이 규칙을 써요. "제목에 '무료'가 있으면 스팸".
2. 하지만 스팸은 계속 진화하고, 규칙을 다 쓰는 건 불가능해요.
3. **Machine Learning**: 스팸/정상 메일 예시를 잔뜩 주면, 모델이 스스로 "어떤 특징이 스팸을 가르는지" 찾아내요.
4. **학습 과정**: 모델이 예측 → 정답과 비교해 얼마나 틀렸는지 계산(**Loss Function**) → 덜 틀리도록 모델의 숫자(**Parameter, Weight**)를 조금 고치기 → 반복.
5. **목표는 Generalization**: 학습 데이터를 외우는 게 아니라, 처음 보는 메일에서도 잘 맞혀야 해요.
6. **좋은 모델의 조건**: 새 데이터에서의 성능(가장 중요), 비즈니스 목표에 맞는 평가 기준, 비슷한 성능이면 더 단순한 모델(Occam's Razor), 필요한 만큼의 해석 가능성, 예측 속도와 비용, 집단 간 공정성.
END: Machine Learning = 데이터로 규칙 찾기. Loss를 줄이도록 Weight를 고치고, 목표는 처음 보는 데이터에서 잘 맞히기예요.

#### 학습의 종류: Supervised · Unsupervised · Self-Supervised · Reinforcement
ONE: 정답을 어떻게 주느냐에 따라 **정답이 있는 학습(Supervised)**, **정답 없이 구조 찾기(Unsupervised)**, **데이터 자체에서 정답 만들기(Self-Supervised)**, **행동하고 보상받으며 배우기(Reinforcement)**로 나뉘어요.
LIKE: Supervised는 답안지가 있는 문제집, Unsupervised는 답 없이 비슷한 문제끼리 묶어 보기, Self-Supervised는 문장의 빈칸을 스스로 가리고 맞히는 연습, Reinforcement는 강아지 훈련처럼 행동한 뒤 간식(Reward)을 받으며 배우는 거예요.
STEP:
1. **Supervised Learning (지도 학습)**: 입력과 정답(Label) 쌍으로 배워요. 정답이 범주면 **Classification**(스팸/정상), 숫자면 **Regression**(집값).
2. **Unsupervised Learning (비지도 학습)**: 정답 없이 데이터의 숨은 구조를 찾아요. 비슷한 고객끼리 묶기(**Clustering**), 차원 줄이기(**Dimensionality Reduction**).
3. **Semi-Supervised Learning**: 정답이 있는 소수 데이터와 정답 없는 다수 데이터를 함께 써요. 정답 붙이기가 비쌀 때 유용해요.
4. **Self-Supervised Learning (자기 지도 학습)**: 데이터 자체에서 문제와 정답을 만들어요. 문장의 다음 단어 맞히기, 가린 단어 맞히기. 사람이 정답을 붙이지 않아도 엄청난 양으로 학습할 수 있어서 **LLM의 Pre-training**이 이 방식이에요.
5. **Reinforcement Learning (강화 학습)**: Agent가 환경 속에서 행동하고 Reward를 받으며, 누적 Reward를 최대로 하는 행동 전략(Policy)을 배워요. 게임, 로봇 제어.
| 종류 | 데이터 | 목표 | 예 |
| Supervised | 입력 + 정답 | 새 입력의 정답 예측 | 스팸 분류, 집값 예측 |
| Unsupervised | 입력만 | 숨은 구조 발견 | 고객 군집, 차원 축소 |
| Self-Supervised | 데이터에서 정답 생성 | 표현 학습 | 다음 단어 예측(LLM) |
| Reinforcement | 행동과 보상 | 누적 보상 최대화 | 게임, 로봇 |
END: 정답이 있으면 Supervised, 없으면 Unsupervised, 스스로 만들면 Self-Supervised, 보상으로 배우면 Reinforcement예요.

#### Feature Vector
ONE: **Feature Vector**는 데이터 하나를 모델이 이해할 수 있게 **특징들을 숫자 목록으로** 바꾼 것이에요. 어떤 Feature를 만드느냐가 전통적 ML 성능을 크게 좌우해요.
LIKE: 집을 컴퓨터에게 설명할 때 "면적 84, 방 3개, 역까지 7분, 12층"처럼 숫자 목록으로 바꾼 게 Feature Vector예요.
STEP:
1. **Feature (특징)**: 예측에 도움이 될 측정 가능한 성질이에요. 집값이라면 면적, 방 수, 위치.
2. **Feature Vector**: 그 Feature들을 순서대로 나열한 숫자 Vector예요. x = (84, 3, 7, 12).
3. **텍스트**: 단어 빈도(BoW, TF-IDF)나 의미를 담은 Embedding Vector로 바꿔요(16번 주제).
4. **이미지**: 픽셀 값들을 숫자로 써요.
5. **Feature Engineering**: 원래 데이터에서 더 유용한 Feature를 만드는 일이에요. "생년월일"보다 "나이", "주소"보다 "역까지 거리"가 더 쓸모 있을 수 있어요.
6. Deep Learning은 Feature를 사람이 만드는 대신 모델이 스스로 배우는 방향으로 발전했어요(15번 주제).
END: Feature Vector는 데이터를 숫자 목록으로 바꾼 것이고, 좋은 Feature가 좋은 모델을 만들어요.

#### Machine Learning과 통계의 차이
ONE: 둘은 많이 겹치지만, **통계**는 "**왜 그런가(해석·인과·불확실성)**"에, **Machine Learning**은 "**얼마나 잘 맞히는가(예측 성능·확장성)**"에 더 무게를 둬요.
LIKE: 의사가 "이 약이 정말 효과가 있나, 왜 효과가 있나"를 따지는 게 통계적 관점이라면, "이 환자가 다음 달에 재입원할지 정확히 맞히기"에 집중하는 게 ML적 관점이에요.
STEP:
1. **통계**: 데이터가 어떻게 생겨났는지 가정(예: 정규 분포)을 세우고, Parameter의 의미, 불확실성(신뢰구간), 인과관계를 중요하게 봐요.
2. **Machine Learning**: 가정을 덜 두더라도, 새 데이터에 대한 예측 성능과 대규모 데이터·복잡한 모델로의 확장을 중요하게 봐요.
3. 같은 Linear Regression도 통계에서는 "계수가 유의한가?"를, ML에서는 "Test 오차가 얼마인가?"를 먼저 물어요.
4. **실무**: 예측은 ML로, 의사결정의 근거와 실험(A/B Test) 해석은 통계로 보완해요.
END: 통계는 "왜", ML은 "얼마나 잘". 둘은 경쟁이 아니라 서로를 보완해요.

### Supervised·Unsupervised·Semi-Supervised·Reinforcement Learning의 차이는?
E: Supervised Learning은 답안지가 있는 문제집, Unsupervised Learning은 답안 없이 비슷한 문제끼리 묶어 보기, Semi-Supervised Learning은 답이 몇 개만 있는 문제집, Reinforcement Learning은 강아지 훈련처럼 행동한 뒤 간식(Reward)을 받으며 배우는 것입니다.
A: Supervised Learning(지도 학습)은 입력과 정답(Label) 쌍으로 Classification·Regression을 학습하고, Unsupervised Learning(비지도 학습)은 Label 없이 Clustering·Dimensionality Reduction 같은 구조를 찾습니다. Semi-Supervised Learning은 적은 Label과 많은 Unlabeled 데이터를 함께 쓰고, Reinforcement Learning(강화 학습)은 Agent가 Environment와 상호작용하며 누적 Reward를 최대화하는 Policy를 배웁니다. LLM Pre-training처럼 데이터 자체에서 정답을 만드는 Self-Supervised Learning도 있습니다.

### Feature Vector란?
E: 집을 컴퓨터에게 설명할 때 "면적 84, 방 3개, 역까지 7분, 층수 12"처럼 숫자 목록으로 바꾼 것이 Feature Vector입니다.
A: Feature Vector는 하나의 데이터를 모델이 처리할 수 있도록 측정 가능한 특성들을 숫자로 나열한 Vector x ∈ Rᵈ입니다. 텍스트는 단어 빈도나 Embedding, 이미지는 픽셀 값으로 만들며, 어떤 Feature를 어떻게 만드느냐(Feature Engineering)가 전통적 Machine Learning 성능을 크게 좌우합니다.

### Machine Learning적 접근과 통계적 접근의 차이는?
A: 둘은 많이 겹치지만 목적의 무게가 다릅니다. Statistics는 데이터 생성 과정에 대한 가정을 세우고 Parameter의 해석·불확실성·Causal Inference("왜 그런가")에 무게를 두고, Machine Learning은 가정을 덜 두더라도 새 데이터에 대한 예측 성능("얼마나 잘 맞히는가")과 대규모 데이터·복잡한 모델의 확장성에 무게를 둡니다. 실무에서는 예측은 ML로, 의사결정의 근거와 실험 해석은 Statistics로 보완합니다.

### 좋은 모델의 정의는?
A: 가장 중요한 것은 학습에 쓰지 않은 데이터에서도 성능이 유지되는 Generalization(일반화) 능력이며, 그 성능을 비즈니스 목표에 맞는 Metric으로 재야 합니다. 그 위에 비슷한 성능이면 더 단순한 모델(Occam's Razor), 필요한 만큼의 Interpretability(해석 가능성), 예측 속도·비용, 데이터 변화에 대한 Robustness, 집단 간 Fairness까지 갖춘 모델이 좋은 모델입니다.

## Data 준비

#### Feature Scaling
ONE: Feature마다 **범위(단위)가 크게 다르면** 큰 숫자를 가진 Feature가 모델을 지배해요. 그래서 범위를 비슷하게 맞추는 **Scaling**을 해요.
LIKE: 키(150~190cm)와 연봉(수천만 원)을 그대로 거리로 재면 연봉 차이만 보이고 키는 무시돼요. 단위를 맞춰야 공정하게 비교돼요.
STEP:
1. **거리 기반 모델 문제**: KNN, K-means, SVM은 거리를 계산하는데, 범위가 큰 Feature가 거리를 거의 다 차지해요.
2. **Gradient Descent 문제**: Feature 범위가 다르면 Loss 지형이 길쭉한 골짜기 모양이 돼서 지그재그로 느리게 내려가요.
3. **Regularization 문제**: 범위가 다르면 Weight 크기도 달라져서 벌점이 Feature마다 불공평해져요.
4. **Min-Max Scaling**: (x − min) / (max − min). 0~1로 맞춰요. Outlier 하나가 있으면 나머지가 좁은 범위에 몰려요.
5. **Standardization (Z-score)**: (x − 평균) / 표준편차. 평균 0, 표준편차 1로 맞춰요. 가장 흔히 써요.
6. **Robust Scaler**: Median과 IQR을 써서 Outlier에 강해요.
KEY: Scaler는 **Training Data로만 fit**(평균·표준편차 계산)하고, Validation·Test에는 그 값으로 **transform만** 해요. 전체 데이터로 fit하면 Test 정보가 새어 들어가요(Data Leakage). Tree 모델은 Scaling이 필요 없어요.
END: 범위가 다르면 맞춰요(Min-Max, Standardization, Robust). Scaler는 Training Data로만 맞춰요.

#### Categorical Variable Encoding
ONE: "서울·부산·대구" 같은 **범주형 값**은 숫자로 바꿔야 모델이 쓸 수 있어요. 순서가 없으면 **One-Hot**, 순서가 있으면 **Label(Ordinal) Encoding**을 써요.
LIKE: 좋아하는 과일을 "사과 = 1, 바나나 = 2, 포도 = 3"으로 적으면, 컴퓨터는 "포도가 사과보다 3배 크다"고 오해할 수 있어요. 그래서 "사과인가? 바나나인가? 포도인가?"를 각각 0/1로 따로 적어요.
STEP:
1. **One-Hot Encoding**: 범주마다 0/1 Column을 만들어요. 서울 = (1, 0, 0), 부산 = (0, 1, 0), 대구 = (0, 0, 1). 순서가 없는 범주(도시, 색상)에 맞아요.
2. One-Hot의 문제: 범주가 수천 개면 Column도 수천 개로 늘어나요(차원 폭발).
3. **Label (Ordinal) Encoding**: 범주를 정수로 바꿔요. 순서가 있는 범주(초급 < 중급 < 고급)에 맞아요.
4. 순서가 없는 범주에 Label Encoding을 쓰면 Linear Model이 없는 크기 관계(서울 1 < 부산 2)를 배워 버려요. 다만 Tree 모델은 값을 기준으로 나누기만 해서 괜찮은 경우가 많아요.
5. **범주가 아주 많을 때 (High Cardinality)**: 범주별 정답 평균으로 바꾸는 **Target Encoding**(Leakage에 주의), Hash로 고정 크기로 줄이는 **Hashing**, 의미를 학습하는 **Embedding**.
END: 순서 없으면 One-Hot, 순서 있으면 Label, 범주가 너무 많으면 Target Encoding·Hashing·Embedding이에요.

#### Class Imbalance (클래스 불균형)
ONE: 한 Class가 **매우 드물면**(사기 거래 0.1%) 모델이 "다 정상"이라고만 해도 정확도가 높게 나와요. 그래서 **평가 기준, 데이터, 학습, Threshold**를 모두 다르게 다뤄야 해요.
LIKE: 거래 1,000건 중 사기가 1건이면, 모두 "정상"이라고만 답해도 Accuracy 99.9%예요. 하지만 사기는 하나도 못 잡아요. 경비원이 "아무 일도 없을 거야"라고만 말해도 99.9% 맞는 것과 같아요.
STEP:
1. **평가 바꾸기**: Accuracy 대신 Recall(사기를 얼마나 찾았나), Precision(사기라고 한 것 중 진짜 비율), F1, PR-AUC를 봐요.
2. **나누기**: Train/Test를 나눌 때 Class 비율을 유지하는 Stratified Split을 해요.
3. **데이터 조정**: 드문 Class를 늘리거나(Oversampling, SMOTE는 비슷한 가짜 Sample을 합성) 많은 Class를 줄여요(Undersampling). **Training Data에만** 적용해야 해요.
4. **학습 조정**: 드문 Class를 틀리면 더 큰 벌점을 주는 Class Weight를 줘요.
5. **Threshold 조정**: 모델이 "사기 확률 50% 이상이면 사기"라고 할 필요 없어요. 사기를 놓치는 비용이 크면 Threshold를 10%로 낮춰 더 많이 잡아요.
END: 드문 Class는 Accuracy로 평가하지 말고, 데이터·가중치·Threshold를 조정해 찾아내요.

#### Data Leakage (데이터 누수)
ONE: 예측하는 시점에는 **알 수 없는 정보**가 학습에 섞여 들어가 **검증 점수가 부풀려지는** 문제예요. 실제 서비스에서는 성능이 무너져요.
LIKE: 모의고사 전에 답지를 살짝 본 거예요. 점수는 잘 나오지만 실제 시험에서는 무너져요.
STEP:
1. **전처리 누수**: 데이터를 나누기 전에 전체로 Scaling이나 결측값 채우기를 하면, Test의 정보(평균 등)가 학습에 섞여요.
2. **시간 누수**: 시계열 데이터를 무작위로 나누면 미래 데이터로 과거를 맞히는 셈이 돼요. 과거로 학습하고 미래로 검증해야 해요.
3. **그룹 누수**: 같은 사용자의 데이터가 Train과 Test에 모두 들어가면, 모델이 그 사람을 외워서 점수가 좋아 보여요.
4. **정답에서 파생된 Feature**: "환불 완료 여부"로 "환불 요청 여부"를 예측하면, 결과를 보고 원인을 맞히는 셈이에요.
5. **막는 법**: 전처리를 Pipeline으로 묶어 Training Data로만 fit하고, 시간·그룹 단위로 나누고, Feature마다 "예측 시점에 이 값을 알 수 있나?"를 따져요.
KEY: 검증 점수가 **믿기 어려울 만큼 좋으면** 먼저 Leakage를 의심하세요.
END: 예측 시점에 모르는 정보가 섞이면 점수가 거짓말을 해요. Pipeline과 올바른 분할로 막아요.

### Feature Scaling(정규화)을 왜 해야 하나요? 방법은?
E: 키(cm, 150~190)와 연봉(원, 수천만)을 그대로 거리로 재면 연봉 차이만 보이고 키는 무시됩니다. 단위를 맞춰야 공정하게 비교됩니다.
A: Feature의 범위가 크게 다르면 KNN·K-means·SVM처럼 거리를 쓰는 모델이 큰 Feature에 끌려가고, Gradient Descent의 등고선이 길쭉해져 수렴이 느려지며, Regularization Penalty가 Feature마다 불공정해집니다. Min-Max Scaling은 (x − min)/(max − min)으로 0~1에 맞추지만 Outlier에 약하고, Standardization(Z-score)은 (x − μ)/σ로 평균 0·표준편차 1로 만들며, Outlier가 많으면 Median·IQR을 쓰는 Robust Scaler를 씁니다. Scaler는 Training Data로만 맞추고(fit) Validation·Test에는 적용(transform)만 하며, Tree 모델은 Scaling이 필요 없습니다.

### Categorical Variable Encoding(One-Hot, Label)은?
A: One-Hot Encoding은 범주마다 0/1 Column을 만들어 순서가 없는 범주(도시, 색상)에 적합하지만 범주가 많으면 차원이 폭발합니다. Label(Ordinal) Encoding은 범주를 정수로 바꾸므로 순서가 있는 범주(학년, 등급)나 Tree 모델에는 괜찮지만, Linear Model에 쓰면 없는 크기 관계(서울 = 1 < 부산 = 2)를 만듭니다. 범주가 수천 개이면(High Cardinality) Target Encoding(Leakage 주의), Hashing, Embedding을 씁니다.

### Class Imbalance는 어떻게 다루나요?
E: 거래 1,000건 중 사기가 1건이면, 모두 "정상"이라고만 답해도 Accuracy 99.9%입니다. 하지만 사기는 하나도 못 잡습니다.
A: 먼저 Accuracy 대신 Recall·Precision·F1·PR-AUC로 평가하고 Stratified Split을 합니다. 데이터 수준에서는 소수 Class Oversampling(SMOTE 등)이나 다수 Class Undersampling을 Training Data에만 적용하고, 모델 수준에서는 Class Weight를 주며, 마지막으로 비즈니스 비용에 맞게 Classification Threshold(임계값)를 조정합니다.

### Data Leakage(데이터 누수)란?
E: 모의고사 전에 답지를 살짝 본 것입니다. 점수는 잘 나오지만 실제 시험에서는 무너집니다.
A: Data Leakage는 예측 시점에는 알 수 없는 정보(Test Data, 미래 정보, 정답에서 파생된 값)가 학습에 섞여 Validation 성능이 부풀려지는 문제입니다. 분할 전에 전체 데이터로 Scaling·Imputation하기, Time Series를 무작위로 나누기, 같은 사용자가 Train·Test에 모두 들어가기, "환불 완료 여부"로 "환불 요청"을 예측하기 등이 흔한 예이며, 전처리를 Pipeline으로 묶고 시간·그룹 단위로 분할해 막습니다.

## Evaluation과 Validation

#### 평가 Metric: Regression과 Classification
ONE: 모델을 무엇으로 채점하느냐가 무엇을 잘하게 되느냐를 정해요. **Regression**은 MAE·RMSE, **Classification**은 Precision·Recall·F1 등을 쓰고, **어떤 실수가 더 비싼지**를 기준으로 골라요.
LIKE: 암 검사에서 Precision은 "양성 판정을 받은 사람 중 진짜 환자의 비율", Recall은 "진짜 환자 중 검사가 찾아낸 비율"이에요. 환자를 놓치면 안 되는 검사는 Recall을, 멀쩡한 사람을 수술대에 올리면 안 되는 검사는 Precision을 중시해요.
STEP:
1. **Regression - MAE**: 오차 절댓값의 평균. 단위가 원래와 같고 Outlier에 덜 민감해요.
2. **Regression - MSE / RMSE**: 오차 제곱의 평균(의 제곱근). 큰 오차에 큰 벌점을 줘요.
3. **Classification - Accuracy**: 맞힌 비율. Class가 균형일 때만 믿을 만해요.
4. **Precision** = TP / (TP + FP): "양성이라고 한 것 중 진짜 양성". 거짓 경보를 싫어할 때 중요해요.
5. **Recall** = TP / (TP + FN): "진짜 양성 중 찾아낸 비율". 놓치는 걸 싫어할 때 중요해요.
6. **F1**: Precision과 Recall의 조화평균. 둘 중 하나만 높으면 낮게 나와서 균형을 봐요.
7. **선택 기준**: FP와 FN 중 무엇이 더 비싼가. 스팸 필터는 정상 메일을 스팸함에 넣는 FP가, 암 진단은 환자를 놓치는 FN이 더 비싸요.
| 종류 | Metric | 특징 |
| Regression | MAE | Outlier에 덜 민감 |
| Regression | RMSE | 큰 오차에 큰 벌점 |
| Classification | Accuracy | 균형 데이터에서만 |
| Classification | Precision | 거짓 경보를 줄이고 싶을 때 |
| Classification | Recall | 놓치기를 줄이고 싶을 때 |
| Classification | F1 | 둘의 균형 |
END: 무엇을 채점하느냐가 모델의 성격을 정해요. FP와 FN 중 더 비싼 실수를 기준으로 Metric을 골라요.

#### Confusion Matrix와 Macro · Micro Average
ONE: **Confusion Matrix**는 실제와 예측을 표로 정리해 **TP·FP·FN·TN**을 보여 주는 표이고, 모든 Classification Metric의 출발점이에요. Class가 여러 개면 **Macro**(Class별 평균)와 **Micro**(전체 합산) 평균을 써요.
LIKE: 시험 채점표에 "맞다고 했는데 맞음, 맞다고 했는데 틀림, 틀리다고 했는데 맞음, 틀리다고 했는데 틀림"을 칸별로 세어 둔 거예요.
STEP:
1. **TP (True Positive)**: 양성이라 했고 실제로 양성.
2. **FP (False Positive)**: 양성이라 했는데 실제로 음성(거짓 경보).
3. **FN (False Negative)**: 음성이라 했는데 실제로 양성(놓침).
4. **TN (True Negative)**: 음성이라 했고 실제로 음성.
5. Precision, Recall, Accuracy 모두 이 네 칸으로 계산해요.
6. **Multi-Class의 Macro Average**: Class마다 Metric을 따로 구해 단순 평균해요. 작은 Class도 똑같이 반영돼요.
7. **Micro Average**: 모든 Class의 TP·FP·FN을 합친 뒤 계산해요. 큰 Class에 좌우돼요. 한 Sample에 정답이 하나인 Multi-Class에서는 Micro-F1 = Accuracy예요.
END: Confusion Matrix의 네 칸이 모든 Metric의 재료이고, 여러 Class는 Macro(공평)와 Micro(전체)로 평균해요.

#### ROC Curve · AUC와 PR Curve
ONE: **ROC Curve**는 Threshold를 처음부터 끝까지 바꾸며 **"찾아낸 비율(TPR)"과 "거짓 경보 비율(FPR)"**의 교환 관계를 그린 것이고, **AUC**는 그 아래 넓이예요. 양성이 아주 드물면 **PR Curve**가 더 정직해요.
LIKE: 공항 검색대의 민감도를 올리면 위험물은 더 잘 잡지만(TPR ↑) 엉뚱한 가방도 더 울려요(FPR ↑). ROC는 이 민감도 다이얼을 처음부터 끝까지 돌리며 교환 관계를 그린 그래프예요.
STEP:
1. 모델은 보통 확률(점수)을 내고, Threshold(예: 0.5)로 양성/음성을 정해요.
2. Threshold를 낮추면 더 많이 양성이라고 해서 TPR(Recall)도, FPR도 올라가요.
3. **ROC Curve**: x축 FPR, y축 TPR로 모든 Threshold의 점을 이어요.
4. **AUC (Area Under Curve)**: ROC 아래 넓이. "무작위로 고른 양성이 무작위로 고른 음성보다 높은 점수를 받을 확률"이에요. 0.5는 동전 던지기, 1은 완벽한 순위.
5. Threshold와 상관없이 모델의 "순위 매기는 능력"을 볼 수 있어요.
6. **양성이 매우 드물 때의 문제**: TN이 엄청 많아서 FP가 꽤 있어도 FPR은 작게 보여요. ROC가 실제보다 좋아 보여요.
7. **PR Curve**: x축 Recall, y축 Precision. 드문 양성 문제(사기 탐지)에서 더 정직하게 보여 줘요.
END: ROC·AUC는 Threshold와 무관한 순위 능력, 양성이 드물면 PR Curve와 PR-AUC를 봐요.

#### Cross-Validation
ONE: 데이터를 **k개 묶음으로 나눠 돌아가며** 한 묶음씩 검증용으로 쓰고 평균을 내는 방법이에요. 한 번의 운에 기대지 않고 더 믿을 만하게 평가해요.
LIKE: 모의고사를 한 번만 보면 운이 좋았는지 실력인지 몰라요. 문제집을 5등분해 돌아가며 한 묶음을 시험용으로 남겨 두고 5번 본 평균이 더 믿을 만해요.
STEP:
1. **Train / Validation / Test 나누기**: Train으로 학습, Validation으로 모델과 설정 고르기, Test는 마지막에 **딱 한 번만** 최종 성능 측정.
2. **k-Fold Cross-Validation**: 데이터를 k개(보통 5나 10)로 나눠요. k−1개로 학습하고 남은 1개로 검증하기를 k번 반복해, 평균과 편차를 봐요.
3. 모든 데이터가 한 번씩 검증에 쓰여서 데이터를 낭비하지 않고, 평가의 운이 줄어요.
4. **Stratified k-Fold**: Classification에서 각 묶음의 Class 비율을 유지해요.
5. **Group k-Fold**: 같은 사용자(그룹)의 데이터가 학습과 검증에 나뉘어 들어가지 않게 해요.
6. **Time Series Split**: 과거로 학습하고 미래로 검증해요. 무작위로 섞으면 안 돼요.
KEY: Cross-Validation은 모델 고르기와 Hyperparameter 튜닝에 써요. 최종 성능은 한 번도 안 쓴 Test Set으로 한 번만 재요. Test를 여러 번 보면 Test에 맞춰지게 돼요.
END: 돌아가며 검증하면 운이 줄어요. 고를 땐 Cross-Validation, 최종 확인은 Test 한 번이에요.

### 알고 있는 Metric을 설명해 주세요. Regression·Classification에 알맞은 Metric은?
E: 암 검사에서 Precision은 "양성 판정을 받은 사람 중 진짜 환자의 비율", Recall은 "진짜 환자 중 검사가 찾아낸 비율"입니다. 환자를 놓치면 안 되는 검사는 Recall을, 멀쩡한 사람을 수술대에 올리면 안 되는 검사는 Precision을 중시합니다.
| 종류 | Metric | 뜻과 특징 |
| Regression | MAE | Mean Absolute Error, 단위가 같고 Outlier에 덜 민감 |
| Regression | MSE / RMSE | 오차 제곱 평균(의 제곱근), 큰 오차에 큰 벌점 |
| Regression | R², MAPE | 설명된 분산 비율, 퍼센트 오차(정답이 0 근처면 불안정) |
| Classification | Accuracy | 맞힌 비율, Class가 균형일 때만 믿을 만함 |
| Classification | Precision TP/(TP+FP) | 양성이라고 한 것 중 진짜 양성 |
| Classification | Recall TP/(TP+FN) | 진짜 양성 중 찾아낸 비율 |
| Classification | F1 | Precision과 Recall의 Harmonic Mean(조화평균) |
| Classification | ROC-AUC, PR-AUC, Log Loss | Threshold와 무관한 순위 능력, 확률의 질 |
A: Regression은 Outlier에 강한 MAE와 큰 오차를 크게 보는 RMSE를 상황에 따라 고르고, Classification은 균형 데이터면 Accuracy, 불균형이면 Precision·Recall·F1·PR-AUC를 씁니다. 가장 중요한 기준은 False Positive(FP)와 False Negative(FN) 중 무엇이 더 비싼가이며, 스팸 필터는 정상 메일을 스팸함에 넣는 FP가, 암 진단은 환자를 놓치는 FN이 더 비쌉니다.

### Confusion Matrix와 Macro vs Micro Average는?
A: Confusion Matrix(혼동 행렬)는 실제 Class와 예측 Class를 표로 정리해 TP·FP·FN·TN을 보여 주며 모든 Classification Metric의 출발점입니다. Multi-Class에서 Macro Average는 Class별 Metric을 따로 구해 단순 평균하므로 작은 Class도 똑같이 반영하고, Micro Average는 모든 Class의 TP·FP·FN을 합친 뒤 계산해 큰 Class에 좌우되며, Single-Label Multi-Class에서는 Micro-F1이 Accuracy와 같습니다.

### ROC Curve와 AUC는? PR Curve는 언제 쓰나요?
E: 공항 검색대의 민감도를 올리면 위험물은 더 잘 잡지만(TPR ↑) 엉뚱한 가방도 더 울립니다(FPR ↑). ROC는 민감도를 처음부터 끝까지 돌리며 그 교환 관계를 그린 그래프입니다.
A: ROC Curve는 Classification Threshold를 바꾸며 x축에 FPR(False Positive Rate), y축에 TPR(True Positive Rate = Recall)을 그린 것이고, AUC는 그 아래 넓이로 "무작위 양성이 무작위 음성보다 더 높은 점수를 받을 확률"입니다. 0.5는 무작위, 1은 완벽한 순위입니다. 양성이 매우 드물면 TN이 엄청나게 많아 FPR이 작게 보여 ROC가 낙관적이므로, Precision-Recall을 그리는 PR Curve와 PR-AUC가 더 정직합니다.

### Cross-Validation은 무엇이고 어떻게 해야 하나요?
E: 모의고사를 한 번만 보면 운이 좋았는지 실력인지 모릅니다. 문제집을 5등분해 돌아가며 한 묶음을 시험용으로 남겨 두고 5번 본 평균이 더 믿을 만합니다.
A: k-Fold Cross-Validation은 데이터를 k개 묶음(Fold)으로 나눠 k−1개로 학습하고 남은 1개로 검증하는 일을 k번 반복해 평균과 편차를 보는 방법으로, 데이터를 낭비하지 않고 평가의 운을 줄입니다. Classification은 Class 비율을 유지하는 Stratified k-Fold, 같은 사용자가 양쪽에 섞이면 안 되면 Group k-Fold, Time Series는 과거로 학습하고 미래로 검증하는 TimeSeriesSplit을 씁니다. Cross-Validation은 Model Selection·Hyperparameter Tuning에 쓰고, 최종 성능은 한 번도 쓰지 않은 Test Set으로 한 번만 잽니다.

## Generalization과 Regularization

#### Bias-Variance Trade-off
ONE: 모델의 오차는 **너무 단순해서 생기는 오차(Bias)**와 **너무 예민해서 생기는 오차(Variance)**로 나뉘어요. 복잡도를 높이면 Bias는 줄고 Variance는 늘어서, **그 사이 균형점**을 찾아야 해요.
LIKE: 직선 자로 구불구불한 길을 그리면 항상 비슷하게 틀려요(Bias). 모든 점을 다 지나는 꼬불꼬불한 선을 그리면 새 점이 올 때마다 모양이 크게 달라져요(Variance).
STEP:
1. **Test 오차 = Bias² + Variance + 줄일 수 없는 잡음**이에요.
2. **Bias**: 모델이 너무 단순해서 실제 관계를 담지 못해 생기는 체계적 오차예요. 곡선 관계를 직선으로 맞추는 경우.
3. **Variance**: 모델이 너무 복잡해서 학습 데이터의 잡음까지 따라가, 데이터가 조금만 바뀌어도 예측이 크게 흔들리는 오차예요.
4. **줄일 수 없는 잡음**: 데이터 자체의 무작위성이에요. 어떤 모델로도 못 줄여요.
5. 모델을 복잡하게 하면 Bias↓ Variance↑, 단순하게 하면 Bias↑ Variance↓.
6. 그래서 **Validation 오차가 가장 낮은 복잡도**를 찾아요.
END: 너무 단순하면 Bias, 너무 복잡하면 Variance. Validation 오차가 최소인 균형점을 찾아요.

#### Overfitting과 Underfitting
ONE: **Overfitting**은 학습 데이터를 **외워서** 새 데이터에서 못하는 것, **Underfitting**은 **너무 단순해서** 학습 데이터조차 못 맞히는 것이에요.
LIKE: Overfitting은 기출문제 답을 통째로 외워서 기출은 100점인데 새 문제는 못 푸는 학생이에요. Underfitting은 공부를 덜 해서 기출문제도 못 푸는 학생이에요.
STEP:
1. **알아보는 법**: Training 오차는 낮은데 Validation 오차가 높으면 Overfitting. 둘 다 높으면 Underfitting.
2. **Learning Curve**: 데이터 양이나 학습 횟수(Epoch)에 따른 두 오차를 그려 보면 상태가 보여요.
3. **Overfitting 해결**: 데이터 더 모으기·늘리기(Augmentation), 모델 단순화, Regularization(L1·L2·Dropout), Validation 오차가 오르기 시작하면 멈추기(Early Stopping), 여러 모델 합치기(Ensemble).
4. **Underfitting 해결**: 더 복잡한 모델, 더 좋은 Feature 추가, Regularization 줄이기, 더 오래 학습.
END: 외웠으면 Overfitting(단순화·Regularization), 못 배웠으면 Underfitting(복잡하게·Feature 추가)이에요.

#### L1 · L2 Regularization
ONE: Loss에 **Weight 크기에 대한 벌점**을 더해서 모델이 지나치게 복잡해지는 걸 막는 방법이에요. **L2**는 Weight를 골고루 작게, **L1**은 일부 Weight를 **정확히 0**으로 만들어요.
LIKE: Weight에 세금을 매기는 거예요. L2는 "큰 값일수록 더 많이" 내는 누진세라 값이 작아지면 세금도 거의 없어져서 0 직전에서 멈춰요. L1은 "얼마를 가지든 단위당 같은 세액"이라 쓸모없는 Weight는 아예 0으로 정리돼요.
STEP:
1. **아이디어**: Weight가 크면 입력이 조금만 바뀌어도 출력이 크게 바뀌어요(예민함 = Variance). 벌점으로 Weight를 작게 유지해요.
2. **L2 (Ridge)**: Loss + λΣw². Weight를 고르게 작게 만들고, 서로 비슷한(상관된) Feature를 안정화해요.
3. **L1 (Lasso)**: Loss + λΣ|w|. 일부 Weight를 **정확히 0**으로 만들어서 필요 없는 Feature를 자동으로 빼 줘요(**Feature Selection**, Sparsity).
4. **왜 L1만 0을 만들까?** L2의 벌점 기울기는 2λw라서 w가 0에 가까워질수록 미는 힘도 약해져요. L1의 기울기는 크기가 항상 λ라서 작은 Weight도 끝까지 0으로 밀어요.
5. **λ (규제 강도)**: 크면 단순한 모델(Underfitting 위험), 작으면 복잡한 모델(Overfitting 위험). Cross-Validation으로 골라요.
6. **Elastic Net**: L1과 L2를 섞은 거예요.
KEY: 통계 관점에서 L2는 Weight에 정규 분포 Prior를 둔 MAP, L1은 Laplace Prior를 둔 MAP와 같아요(13번 주제).
END: L2는 골고루 작게, L1은 쓸모없는 건 0으로. 둘 다 Weight에 매기는 세금이에요.

### Bias-Variance Trade-off란?
E: 직선 자로 구불구불한 길을 그리면 항상 비슷하게 틀리고(Bias), 모든 점을 다 지나는 꼬불선을 그리면 새 점이 올 때마다 모양이 크게 달라집니다(Variance).
A: Test 오차의 기대값은 Bias² + Variance + 줄일 수 없는 잡음(Irreducible Error)으로 나뉩니다. 단순한 모델은 실제 관계를 담지 못해 Bias가 크고, 복잡한 모델은 Training Data의 잡음까지 따라가 데이터가 바뀌면 예측이 크게 흔들리는 Variance가 큽니다. 복잡도를 높이면 Bias는 줄고 Variance는 늘어나므로, Validation 오차가 가장 낮은 지점을 찾습니다.

### Overfitting과 Underfitting은 어떻게 알아보고 해결하나요?
A: Training 오차는 낮은데 Validation 오차가 크면 Overfitting(과적합), 둘 다 높으면 Underfitting(과소적합)이며, Learning Curve(데이터 양·Epoch에 따른 두 오차)로 확인합니다. Overfitting은 데이터 추가·Augmentation, 모델 단순화, Regularization(L1·L2·Dropout), Early Stopping, Ensemble로, Underfitting은 더 복잡한 모델, 좋은 Feature 추가, Regularization 완화, 더 긴 학습으로 해결합니다.

### L1, L2 Regularization은? 왜 L1은 Weight를 0으로 만드나요?
E: Weight에 세금을 매깁니다. L2는 "큰 값일수록 더 많이" 내는 누진세라 값이 작아지면 세금도 거의 없어 0 직전에서 멈추고, L1은 "얼마를 가지든 단위당 같은 세액"이라 쓸모없는 Weight는 아예 0으로 정리됩니다.
A: L2(Ridge)는 λΣw²를 더해 Weight를 고르게 작게 만들고 상관된 Feature를 안정화하며, L1(Lasso)은 λΣ|w|를 더해 일부 Weight를 정확히 0으로 만들어 Feature Selection 효과(Sparsity)를 냅니다. 이유는 L2의 기울기 2λw는 w가 0에 가까워질수록 약해지지만 L1의 기울기는 크기가 항상 λ로 일정해 작은 Weight를 끝까지 0으로 밀기 때문이고, 기하적으로는 L1 제약 영역이 축 위에 꼭짓점이 있는 마름모여서 Loss 등고선이 꼭짓점(일부 좌표가 0)에서 먼저 만나기 쉽기 때문입니다. 둘을 섞은 것이 Elastic Net입니다.

## Linear Model

#### Linear Regression (OLS)
ONE: 입력과 결과 사이를 **직선(평면)으로** 설명하는 가장 기본적인 모델이에요. **오차 제곱합이 가장 작은** 직선을 찾아요.
LIKE: 공부 시간과 시험 점수 데이터에 자를 대고, 모든 점에서 자까지의 세로 거리를 제곱해 더한 값이 가장 작아지도록 자를 놓는 거예요.
STEP:
1. **모델**: ŷ = w₁x₁ + w₂x₂ + … + b. Feature마다 Weight를 곱해 더하고 절편 b를 더해요.
2. **Loss**: 오차 제곱합 Σ(yᵢ − ŷᵢ)². 이걸 최소화하는 방법이 **OLS (Ordinary Least Squares)**예요.
3. **공식으로 바로 풀기**: 미분해서 0으로 놓으면 Normal Equation XᵀXβ = Xᵀy가 나오고, β̂ = (XᵀX)⁻¹Xᵀy예요(12번 주제의 Least Squares).
4. **Feature가 하나일 때**: 기울기 = Cov(x, y) / Var(x), 절편 = ȳ − 기울기 × x̄.
5. 데이터가 아주 크면 공식 대신 Gradient Descent로 풀어요.
6. **Gauss-Markov Theorem**: 오차의 평균이 0이고, 분산이 일정하고, 서로 상관이 없으면, OLS는 선형 비편향 추정량 중 분산이 가장 작아요(**BLUE**).
PRO: 빠르고 단순하고, Weight로 "이 Feature가 1 늘면 결과가 얼마 늘어나는지" 해석할 수 있어요.
CON: 실제 관계가 곡선이면 맞지 않아요(Feature를 변환하거나 다른 모델을 써요). Outlier에 민감해요.
END: Linear Regression은 오차 제곱합이 최소인 직선을 찾는 모델이고, 해석하기 쉬운 강력한 기준선이에요.

#### Logistic Regression
ONE: 선형식으로 점수를 계산한 뒤 **Sigmoid로 0~1 확률**로 바꾸고, Threshold로 분류하는 모델이에요. 이름은 Regression이지만 **Classification** 모델이에요.
LIKE: 점수를 계산하는 것까지는 Linear Regression과 같고, 그 점수를 0~100% 확률로 눌러 담은 뒤 "50% 넘으면 스팸"처럼 선을 긋는 거예요.
STEP:
1. **점수 계산**: z = wᵀx + b. 무한히 크거나 작을 수 있어요.
2. **Sigmoid**: σ(z) = 1 / (1 + e⁻ᶻ). 어떤 z든 0~1 사이로 눌러 줘요. z = 0이면 0.5.
3. **분류**: 확률이 Threshold(보통 0.5)보다 크면 양성.
4. **왜 Regression?** Log-Odds log(p / (1 − p))를 선형식으로 Regression하는 구조라서 이 이름이 붙었어요.
5. **학습**: **Binary Cross-Entropy** −[y log p + (1 − y) log(1 − p)]를 최소화해요. 정답에 낮은 확률을 줄수록 큰 벌점이에요.
6. 이 Loss는 **Convex(그릇 모양)**라서 Gradient Descent가 전역 최솟값을 찾아요. MSE를 쓰면 Sigmoid와 결합해 Convex가 아니게 돼요.
USE: 스팸 필터, 클릭 예측, 대출 승인 같은 이진 분류의 강력한 기준선이에요. 수십만 차원의 희소한 단어 Feature에서도 빠르고, 확률을 내니 Threshold를 조절할 수 있고, 단어별 Weight로 이유를 설명할 수 있어요.
END: Logistic Regression = 선형 점수 → Sigmoid 확률 → Threshold 분류. Cross-Entropy로 학습해요.

#### Softmax Regression (Multi-Class)
ONE: Class가 여러 개일 때, Class마다 점수를 계산하고 **Softmax로 합이 1인 확률**로 바꿔 분류하는 모델이에요. Neural Network Classifier의 마지막 층이 바로 이 구조예요.
LIKE: 반장 선거에서 후보마다 지지 점수를 매기고, 그 점수를 "당선 확률"로 바꿔 모두 더하면 100%가 되게 만드는 거예요.
STEP:
1. Class k마다 점수(**Logit**) zₖ = wₖᵀx + bₖ를 계산해요.
2. **Softmax**: pₖ = e^(zₖ) / Σⱼ e^(zⱼ). 지수를 씌워 모두 양수로 만들고, 전체 합으로 나눠 확률로 만들어요.
3. 점수가 클수록 확률이 커지고, 모든 확률의 합은 1이에요.
4. 가장 확률이 큰 Class를 정답으로 골라요.
5. **학습**: Cross-Entropy Loss −log p(정답 Class)를 최소화해요.
6. Class가 2개일 때 Softmax Regression은 Logistic Regression과 같아요.
END: Softmax = 점수들을 합이 1인 확률로 바꾸기. 여러 Class 분류의 기본이에요.

### OLS(Ordinary Least Squares) Regression의 공식은?
A: OLS는 Residual 제곱합 Σ(yᵢ − xᵢᵀβ)² = ‖y − Xβ‖²을 최소화하는 β를 찾으며, 미분해 0으로 놓으면 Normal Equation XᵀXβ = Xᵀy가 나오고 XᵀX가 Invertible이면 β̂ = (XᵀX)⁻¹Xᵀy입니다(12 Linear Algebra의 Least Squares와 같은 식). Simple Regression에서는 기울기 = Cov(x, y)/Var(x), 절편 = ȳ − 기울기·x̄입니다. 오차의 평균이 0이고 Homoscedastic(등분산)·무상관이면 Gauss-Markov Theorem에 따라 선형 비편향 추정량 중 분산이 가장 작습니다(BLUE).

### Logistic Regression은 왜 "Regression"인데 Classification을 하나요? Sigmoid와 Cross-Entropy는?
E: 점수를 계산하는 것까지는 Linear Regression과 같고, 그 점수를 0~100% 확률로 눌러 담은 뒤 "50% 넘으면 스팸"처럼 선을 긋는 것입니다.
A: Logistic Regression은 Log-Odds log(p/(1−p))를 Feature의 선형식 wᵀx + b로 Regression하므로 Regression이라는 이름이 붙었고, Sigmoid σ(z) = 1/(1 + e⁻ᶻ)로 확률을 만든 뒤 Threshold로 분류합니다. 학습은 Negative Log-Likelihood인 Binary Cross-Entropy −[y log p + (1−y) log(1−p)]를 최소화하며, 이 Loss는 Convex(볼록)라 Gradient Descent로 Global Optimum에 도달합니다. MSE를 쓰면 Sigmoid와 결합해 Convex가 아니게 됩니다.

### 스팸 필터에 Logistic Regression을 많이 쓰는 이유는?
A: 수십만 차원의 Sparse(희소)한 단어 Feature에서도 학습·예측이 매우 빠르고, L1·L2 Regularization으로 Overfitting을 막을 수 있습니다. 확률을 출력하므로 "정상 메일을 스팸함에 넣는 일"을 피하도록 Threshold를 높게 조절할 수 있고, 단어별 Weight로 "무료·당첨이 스팸 쪽으로 끌었다"처럼 설명할 수 있으며, 새 메일이 올 때마다 Online Learning으로 갱신하기도 쉽습니다.

### Multi-Class Classification의 Softmax Regression은?
A: Class k마다 점수(Logit) zₖ = wₖᵀx + bₖ를 계산하고 Softmax pₖ = e^(zₖ) / Σⱼ e^(zⱼ)로 합이 1인 확률을 만든 뒤 Cross-Entropy로 학습합니다. Class가 2개일 때는 Logistic Regression과 같고, Neural Network Classifier의 마지막 Layer가 바로 이 구조입니다.

## Probabilistic Classifier

#### Naive Bayes
ONE: Bayes' Theorem으로 분류하되, **"Class가 정해지면 Feature들은 서로 독립"**이라는 단순한(Naive) 가정을 하는 모델이에요. 빠르고 텍스트 분류에 강해요.
LIKE: "무료"와 "당첨"은 스팸에서 같이 나오기 쉽지만, Naive Bayes는 일부러 "각 단어는 서로 단서를 주지 않는다"고 단순하게 가정해요. 그 덕분에 계산이 엄청 쉬워져요.
STEP:
1. **목표**: P(스팸 | 메일의 단어들)을 구해요.
2. **Bayes**: P(스팸 | 단어들) ∝ P(단어들 | 스팸) × P(스팸).
3. **Naive 가정**: 단어들이 서로 독립이라고 보고 P(단어들 | 스팸) = P(단어₁ | 스팸) × P(단어₂ | 스팸) × …로 쪼개요.
4. 각 확률은 학습 데이터에서 "스팸 메일에 이 단어가 몇 번 나왔나"를 세기만 하면 돼요.
5. **Laplace Smoothing**: 학습 때 스팸에서 한 번도 못 본 단어가 나오면 확률이 0이 되고, 곱셈 전체가 0이 돼요. 그래서 모든 단어 Count에 1을 더해 줘요.
6. 작은 확률을 수없이 곱하면 0으로 사라지니(Underflow), 실제로는 Log 확률을 더해요.
PRO: 학습이 Count뿐이라 매우 빠르고, 새 데이터로 쉽게 갱신되고, 데이터가 적어도 안정적이고, 고차원 텍스트에서 강한 기준선이에요. 단어별 기여도 해석도 쉬워요.
CON: 독립 가정이 틀려서 확률 값 자체는 극단적으로 나오기 쉬워요. 하지만 분류는 "어느 Class 점수가 더 큰가"만 중요해서 실제로 잘 동작해요.
END: Naive Bayes = Bayes + "Feature는 서로 독립" 가정. 단순하지만 빠르고 텍스트에 강해요.

#### Generative Model vs Discriminative Model
ONE: **Generative Model**은 각 Class의 데이터가 **어떻게 생겼는지** 배워서 분류하고, **Discriminative Model**은 Class를 **가르는 경계**만 배워요.
LIKE: Generative Model은 고양이와 개를 각각 그릴 수 있을 만큼 배운 뒤 "이 사진은 어느 쪽 그림에 더 가까운가"로 판단해요. Discriminative Model은 둘을 가르는 경계선만 배워요.
STEP:
1. **Generative**: P(x | y)와 P(y)를 배워 데이터 전체의 분포 P(x, y)를 모델링하고, Bayes로 P(y | x)를 계산해요.
2. 데이터의 생김새를 아니까 새 데이터를 만들어 낼 수도 있어요. 예: Naive Bayes, GMM, HMM, 그리고 이미지·문장 생성 모델.
3. **Discriminative**: P(y | x)나 경계를 직접 배워요. 예: Logistic Regression, SVM, 대부분의 Neural Network Classifier.
4. **경향**: Generative는 가정이 강해 데이터가 적을 때 빨리 배우고, Discriminative는 데이터가 많을 때 분류 오차가 더 낮은 경향이 있어요.
END: 생김새를 배우면 Generative(만들 수도 있음), 경계만 배우면 Discriminative(분류에 집중)예요.

### Naive Bayes의 "Naive"한 가정은? Laplace Smoothing은 왜 필요한가요?
E: "무료"와 "당첨"은 스팸에서 같이 나오기 쉽지만, Naive Bayes는 일부러 "각 단어는 서로 단서를 주지 않는다"고 단순하게 가정합니다. 또 학습 때 스팸에서 한 번도 못 본 단어가 나오면 확률이 0이 되어 전체 곱이 0이 되므로, 모든 단어에 "기본 1번"을 더해 줍니다.
A: Naive Bayes는 Class가 주어지면 Feature들이 서로 Conditionally Independent(조건부 독립)라고 가정해 P(y | x) ∝ P(y)ΠᵢP(xᵢ | y)로 계산하는 Classifier입니다. Laplace(Add-One) Smoothing은 P(w | c) = (count(w, c) + 1) / (Σcount(c) + |V|)처럼 모든 Count에 1을 더해 학습에서 못 본 단어가 확률 0으로 전체 곱을 0으로 만드는 것을 막습니다. 실제 계산은 Underflow를 피하려고 Log Probability의 합으로 합니다.

### 오래된 기법인 Naive Bayes의 장점을 옹호해 보세요.
A: 학습이 Count뿐이라 데이터를 한 번만 훑으면 끝날 만큼 빠르고 새 데이터로 점진적(Incremental) 갱신도 쉽습니다. 추정할 Parameter가 적어 데이터가 적을 때도 안정적이고, 단어 수만 개의 고차원 텍스트에서 강한 Baseline 성능을 냅니다. 독립 가정이 틀려서 확률 값 자체는 극단적이기 쉽지만(Poorly Calibrated) 분류에는 어느 Class 점수가 더 큰지만 중요해 실제로 잘 동작하며, "어떤 단어가 얼마나 기여했는지" 해석도 쉽습니다.

### Generative Model vs Discriminative Model의 차이는?
E: Generative Model은 고양이와 개를 각각 그릴 수 있을 만큼 배운 뒤 "이 사진은 어느 쪽 그림에 더 가까운가"로 판단하고, Discriminative Model은 둘을 가르는 경계선만 배웁니다.
A: Generative Model(생성 모델)은 Joint Distribution P(x, y) = P(x | y)P(y)를 배워 Bayes' Theorem으로 분류하며 데이터를 새로 만들 수도 있고(Naive Bayes, GMM, HMM), Discriminative Model(판별 모델)은 P(y | x)나 Decision Boundary를 직접 배웁니다(Logistic Regression, SVM). 일반적으로 Generative Model은 가정이 강해 데이터가 적을 때 빨리 수렴하고, Discriminative Model은 데이터가 많을 때 분류 오차가 더 낮은 경향이 있습니다.

## SVM과 Kernel

#### SVM: Margin이 가장 넓은 경계
ONE: **SVM**은 두 Class를 나누는 경계 중 **가장 가까운 점까지의 거리(Margin)가 최대**인 경계를 찾아요. 경계는 가장 가까운 몇 개의 점(**Support Vector**)만으로 정해져요.
LIKE: 두 동네 사이에 도로를 낼 때 가장 넓은 도로를 내려면, 도로에 딱 붙어 있는 집 몇 채만 보면 돼요. 그 집들이 Support Vector, 도로 폭이 Margin이에요. 멀리 있는 집은 도로 위치에 영향을 주지 않아요.
STEP:
1. 두 Class를 나누는 선(고차원에서는 Hyperplane)은 무수히 많을 수 있어요.
2. SVM은 그중 양쪽 Class에서 가장 가까운 점까지의 거리, 즉 **Margin이 가장 넓은** 선을 골라요.
3. 넓은 Margin은 새 데이터가 조금 흔들려도 잘못 분류될 여지가 적어서 Generalization에 유리해요.
4. 경계는 Margin에 닿은 점들(**Support Vector**)만으로 정해져요. 멀리 있는 Outlier에 덜 흔들려요.
5. **Soft Margin**: 완벽히 나뉘지 않는 데이터는 일부 오류를 허용해요. **C**가 크면 오류를 엄격하게 막고(Margin 좁아짐), 작으면 너그럽게 허용해요(Margin 넓어짐).
6. **Convex Optimization**이라 항상 전역 최적해를 찾아요.
END: SVM = 가장 넓은 도로 내기. 도로에 붙은 집(Support Vector)만 경계를 정해요.

#### Kernel Trick: 차원을 올려 나누기
ONE: 직선으로 나눌 수 없는 데이터도 **더 높은 차원으로 보내면** 평면으로 나눌 수 있어요. **Kernel Trick**은 실제로 변환하지 않고도 **그 공간에서의 계산을 바로** 해 줘요.
LIKE: 책상 위에 빨간 공이 가운데, 파란 공이 바깥에 둥글게 놓여 있으면 직선 하나로 나눌 수 없어요. 책상을 탁 쳐서 가운데 빨간 공만 공중으로 띄우면(높이라는 새 차원), 평평한 종이 한 장으로 나눌 수 있어요.
STEP:
1. 원래 공간에서 직선으로 안 나뉘는 데이터가 많아요(원 안과 원 밖처럼).
2. Feature를 늘려 고차원으로 보내면(예: x² + y²라는 새 Feature 추가) 평면으로 나눌 수 있게 되는 경우가 많아요(**Cover's Theorem**).
3. 그런데 고차원으로 실제로 변환하면 계산이 폭발해요.
4. **핵심 관찰**: SVM 계산에는 데이터끼리의 Dot Product만 필요해요.
5. **Kernel Function** K(x, z)는 고차원 공간에서의 Dot Product를 원래 공간에서 바로 계산해 줘요. 변환 없이 효과만 얻는 거예요.
6. **대표 Kernel**: RBF(Gaussian, 가장 흔함, 가까울수록 비슷), Polynomial.
PRO: 고차원(텍스트)에서도 잘 동작하고, 비선형 경계도 그려요.
CON: Sample이 수십만 개 이상이면 Kernel 계산이 느리고, Kernel·C·γ 튜닝이 필요하고, 확률을 바로 주지 않아요.
END: 높은 차원으로 띄우면 나뉘고, Kernel Trick은 띄우는 비용 없이 그 효과만 얻어요.

### Margin, Support Vector, Kernel Trick이란?
E: 두 동네 사이에 도로를 낼 때 가장 넓은 도로를 내려면 도로에 딱 붙어 있는 집 몇 채만 보면 됩니다. 그 집들이 Support Vector, 도로 폭이 Margin입니다.
A: SVM(Support Vector Machine)은 두 Class를 나누는 Hyperplane 중 가장 가까운 점까지의 거리(Margin)가 최대인 것을 찾고, 경계는 Margin 위의 점인 Support Vector만으로 정해집니다. 완벽히 나뉘지 않으면 일부 오류를 허용하는 Soft Margin을 쓰고 C로 허용 정도를 조절합니다. Kernel Trick은 데이터를 고차원으로 실제로 변환하지 않고도 그 공간에서의 Dot Product를 Kernel Function K(x, z)(RBF, Polynomial)로 바로 계산하는 방법입니다.

### SVM은 왜 차원을 확장하는 방식으로 동작할까요? SVM은 왜 좋을까요?
E: 책상 위에 빨간 공이 가운데, 파란 공이 바깥에 둥글게 놓여 있으면 직선 하나로 나눌 수 없습니다. 책상을 탁 쳐서 가운데 빨간 공만 공중으로 띄우면(높이라는 새 차원) 평평한 종이 한 장으로 나눌 수 있습니다.
A: 원래 공간에서 Linearly Separable하지 않은 데이터도 더 높은 차원으로 보내면 선형으로 나눌 가능성이 커지기 때문이며(Cover's Theorem), Kernel Trick 덕분에 그 비용을 직접 치르지 않습니다. 좋은 이유는 Margin 최대화가 Generalization에 유리하고, Convex Optimization이라 Global Optimum이 보장되며, 고차원(텍스트)에서도 잘 동작하고, Support Vector만 보므로 먼 Outlier에 덜 흔들린다는 점입니다. 단점은 샘플이 수십만 개 이상이면 Kernel 계산이 느리고, Kernel·C·γ 튜닝이 필요하며, 확률을 바로 주지 않는다는 것입니다.

## Tree와 Ensemble

#### Decision Tree
ONE: **"예/아니오" 질문을 차례로** 던져 데이터를 나누며 예측하는 모델이에요. 각 단계에서 **가장 깔끔하게 나누는 질문**을 골라요.
LIKE: 스무고개에서 "살아 있나요?"처럼 한 번에 후보를 가장 깔끔하게 나누는 질문부터 던지는 것과 같아요.
STEP:
1. 루트에서 시작해, 가능한 모든 Feature와 기준값("나이 ≤ 30?")을 시도해요.
2. 나눈 뒤 각 그룹이 얼마나 "한 Class로 순수해졌나"를 재요. 불순도(**Impurity**)가 가장 많이 줄어드는 질문을 골라요(Greedy).
3. **불순도 기준**: Classification은 **Gini Impurity** 1 − Σpₖ²(CART)나 **Entropy**(Information Gain, 13번 주제), Regression은 분산(MSE) 감소.
4. 나뉜 그룹마다 같은 과정을 반복해요.
5. 그대로 두면 Leaf마다 Sample 하나가 남을 때까지 자라서 학습 데이터를 외워요(Overfitting).
6. 그래서 최대 깊이, Leaf의 최소 Sample 수를 제한하거나, 다 키운 뒤 가지를 쳐요(**Pruning**).
PRO: 규칙을 그대로 읽을 수 있어 해석이 쉽고, Scaling이 필요 없고, 숫자·범주 Feature를 함께 다뤄요.
CON: 혼자서는 Overfitting되기 쉽고, 데이터가 조금만 바뀌어도 구조가 크게 바뀌어요(High Variance).
END: Decision Tree = 가장 잘 가르는 질문부터 묻는 스무고개. 해석은 쉽지만 혼자서는 불안정해요.

#### Ensemble: Bagging · Boosting · Stacking
ONE: 여러 모델을 **합쳐서** 하나보다 더 정확하게 만드는 방법이에요. **Bagging**은 독립적으로 여럿 만들어 투표, **Boosting**은 앞의 실수를 차례로 보완, **Stacking**은 여러 모델 위에 판단하는 모델을 둬요.
LIKE: Bagging은 퀴즈쇼에서 방청객 여러 명의 답을 다수결하는 것, Boosting은 앞 사람이 틀린 문제를 다음 사람이 집중적으로 풀어 보강하는 이어달리기, Stacking은 여러 전문가의 의견을 듣고 최종 판단하는 팀장을 두는 거예요.
STEP:
1. **Bagging (Bootstrap Aggregating)**: 복원 추출(Bootstrap)로 만든 서로 다른 데이터로 모델을 여러 개 **독립적·병렬로** 학습하고, 평균이나 투표로 합쳐요. 개별 오류가 상쇄돼서 주로 **Variance를 줄여요**.
2. **Random Forest**: Bagging + Tree를 나눌 때마다 Feature를 무작위로 일부만 보게 해서 Tree끼리 더 다르게 만들어요. 서로 다를수록 합쳤을 때 효과가 커요.
3. **Boosting**: 약한 모델을 **순차적으로** 추가하면서 앞 모델이 틀린 부분을 고쳐 나가요. 주로 **Bias를 줄여요**.
4. AdaBoost는 틀린 Sample의 가중치를 올리고, **Gradient Boosting**은 남은 오차(Loss의 Negative Gradient)를 다음 Tree가 학습해요.
5. **Stacking**: 여러 모델의 예측을 입력으로 받아 최종 예측을 하는 Meta Model을 학습해요.
6. 작은 Tree 50개를 합치는 게 큰 Tree 하나보다 보통 더 나아요. 단, 하나의 Tree처럼 규칙을 그대로 읽는 해석력은 잃어요.
| 방법 | 학습 방식 | 주로 줄이는 것 | 대표 |
| Bagging | 독립·병렬 | Variance | Random Forest |
| Boosting | 순차적으로 오류 보완 | Bias | XGBoost, LightGBM |
| Stacking | 모델 위에 Meta Model | 상황에 따라 | 대회 상위 솔루션 |
END: 여럿을 독립적으로 투표하면 Bagging(Variance↓), 실수를 이어서 고치면 Boosting(Bias↓)이에요.

#### Random Forest와 XGBoost가 실무에서 강한 이유
ONE: 표 형태(Tabular) 데이터에서는 **Tree 기반 Ensemble**이 Scaling 없이도 강하고 튜닝이 적어, Neural Network보다 좋거나 비슷한 경우가 많아요. **Random Forest**는 병렬화가 쉽고, **XGBoost**는 정확도가 높아요.
LIKE: 엑셀 표 같은 데이터에는 숙련된 스무고개 선수 여러 명(Tree Ensemble)이 거대한 신경망 두뇌보다 더 효율적일 때가 많아요.
STEP:
1. **Random Forest의 병렬성**: Tree들이 서로 독립적이라, Server 100대가 각자 Tree를 만들고 마지막에 모으기만 하면 돼요. 통신이 거의 필요 없어요(Embarrassingly Parallel).
2. Neural Network는 Gradient Descent가 순차적이라 분산 학습 때 매 단계 Gradient를 동기화해야 하고, 보통 GPU가 필요해요.
3. **XGBoost**: Gradient Boosting을 빠르고 정확하게 만든 구현이에요. Loss의 2차 미분까지 쓰는 근사, Tree 복잡도에 대한 Regularization, Learning Rate(Shrinkage), Row·Column Sampling, 결측값을 어느 쪽으로 보낼지 스스로 배우는 기능, 병렬 최적화가 있어요.
4. 그래서 Tabular 데이터에서 높은 정확도를 빠르게 내고 Overfitting에 강해서 Kaggle 상위권에 자주 쓰였어요. 지금은 LightGBM, CatBoost와 함께 쓰여요.
END: 표 데이터에는 Tree Ensemble이 강해요. 병렬이 쉬운 Random Forest, 정확도 높은 XGBoost를 먼저 시도해 보세요.

### Decision Tree는 어떻게 Split 기준을 고르나요?
E: 스무고개에서 "살아 있나요?"처럼 한 번에 후보를 가장 깔끔하게 나누는 질문부터 던지는 것입니다.
A: 각 Node에서 가능한 모든 Feature와 기준값을 시도해, 나뉜 Child Node들의 Impurity(불순도) 가중 평균이 가장 많이 줄어드는 Split을 Greedy하게 고릅니다. Classification에서는 Gini Impurity 1 − Σpₖ²(CART)나 Entropy(Information Gain, ID3·C4.5)를, Regression에서는 Variance(MSE) 감소를 씁니다. 그대로 두면 끝까지 자라 Overfitting되므로 Max Depth·Min Samples 제한이나 Pruning(가지치기)을 합니다.

### Ensemble 방법에는 어떤 것들이 있나요?
E: Bagging은 퀴즈쇼에서 방청객 여러 명의 답을 다수결하는 것, Boosting은 앞 사람이 틀린 문제를 다음 사람이 집중적으로 풀어 보강하는 이어달리기, Stacking은 여러 전문가의 의견을 듣고 최종 판단하는 팀장을 두는 것입니다.
A: Bagging(Bootstrap Aggregating)은 Bootstrap 표본으로 여러 모델을 독립적·병렬로 학습해 평균·투표하므로 주로 Variance를 줄이고, Random Forest는 여기에 Split마다 Feature를 무작위로 일부만 보게 해 Tree 간 상관을 더 낮춥니다. Boosting은 약한 모델(Weak Learner)을 순차적으로 추가하며 앞 모델의 오류를 고치므로 주로 Bias를 줄이고(AdaBoost는 틀린 샘플 가중치를 올리고, Gradient Boosting은 Loss의 Negative Gradient를 학습), Stacking은 여러 모델의 예측을 입력으로 Meta Model을 학습합니다.

### 50개의 작은 Decision Tree는 큰 Decision Tree보다 괜찮을까요?
A: 보통 더 낫습니다. 큰 Tree 하나는 Training Data에 Overfitting되기 쉽고 데이터가 조금 바뀌면 구조가 크게 바뀌는 High-Variance 모델이지만, 서로 다른 데이터·Feature로 만든 50개 Tree의 예측을 모으면 개별 오류가 서로 상쇄되어 Variance가 줄고(Bagging), 작은 Tree를 순차적으로 쌓으면 Bias도 줄일 수 있습니다(Boosting). 단, Tree들이 서로 비슷하면 효과가 작고, 하나의 Tree처럼 규칙을 그대로 읽는 Interpretability는 잃습니다.

### Server가 100대 있을 때 Neural Network보다 Random Forest를 써야 하는 이유는?
A: Random Forest의 Tree들은 서로 독립적으로 학습되므로 Server 100대가 각자 Tree를 만들고 마지막에 모으기만 하면 되는, 통신이 거의 필요 없는 병렬(Embarrassingly Parallel) 작업입니다. Neural Network는 Gradient Descent가 순차적이라 Distributed Training 시 매 단계 Gradient를 동기화해야 하고 보통 GPU가 필요합니다. 또 표 형태(Tabular) 데이터에서는 Tree 기반 모델이 Scaling 없이도 강하고 튜닝이 적어 Neural Network보다 좋거나 비슷한 경우가 많습니다.

### XGBoost를 아시나요? 왜 Kaggle에서 유명할까요?
A: XGBoost는 Gradient Boosting을 빠르고 정확하게 만든 구현으로, Loss의 2차 도함수까지 쓰는 근사, Leaf 수와 Weight에 대한 Regularization, Learning Rate(Shrinkage)와 Row·Column Sampling, 결측값의 기본 방향을 스스로 배우는 Split, 병렬·Cache 최적화된 Split 탐색을 갖추었습니다. 그래서 Tabular 데이터에서 높은 정확도를 빠르게 내고 Overfitting에 강해 Kaggle 상위권 솔루션에 자주 쓰였으며, 현재는 LightGBM·CatBoost와 함께 쓰입니다.

## Unsupervised Learning

#### K-means Clustering과 그 한계
ONE: **K-means**는 데이터를 **K개의 무리**로 나누는데, 각 점을 **가장 가까운 중심(Centroid)**에 배정하고 중심을 다시 계산하기를 반복해요. 단순하고 빠르지만 **둥근 무리**를 가정해요.
LIKE: 운동장에 흩어진 학생들을 K개 팀으로 나눈다고 해 봐요. 팀장 K명을 아무 데나 세우고, 학생들은 가장 가까운 팀장에게 가요. 팀장은 자기 팀의 가운데로 옮겨 서요. 이걸 반복하면 팀이 안정돼요. 그런데 팀이 항상 둥근 공 모양이 돼서, 강을 따라 길게 늘어선 무리는 잘 못 나눠요.
STEP:
1. **K를 정해요**: 몇 개의 무리로 나눌지 미리 정해야 해요.
2. **초기 중심**: K개의 중심을 골라요. 무작위로 고르면 결과가 나빠질 수 있어서, 서로 멀리 떨어지게 고르는 **k-means++**를 써요.
3. **배정**: 각 점을 가장 가까운 중심의 무리에 넣어요.
4. **갱신**: 각 무리의 평균 위치로 중심을 옮겨요.
5. 배정이 더 이상 바뀌지 않을 때까지 3~4를 반복해요.
6. **한계**: 크기가 비슷한 **둥근** 무리를 가정해서, 길쭉하거나 초승달 모양 무리를 잘못 나눠요. 모든 점을 반드시 어느 무리에 넣어 잡음을 따로 못 걸러요. 평균이 Outlier에 끌려가요. 초기값에 따라 결과가 달라지고, Feature Scale에 민감해요.
KEY: K를 고를 때는 K를 늘려 가며 무리 내 거리 합이 꺾이는 지점(Elbow Method)이나 Silhouette Score를 봐요.
END: K-means = 가까운 중심에 배정하고 중심 옮기기 반복. 빠르지만 둥근 무리만 잘 찾아요.

#### 다른 Clustering: Hierarchical · DBSCAN · GMM
ONE: K-means의 한계를 보완하는 방법들이에요. **Hierarchical**은 K 없이 계층을, **DBSCAN**은 밀도로 임의 모양과 잡음을, **GMM**은 확률로 타원형 무리를 찾아요.
LIKE: Hierarchical은 가까운 사람끼리 짝을 짓고, 짝끼리 또 모이고… 해서 가계도 같은 나무를 만드는 것이에요. DBSCAN은 사람들이 빽빽하게 모인 곳을 무리로 보고, 혼자 동떨어진 사람은 "잡음"으로 빼요.
STEP:
1. **Hierarchical Clustering**: 가장 가까운 두 무리를 합치기를 반복해 나무(Dendrogram)를 만들어요. K를 미리 안 정하고 나무를 원하는 높이에서 잘라요. 대신 O(n²) Memory가 필요해서 큰 데이터에는 어려워요.
2. **DBSCAN**: 반경 ε 안에 이웃이 minPts개 이상인 "빽빽한" 점들을 이어서 무리로 만들어요. 임의 모양의 무리를 찾고, 어디에도 속하지 않는 점은 잡음으로 분류해요. K가 필요 없어요. 밀도가 서로 다른 무리가 섞이면 어려워요.
3. **GMM (Gaussian Mixture Model)**: 데이터를 여러 개의 Gaussian(종 모양) 분포의 합으로 보고 EM Algorithm으로 학습해요. 타원형 무리를 표현하고, 각 점이 각 무리에 속할 **확률**을 줘요(Soft Assignment).
4. K-means는 GMM에서 모든 무리가 같은 둥근 모양이고, 확률 대신 하나에만 배정하는 특수한 경우로 볼 수 있어요.
| 방법 | 장점 | 단점 |
| Hierarchical | K 불필요, 계층 구조 | 큰 데이터에 느림 |
| DBSCAN | 임의 모양, 잡음 감지, K 불필요 | 밀도가 다른 무리 어려움 |
| GMM | 타원형, 소속 확률 | K 필요, 초기값 민감 |
END: 계층이 궁금하면 Hierarchical, 모양이 이상하고 잡음이 있으면 DBSCAN, 확률적 소속이 필요하면 GMM이에요.

#### Association Rule: Support · Confidence · Lift
ONE: "A를 산 사람은 B도 산다" 같은 **함께 일어나는 패턴**을 찾는 방법이에요. **Support**는 얼마나 흔한지, **Confidence**는 얼마나 믿을 만한지, **Lift**는 우연보다 얼마나 더 자주인지를 재요.
LIKE: 마트 영수증 100장 중 빵과 우유를 함께 산 게 20장이면 Support 20%, 빵을 산 40장 중 우유도 산 게 20장이면 Confidence 50%예요. 그런데 원래 우유를 사는 사람이 50%라면, 빵은 우유 구매를 전혀 늘리지 못한 거예요(Lift 1).
STEP:
1. **Support(A → B)** = P(A ∩ B). 둘이 함께 나오는 비율이에요. 너무 드문 조합은 의미가 없어요.
2. **Confidence(A → B)** = P(B | A) = P(A ∩ B) / P(A). A를 산 사람이 B도 살 확률이에요.
3. **Confidence의 함정**: B가 원래 엄청 흔하면(우유) 아무 A든 Confidence가 높게 나와요.
4. **Lift(A → B)** = Confidence / P(B) = P(A ∩ B) / (P(A)P(B)). A가 B의 확률을 몇 배로 올리는지예요.
5. Lift > 1이면 함께 잘 팔림(양의 연관), = 1이면 서로 상관없음(독립), < 1이면 오히려 같이 안 팔림.
6. **Apriori Algorithm**: Support가 낮은 조합은 그걸 포함한 더 큰 조합도 낮다는 성질로 후보를 잘라 내며 빠르게 찾아요.
USE: 장바구니 분석("이 상품과 함께 구매한 상품"), 매장 진열, 묶음 할인 기획.
END: Support는 흔함, Confidence는 조건부 확률, Lift는 우연 대비 배율이에요. Lift > 1이어야 진짜 연관이에요.

### K-means의 대표적 의미론적 단점은? (계산량 말고)
E: K-means는 "중심에서 가까운 사람끼리 한 팀"이라 팀이 항상 둥근 공 모양이 됩니다. 강을 따라 길게 늘어선 마을이나 초승달 모양 무리는 엉뚱하게 나눕니다.
A: K를 미리 정해야 하고, Euclidean Distance로 Centroid(중심)에 배정하므로 크기가 비슷한 둥근(구형·볼록) Cluster를 가정해 길쭉하거나 비볼록한 모양, 밀도·크기가 다른 Cluster를 잘못 나눕니다. 모든 점을 반드시 어느 Cluster에 넣어 잡음(Noise)을 따로 분류하지 못하고 평균이 Outlier에 끌려가며, 초기값에 따라 결과가 달라지는 Local Optimum에 빠지고(k-means++로 완화), Feature Scale에 민감합니다.

### Hierarchical Clustering, DBSCAN, GMM은 K-means와 어떻게 다른가요?
| 방법 | 방식 | K-means 대비 장점 | 단점 |
| Hierarchical Clustering | 가까운 Cluster끼리 합쳐 나무(Dendrogram) 생성 | K를 미리 정하지 않고 나무를 보고 자름 | O(n²) Memory로 대규모에 부적합 |
| DBSCAN | 반경 ε 안에 이웃이 minPts 이상인 밀집 지역을 연결 | 임의 모양, Noise 감지, K 불필요 | 밀도가 다른 Cluster가 섞이면 어려움 |
| GMM (Gaussian Mixture Model) | 여러 Gaussian의 합으로 보고 EM으로 학습 | 타원형 Cluster, 소속 확률(Soft Assignment) | K 필요, 초기값에 민감 |
A: Hierarchical Clustering은 K 없이 Cluster의 계층을 보여 주고, DBSCAN은 Density 기반이라 임의 모양의 Cluster와 Noise를 찾으며, GMM은 각 점이 각 Cluster에 속할 확률을 주고 타원형 Cluster를 표현합니다. K-means는 GMM에서 모든 Cluster가 같은 구형 분산을 갖고 확률 대신 하나에만 배정(Hard Assignment)하는 특수한 경우로 볼 수 있습니다.

### Association Rule의 Support, Confidence, Lift는?
E: 마트 영수증 100장 중 빵과 우유를 함께 산 것이 20장이면 Support 20%, 빵을 산 40장 중 우유도 산 것이 20장이면 Confidence 50%입니다. 그런데 원래 우유를 사는 사람이 50%라면 빵은 우유 구매를 전혀 늘리지 못한 것(Lift 1)입니다.
A: 규칙 A → B에서 Support = P(A ∩ B)는 둘이 함께 나오는 비율, Confidence = P(B | A) = P(A ∩ B)/P(A)는 A를 산 사람이 B도 살 확률, Lift = Confidence/P(B) = P(A ∩ B)/(P(A)P(B))는 A가 B의 확률을 몇 배로 올리는지입니다. Lift > 1이면 양의 연관, = 1이면 Independent, < 1이면 음의 연관이며, Apriori Algorithm은 Support가 낮은 조합을 Pruning해 후보를 줄입니다.

## Dimensionality와 Dimensionality Reduction

#### Curse of Dimensionality (차원의 저주)
ONE: Feature(차원)가 많아질수록 공간이 **기하급수적으로 넓어져** 데이터가 **텅 비게** 되고, 거리가 의미를 잃어 학습이 어려워지는 현상이에요.
LIKE: 직선 위에 점 10개를 놓으면 촘촘하지만, 같은 10개를 정사각형, 정육면체에 놓으면 점점 텅 빈 공간이 돼요. 차원이 수백이면 모든 점이 서로 멀고 거리도 거의 비슷해져요.
STEP:
1. 1차원에서 칸 10개를 채우려면 점 10개면 돼요. 2차원(10×10)은 100개, 3차원은 1,000개, 10차원은 100억 개가 필요해요.
2. 그래서 같은 데이터 양이라도 차원이 늘면 데이터가 엄청 듬성듬성(Sparse)해져요.
3. 듬성듬성하면 모델이 우연한 패턴까지 외우기 쉬워요(Overfitting).
4. 고차원에서는 가장 가까운 점과 가장 먼 점의 거리 차이가 줄어들어요. 모두 비슷하게 멀어지는 거예요.
5. 그래서 KNN이나 Clustering처럼 거리에 기대는 방법이 힘을 잃어요.
6. **대응**: 필요한 Feature만 고르기(Feature Selection), 차원 줄이기(Dimensionality Reduction), Regularization.
END: 차원이 늘면 공간이 텅 비고 거리가 무의미해져요. Feature를 고르거나 차원을 줄여 대응해요.

#### Dimensionality Reduction과 PCA
ONE: 많은 Feature를 **적은 수의 새 축**으로 요약하는 방법이에요. 대표적인 **PCA**는 데이터가 **가장 많이 퍼진 방향**부터 서로 직교하는 축을 찾아 상위 몇 개만 남겨요.
LIKE: 럭비공 모양의 점 구름을 생각해 보세요. 길쭉한 방향으로 보면 모양이 거의 다 설명돼요. 두께 방향의 자잘한 흔들림은 버려도 모양은 거의 그대로예요.
STEP:
1. **Feature Selection**: 원래 Feature 중 일부를 골라요(L1 Regularization 등).
2. **Feature Extraction**: 원래 Feature를 섞어 새 축을 만들어요. PCA가 대표적이에요.
3. **PCA 과정**: 데이터를 평균 0으로 옮기고(Centering), Covariance Matrix를 만들어 Eigenvector를 구해요(또는 SVD). 12번 주제의 Symmetric Matrix와 SVD가 여기서 쓰여요.
4. Eigenvalue가 큰 순서대로의 Eigenvector가 **분산이 큰 방향(Principal Component)**이에요. 서로 직교해요.
5. 상위 k개 축만 남기고 데이터를 그 축에 투영해요. d개 숫자 대신 k개 숫자로 표현돼요.
6. **압축이 되는 이유**: 이렇게 고른 축이 원래 데이터를 다시 복원할 때 오차가 가장 작아요.
7. **Noise 제거가 되는 이유**: 진짜 신호는 분산이 큰 몇 방향에 모이고, 무작위 Noise는 모든 방향에 고루 작게 퍼져 있어요. 작은 분산 축을 버리면 Noise의 대부분이 함께 사라져요.
KEY: 다른 방법들: Class 구분을 최대화하는 **LDA(Linear Discriminant Analysis)**, 시각화용 비선형 방법 **t-SNE·UMAP**, Neural Network로 압축하는 **Autoencoder**.
END: PCA는 가장 많이 퍼진 방향을 남기고 나머지를 버려요. 그래서 차원 축소이면서 압축이고 Noise 제거예요.

#### 텍스트 Topic 추출: LSA · LDA
ONE: 많은 문서에서 **숨은 주제(Topic)**를 찾는 방법이에요. **LSA**는 단어-문서 Matrix를 **SVD로 분해**하고, **LDA(Latent Dirichlet Allocation)**는 같은 목표를 **확률 모델**로 풀어요.
LIKE: 신문 기사 수천 개를 읽지 않고도, "선거·후보·투표"가 함께 자주 나오는 묶음(정치 Topic), "골·선수·경기"가 함께 나오는 묶음(스포츠 Topic)을 자동으로 찾아내는 거예요.
STEP:
1. **전처리**: 소문자로 바꾸기, 단어로 나누기(Tokenization), 의미 없는 흔한 단어(Stopword) 빼기, 기본형으로 바꾸기(Lemmatization).
2. **단어-문서 Matrix**: 문서마다 단어 빈도(BoW)나 TF-IDF를 적은 큰 Matrix를 만들어요(16번 주제).
3. **LSA (Latent Semantic Analysis)**: 이 Matrix에 Truncated SVD를 적용해 잠재적인 의미 축(Topic)을 찾아요. Linear Algebra적인 방법이에요.
4. **LDA (Latent Dirichlet Allocation)**: 문서는 여러 Topic이 섞인 것이고, Topic은 단어들의 확률 분포라고 보는 확률 모델이에요. LSA → pLSA → LDA로 발전했어요.
5. **이름 주의**: LDA는 두 가지 뜻이 있어요. NLP의 Latent Dirichlet Allocation(Topic Model)과 통계·분류의 Linear Discriminant Analysis(Class 구분 축 찾기).
6. **최근 방법**: 문장을 Embedding으로 바꾼 뒤 Clustering하고, 무리별 핵심 단어를 뽑아요(BERTopic 방식).
7. Topic 수는 Coherence Score와 사람의 검토로 정하고, 상위 단어와 대표 문서를 보며 Topic에 이름을 붙여요.
END: LSA는 SVD로, LDA는 확률 모델로 숨은 Topic을 찾아요. 요즘은 Embedding + Clustering도 많이 써요.

### Curse of Dimensionality(차원의 저주)란?
E: 직선 위에 점 10개를 놓으면 촘촘하지만, 같은 10개를 정사각형·정육면체에 놓으면 점점 텅 빈 공간이 됩니다. 차원이 수백이면 모든 점이 서로 멀고 거리도 거의 비슷해집니다.
A: 차원이 늘면 공간의 부피가 지수적으로 커져 같은 밀도를 유지하는 데 필요한 데이터가 기하급수적으로 늘고, 데이터가 Sparse해져 Overfitting되기 쉽습니다. 또 가장 가까운 점과 가장 먼 점의 거리 차이가 줄어들어 KNN·Clustering처럼 거리에 의존하는 방법이 힘을 잃습니다. Feature Selection, Dimensionality Reduction, Regularization으로 대응합니다.

### Dimensionality Reduction 기법에는 어떤 것들이 있나요?
A: 원래 Feature 중 일부를 고르는 Feature Selection(Filter·Wrapper·L1 같은 Embedded 방식)과 새 축을 만드는 Feature Extraction이 있습니다. Extraction에는 분산을 최대로 보존하는 PCA, Class 구분을 최대화하는 Supervised 방식의 LDA(Linear Discriminant Analysis), Matrix를 직접 분해하는 Truncated SVD·NMF, 시각화용 비선형 방법인 t-SNE·UMAP, Neural Network로 압축하는 Autoencoder가 있습니다.

### PCA는 Dimensionality Reduction이면서 데이터 압축, Noise 제거 기법이기도 합니다. 왜인가요?
E: 럭비공 모양 점 구름을 길쭉한 방향으로 보면 거의 다 설명됩니다. 두께 방향의 자잘한 흔들림은 버려도 모양은 거의 그대로입니다.
A: PCA(Principal Component Analysis)는 중심화(Centering)한 데이터의 Covariance Matrix Eigenvector(또는 SVD)로 분산이 큰 순서대로 서로 Orthogonal인 축(Principal Component)을 찾고 상위 k개만 남깁니다. d개 값 대신 k개 점수와 축만 저장해도 Reconstruction Error(제곱 기준)가 가장 작도록 고른 축이라 압축이 되고, 신호는 분산이 큰 몇 방향에 모이는 반면 무작위 Noise는 모든 방향에 고루 작게 퍼져 있어 작은 분산 축을 버리면 Noise의 대부분이 함께 제거됩니다.

### LSA, LDA, SVD의 뜻과 관계는?
A: SVD(Singular Value Decomposition)는 Matrix를 UΣVᵀ로 분해하는 Linear Algebra 도구이고, LSA(Latent Semantic Analysis)는 Term-Document Matrix(TF-IDF)에 Truncated SVD를 적용해 잠재 의미(Topic) 축을 찾는 방법입니다. LDA는 두 가지 뜻이 있는데, NLP에서는 문서를 Topic들의 혼합으로, Topic을 단어들의 분포로 보고 Dirichlet Prior를 두는 확률적 Topic Model인 Latent Dirichlet Allocation이고, 통계·분류에서는 Class를 잘 구분하는 축을 찾는 Linear Discriminant Analysis입니다. 관계를 정리하면 LSA는 SVD로 Topic을 찾는 Linear Algebra적 방법이고, Latent Dirichlet Allocation은 같은 목표를 확률 모델로 푸는 후속 방법입니다(LSA → pLSA → LDA).

### 텍스트 더미에서 주제를 추출해야 합니다. 어떻게 접근하시겠어요?
A: 먼저 Normalization·Tokenization·Stopword 제거·Lemmatization(표제어 추출)으로 전처리하고 BoW나 TF-IDF Matrix를 만듭니다. 그다음 LDA·NMF·LSA로 Topic을 추출하거나, Sentence Embedding을 만들어 Clustering한 뒤 Cluster별 핵심 단어를 뽑습니다(BERTopic 방식). Topic 개수는 Coherence Score와 사람의 검토로 정하고, Topic별 상위 단어·대표 문서를 보며 이름을 붙이고 반복적으로 다듬습니다.

## Optimization

#### Gradient Descent와 Local Minimum
ONE: **Gradient Descent**는 Loss가 **가장 가파르게 줄어드는 방향으로 조금씩** 이동하며 최솟값을 찾는 방법이에요. 지형이 울퉁불퉁하면 **작은 웅덩이(Local Minimum)**에 갇힐 수 있어요.
LIKE: 안개 낀 산에서 발밑의 경사만 느끼며 내리막으로 한 걸음씩 내려가는 거예요. 작은 웅덩이에 빠지면 거기가 가장 낮은 곳인 줄 알고 멈출 수 있어요. 산 전체에서 가장 낮은 계곡은 다른 곳에 있는데도요.
STEP:
1. **Gradient**: Loss를 각 Weight로 미분한 값이에요. 가장 가파르게 **증가**하는 방향을 가리켜요(12번 주제).
2. **업데이트**: θ ← θ − η × ∇Loss. Gradient의 반대 방향으로 η(**Learning Rate**)만큼 이동해요.
3. **Learning Rate**: 너무 크면 골짜기를 넘어가 튀고, 너무 작으면 너무 느려요.
4. **Global Minimum**: 전체에서 가장 낮은 점. **Local Minimum**: 주변보다는 낮지만 전체 최저는 아닌 점.
5. **Saddle Point (안장점)**: 어떤 방향으로는 내려가고 어떤 방향으로는 올라가는 말안장 같은 점이에요. Gradient가 0이라 멈출 수 있어요.
6. 고차원 Neural Network에서는 나쁜 Local Minimum보다 **Saddle Point가 더 문제**이고, 많은 Local Minimum의 성능이 비슷하다고 알려져 있어요.
7. **대응**: Mini-Batch의 잡음(SGD), Momentum, Learning Rate Schedule, 여러 번 다른 초기값으로 시작하기(15번 주제).
END: Gradient Descent는 경사를 따라 내려가는 방법이에요. 울퉁불퉁하면 웅덩이와 안장점에 주의해요.

#### Convex Function: 최적화가 쉬운 그릇
ONE: **Convex Function**은 **그릇 모양**이라 웅덩이가 하나뿐이에요. 그래서 내려가기만 하면 반드시 **전체 최솟값**에 도착해요.
LIKE: 매끈한 그릇 안에 구슬을 놓으면 어디서 출발하든 결국 바닥 한 점으로 굴러가요. 울퉁불퉁한 산에서는 작은 웅덩이에 걸릴 수 있지만, 그릇에는 그런 웅덩이가 없어요.
STEP:
1. **정의**: 그래프 위 두 점을 잇는 선분이 항상 그래프 위쪽에 있어요.
2. **핵심 성질**: Local Minimum이 모두 Global Minimum이에요. Gradient가 0인 점이 곧 최적해예요.
3. 그래서 적절한 Learning Rate의 Gradient Descent가 전역 최적해에 수렴하는 게 보장돼요.
4. **Convex 문제의 예**: Linear Regression의 MSE, Logistic Regression의 Cross-Entropy, SVM.
5. **Non-Convex 문제**: Neural Network의 Loss는 울퉁불퉁해서 전역 최적을 보장하지 못해요. 그래도 실제로는 충분히 좋은 해를 찾아요.
END: Convex = 그릇 모양 = 웅덩이가 하나. 내려가기만 하면 정답이에요.

#### Newton's Method vs Gradient Descent
ONE: Gradient Descent는 **경사(1차 미분)**만 보고 일정한 보폭으로 내려가고, **Newton's Method**는 **휘어진 정도(2차 미분, Hessian)**까지 보고 바닥 위치를 계산해 크게 건너뛰어요.
LIKE: Gradient Descent는 발밑 경사만 보고 일정한 보폭으로 내려가는 것이고, Newton's Method는 지형이 얼마나 휘어 있는지까지 보고 "계곡 바닥은 저기쯤"을 계산해 한 번에 크게 건너뛰는 거예요.
STEP:
1. **Gradient Descent**: θ ← θ − η∇f. 1차 미분만 써서 한 번 계산이 싸요. Learning Rate를 정해야 하고 수렴이 느릴 수 있어요.
2. **Newton's Method**: θ ← θ − H⁻¹∇f. Hessian H(2차 미분)를 써서 최적점 근처에서 아주 빨리 수렴해요(Quadratic Convergence). 반복 횟수가 적어요.
3. **Newton의 문제**: Parameter가 d개면 Hessian 저장에 O(d²), Inverse에 O(d³)이 들어요. Parameter가 수억 개인 Neural Network에는 불가능해요.
4. 또 Hessian이 Positive Definite가 아니면 Saddle Point 쪽으로 갈 수도 있어요.
5. **절충: L-BFGS**: Hessian을 저렴하게 근사해요. 중간 규모 문제에 많이 써요.
6. 그래서 Deep Learning은 Gradient Descent 계열(SGD, Adam)을 써요.
END: 경사만 보면 Gradient Descent(싸고 확장 가능), 휘어짐까지 보면 Newton(빠르지만 비쌈)이에요.

### Local Minimum과 Global Minimum은?
E: 안개 낀 산에서 내리막만 따라 내려가면 작은 웅덩이(Local Minimum)에 갇힐 수 있고, 산 전체에서 가장 낮은 계곡(Global Minimum)에는 못 갈 수도 있습니다.
A: Local Minimum(지역 최소)은 주변보다는 낮지만 전체에서 가장 낮지는 않은 점이고, Global Minimum(전역 최소)은 전체에서 Loss가 가장 낮은 점입니다. Convex Function은 Local Minimum이 곧 Global Minimum이지만 Neural Network Loss는 Non-Convex라 Gradient Descent가 Local Minimum이나 Saddle Point(안장점)에 머물 수 있습니다. 다만 고차원 Neural Network에서는 나쁜 Local Minimum보다 Saddle Point가 더 문제이고 많은 Local Minimum의 성능이 비슷하다고 알려져 있으며, SGD의 잡음, Momentum, Learning Rate Schedule, 여러 번의 Initialization으로 대응합니다.

### Newton's Method와 Gradient Descent는?
E: Gradient Descent는 발밑 경사만 보고 일정한 보폭으로 내려가는 것이고, Newton's Method는 지형이 얼마나 휘어 있는지(Curvature)까지 보고 "계곡 바닥은 저기쯤"을 계산해 한 번에 크게 건너뛰는 것입니다.
A: Gradient Descent는 θ ← θ − η∇f(θ)로 1차 미분만 써서 한 번 계산이 싸고 대규모 모델에 쓰이지만 Learning Rate η를 정해야 하고 수렴이 느릴 수 있습니다. Newton's Method는 θ ← θ − H⁻¹∇f(θ)로 Hessian(2차 미분)을 써서 최적점 근처에서 Quadratic Convergence(이차 수렴)해 반복 횟수가 적지만, Parameter가 d개일 때 Hessian 저장에 O(d²), Inverse에 O(d³)이 들고 Hessian이 Positive Definite가 아니면 Saddle Point로 갈 수 있습니다. 그래서 Deep Learning은 Gradient Descent 계열(Adam)을, 중간 규모에는 Hessian을 근사하는 L-BFGS를 씁니다.

### Convex Function은 왜 Optimization이 쉬운가요?
A: Convex Function(볼록 함수)은 그래프 위 두 점을 잇는 선분이 항상 그래프 위쪽에 있는 그릇 모양이라, Local Minimum이 모두 Global Minimum이고 Gradient가 0인 점이 곧 최적해입니다. 따라서 적절한 Learning Rate의 Gradient Descent가 Global Optimum에 수렴하는 것이 보장되며, Linear Regression의 MSE, Logistic Regression의 Cross-Entropy, SVM이 Convex 문제입니다.

## Stochastic Process와 Recommendation

#### Markov Chain
ONE: **다음 상태가 오직 지금 상태에만** 달려 있는(과거는 상관없는) 확률 과정이에요. 오래 지나면 출발점과 상관없이 **일정한 비율(Stationary Distribution)**에 수렴하기도 해요.
LIKE: 내일 날씨를 오늘 날씨만 보고 맞히는 놀이예요. "오늘 맑으면 내일도 맑을 확률 90%, 비 올 확률 10%. 오늘 비가 오면 내일 맑을 확률 50%, 또 비 올 확률 50%." 어제나 그제가 어땠는지는 신경 쓰지 않아요.
STEP:
1. **상태**: 맑음, 비.
2. **Markov Property**: 다음 상태의 확률은 지금 상태에만 달려 있어요. 기억이 없는 거예요.
3. **Transition Matrix (전이 행렬)**: 상태 간 이동 확률을 표로 정리해요.
4. 이 Matrix를 계속 곱하면 며칠 뒤의 날씨 확률을 계산할 수 있어요.
5. **Stationary Distribution**: 위 예에서 한참 뒤에는 출발 날씨와 상관없이 맑음 5/6, 비 1/6에 수렴해요. 맑음에서 비로 가는 양(5/6 × 0.1)과 비에서 맑음으로 가는 양(1/6 × 0.5)이 같아지는 균형점이에요.
6. 이 분포는 Transition Matrix에서 Eigenvalue 1의 Eigenvector예요(12번 주제).
USE: Google PageRank(웹서핑하는 사람이 오래 머무는 페이지 비율), 텍스트 생성의 n-gram Model, HMM, MCMC Sampling, 강화 학습의 MDP.
END: Markov Chain = "지금만 보고 다음을 정하는" 과정. 오래 돌리면 출발점과 무관한 균형에 도달하기도 해요.

#### Recommendation System
ONE: 추천은 **"나와 비슷한 사람이 좋아한 것"(Collaborative Filtering)**이나 **"내가 좋아한 것과 비슷한 것"(Content-Based)**으로 해요. 실무에서는 둘을 섞어요.
LIKE: Collaborative Filtering은 "나와 취향이 비슷한 친구가 재밌게 본 영화"를, Content-Based는 "내가 좋아한 영화와 감독·장르가 비슷한 영화"를 추천하는 거예요.
STEP:
1. **Collaborative Filtering (협업 필터링)**: 사용자 × 아이템 행동(평점, 클릭) Matrix에서 비슷한 사용자나 아이템을 찾아요.
2. **Matrix Factorization**: 이 큰 Matrix를 "사용자 취향 Vector"와 "아이템 특성 Vector"로 분해해서, 빈칸(아직 안 본 영화의 예상 평점)을 채워요(12번 주제의 SVD 아이디어).
3. 장점: 아이템 내용을 몰라도 되고, 예상 밖의 발견(Serendipity)이 가능해요.
4. 단점: 기록이 없는 새 사용자·새 아이템은 추천할 수 없어요(**Cold Start**).
5. **Content-Based (콘텐츠 기반)**: 아이템의 속성(장르, 감독, 키워드)과 사용자의 취향 Profile을 비교해요. 새 아이템도 추천할 수 있어요.
6. 단점: 비슷한 것만 계속 추천해서 시야가 좁아져요(**Filter Bubble**).
7. **Hybrid**: 실무에서는 둘을 섞고, 최근에는 Deep Learning과 Embedding 기반 추천을 많이 써요.
END: 비슷한 사람 기반은 Collaborative, 비슷한 물건 기반은 Content-Based. 서로의 약점을 섞어서 보완해요.

### Markov Chain을 고등학생에게 설명하려면?
E: 내일 날씨를 오늘 날씨만 보고 맞히는 놀이입니다. "오늘 맑으면 내일도 맑을 확률 90%, 비 올 확률 10%. 오늘 비면 내일 맑을 확률 50%, 또 비 올 확률 50%." 어제나 그제가 어땠는지는 신경 쓰지 않습니다.
A: Markov Chain은 다음 상태의 확률이 오직 현재 상태에만 달려 있는(Markov Property) Stochastic Process로, 상태 간 이동 확률을 Transition Matrix(전이 행렬)로 표현합니다. 위 날씨 예에서 한참 뒤에는 출발 날씨와 상관없이 맑음 5/6, 비 1/6의 Stationary Distribution(정상 분포)에 수렴하며, 이는 Transition Matrix에서 Eigenvalue 1의 Eigenvector입니다. PageRank, 텍스트 생성의 n-gram Model, HMM, MCMC가 이 아이디어를 씁니다.

### Recommendation System(Collaborative Filtering vs Content-Based)은?
E: Collaborative Filtering은 "나와 취향이 비슷한 친구가 재밌게 본 영화", Content-Based는 "내가 좋아한 영화와 감독·장르가 비슷한 영화"를 추천하는 것입니다.
A: Collaborative Filtering(협업 필터링)은 User-Item 행동 Matrix에서 비슷한 사용자나 아이템을 찾거나 Matrix Factorization으로 Latent Factor를 배워 추천하므로 아이템 내용을 몰라도 되고 예상 밖의 발견(Serendipity)이 가능하지만, 기록이 없는 새 사용자·새 아이템의 Cold Start 문제가 있습니다. Content-Based(콘텐츠 기반)는 아이템 속성과 사용자 취향 Profile을 비교해 새 아이템도 추천할 수 있지만 비슷한 것만 계속 추천하는 한계(Filter Bubble)가 있어, 실무에서는 둘을 섞은 Hybrid를 씁니다.

## Reinforcement Learning

#### Reinforcement Learning과 MDP
ONE: **Reinforcement Learning**은 Agent가 환경 속에서 **행동하고 보상(Reward)을 받으며**, 장기적으로 **누적 보상이 최대가 되는 행동 전략(Policy)**을 스스로 배우는 방법이에요. 이 상황을 수학으로 나타낸 게 **MDP**예요.
LIKE: 강아지 훈련과 같아요. 앉으면 간식을 주고, 물건을 물어뜯으면 간식을 안 줘요. 강아지는 처음엔 이것저것 해 보다가 점점 "어떤 상황에서 무엇을 하면 간식을 받는지" 배워요.
STEP:
1. **Agent**: 배우는 주체(강아지, 게임 AI, 로봇).
2. **Environment**: Agent가 사는 세계.
3. **State**: 지금 상황. **Action**: Agent가 할 수 있는 행동. **Reward**: 행동 뒤 받는 점수.
4. **MDP (Markov Decision Process)**: 상태, 행동, 상태 전이 확률, 보상으로 정의돼요. 다음 상태는 지금 상태와 행동에만 달려 있어요(Markov).
5. **Policy**: "각 상태에서 어떤 행동을 할지" 정한 규칙이에요. 이걸 배우는 게 목표예요.
6. **Value**: 어떤 상태(또는 상태-행동)에서 시작해 앞으로 받을 **누적 보상의 기댓값**이에요. 먼 미래의 보상은 할인(Discount)해서 덜 쳐요.
7. **Value Iteration·Policy Iteration**: 환경의 규칙을 알 때 최적 Policy를 계산하는 방법이에요. "지금 보상 + 다음 상태의 가치"로 가치를 반복해서 갱신해요(Bellman Equation).
KEY: 결정 이론의 핵심: 결과마다 만족도(효용)를 매기고, 확률로 가중 평균한 **기대 효용이 가장 큰 행동**을 골라요. 정보를 더 모으는 것도 그 비용보다 결정이 좋아지는 정도가 클 때만 해요(정보의 가치).
END: 강화 학습 = 행동하고 보상받으며 Policy 배우기. MDP는 그 상황을 상태·행동·확률·보상으로 나타낸 틀이에요.

#### Exploration vs Exploitation과 Q-Learning
ONE: 강화 학습의 핵심 난제는 **이미 아는 좋은 행동을 할지(Exploitation)**, **새 행동을 시도해 볼지(Exploration)**의 균형이에요. **Q-Learning**은 상태-행동마다 가치를 배워 가는 대표 방법이에요.
LIKE: 단골 맛집(아는 좋은 선택)만 가면 실패는 없지만, 더 맛있는 새 식당을 영영 모를 수 있어요. 가끔은 새 식당에 가 봐야(탐험) 더 좋은 선택을 찾아요. 단, 매번 새 식당만 가면 맛없는 곳에서 자주 먹게 되죠.
STEP:
1. **Exploitation (활용)**: 지금까지 배운 것 중 가장 좋은 행동을 해요. 단기 보상이 좋아요.
2. **Exploration (탐험)**: 덜 해 본 행동을 시도해요. 당장은 손해일 수 있지만 더 좋은 행동을 발견할 수 있어요.
3. **ε-Greedy**: 대부분(1 − ε)은 가장 좋은 행동을, 가끔(ε) 무작위 행동을 해요. 처음엔 ε을 크게, 점점 작게 해요.
4. **Q-Learning**: Q(상태, 행동) = "이 상태에서 이 행동을 하면 앞으로 받을 누적 보상 추정치"를 배워요.
5. 행동하고 보상 r과 다음 상태 s′를 보면, Q(s, a)를 "r + γ × (s′에서 가장 좋은 Q 값)" 쪽으로 조금씩 고쳐요.
6. **Policy Gradient**: 가치 대신 Policy(행동 확률) 자체를 직접 조정해서 보상이 큰 행동의 확률을 높여요.
7. **Deep RL**: Q나 Policy를 Neural Network로 표현해요. Atari 게임을 화면만 보고 배운 DQN, 바둑의 AlphaGo가 대표적이에요.
KEY: **보상 함수를 잘못 설계하면** Agent가 의도와 다른 "편법"을 찾아내요(Reward Hacking). 예: 보트 경주 게임에서 결승선 대신 점수 아이템만 빙빙 돌며 먹는 Agent. 그래서 보상 설계가 매우 중요해요. LLM을 사람의 선호에 맞추는 RLHF도 강화 학습을 써요.
END: 아는 걸 쓸지(Exploitation) 새걸 시도할지(Exploration) 균형이 핵심이고, Q-Learning은 상태-행동의 가치를 경험으로 배워요.

### MDP란? Policy와 Value Function은 무엇인가요?
E: 강아지 훈련에서 "지금 상황(State)에서 어떤 행동(Action)을 하면 간식(Reward)을 받는가"를 정리한 틀이 MDP이고, "상황마다 할 행동" 규칙이 Policy, "이 상황에서 앞으로 받을 간식의 기댓값"이 Value입니다.
A: MDP(Markov Decision Process)는 State 집합, Action 집합, 전이 확률 P(s′ | s, a), Reward R(s, a), Discount Factor γ로 정의되는 순차적 의사결정 모델로, 다음 상태가 현재 상태와 행동에만 의존합니다(Markov Property). Policy π(a | s)는 각 상태에서의 행동 규칙이고, Value Function V(s)·Q(s, a)는 그 Policy를 따를 때의 할인된 누적 보상 기댓값입니다. 최적 가치는 Bellman Equation을 만족하며, 환경 모델을 알면 Value Iteration·Policy Iteration으로 최적 Policy를 구합니다.

### Exploration과 Exploitation의 Trade-off란?
E: 단골 맛집만 가면 실패는 없지만 더 맛있는 새 식당을 영영 모르고, 매번 새 식당만 가면 맛없는 곳에서 자주 먹게 됩니다.
A: Exploitation은 현재 추정으로 가장 좋은 행동을 해 단기 보상을 얻는 것이고, Exploration은 불확실한 행동을 시도해 더 나은 행동을 발견할 정보를 얻는 것입니다. 한쪽만 하면 차선의 Policy에 갇히거나 보상을 낭비하므로, ε-Greedy(확률 ε로 무작위 행동), UCB(불확실성이 큰 행동에 보너스), Thompson Sampling(Posterior에서 Sampling) 같은 방법으로 균형을 잡습니다. 추천 시스템의 Multi-Armed Bandit도 같은 문제입니다.

### Q-Learning이란?
E: 상황과 행동의 조합마다 "이렇게 하면 앞으로 간식을 얼마나 받을까" 점수표를 만들어 두고, 해 볼 때마다 실제 결과를 보고 점수를 조금씩 고쳐 나가는 방법입니다.
A: Q-Learning은 환경 모델 없이 Q(s, a)를 직접 학습하는 Model-Free, Off-Policy 강화 학습 Algorithm입니다. 행동 후 보상 r과 다음 상태 s′를 관측하면 Q(s, a) ← Q(s, a) + α[r + γ maxₐ′ Q(s′, a′) − Q(s, a)]로 갱신하고, 충분히 탐험하면 최적 Q*에 수렴합니다. 상태가 너무 많으면 Q를 Neural Network로 근사하며(DQN), 보상 설계가 잘못되면 의도치 않은 편법(Reward Hacking)을 배울 수 있습니다.

## Deep Learning으로 넘어가는 다리

#### 초기 Neural Network의 문제점
ONE: Neural Network 아이디어는 오래됐지만, 예전에는 **깊이 쌓으면 학습이 안 되고(Vanishing Gradient)**, **데이터가 적어 외우고(Overfitting)**, **계산이 너무 느린** 문제가 있었어요.
LIKE: 귓속말 전달 게임에서 사람이 너무 많으면 처음 말이 끝까지 제대로 전달되지 않아요. 예전 깊은 신경망에서는 학습 신호(Gradient)가 앞쪽 층까지 전달되지 않았어요.
STEP:
1. **Vanishing Gradient**: Sigmoid·tanh 같은 활성 함수는 입력이 크거나 작으면 기울기가 거의 0이 돼요(Saturation). 층마다 이런 작은 수가 곱해지면 앞쪽 층의 Gradient가 사라져 학습되지 않았어요(12번 주제의 Chain Rule).
2. **Overfitting**: 대규모 데이터가 없어서 큰 모델이 학습 데이터를 외웠어요.
3. **계산 비용**: CPU로는 큰 Network 학습이 너무 느렸어요.
4. **Non-Convex**: Loss가 울퉁불퉁해서 초기값과 Learning Rate에 민감했고, 결과를 해석하기도 어려웠어요.
END: 예전 Neural Network는 기울기 소실, 데이터 부족, 계산 부족에 막혀 있었어요.

#### Deep Learning 혁신을 만든 세 가지
ONE: **대규모 데이터**, **GPU 병렬 계산**, **Algorithm 발전**이 동시에 맞물리면서 Deep Learning이 폭발했어요. 여기에 Self-Supervised Pre-training과 Scaling Law가 더해져 지금의 LLM이 나왔어요.
LIKE: 좋은 요리사(Algorithm), 신선한 재료(데이터), 강력한 화덕(GPU)이 한꺼번에 갖춰지자 이전엔 불가능했던 요리가 가능해진 거예요.
STEP:
1. **데이터**: ImageNet(수백만 장의 라벨 붙은 이미지), 웹의 방대한 텍스트.
2. **계산**: GPU·TPU가 Matrix 곱셈을 엄청나게 병렬로 처리해요.
3. **Algorithm**: ReLU(기울기 소실 완화), 좋은 초기화, Dropout, Batch Normalization, Residual Connection(아주 깊은 Network 가능), Adam Optimizer, Attention과 Transformer(15번 주제).
4. **Self-Supervised Pre-training**: 라벨 없는 대량 데이터로 먼저 일반 지식을 배우고, 적은 데이터로 특정 작업에 맞춰요.
5. **Scaling Law**: 모델·데이터·계산을 키울수록 성능이 예측 가능하게 오른다는 관찰이에요. 그래서 모델이 계속 커졌어요.
6. **도구**: PyTorch 같은 오픈소스 Framework가 연구와 개발을 빠르게 했어요.
END: 데이터 + GPU + Algorithm이 동시에 갖춰져 Deep Learning이 열렸고, Pre-training과 Scaling으로 LLM까지 왔어요.

### 전통적인 Neural Network가 가지는 일반적인 문제점은?
A: Layer를 깊게 쌓으면 Sigmoid·tanh의 Saturation(포화) 때문에 Backpropagation Gradient가 점점 작아져(Vanishing Gradient) 앞쪽 Layer가 학습되지 않았고, 데이터가 적어 Overfitting되기 쉬웠으며, CPU로는 계산이 너무 느렸습니다. 또 Non-Convex Optimization이라 Initialization·Learning Rate에 민감하고 결과를 해석하기 어려웠습니다.

### 지금 나오는 Deep Learning 계열 혁신의 근간은 무엇이라고 생각하나요?
A: 세 가지가 동시에 맞물렸다고 봅니다. 첫째 ImageNet·웹 텍스트 같은 대규모 데이터, 둘째 GPU·TPU 병렬 연산, 셋째 ReLU, 좋은 Initialization, Dropout, Batch Normalization, Residual Connection, Adam, Attention과 Transformer 같은 Algorithm 발전입니다. 여기에 Label 없는 데이터로 학습하는 Self-Supervised Pre-training과, 모델·데이터·연산을 키울수록 성능이 예측 가능하게 오른다는 Scaling Law, PyTorch 같은 오픈소스 도구가 더해져 지금의 LLM에 이르렀습니다.

## 실무와 책임

#### 모델의 Bias와 Fairness
ONE: 전체 정확도가 높아도 **특정 집단에 불리하게** 동작할 수 있어요. 그래서 **집단별로 나눠서** 성능과 결과를 측정하고, 데이터·학습·Threshold 단계에서 완화해요.
LIKE: 대출 심사 모델이 전체 정확도는 높아도, 특정 지역 사람들만 자격이 있는데도 자주 거절한다면 공정하지 않아요. 평균만 보면 이런 문제가 숨어 버려요.
STEP:
1. **원인**: 학습 데이터에 담긴 과거의 편견, 특정 집단의 데이터 부족, 편향된 라벨.
2. **측정**: 집단별로 결과를 나눠 봐요.
3. **Demographic Parity**: 집단 간 양성 판정 비율이 같은가?
4. **Equal Opportunity**: 진짜 양성(자격 있는 사람) 중 찾아내는 비율(TPR)이 집단 간 같은가?
5. **Equalized Odds**: TPR과 FPR이 모두 같은가?
6. 여러 기준을 **동시에 만족하는 건 보통 불가능**해서, 상황에 맞는 기준을 골라야 해요.
7. **완화**: 데이터 단계(Resampling, Reweighting), 학습 단계(공정성 제약 추가), 결과 단계(집단별 Threshold 조정).
KEY: 성별·인종 같은 민감 속성을 지우기만 해서는 안 돼요. 우편번호 같은 다른 Feature가 대신 그 정보를 담고 있어서(Proxy Variable) Bias가 남아요.
END: 평균 정확도 뒤에 숨은 집단별 차이를 측정하고, 상황에 맞는 공정성 기준으로 완화해요.

#### 배포 후 성능 저하: Data Drift
ONE: 모델을 배포한 뒤 **세상이 바뀌면** 성능이 떨어져요. 입력이 바뀌는 **Data Drift**, 입력과 정답의 관계가 바뀌는 **Concept Drift** 등이 원인이에요. 계속 지켜보고 다시 학습해야 해요.
LIKE: 작년 유행어로 공부한 번역기는 올해 새 유행어를 못 알아들어요. 세상이 바뀌면 모델도 다시 배워야 해요.
STEP:
1. **Data (Covariate) Drift**: 입력 분포 P(x)가 바뀌어요. 예: 새로운 연령대 사용자가 대거 유입.
2. **Concept Drift**: 입력과 정답의 관계 P(y | x)가 바뀌어요. 예: 코로나 이후 소비 패턴 변화, 사기꾼이 수법을 바꿈.
3. **Label Drift**: 정답 비율 자체가 바뀌어요.
4. **Training-Serving Skew**: 학습할 때와 서비스할 때 Feature를 만드는 코드가 달라서 생기는 차이예요. 아주 흔한 실수예요.
5. **Monitoring**: 입력 분포 변화(PSI, KS Test 같은 지표)와 실제 성능을 계속 지켜봐요.
6. 기준을 넘으면 최신 데이터로 **다시 학습(Retraining)**해요. 이 과정을 자동화하는 게 **MLOps**예요.
KEY: AI 안전과 윤리도 함께 고려해요. 프라이버시, 자동화로 인한 일자리 변화, 책임 소재, 그리고 "고정된 목표를 완벽히 최적화하는 시스템은 위험할 수 있다"는 가치 정렬(Alignment) 문제가 있어요.
END: 배포는 끝이 아니라 시작이에요. 세상이 바뀌는지 지켜보고, 바뀌면 다시 학습해요.

### 모델의 Bias와 Fairness는 어떻게 측정하고 완화하나요?
E: 대출 심사 모델이 전체 정확도는 높아도, 특정 지역 사람들에게만 자격이 있는데도 거절하는 일이 많다면 공정하지 않습니다.
A: 집단별로 성능과 결과를 나눠 봅니다. 대표 Metric은 집단 간 양성 판정 비율이 같은지(Demographic Parity), 진짜 양성 중 찾아내는 비율이 같은지(Equal Opportunity), TPR과 FPR이 모두 같은지(Equalized Odds)이며, 여러 기준을 동시에 만족하기는 보통 불가능해 상황에 맞는 기준을 골라야 합니다. 완화는 데이터 Resampling·Reweighting(Pre-processing), 학습 중 Fairness Constraint(In-processing), 집단별 Threshold 조정(Post-processing)으로 하며, 민감 속성만 지워도 우편번호 같은 Proxy Variable(대리 변수)로 Bias가 남는다는 점에 주의합니다.

### 모델을 배포한 뒤 성능이 떨어지는 이유(Data Drift)는?
E: 작년 유행어로 공부한 번역기는 올해 새 유행어를 못 알아듣습니다. 세상이 바뀌면 모델도 다시 배워야 합니다.
A: 입력 분포 P(x)가 바뀌는 Data(Covariate) Drift, 입력과 정답의 관계 P(y | x)가 바뀌는 Concept Drift(코로나 이후 소비 패턴), 정답 비율이 바뀌는 Label Drift가 있고, 학습·서빙 Pipeline의 Feature 처리가 다른 Training-Serving Skew도 흔한 원인입니다. 입력 분포(PSI, KS Test)와 성능을 Monitoring하고, 임계치를 넘으면 최신 데이터로 Retraining합니다.

- Feature가 늘어난다
- 일부 Weight가 정확히 0이 된다
= D
! L1은 Weight 크기와 상관없이 일정한 힘으로 0 쪽으로 밀어 Sparse한 모델(Feature Selection)을 만듭니다.

? Training Accuracy 99%, Validation Accuracy 70%입니다. 가장 가능성 높은 상황과 대응은?
- Overfitting, Regularization·데이터 추가
- Underfitting, 더 큰 모델
- Data Drift, Retraining
- 정상, 바로 배포
= A
! 학습에는 매우 잘 맞지만 새 데이터에서 크게 떨어지는 것은 전형적인 Overfitting입니다.

? 전체 데이터로 평균·표준편차를 구해 Scaling한 뒤 Train/Test를 나눴습니다. 문제는?
- Curse of Dimensionality

- Class Imbalance

? Bagging(Random Forest)이 주로 줄여 주는 것은?
- Bias

- Feature 수

? 초승달 모양 두 Cluster를 K-means(K = 2)가 잘못 나눕니다. 주된 이유는?
- 중심까지의 거리로 둥근 Cluster를 가정하기 때문
- K가 너무 커서
- 데이터가 너무 많아서
- Supervised Learning이 아니어서

? Association Rule A → B의 Lift가 1이라는 것은?
- A를 사면 반드시 B를 산다
- A와 B는 함께 팔리지 않는다
- Confidence가 100%다
- A와 B는 서로 Independent이다
= D
! Lift = P(A ∩ B) / (P(A)P(B)) = 1이면 P(A ∩ B) = P(A)P(B)이므로 Independent입니다.
